## วิธีตัดผู้สมัคร "table key" ให้ขาดในบูตเดียว (ชุด `=3` -- SPEC ONLY, ยังไม่มีโค้ด) -- ต่อท้ายโดย LANE-K รอบ `2a32q2` 2026-09-07T02:12+07:00 คำต่อคำจาก `notes_to_chief/20260907_0157_LANE-B-TO-K-gt288-addendum-table-key-candidate.md`

ตาราง MOBS มีสองคอลัมน์ที่เป็น "id" คนละอัน: `n_ID` (คีย์แถว -- ตัวที่เราส่งวันนี้) กับ
`n_ID_MODEL` (id ของโมเดล) แถวคู่สามคู่ตัดได้ครบ:

- `K-MATCH` -- `n_ID` 916 คู่กับ preset ของแถว 916 เอง (คู่ที่ ship จริง) = แถวควบคุม
- `K-IDONLY` -- `n_ID` 916 เหมือนเดิม แต่ preset สลับเป็นของแถว NPC (`P_MALE_002_000_SP1`)
  ถ้าสีตามมอน ⇒ client key ด้วย `n_ID` ที่เราส่งจริง ⇒ **ผู้สมัครนี้ตกไป** ปัญหาอยู่ที่ค่าในแถว ไม่ใช่ที่ key
- `K-SKINONLY` -- preset ของ 916 เหมือนเดิม แต่ `n_ID` สลับเป็น id ของแถว NPC
  ถ้าสีตาม NPC ⇒ client **ไม่ได้** key ด้วยช่องที่เราส่ง มันดูโมเดล/preset ⇒ ผู้สมัครนี้ยืน
  และงานต่อไปคือหาว่าช่องไหนในเฟรมเป็น key จริง (ใบ RE ใหม่ ไม่ใช่ใบนี้)

อ่านผลด้วยตารางสีเดิมของเจ้าของ (`2150`) ที่อยู่ในใบแล้ว ไม่ต้องเพิ่มเกณฑ์ใหม่

🔴 **ชุด `=3` = SPEC ONLY (ยังไม่มีโค้ด)** -- `PF_NAME_COLOUR_SWEEP=3` ยังไม่ implement ณ เวลาต่อท้ายนี้ B จะเขียนโค้ดชุดนี้ในรอบเดียวกับที่ต่อสาย env→dispatch เพื่อให้ใบพลิกเป็น READY ครั้งเดียวพร้อมกันทั้งสามชุด -- ห้ามบูตด้วย `=3` จนกว่าจะมีประกาศว่าโค้ดขึ้นแล้ว
