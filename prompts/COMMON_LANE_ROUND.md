## ที่อยู่และภาษา
- clone ใหม่ทุกรอบ ไม่มีความจำข้ามรอบ — ความจำของคุณคือไฟล์ในรีโป · `git fetch origin main` แล้ว `git checkout -B` จาก `origin/main` ทั้งสองรีโปก่อนเสมอ
- โคลนคลาวด์เป็น shallow — จะอ้างเรื่องคอมมิตเก่าต้อง `git fetch --unshallow` ก่อน
- โค้ด · commit message · body ของ PR · ทุกอย่างที่ print ออกคอนโซล = **ASCII อังกฤษเท่านั้น** (คอนโซลสะพาน cp874 อักขระนอกช่วงทำเครื่องมือตาย) · จดหมาย/ไฟล์รอบ = ไทย
- ป้ายเวลาจากคำสั่งเดียว ห้ามคำนวณเอง: ชื่อไฟล์ `TZ=Asia/Bangkok date +%Y%m%d_%H%M` · เนื้อหา `TZ=Asia/Bangkok date +%Y-%m-%dT%H:%M+07:00` · ต่างจากบรรทัดล่าสุดของ `notes_to_chief/_BRIDGE_HEARTBEAT.txt` เกิน 60 นาที = ผิด แก้ก่อน push
- ชื่อไฟล์จดหมาย/รอบ ≤ 100 ตัวอักษร · ใบเทส/ใบ RE ใหม่ ≤ 12,000 อักขระ (นับอักขระ ไม่ใช่ไบต์)

## ล็อกรอบ — ทำก่อนอ่านกล่องจดหมายและก่อนแตะโค้ดทุกรอบ (กติกาเดียวทุกสาย · `AGENTS.md` §7 "ล็อกรอบ" · COO 1226/1349)
1. **ล็อกของสาย = PR ใน pf_bridge หัว `<TAG> round <id>: claim` เท่านั้น** — list เฉพาะใบนี้ (draft นับด้วย) · PR ฝั่ง pirate-force-server ที่เปิดรอเกต/รอ reaper **ไม่ใช่ล็อก ห้ามถอยเพราะเห็นมัน** (ส่งมอบ reaper แล้ว = จบหน้าที่รอบก่อน · Panya 2026-09-05 หลัง Q รอบ 22:26 ถอยเปล่าเพราะ #855 รอเกต) · งานรอบใหม่ทำบนกิ่งใหม่ของตัวเอง ถ้าต้องต่อยอดโค้ดใน PR ที่ยังไม่ merge ให้ `git fetch` กิ่งนั้นมาต่อ แล้วเขียนในไฟล์รอบว่าพึ่ง PR #N · **มองสถานะ PR ไม่ได้ ⇒ จบรอบ ห้ามเดาว่าว่าง**
2. มี created_at ใหม่กว่า 2 ชม. ⇒ มีรอบทำงานอยู่ ถอย: ไฟล์รอบบรรทัดเดียว "ถอยให้ #N อายุ X นาที" ห้ามอ่านซอร์ส ห้ามคิดแผน ห้ามแตะ PR ใบนั้น จบรอบ · ใบถอย push เป็น PR หัว `<TAG> round <id>: claim` แล้วเติม marker ทันที (ไม่งั้นค้างเป็นผีตลอดกาล เกิดจริง `#1377` · PANYA 2026-09-06 01:5x)
3. มี และงานเสร็จแล้วแต่ไม่ได้ปลด (กิ่งมีไฟล์รอบจริงแทน `_claim.md` และ PR เซิร์ฟเวอร์ของรอบนั้น merge แล้ว หรือปิดและไม่มี commit ใหม่ในกิ่งของรอบนั้นทั้งสองรีโปใน 30 นาที — PR ที่ถูกเกตปิดไม่นับว่าจบ)
   ⇒ เติม marker ให้ใบนั้นแทน บันทึกไฟล์รอบ "released #N on behalf" ทำงานต่อ · API 403 ⇒ บันทึกแล้วใช้เกณฑ์อายุ · **ตรวจข้อนี้ก่อนเกณฑ์อายุเสมอ**
4. มี อายุ 2-3 ชม. ⇒ ดู commit ล่าสุดบนกิ่ง ไม่มี commit ใน 60 นาที = ตาย ทำต่อได้ · มี commit = ถอย · อายุเกิน 3 ชม. ⇒ ตาย ทำต่อได้ ห้ามปิดใบผี รายงาน COO
5. 🔴 ยึดต่อจากใบที่ตาย/เสร็จแล้ว (takeover) ต้องเปิด claim ของตัวเองเสมอ บรรทัดที่สามของไฟล์ร่างเขียน "takeover of #N"
6. ไม่มี (หรือยึดต่อ) ⇒ ตัดกิ่งจาก main ของ pf_bridge · commit ไฟล์ร่าง `rounds/<PREFIX>_<YYYYMMDD_HHMM>_<id>_claim.md` (สามบรรทัด: รหัสรอบ · เวลาเริ่ม +07 · claim/takeover of #N) push · เปิด PR ที่ pf_bridge หัว `<TAG> round <id>: claim` ไม่ต้อง draft
   🔴 body ของ claim PR **ต้องไม่มี**สตริง marker จนกว่าจะจบรอบ และห้ามพิมพ์สตริงนั้นลง body เพื่ออธิบาย (reaper จับแบบ substring) — reaper ไม่แตะ PR ที่ไม่มี marker นี่คือสิ่งที่ทำให้ล็อกอยู่ครบรอบ
7. เปิดแล้ว list ซ้ำทันที มี `<TAG>` open ใบอื่น created_at เก่ากว่าและยังมีชีวิต ⇒ คุณแพ้ แก้ไฟล์ร่างเป็น "yielded to #N" เติม marker ให้ใบตัวเอง จบรอบ
8. 🔴 ห้ามตั้งชื่อกิ่งเอง — ใช้กิ่ง `claude/*` ที่ระบบสุ่มให้ · หนึ่งเซสชัน = หนึ่งกิ่ง · เปิด PR ทีละหนึ่งใบต่อรีโป · ห้ามใช้ `gh` (อิมเมจไม่มี) ใช้ GitHub API/tool
9. push หรือเปิด PR ล้ม ⇒ จบรอบทันที ห้าม retry ห้าม force (การแพ้คือคำตอบที่ถูก)

## เวลาและการเลิกรอบ
- 🔴 งบเวลา 75 นาที: ถึงนาที 75 นับจากเริ่มรอบ ห้ามเริ่มงานชิ้นใหม่ push สิ่งที่มี เปิด PR ปลดล็อก งานที่เหลือเขียนลง "รอบหน้าทำอะไร" (รอบเกิน 90 นาทีทำให้รอบถัดไปตื่นเปล่า = เสียครึ่งรอบ)
- รอบทำเกิน 90 นาที: push อัปเดต `_claim.md` หนึ่งครั้ง (checkpoint ไม่ใช่โค้ด) ให้รอบถัดไปเห็นว่ายังมีชีวิต
- 🔴 ปลดล็อกแล้ว = รอบจบ ห้ามแตะโค้ด ห้าม push เพิ่ม ห้ามเปิด PR ใหม่ในรอบเดียวกัน · ผล pf-adversary เพิ่งคืน/เจอของต้องแก้หลังปลด ⇒ เขียนลงไฟล์รอบ รอบถัดไปหยิบเป็นงานแรก
- 🔴 รอบว่างไม่มีอีกแล้ว: งานหลักติด ⇒ **งานสำรองข้อแรกของทุกสาย = ปลดแฟล็ก 1 ตัว**: เปิด `docs/PROMOTION_BACKLOG.md` (รีโปเซิร์ฟเวอร์ · chief ดูแล · COO จัดอันดับ) หยิบ scenario/hypothesis ในเขตตัวเองที่พิสูจน์แล้วแต่ยัง `production_allowed = false` มาทำให้ทำงานไร้แฟล็ก + เทส + ใบ GT (Panya 2026-09-05: 60 scenario พิสูจน์แล้ว โปรโมตแค่ 10) · ถัดไปค่อยเป็น `## งานสำรอง` ในไฟล์สาย (โค้ดก่อน กระดาษทีหลัง) · ทำไม่ได้จริงต้องเขียน "ว่างเพราะรอ <ใคร/ใบไหน>" ให้ COO นับ · ห้ามเงียบเฉยว่า "ไม่มีอะไรทำ"

## ทำงาน + หลักฐาน
- สั่ง `pf-adversary` **ต้นรอบพร้อมเริ่มงาน** (ไม่ใช่ก่อน commit — งานเครื่องมือกิน 25-50 นาที) · ผลยังไม่คืนตอน push ⇒ push ตามเดิม บันทึก `ADVERSARY_PENDING <PR>` · **ห้ามเขียน "ผ่าน adversary" ก่อนผลคืน** · สูงสุด 2 ครั้งต่อรอบ
- เซสชันที่ค้นแล้ว (ToolSearch/Agent) **ไม่มี** `pf-adversary` ให้เรียกจริง ⇒ บันทึก `ADVERSARY_UNAVAILABLE <PR/กิ่ง>` ในไฟล์รอบ (token เดียวกันทุกสาย) + ทำ self-review: อ่านทุก hunk ใน `git diff --cached` · รันมิวแทนต์เฉพาะไฟล์เทสที่แตะ · แล้วเดินต่อตามกฎ draft/marker เดิม · **รอบถัดไปของสายเดียวกันสั่ง adversary บนกิ่งนั้นเป็นงานแรก** เหมือนกรณี PENDING (วัด 5 ก.ย.: ทุกสายเจอ tool หายเป็นบางรอบ chief กำลังหาสาเหตุ)
- ทำงานหนึ่งชิ้นที่ **ผู้เล่นเห็นได้จริงบนจอ** (ไม่ใช่ probe/แฟล็ก/รายงาน) · หลักฐานสองชั้นแยกกันเสมอ (client-observable กับ wire/DB ห้ามใช้ชั้นหนึ่งอ้างอีกชั้น) · ทุกผลมี nonclaims · ผลลบ = ผลที่มีค่า บันทึกเต็ม
- "ต่อสายแล้ว/WIRED" = observed ไม่ใช่ named · ประโยคปฏิเสธ ("ไม่มี/ไม่เคยวัด") ต้องมี `grep` กำกับ และ grep ครบทุกที่ก่อนประกาศ
- ก่อน push: `git merge origin/main` เข้ากิ่งเป็นขั้นสุดท้าย → รันชุดเต็ม (`pytest tests/`) ครั้งเดียวต่อรอบบนต้นไม้นั้น เป็น commit สุดท้ายจริง · ระหว่างทางรันเฉพาะไฟล์เทสที่แตะ (`pytest tests/test_<x>.py`) ห้ามรันชุดเต็มระหว่างทาง
- `python3 tools_bridge/pf_gate_preflight.py --repo <server>` ต้องเขียวก่อน push · เพิ่ม/ลบ/ย้าย skip หรือเพิ่มไฟล์เทสใหม่ ⇒ ซ้อม `pytest_subset` + `skip_census` ในสภาพไม่มี `pf_bridge` ข้าง ๆ (คำสั่งเต็มใน `AGENTS.md` §7)
- 🔴 ห้าม `git add -A` (stage ทีละไฟล์ อ่าน `git diff --cached` ก่อน commit) · ห้ามแตะ canonical DB · ห้าม skip/disable เทสเพื่อให้เขียว · เกตแดงสาเหตุเดิมสองรอบติด ⇒ ห้ามส่งใบที่สาม เขียนจดหมาย COO

## ผลผลิตที่นับ = Scoreboard (Panya 2026-09-05) — ทุกไฟล์รอบจบด้วยบรรทัดนี้ บรรทัดเดียว รูปแบบตายตัว
`SCOREBOARD: <DONE|COMING|STUCK|NONE> | <ประโยคที่ผู้เล่นเข้าใจ: ทำอะไรได้ที่เมื่อวานทำไม่ได้> | <หลักฐาน: PR/GT/sha>`
- DONE = ผู้เล่นทำได้จริงบนบูตปกติไร้แฟล็ก (มี GT ยืนยันบนจอ) · COMING = โค้ดถึง main/รอ merge/รอ GT · STUCK = พิสูจน์แล้วแต่ยังไม่ถึงมือผู้เล่น (ติดแฟล็ก/ติดสายอื่น) · NONE = รอบนี้ไม่มีอะไรขยับ (เขียนเหตุผลสั้น)
- chief รวมบรรทัดนี้จาก `rounds/*.md` เป็น `SCOREBOARD_FACTS.tsv` → `PLAYER_STATUS.html` ทุกรอบ · COO รายงานเจ้าของด้วย "แถวที่ย้ายเข้า DONE" ไม่ใช่จำนวนรอบ · ไม่มีบรรทัดนี้ = รอบไม่นับ

## จบรอบ ตามลำดับ ห้ามสลับ
1. push งานให้ครบทั้งสองรีโป (git ไม่พึ่ง tool)
2. `pirate-force-server`: เปิด PR ไม่ draft หัวขึ้นต้น `<TAG>` เป็นคำอธิบายจริง · body มีบรรทัด `PF-AUTOMERGE: v4` (เป๊ะ บรรทัดของมันเอง) ตั้งแต่เปิด แล้ว GET ยืนยัน marker อยู่จริง (ยกเว้น PR ที่แตะเส้นบูต/ล็อกอิน/ตัวตน actor/เฟรมที่ส่งไคลเอนต์ = draft จนกว่า adversary คืน)
3. `pf_bridge`: ไฟล์รอบจริง + จดหมาย + stub `.CONSUMED.txt` ลงกิ่งเดียวกับ claim (ลบ `_claim.md` บนกิ่ง) push · เมื่อ PR เซิร์ฟเวอร์ทุกใบของรอบ "เปิดแล้ว ไม่ draft และมี marker" ⇒ แก้ body ของ claim PR เติม `PF-AUTOMERGE: v4` = ปลดล็อก แล้ว GET ยืนยัน · 🔴 ปลดล็อก = เติม marker เท่านั้น การ close PR ไม่ใช่การปลดล็อก และทำให้ไฟล์รอบหายไปจาก main (เกิดจริง `#1386` · PANYA 2026-09-06 01:5x)

4. ไฟล์รอบเขียนสถานะ PR เซิร์ฟเวอร์ตามจริง ("เปิดแล้ว รอ gate") **ห้ามเขียนว่าเสร็จ/landed/อยู่บน main** — อยู่บน main ต่อเมื่อรอบถัดไปยืนยันด้วย `git merge-base --is-ancestor <sha> origin/main`
- เติม marker ไม่ได้ (tool ตาย) ⇒ push ให้ครบก่อน ลองแก้ body ซ้ำหนึ่งครั้ง ทำไม่ได้เขียนในไฟล์รอบว่า claim #N ยังไม่ปลด รอบถัดไปปลดตามล็อกรอบ ห้ามหาทางอ้อม (ห้าม curl GraphQL — proxy ปฏิเสธ)

- ห้าม merge เอง ห้าม push main ห้ามปิด PR เอง · PR ของสายอื่นไม่ใช่ล็อกของคุณ ห้ามจบรอบเพราะเห็นมัน ห้ามแตะ

## ใครเปิดใบ คนนั้นบริโภคผล
