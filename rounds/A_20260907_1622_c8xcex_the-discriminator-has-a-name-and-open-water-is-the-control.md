## งานที่สาม — C1 ของ adversary (CRITICAL): ประตู un-freeze เป็น duck type
เดิม `_is_the_same_freeze` ถามแค่ `getattr(value, "_FrozenTier3Module__FROZEN", None) is not None`
สามบรรทัดของ adversary ปลดล็อกทั้งไฟล์:
```

```
`Unfrozen` ไม่มี `__setattr__` เลย ⇒ หลังบรรทัดนั้นทุกชื่อเขียนได้หมด และฟังก์ชันสาธารณะที่ "ถูกแช่แข็ง" ยื่นเฟรมปลอมให้คนที่ยืนอยู่นอกฉาก

ตอนนี้ถามห้าข้อที่ reload ทำซ้ำได้เป๊ะ แต่คลาสสามบรรทัดทำไม่ได้: เป็นคลาส · เป็นคลาสของโมดูล · ชื่อและโมดูลตรง ·
**นิยาม `__setattr__` และ `__delattr__` ของตัวเองใน `vars()`** (ไม่ใช่ `getattr` — ที่ `Unfrozen` ได้มาคือของที่สืบทอด) ·
และเซตที่พกมา **เท่ากับ** ตัวจริง ไม่ใช่แค่ "มี" · เทสสี่ตัวคุม: `Unfrozen` · คลาสที่ลอกเซตจริงมาแต่ไม่มี `__setattr__` ·
`types.ModuleType` เปล่า · และ **`importlib.reload` ต้องยังผ่าน** (นี่คือเหตุผลที่ไม่ใช้เทสเชิง identity)

สั่ง `pf-adversary` ต้นรอบ (นาทีที่ ~30 ทันทีที่แผนนิ่ง) บนกิ่งของรอบนี้ พร้อมสี่คำอ้างเป็นเป้า
ผลคืนตอนนาที ~100 **ก่อนเติม marker** ⇒ ยังไม่ใช่กรณี "เจอของหลังปลด" ⇒ ของที่ถูกและปลอดภัยพอ **แก้ในรอบนี้เลย**
🔴 **แต่ไม่ใช่ทุกข้อ** — สามข้อที่ยังเปิดอยู่ตอน push อยู่ในหัวข้อถัดไป · **ห้ามอ่านไฟล์นี้ว่า "ผ่าน adversary"**

### แก้แล้วในรอบนี้ (วัดซ้ำเองว่าตายจริง ไม่ใช่เชื่อรายงาน)
- 🔴 **C2 CRITICAL — freeze พึ่งชื่อที่ตัวเองไม่ได้ครอบ**: `__setattr__`/`__delattr__` resolve ชื่อ `_FrozenTier3Module`
  **จาก module globals ตอนเรียก** ⇒ `module._FrozenTier3Module = <shim ที่พก __FROZEN ว่าง>` **บรรทัดเดียว**
  ปิดการแช่แข็งทั้งไฟล์ โดยไม่ต้องเจอ `_is_the_same_freeze` เลย · เป็น D1 ซ้ำอีกชั้นหนึ่ง และเป็น "อุบัติเหตุแบบ `module.NAME = value`"
  ซึ่งคือรูปที่เส้นแบ่งวินัยมีไว้กันพอดี ⇒ **แช่แข็งชื่อคลาสเอง** · วัดซ้ำ: `REFUSED`
- 🔴 **C5 — `Mapping` (มาจาก `from ... import`) เป็นชื่อที่ tier 3 อ่าน แต่ AST เดินไม่ถึง**
  `module.Mapping = <คลาสที่ไม่มีอะไรเป็น instance>` ทำให้ reading ที่ถูกต้อง **โยน `TypeError`** แทนที่จะได้คำปฏิเสธที่มีชื่อ
  = พังสัญญา "ไม่เคย raise" ที่ไฟล์นี้เขียนไว้หลายย่อหน้า ⇒ แช่แข็ง · วัดซ้ำ: `REFUSED`
- 🔴 **C6 — หกประโยคปัจจุบันกาลที่กลายเป็นเท็จทันทีที่เติมชื่อ** (docstring สาธารณะของ `answer_guard_reason` สองย่อหน้า ·
  `registered_count` · `_candidate_for_trigger_id` · หัวไฟล์ · และย่อหน้า "การหักล้างไม่กระทบอะไรวันนี้" ซึ่ง**เป็นเหตุผลที่เราไม่ไปแก้พรีมิสผิดในสามเอกสารกลาง**)
  แก้ครบในคอมมิตเดียวกันตามที่ `COO-DECISION 1441` สั่งไว้ตรง ๆ ("ไม่แก้ = เอกสารโกหกอีกแบบ")
  รวมทั้งเลข "สิบสามจุด" → สิบเจ็ด และ "สองกล่อง" → สามกล่อง
- 🔴 **ประโยคที่อันตรายที่สุดที่ adversary จับได้ และผมยอมรับเต็ม ๆ**: refusal 5 เขียนว่าตัดสิน "จาก **coordinates the server owns**"
  **เป็นเท็จ** — พิกัดมาจากอาร์กิวเมนต์ของ caller และ caller ที่รอบหน้าจะเขียนอ่านมันจาก **`TargetPos` ของไคลเอนต์** ในเฟรม `0x1FB2`
  แก้เป็นประโยคที่อ่อนกว่าและจริง พร้อมเขียนคำถามที่ยังไม่มีใครตอบไว้ในไฟล์: **เซิร์ฟเวอร์มีแหล่งความจริงของพิกัดเรือของตัวเองไหม และถ้าขัดกับที่ไคลเอนต์ส่งมา ใครชนะ**
  (SCOREBOARD ของไฟล์นี้ก็แก้ตามแล้ว — เดิมเขียนว่า "จากพิกัดของเรือเอง" ซึ่งอ้างเกิน)
- **C4 — ประโยคของผมเองในไฟล์นี้เป็นเท็จ**: ผมเขียนว่า "ลบชื่อออกจาก `__FROZEN` ทีละตัวในกลุ่มใหม่ ⇒ เทส AST แดง"
  adversary วัดแล้ว: ลบ `RE298_RESULT_LETTER_SHA256` ออกจาก **ทั้ง `__FROZEN` และ `DATA_NAMES`** = **เขียว 118 ตัว**
  เพราะ AST เดินได้ 27 ชื่อ จาก 59 ชื่อในเซต ⇒ อีก 32 ชื่อยัง**พิมพ์มือ**อยู่ · ประโยคเดิมถูกลบและแทนด้วยความจริง
  และซื้อเทสใหม่ `test_the_derivation_is_a_subset_check_not_the_whole_census` ที่**ปักขีดจำกัดนี้ไว้เอง** ไม่ให้รอบหลังอ้างเกินอีก

### 🔴 ยังเปิดอยู่ตอน push — งานแรกของรอบหน้า ห้ามข้าม
- 🔴 **C1 CRITICAL: tier 2 กับ tier 3 ไม่เคยถูกเชื่อมกัน ⇒ ผ่านผิดเกาะ** (วัดแล้วบนทรีที่จะ push)
  `answer_guard_reason(126, **3**, reading@rx248)` = `None` ทั้งที่ `rx248` คือพิกัดของ **เกาะ ordinal 2**
  `_position_is_inside_a_committed_extent` วน `.values()` ไม่เคย index ด้วย wire id ⇒ tier 3 ตอบ "อยู่ในเกาะ*สักเกาะ*"
  tier 2 ตอบ "id เป็น 2 หรือ 3" **ไม่มีใครถามว่าเกาะเดียวกันไหม**
  ผลเมื่อ `_CANDIDATES` มีของ (ขั้นถัดไปตามแผน): เรือจอดที่ Prison Exile ส่ง id 3 ได้เฟรมของ **Spice Paradise**
  🟡 **ทำไมไม่แก้ในรอบนี้**: เป็นการเปลี่ยนพฤติกรรม tier 3 ที่นาที ~110 หลัง adversary คืนแล้ว ⇒ จะไม่มีใครโจมตีตัวแก้เลย
  และคอมเมนต์ที่ให้เหตุผลกับ `.values()` อ้าง nonclaim ของ `RE-289` ซึ่ง **`RE-298` เพิ่งปลดให้** (15/15 จุด · 7/7 id)
  ⇒ สิทธิ์ที่จะเชื่อมมีแล้ว งานเหลือคือทำให้ถูกและให้ adversary ยิงก่อน **ไม่ใช่รีบ**
- **C3/H2** — `RE298_RESULT_LETTER_SHA256` มีแต่เทสเช็คความยาว 64 ตัวอักษร: มิวแทนต์ `"0"*64` = เขียว · ชื่อไฟล์ปลอมที่มีสตริง `RE-298` = เขียว
  🟢 adversary แฮชของจริงทั้งห้าใบเทียบ `origin/main` แล้ว **ตรงหมด** ⇒ ปัญหาคือ "ไม่มีอะไรตรวจ" ไม่ใช่ "ค่าผิด"
- **C8** — เพรดิเคตกล่องปักแค่ 4 ใน 12 ครึ่งแกน: `<=` → `<` **รอด** · ตัดพจน์ z ทิ้ง **รอด** · ระยะเผื่อ 13.45 ที่ `RE-298` เตือน **ไม่มีเทสไหนเข้าใกล้** (จุดที่ใช้ห่าง 194.93)
- **C9** — `M2_OPEN_WATER_CONTROL_BOX` โตเท่าโลก = เขียว · ชื่อ trigger ปลอม = เขียว · และกล่องต้องโต **≥2470 หน่วย** ถึงจะกลืน `rx112`
  ⇒ "แถวที่พูดว่าไม่" จับการโตระดับ 500 หน่วยไม่ได้ (ระดับที่ `MARKER[18]` อยู่ห่างขอบ 129 หน่วย)
- **C10** — oracle ของเทส containment คำนวณจากตารางที่กำลังทดสอบ (`expected = [wire_id] if wire_id in boxes else []`) = double entry ที่ใช้แหล่งเดียวกัน
- **C11** — `importlib.reload` ทำให้ reading ที่สร้างก่อน reload กลายเป็น `CONTACT_REFUSED_NO_EVIDENCE_SUPPLIED` (ชื่อคำปฏิเสธผิดเรื่อง)
- **C7** — ประตู un-freeze ขึ้นจาก 3 บรรทัดเป็น 6 บรรทัด (คลาสที่ลอก `__setattr__` ของ `ModuleType` มาใส่) · ดีขึ้นจริงแต่ docstring เขียนว่า "NOTHING ELSE THAT IS CHEAP" = อ้างเกิน
- **C12** — docstring ของคลาสเทสเขียนว่า "ทั้งสองจุดมาจากสายเดียวกัน" แต่คู่ (id 2, พิกัด rx112) ไม่เคยอยู่บนสายไหน
- **3.14**: adversary ตรวจสี่การเปลี่ยนแปลง (ast.Str/Num ที่ถูกลบ · PEP 649/749 · PEP 765 · warnings-as-errors) **สะอาดทั้งสี่**
