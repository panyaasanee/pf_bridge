## งานจริง

### ปัญหาที่วัดมาแล้ว (R309 · Panya นั่งจอ)

`/warp 2` จาก Port Royal → เซิร์ฟพิมพ์ `WORLD_SCENE scene_id=2` จอเปลี่ยนจริง → ปิดเกมด้วย X →
`character_positions` ยัง `scene_id=1` ที่พิกัดก่อนวาป → ล็อกอินใหม่กลับ Port Royal
เธอลองเอง: วาป → **เดินหนึ่งก้าว** → X → แถวกลายเป็น `scene_id=2 (26414, 20998)` → ถูกต้อง

⇒ การเขียนตำแหน่งลง DB ในโปรเจกต์นี้เป็นสมบัติของ **เฟรมเดิน** เสมอมา
(`runtime.py` สาย TargetPos → `foundation.checkpoint`) `/warp` ไม่เคยเขียนอะไรเลย

### สิ่งที่ลงในรอบนี้

**ใหม่** `src/pirateforce_foundation/gm/warp_scene_persist.py`

- `warp_destination_position(target, current)` — ตัวประกอบแถว บริสุทธิ์ เทสได้โดยไม่มี DB
- `persist_warp_scene(session, target)` — เขียน + อ่านกลับ + พิมพ์ token คืนคำเดียว

**แก้** `src/pirateforce_foundation/gm/chat_command_action.py`

- `_persist_warp_scene(session, target)` ข้าง `_park_warp_target` (เรียกหลังเฟรมมีอยู่จริง
  ด้วยเหตุผลเดียวกับตัวนั้น: วาปที่ถูกปฏิเสธไม่มีไบต์ออกสาย จึงต้องไม่มีการเปลี่ยนแถว)
- เรียกในสองสาขา TeleportVital: `_warp_teleport_action` และ `_warp_teleport_action_no_coords`
- ค่าคงที่ `EVENT_WARP_SCENE_PERSIST_PREFIX` (+ หนึ่งแถวในตารางชื่อ event ที่เทสพินไว้)

**เกณฑ์ที่ `COO 1452` ข้อ 2 ตั้งไว้ ครบทุกบรรทัด**

| ข้อกำหนด | ทำอย่างไร |
|---|---|
| เขียน `scene_id` ปลายทาง + spawn ตัวเดียวกับที่ใส่ในเฟรม | อ่านจาก `WarpTarget` ที่ตัวประกอบเฟรมคืนมา = ค่า binary32 บนสายจริง ไม่ได้อ่านทะเบียนซ้ำ |
| ผ่านประตูเขียนของ DB ที่มีอยู่แล้ว | `FoundationSession.checkpoint` → `lifecycle.checkpoint` → `store.save_position` |
| ห้ามแตะ `store.py` ห้ามเขียน SQL เอง | ไม่แตะ ไม่มี SQL ใหม่แม้บรรทัดเดียว |
| อ่านกลับหลังเขียน | `store.get_character` (ประตูอ่านที่มีในโปรโตคอล `repository.CharacterRepository`) |
| บรรทัดคอนโซลใหม่ | `GM_WARP_SCENE_PERSISTED scene=<n>` ทาง **stderr** |
| ห้ามรอ `TargetPos` ถัดไป | เขียนที่จังหวะประกอบเฟรม ไม่มีการรอ |

**ทำไมการอ่านกลับไม่ใช่พิธี** `lifecycle.checkpoint` เรียก
`store.save_position(..., write_position=allowed)` และสำหรับฉากที่พิน
`persist_position_allowed=False` **คืนค่าปกติโดยไม่เขียนแถวเลย** ถ้าไม่อ่านกลับ token
จะพิมพ์ทับแถวที่ไม่ได้ขยับ — รูปเดียวกับที่ `GM_WARP_POSITION_CONFIRMED` เคยจ่ายมาแล้วครั้งหนึ่ง
(`runtime.py` บันทึกไว้เอง)

**สาขา ForcePos ไม่ต่อ โดยตั้งใจ** `RE-129` วัดว่า handler ForcePos ของไคลเอนต์คือ
