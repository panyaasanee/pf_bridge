### สิ่งที่เพิ่ม (`src/pirateforce_foundation/store.py`)

1. **`commit_acquired_backpack_item(sid, character_id, item)`** — เส้นทางเดียวที่ INSERT แถวของที่เก็บได้
   ใน `BEGIN IMMEDIATE` เดียวกับ `UPDATE character_backpacks SET next_item_identity=?`
   ลำดับด่าน: ตรวจชนิด → ตรวจเจ้าของ session (เหมือน `save_position`) → อ่านตัวนับ → **identity ต้องตรงกับตัวนับ** →
   โหลดกระเป๋าก่อน → ปฏิเสธช่องที่มีของอยู่ → ตรวจรูปร่างของ **สถานะที่กำลังจะเขียน** ก่อนเขียน → INSERT → เดินตัวนับ
   **โดยอ้างค่าที่อ่านมาเป็นเงื่อนไข** (`WHERE next_item_identity=?` ⇒ คนอื่นแซงระหว่างทาง = rowcount 0 = ทั้งรอบพับ) → อ่านกลับเทียบกับที่คาด
2. **`backpack_issued_through(sid, character_id)`** — คืน **ค่าคอลัมน์ลบหนึ่ง**
   เพราะคอลัมน์เป็น EXCLUSIVE ("เลขว่างถัดไป") ส่วนพารามิเตอร์ `issued_through` ของ `mob_pickup` เป็น INCLUSIVE ("เลขสูงสุดที่ออกไปแล้ว")
   migration 005 เตือนกับดักนี้ไว้เอง ⇒ ให้การลบหนึ่งเกิด **ที่เดียว** ในโมดูลที่เป็นเจ้าของคอลัมน์ ไม่ใช่ที่ call site ทุกแห่ง
3. **`_insert_initial_backpack` seed ตัวนับจากแถวของ `INITIAL_BACKPACK`** แทนการปล่อยให้ `DEFAULT 5` ของ migration ทำงาน

### สิ่งที่แดง (อ่านจาก log ของ run 33224035257 ไม่ใช่จากการเดา)

ตารางสรุปเกต: ทุกช่อง GREEN ยกเว้น **`pytest_subset exit=1`**
เทสที่แดงคือ **ไฟล์เทสใหม่ของรอบนี้เอง 5 ข้อ** บน `windows-latest` + **Python 3.14.7**:

```
PermissionError: [WinError 32] The process cannot access the file because it is
being used by another process: '...\Temp\tmpXXXX\state.sqlite3'
```

**เหตุผลที่แท้จริง:** helper ของผมอ่านคอลัมน์ด้วย `with sqlite3.connect(...)` ซึ่ง **commit แต่ไม่ close**
handle ที่ยังเปิดอยู่ = ไฟล์ถูกล็อกบน Windows ⇒ `TemporaryDirectory` ลบไม่ได้
Linux คืนหน่วยความจำแล้ว unlink ไฟล์ที่เปิดอยู่ได้สบาย ⇒ **สวีตบนคลาวด์เขียวทับบั๊กนี้ทั้งรอบ**

### บทเรียนที่ซ้ำสองครั้งในรอบเดียว

2. Linux unlink ไฟล์ที่เปิดอยู่ได้ ⇒ handle รั่วมองไม่เห็นจนขึ้นเกตจริง (เกตจับ)
