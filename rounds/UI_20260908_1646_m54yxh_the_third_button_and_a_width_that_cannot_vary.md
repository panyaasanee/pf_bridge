## 1. งานหลัก

### 1.1 ปุ่มที่สาม — `PartyCmdVital 0x2466` ตอบได้แล้ว  ← ข้อที่ผู้เล่นรู้สึกได้

ก่อนรอบนี้ สองในแปด vital ของ `_FRIEND_MAIL_PARTY_TRADE_DISPATCH` ตอบ (ปุ่มชวนปาร์ตี้ · ปุ่มชวนเทรด)
อีกหกได้ `[]` · รอบนี้เอาตัวที่สาม: `lane_hooks/lane_ui_party_cmd_answer.py` (`production_allowed = True`)

- **ไม่ต้องเปิดใบ RE ใหม่ และไม่ได้เดา**: `RE-312` RESULT-1 มีแถวตรง ๆ
  `0x2466 PartyCmdVital INBOUND_YES handler=0x0062EA70` — **VA ตัวเดียวกับ `PartyInviteVital`** ใน
  `"PartyModule_Client"` (`0x00F0DA14`) · RESULT-2 พินผู้เรียกที่ `0x005F38B2` ในลูป batch dispatch
  ⇒ ช่อง vtable ถูกถึงด้วยเส้นรับปกติ · layout ของคลาสนี้อยู่ใน `ui_party_wire` อยู่แล้ว
  (u8 tag `0x08` + u64 tag `0x32` ทั้งสองทิศ จาก `PF_SERIALIZER_FIELDS.tsv`) — **grep แล้ว: เจอ**
  ⇒ ไม่มีใบ RE ใหม่ในรอบนี้ ไม่กินเวลา RE runner
- **ไบต์ที่ออก = ไบต์ของผู้เล่นเอง**: decode → re-encode → ปฏิเสธถ้าไม่ตรงทุกไบต์ · ไม่ตั้งชื่อฟิลด์ใด
  (`proven_semantics` = UNKNOWN ทั้งสองคลาสปาร์ตี้) · **ฟิลด์เดียวใน vital triple ที่ไม่ใช่ของผู้เล่นคือ version**
  (ไม่ใช่ "ไบต์เดียว" — ทั้งเฟรม 43 ไบต์เป็นของผู้เล่น 11 อีก 32 คือ envelope · adversary D11 จับคำนี้ของผมเอง)

### 1.2 สิ่งที่คลาสนี้มีและอีกสองคลาสไม่มี — **payload ที่ความกว้างเปลี่ยนไม่ได้**

`PartyCmdFields` = `u8 + u64` ไม่มีสตริง ⇒ ทุก payload ที่เลนออกได้ยาว **11 ไบต์เป๊ะ**
ดังนั้นแถวรีวิวใน `ui_dispatch` พิน **ความกว้างจริง** (`max_payload_bytes=11`) ไม่ใช่เพดาน 512 แบบสองคลาสที่มี wstring
และตัวตอบตรวจด้วย **ความเท่ากัน ไม่ใช่ `>`**:

- เพดานที่ไม่มีอะไรเข้าใกล้ = ด่านที่ไม่เคยทำงาน · headroom ที่ไม่มีใครใช้ = reach ที่ไม่มีใครรีวิว
- คุณสมบัติที่พินนี้ยืนอยู่ **วัด ไม่ใช่อ้าง**: 4,000 คู่ฟิลด์สุ่ม + ปลายทั้งสองของทั้งสองฟิลด์ = ได้ 11 ทุกตัว
- ตัวเลขในทะเบียนถูกเทียบกับ **ความกว้างของ encoder เอง** (ทะเบียนคือ "การรีวิว" — รีวิวที่อ่านค่าที่ตัวเองกำลังรีวิว
  พินอะไรไม่ได้ การเทียบจึงอยู่ในไฟล์เทส)
- ด่านถูกขับ **สองทาง**: re-encode ที่สั้นไปหนึ่งไบต์ถูกปฏิเสธด้วย `reason=not_the_reviewed_fixed_width`
  (ซึ่ง `>` จะปล่อยผ่าน) · และแถวทะเบียนที่ถูกขยายเป็น 12 ก็ถูกปฏิเสธเช่นกัน
- 🔴 **เหตุผลที่ผมเขียนไว้ตอนแรกผิด และ adversary จับได้ (D5/D2)**: `>` **จับ** กรณี wire เพิ่มฟิลด์ได้ (12 > 11)
  · สิ่งที่ `>` มองไม่เห็นคือ wire **ลด** ฟิลด์ กับแถวที่ดริฟต์ไปทางหลวม · และ `!=` **ไม่ใช่ "ปลอดภัยกว่าเด็ดขาด"**
  — ขยายแถวรีวิว = ปุ่มตาย · เลือก `!=` เพราะความล้มมัน **ดัง** (proof FAIL + เทสแดง) ไม่ใช่การขยาย reach เงียบ ๆ
- **payload ต้องตรงทั้งความกว้างของ encoder และเลขในแถวรีวิว** (D7 — เดิมเทียบแถวรีวิวอย่างเดียว
  ค่าคงที่ที่ derive จาก encoder จึงเป็นโค้ดตายและคอมเมนต์ของมันเป็นคำเท็จ)
- `max_frame_bytes=64` **จงใจไม่เป๊ะ**: envelope เป็นของ `legacy.make_runtime_vitals` ไม่ใช่ของเลนนี้ วัดได้ 43 ไบต์
  · **แต่ไฟล์เทสพิน 43 เป๊ะ** (D9) และเก็บทั้งคู่ไว้โดยเขียนเหตุผล: **เทสแดง = ข้อความถึงคน · การปฏิเสธ = ปุ่มตายสำหรับผู้เล่น**

### 1.3 D3 residual — เขียนลงหัวโมดูลตามที่รอบก่อนสั่ง (ไม่ใช่ปิด)

รอบ `vy1m79` ค้างไว้ข้อเดียว: `_SESSION_ANSWERS_SENT` เป็น global ของโมดูล ⇒ บรรทัดเดียวในไฟล์เลน

(โมดูลซ่อน state จากโค้ดที่รันในอินเทอร์พรีเตอร์เดียวกันไม่ได้) ⇒ รอบนี้เขียนลง **docstring หัว `ui_dispatch`**

## 2. หลักฐานสองชั้น (แยกกันจริง)

**ชั้น wire/headless** — `tools/pf_ui_party_cmd_answer_headless.py` บูตจริง ไม่มีธง ไม่มี scenario:

    UI_PARTY_CMD_ANSWER_ARMED answered=1 label=UI_PARTY_CMD_ANSWERED payload_bytes=11
    frame_bytes=43 frame_matches=1 echo_is_the_players_bytes=1 junk_refused=1
    width_is_enforced=1 RESULT=PASS

`frame_matches` เทียบกับเฟรมที่ `legacy.make_runtime_vitals` สร้างแยกต่างหาก · `echo_is_the_players_bytes`
เป็นการตรวจเชิงโครงสร้าง (สร้าง envelope เดียวกันรอบ marker แล้วเทียบช่อง payload กับส่วนที่เป็นของ envelope
— ไม่ใช่ `in` ซึ่ง adversary รอบ `xqxadg` D10 วัดว่าผ่านได้ทั้งที่มีไบต์ที่ประดิษฐ์ขึ้น) ·
**negative control สองตัวในบูตเดียวกัน**: payload ที่ decode ไม่ได้ และ payload ที่มีไบต์ท้ายเกินหนึ่งตัว
ทั้งคู่ต้องได้ `[]` (ตัวที่สองโดน `require_exhausted` จับ **ไม่ใช่ด่านความกว้าง** — คอมเมนต์เดิมของผมเขียนผิด adversary D6)
· 🔴 `width_is_enforced` **วัดการบังคับใช้ ไม่ใช่วัด encoder** (D3): ขยายแถวรีวิวในบูตเดียวกัน → กดต้องได้ `[]`
→ คืนแถว → กดต้องได้คำตอบ · **ลบด่านทิ้ง ⇒ `width_is_enforced=0 RESULT=FAIL`** (วัดเองแล้ว) ·
ฉบับแรกของฟิลด์นี้ถาม encoder อย่างเดียว จึงพิมพ์ PASS ได้ทั้งที่ด่านหายไป
🔴 โทเคนนี้วัดบนกิ่ง ไม่ใช่บน main ⇒ ยังขึ้นรถบัส capture ไม่ได้ (เหตุผลเดียวกับสี่รอบก่อน — ใบ `1658`)

**ชั้น client-observable** — **ยังไม่มี และไม่แกล้งว่ามี** · `observed_frames = 0` สำหรับคลาสนี้เหมือนอีกเจ็ดตัว
ไม่ออกใบ GT รอบนี้ด้วยเหตุผลเดียว: `HEADLESS_PROOF:` ต้องวัดบน main ปัจจุบัน และสายโซ่ยังไม่ลง main
⇒ ใบที่ออกวันนี้ตกรถอยู่ดี (นี่คือสิ่งที่ใบ `1658` ขอให้ COO เคาะ)
