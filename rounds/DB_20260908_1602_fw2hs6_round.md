### 1.2 🔴 `persistence_rebuild_guard.py` — **จ่ายหนี้ D2 ที่สายนี้ประกาศไว้เอง**
รอบ `nivlwg` เขียนไว้เองว่า: ยามของ rebuild ทุกตัวในรีโป (`004` `009` `014` `017`) **นับแถวอย่างเดียว**
adversary จึงยัด `UPDATE character_positions SET scene_id=99` ก่อน `DROP` แล้ว**ผ่านเขียว** — ตัวละครทุกตัวย้ายฉาก
และ migration รายงานว่าสำเร็จ · `017` แช่แข็งแล้วซ่อมไม่ได้ ⇒ รอบ `nivlwg` เขียนรูปการซ่อมไว้เอง:
*"helper ที่ทุก rebuild ยืมได้ · `018` ตัวถัดไปต้องผ่าน"* — **นี่คือ helper ตัวนั้น และ `018` คือใบแรกที่ถือมัน**

| ฟังก์ชัน | คืนอะไร |
|---|---|
| `snapshot_sql(table, tag)` | `CREATE TABLE <tag>_before AS SELECT * FROM <table>;` — สำเนาข้อมูลก่อนแตะอะไร |
| `verify_sql(table, columns, tag)` | ยามสี่แถวบน `CHECK(ok=1)`: จำนวนแถว · `EXCEPT` **ทั้งสองทาง** · `pragma_foreign_key_check` |
| `drop_sql(tag)` | ล้าง scaffold ทั้งสองตารางในธุรกรรมเดียวกัน |

- **คืน "ข้อความ SQL" ไม่ใช่รัน** — ตั้งใจ: migration ต้องเป็นไฟล์ที่ sha256 ของ ledger พินได้ทั้งใบ
  helper ที่สร้าง SQL ตอน apply = เอา logic ไปซ่อนในจุดบอดของ checksum
- **ใช้ `EXCEPT` ไม่ใช้ join**: SQLite เทียบแถวใน compound select แบบ NULL-sensitive (สอง NULL = เท่ากัน)
  ส่วน `a=b` ใน `ON` ได้ NULL ⇒ ตารางที่มีคอลัมน์ null ได้ (`characters.deleted_at` `ground_drops.taken_at`)
  จะถูกยามแบบ join รายงานผิดทั้งแถว · **ยังเก็บยามนับแถวไว้** เพราะ `EXCEPT` เป็น set ⇒ พับแถวซ้ำ
