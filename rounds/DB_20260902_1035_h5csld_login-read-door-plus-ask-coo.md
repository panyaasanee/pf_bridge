## 1. ทำอะไร — `SQLiteStore.read_character_vitals_or_none()`

### ปัญหาที่มันแก้ ไม่ใช่ความสวยงามของ API

`read_character_vitals` คืน `VitalsResolution` = วัตถุสองแขนง (`complete` / `gaps`) ที่ตัวเลขออกมาทาง
`require()` ซึ่ง **โยน** รูปนี้ถูกสำหรับรายงาน และผิดสำหรับผู้เรียกที่ **ห้ามโยน** — ซึ่งคือผู้เรียกที่
สายนี้กำลังเดินไปหาพอดี (บล็อกล็อกอิน) ผู้เรียกที่ต้องเขียน try/except เองคือผู้เรียกที่วันหนึ่งจะมีคนเขียน
`except VitalsError: hp_current = 0` — และบนสายนี้ **ศูนย์ไม่ได้แปลว่าไม่รู้ แปลว่าตาย**
`None` เอนโค้ดไม่ได้และบวกไม่ได้ ⇒ ค่าที่ไม่รู้ไปโผล่บนสายเงียบ ๆ ไม่ได้
(🔴 ร่างแรกผมเขียนแรงกว่านี้ว่า "เทียบไม่ได้" ด้วย — ผู้ตรวจวัดแล้วว่าเท็จ: `None != 0` เป็น `True`
ผู้เรียกที่เขียน `if hp != 0:` ยังเลือกกิ่ง "ยังไม่ตาย" ได้ · แก้ถ้อยคำใน docstring แล้ว ดูหัวข้อ 5 D7)

- `None` เมื่อ: ยังไม่ seed · เขียนครึ่งเดียว · `level = 0` (ใบ `0443` ข้อ 4) · `hp_current > hp_max` ·
  `hp_max = 0`
- **ยังโยน `KeyError`** เมื่อไม่มีแถวนั้น/ถูก soft-delete — "ไม่มีตัวละครนั้น" ไม่ใช่ "ไม่มีค่า"
  อันแรกคือบั๊กของผู้เรียก อันหลังคือช่องว่างของฐาน แปลงอันแรกเป็น `None` = ยื่น fallback ให้บั๊ก
- **ยังโยน `VitalsError`** ถ้าเจอ resolution ที่อ้างว่าไม่มี gap แต่ไม่มีค่า (สร้างด้วยมือได้)
  — ประตูนี้มีทางตอบ "ไม่" ทางเดียวคือ gap ไม่ใช่ invariant พัง
- **ยังโยน `SchemaDriftError`** เมื่อสคีมาเพี้ยน (ผู้ตรวจเจอ ผมไม่ได้คิดถึง — หัวข้อ 5 D6)
  เพราะ `read_character_vitals` ตรวจสคีมา typed **ทั้ง 24 คอลัมน์** ไม่ใช่แค่สามของมันเอง

### และสแกนตัวเดียวกันมีบั๊กจริงที่ผมเพิ่งเจอเพราะเรื่องนี้

ครึ่ง raw-SQL ของมันเขียนว่า `"speed_walk" in s and "select" in s` — สตริงที่ทำให้มันฟ้องรอบนี้คือ
**docstring** ที่พูดถึงคอลัมน์และมีคำว่า "**select**ed" อยู่ในประโยค ⇒ **ร้อยแก้วถูกนับเป็นการอ่าน**
แก้เป็น regex ที่ต้องมีรูป SQL จริง (`\bselect\b[\s\S]*\bfrom\b`) — `\bselect\b` ไม่แมตช์ "selected"
และ `SELECT ... FROM characters` ของจริงยังแมตช์ทั้งสองครึ่ง เพิ่มเคสเทสทั้ง "ร้อยแก้วไม่นับ" และ
"ประโยค SQL ตัวเล็กยังนับ" ⇒ **แม่นขึ้น ไม่ได้อ่อนลง**
