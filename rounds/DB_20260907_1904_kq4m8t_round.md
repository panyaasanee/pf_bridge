## 1. งานหลักของรอบ: `lane_hooks/lane_db_item_operate_op5.py` + เทส
รอบก่อนเขียนไว้ว่า "รอบหน้าเป็นงานแรกทันทีที่ RE ตอบ" — **RE ตอบแล้ว** (`RE-280`, ใบผล `20260906_2258`, ปิดและ archive แล้ว) จึงเป็นงานแรกจริงตามที่สัญญาไว้

**สิ่งที่เปลี่ยนสำหรับผู้เล่น**: การ equip ที่ผู้เล่นทำอยู่แล้ววันนี้ **หายไปเฉย ๆ** — เฟรม op=5 วิ่งถึงจุดเสียบที่ chief ลงไว้ (`runtime.py:9910`, PR `#1054`) แล้วไม่มีอะไรเกิดขึ้น ตัวละครล็อกอินกลับมาก็ยังสวมของที่ถูกสร้างมาพร้อมตัวเสมอ · หลังไฟล์นี้ การ equip กลายเป็นแถวใน `character_equipment` ที่อยู่ข้าม session
**ยังไม่ถึงจอ และไม่อ้างว่าถึง**: ครึ่งที่เอาขึ้นจอคือเฟรมตอบ `ItemOperateVitalRes` + การอ่านตอน login ซึ่งไม่ได้อยู่ในไฟล์นี้

### เลขเดียวที่ไฟล์นี้ปฏิเสธที่จะเดา และเป็นทั้งดีไซน์
`RE-280` ปิดฝั่งที่ **client อ่าน**: `ItemAttr+0x39` = **ดัชนีบิต** (`mask = 1 << N` ที่ `0x005833F9`/`0x005833FE` ไม่มี lookup กลางทาง) · `0xFF` = ไม่ได้สวม ⇒ N มีความหมายจริงแค่ `0..31`
`RE-280` **ไม่ปิด** ฝั่งที่ client **ส่ง**: ใบเตือนด้วยตัวเองว่า `value=8` ที่วัดได้จาก `RE-272` **ห้ามก๊อปไปใส่ `+0x39`** และ static ไม่ยืนยันและไม่หักล้างความบังเอิญนั้น
⇒ **`value32` ไม่เคยถูกใช้เป็นช่อง** ในไฟล์นี้ · มันไปอยู่บนบรรทัดคอนโซลเพื่อให้ RE รอบหน้ามีเลข โดยที่เซิร์ฟเวอร์ไม่ได้ลงมือกับมัน (`PANYA 1059`)

### `slot_id` ในแถวที่เขียน คืออะไร — พูดครั้งเดียว ตรง ๆ
คือ `n_EQUIPTYPE` (ผ่าน `combat_pose.equip_type_for_class`) **ไม่ใช่** ดัชนีบิตของ `ItemAttr+0x39`
`store.equip_item` เรียกคอลัมน์นี้ว่า "an opaque validated byte" ไว้เองอยู่แล้ว เพราะตอนเขียนยังไม่มีใครรู้ความหมายฝั่งสาย · ไฟล์นี้คงความ opaque ไว้ **แต่บอกว่าใช้ระบบเลขอันไหน** แทนที่จะประดิษฐ์การแปลงที่ไม่มีใครวัด · วันที่ดัชนีบิตรู้แล้ว การแปลงไปอยู่ที่โค้ดที่ **ประกอบเฟรม** DB ไม่ต้องถูกเขียนใหม่ เพราะแถวตั้งชื่อชนิดของจริงไว้แล้ว

### ทำไมเขียนได้เฉพาะอาวุธมือขวาประจำคลาส
**ไม่มีตาราง `template_id -> n_EQUIPTYPE` ที่ไหนในรีโปทั้งสอง** (grep แล้ว: `equip_value_attack_behavior.tsv` คีย์ด้วยชนิด · `creation_gear_by_class.tsv`/`charcreate_class.tsv` ตั้งชื่อ template ได้คลาสละตัว = `n_SLOT_RHAND`)
⇒ มีไอเทมเดียวต่อคลาสที่เซิร์ฟเวอร์ **derive** ชนิดได้แทนที่จะเดา · ที่เหลือถูกปฏิเสธด้วยชื่อ (`REASON_TEMPLATE_IS_NOT_THE_CLASS_RIGHT_HAND`) และ **ไม่เขียนอะไรเลย** — เพราะการเขียนคือการยื่นหมวกเข้าไปในชนิดของอาวุธ
🔴 ข้อจำกัดนี้เป็น **ขีดจำกัดของตารางที่ commit ไว้ ไม่ใช่แฟล็ก** — มันหายไปเองวันที่ตาราง template→ชนิดลง โดยไฟล์นี้ไม่ต้องเปลี่ยนรูป · ใบ RE ที่ปลดมันออกไปแล้วรอบเดียวกัน (ข้อ 5)

### `production_allowed = True` — ทำไมปลอดภัย
ทุกการเขียนผ่าน `store.equip_item` ซึ่งตรวจ bound ของตัวเอง ปฏิเสธตัวละครที่ไม่มี/ถูกลบนุ่ม (`KeyError`) และใช้ write lock เดียวกับประตูเขียนอื่นทุกบานใน `store.py` · **ไม่เพิ่มสิทธิ์ใหม่**: `INSERT OR REPLACE` บน `UNIQUE(character_id, slot_id)` คือพฤติกรรม "สลับของ" ที่เมธอดนั้นเขียนไว้เอง
เปลี่ยนเส้นทางเฟรมไม่ได้เลย เพราะจุดเสียบไม่มี `return` และไม่นับเฟรม (ใบ chief `1718`: "ทุกเฟรมออกจากบล็อกนี้บนเส้นทางเดิมเป๊ะ")

### ไม่มี predicate ซ้ำ (บทเรียน `D7`)
ร่างแรกอ่าน `creation_gear_by_class.tsv` เองเพื่อเอา `n_SLOT_RHAND` — **นั่นคือ crosswalk ที่สองสำหรับคอลัมน์เดียว** ซึ่งเป็นทรง `D7` ที่สายนี้เคยโดนเก็บเงินมาแล้ว
แก้เป็น derive จาก `persistence_class_id.CLASS_PRESETS` ที่สายเราสร้างอยู่แล้ว (อ่าน `charcreate_class.tsv` ใต้ `class_catalog.SOURCE_SHA256`) ⇒ **ไม่มีการอ่านไฟล์เพิ่มแม้แต่ไฟล์เดียว ไม่มี sha ตัวที่สอง**
ตารางสองใบ **ตรงกันวันนี้** (`{1:2200002, 2:2200003, 4:2200006, 16:2200005, 32:2200008}` ทั้งคู่) และความตรงกันนั้นถูกพินเป็น **เทส** ไม่ใช่ถูกพึ่งพาเงียบ ๆ — วันที่มันเลิกตรงกัน เทสพูด ไม่ใช่โมดูลเลือกข้างเอง (นี่คือ `## งานสำรอง` ข้อ 3 ของสายเรา จ่ายพร้อมงานหลัก)
