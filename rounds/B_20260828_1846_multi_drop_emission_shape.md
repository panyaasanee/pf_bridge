## ④ ที่วัดได้จริงรอบนี้ (ไม่ใช่ข้อสรุป — เป็นการวัด)

ไฟล์ใหม่ `pirate-force-server/tests/test_ground_drop_multi_drop_emission_shape.py` (7 เทส เขียว, เขตเทสของสายตัวเอง)

1. **ฆ่าที่ดรอป N ชิ้น = N เฟรมแยกกัน แต่ละเฟรมเป็น collection `0x08` สมบูรณ์ในตัวเองที่ประกาศ count = ONE**
   (`DROP_ENVELOPE_PIN` ลงท้าย `0x12 0x01 0x00`) ⇒ เฟรมที่ k พูดว่า **"ลิสต์คือ [drop k]"** ไม่ใช่ "เพิ่ม drop k"
   ⇒ มัน **ละ** drop 1..k-1 ทิ้งไว้ข้างนอกทุกครั้ง
2. การละนั้นเป็นการละ **โดยเนื้อหา** ไม่ใช่แค่ไบต์นับ — ไม่มีเฟรมไหนมี element ของ drop ตัวอื่นอยู่เลย
3. 🔴 **ตัดคำอธิบายคู่แข่งออกด้วยไบต์:** census/ศพเดิน derived bit `0x02` -> object+`0x1C`
   (`pf_login_game_server_v141.py:1267-1272`) · ground เดิน `0x08` -> object+`0x20` (`mob_loot.py:227`)
   **คนละ bit คนละ offset = คนละลิสต์** ⇒ census recompose ที่เรายิงทุกครั้งที่ตี **ไม่ใช่** ตัวลบของบนพื้น
   และเฟรมของบนพื้นก็ลบเมืองไม่ได้
4. เพดาน `MAX_DROPS_PER_KILL = 16` ⇒ ถ้าอ่านข้อ 1 เป็นการลบจริง เสี่ยงหายได้ถึง **15 ชิ้นต่อการฆ่าหนึ่งครั้ง**

**ปลูก regression ยืนยันว่าเทสกัดจริง 3 แบบ** (ย้อนคืนครบแล้ว ไม่มี source ถูกแก้ในรอบนี้):
(ก) emitter สะสม element → 3 เทสแดง · (ข) envelope โกหกจำนวนเป็น 2 → 4 เทสแดง ·
(ค) ground bit กลายเป็น `0x02` → 4 เทสแดง รวมข้อ 3

🔴 **บันทึกความซื่อตรงของไฟล์ตัวเอง:** `mob_loot` มี guard ของมันเองที่ refuse ทรงเพี้ยน **ตอนรันในเซิร์ฟเวอร์**
(`REFUSE_COMPOSED_BYTES_OFF_PIN`, mob_loot.py:1461/1493) และ mutation (ก)/(ข) **ถูก guard นั้นจับก่อน**
assertion ของไฟล์ใหม่จะได้พูด ⇒ ไฟล์นี้ **ไม่ใช่ด่านแรก** ห้ามเขียนว่าเป็น · ของที่ไฟล์นี้ถือคนเดียวจริง ๆ คือ
(ก) การตัดคำอธิบายคู่แข่งในข้อ 3 และ (ข) **ลิเทอรัลที่เขียนไว้ในไฟล์เทสเอง** เพื่อไม่ให้รอบหน้าย้าย
ค่าคงที่กับเทสไปพร้อมกันแล้วยังเขียว (defect baseline วนกลับที่ `pf-adversary` จับได้ในรอบ `rbuta4`)
