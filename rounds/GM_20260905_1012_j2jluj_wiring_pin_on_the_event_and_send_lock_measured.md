อ่านไม่ได้ = ไม่ actionable) ไม่งั้นทิ้ง park โดยไม่ยิง = `park_abandoned_row_moved`
**ครั้งแรกไม่ถูกเกตเลย** (มันวิ่งในลมหายใจเดียวกับความล้มเหลวที่ติดอาวุธมัน) และมีเทสของตัวเอง
พูดแบบนั้น · `ParkExpiryTests` ใหม่ · **ถอดเกตออก = แดง 2 ใบ**
- **D2 HIGH** เทสงบประมาณอ่านตัวเลขออกมาจากโมดูลที่มันกำลังตรวจ ⇒ `MAX_ROLLBACK_ATTEMPTS = 1000`
  ทั้งไฟล์ยังเขียว **แก้**: ปักตัวเลขจริง + ปัก**ที่มา**ของตัวเลขใน v141 · มิวแทนต์ 1000 = **แดง**
- **D4 MEDIUM-HIGH ⇒ งบเป็น 2 ไม่ใช่ 3 และเลขนี้ derive ไม่ใช่เลือก**: `heartbeat_worker`
  `break` ออกจากลูปตั้งแต่การส่งที่ล้ม**ครั้งแรก** (`v141:7429-7431`) และ action loop `break`
  รายการ action ตั้งแต่ครั้งแรก ⇒ คอนเนกชันที่กำลังตายส่งล้มได้อย่างมาก **สองครั้ง** · ที่งบ 3
  สาขา "ยอมแพ้" (และ `RETRIES_EXHAUSTED_CONSOLE_TOKEN` ด้วย) **ไปไม่ถึงใน production**
- **D3 HIGH** ดอกสตริงอ้างตัวเลข "ต่อครั้งเดียว" ทั้งที่คอมมิตเดียวกันเพิ่งใส่ตัวคูณเข้าไป
  **แก้**: เขียนทั้งสองตัวเลข และ**วัด** aggregate ด้วยเทสใหม่ ไม่ใช่คูณบนกระดาษ
- **D5 MEDIUM** หมุดปัก `INSTALL_OK` ตัวเดียว ⇒ ถ้า chief ลง**รูป A** (ซึ่งโมดูลนี้เขียนเองว่ารองรับ
  และต่อสายถูกต้อง) หมุดจะ**แดงเท็จ** พร้อมข้อความโทษมิวแทนต์ผิดตัว **แก้**: รับสามผลลัพธ์ที่แปลว่า
  "ต่อแล้ว" และปล่อยเรื่อง liveness ให้เทส end-to-end ที่อ่านแถว DB
- **D6** เกต retry คีย์ที่**ชื่อคลาส exception** และ `store.py:270` มี `WriteLockTimeout` ที่เป็น
  subclass ของ `OperationalError` อยู่แล้ว **แก้เท่าที่เขตนี้ทำได้**: ใส่ทั้งสองสะกดเป็น frozenset
  พร้อมเขียนไว้ว่า `isinstance` คือกุญแจที่ถูก และชื่อคือกุญแจที่ผิด
- **D7 LOW-MEDIUM** ประโยค "`checkpoint()` ล้มที่ `BEGIN IMMEDIATE`" **ผิดประตู** —
  `SQLiteStore.connect()` เปิด DEFERRED โดยปริยาย และตัวที่รอคือ `UPDATE` ของ `save_position`
  ⇒ การ "ไม่ซ้อนกัน" จึงเป็นสมบัติของ **WAL** ไม่ใช่ของรูปทรานแซกชัน **แก้**: แก้ถ้อยคำสามที่
  + เทสใหม่ยืนยันว่า WAL มีผลจริง (`connect()` ตั้ง WAL เฉพาะฐานข้อมูลที่เป็นไฟล์)
- **D8** fixture ตัวสร้าง contention ส่งสัญญาณ "ถือล็อกแล้ว" จาก `finally` ที่วิ่งแม้
  `BEGIN IMMEDIATE` จะโยน ⇒ วินิจฉัยผิด **แก้**: สัญญาณอยู่บรรทัดถัดจากคำสั่งที่ยึดล็อกจริง
  + ส่ง exception ข้ามเธรดกลับมา + `join` มีขอบ
- **D9** ขอบเวลาเหลือ 1.0 วิสองที่ **แก้**: ขยายเป็น 3.0 วิทั้งคู่ และ `BUSY_TIMEOUT_S`
  **อ่านออกมาจาก `store.py`** ไม่ใช่พิมพ์มือ
- **D10** ทางเส้น retry ข้ามการเขียน event ของผลลัพธ์ ⇒ คนนับบน trail เห็นน้อยกว่าจริง
  **แก้**: ทุกครั้งเขียน event ของตัวเอง บรรทัด retry เป็นบรรทัด**ที่สอง** ไม่ใช่ตัวแทน
- **D11** `docs/GM_LANE.md` ยังบรรยายหมุดข้อความที่ถูกลบไปแล้ว และยังลิสต์คำถามสองข้อที่รอบนี้ปิด
  **แก้**: ขีดฆ่า ไม่ลบ (เขตของสายนี้)
