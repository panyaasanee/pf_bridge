## สิ่งที่สร้าง

**คำถามที่ต้องตอบก่อนเขียนโค้ด: สคริปต์หมายถึงอะไรเวลามันบอกว่า "แสดงข้อความ"**

ไม่มีสคริปต์ใดใน 616 ไฟล์ส่ง *สตริง* ให้ชื่อ message เลย — ส่ง **จำนวนเต็ม**
ทุกจุด และจำนวนเต็มนั้นคือเลขแถวใน `gamedata/tables/TEXTDATA_TH__MESSAGE.tsv`
(907 แถว · id 1..961 มีรู · คอลัมน์ `n_ID  n_TYPE  n_NOTIFY_TYPE  s_MESSAGE`)
หลักฐานสามขา — เขียนครบเพราะขา "ครอบคลุม" ขาเดียวตัดสินไม่ได้:

1. **ครอบคลุม** — literal id ทุกตัวที่คอร์ปัสส่งให้ `Player.ShowMessage` /
   `Trigger.TriggerShowMessage` / `Party.ShowMessage` มีแถวจริงครบ:
   `1, 4, 421, 824, 855, 856, 859, 860, 882, 885, 890, 897` (Player) และ
   `914..921` (Trigger) — ไม่มีตัวไหนหลุด
2. **หักล้างตารางคู่แข่ง ไม่ใช่เงียบใส่** — `TEXTDATA_TH__TIP_MESSAGE.tsv` จบที่
   id 561 ⇒ **หักล้างชัด** (17 จาก 20 id ไม่มีแถว). `TEXTDATA_TH__UI_MESSAGE.tsv`
   ครอบคลุมครบทุก id ตามช่วง **จึงไม่ถูกหักล้างด้วยความครอบคลุม** — หักล้างด้วย
   *เนื้อหา*: 855/856/859 ของมันคือป้าย UI "รายละเอียดสกิล" / "อัพสเตตัส" /
   "คะแนนสกิล:" ซึ่งไม่ใช่สิ่งที่เควสเด้งออกมาบอก
3. **ความหมายตรงกับ logic รอบข้าง** — `856` = "ยังไม่ได้รับภารกิจ หรือสถานะของ
   ภารกิจไม่สอดคล้อง" ถูกส่งตรงจุดที่สคริปต์เควสเช็คสถานะแล้วไม่ผ่านพอดี ·
   `855` = "จำนวนไอเทมถึงจำนวนที่จำกัดไว้แล้ว" · `859` = "จำนวนไอเทมที่เกี่ยวข้อง
   ไม่เพียงพอ" · `914..921` = บทพากย์ผู้ประกาศสนามประลอง และทั้งแปดตัวถูกส่งจาก
   ทริกเกอร์ `t_*_msg` ทั้งหมด

**ผู้ฟัง (argument แรกของ `TriggerShowMessage`)** มาจากคอมเมนต์หัวไฟล์
`gamedata/lua/t_msg_mod.lua` เอง (เข้ารหัส Big5 · ถอดแล้ว: "Var2 = ชนิดข้อความ
(1 個人 · 2 隊伍 · 3 場景 · 4 分流)") อ่านคู่กับ if-chain ในไฟล์เดียวกันที่แมป
`Var2 == 1 -> TriggerShowMessage(0,…)` · `== 2 -> 1` · `== 3 -> 2` · `== 4 -> 3`
⇒ ค่าบนสาย = เลขในคอมเมนต์ลบหนึ่ง: **0 คนเดียว · 1 ปาร์ตี้ · 2 ฉาก · 3 สาย**
literal ตัวเดียวที่คอร์ปัสส่งจริงคือ `2`; `0/1/3` มาทางกิ่ง `Trigger.Var2`

**โค้ด (รีโปเซิร์ฟเวอร์)**
- `lua_api/message.py` (ใหม่) — `CATALOG` 907 แถว, `is_known_message_id`,
  `notify_type`, ค่าคงที่ `AUDIENCE_*` + โดเมน `AUDIENCES`, และซีม
  `MessageSink` (`Protocol`) / `InMemoryMessageSink` รูปเดียวกับ
  `QuestStateStore` / `PlayerMobAppearStore` ที่รอบก่อนวางไว้
- `lua_api/message_catalog.tsv` (ใหม่) — ครึ่ง ASCII ของตารางที่เกมส่งมา
  (`message_id`/`message_type`/`notify_type`). **ตั้งใจไม่ vendor คอลัมน์ข้อความ
  ไทย `s_MESSAGE`** ตามแบบเดียวกับ `lua_api/api_spec.tsv` — และเขียนไว้ตรง ๆ ว่า
  นี่คือข้อจำกัดจริง ไม่ใช่ความเรียบร้อย: คนที่ยิงเฟรมจริงต้องใช้ข้อความ และ
  ข้อความอยู่ที่ตารางฝั่งสะพาน
- `lua_api/player.py` — `ShowMessage` ย้าย `STILL_STUBBED` → `REAL_METHODS`

  `REAL_METHODS` (`Trigger.*` จริง 8/17)

  สคริปต์เดียวกันลงบันทึกเรียงลำดับเดียวกัน — เหตุผลเดียวกับที่ `quest_store`
  ถูก normalize ที่นั่นอยู่แล้ว

closure ทั้งสอง **ปฏิเสธ ไม่ clamp**: id ที่ไม่มีแถวคือข้อความที่ client แสดงไม่ได้

`runtime.py`/`app.py` = **นอกเขตเขียนของสายนี้**

`src/pirateforce_foundation/*.py` แบบ **ไม่ recursive** ⇒ `lua_api/` ที่โค้ดรอบนี้
