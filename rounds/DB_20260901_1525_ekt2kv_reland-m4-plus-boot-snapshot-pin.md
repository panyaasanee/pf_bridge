### ชั้น wire-DB (สิ่งที่วัดได้จากฐานข้อมูลกับเทส ไม่ต้องมีคนนั่งหน้าจอ)

รันจริงรอบนี้ ตัวเลขไม่ได้เล่า:

**การพิสูจน์ว่าเทสไม่ใช่ละคร — mutation 7 อัน ทำจริงทุกอัน ไม่ใช่คำรับรอง** (บนสำเนาเวิร์กทรีทิ้ง)
สองอันแรกผมทำเองก่อนเรียกผู้ตรวจ · สามอันกลางเป็น mutation ของผู้ตรวจที่ **จับผมได้** แล้วรันซ้ำหลังแก้ ·
สองอันท้ายคือพื้นที่ที่ผู้ตรวจบอกว่าไม่ได้ตรวจ ผมตรวจเองต่อ:

| mutation | ผลที่วัดได้ |
| --- | --- |
| `sed 's/store.migrate_with_backup()/store.migrate()/g'` ใน `app.py` | หมุด `ast` **แดง** `+ ['migrate', 'migrate'] : app.py calls the unprotected migrate()...` |
| บังคับ `take, reason = (False, 'MUTANT')` ใน `migrate_with_backup` | เทสสำเนา **แดงทั้งสองตัว** `unexpectedly None : 006 was applied with no snapshot taken` |
| ลบ `AND deleted_at IS NULL` ออกจาก **UPDATE อย่างเดียว** | ก่อนแก้ **เขียวทั้งสวีต 6285** · หลังแก้ **แดง** `'deleted_at IS NULL' not found in "UPDATE characters SET level=9,... WHERE id=1"` |
| ย้าย `app.py:787` ไป `def _boot_migrate(store): store.migrate()` ระดับโมดูล | ก่อนแก้ **เขียว 42 passed** · หลังแก้ **แดง** `+ ['migrate']` |
| `_copy_consistent` → `shutil.copyfile` | ก่อนแก้ **เขียว** · หลังแก้ **แดง** `['SnapshotOne'] != []` "the snapshot lost a transaction that was committed into the write-ahead log" |
| ขอบ CHECK ในไฟล์ migration `level … AND 65535` → `655350` | **แดงสองที่** หนึ่งในนั้น INSERT ค่า `70000` จริงแล้ว expect ว่าถูกปฏิเสธ |
| ปิดกฎปฏิเสธ f32 underflow · ตัดการปัด f32 ก่อนเก็บ | **แดง 3 subtests** (`1e-300`, `5e-324`, `-1e-300`) · และ **แดง** ตามลำดับ |

สิ่งที่วัดได้เกี่ยวกับตัวข้อมูลเอง (จากเทสที่รันจริง ไม่ใช่การอ่านโค้ด):
- DB ที่ schema 005 มีตัวละคร `SnapshotOne` เจอ 006 → สำเนาเกิดก่อน · สำเนามี `characters`
  **ไม่มี** คอลัมน์ typed แม้ตัวเดียว · `schema_migrations` ของสำเนา **ไม่มี** version 6
- restore สำเนาแล้วเซิร์ฟเวอร์รุ่นก่อน 006 บูตขึ้น และ `SELECT name FROM characters` = `['SnapshotOne']`
- หลัง 006 บน DB สด: ทุกคอลัมน์ typed = `NULL` ทุกแถว (`test_existing_rows_survive_006_unchanged
  _and_the_new_columns_are_null`) — 006 ไม่ seed อะไรเลย ตามใบ `1447` ข้อ 2

## nonclaims

1. **ไม่อ้างว่ารอบนี้สร้างอะไรใหม่ในเชิงสคีมา** — `migrations/006` กับ `persistence_typed_attrs.py`
   เป็นงานของรอบ `hx8kli` ที่ cherry-pick กลับมาทั้งดุ้น ของใหม่ของรอบนี้มีสองอย่างเท่านั้น:
   การแก้คำอ้างที่กลายเป็นเท็จ 5 จุด และเทสสามตัวใน `BootSnapshotProtects006Tests`
2. **ไม่อ้างว่า 006 อยู่บน main** ตอนเขียนไฟล์นี้มันอยู่บนแบรนช์ `claude/inspiring-bohr-ekt2kv`
   และรอ PR ที่ยังไม่ได้เปิด/ยังไม่ merge — บอตเพิ่งปิด PR ของงานชุดเดียวกันไปหนึ่งใบด้วยเหตุ conflict
   จึงไม่มีใครควรถือว่ารอบนี้ "แน่นอนแล้ว" จนกว่าจะเห็นมันบน main
3. **ไม่อ้างว่ากลไกสำรองเคยทำงานบน canonical DB ของเจ้าของ** — ยังไม่เคยแม้ครั้งเดียว ทุกอย่างที่วัดมา
   วัดบนฐานข้อมูลชั่วคราวใน `tempfile.TemporaryDirectory()` ครั้งแรกบน canonical จริงคือจ็อบยกระดับ
   ที่ผมขอ chief เขียนในใบ `1515` ข้อ ข.2 ซึ่งยังไม่มีใครเขียน
4. **ไม่อ้างว่าหมุด `ast` ป้องกันทุกทาง** มันเฝ้า `main()` ของ `app.py` เท่านั้น ถ้าใครย้ายการเรียก
   ไปฟังก์ชันช่วยระดับโมดูล หมุดจะแดงที่ข้อ `assertGreaterEqual` (ไม่เงียบ) แต่ถ้าใครเพิ่มเส้นทางบูต
   **ที่สอง** ในไฟล์อื่นทั้งไฟล์ หมุดนี้มองไม่เห็น — ผมเขียนข้อนี้ไว้ในใบถึง chief ตรง ๆ แล้ว
5. **ไม่อ้างว่า `speed_walk` คือความเร็วของผู้เล่นจริง** ชื่อคอลัมน์ยังเป็นการระบุที่ยังไม่พิสูจน์
   สำหรับ player object (`BasicAttr+0x54` / bit `0x0040` พิสูจน์แล้วที่ชั้น NPC เท่านั้น) และสองชั้น
   ยังถือเลขคนละตัว (150.0 vs 400.0) รอ RE ที่ COO สั่ง chief เปิดในใบ `1447` ข้อ 2
6. **ไม่อ้างว่า `persistence_canon_gate.py` มีอยู่** — ยังไม่เขียนแม้บรรทัดเดียว ใบ `1515` ข้อ (ข)
   คือ **สัญญาเรียกใช้ที่จะทำให้เป็นจริง** ไม่ใช่รายงานของที่ทำแล้ว และผมเขียนเตือน chief ไว้ในใบว่า
   อย่าเพิ่งต่อสาย ps1 ก่อนโมดูลลง main
7. **ไม่อ้างว่ารอบนี้แตะอะไรนอกเขตเขียน** ไฟล์ที่แก้ในรอบนี้: `migrations/006_*.sql` (ไฟล์เลขใหม่
   ยังไม่เคย apply ที่ไหน) · `persistence_typed_attrs.py` · `persistence_attr_compose.py` ·
   `tests/test_persistence_typed_attr_columns.py` — ทั้งสี่อยู่ในเขต · ที่ cherry-pick มาเพิ่มอีกสี่
   (`store.py` = เมธอดใหม่สองตัว ไม่แตะเมธอดเดิมแม้ตัวเดียว · `tests/test_persistence_attr_compose.py`
   = เทสของงานผม · หมุดนับ migration สองไฟล์ = บรรทัดละหนึ่งจุด แจ้ง chief ไว้แล้วในใบ `1416`)
8. 🔴 **ไม่อ้างว่าหมุด `ast` รับประกันว่า "มีสำเนาแน่นอน"** — 006 ถูกล็อกด้วย checksum ทันทีที่ apply
   ถ้า `app.py` ถอยกลับไป `migrate()` ในบูตที่เกิด **ก่อน** ที่ใครจะรันสวีตนี้ สำเนาของบูตนั้นไม่เคยถูกถ่าย
   และไม่มีเทสไหนทำให้มันย้อนกลับมามีได้ หมุดนี้ **ย่นช่วงเสี่ยงให้สั้นลง ไม่ได้ปิดมัน** (ข้อนี้ผู้ตรวจ
   ตั้งเป็นคำถามค้างของดีไซน์ ผมยกให้ COO ในใบ `1520` ไม่ตัดสินเอง)
9. **ไม่อ้างว่าตรวจครบทุกซอกในไฟล์เทสของตัวเอง** ผู้ตรวจเตือนว่า "ในไฟล์นี้มี assertion แบบ grep
   อย่างน้อยอีกหนึ่งตัวและผมไม่ได้ตรวจที่เหลือ" ผมไล่ `assertIn/assertRegex` ทั้งไฟล์แล้ว (20 จุด)
   และ mutation-test สามพื้นที่ที่เขาระบุ — ผ่านทั้งหมด แต่ **ไม่ได้ mutation-test ทุกจุดทีละจุด**
   ที่ยังไม่ได้ตรวจแน่ ๆ: concurrency จริงสองโปรเซสบน `write_typed_attributes` (`BEGIN IMMEDIATE`
   contention) และ 323 skip ของสวีต ว่ามีอันไหนเกิดใหม่จากดิฟนี้หรือไม่
10. **ไม่อ้างว่าเจ้าของหรือ COO ยืนยันอะไรในรอบนี้** ไม่มีมนุษย์อยู่ในรอบนี้ ทุกอย่างที่เขียนว่า "ตัดสิน"
   คืออ้างจดหมายที่ลงไว้ก่อนหน้า ไม่ใช่การยืนยันสด

   `UNCHANGED` / `EXPLAINED_BY_MIGRATION` / `UNEXPLAINED` + CLI ตามสัญญา exit code `0`/`20`/`13`
