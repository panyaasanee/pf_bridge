## ทำอะไร (โค้ดเซิร์ฟเวอร์ · `pirate-force-server` PR ด้านล่าง)

รางวัลของสายนี้เคยมีครบสองอย่างแต่ไม่ต่อกัน: **ตัวเลข** (`quest_criteria` ถอดจากตารางเกมจริง) กับ **ประตูเขียน** (`store.add_typed_attribute` ของ LANE-DB) — สิ่งที่ไม่มีคือ **ชื่อ API ที่พาตัวเลขไปหาประตู** รอบนี้เพิ่มประตูที่สองและชื่อสองชื่อแรก

1. `lua_api/reward.py`
   - แยก `_store_delta()` ออกจาก `pay()` — สามด่านตรวจคำตอบของ store (raise / ไม่ใช่ int / `balance_after` ต่ำกว่า delta) เหลือ **implementation เดียว** ใช้ร่วมทั้งสองประตู ⇒ store ที่โกหกจะไม่ผ่านประตูหนึ่งแล้วโดนจับอีกประตู
   - เพิ่ม `grant(api_name, kind, character_id, amount, ...)` — ประตูของ "จำนวนที่ **สคริปต์** เป็นคนบอก" (ต่างจาก `pay()` ที่จำนวนมาจากตาราง) · เหตุผลปฏิเสธใหม่สองตัว `unknown_reward_kind` · `amount_is_not_an_integer` (แยกจาก "ติดลบ" เพราะเป็นคนละข้อเท็จจริง)
2. `lua_api/player.py` — **`Player.AddExp` · `Player.AddSkillPoint` เป็น REAL** (จาก 143 STUB → 141): แปลง argument ตัวเดียวจาก Lua · ปฏิเสธค่าติดลบ/NaN/inf/bool/สตริง **ก่อน** แตะ store · คืน `STUB_DEFAULT` แม้จ่ายสำเร็จ (ดู nonclaims)
3. `script_host.py` — พารามิเตอร์ `payout_store` ตัวเดียว ส่งให้ **ทั้ง** Quest และ Player namespace ⇒ หกชื่อ `Quest.Add*Criteria*` (673 จุดเรียก) จ่ายได้ทันทีที่ caller ยื่น store จริงมาให้ · default `None` = ทุก caller เดิมยังปฏิเสธเสียงดังเหมือนเดิม
4. `lua_api/quest.py` — เปลี่ยนชื่อพารามิเตอร์ `reward_store` → `payout_store` (ไม่มีผลต่อพฤติกรรม) เพื่อไม่ให้ `script_host.py` มีสัญลักษณ์ที่ชนคำเฝ้าระวังของ chief — **แจ้ง chief เป็นจดหมายเอง ไม่ปล่อยให้ไปเจอใน diff**
