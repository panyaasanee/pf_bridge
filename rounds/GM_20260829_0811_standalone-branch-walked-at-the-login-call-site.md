## ⓵ ของจริงที่สร้าง — `tests/test_gm_login_scene_override_standalone_at_login.py` (5 เทส)

`consume_login_scene_override` มีสี่ผลลัพธ์ และไฟล์ offline เดินครบทั้งสี่ แต่ **จุดเรียกจริง** ใน `runtime.py`
มีกิ่งละผลลัพธ์ และก่อนรอบนี้เดินแล้วแค่สาม:

| ผลลัพธ์ | ใครเดินผ่าน dispatcher จริง (ก่อนรอบนี้) |
|---|---|
| `CONSUMED` | `test_gm_login_scene_override_position_resync` |
| `NOTHING_STAGED` | ตัวคุมของไฟล์เดียวกัน |
| `CONSUME_FAILED` | `test_gm_login_scene_override_wiring` |
| `STANDALONE_NOT_CONSUMED` | **ไม่มีใครเลย** |

ช่องว่างนี้ **PR #236 เขียนไว้เองในหัวข้อ "not proven here"** ว่า "no test asserts the `standalone_kept` event"
และมันกว้างกว่าชื่อ event ที่หายไปหนึ่งชื่อ: `COO-DECISION 20260829_0542` ข้อ 4 สั่งให้สายนี้มีเทสตรึงว่า
แผนที่ standalone ไม่ถูกบริโภค · ของที่สายนี้มีอยู่แล้ว (`test_gm_standalone_map_is_not_chat_writable`)
เฝ้า **ไฟล์** · ไม่มีอะไรเฝ้า **ล็อกอิน** ⇒ จุดเรียกจะกินใบทิ้ง หรือจะติดป้ายว่า `consumed` ให้ของที่ไม่ได้กิน
ก็ได้ทั้งคู่ โดยที่ชุดเทสทั้งชุดยังเขียว

เทสห้าข้อ ทุกข้อเดินผ่าน `state.dispatch` ด้วยแพ็กเก็ตไคลเอนต์จริง ไม่มีข้อไหนเรียก
`consume_login_scene_override` ตรง ๆ:

1. บัญชีที่ **ไม่ใช่ GM** ซึ่งมีชื่อในแผนที่ standalone ไปถึงฉากนั้นจริง (เทียบกับ `resolve_entry` ที่แยกกันคำนวณ)
   และคอนโซลได้ `gm_login_scene_override_standalone_kept_2` · `consumed_2` กับ `consume_failed` ต้องไม่มี
2. ใบไม่ถูกกิน — **พยานสองปาก**: ไบต์ของไฟล์เท่าเดิม **และ** ล็อกอินครั้งที่สองได้ฉากเดิมอีก
   (จุดเรียกที่เขียนไฟล์ทับด้วยเนื้อเดิมจะผ่านปากแรกแต่ตกปากที่สอง)
3. **ตัวเทียบ**: ใบแบบ GM-gated ยัง **ถูกกิน** ด้วย harness เดียวกัน ฉากเดียวกัน — ตอบตรงข้ามทั้งสองปาก
   ถ้าไม่มีข้อนี้ ประโยค "ใบยังอยู่" คือคำอ้างที่ไฟล์นี้ไม่มีทางทำให้แดงได้
4. ล็อกอินแบบ standalone ก็เป็น **visit** เหมือนกัน (ธง guard อยู่ที่ "มี override" ไม่ใช่ "มาจากแผนที่ไหน")
   — ข้อนี้สำคัญที่สุดถ้าพลาด เพราะ standalone ถูกให้ใหม่ **ทุกล็อกอิน** ⇒ ถ้าเขียนแถวจริง แถวกับ config
   จะเห็นตรงกันตลอดไป และวันที่ผู้ดูแลลบบรรทัดออก ตัวละครค้างอยู่ในฉากที่อาจไม่มีตั๋วกลับ (`CHARTER-02` ข้อ 2)
5. 🔴 **กฎข้อหนึ่งของสายนี้ วัดบนเส้นทางเดียวที่ทำลายมันได้**: `gm_login_scene_standalone.json` เป็น config
   เดียวในสายนี้ที่ให้อะไรกับบัญชีที่ **ไม่อยู่ใน `gm_accounts`** ⇒ ถ้าการมีชื่ออยู่ในนั้นแถมสถานะ GM มาด้วย
   แผนที่นี้จะกลายเป็นทางเป็น GM โดยไม่ได้เป็น GM · วัดที่ **action** `GM_UPDATE_STATE_AFTER_LOGIN`
   ซึ่งเป็นที่ที่เฟรมสถานะ GM เดินทางจริง (ไม่ใช่ที่ `state.events`) พร้อมตัวคุมที่เป็น GM จริงและ **ได้** เฟรมนั้น

**GATE-WALK** (`COO-DECISION 20260829_0742`) เขียนเป็นย่อหน้าในไฟล์เทสเอง: กิ่งที่เดิน · กิ่งที่ไม่เดินพร้อมเหตุ
