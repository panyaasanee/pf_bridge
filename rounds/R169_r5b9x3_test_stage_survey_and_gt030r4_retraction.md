## ⑨ ที่รอบนี้ **ไม่** ได้พิสูจน์

- **ไม่ได้แตะรีโปโค้ดเลย** — รอบนี้เป็นรอบเอกสาร/คิวล้วน · ไม่มี PR ฝั่ง `pirate-force-server`

- **ไม่ได้เปิดไฟล์เรขาคณิตของฉากใดเลย** — คลาวด์มีแค่ `.placements.tsv` · **`0 placements` ไม่เท่ากับ "ฉากว่าง"**

## ⑩ 🔴 ภาคผนวก (วัดหลังปิดรอบ) — **ลำดับปิดรอบของ v5 ข้อ ⑥ ใช้จริงไม่ได้ · ต้องสลับ ② กับ ③**

โดยให้เหตุผลว่า *"`ready_for_review` ไม่อยู่ใน `types:` ของ workflow แต่ `edited` อยู่ ⇒ การแก้หัวข้อคือสิ่งที่ปลุก merge job"*

**สิ่งที่เกิดขึ้นจริงในรอบนี้ (วัดแล้ว · PR #74):**

| เวลา (UTC) | เหตุการณ์ |
|---|---|
| ~14:31 | push commit งานจริง `5d080a4` (PR ยังเป็น draft ⇒ workflow ข้าม) |
| ~14:32:1x | chief เรียก `update_pull_request` ด้วย `draft: false` — **ยังไม่ได้แตะหัวข้อเลย** |
| **14:32:22** | 🔴 **`github-actions[bot]` merge PR เรียบร้อยแล้ว** (`merged_by: github-actions[bot]`) |

⇒ 🔴 **ขั้นตอน ③ ไม่มีโอกาสได้รัน — PR ถูก merge ไปก่อนตั้งแต่ขั้นตอน ②**

**ตรวจ trigger จริงของ workflow บน `main`** (`.github/workflows/merge-claude-pr.yml:58-60`):
```
on:
  pull_request_target:
    types: [opened, reopened, synchronize, edited]
```
✅ **prompt พูดถูกว่า `ready_for_review` ไม่อยู่ใน `types:`** — แต่ **ข้อสรุปที่ต่อจากนั้นผิด**
สิ่งที่เกิดคือ **การ PATCH ผ่าน GitHub API เพื่อถอด draft ทำให้เกิด event `edited` ไปด้วย** (tool ส่ง field ชุดเดิมกลับไป)
⇒ **การถอด draft เพียงอย่างเดียวก็ปลุก merge job แล้ว** ไม่ต้องแก้หัวข้อ

### 🟢 ลำดับที่ถูก — **สลับ ② กับ ③ เท่านั้น ไม่ต้องเปลี่ยนอย่างอื่นเลย**
