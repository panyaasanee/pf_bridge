### 1 `new_character_vitals()` — ข้อ 1 ของใบ `0443` (ทาง ข)
`src/pirateforce_foundation/persistence_vitals.py:575` คืน
`{"level": 1, "hp_current": 100, "hp_max": 100}` คีย์เป็นชื่อคอลัมน์ (`:571-572` เป็นค่าคงที่
`NEW_CHARACTER_LEVEL` / `NEW_CHARACTER_HP`) ป้ายกำกับคือป้ายเดียวกับที่ `007` แบก:
`TRANSCRIBED from player_wire hardcode -- original game default OPEN`

สามอย่างที่ตั้งใจให้เป็นแบบนี้ ไม่ใช่รายละเอียด:
- **คืน dict ใหม่ทุกครั้ง** ไม่ใช่ mapping ที่แชร์กัน — คนเรียกที่ไปแก้ค่าที่ได้มา ต้องเปลี่ยน
  ค่าที่ตัวละครคนถัดไปเกิดมาถือไม่ได้ มีเทสที่ลบคีย์ทิ้งแล้วเรียกซ้ำ
- **ตรวจตัวเองก่อนคืน** ผ่าน `resolve(...).require()` ของโมดูลเอง วันนี้มัน fail ไม่ได้
  ประเด็นคือถ้าวันหนึ่งมีคนแก้ค่าจนผิดกฎ มันจะพังตรงจังหวะสร้างตัวละคร ไม่ใช่เขียนแถวที่
  `read_character_vitals` จะปฏิเสธไปตลอดชีวิตของตัวละครนั้น
- **ไม่มี DEFAULT ไม่มี migration ใหม่** ตามข้อ 2 ของใบ (ห้ามทาง ก) ตารางไม่ถูก rebuild
  ไม่มีไฟล์ `.db` ไหนถูกแตะ รอบนี้ไม่มี migration เลยแม้แต่ไฟล์เดียว

## nonclaims — สิ่งที่รอบนี้ **ไม่** ได้อ้าง

1. **ไม่อ้างว่าตัวละครใหม่มีเลือดแล้ว** `new_character_vitals()` เป็น **ค่า** ไม่ใช่การเขียน
   ไม่มี INSERT ไม่มี UPDATE ไม่มี connection ในฟังก์ชันนี้ ตัวละครที่สร้างวันนี้ยังได้ NULL
   สามคอลัมน์เหมือนเดิมทุกประการ จุดเสียบเป็นของ chief ตามข้อ 1 ของใบ `0443`
2. **ไม่อ้างว่า M4 ปลดล็อกครบ** ตามข้อ 5 ของใบ `0443` ตรง ๆ: ประโยคนั้นใช้ได้เฉพาะตัวละคร
   ที่มีอยู่ตอน `007` รัน จนกว่าใบ `0444` จะขึ้น `main` และรอบนี้ไม่ได้ทำให้มันขึ้น
3. **ไม่อ้างว่า 1/100/100 คือค่าเริ่มต้นของเกมเดิม** ป้าย TRANSCRIBED บอกขอบเขตไว้แล้ว:
   มันคือเลขที่เซิร์ฟเวอร์นี้ส่งอยู่แล้วทุกครั้งที่ล็อกอิน ไม่ใช่คำตอบของ RE ค่าจริงยัง **OPEN**
   วันที่ RE ตอบและตอบไม่ตรง ทางแก้คือแก้ `NEW_CHARACTER_*` ที่เดียว + migration ใหม่
   (ห้ามแก้ `007` ตามข้อ 3 ของใบ `0250`)
4. **ไม่อ้างว่าเทสสองสถานะพิสูจน์ว่าใบ `0444` ถูกต้อง** มันพิสูจน์แค่ว่า *ถ้า* แถวจบลงที่ค่าชุดนี้
   ทางอ่านรับ census นับ และ `_plug_has_landed` มองเห็น ผมไม่ได้เห็นโค้ดของ chief เลย
5. **ไม่ได้แตะ canonical DB** ไม่มี migration ใหม่ ไม่มี SQL ตรง ไม่มีสคริปต์เฉพาะกิจ
   UPDATE ที่มีในรอบนี้อยู่ในไฟล์เทส ทำงานบนไฟล์ชั่วคราวใน `tempfile` เท่านั้น
6. **ไม่ได้ประกาศไมล์สโตนเอง** ถ้าจะนับว่า M4 ขยับ ต้องเป็น chief/COO เป็นคนเคาะ
7. **ไม่อ้างว่ารอบนี้วัดครบทุกอย่างแล้ว** สิ่งที่วัดคือ `pytest tests/` ทั้งชุดในสองสถานะ
   สิ่งที่ **ไม่ได้** วัดคือจุดเสียบจริงของ chief (ยังไม่มีโค้ด ผมจำลองเอง) และพฤติกรรมในเกม
   ฉบับแรกของรอบนี้เขียนตัวเลข 15 จากการวัดผ่านไฟล์ตัวเอง — นั่นคือความผิดพลาดของรอบนี้เอง
   ไม่ใช่ของใคร และเป็นเหตุผลที่ nonclaim ข้อนี้มีอยู่
