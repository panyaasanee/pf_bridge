## ผู้เทสจะทำอะไรได้ที่เมื่อวานทำไม่ได้

เมื่อวานคำถาม "ถ้า `RE-129` ตอบแล้ว เปิดใช้ `/warp` ได้เลยไหม" ไม่มีคำตอบที่ผูกกับอะไรเลย
มีแต่ประโยคในจดหมาย · วันนี้ `RE-129` **ตอบแล้ว** และผู้เทสได้ของสองอย่าง:
(1) คำตอบว่า **ยังไม่เปิด** พร้อมเหตุผลที่วัดได้สองชั้น (คำตัดสิน COO เรื่องเจ้าของตำแหน่ง
และ handler ของ client ที่เป็น `mov al,1; ret 4`)
(2) เทสที่**บังคับ**คำตอบนั้น ⇒ `GT-128` จะไม่ถูกบูตในสภาพที่ client ยืนจุดใหม่แต่ DB จำจุดเก่า
(aggro / ระยะเก็บของ / จุด logout ผิดตามกันทั้งชุด โดยไม่มีสัญญาณเตือน)
และใบ `GT-128` เองก็มีขั้นตอนใหม่ที่ทำให้ตัดสินได้จริงเมื่อถึงวันบูต (เดินหนึ่งก้าวหลัง warp
แล้วดูโทเคน) แทนที่จะเดาว่าแถวใน DB ตามทันหรือไม่

## เกณฑ์สองชั้น

- wire/DB: `RE-129` (static, ผู้อื่นวัด, ใบ DONE/PASS) — รอบนี้ไม่ได้เพิ่ม wire fact ของตัวเอง
  และ**ไม่มีไบต์ออกสาย**
- client-observable: **ไม่มีของรอบนี้** ไม่มีการบูตเกม ไม่มีการยิงเฟรม

## nonclaims

1. **[ไม่อ้าง]** ว่ารอบนี้ทำให้ `/warp` ส่งไบต์ได้ — ตรงกันข้าม รอบนี้คือรอบที่ยืนยันว่ายังไม่ส่ง
   และเขียนด่านที่ทำให้เปิดเองไม่ได้
2. [ไม่อ้าง] ว่า `vital_version = 0` แปลว่าไคลเอนต์จะขยับ — `RE-129` nonclaim 3 พูดตรงกันข้าม
3. [ไม่อ้าง] ว่าชื่อแกน x/y/z ของ `ForcePosBody` ถูก — `RE-129` T2 ปิดเฉพาะ offset
   `+0x14/+0x18/+0x1C` และให้ bounded negative กับชื่อ ⇒ ยัง `[สมมติของสาย GM - รอ RE]`
4. [ไม่อ้าง] ว่าปุ่ม `BT_GM` ใช้การได้ — `RE-126` พิสูจน์แค่ว่า binding ถูกตัว ไม่ได้อธิบายความเงียบ
   และเตือนเองว่าทางแชทไม่ใช่ทางเข้าอีกทางของ `GMUI_BASIC`
5. [ไม่อ้าง] ว่าเทสรอบนี้แทน gate จริงได้ — มันซ้อนทับเฉพาะกฎเดียว (ล็อกของ COO) ในเขตของสายนี้
6. **GM nonclaim:** ทุกอย่างในสายนี้เป็นเครื่องมือเพื่อไปให้ถึงสภาพที่จะเทส
   **ไม่ใช่**หลักฐานว่าฟีเจอร์ใดทำงาน หรือว่า milestone ใดผ่าน
