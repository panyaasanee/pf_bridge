## 4. งานของรอบ -- `COO-DECISION 2342` ข้อ 3

### สิ่งที่พัง (และมันไม่ใช่ทฤษฎี)
`install.bat` มีเกตเดียวที่อ่านตัว DLL: `dumpbin /headers | findstr .rsrc`
มันเห็น **เซกชัน** `.rsrc` เท่านั้น manifest ที่ฝังผิดที่ `;#1` (id ของ EXE ห่างจากคำสั่งที่ถูกหนึ่งตัวอักษร)
**ทิ้งเซกชัน `.rsrc` ไว้ในภาพ** ⇒ เกตขึ้น `[ok]` และ DLL ยังตอบ `LoadLibraryW` ด้วย 14001 เงียบสนิท
= อาการเดียวกับบั๊กที่ปลั๊กอินตัวนี้เกิดมาเพื่อแก้ · ตัวที่แยกออกได้มีตัวเดียวคือ `plugin_image_check`
ที่ parse resource tree และบังคับ id 2 -- และจนถึงรอบนี้มันเป็นแค่ **คำแนะนำที่พิมพ์อยู่ใน README**

### สิ่งที่ลง (`patches/gm_plugin/install.bat` revision 3)
เรียก `pirateforce_foundation.gm.plugin_image_check` **จริง** วางไว้ใต้เกต `[STOP]` และใต้เกต `.rsrc` เดิม (คงไว้ทั้งดุ้นตามใบ)

| กิ่ง | พฤติกรรม | ที่มา |
|---|---|---|
| ไม่มีล่าม Python 3 / หา checkout ไม่เจอ | `[warn]` แล้ว **ติดตั้งต่อ** | `2342` ข้อ 3 (fail-open เฉพาะกิ่งนี้) |
| ตัวตรวจตอบ ไม่ใช่ `image_ok` | `[FAIL]` **ไม่ copy** exit 1 | `2342` ข้อ 3 (fail-closed) |
| ตัวตรวจรันแล้ว **ไม่พิมพ์ verdict เลย** | `[warn]` แล้วไปต่อ **คนละข้อความกับกิ่งแรก** | **[สมมติของสาย GM - รอ COO ยืนยัน]** ดูข้อ 5 |

รายละเอียดที่เป็นเรื่องเป็นราว ไม่ใช่สไตล์:
- **หาล่ามด้วยการสั่งให้มันรัน ไม่ใช่ด้วย `where`** -- `py` launcher ติดตั้งได้โดยไม่มี 3.x อยู่ข้างหลัง
  และ `python.exe` บน PATH เป็น Python 2 ได้ ซึ่ง `import` โมดูลนี้ไม่ผ่านเลย (`from __future__ import annotations`)
  ⇒ ถามทีละตัว `py -3` → `python` (เช็ค `version_info[0] == 3`) → `python3`
- **หา checkout จาก `%PF_SERVER_REPO%` ก่อน** แล้วค่อยมองข้าง ๆ โฟลเดอร์ที่เก็บ `pf_bridge`
  (`Pirate Force ServerProject\src` = ค่าตั้งต้นจริงของ `pf_git_sync.ps1:85` แล้ว `pirate-force-server\src`)
  ตัดสินว่า "เจอ" จากไฟล์ `plugin_image_check.py` เอง ไม่ใช่จากโฟลเดอร์
- **`--dll` อย่างเดียว ห้ามเติม `--client-dir`** -- บล็อกนี้อยู่ **ใต้** เกต `[STOP]` ที่พิสูจน์ไปแล้วว่าโฟลเดอร์ปลายทาง
  **ไม่มี** `GameMaster.dll` ⇒ `--client-dir` จะได้ `verdict=missing` แล้ว exit 1 **ทุกครั้ง**
  = ปฏิเสธติดตั้งถาวรบนโฟลเดอร์สะอาดซึ่งเป็นโฟลเดอร์ที่การติดตั้งมีไว้เพื่อมัน (เขียนเป็นเทสไว้แล้ว ไม่ใช่แค่คอมเมนต์)
- **ตัดสินด้วย exit code **และ** บรรทัด verdict ทั้งคู่** ไม่ใช่อย่างใดอย่างหนึ่ง

### สิ่งที่ลงฝั่งเซิร์ฟเวอร์ (`tests/test_gm_plugin_image_check.py` +5 เทส)
`install.bat` อ่านผลด้วย `findstr /c:` ซึ่งเป็น **substring match ไม่ anchor** และ batch `import` อะไรจากโมดูลไม่ได้เลย
⇒ ชื่อโทเคนคือสัญญาที่ไม่มีคอมไพเลอร์ตัวไหนบังคับ ถ้ามีคนเปลี่ยน label `build` หรือคำว่า `verdict=`
`install.bat` จะ **ตกไปกิ่ง "ไม่มี verdict" ซึ่ง warn แล้วไปต่อ** = เงียบทั้งสองฝั่ง เทสห้าตัวจึงตรึง:
1. ทางผ่านพิมพ์ `GM_PLUGIN_IMAGE build verdict=image_ok` เป๊ะ
2. manifest ที่ id 1 → exit != 0 **และ** พิมพ์ `verdict=manifest_missing`
3. ภาพที่ถูกปฏิเสธ **8 ทรง** ไม่มีทรงไหนพิมพ์สตริง `verdict=image_ok` ออกมาเลยแม้ในร้อยแก้ว (นี่คือช่องของ substring match)
4. `--dll` เดี่ยว = เขียว และไม่แต่งรายงานเรื่อง client dir ขึ้นมาเอง
5. เติม `--client-dir` ชี้โฟลเดอร์สะอาด = `verdict=missing` + exit 1 (วัดไว้ ไม่ใช่แค่เตือนในคอมเมนต์)
