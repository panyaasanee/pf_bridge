## 1. งานแรก: ประตูจดหมายเลิกเดาจาก layout แล้วไปถาม git ว่าไฟล์ shallow อยู่ไหน

รอบก่อน (`av245e`) เขียนทางผ่อนสำหรับโคลน shallow ไว้ **แล้วทางผ่อนนั้นเองผลิตความผิดที่มันมีไว้กัน**
รอบนี้แก้ 6 ข้อจาก 11 ข้อของ adversary · ไฟล์เดียว `tests/test_mob_death_widening_schema_gate.py` · ไม่มีโค้ดโปรดักชัน ไม่มีเฟรมถึงไคลเอนต์

### D3 (เหตุผลที่ marker ถูกถอน) — `git rev-parse --shallow-list` ไม่ใช่ออปชันของ git
`rev-parse` สะท้อนโทเคนที่ไม่รู้จักกลับมาแล้ว exit 0 ⇒ เซตกลายเป็น `{"--shallow-list"}` ⇒ ไม่มี sha ตรงเลย ⇒
**จดหมายทุกใบใน worktree ของโคลน shallow ถูกประกาศว่าปลอม** และนั่นคือต้นไม้ที่โปรโตคอล pf-adversary ของบ้านนี้สร้างเองทุกครั้ง
แก้เป็น: `--is-shallow-repository` ตัดสินก่อนว่ามี graft ไหม → `--git-path shallow` หาไฟล์ (ผ่าน worktree/submodule ที่ `.git` เป็นไฟล์)
→ **หาไม่เจอ = คืนเซตว่าง = แดง** ตาม `COO-DECISION 0945` ข้อ 1 ("ห้าม derive จากหาไม่เจอ") · sentinel `<unknown-graft>` ตายไปพร้อมกัน
เทสใหม่สร้าง `clone --depth 1` จริง แล้ว `git worktree add` จริงบนนั้น และบังคับว่า graft ทุกตัวต้องเป็น sha 40 ตัวอักษร

### D1 — จดหมายที่ถูกกวาดเข้า archive ต้องยังอ่านลายมือ `COO:` ได้
วัดบนสะพาน: 14/14 ใบใน `archive/` รายงานคอมมิตกวาดเป็นผู้เพิ่ม ⇒ การกวาดครั้งถัดไปทำให้กุญแจ 19 ใบแดงพร้อมกัน
`_swept_origin()` เดินสายโซ่ rename แต่ **(ก) เป็นหลักฐานที่เพิ่มเท่านั้น** (ถาม add ตรงก่อนเสมอ) **(ข) รับเฉพาะต้นทางที่ชื่อไฟล์เดียวกัน**
🔴 ข้อ (ข) ไม่ใช่ความระวังลอย ๆ — **วัดในรอบนี้**: `--follow` ของ git ตั้ง `find_copies_harder` ⇒ มันเดินย้อนเข้าไฟล์ที่ไม่เคยถูกลบได้
⇒ ถ้าไม่กันชื่อไฟล์ สายหนึ่งจะ `cp` จดหมายจริงของ COO ไปเป็นชื่อ stamp อื่น **แล้วสืบทอดลายมือ COO สำหรับกุญแจที่ COO ไม่เคยเซ็น**
(เทสสองใบ ใบหนึ่งเป็นด้านความสามารถ ใบหนึ่งเป็นด้านความปลอดภัย · เทสเก่าที่ปัก "MEASURED, not desired" ไว้ ตอนนี้ยืนยันว่าแก้แล้ว)
