### 2.2 สิ่งที่สร้าง (อยู่ในเขตผมทั้งหมด)
`src/pirateforce_foundation/lua_api/quest_state_store.py` **(ไฟล์ใหม่)**
- `StoreBackedQuestStateStore` — เขียนตามสัญญาของ LANE-DB **ชื่อต่อชื่อ ลำดับอาร์กิวเมนต์ต่อลำดับ**
  ไม่ออกแบบใหม่แม้แต่ข้อเดียว ตามที่ใบสั่งกำชับ
- `quest_state_store_for(store, log)` — ประตูครบ = คืนตัวจริง · ไม่ครบ = คืน `None` **พร้อม log
  `LUA_QUEST_STATE_VOLATILE` ที่ระบุชื่อประตูที่หายไปทีละบาน** · `store=None` ก็รายงานแบบเดียวกัน
- ท่าปฏิเสธ: `KeyError` (ตัวละครไม่มี/soft-deleted) · `ValueError` (id นอก u16) ·
  `WriteLockTimeout` (จับผ่านตระกูล `sqlite3.Error` — ไม่ import `store` เข้ามาใน `lua_api`) ·
  แถวรูปร่างเพี้ยน ⇒ **log `LUA_QUEST_STATE_REFUSED` + ตอบ "ไม่มีความคืบหน้าถูกบันทึก" ไม่ raise กลับเข้า Lua**
  (ถ้า raise sweep จะเขียน `LUA_SCRIPT <ไฟล์> ERR` = **โทษสคริปต์แทนเรา** = รูป D9/D11 เป๊ะ)
  · error **นอก**สามตระกูลนั้น **ไม่ถูกกลืน** (`TypeError` จาก adapter ที่ต่อผิด = บั๊กของผม มีเทสจับ)
- `quest.DEFAULT_CONTEXT` (character 0) **ไม่มีวันไปถึง store** — id จริงเริ่มที่ 1 ⇒ บริบท default ยังคงเฉื่อยตามที่มันมีไว้เพื่อสิ่งนั้น
- log มีเพดาน `REFUSAL_LOG_CAP = 256` คีย์ต่างกัน เพราะ `SetFlag`/`GetQuestFlag` เป็นสองชื่อที่จุดเรียกเยอะที่สุดในทั้ง API (416+489)

`lua_api/quest.py` **แก้บรรทัดเดียว**: `InMemoryQuestStateStore.durable = False` (คู่กับ `True` ของตัวทน relog)
⇒ ผู้เรียกแยกออกได้ว่า "รอด relog" กับ "ระเหย" โดยไม่ต้อง isinstance ข้ามโมดูล — **นี่คือสิ่งที่ทำให้การถอยกลับไปใช้หน่วยความจำ "ดังขึ้น" แทนที่จะเงียบ**
