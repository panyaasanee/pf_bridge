## 2.6 รอบนี้ตอบคำถามนั้น: **ผู้ปฏิเสธชนะ**

- `walk_agrees_with_the_frame()` + `WalkGate` — ทางผ่อนปรน (หางต่อท้าย) จะเดินได้ก็ต่อเมื่อ **ทั้งเฟรมเดินผ่าน
  `vital_walk` ได้จริง** · ไม่ผ่าน = `tail_refused_by_vital_walk` (ชื่อใหม่ในทะเบียน) + คอนโซลบอกชื่อของ **ตัวเดิน** ด้วย

  ⇒ กฎ "อ่านทุกฟิลด์ครั้งเดียว" ของเลนนี้ไม่ถูกทำลายในคอมมิตเดียวกับที่เพิ่มการ์ด (และตัวเดินยัง re-derive envelope จากไบต์เอง)

## 2.7 pf-adversary รอบสอง หักล้าง "ตัวแก้" ของข้อ 2.6 — และมันก็ถูกอีก

รันบนตัวแก้ที่เพิ่งเขียน · ผลสำคัญคือ **ตัวแก้ของผมทำให้ผู้เล่นเสียคลิกจริง** (วัดด้วยการบูตเซสชัน + control สองชั้น):

1. 🔴 **D1 — `[Pickup][UpdateServerSetting 0x0F01]` ถูกปฏิเสธ** ทั้งที่ต้นไม้ก่อนแก้อ่านคลิกนั้นได้
   ตารางความยาวของ `vital_walk` มี **4 แถว** แต่ `legacy.NAMES` มี **49 id** ⇒ **46 id หยุดตัวเดิน**
   และ `0x0F01` อยู่ใน `CAPTURE_NOISE_IDS` ของ `v141` เอง = id ที่มันบอกว่าไคลเอนต์ส่ง **ตลอดเวลา**
   ตัวจุดที่สอง: เฟรมที่ประกอบตามการอ่านความกว้างของ `TARGET_POS_VITAL` **อีกแบบหนึ่ง** ซึ่ง `vital_walk`
   เขียนเองว่ายังตัดสินไม่ได้ ⇒ คำถามที่ยังไม่มีคำตอบเรื่องแถวของคนอื่น กลายเป็นราคาที่ผู้เล่นจ่ายเป็นคลิก
2. **D2** — ทางอนุมัติของ tail path ไม่มีจุดเรียกโปรดักชันเหลือเลย (gate เป็น False เสมอบนดิสแพตช์จริง)
3. **D4** — gate เดิน `raw_pc` แต่ decode อ่าน `nested_payload` และไม่มีอะไรผูกสองอย่างเข้าด้วยกัน
4. **D5/D6** — การ์ดหกจุดที่ไม่มีเทสฆ่าได้ · ชื่อ refusal หกชื่อที่ **ไม่อยู่ในทะเบียนใด** ถูกพิมพ์ออกคอนโซล

### สิ่งที่รอบนี้ตัดสิน (กลับทิศจากข้อ 2.6 ในรอบเดียวกัน)

**คำปฏิเสธของตัวเดินเป็น "บรรทัด" ไม่ใช่ "คำตัดสิน"** — แยกด้วยเกณฑ์ว่า *คำตัดสินนั้นพูดถึงอะไร*:
- `unknown_vital_id` / `truncated_vital` / `trailing_bytes_after_last_vital` = คำตัดสินเกี่ยวกับ **ไวทัลของคนอื่น**
  ตัดสินด้วยตารางที่ยอมรับเองว่าขาด 46 id ⇒ **ไม่ใช่หลักฐานเกี่ยวกับเจ็ดไบต์ของเรา** ⇒ ไม่ปฏิเสธ แต่ **พิมพ์บอก**
  (`MOB_PICKUP_REQUEST_WALK_DISAGREES walk=<ชื่อของตัวเดิน>`) ⇒ คำสัญญา "ให้การปฏิเสธยังดังอยู่" ของ `R309` ยังอยู่ครบ
- `envelope_reread_disagrees` = ผู้อ่านสองคน **ไม่เห็นตรงกันว่านี่คือเฟรมอะไร** ⇒ อันเดียวที่ยัง **ผูก** (ปฏิเสธ)
  และเฟรมจากสายจริงสร้างมันไม่ได้ ⇒ ย้ายชื่อไปตระกูล API-only พร้อมตัวขับที่เป็นรูของ D4 พอดี (ปิด D4 ด้วยชื่อเดียวกัน)
- ชื่อทุกชื่อที่พิมพ์หลัง `walk=` ถูกขึ้นทะเบียน (`MOB_PICKUP_REQUEST_WALK_GATE_NAMES` + ทะเบียนของตัวเดิน)
  ชื่อนอกทะเบียน = `unregistered_walk_reason` (แก้ D6)
- พิสูจน์ไม่ vacuous **สองทิศ** ด้วยมิวแทนต์: ลบรายการที่ผูก → ตัวขับ API-only แดง · ผูกทุกชื่อ → เทส "คลิกต้องรอด" แดง
  รวมถึงเทสชั้นดิสแพตช์ที่บูตเซสชันจริงแล้วยิงคลิกที่ซ้อนหลัง `0x0F01`

🔴 **บทเรียนที่ต้องเขียนไว้**: รอบนี้เกือบ ship "ตัวแก้ความปลอดภัย" ที่แพงกว่ารูที่มันปิด และชุดเทสเต็มเขียวทั้งสองสถานะ
สิ่งที่จับได้คือ adversary ที่บูตของจริงและถามว่า *"ตัวแก้นี้ทำให้ผู้เล่นเสียอะไร"* ไม่ใช่แค่ *"มันปิดรูไหม"*
