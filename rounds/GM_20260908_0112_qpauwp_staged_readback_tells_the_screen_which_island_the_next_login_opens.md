## รอบนี้ทำอะไร (โค้ดที่คนหน้าไคลเอนต์เห็นผลเอง)
`/warp` ข้ามฉากไม่ได้ย้ายใคร มัน**เขียนฉากของล็อกอินครั้งหน้า**ลง `config/gm_login_scene.json`
แล้วเงียบ — คำสั่ง GM ทุกตัวที่มีผลถาวรแต่ไม่มีอะไรขยับบนจอ **พูดบนจอ**หมดแล้ว (`LV SET RELOG`,
`SPEED DENIED`, `TYPO REFUSED`) เหลือ warp ที่รายงานตัวเองแค่บน**คอนโซลเซิร์ฟเวอร์** ซึ่งไม่ใช่ที่ที่
คนพิมพ์คำสั่งกำลังมองอยู่ ผู้ปฏิบัติงานที่หน้าเกมมีทางเดียวที่จะรู้ว่าล็อกอินหน้าจะเปิดฉากไหน คือ
**เปิดไฟล์ JSON ข้างเกมอ่านเอง**

รอบนี้เพิ่มคำสั่ง `staged` — คำสั่งที่**ไม่เปลี่ยนอะไรเลย**: อ่านแผนที่ที่สายนี้เขียนเอง เฉพาะบัญชี
ตัวเอง แล้วตอบบนช่อง local-talk เดียวกับสามประโยคข้างบน
```
staged   -> SCENE 000278     (มีฉากค้างอยู่ · ตัวเลขคือ scene id)
staged   -> NO STAGE SET     (บัญชีนี้ไม่มีแถวในแผนที่)
staged   -> STAGE NOREAD     (อ่านแผนที่ไม่ได้เลย)
```
- **ตัวอักษรทุกตัวมาจากสายนี้เองหรือจาก `int`** ที่ loader ตรวจกับตารางฉากที่ commit แล้ว —
  `staged` **ไม่รับอาร์กิวเมนต์เลย** จึงไม่มีโทเคนที่ผู้ใช้พิมพ์ให้ echo ตั้งแต่แรก (กันชนิดเดียวกับที่
  รอบ `osxc85` ต้องไล่ปิดทีหลังในฟอร์ม `warp <ชื่อ>` — D2)
- **ยาว 12 อักขระ ASCII เป๊ะ ทุกคำตอบ** = ความยาวที่ `say_wire.NOTICE_TEXT_EXACT_LENGTH` พินไว้จาก
  หลักฐานจริง (GT-006/GT-009) เทสกวาดทุก id ที่ฟอร์มหกหลักเรนเดอร์ได้ (0, 1, 9, 10, 123, 99999,
  999999) ไม่ใช่สุ่มตัวอย่าง — บอดี้ที่ยาวผิดจะถูกปฏิเสธ**ที่ปลายทาง หลังคำสั่งทำงานไปแล้ว**
