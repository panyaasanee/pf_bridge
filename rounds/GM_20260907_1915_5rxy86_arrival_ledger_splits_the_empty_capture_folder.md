**ขอบเขตที่จ่ายไป เพราะไฟล์นี้เขียนให้บัญชีที่ไม่ใช่ GM โดยตั้งใจ** (นั่นคือประโยชน์ทั้งหมดของมัน —
`gm/dispatch.py` มีอยู่เพื่อถือหลัก "ไม่เขียนอะไรให้การเชื่อมต่อที่ไม่ใช่ GM" ผมจึงไม่เขียนทับหลักนั้น
แต่ตั้งไฟล์ไว้**คนละโฟลเดอร์พี่น้อง** แล้วจ่ายด้วยขอบสี่ข้อ):
1. **ไม่มีไบต์ payload ลงดิสก์เลย** มีแต่ `len=` เป็นจำนวนเต็ม — peer ที่ยังไม่ยืนยันตัวตนเอาไบต์ที่เลือกเองลงดิสก์ผ่านทางนี้ไม่ได้
2. **ทุกฟิลด์ถูกกรองและตัดความยาว** (ตัวกรองเดียวกับ `command_capture._sanitize_account`) ⇒ หนึ่งเฟรม = หนึ่งบรรทัดเสมอ · ค่าที่ไม่ใช่ `str` **ไม่ถูก `str()` บังคับ** (ให้ `__str__` เขียนอะไรก็ได้ลงไฟล์ไม่ได้) ตกไป fallback แทน
3. **งบบรรทัด per account** 24 บรรทัด/บัญชี · ติดตาม 32 บัญชี · เกินนั้นใช้ถังรวมถังเดียว 32 บรรทัด
   ⇒ peer ที่ถล่ม **กินได้แต่งบของตัวเอง** (denial of evidence by flooding คือการโจมตีที่ตรงที่สุด
   กับไฟล์ที่คุณค่าทั้งหมดคือ "มีบรรทัดอยู่") · งบหมดแล้วพิมพ์ `GM_VITAL_LEDGER_FULL` **หนึ่งครั้งต่อถัง**
   เพื่อให้ "ไม่มีบรรทัดเพราะงบหมด" ต่างจาก "ไม่มีบรรทัดเพราะไม่มีอะไรมา"
   🔴 **รูปแรกของรอบนี้แยกงบเป็น authorized/unauthorized ซึ่ง adversary วัดแล้วว่า *ผิด* (D1)** —
   เฟรมของผู้ทดสอบเองคือฝั่ง **unauthorized** (นั่นคือเหตุผลที่ไฟล์นี้มีอยู่) ⇒ ผู้เล่นธรรมดาคนเดียว
   ส่ง 64 เฟรมก็ทำให้บรรทัดของผู้ทดสอบไม่มีที่เขียน = ทำซ้ำความล้มเหลวที่โมดูลนี้เกิดมาเพื่อจบพอดี · แก้แล้วในคอมมิตที่สอง
4. **บรรทัดแรกของทุก process** `GM_VITAL_LEDGER_OPENED` มี **pid + absolute path** และพิมพ์ลงคอนโซลหนึ่งครั้ง
   — cwd ของเซิร์ฟเวอร์ที่ไม่ตรงกับที่ผู้อ่านเปิดอธิบายอาการ "ไม่มีโฟลเดอร์โผล่มาเลย" ของ R322B ได้ดีพอ ๆ กับโลกอื่น
   และไฟล์นี้ append ข้ามรอบบูต ถ้าไม่มีหัวต่อ process ก็แยกบรรทัดของ `pytest` กับของสายจริงไม่ออก
5. **ไม่มีทางที่ ledger จะทำให้ dispatch พัง** — `OSError` ถูกกลืน · `capture_root` ที่แปลงเป็น path ไม่ได้ก็ถูกจับ
   (เดิมเส้น non-GM ไม่เคยแตะ `capture_root` เลย ⇒ ถ้าไม่จับจะเสียทั้ง event และบรรทัดคอนโซลพร้อมกัน — D5)
   · เขียนไม่สำเร็จ = **ไม่กินงบ** · `os.write` **วนจนครบ** ไม่ใช่เรียกครั้งเดียวแล้วเชื่อ (short write เขียนครึ่งบรรทัด
   แล้วบรรทัดถัดไปต่อท้ายเข้าไป — สายนี้แก้บั๊กชนิดเดียวกันมาแล้วสามที่ในแพ็กเกจนี้ D2)

**จุดเสียบ**: `_authorize_and_capture` **ครอบ** gate chain (แยกออกเป็น `_run_gate_chain` โดยไม่แก้ลำดับ
authorize → rate limit → payload size → quota → write แม้แต่บรรทัดเดียว) ⇒ ทางออก**ทุกทาง**บันทึกหนึ่งบรรทัด
รวมทางที่ raise (`outcome=raised_ValueError`) · จุดเข้าสองใบส่ง id ของตัวเอง (`0x51E9` / `0x6CEC`)
ไม่แตะ `runtime.py` (นอกเขต)

**สิ่งที่โมดูลเขียนไว้ในตัวเองว่าบรรทัดที่ *หายไป* ไม่พิสูจน์อะไร**: ไม่ได้แปลว่าไคลเอนต์ไม่ส่ง —
งบหมด / เขียนไม่สำเร็จ / โฟลเดอร์เขียนไม่ได้ / process ตายกลางทาง ให้ผลเดียวกัน · ทิศที่แข็งคือ
**มีบรรทัด = เฟรมถึงสายนี้แน่นอน** ทิศเดียว
