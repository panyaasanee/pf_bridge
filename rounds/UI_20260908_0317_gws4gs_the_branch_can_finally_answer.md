## nonclaims
- ไม่อ้างว่าผู้เล่นทำอะไรได้เพิ่ม — ทะเบียนว่าง ทุกเฟรมได้ `[]` เหมือนเมื่อวาน
- ไม่อ้างว่ารู้ความหมายของแปด vital · ไม่อ้างว่ารู้รูป **เฟรมตอบ** ของคลาสไหนเลย
  (แคตตาล็อกที่มีคือสิ่งที่ **ไคลเอนต์ส่งมา** ไม่ใช่สิ่งที่เซิร์ฟเวอร์ต้องส่งกลับ — นั่นคือใบ RE ที่แถวนี้ยังติดหนี้)
- ไม่อ้างว่า `_actions_are_well_formed()` ครอบทุกรูปที่ผู้บริโภคปลายทางรับได้ — มันตรวจ **คอนเวนชันที่โปรเจกต์ใช้อยู่**
  (`(label, pc, frame, delay)`) ไม่ใช่สัญญาที่ผู้เขียน dispatcher เซ็นไว้ที่ไหนสักแห่ง · ไม่จำกัดขนาดเฟรม
- 🔴 **ไม่อ้างว่ารูปที่ตัวตรวจรับ = รูปที่ถูกต้อง** — รอบนี้พิสูจน์ว่าผมเดาผิดมาแล้วหนึ่งครั้ง (`int` แทน `bytes`)
  สิ่งที่พินไว้ตอนนี้คือ action **จริง**จาก dispatcher ผ่านตัวตรวจได้ ไม่ใช่ความเห็นของผมว่าอะไรถูก
- ไม่อ้างว่าเกตที่อ่าน "โมดูลที่เรียก" กันได้ทุกทาง — ผู้ลงทะเบียนผ่าน decorator/`exec` ชั้นกลาง
  ยังทำให้เฟรมที่อ่านได้เป็นโมดูลกลางนั้น (adversary รอบสองกำลังวัดข้อนี้อยู่ตอนปลดล็อก)
- ไม่อ้างว่ากฎป้าย `UI_` กันการชนกับซับซิสเต็มอื่นได้ทั้งหมด — มันกันป้ายที่ **มีอยู่จริง**วันนี้
  (`_gm_warp_note_position_pending` แมตช์เต็มสตริง · `_move_authority_note_server_moves` แมตช์ substring `TELEPORT`
  ⇒ ป้าย `UI_..._TELEPORT_...` ยังเข้าเงื่อนไขนั้นได้ ถ้ามีคนบูตด้วย scenario ที่เปิดทางนั้น — บันทึกไว้ ไม่ได้แก้)
- ไม่อ้างว่าเกต `production_allowed` ป้องกันโค้ดของสายที่ยังไม่อนุมัติ **ตอน import** — มันกันแค่ตอน "ตอบ"
  ไฟล์ผู้ตอบยังถูก import โดย `_discover()` ตามปกติ
