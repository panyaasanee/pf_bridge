### แก้แล้วในรอบนี้ (คอมมิตหลัง adversary)

**1 (รุนแรงสุด) — โทเคน `LUA_QUEST_PAYOUT` ถูกเทียบกับอะไรไม่ได้เลย** `pay()` ตรวจแค่ว่า
ยอดที่ store ตอบเป็น `int` **ไม่เคยเทียบกับเลขที่ตัวเองขอให้บวก** ⇒ store ที่เป็น
`def add_typed_attribute(...): return 0` (เขียนอะไรไม่ได้เลย) ทำให้ได้บรรทัด
`paid=1050 balance_after=0` พร้อม `reason=None` — **บนหลักฐานชิ้นเดียวที่รอบหน้าถูกสั่งให้ใช้วัดซีมนี้**
🔴 แก้: คอลัมน์ทั้งสามใน `KIND_COLUMN` มี `CHECK(>= 0)` (migration 006) และ delta เป็นบวกเสมอ
⇒ **`balance_after >= delta` ต้องจริงเสมอสำหรับ atomic add ที่ถูกต้อง ไม่ว่ายอดเดิมเท่าไร** —
ซึ่งเป็นคำกล่าวที่แข็งที่สุดที่ผู้เรียกซึ่ง**ไม่อ่านยอด**พูดได้ · ตรึงขอบทั้งสองด้าน
(เท่ากับ delta พอดี = การจ่ายครั้งแรกของตัวละคร ต้องผ่าน)

**5 — `int(inf)`/`int(nan)` โยน exception ทะลุ `pay()` ที่เขียนว่า "NEVER RAISES FOR A REFUSAL"**

**รอบนี้เองคือคนเปิดทาง** เพราะรอบก่อน `player_level` ถูก hard-code เป็น `None` รอบนี้ทำเป็น
