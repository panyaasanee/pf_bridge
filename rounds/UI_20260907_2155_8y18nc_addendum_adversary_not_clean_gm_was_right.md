## D2 — `--emit --artifact <สารบัญ>` **ทำลายสารบัญต้นฉบับ แล้ว exit 0 พิมพ์ `PASS`**
วัดบนสำเนา: md5 `173f662e` -> `9f211939` · หัวไฟล์กลายเป็น `id<TAB>name<TAB>family...` (สำมะโน 328 แถวทับ 327 ชื่อ)
`main()` เขียน `args.artifact` โดยไม่ตรวจว่าไฟล์ที่กำลังจะทับเป็น artifact จริงไหม ทั้งที่ `ARTIFACT_HEADER` อยู่ห่างสามฟังก์ชัน
🔴 และ**ข้อความ error ใหม่ของผมเอง**ที่บอกว่า "the artifact path is `--artifact`" คือสิ่งที่พาคนที่สลับแฟล็กทางหนึ่ง
ไปสลับอีกทางหนึ่งพอดี — การ์ดที่ปิดประตูหน้าแล้วชี้ทางไปประตูหลังที่ยังเปิด

## D3 — **การ์ดของผมกว้างเกิน คำอ้างข้อ 4 ของรอบนี้ผิด**
สารบัญจริงมีบรรทัด `#` **สี่บรรทัด** (`grep -c '^#'` = 4) และบรรทัดที่ 4 คือ `# id<TAB>name` เป๊ะ
⇒ สารบัญ**มี**หัวตารางที่การ์ดของผมล่าอยู่ รอดเพราะอักขระ `# ` สองตัวเท่านั้น
วัดแล้ว: `sed '4s/^# //'` (สารบัญแท้ 327 ชื่อ) ⇒ `CENSUS ERROR ... looks like this tool's own emitted artifact` `exit 2`
สารบัญจริงถูกกล่าวหาผิด ๆ และไม่มีทางข้าม · ทางแก้: เทียบบรรทัดแรกที่ไม่ใช่คอมเมนต์กับ `ARTIFACT_HEADER` (6 คอลัมน์)

## D4/D5/D6 (วัดแล้วจริงทั้งหมด)
- D4 `--emit --tsv <ไฟล์ผิดอื่น>` เขียน artifact ใหม่แล้ว `PASS` เสมอ — `--emit` เขียนก่อนเทียบ จึงเท่ากันโดยโครงสร้าง
- D5 "two leading lines are `#` comments" ผิดในของที่ส่งไปแล้ว **สามที่** (คอมเมนต์การ์ด · ไฟล์รอบ · ใบ `2129`)
