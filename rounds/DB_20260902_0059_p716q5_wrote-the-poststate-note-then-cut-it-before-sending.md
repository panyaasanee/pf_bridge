## เรื่องที่ผู้ตรวจชี้แล้ว **ยังไม่ได้แก้** (จดไว้ ไม่กลบ)

ทั้งหมดนี้อยู่ในโค้ดที่ **ถอนออกไปแล้ว** จึงไม่ได้อยู่ใน PR รอบนี้ แต่ถ้า COO สั่งทาง (ก) หรือ (ข)
โค้ดนั้นจะกลับมา และต้องแก้ทั้งชุดก่อน:

- **D4** `os.open` สำเร็จ แล้ว `os.write` ล้ม (ENOSPC) ⇒ เหลือไฟล์ 0 ไบต์ และ `O_EXCL` ทำให้
  ชื่อนั้นเขียนไม่ได้อีกตลอดกาล = ยาพิษถาวร · ไม่มี `fsync` · ทิ้งค่าคืนของ `os.write`
- **D3** เทส `test_the_whole_world_deleted...` ของผมมี `return` เปล่า ๆ กลางเทส = skip ที่ไม่มีชื่อ
  ไม่มีเลข ไม่ขึ้นใน `-rs` — ห่างจากการ "เกรดศูนย์อย่างเงียบ ๆ" แค่ความกว้างของแถวเดียว
- **mutant ที่รอด**: `poststate_filename` ไม่ `.lower()` · `is_file()` → `exists()` ·
  `hot_wal_bytes` คืน `0` แทน `-1` เมื่อ OSError (= fail-**open** ตรงข้ามกับที่ docstring อ้าง)
- **`settled` vs `actual`** เป็น equivalent mutant จริง (บรรทัดเหนือคืนไปแล้วถ้าต่างกัน)
  ⇒ คอมเมนต์ที่ผมเขียนว่า "ตรวจกับ `settled` เป็นเรื่องสำคัญ" **พิสูจน์ไม่ได้** ต้องเขียนใหม่ให้ตรง

นอกจากนั้น เรื่องที่รู้มาก่อนและยังไม่แก้: `evaluate` → `_snapshot_is_still_good` →
`_verify_snapshot` **ลบ `-wal`/`-shm` ข้างสำเนา**ทุกครั้งที่ด่านตรวจ (ลบเฉพาะ sidecar ที่ตัวมัน
เพิ่งสร้าง จึงไม่เสียข้อมูล แต่ผิดกฎข้อ 3 ของโมดูลนั้นเอง และลบพอดีสิ่งที่ `restore_hint` สั่งให้คนกู้วาง)
ทางแก้คือให้ด่านเปิดสำเนาด้วย `immutable=1` — diff เล็ก เกรดง่าย เก็บไว้รอบหน้า
