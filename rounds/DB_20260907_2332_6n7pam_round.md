## 1. งานหลัก: EXP → เลเวล (`persistence_experience` + `store.grant_experience`)
**ทำไมเป็นงานของผู้เล่น ไม่ใช่งานท่อ**: วันนี้ payout ที่ถึง `characters.experience` (ทาง
`Player.AddExp` → `store.add_typed_attribute`) ทำให้ **ตัวเลขโตอย่างเดียว** — ไม่มีโค้ดที่ไหน
ในรีโปแปลง EXP เป็นเลเวล ตัวละครจึงค้างที่เลเวลตอนเกิดตลอดกาล

**กฎมาจากตารางของไคลเอนต์ ไม่ใช่จากสายผม**: `persistence_standard_status` พิน
`CONSTDATA_TH__STANDARD_STATUS` ด้วย sha256 และระบุผู้บริโภคที่พิสูจน์แล้วตัวเดียวของ
`n_EXP_CURRENTLV` ไว้ในตัวเอง — แถบ EXP ของไคลเอนต์ (`0x519299`) หาร EXP ที่แสดงด้วย
`STANDARD_STATUS[level+1].n_EXP_CURRENTLV` · ตัวหาร = เกณฑ์ ⇒ เลเวลขึ้นตอนแถบเต็มพอดี
- `threshold_for_next_level(level)` = แถว `level+1` · คืน `None` ที่เพดานตาราง (255)
  · เกณฑ์ `<= 0` = ปฏิเสธพร้อมชื่อแถว (ลูปจะแจกเลเวลฟรีตลอดกาล — บนตารางที่ commit ไว้ไม่มีแถวแบบนั้น
  แต่ไม่ไว้ใจอยู่ดี)
- `plan_experience_gain(level, experience, amount)` = เลขล้วน ไม่มี DB ⇒ เทสวัดกฎได้โดยไม่ต้องมี store
- `store.grant_experience(cid, amount)` = กฎเดียวกันใน `BEGIN IMMEDIATE` เดียว: อ่านคู่
  `level`+`experience` → วางแผน → `validate` ทั้งคู่ → `UPDATE ... AND level=? AND experience=?`
  → **read-back** · ค่าที่คืนเป็นค่าจากแถวจริง ไม่ใช่ค่าที่วางแผน

🔴 **ส่วนที่ derive ไม่ใช่วัด** (เขียนกำกับใน docstring และมีเทสปักทั้งสองครึ่ง): เศษ EXP ยกไปเลเวลถัดไป
ไม่ใช่รีเซ็ตเป็นศูนย์และไม่ใช่สะสมรวม — ตัวเศษที่สะสมรวมทำให้การหารเกิน 1.0 ทุกเลเวลหลังเลเวลแรก
ซึ่งแถบวาดไม่ได้ · วันไหนมีผลวัดค้าน เทสจะแดงแทนที่จะเงียบ

**สองประตูบนคอลัมน์เดียว** (บทเรียน `D4` ของ adversary รอบก่อนเรื่อง `skill_points`):
`add_typed_attribute` **ไม่ถูกแตะเลย** และยังบวกโดยไม่ขยับเลเวล — มีเทสชื่อ
`TheOtherDoorIsUnchangedTests` ปักไว้ · payout หนึ่งใบเลือกประตูเดียว · การทำให้ประตูเก่า
**ปฏิเสธ** `experience` ไปเลยจะเปลี่ยน behavior ของประตูที่ LANE-Q เรียกอยู่ตอนนี้
⇒ ไม่ทำเงียบ ๆ · ถามเป็นข้อเดียวในจดหมายถึง LANE-Q แล้ว
`[สมมติของสาย LANE-DB - รอ COO ยืนยัน]` ว่าปล่อยสองประตูไว้ก่อนคือคำตอบที่ถูกในรอบนี้

## 3.5 พินที่คอมมิตแรกทำแดง — ปลดในใบเดียวกัน (`2050`)
ชุดเต็มจับได้ว่า `tests/test_persistence_standard_status.py` พินไว้ว่า "ไม่มีโมดูล production ไหนเอ่ยชื่อ

ที่ปลดได้ ในใบของตัวเอง พร้อมเขียน docstring ใหม่และเทสใหม่ที่ระบุผู้เรียก — ซึ่งรอบนี้เป็นใบนั้นพอดี

`EXPECTED_CALLERS` ออกจากค่าว่าง — คอมมิตนั้นคือคอมมิตนี้)
สิ่งที่มาแทนไม่ใช่ allowlist เปลี่ยนชื่อ: (ก) เทส **กลไก** ที่บิดหนึ่งแถวในหน่วยความจำแล้ววัดว่าคำตอบของ
ผู้เรียกขยับตาม ⇒ ผู้เรียกที่ก๊อปตัวเลขออกไปหรือ import แล้วไม่ใช้ = แดง (ข) เทส AST ว่ามี import จริง
(ค) census เดิมทุกประการ เปลี่ยนแค่เซ็ตที่คาดหวังจากว่างเป็นชื่อผู้เรียกหนึ่งชื่อ ⇒ สายที่สองที่ต่อสายเข้าตารางนี้
ยังทำให้แดงเหมือนเดิม
