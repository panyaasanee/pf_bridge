## 4. งานหลัก — `AvatarAttr` ใบตรวจก่อน (`0205` เรื่องที่ 1, กติกา 14.13 (ง))

### สิ่งที่ต้องตรวจ

Codex ปิด `AvatarAttr` (→ `DBAttribute` **ไม่ใช่** `BasicAttr`) ครบ 22 entry และรีโปนี้

ห้ามสั่งแก้**

### สิ่งที่วัดได้ และวัดจากอะไร

🔴 **ข้อเท็จจริงที่พลิกทั้งใบ: โค้ดที่รันอยู่ "เดินบอดี้ครบทุกฟิลด์" อยู่แล้ว**
`current/pf_login_game_server_v141.py:2224 extract_avatar_attr_wire_from_actor`
(แช่แข็ง เขตของ chief **ไม่แตะ**) เดินแบบนี้:

```
u8 tag 0x0B  -> base_flags            (common-Attr)
ถ้า flags & 0x01 -> raw8 tag 0x32     (identity u64)
u32 tag 0x26 -> mask                  <-- ตรงกับ Codex "+0x28 u32 tag 0x26" เป๊ะ
bit 0..11  -> u32 tag 0x14  (12 ช่อง)
bit 12 -> u8 0x0B · bit 13 -> u8 0x08 · bit 14 -> u8 0x08 · bit 15 -> astr
bit 16 -> u8 · bit 17 -> u32 · bit 18 -> u8 · bit 19 -> u8 · bit 20 -> u32
```

⇒ ไม่ได้ "ทึบ" อย่างที่คอมเมนต์สามจุดบอก · ที่ทึบคือ **ชื่อ** ไม่ใช่ **โครง**

**ไบต์จริงที่ใช้วัด**: `get_preset_actor_wire()` → `_V25_REAL_CREATE_PC` คือ create submit
ที่ capture จากไคลเอนต์ตัวจริง ไม่ใช่ของสังเคราะห์ · บอดี้ยาว **103 ไบต์**
`base_flags = 0xFF` · `mask = 0xFFFFFFFF` · และ walker กินหมดพอดี 103 ไม่เหลือเศษ

**ผลของการตรวจ — วางออฟเซ็ตตามลำดับสายแล้วชื่อของ Codex ลงตรงทุกตัว:**

| Codex | bit | ความกว้าง | ค่าในไบต์จริง |
|---|---|---|---|
| `+0x2C n_DRESS_HAT` | 0 | u32 | `0` (ไม่ใส่หมวก) |
| `+0x30 n_HRID` | 1 | u32 | `0x00114009` |
| `+0x34 n_HDID` | 2 | u32 | `0x0010EFF0` |
| `+0x38 n_FCID` | 3 | u32 | `0x0010F01A` |
| `+0x3C n_ETID` | 4 | u32 | `0` |
| `+0x40` เสื้อ | 5 | u32 | `0x0023187A` |
| `+0x44` ขา | 6 | u32 | `0x0023187B` |

| `+0x58` มือซ้าย | 11 | u32 | `0x002191C2` |
| `+0x5C n_GENDER` | 12 | u8 | **`1` = หญิง** ตรงกับที่ Codex ระบุ |
