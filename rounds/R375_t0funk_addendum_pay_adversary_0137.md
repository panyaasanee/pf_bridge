# ภาคผนวก R375: จ่ายผล pf-adversary รอบสองบนงาน CORE-REQUEST 0137 · ปลด draft PR แล้ว

## พบอะไร

pf-adversary รอบสอง (เจาะจงงาน `0137`) ยืนยันคำกล่าวอ้าง "เฉื่อยจริงวันนี้" ถูกต้อง (`production_allowed
= False` จริง สองชั้นกัน — `_discover`/`_withdraw` ถอนออกจาก `_SCENE_CHOOSE_NPC_RESPONDERS` ตอน import
และจุดเรียกเช็ค `module_production_allowed` ซ้ำอีกชั้น) แต่พบข้อบกพร่องจริงหนึ่งข้อในตัวโค้ดเอง:
`actions.extend(response.extra_actions)` กับลูป `setattr` ของ `latches_spent` **อยู่นอก try/except**
ที่คุ้มครองทุกจุดอ่านค่าเปราะบางอื่นที่จุดเรียกเดียวกัน (`mob_loot_cell`, `mob_death_register`,
`mob_combat_ledger`, ตัวเรียก `respond()` เอง) — วัดจริงด้วยการปลอมสาย responder ตอบ
`extra_actions=None` แล้วขับ dispatch จริง ได้ `TypeError: 'NoneType' object is not iterable` หลุด
ออกมาจาก `state.dispatch()` โดยไม่มีใครจับ — ตรงกับ interlock X07 ของ `pose_trial.py` เองที่บันทึกไว้ว่า
`game_listener` รอบ `dispatch()` ไม่มี except handler เลย = เธรดฟังของ connection นั้นตาย

ไม่มี responder ที่ลงทะเบียนอยู่จริงตัวไหนกระตุ้นสิ่งนี้ได้วันนี้ (มีแค่ `lane_a_choose_npc_scene1`
เท่านั้นที่คืนค่า `extra_actions`/`latches_spent` ไม่ใช่ค่าเริ่มต้น และตัวมันเองก็ `production_allowed
= False`) — เป็นเหตุผลตรงที่ว่าทำไมไม่มีเทสจับมาก่อน: ไม่มีเส้นทาง production ไหนไปถึงบรรทัดที่ไม่มี
การ์ดเลย

## แก้อะไร

ห่อทั้งสองบรรทัดด้วย try/except ของตัวเอง ตรงตามธรรมเนียมเดิมของจุดเรียกนี้ · ทิศทาง fail-closed ตรงตาม
สัญญาที่ docstring ของ `ChooseNpcResponse` เขียนไว้เองอยู่แล้ว ("a malformed entry means send the main
pair only -- never a dropped answer and never a raise") เฟรมหน้าตอบที่ประกอบไว้แล้วยังส่งตามปกติ มีแค่
ครึ่งคอลเลกชันกับการเขียนกลับแฟล็กที่ถูกข้าม เพิ่มเทส
`test_a_malformed_extra_actions_does_not_kill_the_dispatch_thread` ที่ปลอม responder ตอบ
`extra_actions=None` จริงแล้วขับ dispatch จริง — ยืนยันว่า**พังจริงก่อนแก้** (ได้ `TypeError` หลุดออกมา
ตรงกับที่ adversary รายงาน) และ**ผ่านหลังแก้** รันชุดเต็มอีกครั้ง: 12432 passed, 373 skipped, 0 failed
