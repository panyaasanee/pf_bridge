## ⑥ ตัวคุมชุดเดียว — และสิ่งที่ยังเป็นสองชุด

COO ปฏิเสธทาง (ข) เพราะ *"ตรรกะ threat สองชุดจะเพี้ยนจากกันแน่นอน"* ⇒ สถานะ AI มีเจ้าของเดียว

| ทะเบียน | ตอบคำถามอะไร | ของใคร |
|---|---|---|
| `mob_combat.CombatLedger` | มอนตัวนี้เหลือเลือดเท่าไร | มีอยู่แล้ว |
| `mob_death.DeathRegister` | ใครเป็นศพ | มีอยู่แล้ว |
| **`mob_ai_control.MobAiRegister`** | **มอนตัวนี้โกรธใคร** | **รอบนี้** |

สามทะเบียน คำถามละหนึ่ง — และ **สถานะ AI มีเจ้าของเดียว** ตามที่คำเคาะสั่ง

🔴 **สิ่งที่ยังเป็นสองชุดและผมพูดตรง ๆ:** สามทะเบียนไม่ได้อยู่ในธุรกรรมเดียวกัน
ถ้า driver ตายระหว่าง commit ที่ 1 กับที่ 2 มอนจะเลือดลดโดยไม่โกรธใคร
**กู้ได้ ไม่พัง แต่ไม่ atomic** และรอบนี้ไม่ได้อ้างว่ามันเป็น

🔴 **และคำว่า "แชร์กับ death gate" — adversary จับได้ว่ามันเป็น *สตริง* ไม่ใช่กลไก** (⑩ D11)
`mob_ai_control` **ไม่ import `mob_death`** · `death_step` อ่านแค่ `HitOutcome` ซึ่งเป็น **ครึ่ง HP**
**ด่าน RE-071 จริง (HP 0 *และ* timer ≤ 0) อยู่ใน `mob_death` ทั้งหมด และที่นี่ไม่เคยถาม**

⇒ ถ้อยคำฉบับที่ใช้ได้: **สิ่งที่แชร์คือ *สถานะ AI* ซึ่งมีเจ้าของเดียวและไม่มีสำเนาที่ไหน**
สิ่งที่ **reconcile ไม่ใช่ share** คือ *ความเห็นตรงกันว่าใครเป็นศพ* ⇒ `reconcile()` คือฟังก์ชันที่ทำ

## ⑦ ลำดับที่ driver ห้ามสลับ (อยู่ในบรรทัดที่ยื่นให้ chief)

```
1. mob_combat.commit_step              HP ขยับ หรือ REFUSE_LEDGER_STALE
2. mob_ai_control.damage_step + commit  threat ถูกพับ
3. ถ้าตาย: mob_death.kill + commit_death   ศพ
4. mob_ai_control.death_step + commit   phase กลายเป็น absorbing
```

- **4 ก่อน 3** ⇒ AI บอกว่าตาย ทะเบียนศพบอกว่ายังไม่ตาย ⇒ ทิกถัดไปเงียบให้มอนที่ยังยืนอยู่
- **2 ก่อน 1** ⇒ บันทึก threat ให้การลบเลือดที่ ledger เก่าปฏิเสธไปแล้ว
- **`death_step` ปฏิเสธ outcome ที่ไม่ใช่การฆ่า ด้วยชื่อ** ด้วยเหตุผลเดียวกับที่ `mob_death.kill` เขียนไว้:
  เลนที่ปลดมอนที่เลขไม่ได้ฆ่า คือเลนที่ปลดมอนเลือดเต็มได้
- **retry ทั้งสองจุด idempotent** — `death_step` เซ็ต DEAD แบบไม่สะสม · `damage_step` พับครั้งเดียวจาก register ที่อ่านใหม่
- 🔴 **แต่ "idempotent" ไม่พอ ถ้าบรรทัดเดินสายไม่ได้สั่งให้ *วน*** — adversary สร้าง wedge จริงจากตรงนี้ (⑩ D12)
  ⇒ บรรทัดเดินสังฉบับที่ใช้ได้เขียนลูป retry ให้ **ทั้งสอง** commit **และ** ให้ทางซ่อมที่ไม่ต้องมี outcome:
  **`mob_ai_control.reconcile(register, death_register)`** — เรียกที่หัวของทุก rebuild
- **`epoch`** — rebuild ต้องยกเลข มิฉะนั้น step เก่า commit ทับ rebuild ได้เงียบ ๆ (⑩ D9)

## ⑧ สองอย่างที่รอบนี้กันไว้ และไม่มี exception ไหนจะบอก

1. **เลขที่ส่งให้ threat ต้องเป็นเลข wire ที่ติดลบ**
   `HitOutcome.damage` เป็นบวก `damage_wire` เป็นลบ · `apply_damage_threat`
   **เพิ่ม threat เฉพาะค่าติดลบ และคืนสถานะเดิมเงียบ ๆ สำหรับค่าบวก**
   ⇒ ส่งผิดตัว = มอนโดนตี เลือดลด บาร์ขยับ **แล้วไม่เคยคิดว่ามีศัตรู** โดยไม่มีอะไรโยน
   ⇒ `test_the_threat_fold_hands_over_the_negative_wire_number` พิสูจน์ทั้งสองทาง

2. **`MobAiRow` ถือ `FieldMob` ไว้ด้วย และ `tick_step` รับ identity ไม่ใช่แถว**
   `mob_aggro.MobObservation` **ไม่มี identity ของตัวเอง** (มีแค่ตำแหน่ง HP และรายชื่อผู้เล่น)
   ⇒ ถ้า tick รับ `(แถว, observation)` เป็นสองอาร์กิวเมนต์ driver ที่จับคู่ผิด
   จะขับสถานะของมอน A ด้วยสภาพแวดล้อมของมอน B **เงียบ ๆ ตลอดไป**
   ⇒ ให้ register ถือแถวไว้เอง แล้วไม่เหลืออะไรให้จับคู่ผิด

3. **เทียบด้วยค่า ไม่ใช่ด้วย identity ของอ็อบเจกต์** — threat saturate ที่ `THREAT_MAX`
   การตีมอนที่ threat ชนเพดานแล้วสร้างอ็อบเจกต์ใหม่ที่ **เท่ากับของเดิม**
   ⇒ ถ้าเทียบด้วย `is` generation จะขยับโดยไม่มีอะไรเปลี่ยน = ปลอม stale ให้ driver อื่นทั้งทิก
   ในขณะที่ `step.moved` บอกว่าไม่มีอะไรเกิด
