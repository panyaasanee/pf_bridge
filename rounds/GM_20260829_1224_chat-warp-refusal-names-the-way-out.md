## ② ของที่รอบนี้ **เจอโดยไม่ได้ตั้งใจหา** — diagnostic ที่ฆ่าคำสั่งทั้งตัว

เทสที่เขียนไว้พิสูจน์ข้อ ③ ข้างล่าง (คอนโซลที่เขียนไม่ได้ ต้องเสียแค่บรรทัด ไม่ใช่เสียคำสั่ง) **แดงทันทีที่เขียนเสร็จ**
และมันแดงด้วยเหตุผลที่ไม่ใช่โค้ดใหม่ของรอบนี้:

```
AssertionError: 'gm_chat_action_warp_stage_refused_scene_has_no_login_entry'
  not found in ['gm_chat_action_accepted_warp', 'gm_chat_action_unexpected_OSError']
```

บน main บรรทัด 590 ของ `chat_command_action.py` เป็น `print(...)` **เปล่า ๆ ไม่มี try/except**:

```python
print(f"{CONSOLE_TOKEN} {command.name} route=action", file=sys.stderr)
```

⇒ stderr ที่ `write` โยน `OSError` (ไปป์ปิด · service console ที่ถูกถอด) ทำให้ **คำสั่ง GM ทุกคำสั่งล้ม**
โดยบันทึกเป็น `gm_chat_action_unexpected_OSError` — ชื่อที่โทษโมดูลนี้สำหรับสิ่งที่ไม่เคยแตะตัวคำสั่งเลย
นี่คือกฎที่ไฟล์นี้ **อ้างถึงเองในที่อื่น** (`A DIAGNOSTIC MAY NEVER ALTER DISPATCH`)
ถูกละเมิดโดย diagnostic ที่ประกาศ dispatch · รอบนี้ห่อมันแล้ว

🔴 **และมันสำคัญกับข้ออ้างของรอบนี้โดยตรง ไม่ใช่ของแถม**: ถ้าไม่แก้ตัวนี้ คำสัญญาของบรรทัดใหม่
