## ของที่ต้องแก้ เรียงตามที่ควรทำในรอบถัดไป

**D2 [วัดแล้ว มี control] `--bridge-only` ทิ้งผล `[prbody]` แล้ว exit 0 ทั้งที่ body แดง**
`pf_gate_preflight.py`: กิ่ง `--bridge-only` สร้าง `results` โดย**ไม่ใส่**
`body_result` (เส้นเดิมใส่ที่ท้าย) · วัดด้วย body ที่มีโทเคน `PF-AUTOMERGE: v4`
สองบรรทัด: `--repo /nonexistent --pr-body bad --pr-stage claim` ⇒ `[prbody] RED`
+ exit **1** · `--bridge-only --pr-body bad --pr-stage claim` ⇒ พิมพ์

**D4 [วัดแล้ว] `workflow_dispatch` = เขียวไม่มีเงื่อนไข**
`bridge-preflight.yml` ใช้ `${{ ... base.sha || github.sha }}` ⇒ ตอนกดปุ่ม Run
workflow ไม่มี PR ⇒ `BASE_SHA` = HEAD ⇒ ทุกเช็ค diff HEAD กับ HEAD · วัดบน
ต้นไม้ที่มีของผิดสามอย่าง (NOW.md เกินเพดาน · คิว +80,000 B · ชื่อไฟล์ 132 ตัว
อักษร): `--base <base จริง>` ⇒ RED สามแถว exit 1 · `--base <HEAD>` ⇒ PASS
ทุกแถว exit 0 · `git cat-file -e "$BASE_SHA^{commit}"` ที่ผมใส่ไว้กันข้อนี้ไม่ได้
เลย (HEAD มีอยู่เสมอ) 🔴 **และไฟล์รอบของผมเองสั่งรอบถัดไปให้ "ยืนยันว่า workflow
มี run จริง" — ถ้ายืนยันด้วยการกดปุ่มนี้จะได้เขียวปลอม** ⇒ แก้: ถอด
`workflow_dispatch` หรือให้โหมดนั้นใช้ `git merge-base HEAD origin/main`

**D3 [วัดแล้ว] `base.sha` + checkout ของ merge ref = โยนงานของ main มาเป็นของกิ่ง**
`actions/checkout` บน `pull_request` เช็คเอาต์ `refs/pull/N/merge` ซึ่ง**คำนวณ
ใหม่กับ main ปัจจุบัน** แต่ base ที่ผมส่งไปถูกแช่ไว้ ⇒ จดหมายที่ main เพิ่ง
merge เข้ามาถูกนับเป็นไฟล์ใหม่ของกิ่งนั้น · วัดบน PR ที่เปิดจริง: `#1577`
(ตามหลัง main 790 commit) ⇒ RED 300 ใบ · `#1493` (ตามหลัง 320) ⇒ RED 99 ใบ ·
`#1571` (31) และกิ่งนี้ (7) ⇒ PASS · ควบคุมด้วย base ของ merge ref เอง ⇒ PASS ทั้งสี่
⇒ แก้: `--base "$(git rev-parse HEAD^1)"` (พ่อคนที่ 1 ของ merge ref **คือ** base
ที่มันถูกสร้างจาก drift = 0 โดยโครงสร้าง) · และ `--base origin/main` ก็ผิดคนละทาง:
main โต 768 commit/24 ชม. และ archive sweep ของ K ย้าย `GAME_TEST_QUEUE.md`
