## pf-adversary หา 18 ข้อ แก้ไป 12 เหลือ 6 เป็นข้อเสนอ

รันก่อน commit สุดท้าย · เขาวัดจริงด้วย worktree แยก 480 dispatch + mutation ทีละบรรทัด ไม่ได้อ่านเฉย ๆ

**ข้อที่เขาพยายามแล้วพังไม่ได้:** ไม่มีเส้นทางไหนบน default ที่ `SPEED_ACTION_LABEL` ออกไวร์ได้ (0/480)

**แก้ในรอบนี้:**
- **D1 (สูง)** `_announce_console_outcome` คืนทันทีที่ `line_printed` ⇒ audit ล้มแล้ว `SPEED DEFERRED` พิมพ์ **เหมือนกันเป๊ะทั้งสามสถานะ** (แถวอยู่ / แถวถูกย้อน / แถวย้อนไม่ได้) และ `WHY_AUDIT_ROW_NOT_WRITTEN_EFFECT_KEPT` กลายเป็นโค้ดที่ไปไม่ถึง ⇒ แก้เป็น `line_printed and audited` แล้วให้ backstop พูด **ข้าง ๆ** บรรทัดของ handler เมื่อ audit ล้ม (แก้ให้ทุก handler ไม่ใช่แค่ของผม)
- **D2 (สูง)** mutation รอด 4 ตัว: ถอด `undo` ออกจาก verdict ของ deferral · เปลี่ยนสตริง `OUTCOME_SPEED_DEFERRED` · ถอด `character_id`/`identity` · ถอด `account=` ⇒ เพิ่มเทสปักครบทั้งสี่ (`TheUndoSurvivesTheDeferralTests` · `TheWordsAGraderGrepsAreLiteralsTests` · `TheLineCarriesTheRowItNamesTests`)
- **D3** ทางออกไร้ไบต์ทางที่ 11 ไม่ได้อยู่ใน `REFUSAL_PATHS` และไม่มีใครเขียนว่าจงใจ ⇒ ประกาศเป็นค่าคงที่ + เทส และเขียนว่ามันแลกอะไรไป
- **D4** docstring อ้างว่ามี fallback ตอนคอนโซลตาย — **ไม่จริง** ทั้งสอง printer ใช้ stream เดียวกัน ⇒ ขีดฆ่า และเขียนเทสใหม่ให้วัดของจริง (ของเดิมเขียวเพราะสร้างสถานะที่ production สร้างไม่ได้)
- **D5** ประโยค blocker ชี้ไปที่บรรทัดที่ตามนิยามแล้วไม่ได้พิมพ์ ⇒ ตัดออก
- **D6** เขาเขียน mutant ที่ **รอดทุกเกต**: เอาเหตุผลที่สองไปพ่วง `or` ในเงื่อนไข deferral เดิม (และ short-circuit ทำให้ไม่มีเทสไหนเห็นได้เลยจนวัน login-read ลง) ⇒ เพิ่มเกตว่าเงื่อนไขนั้นต้องเป็น call เดียวชื่อ `send_deferred` เท่านั้น · **ยืนยันแล้วว่าฆ่า mutant ของเขาได้จริง** (รัน mutant → แดง → คืนค่า → เขียว)
- **D8 (สูง)** ค่า sha256 ที่ปักใน README เป็นของไฟล์ **ก่อนแก้** ทั้งชุด ⇒ คนเช็คบนบริดจ์จะสรุปผิดตามคำเตือนของไฟล์เอง ⇒ อัปเดตครบหกค่า + เขียนกฎว่าแก้สคริปต์ต้องอัปเดตในคอมมิตเดียวกัน
- **D9 (สูง)** `%TARGET%` ที่ไม่ครอบ quote ในบล็อกวงเล็บของ `install.bat` ⇒ ติดตั้งลงพาธที่มี `(x86)` ไม่ได้เลย และบล็อกที่สองจะขึ้น `[STOP]` แบบไม่มีเงื่อนไข ⇒ ครอบ quote ทั้งสามจุด (บั๊กเดียวกับที่ผมเขียนเตือนไว้ในหัว `find_mt.bat` รอบนี้เอง แต่ไม่ได้เอาไปใช้อีกไฟล์)
- **D10 (สูง)** `if errorlevel 1` เป็นการเทียบ `>=` แบบมีเครื่องหมาย ⇒ `mt.exe` ที่ตายด้วย exit code ติดลบ (`STATUS_DLL_NOT_FOUND` = -1073741515 ซึ่งเป็นไปได้จริงเพราะเรารันมันจากโฟลเดอร์ที่ไม่อยู่บน PATH) จะได้ `[ok]` สองครั้งแล้วส่ง DLL ที่โหลดไม่ได้ออกไป ⇒ เปลี่ยนเป็น `%errorlevel% neq 0` ทั้ง 13 เกต
- **D11 (สูง)** ผมเขียนเช็ค 0/4 บน `-inputresource ... -validate_manifest` ซึ่ง **ไม่มีใครเคยรัน** แล้วบรรยายว่าเป็นการวัด ⇒ เกตแข็งเปลี่ยนเป็น "มีเซกชัน `.rsrc`" (สภาพที่ ka1-A วัดว่าไม่มีจริง ๆ ด้วย `dumpbin` ที่สคริปต์ใช้อยู่แล้ว) · ตัว `mt.exe` ลดเป็น `[warn]` ที่บอกสองสาเหตุที่แยกไม่ออกและวิธีตัดสิน
- **D12** เกตเครื่องมือถูกวางไว้ **เหนือ** `[STOP]` ⇒ เครื่องเกม (ไม่มี SDK) จะไม่มีวันได้ยินว่ามี `GameMaster.dll` เดิมอยู่ ซึ่งเป็นผลลัพธ์ที่มีค่าที่สุดของสคริปต์นี้ ⇒ ย้ายลงใต้ `[STOP]` และ "ไม่มีเครื่องมือ = เตือนดัง ๆ แล้วไปต่อ" ส่วน "เครื่องมือบอกว่าไม่มี manifest = ปฏิเสธ"
- **D13** `plugin_image_check` รับ RT_MANIFEST **id ไหนก็ได้** แต่ loader ของ DLL อ่าน id 2 · docstring ของมันยังบอกว่า `build_vs2008.bat` ไม่เรียก `mt.exe` ⇒ แก้ docstring + เขียนช่องโหว่ id ไว้ตรงนั้น (ยังไม่รัดให้แคบลง — เปลี่ยนคำตัดสินของเครื่องมือที่ใบเทสอ่านอยู่ ควรเป็นรอบของมันเอง)
- **D14** `find_mt.bat` ยัง untracked ⇒ `git add` แล้ว (ถ้าหลุดไป สคริปต์สองตัวจะ `call` ไฟล์ที่ไม่มีในรีโป)
- **D15** ข้อความ FAIL ของ `find_mt.bat` บอกว่า "ช่องว่าง = ตัวแปรไม่ถูกตั้ง" แต่ cmd ปล่อย `%VAR%` ที่ไม่มีค่าเป็นตัวอักษรดิบ ⇒ แก้คำอธิบายให้ตรงกับสิ่งที่มันพิมพ์จริง
- **D16** `build_vs2008.bat` ลบ `GameMaster.dll` ทิ้งทุกครั้ง ในโฟลเดอร์เดียวกับที่ `install.bat` ใช้ทั้งหัวไฟล์อธิบายว่าห้ามทับไฟล์นั้นเด็ดขาด ⇒ ถ้าไม่มี `.obj` คู่กัน (= ไม่ได้เกิดจากบิลด์ที่นี่) ให้ `[STOP]` พร้อมพิมพ์ sha256 ก่อน
