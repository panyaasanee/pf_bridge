### 1. ไฟล์ hook ถูกพบว่าถูกแก้เป็นโค้ดพังกลางรอบ — และเทสของสายนี้จับไม่ได้
`lane_gm_chat_command.py:53` ปรากฏกลางรอบเป็น `handle_local_talk_chat(payload, session.tokn)`
ติดป้ายคอมเมนต์ `# MUTANT` — สลับลำดับอาร์กิวเมนต์ (ส่ง payload ที่ client คุมได้เข้าไปเป็น identity)
**และ** สะกด `session.token` ผิดเป็น `session.tokn`

ผลถ้าหลุดขึ้น production: `AttributeError` ทุกครั้งที่ hook ยิง · `lane_hooks.fire()` กลืน exception ทุกตัว
โดยดีไซน์ ⇒ **หน้าตาเหมือน hook ที่จุดยิงยังไม่ถูกต่อสาย** พอดี = อาการเดียวกับ `[BLOCKED-ON-WIRING]`
ที่เราคาดไว้อยู่แล้ว ⇒ จะไม่มีใครรู้ว่าพัง

**สิ่งที่แย่กว่าคือช่องโหว่ในชุดเทสเอง:** เทส hook เดิมสองตัวพิสูจน์แค่ "มีฟังก์ชันลงทะเบียนในชื่อ point
ที่ถูก" และ "`production_allowed = True`" ⇒ ผ่านฉลุยกับโค้ดที่พังสนิท

**แก้:** เพิ่ม `HookBehaviourTests` 8 ตัวที่**เรียกตัว hook จริง**ด้วย fake session ที่มีแค่ `token`/`events`
(ไม่ผ่าน `fire()` เพื่อไม่ให้ exception ถูกกลืน) ครอบ: อ่าน identity จาก session ไม่ใช่จาก payload ·
ชื่อ event ต่อคำสั่ง · ปฏิเสธบัญชีที่ไม่ใช่ GM · แชทธรรมดา · **ไม่มี event ใดพก text ที่พิมพ์ออกมาเลย** ·
payload พังต้องไม่โยน exception ของตัวเอง · ไม่มี allowlist ให้อ่านเลย = ไม่มีใครเป็น GM
**ยืนยันแล้วว่าเทสชุดใหม่ล้ม 8 ตัวกับโค้ดที่ติดป้าย MUTANT และเขียวเมื่อแก้บรรทัดกลับ** จึงแก้กลับเป็น
`handle_local_talk_chat(session.token, payload)` **ไม่ commit บรรทัดที่ติดป้าย MUTANT**
