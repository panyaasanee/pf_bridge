## 1. งานที่ส่ง — `store.mint_backpack_item` [PROPOSED ชื่อ รอ Q ยืนยัน]
`COO-DECISION 20260908_2055` ("the item minter next to your own door is yours"): helper ที่
ประกอบ `ItemAttrState` จาก **เลขไอเทม + จำนวน** แล้วเขียนผ่านประตูเดิม ไม่ใช่ประตูใหม่

```python
def mint_backpack_item(self, sid, character_id, item_id, quantity) -> BackpackState
```
- **ไม่มี `INSERT`/`UPDATE` ของตัวเอง** — ประกอบแถว (identity ถัดไปจาก `backpack_issued_through`
  ช่องว่างช่องแรกจากการสแกน `0..39` กับกระเป๋าที่โหลดจริง) แล้วส่งเข้า `commit_acquired_backpack_item`
  ตรง ๆ · เทส `test_lands_the_row_through_the_existing_door_not_a_new_one` พิสูจน์ด้วย
  `mock.patch.object(..., wraps=...)` ว่าประตูเดิมถูกเรียกจริง ไม่ใช่แค่ "ดูเหมือน" ตามดอกสตริง
- **สามคำปฏิเสธที่อ่านได้ (ตามที่ `2055` สั่ง)**: `item_id` ไม่รู้จัก → `KeyError` (เทียบกับ
  `gm.item_catalog.is_known_item` — ตารางจริงจากการสกัด `gamedata` มี sha256 pin อยู่แล้ว
  ไม่ใช่รายการมือ) · `quantity` ไม่ใช่ int บวก → `TypeError`/`ValueError` · กระเป๋าเต็ม (40/40) →
  `ValueError` **ก่อน**ประกอบอะไรทั้งนั้น — เทส `test_refuses_when_the_backpack_is_full_before_
  composing_anything` เติม 36 แถวจริงผ่าน raw SQL แล้วยืนยันกระเป๋าไม่ขยับหลังปฏิเสธ
- **atomic กับตัวนับ identity**: ไม่เปิดทรานแซกชันเอง — อ่านนอกทรานแซกชัน (`get_backpack`/
  `backpack_issued_through`) แล้วส่งเข้า `commit_acquired_backpack_item` ซึ่งเช็ค identity/slot
  ซ้ำใน `BEGIN IMMEDIATE` ของมันเอง ⇒ แข่งกันสองตัวพร้อมกันได้ `ValueError` ที่ชื่อบอกเหตุ ไม่ใช่แถวเพี้ยน
  (รูปเดียวกับสอง ground-pickup แข่งกัน — ไม่มีทรานแซกชันใหม่ให้พิสูจน์ atomicity ของตัวเอง)

**เทส**: `tests/test_store_mint_backpack_item.py` ใหม่ 7 ตัว ผ่านหมด (happy path + ไม่มี
ground-drop involved + delegate ผ่านประตูเดิม [spy] + สี่คำปฏิเสธ) — ทั้งไฟล์ไม่แตะ `store.py`
