## สาม finding ที่ล้มข้ออ้างหลักของดีไซน์

**D1 — `slot_id = n_EQUIPTYPE` คือ "ชนิด" ไม่ใช่ "ช่อง" และคอลัมน์รับมันไม่ได้**
วัดเองจาก `gamedata/tables/CONSTDATA_TH__EQUIPMENT_BASE.tsv`:
```
974 แถว · n_EQUIPTYPE > 255 = 650 แถว · ค่าสูงสุด 524288
n_EQUIPSLOT   24 -> n_EQUIPTYPE [8, 16, 64]   <- สามชนิด ช่องกายภาพเดียว (คลาส 4/16/32)
n_EQUIPSLOT 16384 -> n_EQUIPTYPE [1]
```
`store.equip_item` ปฏิเสธ `slot_id` นอก `0..255` และ migration 015 ตัดคอลัมน์นี้ให้เท่า `ItemAttr+0x39` = ดัชนีบิต `0..31` ⇒ **ระบบเลขที่ผมเลือกเข้ากับคอลัมน์ไม่ได้ในเชิงเลขคณิต สำหรับ 650 จาก 974 แถว**
และในอนาคตที่ docstring ของผมเขียนเอง (วันที่ตาราง template→ชนิดลง) การสวม type-8 แล้วเปลี่ยนเป็น type-16 จะเขียน **สองแถวสำหรับช่องเดียว** — `UNIQUE(character_id, slot_id)` ไม่ไล่อะไรออก การสลับของกลายเป็นการสะสม
🔴 มิวแทนต์ที่ชี้ชัดที่สุด: `slot_id = equip_type.bit_length() - 1` (เลขที่ encoder ของ `+0x39` ต้องการจริง) **ถูกเทสของผมฆ่า** ⇒ ผมพินเลขที่เป็นไปไม่ได้ไว้ และปล่อยเลขที่ผิดอีกสามตัวผ่าน

**D2 — ข้ออ้างหลักของใบเป็นเท็จ และ crosswalk อยู่ในรีโปนี้เอง**
`tools/pf_equip_attack_behavior_extract.py` ทำ `n_SLOT_RHAND - 2200000` → แถว `EQUIPMENT_BASE` → `n_EQUIPTYPE` อยู่แล้ว (`WEAPON_SLOT_KEY_BASE = 2200000`) และมันคือเครื่องมือที่ **ผลิต** `data/creation_gear_by_class.tsv` ที่โมดูลผมพึ่งอยู่
⇒ ประโยค "ไม่มีตาราง `template_id -> n_EQUIPTYPE` ที่ไหนในรีโปทั้งสอง" ใน **docstring ของโมดูล · commit message · ไฟล์รอบ · บอดี้ PR · และใบ RE ที่ผมส่งถึง K** เป็นเท็จทั้งหมด
ขอบเขตที่ยังจริง: ฐาน `-2200000` พิสูจน์แล้วเฉพาะตระกูล `2200xxx` ⇒ crosswalk ทั่วไปยังต้องทำ แต่สำหรับ **อาวุธ** ซึ่งเป็นทั้งหมดของโมดูลนี้ มันมีอยู่แล้ววันนี้
⇒ ข้อจำกัด "เขียนได้ตัวเดียวต่อคลาส" ที่ผมขายว่าเป็นขีดจำกัดของตารางที่ commit ไว้ **เป็นขีดจำกัดของการค้นของผมเอง** · แก้เป็นใบถึง K แล้ว (`20260907_1955_LANE-DB-TO-K-CORRECTION-*`)

**D5 — ข้ออ้างพาดหัวไม่รอด relog**
`list_equipped_items` **ไม่มีผู้เรียกที่ไหนเลย** · ขณะที่ `inventory.ItemAttrState.raw_u8_39` (ไบต์ `+0x39` ตัวจริง) ถูก persist ใน `character_backpack_items` และ **ส่งบนสายแล้ว** ใน StartGame BackpackAttr (`inventory.py:508`)
⇒ สวมของ → hook เขียน `character_equipment` → relog → `_load_backpack` คืน `raw_u8_39 = 255` → เฟรมส่ง 255 → sentinel ของ `RE-280` ทำให้ไคลเอนต์ข้ามไอเทมว่า "ไม่ได้สวม" · DB เก็บสองประโยคที่ขัดกันเรื่องไอเทมเดียว และสายยังส่งประโยคที่บอกว่าไม่ได้สวม
**"การ equip อยู่ข้าม session" จริงเฉพาะกับแถวที่ไม่มีใครอ่าน**

## finding อื่นที่รับไว้
- **D6** `production_allowed = True` ทำให้เกิด stall 5 วินาทีบนเส้น dispatch เมื่อชน write lock (วัดจริง: uncontended 0.002s · contended 5.01s แล้ว `WriteLockTimeout`) · `game_listener` จัดการทั้งคอนเนกชันบนเธรดเดียว ⇒ ประโยคของผมที่ว่า "เปลี่ยนพฤติกรรมเฟรมไม่ได้เพราะ seam ไม่มี return" จริงเรื่อง **ค่าคืน** และ **เท็จเรื่องเวลา**
- **D4** บรรทัดที่เขียนแถวเป็น dead code สำหรับ 4 ใน 5 คลาสในโปรดักชัน — `_insert_initial_backpack` แจก `INITIAL_BACKPACK` ให้ทุกคลาส และมีแถวอาวุธเดียวคือ `2200002` (ของคลาส 1) · ไม่มีเทสไหน import `INITIAL_BACKPACK` ⇒ เทสเขียวบนทรงกระเป๋าที่โปรดักชันไม่เคยผลิตให้ผู้เล่น 80%
- **D7** มิวแทนต์รอด 11 ตัว ที่ตาราง 7/7 ในไฟล์รอบไม่มีสักตัว · รากเดียวกันสามตัวแรก: `CLASS_UNDER_TEST = 1` ซึ่ง `class_id`/`n_EQUIPTYPE`/`bit_length` **เท่ากับ 1 ทั้งสามค่า** · และสองตัวเป็นทรง "โทเคนเทียบกับตัวเอง": `CONSOLE_PREFIX = "LANE_DB_EQUIP_V2"` กับ `WROTE = "persisted"` รอด เพราะทุก assertion วิ่งผ่าน `mod.CONSOLE_PREFIX`/`mod.WROTE` · `REASONS = frozenset()` รอดเพราะทำให้ census ASCII เป็นลูปศูนย์รอบแล้วรายงาน PASS
- **D8/D9/D10** `_say` ไม่ผ่าน `lane_hooks.console_safe` · โทเคน `wrote` ยิงตอน "เมธอดคืนค่า" ไม่ใช่ "แถวอยู่จริง" · บูต `--scene-load` แบบอ่านอย่างเดียวปลอดภัยด้วย **อุบัติเหตุ**ที่ `ReadOnlyFoundationSession` ตั้งชื่อ `self.store` ไม่ใช่ `self.lifecycle.store` — ไม่ใช่เกตตั้งใจ และไม่มีพิน

## ผลลบที่ผู้ตรวจหักล้างไม่ได้ (แข็งกว่าหลักฐานฝ่ายบวกของรอบ)
ไม่มี predicate ซ้ำ (การใช้ `combat_pose.equip_type_for_class` + `persistence_class_id.CLASS_PRESETS` ถูกต้อง) · ไม่มีพินค้าง ทุกเลข derive ตอน import หรืออ่านจากตารางที่เช็ค sha · fail-closed **ยืนครบ**: `__eq__` ที่ raise, property `identity` ที่ raise, generator ที่ตายกลางคัน, store หาย, keyword หาย, `KeyError`/`ValueError`/`RuntimeError` จาก store — **ไม่มีอันไหนหลุดออกจาก `fire()` และทุกอันเขียนศูนย์แถว** · skip census เขียว ไม่มี skip ใหม่ · ซอร์สโมดูล ASCII ล้วน · ล็อกได้มาด้วยการชนะ `BEGIN IMMEDIATE` ไม่ใช่ด้วยการเขียน

## คำถามเดียวที่ดีไซน์ยังไม่ตอบ และเป็นรากของ D1/D2/D5
**อะไรอ่าน `character_equipment.slot_id` และผู้อ่านนั้นคาดหวังระบบเลขไหน**
ตราบใดที่ยังไม่มีผู้อ่าน `slot_id` **ไม่ใช่ opaque มันคือ undefined** และมีสี่เลขที่แก้ต่างได้เท่ากันสำหรับดาบ Gladiator เล่มเดียว: `n_EQUIPTYPE` 1 · `n_EQUIPSLOT` 16384 · `value32` บนสาย 8-หรือ-16 · และดัชนี `+0x39` = 3 ที่ `reports/PF_RE_V130_*` บันทึกไว้แล้ว
ผมเลือกตัวที่ตั้งชื่อ **ชนิด** เอาไปใส่คอลัมน์ชื่อ **ช่อง** ที่ถูกตัดขนาดมาเพื่อ **ดัชนีบิต** และรับ namespace นั้นไม่ได้สำหรับ 650 จาก 974 แถว
