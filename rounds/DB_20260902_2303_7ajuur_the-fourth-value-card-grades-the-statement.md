(หลัง `009` คอลัมน์นั้น *ไม่* NULL บนแถวเกิด การอ้าง NULL จะแดงบนฐานที่ถูกต้อง) · ข้อความ fail บอกคำสั่งที่เห็น

**ห้าชั้น** (ร่างแรกมีสามชั้น · `pf-adversary` หักได้ห้ารูป · ที่เพิ่มคือชั้น authorizer กับชั้นนับ insert):
- **ชั้นสถิต** `scan_birth_path()` แจง `store.py` ด้วย `ast` เดินจาก `SQLiteStore.create_character`
  แล้ว **ไล่ตาม `self.<method>` แบบ transitive** (รอบนี้กราดถึง `_insert_initial_backpack`,
  `get_character`, `_character`, `connect`) อ่านอาร์กิวเมนต์แรกของ `execute/executemany/executescript`
  🔴 **fail-closed:** คำสั่งที่อ่านไม่ออก (f-string / `%` / ต่อสตริง) = **แดง ไม่ใช่ข้าม**
  (ราคาของกฎนี้: เขียน `SELECT` ในวงปิดนี้เป็น f-string ก็แดง — เขียนไว้ในข้อความ fail ตรง ๆ ไม่ซ่อน)
- **ชั้นคำสั่งที่รันจริง** `set_trace_callback` บนฐานจริงที่ migrate ด้วย `migrations/` จริง
  เห็นคำสั่งจากโมดูลอื่นและ SQL ที่ประกอบตอนรัน แต่เห็นเฉพาะกิ่งที่ fixture เดิน และ **ไม่เห็นตัวทริกเกอร์**
- **ชั้น authorizer** `set_authorizer` รายงาน `SQLITE_UPDATE` พร้อม **ชื่อตาราง + ชื่อคอลัมน์**
  รวมถึงคำสั่งที่อยู่ในตัวทริกเกอร์ (attribute ตามชื่อทริกเกอร์) ⇒ ชั้นนี้ **ไม่สนใจว่าคำสั่งสะกดยังไง**
  คอมเมนต์นำหน้า / `WITH` นำหน้า / ทริกเกอร์ ผ่านชั้นนี้ไม่ได้
- **ชั้นนับ insert** `SQLITE_INSERT` ไม่พกชื่อคอลัมน์ ⇒ การเขียนแบบ **ตามตำแหน่ง**
  (`REPLACE INTO characters SELECT ...`) ไม่เอ่ยชื่ออะไรเลยและมองไม่เห็นด้วยข้อความ
  ปิดด้วยการนับแทน: **การเกิดหนึ่งครั้ง = insert บน `characters` หนึ่งครั้ง** ใบที่สองถูกปฏิเสธเสมอ
- **ชั้นสคีมา** อ่านทริกเกอร์บน `characters` จาก `sqlite_master` โดยตรง (ตัวทริกเกอร์อยู่ในไฟล์ migration
  ไม่ใช่ `store.py` ⇒ ชั้นสถิตมองไม่เห็น) พร้อมเทสที่ **สร้าง migration `010` ปลอมที่ติดทริกเกอร์จริง**
  แล้วบังคับให้ทั้งชั้นสคีมาและชั้น authorizer รายงาน — ไม่งั้น "ผ่านเพราะไม่มีทริกเกอร์" กับ
  "ผ่านเพราะคิวรีมองไม่เห็นทริกเกอร์" แยกกันไม่ออก (ฐานวันนี้มีทริกเกอร์บน `characters` = ศูนย์ตัว)
- **ชั้นมิวเทชัน** ปลูกคำสั่งต้องห้ามลง source สำเนา แล้ว **รันเมธอดเทสที่ ship จริง** บนสำเนานั้น

prose "สี่ INSERT" · connection ไม่ปิด · `sys.path` เกิน) แก้แล้วทั้งหมดยกเว้นข้อ global patch
ซึ่งผมเก็บไว้และ **เขียนความจริงลง docstring แทน** (มันกว้างจริง แต่ให้ผลเป็น *แดงเกิน* ไม่ใช่เขียวปลอม
และเกต Windows รัน pytest แบบอนุกรม)

🔴 **รูที่ยังปิดไม่ได้ ผมเขียนไว้ในหัวไฟล์เอง**: ฟังก์ชัน *ระดับโมดูล* ที่ถูกเรียกใต้กิ่งที่ fixture ไม่เดิน
(เช่น เฉพาะตัวละครที่สี่) — ชั้นสถิตไม่เดินเข้าไป ชั้นรันจริงไม่ได้เดินกิ่งนั้น
รอบนี้ขยับ fixture เป็น **สามการเกิด + retry** ทำให้แถว G แดง แต่ **ไม่ใช่ศูนย์** ผมไม่อ้างว่าเป็นศูนย์

🔴 **นอกจากนี้ เทสกันเปล่าของผมเองจับบั๊กในตัวตรวจของผมหนึ่งตัวก่อน adversary จะกลับมา**:
`_WRITES` ยึดหัวสตริงจึงมองไม่เห็น `UPDATE` กลางตัวทริกเกอร์ (`CREATE TRIGGER ... BEGIN UPDATE ...`)
— เรื่องเดียวกับข้อ 1 ของ adversary เจอคนละทาง
