## 1. ของที่ลงจริงรอบนี้: `migrations/007_character_vitals_seed.sql`

สองประโยค SQL เท่านั้น ทั้งคู่มี `IS NULL`:

```sql
UPDATE characters SET level = 1 WHERE level IS NULL;
UPDATE characters SET hp_current = 100, hp_max = 100
 WHERE hp_current IS NULL AND hp_max IS NULL;
```

ที่มาของเลขสามตัว ไม่ใช่การเดา — เป็นการ**ถอดความ**สิ่งที่เซิร์ฟเวอร์ตัวนี้ส่งอยู่แล้วทุกล็อกอิน:
`player_wire.py:22` (`PLAYER_LOGIN_LEVEL = 1`, เป็นดีฟอลต์ที่ `:220`) · `player_wire.py:204` และ `:205`
(`legacy.u32tag(0x14, 100)` สองบรรทัดติดกัน) ป้ายหัวไฟล์เป็นคำที่ COO สั่งเป๊ะ:
`TRANSCRIBED from player_wire hardcode -- original game default OPEN`

**จุดเดียวที่อ่านใบแคบกว่าตัวอักษร และแจ้ง COO ไว้แล้ว:** `hp_current`/`hp_max` เดินเป็น **คู่** (`AND`)
ไม่ใช่ทีละคอลัมน์ เพราะแถวที่มี `hp_max = 50` อยู่ก่อนแล้วถ้าเดาเติม `hp_current = 100` จะกลายเป็น
`REASON_HP_ABOVE_MAX` — **กฎของเซิร์ฟเวอร์เองปฏิเสธแถวที่การซ่อมเพิ่งสร้างขึ้นมา** บนฐานข้อมูลวันนี้
