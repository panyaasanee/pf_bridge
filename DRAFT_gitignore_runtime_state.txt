.gitignore ตัวจริง **บรรทัดที่ 1 คือ `/*`**  แปลว่ารีโปนี้เป็นแบบ
"ปิดหมดก่อน แล้วค่อยเปิดทีละอัน" (deny-all + allowlist) มี 269 บรรทัดที่ขึ้นต้น
ด้วย `!` เป็นตัวเปิด

ผลที่ตามมา 2 ข้อ ที่คนมักพลาด:

  (1) ตอนนี้ถ้าย้าย pf_bridge เข้ามาเฉย ๆ  **ทุกไฟล์จะถูกกันหมด** โดย `/*`
      พิสูจน์แล้ว: pf_bridge/GAME_TEST_QUEUE.md => .gitignore:1:/*
      ⇒ ไม่ได้แปลว่า "ปลอดภัยแล้ว" แต่แปลว่า "commit ไม่เข้าเลยสักไฟล์"
        ต้องมีบรรทัด `!` เปิดประตูก่อน บล็อกข้างล่างจึงเริ่มด้วยการเปิด

  (2) git **ไม่เดินเข้าไปในโฟลเดอร์ที่ถูก exclude ไปแล้ว**
      ดังนั้น `!/pf_bridge/GAME_TEST_QUEUE.md` เดี่ยว ๆ จะ "ตายฟรี"
      ต้องเปิดตัวโฟลเดอร์ก่อน (`!/pf_bridge/`) แล้วค่อยเปิดข้างใน

  (3) กติกา git คือ **บรรทัดท้ายสุดที่ match ชนะ** บล็อกนี้ถูกต่อท้ายไฟล์
      แปลว่า `!/pf_bridge/**` ของเรา จะ "ชนะ" บรรทัด `**/*.png` `**/*.zip`
      `**/capture*/` ที่อยู่บรรทัด 163-177 ของเดิม
      ⇒ จึงต้องเขียนกันไบนารีซ้ำอีกรอบในบล็อกนี้ ไม่ใช่พึ่งของเดิม
      (ข้อนี้คือกับดักที่ทำให้ไฟล์เกม 9 MB หลุดขึ้น remote ได้จริง)
