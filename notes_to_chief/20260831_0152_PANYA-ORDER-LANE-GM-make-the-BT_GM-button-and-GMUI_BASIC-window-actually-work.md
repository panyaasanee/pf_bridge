# 2. ของที่วัดไว้แล้ว — อย่าเริ่มจากศูนย์ อย่าขุดซ้ำ

## รู้แล้วและปิดแล้ว
- **`RE-126` CLOSED**: ปุ่มผูกกับ **object เดียวกัน** ไม่ได้ผูกผิดตัว
  binder (`vtable 0x00F21FA8+0x60 -> 0x0053ADE0`) lookup resource `BT_GM` แล้วเขียน pointer ลง
  `this+0x48` ที่ `0x0053B0CB` · dispatcher ของ vtable เดียวกัน (`+0x28 -> 0x0053BCA0`) เทียบ
  `event.source` กับ `[ESI+0x48]` ที่ `0x0053BCEF` แล้วเรียก `0x0053B9B0` ด้วย `this` ตัวเดิม
  ⇒ **สมมติฐาน "ผูกผิดตัว" ตายแล้ว ห้ามเปิดใบซ้ำ**
- **`GT-103` A/B NO-RESULT (ผลลบที่มีค่า)**: เจ้าของคลิก `BT_GM` **สี่สถานะ UI** (HUD เปล่า /
  แผนที่เปิดค้าง / กระเป๋าเปิดค้าง / ปิดกระเป๋าแล้วคลิกซ้ำ) **เงียบทุกครั้ง** สำมะโนเฟรมขาเข้า
  `0x51E9` = 0 ทั้งบูต · `TargetPosVital` ×3 ช่วงเดียวกันพิสูจน์ว่า client ยังมีชีวิต ไม่ใช่เซสชันตาย
  ⇒ **สมมติฐานเชิงปฏิบัติของ `RE-118` (เปิด panel ให้ current-UI key ไม่ว่าง) ถูกหักล้างแล้ว**

## ที่ RE-126 บอกเองว่ายังไม่รู้ — และปฏิเสธที่จะเดา
> "สาเหตุอยู่ **ถัดจาก** binding (connection context / query gate / current-UI object-key /
>  create path) ซึ่ง RE-126 ปฏิเสธที่จะเดา — **ใบใหม่ถ้าจะไล่ต่อ ไม่ใช่ใบนี้**"

นั่นคือใบที่คำสั่งนี้ขอให้เปิด สี่ผู้ต้องสงสัยที่มีชื่ออยู่แล้ว:
1. **connection context** — handler มี context ของ connection ที่ใช้ส่งจริงไหม
2. **query gate** — query `0x25` ที่อ่าน `GMModule_Client+0x19` (ตัวที่ทำให้ปุ่ม*โผล่*) ยังคืน true
   อยู่ไหม **ตอนคลิก** หรือคืน true แค่ตอนวาดปุ่ม
3. **current-UI object-key** — RE-118 เดาว่าต้องไม่ว่าง แต่ GT-103 หักล้างข้อเสนอ*เชิงปฏิบัติ*ไปแล้ว
   ⇒ เงื่อนไขจริงคืออะไร ยังไม่มีใครตอบ
4. **create path** — factory `0x007280D0` ที่สร้าง `GMUI_BASIC` ถูกเรียกไหม หรือถูกตัดก่อนถึง

# 3. วิธีที่เจ้าของอยากให้ลอง (ข้อเสนอของกะ1-A — สาย GM ตัดสินเอง)

**static RE อย่างเดียวเคยให้คำตอบที่ถูกหักล้างมาแล้วหนึ่งครั้ง (`RE-118`)** อย่าเดินซ้ำทางเดิม

เลนทดลอง `PF_ADHOC_ATTR_PROBE` ของเจ้าของพิสูจน์ **วิธีทำงาน** ที่ได้ผลกว่า: ยิงทีละตัวแปรใส่ client
จริงแล้วดูด้วยตา มี negative control ในตัว (266 คำสั่ง 2 ชม. 20 นาที ไม่เด้ง) — วิธีนี้ตอบเรื่องชั้นจอ
ได้เร็วกว่า static RE มาก และเพิ่งพิสูจน์ตัวเองมาแล้วสองเคส (ฟิลด์ `class` กับชื่อลงช่องกิลด์)

ข้อเสนอ: ทำ **fork ทดลองแบบเดียวกันสำหรับ GM state** — เปิด/ปิดทีละบิตของ `GM_UpdateGMStateVital`
(`0x5A19`, เฟรม 41 ไบต์ที่พินแล้ว) และทีละเงื่อนไขของสี่ผู้ต้องสงสัย แล้วให้ผู้เทสคลิกปุ่มทุกครั้ง
ดูว่าสถานะไหนทำให้หน้าต่างเปิด — แทนการอ่าน disassembly ไล่ทีละ gate

# 4. ใครทำอะไร (ตามกฎใบเดียวผู้ทำเดียว)

- **สาย GM**: เปิดใบ RE ใหม่ (ผู้เปิดใบเป็นผู้บริโภคผล) · สร้าง fork/สคริปต์ทดลองในเขต `gm/`
  หรือเขตทดลองแยก · เขียนสเปกให้ผู้เทสว่าต้องคลิกอะไร ตอนไหน วัดอะไร
- **กะ1-A (ผู้เทส attended)**: ครึ่งที่ต้องขับ UI จริงเป็นของผมคนเดียว — สาย GM สั่งมาได้เลย
  ผมจะจัดบูตให้ · ปุ่ม `BT_GM` ต้องมีคนคลิกด้วยมือจริง เอเจนต์คลิกเองไม่ได้
- **chief/COO**: ไม่ต้องทำอะไรกับใบนี้ ไม่ใช่ CORE-REQUEST (ยังไม่แตะ `runtime.py`)
  ถ้าถึงจุดที่ต้องแตะ ค่อยเปิด CORE-REQUEST ตามปกติ
