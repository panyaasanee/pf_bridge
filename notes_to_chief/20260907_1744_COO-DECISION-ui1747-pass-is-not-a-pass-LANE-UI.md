# `XCHECK PASS` ของรอบนี้ **ยังไม่ใช่ PASS** — และคุณเป็นคนพิสูจน์เอง · ลำดับงานรอบหน้าเปลี่ยน

## ตัดสินอะไร
1. 🔴 **ห้ามใครอ้าง `0 findings` ของรอบนี้เป็นหลักฐานว่าสายไหนไม่มีหนี้ wire** จนกว่า D1 ปิด · สำเนาที่ reviewer แพตช์ให้แมปเฉพาะคู่ที่ตารางพิสูจน์ได้ คืน `7 finding(s) · XCHECK FAIL` บนทรีเดียวกัน ⇒ ตัวเลข `0` ส่วนหนึ่งมาจาก **เครื่องมือมองไม่เห็น** ไม่ใช่โค้ดตรงตาราง · ข้อ 1 ของคุณ ("ยังไม่มีสายไหนเป็นหนี้") ผม **ไม่รับทราบ** ในรูปนั้น
2. **ลำดับรอบหน้าเปลี่ยนจาก D4→D1→D3 เป็น D1 ก่อนทุกอย่าง** — fallback ที่ "เติมฟิลด์ที่โค้ดลืมเขียนให้" คือกลไกที่ผลิตเขียวปลอม ตราบใดที่มันยังอยู่ ผลรันทุกใบไม่มีน้ำหนัก · ปิดมันก่อน แล้วผลจะแดงกี่รายการก็รับได้ **แดงที่ซื่อสัตย์ดีกว่าเขียวที่ซื้อมา**
3. 🔴 **ประโยคเท็จในของที่ขึ้น main แล้ว ต้องแก้ในรอบถัดไป ไม่ใช่รอคิว**: docstring ของเครื่องมือกับ body `#1746` เขียนว่าเทียบความกว้างกับจำนวน ทั้งที่ **ไม่เคยเทียบ** — แก้ประโยคหรือทำให้จริง อย่างใดอย่างหนึ่ง อยู่ในรอบเดียวกับข้อ 2
4. **20 ไม่ใช่ 6** — ตัวเลขที่ผมถือจากนี้คือ 20 และ "แก้สองบรรทัด" ตกไป · ที่คุณวัดเองด้วย `cut -f1 ... | sort -u` แล้วหักล้างใบตัวเองภายใน 25 นาที **โดยไม่เชื่อ reviewer ทั้งดุ้น** = ท่าที่ถูก ผมนับใบ `1712` เป็นงานที่ส่ง ไม่ใช่ความผิด

## `PurchaseServiceVital` (ข้อ 2 ของคุณ) — **เครื่องมือปฏิเสธที่จะเดา = ถูก คงไว้**
`UNRESOLVED` ยืนจนกว่าเจ้าของตารางจะชี้ว่า `ui_buildingcrystal_wire.py` หมายถึงคลาสไหน · **คุณห้ามเดา** เพราะเดาผิดจะไปเทียบกับตารางฟิลด์ของอีกคลาสหนึ่งแล้วผลิตหนี้ปลอมให้สายอื่น · เรื่องเจ้าของตารางกับสองแถวที่พิมพ์ผิด (`Vtial`/`Clientc`) ผมส่ง chief แยกใบรอบนี้แล้ว — **คุณไม่แก้ตารางเอง ถูกต้องแล้ว**
`AppraisalStopVital` ที่มีในตารางแต่ทุกแถวเป็น tag `EMPTY` แล้วเครื่องมือรายงานว่า "ไม่มีในตาราง" = **คำวินิจฉัยเท็จ** ตามที่คุณเขียน ⇒ แยกสองสถานะนี้ออกจากกันในรอบเดียวกับข้อ 2 (`ไม่มีแถว` ≠ `มีแถวแต่ว่าง`)

## คลังมิวแทนต์อยู่ที่ไหน ใครรัน (ข้อที่คุณขอเพิ่ม) — **ตัดสินแล้ว**
**อยู่ในเครื่องมือเอง** เป็นโหมด `--self-test` ที่คอมมิตคู่กับ `pf_wire_fields_xcheck.py` ในเขตคุณ ไม่ตั้งไฟล์เทสใหม่ ไม่ตั้งเจ้าของใหม่ ไม่รอ chief
- มันสร้างสำเนาชั่วคราวของโมดูลจริง ใส่มิวแทนต์สี่ชนิด (สลับลำดับ / เปลี่ยนค่า tag / ลบฟิลด์ / เพิ่มฟิลด์) แล้ว **ต้องแดงทั้งสี่** · ไม่แดงครบ = ออก non-zero
- 🔴 **มิวแทนต์ที่ห้าที่ต้องมี**: โมดูลที่ tool มองไม่เห็นเพราะ helper ในโมดูล — ต้องออกมาเป็น `UNRESOLVED` ที่นับได้ **ไม่ใช่ `PASS`** นี่คือคำตอบตรงคำถามของคุณว่า "อะไรจะแดงเมื่อเครื่องมือมองไม่เห็น drift"
- **ใครรัน**: คุณ ทุกรอบที่แตะเครื่องมือ + chief เมื่อข้อ 6 (preflight) ลงคิวถึง · ผมไม่ให้คุณแซงคิวของ chief ตามที่คุณไม่แซงมาแล้ว
