## จุดที่แคบกว่าใบสั่ง — ขอให้อ่านข้อนี้ก่อนข้ออื่น
ใบ `0250` ข้อ 1 เขียนว่า `WHERE ... IS NULL` **ทั้งสามคอลัมน์** ถ้าทำตามตัวอักษรแบบต่อคอลัมน์
จะได้สามคำสั่ง และคำสั่งของ `hp_current` จะยิงแถวที่ **`hp_max = 50` อยู่แล้วแต่ `hp_current` เป็น NULL**
⇒ แถวนั้นออกมาเป็น `hp_current = 100 > hp_max = 50` ซึ่ง `persistence_vitals.resolve(...).require()`
**ปฏิเสธ** (ความสัมพันธ์ระหว่างสองคอลัมน์คือสิ่งเดียวที่ SQL CHECK ต่อคอลัมน์เขียนไม่ได้)
= migration ผลิตตัวละครที่เซิร์ฟเวอร์ประกอบบล็อกให้ไม่ได้ ด้วยมือของตัวเอง

สิ่งที่ลงจริงจึงเป็น **สองคำสั่ง**: `level` ตามเงื่อนไขของตัวเอง · คู่ HP ยิงพร้อมกัน
`WHERE hp_current IS NULL AND hp_max IS NULL` — **แตะแถวได้น้อยลงเท่านั้น ไม่มีทางมากขึ้น**
และไม่มีทางสร้างคู่ครึ่ง ๆ ถ้า COO เห็นว่านี่เกินอำนาจสาย บอกมา แก้กลับเป็นสามคำสั่งได้ในรอบเดียว
(เทส `test_a_half_written_hp_pair_is_left_alone_entirely` คือที่ที่เคสนี้ถูกวัด)

## 🔴 ข้อที่ต้องให้ COO ตัดสิน — ผู้ตรวจวัดได้ และสายนี้ปิดเองไม่ได้
**`007` seed "รุ่น" ไม่ใช่ "ฐานข้อมูล"** มันเขียนตัวละครที่ **มีอยู่ตอนมันรัน** เท่านั้น ตลอดกาล
- `SQLiteStore.create_character` ระบุคอลัมน์ที่ INSERT ไว้ชัด และไม่มีสามคอลัมน์นี้อยู่ในนั้น
- `006` เพิ่มคอลัมน์แบบ **ไม่มี DEFAULT** (โดยตั้งใจ ตามกฎ "ห้ามเดาเป็นศูนย์")
- ledger กัน `007` ไม่ให้รันซ้ำ และใบ `0250` ข้อ 3 ห้ามแก้ `007` ย้อนหลัง
⇒ **ตัวละครที่สร้างหลัง migration มี vitals เป็น NULL ตลอดไป** และบน **เครื่องลงใหม่**
(ตารางว่างตอน `007` รัน) census จะอ่านได้ `0/0/0` ทั้งสามคอลัมน์ ทั้งที่ migration รายงานว่าสำเร็จ
วัดแล้ว ไม่ใช่ทฤษฎี · เทส `SeedsACohortNotADatabaseTests` ปักหมุดไว้ทั้งสามเคส

**ทำไมสายนี้ปิดเองไม่ได้** `create_character` เป็น method เดิม charter `1100` ห้ามเปลี่ยนพฤติกรรม method เดิม
ทางปิดมีสองทางและทั้งคู่เป็น **คำตัดสิน** ไม่ใช่การแก้โค้ด:
- **(ก)** ใส่ `DEFAULT` ให้สามคอลัมน์ = ต้อง **rebuild ตาราง** (SQLite ใส่ default ให้คอลัมน์ที่มีอยู่ไม่ได้)
  แบบเดียวกับ `004` · ผลคือ **ตัวละครทุกตัวในอนาคตเกิดมาพร้อมเลขนี้โดยอัตโนมัติ**
- **(ข)** เขียนค่าตอนสร้างตัวละคร = ต้องมีจุดเสียบใน `create_character` (นอกเขตเขียนของสายนี้)
คำถามเดียวกับที่ใบ `0250` ตอบให้ "ตัวละครที่มีอยู่แล้ว" ถามใหม่สำหรับ "ตัวละครที่ยังไม่เกิด"
🔴 **ไม่ตัดสินเอง** ขอ COO เคาะ · จนกว่าจะเคาะ ประโยค "M4 ปลดล็อกแล้ว" จริงเฉพาะกับตัวละคร
ที่มีชีวิตอยู่เช้าวันที่ 2 ก.ย. 2026 เท่านั้น ไม่จริงกับตัวอื่น

## จุดที่สองที่แคบกว่าใบสั่ง — เพิ่มหลังผู้ตรวจวัด
คำสั่งคู่ HP มี `AND (level IS NULL OR level > 0)` ต่อท้ายด้วย เพราะแถวที่ `level = 0` กับ HP ว่างทั้งคู่
**วันนี้ถูกปฏิเสธ** (HP ไม่มีค่า) แต่ถ้า seed คู่ HP เข้าไปมันจะกลายเป็น **สถานะสมบูรณ์ที่ `require()` รับ**
และ `apply_hp_damage` รันได้ โดยแบกเลเวลศูนย์ที่ไม่มีใครเคาะ — `persistence_vitals` ปฏิเสธ `hp_max = 0`
แต่ **ไม่มีกฎเรื่อง `level = 0` เลย** และ CHECK ของ `006` ยอมให้ (`BETWEEN 0 AND 65535`)
= migration เปลี่ยนแถวที่ fail-closed ให้กลายเป็นแถวที่ถูกรับ ซึ่งคือสิ่งเดียวกับที่เหตุผลของคู่ HP ห้ามไว้
