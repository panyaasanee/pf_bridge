## ① ติดอะไร

`BUILD-006` เขียนว่า **"ของตกพื้น เก็บขึ้นมา เข้ากระเป๋า relog แล้วยังอยู่"**
รอบก่อน (`g627j0`) ปิด *"ของตกพื้น"* ไปแล้วครึ่งหนึ่ง (ป้ายชื่อ ไม่ใช่วัตถุ)
รอบนี้ผมสร้าง **ธุรกรรมการเก็บ** ครบเส้น — และไปเจอกำแพงที่ **ไม่ได้อยู่ในรายการอุปสรรคของใคร**

เอกสารเก่าเขียนว่า *"Door 6 (persist) มี schema แต่ไม่มีตัวเขียนแถวไอเทมใหม่"*
🔴 **ประโยคนั้นจริง แต่ไม่ครบ และส่วนที่ขาดหายอันตรายกว่ามาก:**

`store.py` โหลดกระเป๋าผ่าน `inventory.require_known_backpack` ซึ่ง **ตรวจเนื้อหา ไม่ใช่แค่รูปทรง**
มันรับได้ **สองสแนปช็อตเท่านั้น** — สี่ชิ้นที่ ship มา กับสามชิ้นหลัง merge V111
และ `legacy_bridge` ประกอบ attr ตอนเข้าโลกผ่าน **ฟังก์ชันเดียวกัน**

**สามด่าน ทั้งหมดอยู่บนเส้นเลือกตัวละครเส้นเดียว** (`runtime.py:3645` → `session.select_and_start`):

```
1. store._load_backpack     -> require_known_backpack -> ValueError
2. session.select_and_start -> is_unmoved_baseline    -> PermissionError
3. legacy_bridge.start_game -> make_backpack_attr     -> require_known_backpack
```

🔴 **และสองข้อยกเว้นนี้ถูกตอบคนละแบบ** — `runtime.py:3646` ครอบไว้ด้วย `except (KeyError, PermissionError)`
⇒ ด่าน 2 = **ไม่ตอบอะไรเลย ไคลเอนต์ค้างที่ "connecting"** · ส่วนด่าน 1 เป็น `ValueError` **ซึ่ง handler นั้นไม่รับ**
⇒ มัน unwind เธรดฟังของคอนเนกชันแทน

⇒ 🔴 **ถ้าเขียนแถวไอเทมใหม่ลง DB วันนี้ ผลไม่ใช่ "ไม่ค้าง" แต่คือ "ตัวละครเข้าโลกไม่ได้อีกเลย"** — เงียบหรือดัง แล้วแต่ว่าชนด่านไหนก่อน
⇒ และ `inventory.py` / `store.py` **ไม่ใช่เขตของสาย B** (ไม่ใช่โมดูลใหม่ของสายนี้)
⇒ รอบก่อน `pf-adversary` จับผมได้ว่า **ทำตัวดักของเลนอื่นอ่อนลง** ผมจะไม่ทำซ้ำอีก

## ④ครึ่ง 🔴 **คำถามที่สอง ที่ผมตัดสินเองไม่ได้: ใครเป็นเจ้าของตัวนับ item identity**

`pf-adversary` ถามคำถามเดียวที่ผมตอบเองไม่ได้ และมันถูก:

`next_item_identity` = **"ไอดีสูงสุดในกระเป๋า + 1"** — ซึ่งเป็น **รูปแบบที่ `mob_loot` พิสูจน์ไปแล้วว่าเป็นบั๊ก**
`DropLedger.next_key` เขียนเหตุผลไว้ทั้งย่อหน้า: **ตัวนับที่ derive จากสิ่งที่ "ยังอยู่" จะแจกค่าเดิมซ้ำทันทีที่ของหาย**

| ใช้/ทิ้ง/ขายดาบ | แถวหายจากกระเป๋า |
| เก็บยา | 🔴 **ได้ identity 5 อีกครั้ง** — ขณะที่ไคลเอนต์อาจยังถือ 5 ตัวเก่าอยู่ |

และ `inventory.py` บันทึกไว้เองว่าลูปที่ไคลเอนต์ใช้คือ **clear-by-identity แล้ว place-by-slot**
⇒ เป็นลูปที่สับสนได้พอดีกับของสองชิ้นที่ใส่ไอดีเดียวกัน

**สิ่งที่ผมทำไปแล้ว:** `next_item_identity(bag, issued_through=None)` — **รับ** mark จากผู้เรียกถ้ามี · ถอยไปใช้รูปแบบ derive ถ้าไม่มี
· `BagCell` พา mark เดินต่อให้ · mark ที่ **ต่ำกว่าแถวจริงในกระเป๋า ถูกปฏิเสธ**

**สิ่งที่ต้องให้คุณ/เลนไอเทมเคาะ:** จะเพิ่มคอลัมน์ `next_item_identity` ที่ `character_backpacks` ไหม
ถ้าเอา ⇒ เป็น migration ของเลนไอเทม และเลนนี้ส่ง mark เข้า `BagCell` บรรทัดเดียว

## ⑤ บรรทัดเดินสายที่ขอให้ chief ทำ (รอบถัดไป ไม่ใช่รอบนี้)

`runtime.py` เป็นของ chief ผมเขียนไว้ให้ครบใน `mob_pickup.MOB_PICKUP_WIRING` แล้ว สรุป:

1. เมื่อถอดรหัสคำขอเก็บได้แล้ว ⇒ `claim = mob_pickup.PickupClaim(identity, x, y, z, object_ref_u32, opaque_u8)`
0. **ตอนเลือกตัวละคร:** `bag_cell = registry.claim(character_id, store.get_backpack(...))`
   · `registry` = `mob_pickup.BagCellRegistry()` **หนึ่งตัวต่อเซิร์ฟเวอร์** ถือไว้แบบเดียวกับที่ถือ ledger cell ของฉาก
   · 🔴 **`claim()` คือหัวใจ** — เซลล์ที่สองของตัวละครเดียวกันจะจองช่องเดียวกันและไอดีเดียวกันกับตัวแรก
     และของหลุดจากพื้นทั้งสองชิ้น · ตัวที่สองจึงถูก **ปฏิเสธด้วยชื่อ `bag_already_claimed`**
   · `registry.release(character_id)` ตอน logout / หลุด / สลับตัวละคร
     (ถ้า teardown ไม่ทำงาน ตัวละครจะยังถูกจอง และการเลือกครั้งถัดไป **ปฏิเสธเสียงดัง** ซึ่งดีกว่าแจกตัวจองซ้ำเงียบ ๆ)
2. `outcome = bag_cell.commit_pickup(drop_ledger_cell, claim, legacy)`
   · `drop_ledger_cell` คือ `DropLedgerCell` ตัวเดิมของฉาก **ไม่ต้องมีตัวที่สอง**
   · 🔴 **ส่ง `legacy` เข้าไปด้วย** — ไบต์คำตอบจะถูกประกอบ **ข้างในธุรกรรม ก่อนของหลุดจากพื้น**
     ⇒ ไบต์มีปัญหา = **ปฏิเสธการเก็บ** ไม่ใช่ **กินของทิ้ง** (รอบสองของ adversary จับได้ว่าเวอร์ชันก่อนหน้าทำอย่างหลัง)
3. 🔴 **ยังห้าม `INSERT`** จนกว่า A จะผ่าน — ให้ log `outcome.row_write.values()` ไว้ก่อน
   (ปลอดภัยที่จะ log เฉย ๆ ได้ **เพราะ registry+cell ไม่ใช่ฐานข้อมูล เป็นตัวที่กันการเก็บสองครั้งในเซสชันเดียวกัน**)
4. ส่ง **`outcome.delta`** ให้ผู้เล่นคนนั้น — เป็นคู่ `(pc, frame)` ที่ข้อ 2 ประกอบและตรวจแล้ว
   🔴 **ห้ามเรียก `bag_delta_pc` เอง** (nonclaim 3: **ไม่มีใครเคยเห็นไคลเอนต์รับ shape นี้สำหรับของที่มันยังไม่มี**)
5. 🔴 **ตัวตัด (prune) ที่ `mob_loot` บังคับให้ทำ ฆ่าคำขอที่กำลังเดินทางได้** — มันลบแถวในช่วงเวลาเดียวกับที่คำขอเดินทาง
   เลนนี้แยกไม่ออกระหว่าง "คนอื่นเก็บไป" กับ "ตัวเราเองตัดทิ้ง" จึงไม่พูดทั้งสองอย่าง
