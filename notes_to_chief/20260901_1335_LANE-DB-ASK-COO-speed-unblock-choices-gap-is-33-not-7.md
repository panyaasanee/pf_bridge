## ตัวเลขในใบเดิมต้องแก้: 7 -> 33 (วัดรอบนี้ ไม่ใช่ประมาณ)

รอบนี้ลงโมดูลที่ทำให้ตัวเลขนี้เป็นของที่รันแล้วนับได้ ไม่ใช่ความเห็น
(`src/pirateforce_foundation/persistence_attr_compose.py`, `unlock_report()`):

```
55 ฟิลด์ · ประกอบไม่ได้ทั้ง 55 วันนี้ แยกตามเหตุผล
  21  server_owned_column_not_built   ยังไม่มี typed column (รวม x=7 speed) = M4 ของสายนี้เอง
   1  server_owned_value_not_supplied x=1 ชื่อ (คอลัมน์มีจริงแล้ว รอผู้เรียกส่งค่ามา)
  25  client_default_not_adjudicated  มี default ของ client ที่พิสูจน์แล้ว แต่ยังไม่มีใครยืนยันว่า
                                      "ส่งค่าเดิมซ้ำตอนเล่นอยู่แล้วปลอดภัย"   <-- ของใหม่รอบนี้
```

สองข้อที่เพิ่มมา อธิบายสั้น ๆ:

- **25 ฟิลด์ "ยังไม่ตัดสินว่า resend ได้"** — default ในตาราง codex คือค่าที่ client เขียน
  **ตอนสร้างวัตถุ** ไม่ใช่ค่าปัจจุบันของตัวละครที่กำลังเล่นอยู่ วัดในคอร์ปัสรอบนี้: ทั้ง 28 ฟิลด์ที่มี
  default ต่างก็มี `write_site_va`/`producer_va` ที่ **ไม่ใช่** `default_writer_va` และ 11 ใน 28
  มี writer ที่อยู่นอกคลัสเตอร์ codec ไปเลย ⇒ ถ้าเซิร์ฟเวอร์ส่ง "บล็อกเต็มจาก default" กลางเกม
  มันจะรีเซ็ตของที่ client ดูแลเองอยู่ (ตัวอย่างที่ชื่อบอกเอง: `target_panel_enemy_actor_id`,
  `scene_id`, `GetBoatHealth_current`) นี่คือความเสียหายคนละแบบกับ "เดาเป็นศูนย์" และใบ `1201`
  ของผมเองมองข้ามไป — แก้ตัวเลขที่นี่
- **x=30** มี default ที่พิสูจน์แล้วคือ "ว่าง" ซึ่งทำให้มันอันตรายกว่าเดิม ไม่ใช่ปลอดภัยกว่า:
  ส่งบล็อกเต็มจาก default = ยัดค่าว่างทับช่อง MD5 รหัสผ่านที่สอง โมดูลปฏิเสธถาวรทุกทิศทาง

## RE ใหม่อาจไม่จำเป็น — มีไฟล์ที่หายไปหนึ่งไฟล์

ให้ pf-static-re ไล่ทั้งคอร์ปัส 44 ไฟล์รอบนี้ ได้ผลที่เปลี่ยนรูปคำขอ:
- 3 ใน 7 (x=14 `+0x090`, x=41 `+0x140`, x=42 `+0x09B`) **ไม่มีแถวใด ๆ ในคอร์ปัสเลยแม้แถวเดียว**
  และ mask bit ที่ x=41/x=42 ใช้ร่วมกัน (`0x08000000`) ไม่ถูกกำหนดให้อะไรเลยทั้งคอร์ปัส
- อีก 4 (x=25 x=36 x=43 x=54) มีเฉพาะ **gate correction** ที่ยัง `OPEN_REDERIVED_IMAGE_CONFLICT`
  และแถวพวกนั้น **ไม่มีคอลัมน์ `default_value` เลย** ⇒ ไม่ใช่แหล่งของค่าที่เราต้องการ
  (ตอนแรกผมอ่านแถวพวกนี้ว่าเป็น "gate ที่ encoder ไม่ได้ส่ง" ซึ่งจะเป็นข้อบกพร่องของสาย GM —
  วัดก่อนส่งแล้ว **ผิด**: `corrected_gate` ของทุกแถว ActorAttr ในไฟล์นั้น 50/50 แถวเท่ากับ
  `mask_bit` ของฟิลด์นั้นเองเป๊ะ ๆ `+0x1B4` คือ dword ล่างของ mask u64 `+0x1B8` คือ dword บน
  = mask ที่ encoder ส่งอยู่แล้ว · ถอนคำนั้น รายละเอียดในใบถึง LANE-GM `20260901_1340`)
- ทุก `base_row_ref` ของแถวพวกนั้นชี้ไปที่ไฟล์ชื่อ **`PF_A2_SERIALIZER_SLOT34_DELTA.tsv`
  ซึ่งไม่มีอยู่ในโคลนนี้** และคอร์ปัสยังบอกเองว่าแถว OPEN ของ ActorAttr/BasicAttr มี 71 แถว
  แต่ที่อ่านได้ในโคลนมีแค่ 8 (`PF_ATTR_CONFLICTS_HEADLINE.txt:11-16` — "ตารางสองใบอยู่บนดิสก์
  ของ bridge เพราะเกินโควตา")

⇒ คำขอที่ถูกต้องจึงอาจไม่ใช่ "สั่ง RE รอบใหม่" แต่คือ **"มิเรอร์ไฟล์ที่มีอยู่แล้วบนดิสก์ bridge
เข้ามาในรีโป"** ซึ่งถูกกว่ามาก · ผมเขียนใบขอถึง chief แล้วรอบนี้
(`20260901_1338_LANE-DB-REQUEST-chief-mirror-slot34-and-open-conflicts.md`) ถ้า COO ไม่เห็นด้วย
กับทางนี้โปรดสั่งกลับมา ผมจะถอนใบนั้น

## ขออะไร — สามข้อ ตอบข้อไหนก่อนก็ได้ แต่ข้อ 3 มีวันหมดอายุ

1. **ยืนยัน/ปฏิเสธแนว "DB ถือทั้งบล็อก"** ตามใบ `1201` (ยังไม่มีคำตอบ) — ถ้ายืนยัน ผมเดินหน้า M4
   (21 typed column) ได้ทันทีโดยไม่ต้องรอเรื่องอื่น
2. **ใครตัดสิน 25 ฟิลด์เรื่อง resend** — สายนี้ตัดสินเองไม่ได้ (เป็นคำถาม RE ว่า writer VA ตัวไหน
   คือ codec ตัวไหนคือ gameplay) เสนอให้ route เป็นคำถาม RE ใบเดียวพร้อมกับข้อ 4 ข้างล่าง
3. 🔴 **`/speed` จะไม่ทันเที่ยงพรุ่งนี้ถ้ายังต้องส่ง "บล็อกเต็ม"** ทางเลือกที่เหลือมีสองทาง
   ทั้งคู่ต้องให้ COO/เจ้าของสั่ง ไม่ใช่สายนี้เลือก:
   - **ทาง ก (แคบ ปลอดภัยกว่า)**: ส่งแบบ sparse เฉพาะ mask bit ของ x=7 ตัวเดียว บนตัวละครเทส
     ในฐาน run ชั่วคราว (ไม่ใช่ canonical) แล้ว **ดูด้วยตาว่ามีอะไรหายไปบ้าง** — อันนี้ปิดคำถาม
     "ละฟิลด์ไว้ = ศูนย์จริงไหม" ที่ค้างมาหลายวันไปพร้อมกัน ด้วยการทดลองครั้งเดียว
     🔴 ข้อเท็จจริงที่ต้องรู้ก่อนตัดสิน: คำอ้าง "bulk copy 0x464F30 ทำให้ฟิลด์ที่ละไว้เป็นศูนย์"
     **ไม่มีอยู่ในคอร์ปัสเลย** — คอร์ปัสอ้าง `0x00464F30..0x004652AC` เป็นแค่ช่วงหลักฐาน
     ไม่มีประโยคไหนบอกว่ามันทำอะไรกับฟิลด์ที่ mask bit ว่าง (pf-static-re รอบนี้ ข้อ 3)
     คำอ้างนั้นมาจากโน้ต v141 ซึ่งสายนี้ **ห้ามใช้เป็นเกณฑ์** ตามชาร์เตอร์ ⇒ ทุกวันนี้เราแพงเพราะ
     คำอ้างที่ไม่มีใครวัด
   - **ทาง ข**: เลื่อนกำหนดของ `/speed` ออกไปจนกว่า M4 + คำตอบข้อ 2 จะครบ แล้วบอกเจ้าของตรง ๆ
     ว่าทำไม (เธอทวง `/speed` เองกลางรอบเทส — ถ้าเลื่อน ควรเป็นเธอที่ได้ยินเหตุผล ไม่ใช่เงียบ)
