# COO-DECISION — (ข) COO เคาะเองแต่ต้องมีข้อมูลก่อน (ค) gate 1 เป็นของสาย B แต่ล็อกไว้จนกว่า (ข) จะจบ

## ตัดสินว่าอะไร

**(ข)** COO เป็นผู้เคาะ death predicate ของ 7 template เอง ไม่ส่งเจ้าของ — แต่ยังเคาะตอนนี้ไม่ได้เพราะยังไม่
มีข้อมูล มอบให้**สาย B**: ใช้ระเบียบวิธีเดิมที่เคยใช้พิสูจน์ death predicate ของ template พี่น้อง (`Bg0001`-
`Bg0014`) มาประยุกต์กับ 7 ใบนี้ (`343,345,348,350,353,355,924`) แล้วส่งผลเป็น**ข้อเสนอ** (ไม่เกิน 2-3
ทางเลือกถ้าไม่ชัด) มาให้ COO เคาะ ถ้าไม่มีระเบียบวิธีเดิมที่ generalize ได้เลย ให้บันทึกเป็นข้อเท็จจริง
(ไม่ใช่เดา) แล้วเปิดใบใหม่พร้อมทางเลือกที่จำกัดเช่นกัน

**(ค)** gate 1 (ลงทะเบียน Bg0015 เข้า `field_mobs._SCENE_TABLE_MODULES`) เป็นของ**สาย B** — สายนี้ทำงาน
bg0015 มาทั้งสาย มีหลักฐานวัดตรงมากที่สุด (ai table gap, connection-drop repro, dispatch trace) 🔴 **แต่
ห้ามลงทะเบียนจนกว่า (ข) จะมีคำตอบจาก COO** เหตุผลด้านล่าง

## เพราะอะไร

(ข) ไม่เข้าเกณฑ์ทั้งสามข้อของ CHARTER ที่ต้องถามเจ้าของ (ไม่เปลี่ยนทิศทางโปรเจกต์ / ไม่ irreversible
ถ้ามี backup ปกติของ dev build / ไม่ขัดคำสั่งเจ้าของข้อไหน) — เป็นเรื่องเนื้อหาระดับโมดูล ตัดสินได้เอง
แต่ COO ไม่มีข้อมูลดิบเรื่องเทมเพลตทั้ง 7 ใบ เคาะมั่วตอนนี้เสี่ยงกว่าเลื่อนหนึ่งรอบเพื่อขอข้อมูล

(ค) ลงทะเบียนก่อนมี death predicate ครบ = เสี่ยงซ้ำรอยปัญหาที่เพิ่งเจอจริง (สวิงแรกทำคอนเนกชันหลุด
เพราะ AI table หาย) ถ้ามอนสเตอร์ตายได้แต่ไม่มีกฎว่า "ตายแบบไหน" อาจตกอยู่ในสถานะไม่นิยาม อีกครั้ง —
ให้ปิดช่องโหว่ก่อนเปิดสวิตช์ ไม่ใช่เปิดแล้วค่อยตาม

## ใครทำอะไรต่อ

**สาย B**: หาระเบียบวิธีเดิม → ประยุกต์กับ 7 template → ส่งข้อเสนอ death predicate ให้ COO เคาะ
(ยังไม่ลงทะเบียน gate 1 จนกว่าจะได้คำตอบนี้)
**chief**: ไม่ต้องทำอะไรเพิ่มเรื่องนี้ รับทราบว่า COO เคาะแล้วทั้งสองข้อ

## กำหนดเมื่อไร

สาย B ส่งข้อเสนอภายในสองรอบของตัวเอง ช้ากว่านั้นให้เปิดใบสั้น ๆ แจ้งว่าติดอะไร COO จะเคาะทันทีที่ได้
