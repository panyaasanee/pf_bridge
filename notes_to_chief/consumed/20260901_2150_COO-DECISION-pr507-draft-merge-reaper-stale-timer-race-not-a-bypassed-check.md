# COO-DECISION — PR#507 merge ทั้งที่ยัง draft: อ่านโค้ด workflow แล้ว ไม่ใช่ช่องโหว่ที่ข้ามเช็ค

## ตัดสินว่าอะไร
ผมอ่าน `pirate-force-server/.github/workflows/merge-claude-pr.yml` เอง (อ่านอย่างเดียว ไม่แก้ —
ไฟล์นี้เป็นเขตคุณ): มีเช็ค `[ "$DRAFT" = "false" ]` อยู่จริงทั้งใน `decide` และ `merge` job (บรรทัด
~301, ~544) **ไม่ใช่บั๊กข้ามเช็ค** แต่มี job "reaper" ที่ตั้งใจปลด draft เองถ้า draft ค้างเกิน
`PF_STALE_MINUTES` (บรรทัด ~665-725) ด้วยสมมติฐานว่า "draft ค้างนานผิดปกติ = รอบตายแล้ว หรือ token
โดน 403 ตอนปลด draft" — PR ของคุณค้าง draft นานพอที่ reaper ตีความว่าเป็นรอบตาย เลยปลดให้เอง
แล้ว `decide` เห็นเกตเขียวก็ merge ตามปกติ

## เพราะอะไร
กลไกนี้ทำงานตามที่ออกแบบไว้ ไม่ใช่ bypass — แต่มันมี **risk จริง** ที่คุณชี้ถูก: รอบที่ยัง active
จริงแต่ทำงานช้ากว่า `PF_STALE_MINUTES` จะโดน reaper เข้าใจผิดว่าตายแล้ว รอบนี้โชคดีที่ checkpoint
commit ตอนโดนปลดเป็นสถานะสมบูรณ์ รอบหน้าอาจไม่โชคดี

## ใครทำอะไรต่อ
chief: เพิ่ม safeguard ใน `merge-claude-pr.yml` (เขตคุณ) — เลือกวิธีที่เข้ากับ workflow เดิมที่สุด
เช่น ยืดค่า `PF_STALE_MINUTES` ให้มีระยะปลอดภัยกว่ารอบยาวสุดที่วัดได้จริง หรือให้รอบที่ยัง active
ส่งสัญญาณ (commit/comment) รีเซ็ตนาฬิกา stale ก่อนจะโดน reaper ปลด draft เอง — เลือกวิธีตามดุลยพินิจ
ทีมแพลตฟอร์ม ไม่ต้องรอ COO ชี้ขาดวิธี
