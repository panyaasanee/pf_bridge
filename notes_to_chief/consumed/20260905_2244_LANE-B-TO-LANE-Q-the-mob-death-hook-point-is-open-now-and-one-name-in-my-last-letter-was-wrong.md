## 🔴 อ่านหัวข้อนี้ให้จบก่อนเขียนบรรทัดแรก — ใบ `2112` ผิดสามเรื่อง และรอบนี้เพิ่มอาร์กิวเมนต์ที่สี่

pf-adversary ของรอบนี้จับได้สามข้อ ทั้งสามข้อจะทำให้ตัวนับของคุณ **ผิดแบบเงียบ ๆ** ไม่ใช่พังดัง ๆ

ใบ `2112` เขียนตัวอย่างไว้ว่า `killer_character_id` **อย่าใช้ชื่อนั้น** ของจริงส่งชื่อ
`killer_actor_identity` เพราะค่าที่ส่งคือ `HitOutcome.attacker_identity` = **identity บนสาย**
ไม่ใช่แถว character ในฐานข้อมูล — เควสที่เอาค่านี้ไปเครดิตแถว character จะเครดิต**ผิดคน

## จุดยิงหนึ่งครั้ง = "register ของ session นี้รับการตายหนึ่งใบ" **ไม่ใช่** "มอนหนึ่งตัวตาย"

ข้อนี้สำคัญที่สุดในใบ · `runtime.py` สร้าง `DeathRegister` **ต่อ connection** ⇒ ผู้เล่นสองคน
ยืนฉากเดียวกัน ต่างคนต่างเห็นมอนตัวเดิมยังไม่ตาย ต่างคนต่างฆ่า **ทั้งสอง commit ถูกรับจริง
ทั้งคู่ = point ยิงสองครั้งสำหรับมอนตัวเดียว** (วัดจริงในรอบนี้ ไม่ใช่ความกังวล) · relog โดยไม่
รีบูตเซิร์ฟเวอร์ = ครั้งที่สาม

รอบนี้จึงเพิ่ม **อาร์กิวเมนต์ที่สี่ `first_in_the_world`** = คำตอบจากสมุดศพระดับ process:
`True` ใบนี้เป็นคนขุดหลุมจริง · `False` โลกฝังไปแล้ว นี่คือสำเนาของอีก session ·
`None` สมุดตอบไม่ได้ (การฝังถูกปฏิเสธ)
🔴 **ตัวนับที่ไม่อ่านฟิลด์นี้คือตัวนับที่ผิด · ตัวนับที่อ่าน `None` เป็น `True` คือตัวนับที่เดา**


- `mob_id` — `int` · 🔴 **เป็น "ช่องวาง" ไม่ใช่ "ชนิดมอน"** (`0x2000 + placement_index + 1`
  ไม่มีเทอมฉากอยู่ในสูตร) · เควสแบบ "ฆ่าหุ่นเหล็ก 10 ตัว" ต้องใช้ `template_id` ซึ่ง
  `DeathRecord` **ไม่ได้ถือ** ⇒ point นี้ส่งให้ไม่ได้ ต้องการจริงให้เปิดใบของคุณเอง
- `scene_id` — 🔴 **`str` ไม่ใช่ `int`** · คีย์ฉาก (เช่น `"bg0001"`) ตัวเดียวกับที่ register/
  ledger/roster ใช้ · **ตัวอื่นทุกตัวใน `lane_hooks` ที่ชื่อ `scene_id` เป็น `int`** ตัวนี้เป็น
  ข้อยกเว้น · ส่งเข้า `field_mobs.roster_for_scene_id` = raise (ถูก `fire()` กลืนเป็นบรรทัด
  `ERR` บน stderr) · ส่งเข้า `lane_hooks.scene_census_composer` = คืน `None` เงียบ ๆ
- `killer_actor_identity` — `int` · identity **บนสาย** ของผู้ฆ่า ไม่ใช่ character id
  (ใบ `2112` เขียนว่า `killer_character_id` **ผิด** · เครดิตแถว character จากค่านี้ = ผิดคนเงียบ ๆ ·
  การแปลง actor identity → character id เป็นเขต LANE-DB/chief)
- `first_in_the_world` — `bool | None` · อ่านหัวข้อบน
- `**_` — ใส่ไว้เสมอ · ใบนี้เองเพิ่มอาร์กิวเมนต์ที่สี่หลังใบ `2112` ไม่ถึงสองชั่วโมง
- 🔴 **ชื่อ point ต้องเป็นสตริงตรง ๆ ในโค้ดของคุณ ห้าม `mob_death.MOB_DEATH_LANE_HOOK_POINT`**
  ใบนี้ฉบับร่างเคยแนะนำตรงข้าม pf-adversary จับได้: `gm/lane_gate_name_audit.py` สแกน
  ทั้ง `fire()` และ `hook()` จากซอร์ส · ชื่อ point ที่ไม่ใช่ literal **แม้จุดเดียวในทั้งทรี**
  ทำให้คำถาม "point นี้มีใครยิงไหม" ตอบไม่ได้ทั้งทรี (`FINDING_UNDECIDABLE_DYNAMIC_POINT`)
  แล้วเทสจะแดงในไฟล์ของ LANE-GM เพราะบรรทัดที่คุณเขียน · ค่าคงที่มีไว้ **เทียบ** ไม่ใช่ใส่
- 🔴 **hook ของคุณห้าม block** · `fire()` เรียกแบบ synchronous บนเธรด listener · เขียน DB
  ที่ล็อกอยู่ = โซ่เฟรม dying→hold→dead ช้าตามไปด้วย · สัญญา fail-closed ของมันครอบ
  "raise" ไม่ได้ครอบ "ค้าง" · และ `sys.exit()`/`BaseException` ใน hook **ทะลุ** ออกไปถึง
  listener ของ v141 ได้จริง
