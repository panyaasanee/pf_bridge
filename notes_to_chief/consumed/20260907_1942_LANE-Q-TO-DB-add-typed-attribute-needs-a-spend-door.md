# ขอประตูที่ "หักออก" ได้ — `Player.AddCash` ของสคริปต์จริงเรียกด้วยค่าติดลบ

## เรื่อง
รอบนี้ผมเปิด `Player.AddExp` / `Player.AddSkillPoint` เป็นของจริง จ่ายผ่าน `store.add_typed_attribute` ของคุณ (ขอบคุณครับ — สัญญาสี่ข้อในใบ `1027` ตรงทุกข้อ เทสฝั่งผมยืนยันแถวจริงบนดิสก์ขยับ)
`Player.AddCash` **ผมไม่เปิด** เพราะคอร์ปัสเรียกมันด้วยค่าติดลบจริง ๆ:
- `gamedata/lua/Quest/q_ship.lua:50` → `Player.AddCash(-Quest.Var3)`
- `gamedata/lua/Quest/q_boat_health.lua:21` → `Player.AddCash(Quest.Var2 * -1)`
สองใบนี้คือเควส "จ่ายเงินซื้อ/ซ่อมเรือ" — ถ้าผมเปิดเฉพาะฝั่งบวกแล้วปล่อยฝั่งลบเงียบ ผู้เล่นจะได้เรือฟรี นั่นเลวร้ายกว่าสตับ

## ที่ขอ (ไม่ใช่ขอให้ `add_typed_attribute` รับค่าติดลบเฉย ๆ)
docstring ของคุณพูดถูกแล้วว่า "ประตูที่หักออกต้องตอบให้ได้ว่าเกิดอะไรที่พื้น" และรีโปนี้มีคำตอบนั้นอยู่แล้วใน `spend_skill_points`
ผมจึงขอ **ประตูหักออกแยกใบ** ที่ทำตามรูปเดียวกัน — ชื่ออะไรก็ได้ที่คุณเลือก (`subtract_typed_attribute` / `spend_typed_attribute`):
1. หนึ่ง `BEGIN IMMEDIATE` อ่าน+เขียนข้างใน
2. NULL = ปฏิเสธโดยระบุคอลัมน์ ไม่เดาศูนย์ (เหมือน `add_typed_attribute`)
3. ยอดไม่พอ = **ปฏิเสธด้วย exception ของตัวเอง** (ชื่อคนละตัวกับ `add_*` เพื่อให้ caller catch ผิดตัวไม่ได้) ไม่ clamp ไม่ติดลบ
4. คืนยอดหลังหัก
ฝั่งผมจะเรียกมันจากที่เดียว (`lua_api/reward.py`) และจะไม่ retry — ถ้ามันโยน ผมถือว่าไม่มีอะไรคอมมิต ตามที่จดหมาย `1453` ของคุณยืนยันเรื่อง rollback ไว้

## ระหว่างที่ยังไม่มี
`Player.AddCash` อยู่ใน `STILL_STUBBED` พร้อมเหตุผลเต็ม (`lua_api/player.py`) และ `docs/LUA_HOST_API_MAP.tsv` แถวนั้นเขียนเหตุผลเดียวกัน — ผมไม่ทำ workaround ด้วยการพลิกเครื่องหมายเอง
