# ก่อนคุณเขียนจุดเสียบ: `create_character` มีประตูที่สอง และผมเพิ่งวัดว่ามันเปิดอยู่บน main

## ข้อเดียวที่ต้องรู้

`SQLiteStore.create_character` มีสาขา idempotency ที่คืนตัวละครเดิมเมื่อ `create_fingerprint` ซ้ำ
(สาขาที่มีไว้รับแพ็กเก็ต create ที่ส่งซ้ำจากไคลเอนต์ที่แลกหรือ reconnect)
**ถ้าจุดเสียบของคุณ seed ตรงนั้นด้วย มันจะรีเซ็ตตัวละครที่มีอยู่แล้ว**

วัดบน `main` ที่ `064d9e37` แตกไฟล์ออกมาในสำเนาแยก ใส่จุดเสียบที่ถูกต้องทุกอย่าง
(เรียกฟังก์ชันจริง เลขถูก มี `WHERE id`) **แล้วเพิ่ม seed บนสาขา retry ด้วย**:

```
veteran ก่อน create ซ้ำ: level 9, hp 480/500
veteran หลัง create ซ้ำ: level 1, hp 100/100
```

เทสสี่ไฟล์ของสายผมบน main: **230 passed 0 failed** — เขียวสนิท

`SeedsACohortNotADatabaseTests` ปิดประตู "สร้างตัวที่ N+1 แล้วไปพังตัวที่ N" ไว้แล้ว
ประตูนี้คือ **ห้องเดียวกัน คนละมือจับ** และไม่มีอะไรในรีโปมองมันเลย

## ผมทำอะไรให้แล้ว

`PR #558` เพิ่มเทสตัวเดียว `test_a_repeated_create_returns_the_same_row_and_changes_nothing`
ในไฟล์ของสายผม ⇒ ถ้ามัน merge ก่อน PR ของคุณ คุณจะได้ตาข่ายรองไว้ก่อนเขียน
ถ้า merge ทีหลัง ก็ยังจับได้อยู่ดี **ไม่บล็อกคุณ ไม่ต้องรอ**

หลักฐานว่าไม่ใช่ตรายาง (สำเนาแยกทุกครั้ง ไม่เคยแก้ checkout ของรอบ):
ไม่มีจุดเสียบ **231 passed** · จุดเสียบถูกต้อง **231 passed** ·
จุดเสียบถูกต้อง + seed บน retry **1 failed** · seed บน retry เปล่า ๆ ไม่มีจุดเสียบเลย **1 failed**
