# พบช่องโหว่ในการ์ด "ห้ามพูดคำ quest/shop/trade/price/reward/store5" ทั้งโปรเจกต์ — ไม่ใช่แค่สามไฟล์ของ LANE-UI

## สั้น
ระหว่างแก้บั๊กที่ `pf-adversary` พบใน `#733` (ดูรายละเอียดเต็มใน `pirate-force-server#742`) พบว่าการ์ด
`test_no_foundation_module_implements_quest_or_shop_behavior` ใช้ regex `\bword\b` ซึ่ง **ไม่จับคำที่อยู่ใน
snake_case identifier เลยไม่ว่าไฟล์ไหนในโปรเจกต์** เพราะ underscore (`_`) นับเป็น `\w` ใน Python regex ⇒ ไม่มี
word boundary ระหว่าง `_` กับตัวอักษร พิสูจน์แล้ว: เติมฟังก์ชัน `settle_trade(offered_items, requested_items):
offered_items.clear(); requested_items.clear(); return True` ลงไฟล์ทดลอง (isolated worktree ไม่ได้ commit) —
การ์ดไม่จับ ทั้งที่ฟังก์ชันทำพฤติกรรม trade-settlement จริงและตั้งชื่อด้วยคำที่อยู่ในลิสต์ตรง ๆ

## ทำไมไม่แก้เองรอบนี้
ลองแก้ regex เป็น `(?<![a-zA-Z0-9])word(?![a-zA-Z0-9])` (นับ underscore เป็นตัวแบ่งคำด้วย) แล้วรันการ์ดเดิมทั้งไฟล์
— จับของใหม่เพิ่มในไฟล์ที่ไม่ใช่เขตเขียนของ LANE-UI เลย: `field_drop_tables.py`, `loot_*.py` (อย่างน้อยสองไฟล์
จากที่เห็นตอนรัน ยังไม่ได้ไล่ครบ) แต่ละ hit ต้องมีคนของเขต (LANE-B ดูจากชื่อไฟล์) ตรวจว่าเป็นคำจริงที่เป็น
false positive (เช่น ตัวแปรชื่อ `quest_id` ที่แค่ผ่านค่า ไม่ได้ทำ business logic) หรือเป็นบั๊กจริงแบบเดียวกับที่
`#742` แก้ — **ฉันตัดสินแทนเขาไม่ได้** (ไม่ใช่เขตเขียน ไม่รู้บริบทไฟล์) ⇒ ถอนการทดลองออก ไม่รวมใน `#742` รายงาน
ไว้ที่นี่แทน

## ผลกระทบ (เท่าที่วัดได้ตอนนี้ ไม่ได้ไล่ครบ)
- ไฟล์ที่การ์ดเคยพลาด (ก่อน `#742`): `ui_social_wire.py`/`ui_party_wire.py`/`ui_trade_wire.py` ผ่าน exemption
  ที่กว้างเกินจริง (จุดที่ `#742` ปิดแล้ว)
- ไฟล์ที่ยังไม่ได้ตรวจว่าการ์ดพลาดจริงหรือ false positive: `field_drop_tables.py`, `loot_*.py` (พบตอนทดลอง
  regex กว้างขึ้น — **ไม่ยืนยันว่ามีบั๊กจริง** แค่บอกว่าการ์ดปัจจุบันมองไม่เห็นทั้งสองไฟล์นี้เลยถ้ามีคำในลิสต์แบบ
  snake_case)
- ไฟล์อื่นทั้งโปรเจกต์ที่มีคำ `quest`/`shop`/`store5`/`price`/`reward`/`trade` แบบ snake_case — **ไม่ได้ไล่ครบ**
  รอบนี้แค่เจอสองไฟล์ตัวอย่างระหว่างรัน ไม่ใช่การสำรวจเต็ม
