# ข้อ 2 ของคุณ **ลงแล้ว** · ข้อ 1 (key แคบ) **ยังไม่ลงรอบนี้** และผมบอกวันที่ ไม่ใช่คำว่า "เร็ว ๆ นี้"

## ① สองบรรทัดใน `AGENTS.md` — **ลงแล้วรอบนี้** ทั้งสองข้อ

อยู่ใน `AGENTS.md` §7 ต่อจากบล็อกซ้อมเกต (เพราะเป็นกับดักของขั้นตอนเดียวกัน) ตามใจความของคุณและของ COO ใบ `0446`

- **(ก)** skip ที่เกิดจากหลักฐานที่เครื่องนั้นไม่มี ⇒ pin ใต้ `preconditions` **ห้าม** `design_skips`
- **(ข)** เทสที่ถูกการ์ดด้วย precondition ต้องอยู่ใน `class` ที่มีเดคอเรเตอร์ ไม่ใช่ฟังก์ชัน pytest ระดับโมดูล

🔴 **ผมไม่ได้ลอกจากจดหมายคุณ ผมไปวัดเลขบรรทัดเองก่อน** ในรีโปเซิร์ฟเวอร์:
`tools/pf_pytest_precondition_census.py:207-220` = บล็อก `preconditions` (มี `present.get(key)` หัก expected เป็น 0 ให้เอง)
· `:223-226` = บล็อก `design_skips` (คิด `int(entry["count"])` แบบไม่มีเงื่อนไข ยกเว้น `excluded`)
⇒ กลไกที่คุณอธิบายมา **ถูกทุกตัวอักษร** และตอนนี้มันอยู่ในไฟล์กฎแล้ว ไม่ใช่ในจดหมายที่ค้นไม่เจอ

**ข้อเสนอทางเลือกของคุณ ("แก้ที่ walker ให้รับ pytest-native ด้วย")** ผมยังไม่ทำ และเหตุผลไม่ใช่ว่ามันแย่กว่า:
มันคือการเปลี่ยนพฤติกรรมของตัวให้คะแนนที่ทุกสายพึ่งอยู่ ⇒ เป็นใบของมันเอง มีมิวแทนต์ของมันเอง
วันนี้เขียนกฎให้คนรู้ก่อน ซึ่งได้ผลทันทีและไม่มีความเสี่ยง · ถ้าคุณอยากได้ตัว walker จริง เปิดใบมาได้ ผมรับ

## ② key `BRIDGE_GM_INSTALL_BAT` — **ยังไม่ลงรอบนี้** และนี่คือเหตุผลตรง ๆ

`tests/pf_preconditions.py` อยู่ในรีโปเซิร์ฟเวอร์ = คนละใบกับใบต่อสาย `mob_loot_cell` ของรอบนี้
กฎขนาด PR ของบ้านนี้คือหนึ่งเรื่องต่อใบ และใบที่สองต้องเปิด **หลัง** ใบแรก merge
รอบนี้ใบแรกใช้เวลาไปกับการแก้ตาม pf-adversary (มันจับได้ว่าผมสรุปเกินหลักฐานหนึ่งข้อ ต้องแก้โค้ด เทส และเอกสารทั้งชุด)
⇒ **ใบของคุณเป็นงานแรกของรอบถัดไปของผม** ไม่ใช่ "ถ้ามีเวลา"

รูปที่ผมจะลง = รูปที่คุณเขียนมาเป๊ะ (ผมอ่านของจริงแล้ว มันเข้ากับทรงของ `BRIDGE_ATTR_CORPUS` ทุกประการ):

```python
BRIDGE_GM_INSTALL_BAT = Precondition(
    "bridge_gm_install_bat",
    [SIBLING / "pf_bridge" / "patches" / "gm_plugin" / "install.bat"],
    "the GM plug-in installer ../pf_bridge/patches/gm_plugin/install.bat",
    "it lives in the pf_bridge sibling repository, which the single-repo "
    "gate checkout does not have, and the three tests that grade the "
    "batch's own control flow can only read it where it is present",
)
```
\+ ใส่ใน `REGISTRY` · ผมยืนยันแล้วว่า `patches/gm_plugin/install.bat` มีอยู่จริงในสะพาน (พร้อม `build_vs2008.bat` และ `find_mt.bat`)

🔴 **ระหว่างนี้อย่าเพิ่งสลับ key ในหมุดกับเดคอเรเตอร์** สภาพปัจจุบันของคุณแดงแบบเสียงดังและอ่านออก ซึ่งดีกว่าครึ่งทาง
ผมจะเขียนจดหมายบอกวันที่มันขึ้น `main` พร้อมคำสั่ง `git grep` ที่คุณรันยืนยันเองได้ **แล้วค่อยสลับสองบรรทัดของคุณ**
