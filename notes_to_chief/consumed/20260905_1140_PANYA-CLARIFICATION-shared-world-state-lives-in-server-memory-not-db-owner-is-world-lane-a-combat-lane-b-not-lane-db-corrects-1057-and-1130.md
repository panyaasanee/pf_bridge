## ถ้อยคำ Panya
> "ทำไมเรื่องของพื้น/ศพข้าม session ไม่เป็นของ A ทำไมเป็นของ DB — มอนตายแต่ละตัว ตำแหน่งมอนเปลี่ยนแต่ละตัว เลือดมอนเปลี่ยนแต่ละตัว ของดรอปบนพื้นทุกชิ้น มันไม่ต้องบันทึกลง DB อยู่แล้วตาม logic จริง มันควรอยู่แต่ใน world พอ reboot world กลับมา ไอเท็มไม่ได้ค้างต่อจาก boot ก่อน มอนที่โดนตีเลือดไปแล้วครึ่งหนึ่ง ตำแหน่งมอนล่าสุด ก็เช่นกัน"

## แก้ไข (แทนที่ถ้อยคำเดิม)
1. ใบ 1057 ข้อ 1 "สถานะโลกอยู่ที่เซิร์ฟเวอร์ + DB" → **"สถานะโลกอยู่ที่ world ในหน่วยความจำของ process เซิร์ฟเวอร์ แชร์ให้ทุก session ที่อยู่ฉากเดียวกัน อายุเท่ากับการบูตเซิร์ฟเวอร์ (reboot = reset)"** · สิ่งที่ลง DB มีเฉพาะสถานะที่ต้องรอดข้าม reboot และเป็นของตัวละคร/บัญชี (ตำแหน่ง/ฉากของตัวละคร · กระเป๋า · สกิล · เควส · class) — ของเหล่านั้น LANE-DB ทำอยู่แล้วและถูกต้อง
2. ใบ 1130 ข้อ 3(ข) ที่ ka1-A เสนอ "ย้ายงาน persistence ของโลกไป LANE-DB" — **ถอน** (ka1-A เข้าใจผิด เอา "แชร์ข้าม session" ไปปนกับ "บันทึกลง DB") · เจ้าของที่ถูก: **LANE-A = world state** (roster/ตำแหน่ง/ศพ/ของพื้น/อายุของ ต่อฉาก ในหน่วยความจำ แชร์ทุก session) · **LANE-B = combat state** (เลือดมอน ตาย เกิดใหม่ aggro — เขียนลง world ของ LANE-A ไม่ใช่ทะเบียนต่อ session) · LANE-DB ไม่รับงานโลก
3. เกณฑ์เดียวที่ต้องผ่านสำหรับ "shared world": **session ที่สอง (หรือ relogin โดยเซิร์ฟไม่ reboot) ต้องเห็นเลือดมอน ตำแหน่งมอน ศพ และของพื้นเหมือน session แรก** · ส่วน reboot เซิร์ฟเวอร์ = โลกใหม่ (ไม่ต้องกู้ของพื้น/เลือดมอนจากที่ไหน)
4. คำถามกำลังทีม (ใบ 1130 ข้อ 3) ยังคงอยู่ — แต่ให้ COO ประเมินบนการมอบหมายที่ถูกข้อ 2 (โหลดจะไปกอง LANE-A/LANE-B · LANE-DB ยังว่าง → COO เสนอเองว่าจะใช้ DB ทำอะไรที่เป็นงาน persistence จริง เช่น class/skill/quest หรือจะให้ช่วย world ในฐานะ "ลูกมือ" ภายใต้เจ้าของ A/B)
