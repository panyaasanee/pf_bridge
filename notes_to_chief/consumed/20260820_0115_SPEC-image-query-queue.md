# 📐 สเปก — คิวย้อนกลับสำหรับถามข้อมูลจากอิมเมจ (image query queue)

**provenance:** Panya สั่ง 2026-08-20 ~01:1x — *"คิวย้อนกลับ ทำได้เลยตอนนี้"*
**ผู้เขียนสเปก:** ผู้เทส cloud (มือเขียนแทน) · **ผู้ลงมือ: chief** (โค้ดใน `tools/` เป็นอำนาจ chief)

---

## ปัญหาที่มันแก้

`GameClient.local.bin` **จะไม่มีวันขึ้น cloud** (คำตัดสิน Panya: แกะ binary = งาน local ถาวร)
⇒ cloud chief ที่อยากรู้ข้อเท็จจริงระดับไบต์ **ต้องมีช่องทางถาม** ไม่งั้นเลนนั้นตัน

## ⭐ คุณสมบัติสำคัญที่สุดของดีไซน์นี้

**อิมเมจเป็นของตายตัว sha ตรึงแล้ว ⇒ ทุกคำตอบถูกต้องถาวร ไม่มีวันหมดอายุ**
⇒ **คำตอบทุกใบถูก commit เข้ารีโป และกลายเป็น fact pack ที่โตขึ้นเอง**
⇒ **คิวย้อนกลับ = ตัวสร้าง dossier แบบค่อยเป็นค่อยไป ตามความต้องการจริง ไม่ใช่ตามการเดา**
ยิ่งใช้ ยิ่งถามน้อยลง เพราะคำตอบเก่าสะสมอยู่ในรีโปแล้ว

## โครงไฟล์

```
pf_bridge\image_queries\
├── pending\      <- chief เขียนคำถามลงที่นี่ (ไม่ต้องถือธง)
├── answered\     <- ตัวรัน local เขียนคำตอบ + ย้ายคำถามมาไว้คู่กัน
└── README.md
```

**และคำตอบที่ตรวจแล้ว ให้ chief ยกเข้ารีโปที่**
`Pirate Force ServerProject\derived\image_facts\<subsystem>\` **(นี่คือที่ที่ dossier โตขึ้น)**

## รูปแบบคำถาม — `pending\<YYYYMMDD_HHMMSS>_<subsystem>_<seq>.query.json`

```json
{
  "id": "20260820_0130_deathchain_001",
  "asked_by": "chief round 93",
  "subsystem": "deathchain",
  "why": "ต้องยืนยัน byte guard ของ vtable +0x3C ก่อน flip matrix row",
  "kind": "bytes",
  "image_sha256_expected": "<sha ของ GameClient.local.bin>",
  "args": { "offset": 4439408, "length": 64 }
}
```

## ชนิดคำถามที่รองรับ (`kind`)

| kind | args | คืนอะไร |
|---|---|---|
| `bytes` | `offset`, `length` | hex dump |
| `hash` | `offset`, `length` | sha256 — **ยืนยันได้โดยไม่ต้องเห็นไบต์** |
| `search` | `pattern` (hex), `max_hits` | รายการ offset ที่เจอ |
| `strings` | `offset`, `length`, `encoding` | สตริงที่เจอพร้อม offset |
| `disasm` | `offset`, `length` | disassembly ช่วงนั้น |
| `xref` | `target_addr` | รายการ address ที่อ้างถึง |

## 🔴 การ์ดที่ต้องมี (ห้ามข้าม)

1. **`length` ต่อคำถามไม่เกิน 4096 ไบต์** สำหรับ `bytes` และ `disasm`
2. **เพดานรวมต่อวัน** (เสนอ 64 KB) — กันการถามทีละนิดจนได้อิมเมจทั้งก้อน
   ⇒ **ถ้าชนเพดาน = สัญญาณว่าออกแบบผิด ไม่ใช่สัญญาณว่าต้องขยายเพดาน** ให้หยุดแล้วคุยกับ Panya
3. **ทุกคำตอบต้องฝัง sha256 ของอิมเมจ** ถ้าไม่ตรงกับ `image_sha256_expected` → ตอบ `MISMATCH` ไม่ตอบข้อมูล
4. **ตรวจ `answered\` และ `derived\image_facts\` ก่อนถามเสมอ** — อิมเมจไม่เปลี่ยน คำตอบเก่าใช้ได้ตลอด
5. **ตัวรันไม่ตีความ** — คืนข้อเท็จจริงดิบ การตีความเป็นงาน chief
6. **ASCII ล้วนใน console** (บทเรียน cp874)

## รูปแบบคำตอบ — `answered\<id>.answer.json`

ต้องมี: `id` · `answered_at` · `image_sha256_actual` · `ok` (bool) · `data` · `error` (ถ้ามี)
· **`query_verbatim`** (คัดลอกคำถามมาทั้งดุ้น เพื่อให้คำตอบอ่านได้โดยไม่ต้องหาไฟล์คำถาม)

## ตัวรันฝั่ง local

- สคริปต์ `tools\pf_image_query_runner.py` (**chief เขียน**) — pure stdlib
- รันผ่าน **PF BRIDGE** ตามปกติ (ต้องแตะอิมเมจ ⇒ ต้องอยู่บนเครื่อง)
- **ตอบเป็นชุด** — อ่าน `pending\` ทั้งหมดแล้วตอบรวดเดียว ไม่ใช่ทีละใบ
- ⏱️ **จับเวลาแต่ละ kind แล้วบันทึกไว้** — จะได้รู้ว่า `disasm` แพงกว่า `bytes` แค่ไหนจริง ๆ

## 📊 สถิติที่ต้องเก็บตั้งแต่วันแรก (นี่คือหัวใจ)

ทุกครั้งที่ chief **อยากได้ข้อมูลจากอิมเมจแล้วไม่มี** ให้จดลง
`pf_bridge\image_queries\blocked_log.tsv` — คอลัมน์:
`timestamp · subsystem · lane_that_parked · kind · ตอบเองได้จากของเดิมไหม (y/n)`

⇒ อีกสองสัปดาห์จะรู้ **ด้วยตัวเลขจริง** ว่า:
- chief ติดบ่อยแค่ไหน · ติดที่ระบบย่อยไหน · คำตอบเก่าช่วยได้กี่ %
- **และนั่นคือสิ่งที่ตัดสินว่า dossier ต้องใหญ่แค่ไหน ไม่ใช่ความเห็นของใคร**

## ลำดับที่แนะนำให้ chief ทำ

1. สร้าง `blocked_log.tsv` + เริ่มจด **ทันที** (ฟรี ไม่ต้องเขียนโค้ด)
2. `pf_image_query_runner.py` รองรับ `bytes` + `hash` + `search` ก่อน (สามอันนี้ครอบคลุมงานส่วนใหญ่)
3. `strings` / `disasm` / `xref` ตามมาทีหลังเมื่อ `blocked_log` บอกว่าจำเป็น

## nonclaims

- สเปกนี้ **ยังไม่ผ่านการใช้งานจริงแม้แต่ครั้งเดียว** — ตัวเลขเพดาน 4 KB / 64 KB เป็น **ข้อเสนอ ไม่ใช่ผลวัด**
- **ไม่รู้** ว่า `disasm` บนอิมเมจ 14.1 MB ใช้เวลาเท่าไหร่ — ข้อ "จับเวลา" มีไว้แทนที่การเดานี้
- ผู้เทส **ไม่ได้เขียนโค้ดใน `tools/`** ตามกติกา (เป็นอำนาจ chief) — นี่คือสเปก ไม่ใช่ implementation
