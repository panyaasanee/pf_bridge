## หลักฐานวัดจากคอนโซลรอบนี้ (บูต `20260901_094056`, commit `3ce8ab16`)

**เส้นทางล็อกอิน — ไม่ส่งสำมะโน:**
```
163  WORLD_SCENE scene_id=1 model=BG0001 name=Port_Royal population=bg0001_census marker=1
```
หลังบรรทัดนี้ **ไม่มีบรรทัด `WORLD_CENSUS_*` ใด ๆ เลย** จนกว่าจะมีเหตุอื่นมากระตุ้น เจ้าของยืนนิ่ง
ในเมืองแล้วไม่เห็นใครสักคน ทั้งที่ `population=bg0001_census` ประกาศไว้ในเฟรมฉากเอง

**เส้นทางวาร์ป — ส่งเองทันที (โค้ดที่เพิ่ง merge วันนี้):**
```
268  [G>] LANE_GM_CHAT_WARP_CROSS_SCENE_NO_COORDS_TELEPORT_VITAL (73 bytes)
283  WORLD_POP_HANDOFF scene=3 kind=census actors=62 wire=62 slot=after_teleport
     reason=scene_3_repopulated_from_bg0003_roster
284  WORLD_CENSUS_BG0003 assembled=62/72 shippable=62 anchor=(-21215.000,16907.000,-830.000)
     source=bg0003_full_roster
358  [G>] WORLD_CENSUS_LANE_SCENE3_INITIAL_62 (11498 bytes)
1079 [G>] WORLD_CENSUS_LANE_SCENE3_REAPPLY_62
```
⇒ มีทั้ง handoff (`slot=after_teleport`), roster ของฉากปลายทางเอง (`source=bg0003_full_roster`),
anchor ที่ตำแหน่งจริงของผู้เล่น, initial + reapply **เจ้าของเห็น NPC ทันทีโดยไม่ขยับ**

## คำสั่ง

ทำให้เส้นทาง **ล็อกอิน** ส่งสำมะโนเองทันทีแบบเดียวกับที่เส้นทาง **วาร์ป** ทำอยู่แล้ว
🔴 **มีตัวอย่างที่ทำงานจริงอยู่ในโค้ดแล้ว ไม่ต้องออกแบบใหม่** — คัดลอกรูปแบบจากจุดที่ผลิต
`WORLD_POP_HANDOFF ... slot=after_teleport` มาใช้กับ slot ของการเข้าฉากตอนล็อกอิน

เกณฑ์ผ่านที่เจ้าของจะใช้ตัดสิน (ชั้น client-observable): **ล็อกอินเข้า Port Royal แล้วเห็นสิ่งมีชีวิต
บนจอโดยไม่ต้องกดเดินแม้แต่ก้าวเดียว**

## ข้อควรระวังที่รู้อยู่แล้ว ห้ามแก้ด้วยวิธีนี้

🔴 Port Royal มี 108-115 actor และเฟรมสำมะโนขนาด ~20 KB **เคยทำให้ไคลเอนต์หลุดการเชื่อมต่อ
(`ConnectionAbortedError 10053`) แบบเป็นครั้งคราว** (บันทึกไว้ตั้งแต่ 31 ส.ค. รอบ GT-165)
⇒ ถ้าเปิดส่งเองตอนล็อกอินแล้วอาการนั้นกลับมา **ห้ามแก้ด้วยการลดจำนวน actor เงียบ ๆ** ตามที่เจ้าของ
สั่งไว้แล้ว ให้เขียนใบแยกและรายงาน · ฉาก 3 รอบนี้ส่ง 11,498 ไบต์ (62 ตัว) ผ่านฉลุย ปัญหาอยู่ที่
ขนาดเฟรมของ Port Royal โดยเฉพาะ ไม่ใช่ที่กลไก
