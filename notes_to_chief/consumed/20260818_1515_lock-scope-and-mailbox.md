## กติกาใหม่ (สรุป — ฉบับเต็มอยู่ใน prompt แล้ว)

**ก. `LOCK.txt` คุ้มครองเฉพาะทรัพยากรที่ชนกันจริง 4 อย่าง:**
① bridge inbox/job ② พอร์ต server + หน้าต่างเกม ③ canonical DB ④ git commit/gate
→ อ่านไฟล์ · วิเคราะห์ · static RE · spawn ลูกมือ · เขียนไฟล์ลง worktree = **ไม่ต้องถือ LOCK**

**ข. 📬 `pf_bridge\notes_to_chief\` = กล่องจดหมายขาเข้าของ chief**
- เซสชันหลักหย่อนคำตัดสิน/ผลเทส/บทเรียนไว้ที่นี่ **โดยไม่ต้องรอ LOCK** แล้วจบ
- **chief = ผู้เขียน CHIEF_CONTINUATION.md และ GAME_TEST_QUEUE.md แต่เพียงผู้เดียว** →
  อ่านกล่องเป็นขั้นแรกของทุกรอบ (ก่อน inbox) · ย้ายเนื้อหาไปไว้ที่ถูกที่ · ย้ายไฟล์ไป
  `notes_to_chief\consumed\` (ไม่ลบ) · จดใน release note ว่าบริโภคอะไรไป
- ผลพลอยได้: ไฟล์ใหญ่ไม่มีวันถูกเขียนพร้อมกันสองมืออีก

**ค. ระหว่างเซสชันหลักถือ LOCK เทสรอบใหญ่ → chief ห้ามหยุดงาน**
ทำ static RE / ลูกมือ / เขียน worktree ต่อได้เต็มที่ · ห้ามเฉพาะ: วาง job ลง inbox · บูต server ·
แตะ canonical DB · commit/gate → เก็บไว้ commit ตอน LOCK ว่าง (จดไว้ว่ามีอะไรค้างรอ commit)

**ง. 💓 heartbeat + เกณฑ์ stale ใหม่ (กันเหตุแบบรอบ 76 ซ้ำ)**
- chief ต้องแตะ/อัปเดต timestamp ใน `LOCK.txt` อย่างน้อยทุก ~5 นาทีระหว่างงานยาว/รอลูกมือ
- **จะ takeover ได้ต่อเมื่อ: อายุ ≥20 นาที และไม่มีสัญญาณชีพใน ~20 นาที** โดยสัญญาณชีพ =
  ไฟล์ใหม่ใน `outbox\` **หรือ** `git status` worktree ขยับ **หรือ** `LOCK.txt` ถูกแตะ
