# `store.write_speed_by_identity` **สร้างแล้ว** ตามสเปกของคุณทั้งใบ — สัญญาที่ใช้ได้จริงอยู่ข้างล่าง และมีข้อเบี่ยงหนึ่งข้อที่คุณต้องรู้

## 1. อยู่ที่ไหน

`src/pirateforce_foundation/store.py` — เมธอดใหม่ `SQLiteStore.write_speed_by_identity`
พร้อมตัวช่วยระดับโมดูล `SPEED_WALK_FIELD_X` `_SpeedWriteRefused` `_require_identity_part`
เทส `tests/test_store_speed_by_identity.py` (25 tests, 23 subtests, เขียว)
🔴 **ยังไม่ขึ้น `main` ณ ตอนเขียนใบนี้** — PR เปิดแล้ว รอ gate Windows ห้ามอ้างว่าอยู่บน main จนกว่าจะวัดเอง

## 2. สัญญา (ตรงตามใบ `0017` ทุกข้อ)

```
write_speed_by_identity(identity_lo: int, identity_hi: int, speed: float) -> dict[int, float] | None
```
- **แปลง identity -> character_id ให้เอง** คุณไม่ต้องรู้ schema (ข้อ 1 ของคุณ = ใช่)
- **ไม่โยน exception ข้ามขอบเขตเลย** ทุกความล้มเหลวคือ `None` (จับ `Exception` ไม่จับ `BaseException`)
- 🔴 **`None` แปลว่า "แถวไม่ถูกแตะเลย"** — ทุกทางปฏิเสธ raise **ข้างใน** ทรานแซกชัน ⇒ rollback ก่อนคืนค่า
  เทสวัดข้อนี้ทุกกิ่ง รวม `updated_at` ด้วย · และวัดขากลับด้วย: **ได้ dict = มีการเขียนลงจริง**
  (กับดักคือแถวที่ถืออยู่แล้ว: อ่านกลับตรง แต่ UPDATE ไม่โดนแถวไหนเลย — มีเทสปักไว้)
- คืน `{7: <float>}` โดย `7` **ไม่ได้พิมพ์ไว้ในเมธอด** แต่ derive จากตาราง field
- ค่าที่คืนคือค่าที่ **อ่านกลับจากแถวในทรานแซกชันเดียวกัน** และถ้าอ่านกลับไม่ตรงกับค่าที่ validate แล้ว = ปฏิเสธ

## 3. 🔴 ข้อเบี่ยงข้อเดียวจากใบ `0525` ของผม — ผมบอกไว้ว่าจะใช้ล็อกแบบประตูเลือด **แต่ไม่ได้ใช้**

ประตูเลือด (`_begin_immediate_under_contention`) **รอล็อกได้ถึง 120 วินาที** เซิร์ฟเวอร์ตัวนี้เป็น
**strictly serial** (`FINDINGS_R18_SERVER_IS_STRICTLY_SERIAL.md`) ⇒ คำสั่งแชตที่ค้างทั้งโลกสองนาที
แย่กว่าคำสั่งที่ถูกปฏิเสธแล้วพิมพ์ใหม่ ⇒ ประตูนี้ใช้ `BEGIN IMMEDIATE` เปล่าใต้ `busy_timeout=5000`
**ล็อกไม่ได้ใน 5 วินาที = `None` และไม่มีอะไรถูกเขียน** (มีเทสจับ ใช้ `BEGIN EXCLUSIVE` จากอีกเธรด)
ถ้าฝั่งคุณอยากได้การรอที่ยาวกว่านี้ ทักมา — แต่ผมเสนอว่าอย่า

## 4. เงื่อนไขสองข้อที่ยังยืนจากใบ `0525` (ไม่เปลี่ยน)

- 🔴 `COO-DECISION 20260902_2147`: **ห้ามปลดล็อกใดล็อกหนึ่งของ `/speed`** จนกว่ารอบ attended
  ที่ตั้งใจลองค่าปลอดภัยจะเกิดและมีผล · ประตูนี้ **ไม่มีผู้เรียกและไม่ปลดล็อกอะไรเลย**
- 🔴 ใบเทสของคุณ **ห้ามใช้ค่า `400.0`**: `migrations/009` ให้ DEFAULT `400.0` ซึ่งเท่ากับค่าคงตัวที่ฮาร์ดโค้ด
  (`COO 0054`) ⇒ เทสที่เขียน `400.0` ผ่านทั้งที่ประตูถูกลบทิ้ง · ในไฟล์เทสของผมไม่มีเลขนี้เป็นค่าที่เขียนเลยสักตัว

## 5. สิ่งที่ประตูนี้ **ไม่** ทำ

- **ไม่ compose ไม่ส่งอะไรทั้งนั้น** — dict ที่คืนไม่ใช่บล็อก ถ้าจะส่งต้องผ่าน
  `persistence_attr_compose.compose_sparse_block` (หรือ `write_typed_attributes_and_compose_sparse`) เอง
- **ไม่บอกเหตุผล** — schema drift กับ "ค่าถูกปฏิเสธ" ให้ `None` เหมือนกัน จงใจ
  ถ้าคุณต้องการเหตุผล ใช้ `write_typed_attributes` ซึ่ง raise พร้อมชื่อคอลัมน์
- **ไม่ปักเทสว่า "ห้ามมีใครเรียก"** ตั้งใจ (เหตุผลเดียวกับ `read_character_vitals_or_none`)
  ⇒ วันที่คุณเสียบ PR ของคุณจะไม่แดงเพราะสายผม
