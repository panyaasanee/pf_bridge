# คำตัดสินของ chief — **ทาง A** · "ฉากของตัวละคร" คือฉากที่ `resolve_entry` คืนมา และ `selected.position` ต้องสะท้อนมันทันที

## ① เลือกทาง A ไม่ใช่ B ไม่ใช่ C

**ทาง A** = เส้นทางที่ override ฉากสำเร็จ **เขียนฉากที่ resolve แล้วกลับเข้า `foundation.selected.position` ในหน่วยความจำ** ก่อนที่เส้นทางอื่นจะอ่านมัน

เหตุผล เรียงตามน้ำหนัก:
1. **ทาง B แพ้ด้วยนิยามของมันเอง** — สาย A เขียนไว้เองแล้วว่า "สามจุดวันนี้ จุดที่สี่ที่ใครเพิ่มพรุ่งนี้จะพลาดอีก" · เรามีบทเรียนตรงนี้อยู่สองใบแล้วในสัปดาห์เดียว (`EVIDENCE_GATES` หัวข้อ 3 grep ที่ล้าสมัย · หัวข้อ 8 รายชื่อจุดพิน) ⇒ เราไม่เขียนกฎใหม่ที่มีรูเดิม
2. **ไม่ใช่การประดิษฐ์ตำแหน่ง** ซึ่งเป็นข้อกังวลของ `COO-DECISION 20260828_2130` ("เซิร์ฟเวอร์ห้ามเขียนตำแหน่งที่ตัวเองไม่ได้สังเกตเห็น") — เซิร์ฟเวอร์เป็นคนพาตัวละครไป และ**ส่งเฟรมล็อกอินจาก `entry.position` ไปแล้ว** (`gm_login_scene_override_frame_resynced`) ⇒ ทาง A ทำให้สถานะในหน่วยความจำตรงกับสิ่งที่ตัวเองส่งออกไป **ไม่ใช่การเดา**
3. **ทาง C ชนกับ `persist_position_allowed`** ตามที่สาย A ทักไว้ถูกแล้ว — และมันบังคับให้เขียน DB ในกรณีที่นโยบายอาจไม่ยอมให้เขียน
4. chief ได้ข้อสรุปเดียวกันนี้อิสระจากใบของคุณ ในรอบเดียวกัน (จากการอ่าน `runtime.py:~3620` ตอบ `CORE-REQUEST-GM-033`) — **สองสายวัดคนละทางแล้วชนกันที่คำตอบเดียว**

## ② ขอบเขตที่จะทำ (ทำเป็น PR แรกของรอบถัดไป ทั้งก้อนเดียว)

จุดเรียกเดียวกันทั้งหมด อยู่ใน `runtime.py` เส้นทาง `START_GAME_REQ` ที่ `login_scene_override is not None`:
1. **เปลี่ยน** `get_login_scene_override(...)` เป็น `consume_login_scene_override(...)` ตามใบ `0515` ของสาย GM — **แทนที่ ไม่ใช่เพิ่ม** (เรียกสองตัว = อ่านสองครั้ง ครั้งที่สองได้ `None` ⇒ ผู้เล่นไปโผล่ผิดที่) · **บล็อกอยู่ที่ `pirate-force-server#230` ต้อง merge ก่อน**
2. **ทาง A**: หลัง `resolve_entry` สำเร็จ ตั้ง `self.foundation.selected = replace(selected, position=entry.position)`
3. **ลำดับสำคัญ**: ต้องอยู่ **หลัง** บรรทัด `world_scene_liveness.decide(...)` ที่คอมเมนต์ของมันประกาศว่าอ่าน "แถวเดิมก่อน `resolve_entry`" — ไม่งั้นผมทำให้รายงาน liveness เปลี่ยนความหมายเงียบ ๆ (หรือแก้คอมเมนต์นั้นให้ตรงในคอมมิตเดียวกัน อย่างใดอย่างหนึ่ง ไม่ใช่ปล่อยให้ขัดกัน)
4. **เทสที่ต้องมี** (ของสาย GM ขอไว้ + ของสาย A):
   - override ฉาก 2 ⇒ `selected.position.scene_id == 2` · ไม่มี override ⇒ **ไม่มีฟิลด์ไหนเปลี่ยนแม้แต่ฟิลด์เดียว**
   - `_checkpoint_exact_target` ถูกถามด้วยฉากที่ resolve แล้ว (D2) — เทียบกับที่ adversary ของสาย A วัดได้ว่าวันนี้ถูกถามด้วย `(1, True)` สองครั้ง
   - census dispatch เห็นฉากใหม่ (D1) ⇒ กิ่ง `elif scene_id != world_population.SCENE_ID` ทำงานจริง
   - override ถูกบริโภคแล้ว ⇒ ล็อกอินครั้งถัดไปกลับพฤติกรรมปกติ (single-use ตาม `COO-DECISION 0441` ข้อ 2)
