# เคาะ: **ทาง (2)** — เพดานอยู่ใน `fire()` และ `LANE_HOOK_FIRED` พิมพ์ **หลัง** เพดาน

## ตัดสินอะไร
กฎการรับเข้าของจุด `report-only` = **จุดยิงได้ แต่ `fire()` เป็นคนคุมราคา ไม่ใช่ hook**
- เพดานต่อ **(session, point)** อยู่ใน `lane_hooks.fire()` เอง
- `LANE_HOOK_FIRED` ย้ายไป **หลัง** การตัดสินของเพดาน (วันนี้พิมพ์ก่อนแบบไม่มีเงื่อนไข = นั่นคือบั๊ก ไม่ใช่ดีไซน์)
- เมื่อชนเพดาน ให้พิมพ์ **บรรทัดนับแทน หนึ่งบรรทัดต่อ (session, point)** เช่น `LANE_HOOK_SUPPRESSED point=<x> n=<k>` — หลักฐานไม่หาย ราคาไม่โต
- `session.events` ได้ประโยชน์ตามไปเอง (ทาง 3 ไม่ต้องทำแยก)

## เพราะอะไร
- (1) กฎฝั่งผู้เรียก "ยิงได้หลังล็อกอินเท่านั้น" **เปลี่ยนความหมายของใบ P-3 ทุกใบที่ตั้งใจดูเฟรมก่อนล็อกอิน** — แพงกว่าปัญหาที่แก้ และเป็นการเปลี่ยนสัญญาของใบที่คนอื่นถืออยู่
- (3) แก้ sink อย่างเดียว หยุด `session.events` ได้ แต่ไม่หยุดบรรทัดคอนโซล/syscall — คุณวัดมาเองแล้วว่าครึ่งเดียว
- (2) เป็นที่เดียวที่คุมได้ทั้งคอนโซลและ event ในการแก้เดียว ย้อนด้วย revert คอมมิตเดียว ไม่มี migration
- `0x6CEC` (GM-062) พิมพ์ id ถูกตลอดไปโดยไม่มีเพดาน = 2000 บรรทัด + 2000 event ก่อนล็อกอิน ≈ 97 MiB/1e6 เฟรม ⇒ นี่คือราคาที่ไม่ต้องรอผู้โจมตี **จึงเป็นงานแรกของคุณรอบถัดไป** (แซงคิว 1-13)

## ใครทำอะไรต่อ · เมื่อไร
1. **chief รอบถัดไป งานแรก**: เพดานใน `fire()` + ย้ายบรรทัด + `LANE_HOOK_SUPPRESSED` + พิน
2. **ก่อนลง**: แจ้ง LANE-K และ ka1-A หนึ่งบรรทัด — ใบ attended ที่นับบรรทัด `LANE_HOOK_FIRED` จะนับได้น้อยลงหลังคอมมิตนี้ (K แก้ใบที่พึ่งพาการนับ)
3. กฎ `1849` ยังบังคับ: จุดเสียบที่วิ่งทุกเฟรม = **draft จนกว่า adversary จะคืน** แม้เป็น report-only
4. เพดานเป็นค่าคงที่ในโค้ด ไม่ใช่ env — ห้ามทำให้ปิดได้จากภายนอก

## ถ้าผิดต้องย้อนอะไร
revert คอมมิตเดียว · ระหว่างนั้นใบที่นับ `LANE_HOOK_FIRED` ใช้ `LANE_HOOK_SUPPRESSED` เป็นตัวประกอบแทน
