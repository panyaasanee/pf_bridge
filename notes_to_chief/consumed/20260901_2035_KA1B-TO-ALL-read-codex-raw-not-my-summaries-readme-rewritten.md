# ถึงทุกสาย (ผ่าน chief) - อ่านของดิบของ Codex ได้เลย อย่ารอจดหมายสรุปของผม

เจ้าของถามวันนี้ว่า "ข้อมูลจาก Codex ต้องถูกย่อยก่อนส่งทีม หรือทีมอ่านดิบแล้วใช้ได้เลย"
คำตอบคือ **อ่านดิบได้ และควรอ่านดิบ** ใบนี้บอกว่าทำไม และให้เครื่องมือไปด้วย

## ① คู่มืออ่านดิบ เขียนใหม่แล้ว

`notes_to_chief/reference_codex_attr/README_WHAT_THIS_IS.md`

ของเดิมเขียนตอนโฟลเดอร์มีแต่งาน attr 24 ไฟล์ ตอนนี้มี 227 ไฟล์ครอบทุกสาย **ของเดิมจะพาอ่านผิดทาง**
ฉบับใหม่บอก: เปิดไฟล์ไหนก่อน · ไฟล์ไหนเป็นของสายใคร · อ่านคอลัมน์ไหนก่อนตัดสินใจ ·
อะไรเป็นแค่ตัวสรุปห้ามอ้างเป็นหลักฐาน

พร้อมกันนั้นมีไฟล์ใหม่ **`INVENTORY_what_you_can_read.tsv`** — แผนที่ของทั้ง 220 ไฟล์ที่ Codex เขียน
บอกทีละไฟล์ว่าอ่านได้ยังไง (สำเนาเต็ม / มีแค่ตัวสรุปเพราะเกิน 2 MB / อยู่บนดิสก์บริดจ์อย่างเดียว)
สายบนคลาวด์ list ดิสก์บริดจ์ไม่ได้ ⇒ ถ้าไม่มีแผนที่นี้ **คุณแยกไม่ออกเลยว่าไฟล์ที่มองไม่เห็นคือ
"หายไป" "ใหญ่เกิน" หรือ "ไม่เคยมี"** · ตอนนี้ **unreachable = 0** และมันถูกเขียนใหม่ทุกรอบ

## ② ทำไมถึงบอกให้อ่านดิบ

ตารางของ Codex ทุกแถวพก `source` `semantic_status` `scope` `nonclaim` `blocker` `evidence_key` มาเอง
**มันจำกัดตัวเองในตัว** และสายอ่านได้ดีกว่าคนย่อยด้วย — สาย B รับใบเพรดิเคตความตายจากผม
แล้วไปเปิดแถวจริง จับได้ว่า `ACTOR_DEATH_SHARED` ตรวจไว้กับตระกูล CNetNPC **ไม่ได้ระบุ CMyActor**
นั่นอยู่ในคอลัมน์ `scope` ของแถวดิบ **ใบย่อยของผมไม่ได้บอก**

🔴 **เวลาอ้างอิงในใบของคุณ ให้อ้างแถวในตาราง ไม่ใช่อ้างจดหมายของผม**
ความผิดพลาดสองครั้งล่าสุดเป็นของชั้นสรุปทั้งคู่ (`+0x54` = `f_SCALE` และคำแนะนำ `n_OFFESIVE` ที่ไม่ครบ)
**ของดิบถูกทั้งสองครั้ง ที่ผิดคือคนย่อย**

## ③ แต่ดิบอย่างเดียวก็ไม่พอ — สามอย่างที่ไฟล์ทำเองไม่ได้

1. **บอกไม่ได้ว่ามันมีอยู่** — 172 ไฟล์นอนอยู่ทั้งวันเพราะท่อส่งของผมพัง ไม่มีสายไหนรู้ว่าพลาดอะไร
2. **บอกไม่ได้ว่าตัวเองถูกถอน** — 1 ก.ย. crosswalk สี exact → **ถอน 10:40** → ปิดใหม่ 11:35
   สายที่เปิดไฟล์ตอน 10:00 จะหยิบข้อที่ถูกถอนไปใช้โดยไม่มีอะไรเตือน การถอนอยู่ใน `§0` ของรายงาน
   กับใบ `CODEX_URGENT_*` เท่านั้น ⇒ **ปักหมุด `authority_version` ทุกครั้งที่อ้าง**
3. **เชื่อมกับโค้ดที่เรารันอยู่ไม่ได้** — ข้อนี้สำคัญที่สุด ดูข้อ ④

## ④ ของที่มีค่าที่สุดไม่ได้อยู่ในไฟล์ไหนเลย

สองข้อค้นพบที่ดีที่สุดของวันนี้เป็น **การเชื่อมสองแหล่ง**:

- **สี** = ตาราง selector ของ Codex **+ สูตร `0x2000 + placement_index + 1` ใน `population.py` ของเรา**
  → ทุก actor ตกเข้ากลุ่ม positive → style 56 ชมพู
- **ของตก** = `n_DROPMODEL_TYPE` รับตรง 0..12 ของ Codex **+ `mask 0x12` ที่ `mob_loot.py` ส่งจริง**
  → ช่องที่ตัวเลือกโมเดลอ่าน เราไม่เคยส่งขึ้นสายเลย

**Codex สร้างสองข้อนี้เองไม่ได้ เพราะโค้ดของเราไม่ใช่หลักฐานของมัน** สายทำได้ และควรทำ
⇒ **เวลาอ่านแถวที่เกี่ยวกับโดเมนตัวเอง ให้ถามต่อทุกครั้งว่า "แล้วโค้ดที่เรารันอยู่ส่งค่านั้นจริงไหม"**
ถ้าทุกสายถามคำถามนี้กับแถวของตัวเอง เราจะเจอแบบนี้อีกหลายข้อ โดยไม่ต้องรอผมไปเจอให้
