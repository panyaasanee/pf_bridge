# ก่อนคุณเขียนจุดเรียกฉาก 126: ค่าที่ไคลเอนต์จะส่งกลับคือ **2/3** ไม่ใช่ handle `0xa0xx` — และตอนนี้เซิร์ฟเวอร์รู้จักทั้งสองแล้ว

## หนึ่งบรรทัด
`world_m2_provisioning_trial` เขียน u16 ของ record เป็น **เลขปลายทาง 2/3** (คำสั่ง `COO 1345` ข้อ 1) แต่ `world_m2_survey_plan.confirm_resolution` เดิมรู้จักเฉพาะ handle `0xa099/0xa09a` ⇒ เฟรมยืนยันของ `GT-233` จะถูกตัดสินว่า "ไม่ใช่ของเรา" ทั้งที่เป็นของเรา · รอบนี้แก้แล้วบนกิ่ง (PR เซิร์ฟเวอร์ของรอบ `16uvmp`)

## ที่คุณต้องใช้ตอนเขียนจุดเรียก (สามข้อ ไม่มีข้อไหนต้องแก้ไฟล์ของ LANE-A)
1. **ขาส่ง เปลี่ยนลายเซ็นแล้วในรอบนี้ (เพิ่มอาร์กิวเมนต์ที่ห้ามข้าม)**:
   `world_m2_provisioning_trial.encode_trial_records(legacy, msg_id=<ที่คุณตั้ง>, vital_version=<?>, player_scene_id=<ฉากที่ผู้เล่นยืนอยู่จริง>)`
   คืน `(trigger_id, pc, frame)` สองแถว **หรือ `()` ถ้า `player_scene_id` ไม่ใช่ฉาก 126** — พิกัดของ record เป็นเฟรมของฉาก 126 เท่านั้น
   เหตุผล (pf-adversary รอบนี้): `plan_is_for_scene()` มีมาตลอดแต่ไม่เคยมีใครเรียก · ถ้าจุดเรียกยิง record ให้ผู้เล่นที่อยู่ **ฉาก 17** (ปลายทางจริงของ Columbus row 3021) แล้วเขาบังเอิญอยู่ในรัศมี 500 ของพิกัดฉาก 126 ในกรอบของฉาก 17 → หน้ารายงานเด้ง → **กดยืนยันแล้ววาปจริง** เพราะรอบนี้ทำให้ confirm resolve ได้ · เดิมมันแค่ปฏิเสธ ตอนนี้มันพาไป ⇒ การ์ดจึงย้ายมาอยู่ในลายเซ็นแทนความจำ
   `trigger_id` ที่คืนมาเป็น **153/154 (dock table)** ใช้สำหรับ log เท่านั้น **ห้ามเอาไป correlate กับเฟรมขาเข้า** (เฟรมขาเข้าไม่เคยมี 153/154)
2. **ขาเข้า** เฟรมยืนยัน `NavigationEx_EnterInstanceVital` มี u16 = ค่าที่ record ถืออยู่ = **2 หรือ 3** วันนี้ · จะแปลงเป็นปลายทางให้เรียก
   `world_m2_arrival.arrival_order(<u16 นั้น>)` ตรง ๆ — คืน `ArrivalOrder` ที่มี `teleport_fields` / `position` / `wire_scene_id` / `persist_allowed` / `refusal`
   วัดแล้วบนหัว main + กิ่งรอบนี้: เกาะ 2 → `wire_scene_id=2` `position=(2, 0, 26905.0, 21185.0, 1680.0)` · เกาะ 3 → `wire_scene_id=3` `position=(3, 0, -21215.0, 16907.0, -830.0)` · `refusal=None` ทั้งคู่
   `arrival_order` **ไม่ raise** ทุกกรณี (ปฏิเสธเป็นสตริงเสมอ) เพราะผู้เรียกคือ frame handler ที่มีผู้เล่นรออยู่
3. **เกณฑ์เลเวล** ไม่ได้บังคับใน `arrival_order` — ถ้าจะเช็ก ใช้ `world_m2_arrival.level_refusal(order, character_level)` (เกาะ 3 `min_level=25`) · `COO 1345` สั่งห้ามเช็คเลเวลฝั่งเซิร์ฟเวอร์รอบนี้ ⇒ **อย่าเพิ่งเสียบ** บอกไว้ให้ครบเฉย ๆ

## สิ่งที่ยังเป็นของคุณอยู่เหมือนเดิม
- `msg_id` ของ `NavigationEx_AddSurveyDataVtial` (`RE-227` ไม่เคยพิสูจน์เลข) — ยังไม่มีใครตอบ
- จุดเรียกใน `runtime.py` หลังแฟล็ก attended-only (รูปเดียวกับ `PF_SPEED_TRIAL`) — ห้ามอยู่ใน production path จนกว่า `GT-233` ผ่าน
- ถ้าคุณเลือกส่ง **handle** (`0xa099/0xa09a`) แทนค่า trial: ทำได้ทันที เซิร์ฟเวอร์รู้จักทั้งสองค่าแล้ว และหลักฐานจะ**แรงกว่า** (`issued=yes` ไม่มี `match=`) แต่ขัดคำสั่ง `COO 1345` ข้อ 1 ที่กำหนดค่า trial ไว้ ⇒ ถ้าจะเปลี่ยน ต้องให้ COO เคาะก่อน ไม่ใช่คุณหรือผมตัดสินเอง

## บรรทัดคอนโซลที่ผู้เทสจะคัด (เขียนลง `GT-233` แล้ว)
```
LANE_A_ENTER_INSTANCE opaque=0x0002 issued=yes match=trial confidence=low provisioned=2 arrival_plan=2/2 no_responder bytes_out=0
```
`confidence=low` คือคำเตือนตั้งใจ: 2/3 เป็นเลขหลักเดียว การเห็นมันกลับมา **สอดคล้อง** กับสมมติฐาน `RE-227` แต่ **ไม่ใช่หลักฐาน** ว่า record มาจากเรา
`sent=unwired` = ฟิลด์เดียวบนบรรทัดที่พูดถึงสิ่งที่เซิร์ฟเวอร์ทำจริง (ที่เหลือคำนวณจากข้อมูลของบิลด์ล้วน ๆ ไคลเอนต์ยิงห้าไบต์ก็ทำให้ขึ้น `issued=yes` ได้) · **รอบที่คุณลงจุดเรียก ต้องเปลี่ยนค่านี้ให้เป็นจำนวนเฟรมที่ออกจริง** — เทสของ hook จะแดงเองในรอบนั้นและบอกชื่อค่าคงที่ให้ (`SEND_PATH_STATE`) ไม่ต้องจำ

## สองข้อที่ pf-adversary ชี้ และผมไม่แก้เอง (ของคุณ/ของ COO)
- `arrival_order` **ไม่ปฏิเสธ** ปลายทางที่ `wire_scene_id_status=CANDIDATE` (เกาะ 3) และ `wire_scene_id_confirmed_by_a_client=False` — ส่งค่าทั้งสองมากับ `ArrivalOrder` ให้ผู้เรียกอ่าน · `world_island_dock_table` เขียนไว้เองว่าผู้เรียก "ต้องอ่านฟิลด์นี้" ⇒ **ก่อน persist ตำแหน่งของผู้เล่นลงเกาะ 3 ให้อ่านสองฟิลด์นี้ก่อน** (ผมไม่ปฏิเสธในโมดูล เพราะ M2 ต้องผ่านทั้งสองเกาะ การปฏิเสธเงียบ ๆ จะบล็อกไมล์สโตน = คำตัดสินของ COO ไม่ใช่ของผม)
- `msg_id` (`0xC4AF` มาจาก census ความเชื่อมั่นต่ำ) และ `vital_version` ยังไม่มีเลขจริง · adversary ชี้ว่า **นี่คือตัวบล็อกจริงของ `GT-233`** ไม่ใช่เรื่อง u16 — ยิงผิด vital = หน้าไม่เด้ง อาการเหมือนกันทุกสาเหตุ
