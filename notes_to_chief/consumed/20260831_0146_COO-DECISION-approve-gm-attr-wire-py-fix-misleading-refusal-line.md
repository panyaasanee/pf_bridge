# COO-DECISION — อนุมัติ `gm/attr_wire.py`, มอบสาย GM, แก้ประโยคปฏิเสธที่ทำให้เข้าใจผิด

## ตัดสินว่าอะไร

1. อนุมัติ: ยก mechanism ของ `PF_ADHOC_ATTR_PROBE` เข้ามาเป็น `gm/attr_wire.py` แล้วต่อ `/lv` ก่อน
   (`/item` `/npc` `/spawn` ตามหลัง) แทนเปิด CORE-REQUEST ทีละคำสั่ง — มอบ **สาย GM** เป็นเจ้าของ
   (อยู่ในเขต `gm/` ของสายอยู่แล้ว ไม่ต้องเปิดเขตใหม่)
2. เงื่อนไขบังคับ ห้ามข้าม: (a) ส่งทั้งบล็อก ActorAttr เสมอ ห้ามส่ง delta บางส่วน (ไคลเอนต์ copy ทั้งก้อน
   ตาม v141 note 0x464F30 — ส่งไม่ครบ = ฟิลด์ที่ไม่ส่งกลายเป็นศูนย์) (b) ต้องเขียนผ่าน DB จริง ให้ค่าที่
   ตั้งด้วย `/lv` คงอยู่ข้าม relog เหมือนคำสั่ง GM อื่น ไม่ใช่ debug ชั่วคราวบน session object อย่าง probe
   (c) ผ่าน audit/gate/เทสตามปกติของเลน — probe ข้ามได้เพราะเป็นของทิ้ง ของจริงข้ามไม่ได้
3. แก้ประโยคที่ `gm/chat_command_action.py:724` ให้ตรงความจริง: จาก "ยังไม่มีสายส่งที่พิสูจน์แล้ว" เป็น
   "โฟลเดอร์ `gm/` ยังไม่มีจุดต่อกับสายส่งที่พิสูจน์แล้วบน main" พร้อมชี้ `UpdateAttrVital 0x309A` (5
   โมดูลบน main + probe) — ประโยคเดิมทำให้เข้าใจผิดมาหลายรอบว่าโปรเจกต์ยังไม่รู้วิธี ทั้งที่รู้แล้ว
4. ยืนยัน: การอ่านเรื่อง `/warp` ของกะ1-A ถูกต้อง — ข้ามฉากยังรอ `GT-106-R2` ตาม
   `COO-DECISION 20260830_2048` เดิม ไม่เกี่ยวกับงาน attr_wire.py นี้ คนละกลไก คนละเงื่อนไขปลดล็อก

## เพราะอะไร

สายส่ง `UpdateAttrVital 0x309A` พิสูจน์แล้วจริงบน main (5 โมดูล) และพิสูจน์กับไคลเอนต์จริงแล้ว 266
คำสั่งต่อเนื่อง 2 ชม. 20 นาที ไม่เด้งไม่ค้าง ปัญหาไม่ใช่ "ยังไม่รู้วิธี" แต่คือ `gm/` ยังไม่มีจุดต่อ — รวมเข้า
ไฟล์เดียวปลดได้หลายคำสั่งพร้อมกัน คุ้มกว่าเปิด CORE-REQUEST ทีละคำสั่ง และแก้ปัญหาที่เจ้าของสังเกตเอง
ตอนเทส probe ว่า `/lv` ควรทำงานได้เหมือนกับที่ probe ทำได้อยู่แล้ว
