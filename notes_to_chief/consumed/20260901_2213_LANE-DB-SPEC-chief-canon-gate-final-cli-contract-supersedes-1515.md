## 1. โมดูลลง `main` แล้วหรือยัง — ยัง PR รอบนี้เอง

🔴 ใบ `1515` เขียนว่า "อย่าเพิ่งต่อสายก่อนโมดูลลง main" — **ข้อนั้นยังใช้อยู่**
รอบนี้เพิ่งเปิด PR ยังไม่ merge ถ้า PR ตาย ต่อสายไปก็เรียกอะไรไม่ได้ กรุณารอเห็นไฟล์บน `main` ก่อน

## 2. สามจุดที่เปลี่ยนจากใบ 1515 — ทั้งสามมาจากของที่วัด ไม่ใช่ความชอบ

### 2.1 exit code ของ `EXPLAINED_BY_MIGRATION`: `20` → **`75`**

ผมเสนอ 20 ไว้เอง และผมเองเป็นคนขอถอน pf-adversary จับได้ว่า **20 มีความหมายตรงข้ามอยู่แล้ว**
วัดซ้ำด้วยตัวเองรอบนี้:
- `staged/TEMPLATE_teardown_generic.ps1:520-521` → `'=== SALVAGE DONE - THIS ROUND IS DEGRADED, NOT GREEN (exit 20) ==='; exit 20`
- `staged/072_gt001_boot.ps1:72` → `'ABORT: no server PID'; exit 20`
- `grep -ho "exit [0-9]\+" staged/*.ps1 | sort | uniq -c` → ไม่มี `exit 75` เลยแม้ครั้งเดียว

`13` **คงเดิม** โดยตั้งใจ (สคริปต์ที่ยังไม่ถูกต่อสายจะยัง ABORT ถูก)

### 2.2 บรรทัดที่ต้องพาร์ซ: `NEW_SHA=<64 hex ตัวใหญ่>` (ตามใบ 1515) และมีได้ครั้งเดียว

โมดูล **ตรวจเองก่อนพิมพ์** ว่าบรรทัดขึ้นต้น `NEW_SHA=` ปรากฏพอดีหนึ่งครั้ง ไม่งั้นไม่พิมพ์เลย
เหตุ: ผู้ตรวจวัดแล้วว่าชื่อโฟลเดอร์สำเนาที่มีขึ้นบรรทัดใหม่ฝังอยู่ สามารถแทรกบรรทัด `NEW_SHA=`
ปลอมนำหน้าของจริงได้ ⇒ ps1 ที่เอา match แรกจะหมุนค่าของผู้โจมตี
ตอนนี้ข้อความทุกชิ้นที่มาจากดิสก์ถูกบีบเป็นบรรทัดเดียว ASCII และตัดความยาวก่อนพิมพ์
🔴 ฝั่งคุณขอให้ยึด **`Select-String '^NEW_SHA='`** (ยึดต้นบรรทัด) อย่าใช้ match กลางบรรทัด

### 2.3 ธงบรรทัดคำสั่ง: รับทั้งสองสะกด

```
py -3 -m pirateforce_foundation.persistence_canon_gate `
    --db <canonical .db> --migrations <repo migrations/> `
    --expect-sha-file <path ของ CANON_SHA.txt>      # หรือ --expect-sha <64 hex>
    [--backups-root <dir>] [--json]
```
`--expected-sha` / `--expected-sha-file` เป็นชื่อพ้องของธงเดียวกัน เขียนแบบไหนก็ได้

## 3. ตารางที่ ps1 ต้องยึด (แทนตารางในใบ 1515)

| exit | ผล | ps1 ทำอะไร |
| --- | --- | --- |
| `0` | `UNCHANGED` | เดินต่อ |
| `75` | `EXPLAINED_BY_MIGRATION` | หมุน `CANON_SHA.txt` เป็นค่าใน `NEW_SHA=` แล้วเดินต่อ + log ก่อน/หลัง |
| | | 🔴 โหมด `--json` **ไม่มีบรรทัด `NEW_SHA=`** (สตรีมต้องพาร์ซเป็น JSON ได้) ค่าอยู่ที่ฟิลด์ `new_canon_sha` |
| `13` | `UNEXPLAINED` | ABORT ห้ามหมุน |
| `2` | ด่านไม่ได้ทำงาน (อาร์กิวเมนต์ผิด · อ่านไฟล์ sha ไม่ได้ · `--help` · ข้อยกเว้นที่ไม่คาด) | ABORT |
| อื่น | ไม่ควรเกิด | ABORT |

🔴 สองข้อที่ขอให้ยึดให้แน่นเหมือนเดิม:
1. **`75` เป็นทางเดียวที่ `CANON_SHA.txt` ถูกเขียนใหม่** ถ้าหมุนในกรณีอื่นด้วย ด่านจะปลดตัวเองได้ทุกกรณี
2. **ห้ามอ่าน "ด่านพัง" เป็น "ด่านผ่าน"** — `--help` คืน `2` ไม่ใช่ `0` โดยตั้งใจ (การเรียกที่ไม่ได้
   ตรวจอะไรเลย ต้องไม่มีรหัสเดียวกับการตรวจแล้วผ่าน) และโมดูลจะไม่ตายด้วย traceback + exit 1
   ถ้าเลี่ยงได้ เพราะ `exit 1` ถูก ps1 ที่แตกที่ `13` อ่านว่า "ไม่ใช่ 13"

## 4. 🔴 ตอนหมุน `CANON_SHA.txt` ให้เขียนเป็น ASCII

วัดแล้ว: PowerShell 5.1 `>` และ `Out-File` เขียน **UTF-16LE** เป็นค่าเริ่มต้น
โมดูลอ่าน UTF-16/BOM ได้แล้ว (กันไว้) แต่ไฟล์ที่ทั้งบริดจ์ใช้ร่วมกันควรอยู่ในรูปเดิม
⇒ ขอให้ใช้ **`Set-Content -Encoding ascii`** ไม่ใช่ `>` และไม่ใช่ `Out-File`

## 6. จ็อบยกระดับ canonical (ข.2 ของใบ 1515) — ลำดับเดิม เพิ่มสองข้อที่สำคัญมาก

ขั้น 1-6 เหมือนเดิมทุกประการ **เพิ่มสองข้อ ทั้งคู่มาจากของที่ pf-adversary วัดได้ ไม่ใช่ความระวังลอย ๆ**

### 6.1 บูตเขียน `POSTSTATE.<sha>.json` ให้เอง — ห้ามล้าง `db_backups/` ก่อนหมุนค่าเสร็จ

หลัง migrate เสร็จ บูตจะเขียนไฟล์ `POSTSTATE.<sha 64 ตัว>.json` ไว้ในโฟลเดอร์สำเนา
(บันทึก sha ที่ migration **ผลิตออกมา**) และ **ด่านต้องการไฟล์นั้น**
⇒ ถ้าจ็อบของคุณ **คัดลอก/ย้าย/ล้าง `db_backups/` ระหว่างขั้น 2 กับขั้น 5 ด่านจะตอบ `13`**

### 6.2 🔴 ด่านจะ **ปฏิเสธตอบ** ถ้าฐานข้อมูลมี `-wal` ค้างอยู่ — และนี่คือการเปลี่ยนพฤติกรรม

นี่คือข้อที่ผมอยากให้คุณอ่านสองรอบ เพราะมัน **ต่างจากด่าน sha วันนี้**:
ธุรกรรมที่ commit แล้วของ SQLite อยู่ใน `-wal` ได้ทั้งก้อนโดยที่ **ไฟล์หลักไม่ขยับแม้ไบต์เดียว**
⇒ การ hash ไฟล์หลักตอนนั้น **ไม่ได้พูดถึงฐานข้อมูล** เลย ผู้ตรวจวัดได้สองทางเลย:
- ลบบัญชี**ทั้งตาราง** commit แล้วปิดโปรแกรมทิ้ง → ไฟล์หลักยัง hash เท่าเดิม → ด่านรุ่นก่อนตอบ
  `EXPLAINED_BY_MIGRATION` + สั่งหมุนค่า ทั้งที่โลกว่างเปล่า
- migrate จริงขณะมีอีก connection เปิดอยู่ → migration ไม่ลงไฟล์หลัก → ด่านรุ่นก่อนตอบ
  `UNCHANGED` exit 0 ทั้งที่เพิ่ง migrate ไป

ตอนนี้ถ้ามี `-wal` ไม่ว่าง ด่านตอบ **`13` พร้อมข้อความบอกให้หยุดตัวที่เขียนอยู่แล้วรันใหม่**
🔴 ผลกับคุณ: **ถ้าเอาด่านนี้ไปวางในจุดที่รันตอนเซิร์ฟเวอร์ยังขึ้นอยู่ มันจะแดง** ซึ่งด่าน sha
วันนี้ไม่แดง (มันเทียบ sha เฉย ๆ ซึ่งเป็นการเทียบที่ไม่มีความหมายในสภาพนั้น)
⇒ ขั้น 1 ของจ็อบ (ยืนยันไม่มี server/GameClient รันอยู่) **ไม่ใช่ขั้นที่ข้ามได้**
และตอนเลือกจุดต่อสายใน 19 ไฟล์ กรุณาเลือกจุดที่เซิร์ฟเวอร์หยุดแล้ว ถ้าจุดไหนต้องรันตอนเซิร์ฟเวอร์ขึ้น
**บอกผมมา** ผมจะออกแบบทางที่ตอบได้ในสภาพนั้นให้ (เช่นให้ checkpoint ก่อนใต้ล็อก) ไม่ใช่ให้คุณไปปิดด่าน
