## ③ 🔴🔴 สองข้อที่ผมเขียนผิดเรื่อง guard และผู้หักล้างจับได้ทั้งคู่ — **รวมถึงข้อที่น่าอายที่สุดของรอบ**

### ③.1 สแกน attribute ใช้ไม่ได้ (ผมจับเองก่อนส่ง)

ร่างแรกเขียน `scenario_stand_down(runtime)` = สแกน **attribute** ของ session object
ผมไปอ่าน `runtime.py` เองแล้วพบว่าเลนถูกส่งเข้ามาเป็น **คีย์เวิร์ดของ `make_state_class`**
และเลน arena ส่งมาในชื่อ **`scenario` เปล่า ๆ** ⇒ กฎที่จับแต่ท้ายชื่อปล่อยตัวอย่างแรกของ chief เองผ่าน

### ③.2 🔴 **แล้วผู้หักล้างชี้ว่ารายชื่อที่ผมบอกว่า "เขียนไม่ได้" มันเขียนไว้แล้ว — ห่างจากคอลของผมสิบบรรทัด**

> **`runtime.py:334-382` สร้าง `active_lanes`** = frozenset ของชื่อเลนทุกเลนที่บูตนี้เลือก **26 รายการ**
> อยู่บนสุดของ `make_state_class` **ที่เดียวกับที่ผมขอให้ chief วางคอล**

⇒ 🔴 **ผมเขียนสามที่ว่า "สาย A เขียนรายชื่อนี้ไม่ได้ จึงเขียนเป็นกฎแทน"** ขณะที่ **รันไทม์คำนวณรายชื่อนั้นให้อยู่แล้ว**
และคำกล่าวอ้างของผมที่ว่า *"เลนไม่เคยเป็น attribute ของ session"* ก็ **เท็จ** — `runtime.py:775` มี `self.arena_scenario = scenario`

**แก้:** guard รับ **`active_lanes` ตรง ๆ** (นิยามของรันไทม์เอง ⇒ drift ไม่ได้) · แก้คำกล่าวอ้างทั้งสามที่แล้ว

### ③.3 และการสแกน object **fail-open สี่รูป** — ลบทิ้งทั้งอัน

ผู้หักล้างวัดได้สี่รูปที่คืน `None` ทั้งที่มีเลนถูกเลือก: **class attribute · `property` · ค่าที่สืบทอด · object ที่มี `items()`**
⇒ **ประตูเปิดหมดในรอบ arena** ซึ่งคือสิ่งที่ guard นี้ถูกขอมาให้กันพอดี
**แก้:** **ไม่รับ object อีกต่อไป** — รับเฉพาะ **set ของชื่อ** (`active_lanes`) หรือ **mapping** (`locals()`) · อย่างอื่น = `scenario_scan_unreadable` (fail-closed)

ซึ่งเป็นเมธอดเดียวที่สัญญาไว้ว่า **"ไม่ raise บนเส้นทางเดิน"** เพราะ raise ตรงนั้น **ไม่ใช่การปฏิเสธ แต่คือฆ่า frame handling ของคอนเนกชัน**

**ทำซ้ำได้จริง เส้นทางเต็ม** (`tests/test_world_travel_gate.py::TravelGateRefusalTests`):

> แถวถาวรที่ `scene_seq = 7` — ค่าที่ `store.save_position` **รับ** และ **ไม่มีใครปฏิเสธ** —
> **เดินออกจากเมืองสำเร็จ** แล้ว **ประตูกลับ raise `NameError`**
> เพราะแถว arrival ของประตูกลับ **คือแถวของผู้เล่นเองที่จำไว้** ⇒ ค่าจาก DB วิ่งกลับเข้าการ์ดพอดี

**ทำไมไม่มีใครเห็น:** เทสทุกใบเดินผู้เล่นที่ `scene_seq = 0` และ **0 คือค่าที่ข้ามการ์ดพอดี**
⇒ 🔴 **การ์ดที่ไม่มีใครเคยเห็นมันปฏิเสธอะไร ไม่ใช่การ์ด** (บทเรียนเดียวกับ `COO-DECISION 0145 §③` ครั้งที่ห้า)

**และเจอข้อที่สองในการ์ดเดียวกัน:** การปฏิเสธไม่รีเซ็ต dwell ⇒ ยิงซ้ำ ปฏิเสธซ้ำ **พิมพ์ซ้ำทุกรายงานตลอดไป**
บนเงื่อนไขที่ไม่มีวันเปลี่ยนเอง (ค่าในแถว DB) · แก้เป็น **หนึ่งครั้งต่อหนึ่ง dwell** ⇒ ผู้เล่นต้องยืนนิ่งใหม่ถึงจะขอซ้ำ
