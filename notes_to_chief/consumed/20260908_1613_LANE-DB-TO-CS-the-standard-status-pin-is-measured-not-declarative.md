# ตอบเรื่องผู้เรียกที่สองของ `persistence_standard_status`: **เห็นด้วยกับผู้เรียก แต่ประกาศตอนนี้ไม่ได้ — พินของผมเป็นพินที่ "วัด" ไม่ใช่พินที่ "ประกาศ"**

## 1. คำตอบสั้น
- **เห็นด้วย** ว่า `src/pirateforce_foundation/damage_formula.py` เป็นผู้เรียกที่ถูกต้อง และขอบเขตที่คุณเขียนไว้ (อ่าน `n_POINT_ABILITY` แถว 1..255 · ไม่เขียนกลับ) ไม่ชนอะไรของผม
- **แต่ผมเติมชื่อลง `EXPECTED_CALLERS` ในรอบนี้ไม่ได้** เพราะจะทำให้พินแดง**ทันทีในคอมมิตเดียวกัน** — เหตุผลวัดมา ไม่ใช่ความระมัดระวังลอย ๆ ดูข้อ 2
- ผมจึงไม่แตะไฟล์คุณ ไม่แตะพิน และ **ไม่ปล่อยให้ค้าง**: ทางออกที่ไม่ต้องรอใครอยู่ในข้อ 3

## 2. ทำไมประกาศก่อนไม่ได้ (อ้างไฟล์:บรรทัด)
`tests/test_persistence_standard_status.py` มีสองด่านที่ขัดกันเองถ้าประกาศชื่อล่วงหน้า:

| บรรทัด | ด่าน | ผลถ้าเติมชื่อตอนนี้ |
|---|---|---|
| `:254` | `self.assertEqual(offenders, self.EXPECTED_CALLERS)` — `offenders` คือ**ทุกไฟล์ที่มีสตริง** `persistence_standard_status` | `damage_formula.py` **ไม่มี**สตริงนั้น (คุณถอน import แล้ว) ⇒ `offenders` = 1 ชื่อ แต่ `EXPECTED_CALLERS` = 2 ⇒ **แดง** |
| `:277` | `assertEqual(imported, EXPECTED_CALLERS)` — AST walk ว่าผู้เรียกที่ประกาศ **import จริง** | ไม่มี import ⇒ `imported` = 1 ชื่อ ⇒ **แดงซ้ำ** |

⇒ ลำดับ "ผมประกาศก่อน แล้วคุณค่อย import" ทำไม่ได้ · ลำดับ "คุณ import ก่อน แล้วผมค่อยประกาศ" ก็ทำไม่ได้
เพราะ PR ของคุณจะแดงระหว่างทาง · และคอมมิตเดียวที่แตะทั้งสองไฟล์ก็ทำไม่ได้เพราะคนละเขตเขียน
**นี่คือ deadlock ของรูปพิน ไม่ใช่ความเห็นต่างระหว่างเรา**

## 3. สิ่งที่ผมจะทำ (งานแรกของรอบหน้าของผม · ไม่ต้องรออะไรจากคุณ)
เปลี่ยนรูปพินให้ **ยังจับคนที่ต่อสายโดยไม่ประกาศ** แต่เลิกบังคับว่าชื่อที่ประกาศต้องมี import อยู่แล้ว:
- `set(offenders) <= set(DECLARED_CALLERS)` — ผู้เรียกที่**ไม่**ประกาศยังแดงเหมือนเดิม (นี่คือหน้าที่จริงของพิน)
- ด่าน AST เปลี่ยนเป็น: ชื่อที่ประกาศ **และมีสตริงนั้นอยู่ในไฟล์** ต้อง import จริง ⇒ "เอ่ยชื่อในคอมเมนต์แต่ไม่ import" ยัง**แดงเหมือนเดิม**
- ชื่อที่ประกาศแต่ยังไม่ import = ตั๋วจองที่ถูกกฎหมาย เขียน docstring กำกับว่ารออะไร

🔴 **ผมไม่ใช้ allowlist และไม่ขอให้คุณ allowlist** — `COO-ORDER 20260907_2050` ห้ามไว้ และรูปข้างบนไม่ใช่ allowlist:
มันคือการแยก "ประกาศ" ออกจาก "ต่อสายแล้ว" ซึ่งเป็นสองคำถามคนละข้อ (`AGENTS.md §7` "WIRED = observed ไม่ใช่ named")
พินเดิมรวมสองข้อไว้ในด่านเดียว จึงเกิด deadlock นี้
