## ④ 🔬 ช่องว่างที่ GT-046 เปิดไว้ — และผมคิดว่านี่คือใบต่อไปที่คุ้มที่สุด

GT-046 เขียนไว้เองว่า:
> *"No static link from any of these three message IDs (`0x1F` / `0x03` / `0x22`) to the green `received [name] * quantity` chat template was found."*

**นี่สำคัญมาก** — คลิปแสดงชัดว่าตอนค้อนหาย มีบรรทัด **`ได้รับ [ Red leaves Hammer ] * 1` สีเขียว** โผล่ใน**เฟรมเดียวกัน**
แต่เลนคลิกเมาส์ที่เพิ่งพิสูจน์ **ไม่ได้ต่อไปถึงข้อความนั้นเลย**

⇒ **อย่างใดอย่างหนึ่ง:**
- (ก) ข้อความ `ได้รับ` มาจากเลนอื่นที่เรายังไม่เจอ — และ**เลนนั้นอาจเป็นเลนที่เพ็ตใช้** หรือเลน server-push
- (ข) มันเชื่อมกันแบบ indirect ที่การ census รอบนี้ยังไล่ไม่ถึง

**เสนอใบต่อไป (ให้ cc ตัดสินว่าจะเปิดเป็น GT-049 หรือแปะเข้า GT-046 รอบสอง):**
1. หา **template ข้อความ `ได้รับ [%s] * %d`** (หรือรูปแบบเทียบเท่า) ในตารางข้อความ/`B_CONSTDATA` แล้วจดหมายเลข id ของมัน
2. ไล่ย้อนว่า **ใครยิง id นั้น** — ถ้าไม่ใช่ `0x1F/0x03/0x22` แปลว่า **มีเลนที่สองจริง** และนั่นคือเลนของ "ของเข้ากระเป๋า"
3. ถ้าเลนที่สองเป็น **inbound** (ผ่าน `0x0089A640`) ⇒ เซิร์ฟเวอร์เป็นคนตัดสินการเก็บ ไม่ใช่ไคลเอนต์
   ⇒ **เปลี่ยนดีไซน์เซิร์ฟเวอร์ทั้งเลน**
4. ผลลบมีค่าเท่าผลบวก: "ไม่พบ template" ก็เป็นคำตอบ ต้องเขียนว่าไล่ indirect ครบแค่ไหน
