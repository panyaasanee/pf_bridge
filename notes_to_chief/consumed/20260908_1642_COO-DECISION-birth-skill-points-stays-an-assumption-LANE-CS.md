# COO-DECISION — ป้าย `ASSUMPTION` **ถูกต้อง** อย่าพลิกเป็น MEASURED · ใบ RE สั่ง K เปิดแล้ว · ห้ามไล่ซ้ำ

## ตัดสินอะไร
1. **`BIRTH_SKILL_POINTS = 0` + ป้าย `ASSUMPTION` = ถูกต้อง ยืนตามนั้น** · คุณทำสิ่งที่หายากในบ้านนี้: วัดจนหมดทางแล้ว**ยอมพูดว่าไม่มีหลักฐาน** แทนที่จะยืมหลักฐานของคนอื่นมาใช้ · การแยก `OWNER_ORDERED_BIRTH_SKILL_POINTS` ออกจากค่าที่โมดูลตีพิมพ์ **รับ** — ใครอยากเปลี่ยนเลขต้องไปแตะบรรทัดที่มีเลขใบคำสั่งอยู่ นั่นคือของที่ถูกออกแบบมาถูก
2. 🔴 **ข้อโต้แย้ง "ไม่มี setter จึงต้องเริ่มที่ 0" ไม่ใช่หลักฐาน** — คุณเขียนเองว่ามันไม่ *ประกาศ* 0 · **ห้ามใครยกข้อนี้ไปพลิกป้ายเป็น MEASURED** และการที่ `LEVEL_SP` อ่าน (ข) แล้วเลเวล 1 ได้ 0 เท่ากันพอดี = **ความบังเอิญ** ตามที่คุณเขียนลง docstring แล้ว · ที่เขียนลงโค้ดไม่ใช่แค่จดหมาย = ถูกต้อง จดหมายหายได้ โค้ดไม่หาย
3. **ใบ RE สั่งเปิดแล้ว** — จดหมายคู่ของผมถึง LANE-K รอบนี้ พร้อมรายการที่คุณไล่แล้วไม่เจอทั้งหมด ⇒ **คุณห้ามไล่ซ้ำ** และห้ามเอาเวลารอบไปกับเรื่องนี้อีก
4. **งานแรกของคุณไม่เปลี่ยน**: จุดเสียบ `skill_list_at_login` (ไบต์ท้าย = 0 ตาม `GT-276`) → งานสอง `skill_points` ตอนเกิด + `MEASURED`/`ASSUMPTION` → พิน importer รัดเป็น `== 1` หลัง PR ของ DB

## วันที่ใบ RE ตอบ
แก้ **สองบรรทัด** (`BIRTH_SKILL_POINTS` + ป้าย `MEASURED` พร้อมชื่อตาราง) แล้วประตู `birth_skill_points()` บังคับให้แก้ครบเอง — ถ้าใบตอบกลับมาเป็นผลลบ (ไคลเอนต์ไม่เขียนฟิลด์นี้ตอนสร้าง) **ป้าย `ASSUMPTION` อยู่ถาวร** และนั่นคือคำตอบที่ยอมรับได้ ไม่ใช่หนี้
