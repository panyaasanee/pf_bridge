# แยกเป็นสองกรณี: กรณี "แถวมา แต่ selector ไม่ติดอาวุธ" = **(ข) ขยายได้เลย วัดแล้ว** · กรณี "แถวหาย" = **วัดกำแพงก่อน**

## ตัดสินอะไร
1. 🔴 **`guard_armed_block({3: 0xFFFFFFFF, 4: 1})` ผ่านประตู = รูที่วัดแล้ว ไม่ต้องรอสวีปเพื่อยืนยัน**
   นี่คือ **อาการที่เจ้าของรายงานคำต่อคำ** (`-1/1` บนแผงตัวเอง) บน **คู่หลัก** ซึ่งไคลเอนต์อ่านโดยปริยาย
   และ `primary_pair_gaps` ของคุณ **จับได้อยู่แล้ว** ประตูแค่ไม่เรียกมันเพราะ `x=9` ไม่ใช่ 8
   ⇒ **ขยายเงื่อนไขการยิงเป็น "บล็อกมีคู่ HP ที่ไม่ซื่อสัตย์ ไม่ว่า selector จะติดอาวุธหรือไม่"**
   เงื่อนไข: **สวีปใหม่ทั้งชุดในรอบเดียวกันกับที่เปลี่ยน WHEN** (adversary สวีป 50,625 บล็อกบนรูปเก่า
   รูปใหม่ต้องมีตัวเลขของตัวเอง) · ห้ามขยายแล้วค่อยสวีปรอบหน้า
2. **กรณี "แถว x=9 หายทั้งแถว" ยังไม่ตัดสิน — วัดก่อน** ตามที่คุณเสนอ: สวีปว่ามี key set ไหนที่กำแพง
   `make_update_attr_frame` (`gm/attr_wire.py:955`) **รับ** แล้วแถว HP หายไป
   - เซตว่าง ⇒ (ก) จริง · **แล้วคุณต้องแก้พาดหัวเอง**: ประตูของคุณคือ "ประตูที่ปฏิเสธค่า" ไม่ใช่ "ประตูที่กันอาการ"
     แก้ทั้ง docstring และถ้อยคำในไฟล์รอบ **ในรอบเดียวกัน** — ประโยคที่ฟังแข็งแรงเกินจริงคือหนี้ ไม่ใช่ผลงาน
   - เซตไม่ว่าง ⇒ กำแพงมีรู · **เขียน `CORE-REQUEST` ถึงเจ้าของ `gm/attr_wire.py` ห้ามแก้เอง**
   🔴 **อ่าน** ไฟล์นอกเขตได้เสมอ (เขต = สิทธิ์ **เขียน**) การสวีปนี้ไม่ใช่การออกนอกเขต
