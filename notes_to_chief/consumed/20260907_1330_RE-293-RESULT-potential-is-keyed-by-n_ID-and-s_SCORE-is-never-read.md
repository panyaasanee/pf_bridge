## ข้อ 1 — คีย์ของตาราง `POTENTIAL` = **`n_ID`** (คอลัมน์เดียว ไม่ใช่ class×level)

ตัวโหลดอยู่ที่ `0x004A4371`-`0x004A4576` วนทุกแถวของตาราง `L"POTENTIAL"` (สตริง `0x00F14B94`)
แล้วต่อหนึ่งแถวทำแบบนี้:

```
4a43a6  ; row i  <- call 0x0088FA20
4a43be  push 0x00F0C958        ; L"n_ID"      <<<< อ่านคอลัมน์นี้ก่อนเพื่อน
4a43ca  call 0x00891EE0        ; get column by name
4a43d1  mov edi,[eax+4]        ; edi = ค่า n_ID = คีย์
4a43e4  push 0x20 ; call 0x00B37980   ; จองเรคคอร์ด 32 ไบต์
4a43f2..4a4408                  ; ล้าง 8 dword (+0x00..+0x1C) เป็นศูนย์
```

แล้วเติมหกช่องด้วยชื่อคอลัมน์ตรง ๆ:

|---|---|---|---|
| `0x004A449D` | `0x00F14B84` | **`n_LEVEL`** | `record+0x08` |
| `0x004A44C5` | `0x00F14B70` | `n_STRENGH` | `record+0x0C` |
| `0x004A44E5` | `0x00F14B50` | `n_CONSTITUTION` | `record+0x10` |
| `0x004A4502` | `0x00F14B3C` | `n_AGILITY` | `record+0x14` |
| `0x004A4522` | `0x00F14B24` | `n_INTELLECT` | `record+0x18` |
| `0x004A4542` | `0x00F14B08` | `n_PERCEPTION` | `record+0x1C` |

🔴 **แก้รายการ `POTENTIAL_BINDS` ในใบ**: รายการหกตัวที่ใบอ้าง (`tools/pf_stats_progression_static.py:658`)
**ตัวแรกคือ `n_LEVEL` ไม่ใช่สแตท** และรายการนั้น **ตกคีย์ทิ้ง** — bind ของ `n_ID` อยู่ที่
`0x004A43BE` ซึ่งไม่อยู่ในรายการ ⇒ ใครอ่านรายการนั้นจะเข้าใจว่าตารางไม่มีคีย์

**⇒ หนึ่งแถว = หนึ่งเรคคอร์ด คีย์ `n_ID` · `n_LEVEL` เป็น "คอลัมน์ที่เก็บไว้" ไม่ใช่ส่วนหนึ่งของคีย์**
สมมติฐาน "class×level" ของใบ **ไม่ตรงกับสิ่งที่ตัวโหลดทำ**

**เขียนตรง ๆ ไม่มีการบวก**: ทุกช่องเป็น `mov DWORD PTR [ebx+0xNN],eax` จากค่าคอลัมน์ดิบ
ไม่มี `add`/`imul` ในเส้นทางโหลด ⇒ ถ้ามีการบวกแต้ม มันเกิดตอนใช้งาน ไม่ใช่ตอนโหลด (ดูข้อ 2)

## ข้อ 3 — `s_SCORE`: **ไม่ถูกอ่านเลย ทั้งอิมเมจ**

ค้นทั้ง `.rdata` ทั้งแบบ UTF-16LE และ ASCII:

| สตริง | จำนวนที่พบในอิมเมจ |
|---|---|
| `s_SCORE` (UTF-16) | **0** |
| `s_SCORE` (ASCII) | **0** |
| `n_SCORE` (ASCII) | **0** |

⇒ **ไคลเอนต์ไม่มีโค้ดที่ lookup คอลัมน์ชื่อ `s_SCORE` เลย** · ทุก lookup ในระบบนี้ทำผ่าน
`0x00891EE0(ชื่อคอลัมน์ UTF-16)` ซึ่งต้องมีสตริงชื่อคอลัมน์อยู่ในอิมเมจ — ไม่มีสตริง = ไม่มีการอ่าน
นี่คือคำตอบแบบ **"ไม่ถูกอ่านเลย"** ที่ใบบอกว่ามีค่าเท่ากับคำตอบบวก

เทียบเป็นตัวควบคุม (คำที่**มี**จริง): `CHARCREATE_CLASS` `0x00F0C650` (18 xref) ·
`n_POINT_ABILITY` `0x00F14BE0` (**1** xref) · `STANDARD_STATUS` `0x00F152AC` (9 xref) ·
`n_STRENGH` `0x00F14B70` (5 xref) ⇒ วิธีค้นใช้ได้จริง ไม่ใช่ผลลบเพราะค้นผิดวิธี

## ข้อ 4 — ตาราง `POTENTIAL` ตัวเต็มอยู่ไฟล์ไหน: **ไม่มี และตัวโหลดรับมือกับความว่างนั้นเงียบ ๆ**

`RE-282` (ปิดแล้ว 2026-09-06T23:22) พิสูจน์ไปแล้วว่า `POTENTIAL` มี **0 แถวจริง** ในไฟล์ที่ไคลเอนต์
shipped มาเอง และสำมะโนครบ 120 ตาราง CONSTDATA ไม่มีตารางสแตทเริ่มต้นต่อคลาสเลย
🔴 ใบนั้นประกาศ **method ceiling** ห้าม rerun เส้นทาง `s_SCORE` — รอบนี้จึง **ไม่รันซ้ำ** เส้นทางนั้น
ข้อ 3 ข้างบนตอบด้วยวิธีคนละอย่าง (census สตริงทั้งอิมเมจ) ไม่ใช่การแกะ `s_SCORE` ซ้ำ

สิ่งที่รอบนี้เติมให้: **ตัวโหลดมีทางออกเงียบสำหรับตารางว่าง**

```
4a438c  mov ecx,[tbl+0x68] ; sub ecx,[tbl+0x64]   ; ขนาดเวกเตอร์แถว
4a439a  test ecx,0xFFFFFFFC
4a43a0  jle 0x004A459C                            ; 0 แถว -> ข้ามลูปทั้งก้อน ไม่มี log ไม่มี error
```

⇒ บนบิลด์นี้ **แมป `POTENTIAL` ว่างตอนรันไทม์** ⇒ **STR ที่เห็นบนจอเป็นไปไม่ได้ที่จะมาจาก `POTENTIAL`**
ในไคลเอนต์ที่เรามี · ถ้าเซิร์ฟเวอร์จริงเคยมีค่า มันมาจากไฟล์ข้อมูลที่ไม่ได้ ship มากับไคลเอนต์

## ข้อ 2 — **ยังเปิด** (ผู้เรียก / มีการบวก `n_POINT_ABILITY` ไหม)

สิ่งที่วัดได้แล้วและใช้ต่อได้:

  (ช่วง `STANDARD_STATUS`) ⇒ **ไม่มีโค้ดที่ไหนอีกเลยที่เอ่ยชื่อคอลัมน์นี้** — ถ้ามีการบวกแต้ม
  มันต้องอ่านผ่านออฟเซ็ตของเรคคอร์ดที่โหลดไว้ ไม่ใช่ผ่านชื่อคอลัมน์
- ผู้ต้องสงสัยที่เหลือ (xref ของ `n_STRENGH` ที่ **ไม่ใช่** ตัวโหลด): `0x00585971` · `0x00588843` ·

- จุดที่เปิดตาราง `POTENTIAL` นอกตัวโหลด: `0x00585A02` และ `0x005888D5`

## BUILD_IMPACT

1. **ห้ามสร้าง `POTENTIAL` ฝั่งเซิร์ฟเวอร์ด้วยคีย์ class×level** — โครงจริงคือคีย์เดียว `n_ID`
   พร้อมคอลัมน์ `n_LEVEL` อยู่ในแถว · ความหมายของ `n_ID` ยังไม่ทราบ (ดู nonclaim 2)
2. **`s_SCORE` ตัดออกจากรายการผู้ต้องสงสัยได้ถาวร** — ไคลเอนต์ไม่เคยอ่าน
   ⇒ สาย CS ไม่ต้องออกใบ dump `s_SCORE` อีก
3. **แก้ `tools/pf_stats_progression_static.py:658`**: `POTENTIAL_BINDS` ควรมี 7 ตัว ไม่ใช่ 6
   และควรทำเครื่องหมายว่าตัวแรก (`0x004A43BE`, `n_ID`) คือคีย์ · ตัวที่สอง (`0x004A449D`) คือ `n_LEVEL`
   ไม่ใช่สแตท — งานนี้เป็นของสาย CS/DB ไม่ใช่ RE runner
4. **ยังปลดบล็อกสูตรดาเมจไม่ได้** — เพราะตารางว่างในไคลเอนต์ที่ shipped มา ค่าฐาน STR
   ต่อคลาส/เลเวลไม่มีอยู่ในของที่เรามีเลย · ทางเลือกกลายเป็นคำถามออกแบบสำหรับ Panya/chief
   (ตั้งค่าเอง vs. หาไฟล์ข้อมูลจากที่อื่น) ไม่ใช่คำถาม RE อีกต่อไป

## nonclaims

1. **ไม่อ้างว่ารู้ว่า `n_ID` หมายถึงอะไร** (class id? ลำดับแถว? คีย์ผสม?) — วัดได้แค่ว่ามันคือคอลัมน์
   ที่ถูกอ่านก่อนและใช้เป็นคีย์ · **ห้ามจับคู่กับ class id เพราะเลขเท่ากัน** ยังไม่มี crosswalk field
2. **ไม่อ้างว่า STR ไม่ได้มาจากแต้มที่ผู้เล่นแจก** — ข้อ 2 ยังเปิด ยังไม่ได้เดินถึงผู้บริโภค
3. **ไม่อ้างว่า STR มีผลต่อดาเมจในบิลด์นี้** (ตาม nonclaim ของเจ้าของใบเอง)
4. **ไม่ได้ใช้ linear disassembler เป็นหลักฐานผลลบ** — ผลลบข้อ 3 มาจาก census สตริงทั้ง `.rdata`
   (ทั้ง UTF-16 และ ASCII) + การพิสูจน์ว่ากลไก lookup ต้องใช้สตริงชื่อคอลัมน์ **ไม่ใช่**
   จากการไล่ดิสแอสเซมบลีเชิงเส้นแล้วไม่เจอ
5. **ผลลบจำกัดที่ `GameClient.local.bin` ไฟล์เดียว** ไม่ได้ค้นไฟล์ข้อมูลนอกอิมเมจ
6. ไม่ได้แก้ไฟล์ใด ๆ · ไม่ได้แตะ `GameClient/`
