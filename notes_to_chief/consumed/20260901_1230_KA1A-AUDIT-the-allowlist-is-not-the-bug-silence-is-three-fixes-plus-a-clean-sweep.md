## ข้อสรุปหลัก: **อย่ากลับ allowlist เป็น denylist**

นี่คือทางแก้ที่ดูน่าทำที่สุดและเป็นทางที่ผิดที่สุด `pf_bridge` เป็น **repo สาธารณะ** และดิสก์
bridge มีของที่ derive จาก client (capture, gamedata, วิดีโอ, ไบนารี) allowlist คือ**ด่านกัน
ของหลุด** ไม่ใช่ตัวจัดระเบียบ — denylist ที่ลืมหนึ่ง pattern = ของหลุดขึ้นที่สาธารณะถาวร
กลับด้านไม่ได้ **ที่ต้องแก้คือความเงียบ ไม่ใช่ตัวลิสต์**

อยู่ใน .gitignore โดยเจตนา คุณมองไม่เห็นธง และธงมองไม่เห็นคุณ และนั่นถูกแล้ว"* ส่วนที่อ้างอีกจุด
เป็นพรอมป์เซสชัน attended ซึ่งอ่านผ่าน device_bash บนเครื่องเจ้าของ ไม่ใช่จาก clone

**สองไฟล์ ⚠️ ยังไม่พังวันนี้** เพราะสายเขียนมันจาก clone ตัวเองแล้วขึ้น main ทาง PR (ไม่ผ่าน
sync) และไหลลง bridge ทาง pull ปกติ **แต่มันเป็นกับระเบิดฝั่ง bridge**: ถ้าผู้เทส/ผู้ช่วย/เจ้าของ
แก้ไฟล์พวกนี้บนดิสก์เมื่อไหร่ มันจะกลายเป็น tracked-modified ที่อยู่นอก SHARED_TRACKED =
**deadlock ทางเดียว: ออกไม่ได้ และบล็อกทุก pull ที่จะเข้ามา** — ตรงกับที่คอมเมนต์ในสคริปต์บันทึกไว้
ว่าเคยเกิด 94 ครั้งกับ `AGENTS.md`/`CHIEF_CONTINUATION.md` และเป็นเหตุผลที่ SHARED_TRACKED
ถูกสร้างขึ้นมา · ไฟล์ราก `.md` อีกประมาณร้อยใบ (`FACTPACK_*`, `FINDINGS_*`, `EVIDENCE_GATES.md`,
`PROCESS_GATES.md` ฯลฯ) อยู่ในกลุ่มเดียวกันทั้งหมด

**นอกจาก NOW.md ที่แก้ไปแล้ว ไม่มีไฟล์ไหนพังอยู่ตอนนี้** — นั่นคือคำตอบตรง ๆ ของคำถามเจ้าของ
