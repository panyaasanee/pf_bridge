## คำสั่งเจ้าของ

> "เปิดใบ RE นั้นเลย **และให้แน่ใจว่ามีคนจะหยิบผลลัพธ์ของใบนั้นไปใช้ต่อด้วย**"

ประโยคหลังคือส่วนที่สำคัญที่สุดของใบนี้ — ดูหัวข้อ "สัญญาผู้บริโภค" ท้ายใบ **ห้ามเปิดใบนี้ถ้าไม่มีคนเซ็นรับส่วนนั้น**

## ทำไมใบนี้ (เจ้าของถามเองว่า "ทำไมยังเปลี่ยนแมพในเกมเดียวไม่ได้")

กะ1-A วัดจากซอร์สบน main ตอบเธอไปแล้ว สรุปหลักฐานสามบรรทัด:

1. **`ForcePos` ไม่มีช่องใส่ฉาก** — docstring ของ `gm/warp_executor.py` อ้าง RE-090 ตรง ๆ: *"ForcePos ... carries no presence bit, **scene id**, sequence, string or control field"* ⇒ ย้ายได้เฉพาะในแมพเดิม **ไม่ใช่ข้อจำกัดที่เราตั้งเอง ตัวเฟรมไม่มีที่ให้ใส่**
2. **`TeleportVital` เป็นตัวเดียวที่น่าจะใส่ฉากได้ แต่ฟิลด์ยังไม่ถูกพิสูจน์** (RE-090 ปิดโดยยังไม่รู้)
3. **`warp_executor` ยังไม่ถูกต่อสายเลย** — `grep -c warp_executor src/pirateforce_foundation/runtime.py` = **0**

⇒ ทางเดียวที่พิสูจน์แล้วว่าทำให้ client โหลดฉากได้คือ **ทางล็อกอิน** (`START_GAME_RES` + สำมะโน) ซึ่งเป็นเหตุผลที่ `/warp <ฉากอื่น>` ถูกออกแบบเป็น "จองไว้รอล็อกอินหน้า" — และ **GT-141 เพิ่ง PASS วันนี้ 16:3x** พิสูจน์ว่าทางนั้นใช้ได้จริง

**แต่ปลายทางที่เจ้าของต้องการคือเปลี่ยนแมพโดยไม่ต้องล็อกเอาต์** ซึ่งวันนี้ไม่มีใครรู้ว่าต้องส่งไบต์อะไร

## ใบที่ขอให้เปิด (ร่างเต็ม — RE runner ปรับถ้อยคำได้ แต่ห้ามลดขอบเขต)

**เลข: `RE-162`** — grep ยืนยันโดยกะ1-A ณ 16:55 +07:00: `RE-162`/`GT-162` = **0 hit** ทั้ง `CLIENT_RE_QUEUE.md` และ `GAME_TEST_QUEUE.md` (เลขที่ใช้แล้วสูงสุด = 161) · **grep ซ้ำก่อนจองจริงตามกติกา**

**ชื่อ:** `RE-162 IN-SESSION-SCENE-CHANGE-WIRE-001 [STATIC-ON-BRIDGE]` — ไคลเอนต์ยอม **ทิ้งฉากปัจจุบันแล้วโหลดฉากใหม่ระหว่างเซสชันเดียว** ด้วยเฟรมอะไร และฟิลด์ไหนคือหมายเลขฉาก

**คำถามที่ต้องตอบ (เรียงตามลำดับ ไล่ประตูบานแรกก่อน):**
1. `CTeleportVital`/`TeleportVital` — layout เต็ม ฟิลด์ไหนคือ scene id / seq / xyz / heading · ฟิลด์ไหนที่ RE-090 ทิ้งไว้ว่า "ยังไม่พิสูจน์" และมันถูกอ่านที่ VA ไหน
2. ฝั่ง client: **ฟังก์ชันไหนคือตัวที่สั่ง unload ฉากเดิม + load ฉากใหม่** และมันถูกเรียกจากเส้นทางไหนบ้าง — เส้นทางล็อกอิน (`START_GAME_RES`) กับเส้นทางระหว่างเซสชันเป็นตัวเดียวกันหรือคนละตัว
3. ถ้าเป็นคนละตัว: เส้นทางระหว่างเซสชันมี **gate อะไรบ้างก่อนถึงจุดโหลด** (เทียบเคียงบทเรียน `RE-118`: ไล่จากประตูบานแรก ไม่ใช่บานสุดท้าย)
4. ต้องส่ง **สำมะโน/actor ของฉากใหม่** ตามมาไหม และตามลำดับใด (ก่อน/หลัง/พร้อม) — ถ้าลำดับผิดจะเห็นอาการอะไร
5. **ผลลบก็เป็นคำตอบ:** ถ้าอิมเมจไม่มีเส้นทางเปลี่ยนฉากระหว่างเซสชันเลย ให้ปิดเป็น bounded-negative พร้อมระบุว่า "ล็อกอินคือทางเดียว" — นั่นคือคำตอบที่ปิดคำถามของเจ้าของถาวรและมีค่าเท่าผลบวก

**ข้อห้าม:** ห้ามเดาค่าแล้วให้ผู้เทสยิงใส่ client จริง (บทเรียน GT-101 error 23065/28317) · ห้ามอ้างว่า `ForcePos` ทำได้ (RE-090 ปิดไปแล้วว่าไม่มีช่องฉาก) · ห้ามลดรูปเหลือ "same-scene ก็พอ"
