## 2) เพดานที่ทำให้ใบเดิมอาจ "รันไม่ได้" ถ้าไม่แก้ objective (ข้อสำคัญที่สุดของใบนี้)
หัวใบ `RE-265` เขียนเป็นเงื่อนไขไว้เองว่า checkpoint = **cross-layer ceiling: ห้าม RE runner rerun image เดิมจนกว่า chief จะเปลี่ยน objective**
ใบ `RE-303` ที่ถามว่า "vital ขาเข้าตัวไหนเปิด `Common_Confirm`" คือ **objective เดียวกับข้อ (ก) ของ `RE-265`** ซึ่งตอบไปแล้วเป็นผลลบ
⇒ ถ้าปล่อยรูปคำถามเดิม runner จะเดินพื้นที่เดิมแล้วคืนคำตอบเดิม = เสียเวลาเครื่องคุณ Panya หนึ่งนัด

## 3) objective ที่แคบลงแล้ว — ขอให้ผูกลงแถว `RE-303` ต่อท้ายเนื้อใบเดิม **คำต่อคำ** (คำของ LANE-A ไม่ใช่ของ K)
```
RE-303 ถามเฉพาะ "ประตูที่สอง" เท่านั้น -- ประตูแรก (AddSurveyData contact tick) ปิดแล้วโดย RE-265/RE-270 ห้ามเดินซ้ำ:
(1) มี vital ขาเข้า *ตัวอื่น* ตัวไหนไหม ที่ทำให้ client เปิด Common_Confirm ที่ถือข้อความรายงานกัปตัน
    โดย *ไม่* ผ่าน NavigationExModule_Client contact tick -- วิธี: string UTF-16 ของหน้าต่างนั้น -> xref
    -> ฟังก์ชันเปิด UI -> ไล่ขึ้นหา handler ขาเข้า ถ้ามี
(2) ถ้ามี: id + layout ของมัน  ถ้าไม่มี: ผลลบต้องบอก "กวาดอะไรบ้าง" -- string table ช่วงไหน, xref กี่จุด,
    ฟังก์ชันเปิด UI ตัวไหนถูกไล่ขึ้นไปแล้วบ้าง (ไม่ใช่คำว่า "ไม่เจอ")
(3) กด OK บนประตูที่สองนั้นส่งอะไรกลับ -- สำหรับประตูแรก RE-265 ตอบแล้วว่า client ยิง EnterInstanceVital เอง
    ข้อนี้ถามเฉพาะกรณีที่ (1) ตอบว่า "มี"
อะไรถูกตัดออกไปแล้ว (ห้ามกวาดซ้ำ): RE-285 (ปิดลบ) · RE-286 (ไม่ใช่ตัวเปิด) · RE-227 (REFUTED-ON-SCREEN R318)
· RE-265 (ประตูแรกทั้งเส้น + คำตอบของ OK) · RE-270 (คีย์ store = n_ID คอลัมน์ 0)
```

## 4) สิ่งที่ผมไม่ทำในใบนี้
