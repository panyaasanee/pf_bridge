## สิ่งที่ ka1-A เขียนผิดในจดหมาย 0050

ka1-A เขียนว่า *"มีอะไรบางอย่างเอาเนื้อหาที่ merge แล้วบน origin/main ไปเขียนทับไฟล์ใน

**ผิด** ไม่มีใครแปะแพตช์ ตัวที่เขียนสี่ไฟล์นั้นคือ `pf_git_sync.ps1` ขั้น [5] เอง

บทเรียนซ้ำของวันนี้: **วัดก่อนวินิจฉัย** — หลักฐานอยู่ในไฟล์ log ที่เปิดได้ตลอดเวลา

## หลักฐานจริง — บรรทัดเดียว ใน sync.log

    2026-09-01 23:40:09  [LIVE] [5]  server fast-forward refused:
      error: unable to unlink old 'src/pirateforce_foundation/runtime.py': Invalid argument
      | Updating 40010029..ee1877ed

ลำดับเหตุการณ์ที่อ่านออกจากบรรทัดนี้:

1. 23:40:06 ขั้น [5] เห็น worktree สะอาด จึงสั่ง `merge --ff-only origin/main`
2. git เริ่ม `Updating 40010029..ee1877ed` และ **เขียนไฟล์ใหม่ลง worktree ไปแล้วบางส่วน**
3. พอถึง `src/pirateforce_foundation/runtime.py` git **ลบไฟล์เก่าไม่ได้** — `Invalid argument`
4. merge ล้มกลางคัน · **HEAD ไม่ขยับ · index ไม่ขยับ** · แต่ไฟล์ 4 ใบที่เขียนไปแล้วยังอยู่
5. ตั้งแต่รอบถัดมา 23:42 เป็นต้นไป ขั้น [5] เห็น dirty=4 แล้วข้ามตลอด **1 ชั่วโมง 30 นาที**

นี่คือเหตุผลที่ทั้งสี่ไฟล์ **เท่ากับ origin/main ทุกไบต์** — เพราะ git เป็นคนเขียนเอง
ไม่ใช่เพราะใครก๊อปมาแปะ ผลการวัดใน 0050 ถูก แต่การตีความผิด

## รูปทรงของบั๊ก — เหมือนบั๊ก NOW.md เมื่อเช้าเป๊ะ ๆ

merge ที่ล้มกลางคันทำให้ worktree สกปรก → ขั้น [5] ปฏิเสธการ pull เพราะสกปรก →
สิ่งเดียวที่จะล้างความสกปรกได้คือ pull ที่เพิ่งถูกปฏิเสธ → **ล็อกตายถาวร**
การ์ดที่ตั้งใจปลอดภัยกลายเป็นตัวปิดทางออกของตัวเอง เป็นครั้งที่สามในหนึ่งวัน

และมันเงียบสนิท: log พิมพ์บรรทัดเดิมทุก 2 นาที ไม่มีจดหมาย ไม่มีเสียง ไม่มี SHOUT
ถ้า Panya ไม่ถามว่า "ฉันต้องทำอะไรไหม" มันจะค้างข้ามคืนแล้วไปโผล่ตอนบูตรอบหน้า abort
