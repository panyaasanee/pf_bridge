## ① ที่มา (ค้นแล้ว: เจอ — จาก log ของ gate เอง ไม่ใช่การเดา)

รอบก่อน (`vb3ktn`) แก้ `gm/command_capture.py` ให้ `os.open(...)` ใส่ `mode=0o600`
อย่างชัดเจน (แก้ปัญหาไฟล์ capture เป็น `0o755` โลกอ่าน+รันได้ ภายใต้ umask ปกติของ
โปรเจกต์) แล้วเพิ่มเทสยืนยัน แต่ gate ของ `pirate-force-server` (windows-latest,
run `33132956815`) แดง: `AssertionError: 438 != 384 : 0o666` — เทสคาดว่า mode
เป็น `0o600` เป๊ะ แต่บน Windows ได้ `0o666`

สาเหตุคือ NTFS ไม่มีบิตสิทธิ์แบบ POSIX (owner/group/other) — `os.open()` ของ
CPython บน Windows อ่านอาร์กิวเมนต์ `mode` แค่บิตเดียว (เขียนได้ vs read-only)
แล้วเมิน owner/group/other ทั้งหมด **แปลว่า `mode=0o600` ที่รอบก่อนใส่ไป ไม่บังคับ
อะไรเลยบน Windows จริง** — เป็นการป้องกันที่ใช้ได้เฉพาะบน POSIX (sandbox/CI ของ
โปรเจกต์นี้ทั้งหมด) ไม่ใช่บนสะพาน Windows ของเจ้าของที่เป็น production target จริง
(`gate-windows.yml` มีอยู่เพราะเหตุผลนี้ตรง ๆ — ดู docstring ของไฟล์นั้น)
