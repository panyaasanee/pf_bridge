เรื่อง (หนึ่งเรื่องต่อหนึ่งใบ): `CURRICULUM.n_PPCLASS` ถัง `1024` ควรอ่านว่าอะไร

## ติดตรงไหน

รอบนี้ผมพิสูจน์ได้ว่า `CONSTDATA_TH__CURRICULUM.tsv` คอลัมน์ `n_PPCLASS` ใช้รหัสคลาสชุดเดียวกับ
`CHARCREATE_CLASS.n_ID` (รายละเอียดในใบ `2150`) — แต่มันมี **6 ค่า** ไม่ใช่ 5:

    1, 2, 4, 16, 32   = ห้าคลาสที่เลือกได้จริง (ตรงกับ CHARCREATE_CLASS ทุกตัว)
    1024              = ไม่ใช่ n_ID ของคลาสไหนเลย

สิ่งที่ **วัดได้** เกี่ยวกับถัง 1024:
- ถือ 11 skill id: `99, 110, 111, 2950, 2955, 2957, 2960, 2965, 2968, 2971, 2978`
- ไม่มี id ไหนอยู่ใน block ของคลาสใดคลาสหนึ่ง (40xxx..44xxx) เลย — disjoint สะอาด
- มี `99` (Normal Attack), `110` (Strive Jump), `111` (VIP Strive Jump) ครบ ซึ่ง **คือสามสกิลที่
  ทั้งห้าคลาสแชร์กันพอดี** ใน `CHARCREATE_CLASS` (`s_SKILL_1/3/4` เหมือนกันหมดทั้งห้าแถว)

สิ่งที่ **วัดไม่ได้**: ตัวเลข 1024 เองไม่มีตารางไหนที่ commit แล้วอธิบายว่าแปลว่าอะไร

## ตัวเลือก

- **(ก) 1024 = "ทุกคลาส"** — อ่านตรงตัวจากหลักฐานข้างบน ถ้าใช่ สกิลอีก 8 ตัว (2950..2978) ก็เป็น
  สกิลที่ตัวละครทุกคลาสได้ และลิสต์จริงต่อคลาส = 25/26 + 11
- **(ข) 1024 = ธง bitmask ที่แปลว่าอย่างอื่น** (เช่น "ไม่ผูกคลาส" / เควส / เรือ) — 1024 เป็นกำลังสอง
  เหมือนรหัสคลาสอื่น ๆ จึงอาจเป็นบิตในชุดเดียวกันที่หมายถึงหมวดอื่น ไม่ใช่ "ทุกคลาส"
- **(ค) รอ RE ใบใหม่** ก่อนตัดสินใจ — แต่ใบนั้นต้องบูตเครื่องเจ้าของ (attended) ซึ่งตอนนี้ยังติด

## ผมเลือกอะไรไปก่อน

ผมเลือก **ไม่ตัดสิน** และกันความเสียหายไว้แทน — ในโค้ดมันชื่อ `SHARED_BUCKET_CODE` /
`shared_bucket_skill_ids()` ตามเลขถังดิบ ไม่ได้ชื่อว่า "ทุกคลาส" และที่สำคัญ
**`curriculum_skill_ids(class_id)` คืนเฉพาะถังของคลาสนั้นเท่านั้น ไม่รวม 1024 เข้าไปเลย**
พร้อมเทสที่บังคับข้อนี้ไว้ (`test_curriculum_skill_ids_never_folds_the_shared_bucket_in`)
ในเอกสารโมดูลกำกับว่า `[สมมติของสาย CS - รอ COO ยืนยัน]` ตรงจุดที่พูดถึงการอ่านแบบ (ก)

## ถ้าเคาะแล้วผมอ่านผิด ต้องย้อนอะไร

น้อยมาก และเป็นเหตุผลที่ผมกันไว้แบบนี้ตั้งแต่แรก:
