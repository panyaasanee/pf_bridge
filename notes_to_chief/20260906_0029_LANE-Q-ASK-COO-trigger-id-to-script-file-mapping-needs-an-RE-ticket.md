# LANE-Q ASK-COO -- เปิดใบ RE เรื่อง trigger-id -> script-file mapping ได้ไหม (ตัวบล็อกเดียวที่เหลือของคิว Trigger.*)

## ติดอะไร

รอบก่อน (`456vso`) สร้าง `TriggerStatusRegistry` (สถานะทริกเกอร์จริง 5/17 ฟังก์ชัน) แล้วชี้ว่างานถัดไปคือ
"ต่อสาย `TriggerVital` (0x1FB2) ของจริงเข้ากับไฟล์สคริปต์" -- ข้อนี้คือสิ่งเดียวที่ปิดเกณฑ์ผ่านของคิวนี้
("ผู้เล่นแล่นเรือชนทริกเกอร์แล้วสคริปต์ทำงาน") รอบนี้ (`4jsydv`) grep หาตารางที่แปลง wire trigger id
(tag 0x0F ใน `TriggerVital`, พิสูจน์แล้วใน `external/PF_SERIALIZER_FIELDS.tsv`) ให้เป็นชื่อไฟล์ `.lua`
ก่อนเขียนโค้ดสักบรรทัด -- **ไม่เจอ**:

- `gamedata/tables/` -- ไม่มีคอลัมน์ไหนตรง `\.lua|ScriptStart|script_name|s_Script` ในตารางไหนเลย
  (`CONSTDATA_TH__Trigger.tsv` มีแค่ `n_ID`/เสียง/`n_MESSAGE_TYPE`, ไม่มีชื่อสคริปต์)
- `gamedata/scene/*/*.placements.tsv` -- ตรวจ header แถวแรกแล้ว ไม่มีคอลัมน์ชื่อสคริปต์
- `external/` -- เจอแค่ `PF_SERIALIZER_FIELDS.tsv` (เลย์เอาต์ของเฟรม ไม่ใช่ตาราง mapping)
- `archive/`, `notes_to_chief/consumed/` -- ไม่เจอ
- ชื่อไฟล์สคริปต์เองก็ไม่เข้ารหัส id (`t_nex_t6.lua` ไม่ใช่ "ทริกเกอร์เลข 6 ในฉาก nex" -- อ่านเนื้อไฟล์แล้ว
  `Var1..Var6` ของมันคือทริกเกอร์ *อื่นหก* ตัวที่มันรอ ไม่เกี่ยวกับเลขในชื่อไฟล์ตัวเอง)

พูดตรง ๆ : นี่เป็นช่องว่างจริงในเอกสาร/ข้อมูลที่ commit แล้ว ไม่ใช่ grep พลาด และไม่ใช่สิ่งที่ควรเดา
(สคริปต์ 309 ไฟล์ ผูกกับ trigger id ผิดไฟล์ = เควส/ฉากทำงานผิดเงียบ ๆ)

## ทางเลือก

1. **เปิดใบ RE ใหม่** ถามหา mapping นี้ -- อาจเป็นตารางที่ยังไม่ extract จาก client (เช่นในไฟล์ `.scn`
   ไบนารีของแต่ละฉาก ที่ `*.placements.tsv` สกัดมาได้แค่บางส่วน) หรือฝังอยู่ในโค้ด client เป็น
   id -> resource-path lookup ไม่ใช่ตาราง -- ไม่รู้แน่ชัดจนกว่าจะมีคนดู ต้องการเลขใบจาก chief (ตัวนับ
   ร่วมกับ GT ตาม `AGENTS.md` §9)
2. **หรือ capture ที่เครื่องคุณ**: ถ้ามี debug/log บน client ที่พิมพ์ชื่อสคริปต์เวลาทริกเกอร์ทำงาน (ทริกเกอร์
   ในเกมจริงต้องรู้ชื่อไฟล์ของตัวเองแน่ ๆ ไม่งั้นมันรันสคริปต์ไม่ได้) อาจถามได้ตรงกว่าใบ RE static

รอบนี้ตัดสินใจเอง (ตาม `[สมมติของสาย LANE-Q - รอ COO ยืนยัน]`): **ไม่เปิดใบ RE เอง** เพราะไม่มีเลขใบและ
ไม่อยากชนใบอื่นที่อาจถามเรื่องเดียวกันอยู่แล้ว (`grep -n "LANE-Q" CLIENT_RE_QUEUE.md` ไม่เจอใบเก่าเรื่องนี้ --
ตรวจแล้ว ไม่ใช่ใบซ้ำ) -- ทำงานสำรอง (ดูรอบนี้: `run_corpus_entry_points`, `docs/SCRIPT_LANE.md` round
`4jsydv`) แทนจนกว่าจะมีเลขใบ

## ถ้าผิด ต้องย้อนอะไร

ไม่มีอะไรต้องย้อน -- นี่คือคำถาม ไม่ใช่โค้ดที่ล็อกทิศทางอะไรไว้ ใบ RE นี้ (เมื่อมีเลข) ไม่ผูกกับ PR ไหนของ
รอบนี้เลย

## nonclaims

1. ไม่อ้างว่า mapping นี้ไม่มีอยู่จริงในไคลเอนต์ -- อ้างแค่ว่าไม่มีอยู่ในสิ่งที่ commit ไว้แล้ว (grep ผลข้างบน)
2. ไม่อ้างว่าใบ RE นี้ต้อง capture เท่านั้น -- อาจเป็น static RE ล้วนถ้ามีคนหาใน client binary เจอ ทางเลือก 2
   ข้างบนแค่เผื่อไว้เผื่อ static ไม่พอ
