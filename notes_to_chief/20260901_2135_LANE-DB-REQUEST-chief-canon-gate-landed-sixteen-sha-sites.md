## 3 โมดูลอยู่ใน PR รอบนี้แล้ว — สัญญาเรียกใช้ตามใบ `1515` (ข.1) ไม่เปลี่ยน + สามข้อที่ต่างจากใบเก่า

`src/pirateforce_foundation/persistence_canon_gate.py` (ใหม่ ในเขตเขียนผม) + เทส 28 ตัว

```
python -m pirateforce_foundation.persistence_canon_gate \
    --db <canonical .db> --migrations <migrations/> --expect-sha <ค่าใน CANON_SHA.txt>
    [--backups-root <ที่เก็บ snapshot ถ้าไม่ใช่ db_backups/ ข้าง ๆ ไฟล์>]
```

`exit 0 UNCHANGED` · `exit 20 EXPLAINED_BY_MIGRATION` · `exit 13 UNEXPLAINED` เหมือนใบเดิมเป๊ะ

**สามข้อที่ต่างจากใบ `1515` ต้องรู้ก่อนต่อสาย:**

1. 🔴 **`NEW_SHA=` พิมพ์เป็นตัวพิมพ์ใหญ่** เพราะห้าไฟล์กลุ่มแรกในตารางข้อ 2 ใช้ `-cne` ซึ่ง
   **case-sensitive** ⇒ ถ้าหมุนค่าตัวพิมพ์เล็กลง `CANON_SHA.txt` รอบถัดไปของห้าไฟล์นั้นจะ abort
   ทั้งที่ฐานข้อมูลไม่ได้เปลี่ยนเลย (ฝั่งอ่านของโมดูลรับทั้งสองแบบ ไม่พังกับไฟล์วันนี้)
2. 🔴 **`NEW_SHA` ไม่ปรากฏในผลลัพธ์ของ exit อื่นเลย** ทางที่ไม่อนุญาตให้หมุนพิมพ์ `ACTUAL_SHA=` แทน
   ⇒ ps1 จะ grep `NEW_SHA=` ตรง ๆ ได้โดยไม่ต้องเช็ค exit ซ้ำ (แต่ควรเช็ค)
3. **`exit 70` = โมดูลเองพัง** (แถวสุดท้ายของตารางใบ `1515`) ตั้งใจไม่ให้ชนกับ 0/13/20 และ
   argparse ใช้ `2` — ทั้งคู่ต้อง ABORT

**เงื่อนไขที่สามของ exit 20 ที่คุณต้องรู้ตอนเขียนจ็อบ ข.2:** โมดูลจะให้ `20` ต่อเมื่อมี snapshot
ที่ `MANIFEST.json` บอกว่าถ่ายจากฐานข้อมูล**ไฟล์เดียวกันนี้** ตอนที่มันมี sha เท่ากับ `--expect-sha`
พอดี **และ snapshot นั้นยัง re-verify ผ่าน** ⇒ ถ้าจ็อบ ข.2 บูตด้วยเส้นทางที่ไม่เรียก
`migrate_with_backup` ผลจะเป็น `13` ไม่ใช่ `20` **โดยตั้งใจ**: การหมุน `CANON_SHA.txt` คือการทิ้ง
บันทึกสุดท้ายว่าฐานข้อมูลเคยเป็นอะไร ทำได้ต่อเมื่อไบต์เดิมยังกู้ได้จริง
