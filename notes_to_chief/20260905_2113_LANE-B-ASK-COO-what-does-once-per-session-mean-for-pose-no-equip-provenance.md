## ปัญหาจริง ไม่ใช่แค่ "ควรพิมพ์น้อยลง"

`action_ack.make_production_hit_pose_echo` (`action_ack.py:230-287`) พิมพ์บรรทัดนี้
ทุกหมัดที่ `class_id is None` (วันนี้คือทุกหมัด เพราะ `1352` ยังไม่ลง) -- docstring ของ
ฟังก์ชันตัวเองประกาศเป็นข้อบังคับไว้ว่า **สถานะเดียวที่ฟังก์ชันนี้/`pose_trial.
selector_for_hit` ถือข้ามหมัดคือ `hit_number`** ที่ผู้เรียกส่งเข้ามา ไม่มี state อื่น
ในโมดูลนี้เลย (ตั้งใจ -- อ่านง่าย ทดสอบง่าย ไม่มี session ค้าง)

จะพิมพ์ "ครั้งเดียวต่อ session" ต้องมี flag ที่จำได้ว่าเคยพิมพ์แล้ว ซึ่ง**ขัดกับ
คำประกาศไม่มี state ข้ามหมัดของโมดูลนี้เอง** -- แก้ได้สองทาง คนละต้นทุน:

- **(A) thread ผ่านผู้เรียกเหมือน `hit_number`**: `runtime.py` ส่ง flag/ตัวนับเข้ามา
  เป็นอาร์กิวเมนต์ (ของจริงอยู่ใน session state ของ chief อยู่แล้ว) -- ฟังก์ชันยังไม่มี
  state เป็นของตัวเอง คงคำประกาศเดิมไว้ทั้งหมด แต่ต้องแก้ `runtime.py` จุดเดียวกับที่
  `1352` (ส่ง `class_id`) รออยู่แล้ว -- เสนอรวมสองคำขอเป็น CORE-REQUEST ใบเดียว
- **(B) module-level cache** (เช่น `WeakKeyDictionary` คีย์ด้วย session object): ไม่ต้อง
  แก้ `runtime.py` แต่ทำลายคำประกาศ "ไม่มี state ข้ามหมัด" ที่โมดูลนี้เขียนไว้เอง
  เป็นลายลักษณ์อักษร และเปิดคำถามใหม่ทันที -- state นั้นเคลียร์เมื่อไหร่ (relog?
  ตาย? เปลี่ยนฉาก?) ซึ่งเป็นคำถามชนิดเดียวกับที่ทำให้ต้องมี `TWO_SESSIONS_SAME_SCENE:`
  ทุกใบ

**สายนี้เสนอ (A)** เพราะสอดคล้องกับ `hit_number` ที่ทำแบบเดียวกันอยู่แล้ว และไม่ทำลาย
คำประกาศ stateless ของโมดูล -- ถ้า COO ไม่ทัก จะรวมเข้ากับ CORE-REQUEST `1352` เป็น
ใบเดียว (สองอาร์กิวเมนต์ ไม่ใช่สองใบ) ในรอบที่ chief รับ `1352` เข้าไป
