## ③ เลน attended — เปิดรอบ unattended ทิ้งไว้ได้ แต่กติกาผลเปลี่ยน

Panya จะส่งรอบเทสเกม **unattended** ทิ้งไว้คืนนี้ **เผื่อจับภาพทัน** และ **จะกลับมาเทสเองวันมะรืน (2026-08-26)**

🔴 **กติกาใหม่ที่ต้องทำตามเป๊ะ — ผลจากรอบ unattended มีค่าไม่เท่ากันสองทาง:**

| ผลที่ได้ | ทำยังไง |
|---|---|
| **เห็นจริง** — ภาพ/วิดีโอแสดงสิ่งที่ใบถาม อ่านออกด้วยตา | ✅ **ปิดใบได้** แนบเฟรม + เวลา |
| ไม่เห็น เพราะ **จับภาพไม่ทัน** | 🔴 ห้ามปิด — ค้าง `NO-RESULT / รอ Panya` |
| ไม่เห็น เพราะ **กล้องแพนไปไม่ถึง** | 🔴 ห้ามปิด — ค้าง `NO-RESULT / รอ Panya` |
| ไม่เห็น เพราะ **น่าจะไม่มีจริง** | 🔴 ห้ามปิด — ค้าง `NO-RESULT / รอ Panya` |

🔴 **"ไม่เห็น" จากรอบ unattended ไม่ใช่ผลลบ — มันคือ "ยังไม่ได้วัด"**
บ้านนี้ถือว่าผลลบมีค่าเท่าผลบวก **แต่กฎนั้นใช้ไม่ได้กับใบชั้น client-observable ที่รันโดยไม่มีคนเฝ้า**
เพราะจุดบอดสองข้อทำให้ "ไม่มีจริง" กับ "มีแต่ไม่เห็น" แยกออกจากกันไม่ได้
⇒ **ห้ามเขียนคำว่า "ไม่มี" หรือ "ไม่เกิด" ลงในผลของรอบ unattended** ให้เขียน **"ไม่พบในรอบนี้ · ยังไม่ได้วัด"**
พร้อมระบุว่าถ่ายอะไรไว้บ้างและกล้องอยู่ตรงไหน

**ผู้ช่วยเขียนกติกานี้ลง `AGENTS.md` §9 แล้ว** (ต่อจากบล็อก "ใบที่ต้องใช้ตาคน") ⇒ ถึงมือผู้เทสโดยไม่ต้องแก้ prompt

# ร่างใบ **RE-056 PLACEMENT-INDEX-CROSSWALK-001** `[STATIC-ON-BRIDGE]`

> chief เป็นคนเปิดใบ (ไฟล์คิวเป็นโซนของ chief) — ผู้ช่วยร่างให้พร้อมงานเตรียมที่ทำไปแล้ว

**ที่มา:** คำสั่ง Panya 2026-08-24 ~01:5x เลือก "ทาง ก." · ต่อยอดจาก GT-053 (PASS: `Bg0002` N=106 · band `0x2000+idx+1`)
และจาก `gamedata\PF_LUA_API_SPEC.md` (สร้าง 2026-08-24)

**หมวด:** `STATIC-ON-BRIDGE` — อ่าน TSV กับไฟล์ Lua ที่ถอดแล้วเท่านั้น · ไม่เปิดเกม ไม่บูตอะไร ไม่มี `LOCK_GAME`
**ไม่มีอะไรให้ดูบนจอเกมแม้แต่อย่างเดียว** · ผู้เทสหน้าจอไม่ต้องทำอะไรกับใบนี้

### objective (claim เดียว)
**เลขที่สคริปต์ส่งให้ `Scene.PlacementOFF(N)` เป็น index ตัวเดียวกับ placement index ในไฟล์ฉาก native
(ตัวที่ band `0x2000 + index + 1` สร้างขึ้นมา) หรือเป็นคนละ namespace**

### 🔴 งานเตรียมที่ผู้ช่วยทำให้แล้ว — อย่าทำซ้ำ

**พื้นผิว `Scene.*` ทั้งหมด (จาก `gamedata\PF_GAMEDATA_LUA_API.tsv`):**

| API | จุดเรียก | arity | รูปพารามิเตอร์ |
|---|---:|---|---|
| `Scene.PlacementOFF` | 173 | 1 | `num` (เลขตรง ๆ 112 จุด · ตัวแปร 61 จุด) |
| `Scene.PlacementON` | 96 | 1 | `var` — **ไม่มีเลขตรง ๆ เลยสักจุด** |
| `Scene.CheckPlacementAlive` | 65 | 1 | `var` |
| `Scene.PlacementCancel` | 32 | 1 | `var` (เลขตรง ๆ 1 จุด = `9`) |
| `Scene.CheckPlacementCombat` | 1 | 1 | `var` |

⇒ ห้าฟังก์ชันนี้เป็น **ระบบเดียวกัน**: เปิด/ปิด/ยกเลิก placement + ถามว่ายังมีชีวิต/อยู่ในคอมแบตไหม
**นี่คือพื้นผิวควบคุม entity ที่ถูกวางในฉาก — ตรงกับสิ่งที่เลน wire กำลังทำอยู่พอดี**

**ค่าที่ส่งให้ `PlacementOFF` แบบเลขตรง ๆ (112 จุด):** `min=13 · max=61 · ค่าไม่ซ้ำ 49 ค่า`
ที่พบบ่อย: 26 (×4) · 27 (×4) · 28 (×4) · 34 (×3) · 35–38 (×3 ต่อค่า)

**ฝั่งไฟล์ฉาก (จาก `gamedata\PF_GAMEDATA_SCENE_INDEX.tsv`):** 289 ฉาก · `max placement_count = 240`
⇒ index สูงสุดที่เป็นไปได้ = **239**

### 🔴 KILL TEST ที่รันไปแล้ว — **ไม่ตาย**

`max(arg) = 61` vs `max(index) = 239` ⇒ ค่าที่สคริปต์ใช้อยู่ในพิสัยของ index ทั้งหมด
**สมมติฐานยังรอด แต่ยังไม่ได้พิสูจน์** (ถ้า `max(arg)` เกิน 239 ใบนี้จะตายตั้งแต่ยังไม่เปิด)
⚠️ อยู่ในพิสัย ≠ เป็นตัวเดียวกัน — เลข 13–61 อยู่ในพิสัยของอะไรก็ได้ที่นับถึง 239 **ห้ามใช้ข้อนี้เป็นหลักฐาน**

### จ็อบ (ตามลำดับ · ห้ามข้าม)

1. **หา crosswalk สคริปต์ → ฉาก** — สคริปต์ที่เรียก `PlacementOFF` ด้วยเลขตรง ๆ อยู่ในฉากไหน
   🔴 **ห้ามเดาจากชื่อไฟล์** · ทางที่น่าจะมี: ตาราง `QUESTDATA_TH__*` / `QUESTTEXT_TH__*` ใน `gamedata\tables\`
   น่าจะมีคอลัมน์ที่ผูกเควสต์กับฉาก · ถ้าหา crosswalk ไม่ได้ = **หยุด รายงาน** (นั่นคือคำตอบที่ใช้ได้)
2. **ทดสอบขอบเขตต่อฉาก** — สำหรับทุกไซต์ที่ resolve ฉากได้: `N < placement_count` ของฉากนั้นหรือไม่
   - **ทุกจุดผ่าน** ⇒ สอดคล้องกับการเป็น index space เดียวกัน (ยังไม่ใช่ข้อพิสูจน์ แต่แข็งขึ้นมาก)
   - **มีจุดใดจุดหนึ่ง `N >= placement_count`** ⇒ 🔴 **คนละ namespace — สมมติฐานตายทันที** แนบไฟล์+บรรทัด+ฉาก+N+count
3. **ยืนยันแบบชี้ตัว (ตัวที่ทำให้ใบนี้เป็นข้อพิสูจน์ ไม่ใช่แค่ความสอดคล้อง)** — เลือกไซต์ที่ resolve ได้อย่างน้อย 3 จุด
   แล้วเปิด `gamedata\scene\<ฉาก>\<ฉาก>.placements.tsv` ที่แถว index = N
   จด `name` / `MOBSET` / template ของแถวนั้น แล้วดูว่า **สคริปต์รอบ ๆ บรรทัดนั้นพูดถึงตัวเดียวกันไหม**
   (เช่นเควสต์ที่ปิดมอนสเตอร์ตัวหนึ่ง แล้วแถวนั้นก็เป็นมอนสเตอร์ตัวนั้นจริง)
   🔴 ต้องมีตัวอย่างจริง ≥3 จุด · **ตรงทั้ง 3 = ข้อพิสูจน์ · ตรงบ้างไม่ตรงบ้าง = รายงานตามที่เห็น ห้าม force**
4. **ผูกกลับไปหา band** — ถ้าจ็อบ 3 ผ่าน ให้ระบุเป็นประโยคเดียวว่า `Scene.PlacementOFF(N)` ชี้ไปที่ entity
   ที่ wire เรียกว่า `0x2000 + N + 1` หรือไม่ · 🔴 **band ยืนยันจริงเฉพาะ `bg0001` (GT-022/048) และ `Bg0002` (GT-053)**
   — ถ้าฉากที่ใช้ในจ็อบ 3 ไม่ใช่สองฉากนี้ ให้เขียนว่าเป็นการ **อนุมานรูปแบบ** ไม่ใช่ของที่ยืนยันแล้ว

### pass criteria — ชั้น static ชั้นเดียว
- ตอบ objective เป็นประโยคเดียวได้อย่างใดอย่างหนึ่ง: `เป็น index เดียวกัน (พิสูจน์ด้วย N ตัวอย่าง ...)` /
  `คนละ namespace (พิสูจน์ด้วย N=... >= count=... ที่ไฟล์ ... บรรทัด ...)` / `resolve crosswalk ไม่ได้ — ตอบไม่ได้จากชุดนี้`
- แนบ sha256 ของทุก TSV/ไฟล์ที่พึ่ง ก่อน-หลัง ต้องตรงกัน
- **ชั้น client-observable: 🔴 ว่างเปล่าโดยเจตนา** — ใบนี้ไม่ผลิตหลักฐานชั้นนี้

### 🔴 ผลลบมีค่าเท่าผลบวก
- **คนละ namespace** = ข่าวใหญ่ ⇒ เลขที่สคริปต์ใช้มาจากตารางอื่น ต้องไปหาว่าตารางไหน · และเตือนว่าอย่าเอา
  เลขฝั่งสคริปต์ไปยัดใส่ band ตอนสร้างเซิร์ฟเวอร์
- **resolve crosswalk ไม่ได้** = ผลที่ใช้ได้ ⇒ จดว่า census ตารางไปถึงไหน แล้วเสนอว่าต้องดูตารางไหนเพิ่ม (ยังไม่เปิดใบใหม่เอง)

### nonclaims (ติดไปกับผลทุกกรณี)
- **สคริปต์ในไคลเอนต์ = สิ่งที่ไคลเอนต์รู้ ไม่ใช่กฎของเซิร์ฟเวอร์ต้นฉบับ** ซึ่งปิดไปแล้ว กู้ไม่ได้ตลอดกาล
- **ไม่พิสูจน์ว่า runtime เรียก `PlacementOFF` จริงตอนเล่น** — พิสูจน์แค่ mapping ของเลขในไฟล์
- **ห้าม join เพราะเลขอยู่ในพิสัยเดียวกัน** — ต้องมี crosswalk field จริง (บทเรียน GT-044)
- **ยังไม่มีใครผูกชื่อ API ฝั่งสคริปต์เข้ากับชื่อข้อความฝั่ง wire ได้สักคู่เดียว** — ใบนี้ก็ไม่ได้ทำข้อนั้น
- ช่องบังคับ: `ค้นใน pf_bridge\external\ แล้ว: ...` · `ค้น gamedata แล้ว: ...`
