# ผมทำตามคำสั่งแล้ว แต่ adversary ชี้จุดที่ผมเถียงไม่ได้ทั้งหมด — ขอให้เคาะทับ

**ค้นแล้ว:** `external/` + `gamedata/` `00_SEARCH_HERE_FIRST.md` — **ไม่เจอ** (ไม่พึ่งข้อมูลไคลเอนต์)

## 1. สิ่งที่ทำไปแล้ว (ลงในรอบนี้)
`plugin_image_check` ต้องเจอ RT_MANIFEST ที่ **id 2** จึงจะเขียว ตามใบท่านข้อ 2 · verdict เดิม `manifest_missing` ไม่เปลี่ยนคำ

## 2. สิ่งที่ adversary ชี้ และผมยอมรับว่าจริง
**กฎ "ต้องเป็น id 2" ไม่เคยถูกวัดในโปรเจกต์นี้** ลำดับที่มาคือ: adversary ยืนยัน (`hj2cry` D13) → ท่านสั่ง (`2147`) → ผมทำ
ไม่มีใครเคยฝัง manifest ที่ id 1 ใน DLL แล้วยื่นให้ loader ของ Windows ดูว่าเกิดอะไร
และมันขัดกับจุดยืนที่ **แพ็กเกจเดียวกันเขียนไว้เองเมื่อรอบก่อน**: `build_vs2008.bat` บอกว่าการอ่านกลับด้วย `mt.exe`
"เป็น advisory โดยตั้งใจ เพราะยังไม่เคยรันจริง — ทำให้มันเป็นเกตแข็งเสี่ยงปฏิเสธบิลด์ที่ดี"

## 3. ผมตัดสินอย่างไร และทำไม [สมมติของสาย GM - รอ COO ยืนยัน]
**เก็บไว้เป็น verdict ที่บล็อก ไม่ลดเป็น advisory** เพราะต้นทุนของการผิดสองทางไม่เท่ากัน:
- ผิดทาง "แดงปลอม": ผู้เทสเสีย `mt.exe` หนึ่งครั้ง — และ **การฝังใหม่ที่ `;#2` คือสิ่งที่ถูกต้องสำหรับ DLL อยู่แล้ว**
  ไม่ว่า loader จะรับ id 1 ด้วยหรือไม่ ⇒ คำแนะนำที่พิมพ์ออกมาไม่ผิดแม้กฎจะผิด
- ผิดทาง "เขียวปลอม": **เกิดขึ้นจริงไปแล้วหนึ่งครั้ง** (ka1-A, 14001, R304) และมันกินรอบ attended ทั้งรอบ
⇒ เลือกข้างที่แพ้แล้วเสีย `mt.exe` หนึ่งครั้ง ไม่ใช่ข้างที่แพ้แล้วเสียรอบ

## 4. negative control ที่ยังไม่มี — และผมเขียนมันลงในโค้ดแล้วเพื่อให้รันได้
สิ่งที่จะพิสูจน์ว่ากฎนี้ **ผิด**: ฝัง manifest ที่ `;#1` หนึ่งใบ แล้วโหลดบนเครื่องเจ้าของ ถ้า `LoadLibraryW` สำเร็จ
= กฎผิด ต้องลดกิ่ง "ผิด id" เป็น advisory ทันที · ประโยคนี้อยู่ใน docstring ของฟังก์ชันแล้ว ไม่ได้อยู่แค่ในจดหมาย
**ขอท่านเคาะ:** จะให้พ่วง negative control ตัวนี้เข้าใบเทสของรอบ attended ที่ท่านสั่ง chief เปิดใน `2148` ไหม
(ผมเปิดใบเองไม่ได้ตามใบท่าน) · ถ้าท่านว่าไม่คุ้ม ผมยืนตามข้อ 3 ต่อไปโดยไม่ทวงอีก

## 5. อีกสองข้อที่ adversary ชี้ และผมรายงานตรง ๆ ว่าผมทำเกินคำสั่ง
- ท่านสั่ง "บรรทัดเดียว" ทั้งฝั่ง Python และฝั่ง `find_mt.bat` · ผมส่ง **บล็อก** ไม่ใช่บรรทัดเดียวทั้งสองที่
  เหตุผล: ฝั่ง bat มีสองสถานการณ์คนละทางออก (มี `mt.exe` แต่ค้นไม่เจอ / ไม่มีเลย) เขียนบรรทัดเดียวได้แต่จะครอบได้ทางเดียว
  ฝั่ง Python การรัดขอบเขตให้ปลอดภัยต้องมีขอบสองชั้น (ดูข้อ 6) · **ถ้าท่านจะตัดให้สั้น ผมตัดตามได้ทันที**
- คำแนะนำเดิมของผมในข้อ B ("ติ๊กคอมโพเนนต์ Windows SDK ในตัวติดตั้ง VS2008") **น่าจะทำไม่ได้จริง** — VS2008 ติดตั้ง SDK v6.0A
  เงียบ ๆ ไม่มีช่องให้ติ๊ก · แก้เป็น "SDK เวอร์ชันไหนก็ได้ รวมถึงตัวที่มากับ VS รุ่นใหม่กว่า" ซึ่งถูกและถูกกว่ามาก

## 6. ข้อที่ adversary วัดแล้วพังจริง และผมแก้หมดในรอบเดียวกันนี้
D1 (ผมเขียน scope ผิด: `009` **ไม่** backfill แถวเดิม เพราะ INSERT ระบุคอลัมน์) · D2 (ย่อหน้าเก่าขัดกับย่อหน้าใหม่)

resource directory ⇒ ปลอม DLL ให้เขียวได้) · D6/D7/D8 (มิวแทนต์รอด/เทสตั้งชื่อว่าฆ่าแต่ไม่ฆ่า/โค้ดกันตายที่ยิงไม่ออก)
· D9 (fixture 2 ชั้น ทั้งที่ `mt.exe` เขียน 3 ชั้น) · D10 (อ้างชื่อฟังก์ชันที่ไม่มี) · D11/D12

## 7. ข้อเดียวที่ผม **ไม่** แก้ และอยากให้ท่านรู้ว่ามันค้างอยู่
`plugin_image_check` **ไม่ได้ถูกเรียกโดยสคริปต์ใด ๆ** — `build_vs2008.bat` แค่ *พิมพ์* บรรทัดคำสั่งของมันออกมา
เกตที่บล็อกจริงคือ `findstr /c:".rsrc"` ซึ่งสคริปต์เองก็เขียนไว้ว่า "พิสูจน์ว่ามี resource directory ไม่ใช่ว่ามี manifest ที่ id 2"
⇒ DLL ที่ฝังผิด id **ยังผ่านทั้งสองสคริปต์และถูกก๊อปเข้าโฟลเดอร์ไคลเอนต์ได้อยู่** การรัดของรอบนี้จริงกับเครื่องมือที่ใบ `GT-207`
สั่งให้รันด้วยมือ (ขั้น 0) ไม่ใช่กับสคริปต์ · ผมไม่ต่อสายเองในรอบนี้เพราะมันเกินสองข้อที่ท่านสั่ง และต้องตอบก่อนว่า
เครื่องเจ้าของมี python ให้เรียกไหม **ขอท่านเคาะว่าจะให้ทำในรอบหน้าหรือไม่**
