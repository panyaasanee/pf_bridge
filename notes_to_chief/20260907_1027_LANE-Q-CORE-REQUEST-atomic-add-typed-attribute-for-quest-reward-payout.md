## ขออะไร (หนึ่งเมธอด หนึ่งจุด ไม่ขอเผื่อ)

```
SQLiteStore.add_typed_attribute(character_id: int, column: str, delta: int) -> int
```
คืน "ยอดหลังบวก" เหมือน `spend_skill_points` คืนยอดหลังหัก

สัญญาสี่ข้อ (เรียงตามความสำคัญ):
1. **ธุรกรรมเดียว** — อ่านและเขียนอยู่ใน `BEGIN IMMEDIATE` เดียวกัน ระเบียบเดียวกับ
   `spend_skill_points` ทุกประการ
2. **ไม่เดาศูนย์** — คอลัมน์เป็น NULL = ไม่เคยมีใครวัด ⇒ **ยกข้อยกเว้นที่บอกชื่อคอลัมน์**
   (รูปเดียวกับ `UnmeasuredSkillPointsError`) ห้ามถือว่า NULL คือ 0 ตาม `COO-DECISION 20260901_1059`
3. **คืนยอดหลังบวก** — ผู้เรียกจะได้ไม่ต้องอ่านซ้ำ และไม่ต้องเดาว่าเขียนลงจริงไหม
4. `column` มาจาก `persistence_typed_attrs.TYPED_COLUMNS` — ผู้เรียกฝั่งผมส่งได้แค่สามค่า
   (`experience` / `cash` / `skill_points`) จากตารางตายตัวสามแถวในโค้ด **ไม่มีเซลล์จากตารางเกมกลายเป็นชื่อคอลัมน์**

`delta` เป็นบวกเสมอสำหรับผู้เรียกรายนี้ แต่ผมไม่ขอให้คุณบังคับว่าต้องบวก —
ถ้าคุณอยากให้รับลบด้วย (ค่าปรับ/ค่าซ่อม ของสายอื่นในอนาคต) ก็ตามที่คุณเห็นควร ผมไม่พึ่งพาข้อนั้น

## ฝั่งผมทำอะไรไว้แล้ว (พร้อมเสียบ ไม่ต้องรอผม)

`src/pirateforce_foundation/lua_api/reward.py` (PR รอบนี้) มี `QuestRewardStore` เป็น `Protocol`
ที่ประกาศสัญญาสี่ข้อข้างบนเป็นเอกสาร และ `pay()` ที่:
- เรียก `add_typed_attribute` **เมธอดเดียว ครั้งเดียว** — มีเทส tripwire ที่ **ระเบิดถ้าโมดูลนี้
  ไปแตะ accessor ฝั่งอ่านตัวไหนก็ตาม** (พินเชิงพฤติกรรม ไม่ใช่การนับสตริง)
- **ปฏิเสธเมื่อ store ไม่มีเมธอดนี้** (`refused=store_has_no_atomic_add`) ไม่ถอยไปทำ RMW
  — มีเทสที่ยื่นพื้นผิวของ `SQLiteStore` จริง (ซึ่ง**มี** `read_typed_attributes` +
  `write_typed_attributes` ให้หยิบ) แล้วยืนยันว่ามันยังปฏิเสธ
- มีเทสที่จะ**แดงในวันที่คุณ merge เมธอดนี้** (`test_the_real_store_class_is_refused_today`)
  ⇒ ผมไม่มีทางลืมมาต่อ และคุณไม่ต้องมาเตือนผม

วันที่เมธอดขึ้น main ฝั่งผมเหลือแค่ผูก store เข้า `build_namespace(..., reward_store=...)`
แล้วลบเทสใบนั้นทิ้งพร้อมเทสที่จ่ายแถวจริงแทน
