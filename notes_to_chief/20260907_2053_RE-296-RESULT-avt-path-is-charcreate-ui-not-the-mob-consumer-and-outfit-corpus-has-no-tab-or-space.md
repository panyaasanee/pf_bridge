## 3. ตัดเส้นทางผิดออกสองเส้น (ประหยัดรอบหน้า)

### 3.1 สำมะโน `lea r,[r+0x108]` ครบทั้ง `.text` — **ไม่มีจุดใดนอกตัวโหลดที่ "ส่งที่อยู่" ของเวกเตอร์นี้**

วิธี: ค้นแพตเทิร์นไบต์ `disp32 = 08 01 00 00` ที่นำหน้าด้วย opcode `8D` (lea) ทั้งเซกชัน `.text` แล้วดิสแอสเซมเบิลยืนยันทีละจุด
ผล: **58 จุด** = **41 จุดเป็น `[esp+0x108]`** (กรอบสแตกของฟังก์ชัน ไม่ใช่ฟิลด์อ็อบเจ็กต์ ตัดออกทันที) + **17 จุดเป็นฐานรีจิสเตอร์** — ตรงกับเลข 17 ของจดหมายรอบก่อนพอดี (คนละวิธีนับ ผลตรงกัน)

17 จุดฐานรีจิสเตอร์ จำแนกครบแล้ว:

| จุด | คำตัดสิน |
|---|---|
| `0x004A1F39` · `0x004A20EF` · `0x004A36CE` | **ตัวโหลด CONSTDATA** (ที่จดหมายรอบก่อนพินไว้แล้ว) |
| `0x00543BEC` · `0x007154AB` | ตัดออกแล้วในรอบก่อน (คนละโครงสร้าง) — ยืนยันซ้ำ |
| `0x009C361F` · `0x009C372D` · `0x009C39E2` · `0x009C456E` · `0x009C4FEE` | ctor/dtor ของคลาสอื่น — `0x009C34B0` เขียน vtable **`0xF53674`** ลงสมาชิกหลายตัว (`+0x108`, `+0x148`, …) แล้วเรียก `0x0079B180` = ลูปทำลาย/สร้างสมาชิก |
| `0x00A4417C` | อยู่ในบล็อกเลขทศนิยม (`fadd`/`fstp`/`movss`/`cvtps2pd`) ของ `0x00A44150` — ไม่ใช่เรคคอร์ดตาราง |
| `0x00B7A635` · `0x00B7A6A6` · `0x00B7A906` · `0x00B7A96C` · `0x00B7D21A` · `0x00B7D320` | ctor/dtor ของคลาสอื่น — `0x00B7A630` เขียน vtable **`0xFBBDBC`** ที่ `[esi]` |

🔴 **สรุป**: **ไม่มีโค้ดเกมจุดใดเลยนอกตัวโหลดที่ทำ `lea` บน `record+0x108`**
⇒ ผู้บริโภคเวกเตอร์ **ต้อง** เข้าถึงผ่าน `mov reg,[record+0x108]` (คัดลอกพอยน์เตอร์ภายในของ vector) ไม่ใช่ผ่านการส่งที่อยู่สมาชิก
⇒ **การกวาดด้วย `lea` ปิดแล้ว** รอบหน้าอย่าเสียเวลากับมันซ้ำ

### 3.2 สตริงพาธ `.avt` ทั้งสามตัว — เป็นของ **UI สร้างตัวละคร** ไม่ใช่ผู้บริโภค `s_OUTFIT` ของมอน

สตริงพาธอวตารทั้งหมดในอิมเมจ (utf-16) และ xref แบบ dword ทั้งอิมเมจ:

| สตริง | VA | xref |
|---|---|---|
| `.\Data\GC\V\%s_%s.avt` | `0x00F18120` | **1 จุด** = `0x004CF551` |
| `.\Data\GC\V\%s_N.avt` | `0x00F1850C` | **1 จุด** = `0x004D1C5B` |

- `0x004CF3F0` (ฟังก์ชันครอบของ `0x004CF551`) ประกอบพาธด้วย `0x00894D20` (sprintf-like) โดยเอา `%s` **สองตัวมาจาก vfunc `+0x124`** ของอ็อบเจ็กต์สองตัว: `[esi+0x40]` และ `[esi+0x18]` แล้วส่งให้ `0x008820D0` ผ่าน singleton `[0x01032EC4]+0x80` · ก่อนหน้านั้นในฟังก์ชันเดียวกันยังประกอบ `%s_%s.dds` (`0x00F1810C`) จาก vfunc ตัวเดียวกัน = **คู่ texture ของพรีวิว**
- `0x004D1B60` (ฟังก์ชันครอบของ `0x004D1C5B`) ทำแบบเดียวกันกับ `%s_N.avt` โดยใช้ vfunc `+0x124` ของ `[esi+0x18]` ตัวเดียว
- ทั้งสองตัวถูกเรียกจาก **dispatcher เดียวกัน `0x004D1CE0`** ซึ่งเทียบ control id ที่ `[edi+8]` กับสมาชิก `[esi+0x20]` / `[esi+0x44]` / `[esi+0x48]` แล้วแตกทาง ⇒ รูปของ **event handler ของหน้าต่าง UI** (สมาชิกคือ handle ของคอนโทรลสามตัว) ไม่ใช่เส้นทาง spawn มอน

🔴 **สรุป**: `%s` ที่เติมลงพาธ `.avt` สองตัวนี้มาจาก **"ข้อความของรายการที่ถูกเลือกในคอนโทรล UI"** (vfunc `+0x124`) **ไม่ได้มาจากเรคคอร์ด `MOBS` และไม่ได้มาจากเวกเตอร์ `+0x108`**
⇒ เส้นทาง `.avt` แบบฟอร์แมตสองตัวนี้ **ไม่ใช่** ผู้บริโภคที่ใบตามหา — ตัดออก

### 3.3 ไม่ใช่ `rand()` ของ CRT

ค้นค่าคงที่ LCG ของ MSVC CRT (`0x000343FD` ตัวคูณ · `0x00269EC3` ตัวบวก) ทั้งเซกชัน `.text` = **0 จุดทั้งคู่**
⇒ ถ้าการเลือก variant เป็นการสุ่ม **มันไม่ได้ใช้ `rand()` ของ CRT**
🔴 **ขอบเขต**: ไม่ได้ตัดความเป็นไปได้ของ RNG ของเอนจินเอง (Mersenne / xorshift / ตัวนับ) — ตัดได้เฉพาะ `rand()` มาตรฐาน

# 6. 🔴 คำตอบของคำถามหลัก — เดินได้ถึงผู้บริโภคจริงในรอบเดียวกัน

## 6.1 ฟังก์ชัน `0x0059A7A0` — ห่วงโซ่ครบจากตาราง `MOBS` ถึงพาธ `.avt`

ทุกบรรทัดข้างล่างเป็นไบต์จริงจากอิมเมจที่พินไว้ (ไม่ใช่การอนุมาน):

```
0x0059A822  push 0x00F0C554            ; L"MOBS"              <- ตัวนี้คือสาเหตุที่ฟังก์ชันนี้เป็นตัวจริง
0x0059A867  push 0x00F1DEFC            ; L"s_ID_MODEL_CLASS"
0x0059A8AE  push 0x00F14FA8            ; L"s_OUTFIT"

0x0059A8BD  call 0x00892050            ; อ่านคอลัมน์ชนิดสตริงของแถวนี้
0x0059A8CA  call ds:0x00C3B438         ; assign -> std::string ที่ frame+0xB8
0x0059A8EA  call 0x008946F0            ; is-empty? ของ frame+0xB8
0x0059A8F4  jne  0x0059ABF5            ;   ว่าง -> ออก (ไม่มีร่าง)
0x0059A902  call 0x008946F0            ; is-empty? ของ frame+0xD4

0x0059A921  lea  ecx, [esp+0xF8]       ; = frame+0xF0   (มี 2 push ค้าง)
0x0059A928  call 0x00434380            ; tokenize -> เวกเตอร์ที่ frame+0xF0
0x0059A943  lea  ecx, [esp+0xF4]       ; = frame+0xF0   (มี 1 push ค้าง)
0x0059A94A  call 0x00435C30
```

## 6.2 ทำไมถึงยืนยันได้ว่า "เวกเตอร์ตัวเดียวกัน" (crosswalk ไม่ใช่การเดาจากตัวเลข)

- ทั้งสามจุด (`0x0059A921` · `0x0059A943` · `0x0059AA41`) ชี้ไปที่ **frame+0xF0 เท่ากันพอดี** หลังหักจำนวน `push` ที่ค้างอยู่ ณ จุดนั้น (2 · 1 · 0 ตามลำดับ)
- ฐานเฟรมเป็นตัวเดียวกันตลอดช่วง พิสูจน์ด้วยตัวแปรสถานะ destructor ที่ถูกเขียนด้วย **ออฟเซ็ตเดียวกัน `[esp+0x158]`** ตลอด: `=3` ที่ `0x0059A8B5` · `=5` ที่ `0x0059A8D4` · `=6` ที่ `0x0059A934` · อ่าน `=8` ที่ `0x0059AA76` ⇒ ไม่มีการขยับฐานเฟรมคั่นกลาง

## 6.3 ทำไม `push 0` ตัวที่สองคือ "เลือก token ตัวไหน"

ถอด `0x00431910` (ตัวเข้าถึงสมาชิก) ทั้งฟังก์ชัน:

```
0x00431910  push esi / mov esi,ecx / ... / push edi
0x0043191A  mov  edi, dword ptr [esp+0x10]      ; = arg2 (push ตัวแรกของผู้เรียก)
0x0043191E  sar  eax, 2                         ; (end-begin)/4 = จำนวนสมาชิก
0x00431921  cmp  edi, eax / jb ...              ; bound check บน arg2
0x00431945  mov  edx, dword ptr [esi+0x10]      ; begin
0x00431948  mov  esi, dword ptr [edx+edi*4]     ; <<< index ด้วย arg2
```

⇒ **`arg2` (คือ `push` ตัวแรกที่ผู้เรียกวาง) คือ index ชั้นนอก** และมันถูก bound-check กับจำนวน token

ตรวจไขว้กับตัวโหลด CONSTDATA ที่จดหมายรอบก่อนพินไว้ — จุดเดียวกัน รูปเดียวกัน:
```
0x004A36A0  sub ecx,...  / sar ecx,2 / xor edi,edi / jbe ...   ; ลูปทุก token
0x004A36B0  push edi                 ; arg2 = ตัวนับลูป  <-- ที่นี่ index เป็นตัวแปร
0x004A36B1  push 0                   ; arg1
0x004A36BA  call 0x00431910
```
ตัวโหลดใส่ **ตัวแปร** (`edi`) ⇒ เก็บทุก token · ผู้บริโภคที่ `0x0059AA52` ใส่ **ค่าคงที่ 0** ⇒ **หยิบตัวแรกเสมอ**

## 6.4 ตัดคำตอบอื่นออก

- **ไม่ใช่ (ข) สุ่ม** — index เป็น immediate `0` ในสตรีมคำสั่ง ไม่มี call ไป RNG ใด ๆ คั่นระหว่าง `0x0059AA41`–`0x0059AA54` · และค่าคงที่ LCG ของ `rand()` CRT ไม่มีในอิมเมจเลย (ข้อ 3.3)
- **ไม่ใช่ (ง) เซิร์ฟเวอร์ชี้** — ไม่มีฟิลด์ใดจากสายเข้ามาแตะ index นี้ ระหว่าง tokenize (`0x0059A928`) กับการหยิบ (`0x0059AA54`) มีแค่การเช็คสตริงว่างและ `0x00435C30`
- อีก 12 xref ของ `%s%s.avt` **ไม่ใช่คู่แข่ง**: ตรวจ 4 จุดตัวอย่าง (`0x005057AF` `0x00559916` `0x005999B8` `0x0059AF92`) ทั้งหมดดึงชื่อจาก `std::string` ที่แก้แล้ว (`c_str()` `ds:0x00C3B484` บน `[esi+0x28]` / `[esp+0xBC]` / ผลลัพธ์ vfunc) **ไม่มีจุดใด tokenize ตอนใช้งาน** ⇒ ไม่มีจุดที่สองที่จะเลือกต่างออกไป

## 6.5 ของแถมที่ไม่ได้ถาม แต่กระทบโค้ดฝั่งเรา

🔴 **ตัวคั่นที่จุดใช้งานคือ `;` ตัวเดียว (`0x00F0C9AC`) ไม่ใช่ชุด `";\t "` (`0x00F14594`) ที่ตัวโหลดใช้** — สองจุดนี้ใช้ตัวคั่นคนละชุดจริง ๆ (คนละ VA คนละสตริง) · บนคลังปัจจุบันไม่มีผล เพราะ 0/3,210 แถวมี tab/space (ข้อ 2) แต่ **ห้ามเขียนโค้ดฝั่งเราโดยสมมติว่าทั้งเกมใช้ชุดตัวคั่นเดียวกัน**

## 6.6 ผลต่อ `BUILD_IMPACT` ที่เขียนไว้ข้างบนในจดหมายฉบับนี้

- ข้อ 2 และ 3 **ยกเลิก**: "ห้ามสรุปว่าเอาตัวแรกเสมอ" ใช้ไม่ได้อีกแล้ว — วัดได้ว่าไคลเอนต์**เอาตัวแรกเสมอจริง**
- ข้อ 3 (ความขัดแย้งกับ `[PROPOSED SAFETY RULE]` บรรทัด 345 ของ `PF_MONSTER_PRESENTATION.md`) **แก้ได้ด้วยหลักฐานแทนการเคาะ**: กฎนั้นเขียนว่า *"do not **infer** original-server selection from token order"* ⇒ ข้อห้ามคือการ **อนุมาน** · รอบนี้ไม่ได้อนุมาน แต่ถอด index ออกมาจากไบต์ ⇒ เสนอให้ COO ปลดรายการ `MONSTER_PRESENTATION@ACTIVE_SELECTION#N` ในส่วนของ **outfit** (ส่วน action/idle ยังไม่ได้แตะ ยังค้างอยู่)
- **สิ่งที่ฝั่งเซิร์ฟเวอร์ทำอยู่วันนี้ถูกแล้ว**: `world_bg000x_identity.py` ทำ `s_OUTFIT.split(';')[0]` = ตรงกับไคลเอนต์ทั้งตัวคั่นและ index

## 6.7 nonclaims เพิ่มเติมของข้อ 6 (ห้ามตัดออก)

1. **ไม่อ้างว่า `0x0059A7A0` คือ "ตัวสร้างมอน" โดยชื่อ** — วัดได้ว่ามันเปิดตาราง `MOBS` อ่าน `s_ID_MODEL_CLASS` และ `s_OUTFIT` ของแถวหนึ่ง แล้วประกอบพาธ `.avt` · **ไม่มี crosswalk field ที่บอกชื่อฟังก์ชัน** ห้ามเติมชื่อเอง
2. **ไม่อ้างว่าไม่มีผู้บริโภคจุดที่สองเลยทั้งอิมเมจ** — ตรวจ xref ของ `%s%s.avt` ครบ 13 จุด แต่**เดินจริง 5 จุด** (จุดที่ตอบ + 4 จุดตัวอย่าง) · อีก 8 จุดอ่านจากรูปแบบเดียวกัน (`c_str()` บนสตริงที่แก้แล้ว) แต่ยังไม่ได้เดินทีละจุด
3. **ไม่อ้างว่า index 0 ใช้กับ `action`/`idle`/`KfFile`** — ใบนี้ถามแค่ `s_OUTFIT` และหลักฐานนี้ครอบคลุมแค่ `s_OUTFIT`
4. **ไม่อ้างว่าเซิร์ฟเวอร์จริงในอดีตทำแบบเดียวกัน** — วัดได้แค่ว่า**ไคลเอนต์ที่เรามี**ทำแบบนี้
