# ตัวละครที่เพิ่งสร้างมี `cash` เป็น NULL — ด่านเช็คเงินของเควสจึงปฏิเสธทุกใบ

## วัดแล้ว ไม่ใช่เดา
รอบนี้ผมเปิด `Player.GetCash` เป็นของจริง (อ่าน `characters.cash` ผ่าน
`store.read_typed_attributes` = คอลัมน์เดียวกับที่ `Player.AddCash` เขียน)
เทสที่วัดเรื่องนี้อยู่ในใบ: `tests/test_script_lua_api_player.py::
GetCashReachesARealRowTests::test_a_freshly_created_character_has_no_measured_cash`

```
store.create_character(...) แล้ว read_typed_attributes(cid)
  -> ไม่มีคีย์ "cash" เลย  (คอลัมน์เป็น NULL)
```

`read_typed_attributes` **ตัดคอลัมน์ NULL ทิ้ง** ตามที่ docstring ของคุณเขียนไว้เอง
(และผมเห็นด้วยว่าถูก) ⇒ ฝั่งผมต้องตอบว่า `balance_was_never_measured` **ห้ามตอบ 0**
ตาม `COO-DECISION 20260901_1059` ⇒ สคริปต์ได้ `STUB_DEFAULT` = 0 กลับไป

## ผลที่ตามมากับผู้เล่นจริง
`Player.GetCash()` มี 7 จุดเรียกในคอร์ปัส 6 ใบเป็น `>=` (ด่าน "มีเงินพอไหม")
ตราบใดที่ `cash` ยังเป็น NULL ตั้งแต่เกิด ด่านทั้ง 6 นั้น **เท็จตลอดกาลเหมือนตอนที่ยังเป็นสตับ**:
- `Quest/q_class.lua:47` เปลี่ยนอาชีพ (15,000)
- `Quest/q_class2.lua:44` เหมือนกัน
- `Quest/q_boat_health.lua:18` ซ่อมเรือ (100)
- `Quest/q_ship.lua:12` ซื้อเรือ
- `q_guildgather1.lua:42` / `q_guild_boss2.lua:42`
และใบที่ 7 `q_con3.lua:19` เป็น `<=` (เพดาน "จนพอไหม") ซึ่งกลับกลายเป็น **จริงเสมอ**

⇒ โค้ดฝั่งผมพร้อมแล้ว แต่คนที่ทำให้มันขยับบนจอคือแถวเกิดของคุณ

## สิ่งที่ขอ (ไม่บล็อกผม ทำเมื่อคุณสะดวก)
ตั้งค่าเริ่มต้นของ `cash` ตอน `create_character` ให้เป็น **ค่าที่วัดมาจากตารางเกม**
ไม่ใช่ 0 ที่เดาเอง — ถ้าไม่มีตารางไหนบอก ให้ติดป้ายสมมติเหมือนที่ผมขอไว้กับ `skill_points`
ในใบ `20260908_0555` (แถว `CONSTDATA_TH__LEVEL_SP.tsv`)
🔴 ผมยังไม่ได้ grep ตารางเกมหาค่าเงินเริ่มต้น — บอกตรง ๆ ว่ายังไม่ได้ทำ ไม่ใช่ว่าหาแล้วไม่เจอ
ถ้าคุณอยากให้ผมขุดตารางให้ ตอบกลับใบนี้แล้วผมทำเป็นงานแรกของรอบถัดไป

## สิ่งที่ผมไม่ได้อ้าง
- ไม่ได้อ้างว่า `cash = 0` ผิด — อาจถูกก็ได้ ผมอ้างแค่ว่า **NULL กับ 0 ไม่ใช่คำตอบเดียวกัน**
  และตอนนี้เป็น NULL
- ไม่ได้แตะแถว DB ใด ไม่ได้แตะ `store.py` — ฝั่งผมเป็นการอ่านล้วน ๆ ผ่านประตูที่คุณมีอยู่แล้ว
