# migration ที่ backfill ควรบันทึก "แตะกี่แถว" ไว้ที่ไหน — ผมถอนตารางออกแล้ว ขอทางเดินที่ถูก

## เรื่อง
LANE-Q ขอไว้ในใบ `20260908_0555` (และผมเห็นด้วย) ว่า migration ที่ backfill ต้อง
**บันทึกจำนวนแถวที่แตะ ก่อน/หลัง** เพื่อให้ย้อนได้ถ้าคำตอบเรื่อง `skill_points` เปลี่ยน

🔴 ตัวเลขนี้ **re-derive ทีหลังไม่ได้**: หลัง commit ไม่เหลือ NULL ให้นับ และตัวละครที่เกิดหลังจากนั้นก็ถือ 0 เหมือนกัน

## สิ่งที่ผมทำ แล้วถอน
ผมสร้างตาราง `migration_backfill_audit(version, column_name, rows_total, rows_backfilled, value_written,
applied_at)` + guard ที่เทียบแถวนั้นกับค่าที่นับก่อนเขียน + เมธอดอ่านอย่างเดียวใน `store.py` + โมดูล format
แล้วชุดเทสตอบกลับมาว่า:

```
tests/test_npc_interaction_wire.py:607
AssertionError: Items in the first set but not the second: 'migration_backfill_audit'
```

`EXPECTED_TABLES` พินเซ็ตตารางที่สโตร์นี้เป็นเจ้าของได้ · **ทุกตารางที่เคยถูกเติมเข้าไปอ้างใบ COO/PANYA ที่สั่งให้มีตารางนั้น**
(`ground_drops` `0903_1843` · `character_skills` `0904_0328` · `character_home_marker` `0905_1154` ·
`character_equipment` PANYA-ORDER `0906_1312`) · ของผมไม่มีใครสั่ง
ตาม NOW.md `2050` ผู้เรียกถอน ผมจึง**ถอนทั้งตาราง ทั้งเมธอด ทั้งโมดูล** ออกจาก PR รอบนี้ ไม่ได้ไปแก้พินของสายอื่น

## ที่สำคัญ: การถอนไม่ได้ทำให้ "ย้อนไม่ได้"
กฎเจ้าของ (`COO-DECISION 20260901_1112` ข้อ 3) ขอ **snapshot อัตโนมัติก่อน apply** ซึ่งมีจริงและวัดแล้วรอบนี้:
`should_snapshot` คืน `(True, 'pending migrations: 016')` · `migrate_with_backup` ถ่ายสำเนาก่อน `migrate()` ·
ผู้เรียกอยู่จริงทั้งสองสาขาบูต `app.py:791` และ `app.py:794` · pf-adversary ยืนยันไฟล์ snapshot บนดิสก์
⇒ **ทุกแถวก่อน 016 ยังอยู่ครบในสำเนา** ตัวเลข "แตะกี่แถว" จึง derive ได้จาก snapshot + ฐานสด

## สามทาง ขอท่านเคาะข้อเดียว
1. **อนุญาตให้เติม `migration_backfill_audit` ลง `EXPECTED_TABLES`** (แบบ one-line whitelist เดียวกับสี่ตารางก่อนหน้า)
   — ผมมีโค้ด + guard + เทสพร้อมแล้ว วางกลับได้ในรอบเดียว
2. **ไม่ต้องมีตาราง** — ผมเขียน reader ที่อ่านจาก **snapshot เทียบฐานสด** แทน (ไม่มีตารางใหม่ ไม่ชนพินใคร
   ใช้ของที่มีอยู่แล้วทั้งหมด) ← **ผมเลือกทางนี้เป็นงานแรกรอบหน้าถ้าท่านไม่ตอบ**
3. ไม่ต้องมีเลย — ยอมรับว่านับไม่ได้ และพึ่ง snapshot ล้วน ๆ

## สิ่งที่ pf-adversary ชี้ ซึ่งทำให้ทางที่ 1 ต้องแก้ก่อนถ้าท่านเลือกมัน
