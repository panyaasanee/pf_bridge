## 3. ต้นเหตุ และแพตช์ที่เสนอ (สาย DB เป็นเจ้าของโค้ด ผมไม่แตะเขตเขา)

`#605` ทำให้ล็อกอิน **เซ็ต `movement_speed` ในหน่วยความจำจากแถวจริง** (`LOGIN_SPEED from_row value=400.0`)
แต่แถวที่ `store.get_character()` คืนยังเป็น `None` ⇒ ค่าคงตัวเดิมของใบเทสข้างเคียง
"ล็อกอินต้องไม่เปลี่ยนฟิลด์ใดของ `selected`" **เป็นเท็จโดยตั้งใจแล้ว** แต่ใบเทสนั้นไม่ได้ถูกอัปเดตในคอมมิตเดียวกัน

สองทางที่ผมเห็น — **สาย DB เท่านั้นที่ตอบได้ว่าอันไหนถูกต้องตามเจตนา**:
- **ก. ถ้าค่าควรอยู่ในหน่วยความจำเท่านั้น**: แก้ใบเทสให้เทียบทุกฟิลด์ **ยกเว้น `movement_speed`** พร้อมคอมเมนต์
  ว่า `#605` ทำให้ล็อกอินเป็นผู้เขียนฟิลด์นี้โดยตั้งใจ (การ์ดอื่นของใบยังต้องอยู่ครบ ห้ามลบทั้งเทส)
- **ข. ถ้าค่าควรถูกเก็บด้วย**: ให้ล็อกอินเขียนกลับลงแถว แล้วใบเทสเดิมกลับมาเขียวเองโดยไม่ต้องแก้
🔴 ผมเดาแทนไม่ได้ และ **ห้ามตัวเองแตะ** — เขตของสาย DB · แต่ใครก็ตามที่หยิบ ควรใช้เวลาไม่กี่นาที ไม่ใช่ทั้งรอบ

## 4. สาย B ทำอะไรไปแล้วในรอบนี้

- push ครบทั้งสองรีโป งานไม่หาย (`pf_bridge` PR #902 · เซิร์ฟเวอร์ branch `claude/lucid-gauss-di7ers`)
- **กัก PR ฝั่งเซิร์ฟเวอร์ไว้เป็น draft โดยเจตนา** เพราะ `merge-claude-pr.yml:301` ข้าม draft
  (`[ "$DRAFT" = "false" ] || skip`) ⇒ ยังไม่ถูกปิดทิ้งขณะที่ main แดง · reaper จะปลด draft เองที่ 45 นาที
  (`PF_STALE_MINUTES: 45`) ⇒ **ถ้าถึงตอนนั้น main เขียวแล้ว รอบนี้รอด ถ้ายังแดง คำตัดสินนั้นเป็นของ main ไม่ใช่ของใบผม**
  marker `PF-AUTOMERGE: v4` อยู่ใน body ตั้งแต่เปิดใบ ตามลำดับจบรอบ (marker ก่อนปลด draft เสมอ)
- แจ้งเจ้าของผ่านช่องทางที่เธอเห็นจริงแล้ว (push notification) เพราะเรื่องนี้บล็อกทุกสาย ไม่ใช่แค่สายเดียว
