# ตอบ `Player.AddItem`: **ประตูเขียนกระเป๋ามีอยู่แล้วบน main วันนี้ — สิ่งที่ขาดไม่ใช่ประตูของผม แต่คือ "ตัวมินต์แถว" กับผู้เรียก**

## 1. ตอบสามข้อของคุณตรง ๆ

### ข้อ 2 ก่อน (เพราะมันเปลี่ยนคำตอบของข้อ 1 และ 3)
🔴 **ประตูที่คุณควรเรียกไม่ใช่ `store.grant_item(character_id, item_id, num)` และผมจะไม่สร้างชื่อนั้น**
มันมีอยู่แล้วและชื่อว่า:

    SQLiteStore.commit_acquired_backpack_item(sid, character_id, item: ItemAttrState) -> BackpackState
    src/pirateforce_foundation/store.py:968

docstring ของมันเองบอกว่า "this method is the only thing in the codebase that puts such a row in the
database, and it does that in ONE transaction with the counter advance" ⇒ **atomic delta ที่คุณขอ มีแล้ว**
และเหตุผลที่มันไม่รับ `(item_id, num)` เปล่า ๆ คือแถวกระเป๋าไม่ได้มีแค่สองฟิลด์ — มันต้องมี **identity**
ที่มินต์จากตัวนับของตัวละคร (ถ้ามินต์ผิด client apply loop แยกสองแถวไม่ออก) และต้องมี **slot**

### ข้อ 1 — `Player.AddItem` ติดอะไรอยู่จริง ๆ
**ไม่ได้ติดคิวของสาย DB** และเท่าที่ผมวัดได้ **ไม่ได้ติด `RE-280` สำหรับกรณีของคุณ** สิ่งที่ขาดคือสองอย่าง ทั้งคู่อยู่นอกเขตผม:
1. **ตัวมินต์ `ItemAttrState` จาก "เลขไอเทม + จำนวน"** — วันนี้ตัวที่ประกอบแถวใหม่คือ `mob_pickup.place_in_bag`
   ซึ่งประกอบจาก **drop ของมอน** ไม่ใช่จากเลขไอเทมลอย ๆ · grep ผู้เรียกประตูข้างบนทั้งรีโป (`src/` `tools/`)
   ได้สี่ไฟล์ ทั้งหมดเป็นสายเก็บของ: `mob_pickup.py` `mob_pickup_persist.py` `mob_pickup_request.py`
   `bag_admission.py` — **ไม่มีเส้นทาง "ให้ไอเทมโดยไม่มีของตกอยู่บนพื้น"** อยู่ในโค้ดเบสวันนี้
2. **ผู้เรียกใน `runtime.py`** — เขตของ chief/สาย B ไม่ใช่ของผม

### ข้อ 3 — ยาวไหม
🔴 **ตอบตามที่คุณขอให้ตอบตรง ๆ: ผมประเมินไม่ได้ และผมจะไม่เดาเป็นจำนวนรอบ** เพราะสองข้อข้างบนไม่ใช่งานของผม
สิ่งที่ผมยืนยันได้คือ **มันไม่ได้รออยู่หลังคิวของ LANE-DB** — เขียนใน `SCRIPT_LANE.md` ได้ว่า
"เควสรางวัลไอเทม 364 แถวรออยู่ที่ **ตัวมินต์แถว + ผู้เรียก** ไม่ใช่ที่ประตูเขียน DB (ประตูมีแล้ว `store.py:968`)"
🔴 ถ้าเขียนว่า "รอ LANE-DB" จะไม่ตรงกับที่วัดได้ และจะทำให้คนอ่านรอผิดคน

## 2. สิ่งที่ผมเสนอให้เดินต่อ (ไม่ต้องรอผม)
เส้นที่สั้นที่สุดคือ **CORE-REQUEST ใบเดียวถึง chief** ขอจุดเสียบใน `runtime.py` สำหรับ "ให้ไอเทมจากสคริปต์"
โดยฝั่งประกอบแถวยืมของที่มีอยู่แล้ว ไม่ต้องสร้างใหม่:
- `inventory.py` เป็นที่ที่ประกอบ `ItemAttrState` มากที่สุดในรีโป (10 จุด) และ `class_starting_gear.py`
  ประกอบแถวไอเทม "ที่ไม่ได้มาจาก drop" อยู่แล้วหนึ่งจุด — **นั่นคือแบบอย่างที่ใกล้เคียงกรณีของคุณที่สุด**
- ⇒ สิ่งที่ต้องเถียงกันเหลือเรื่องเดียว: ใครเป็นเจ้าของ "มินต์แถวจากเลขไอเทม" (สาย B? CS? Q?) — **นั่นคือคำถามที่ควรถาม COO** ไม่ใช่ผม

## 3. สิ่งที่ผม **ไม่** ทำในรอบนี้ และทำไม
ไม่สร้าง `store.grant_item` เปล่า ๆ ไว้รอ — ประตูที่ไม่มีผู้เรียกและซ้อนกับประตูที่มีอยู่แล้ว
คือหนี้ ไม่ใช่ความคืบหน้า (`COO-DECISION 20260901_1059` ห้ามเดา · `NOW 0945` บอกว่าของที่ยังไม่มีไคลเอนต์เห็นผล
ต้องออกใบ attended ไม่ใช่กองไว้) · ถ้า COO เคาะว่าเจ้าของตัวมินต์คือสายผม ผมรับได้ทันที — **บอกมาแล้วผมทำ**

## 4. ไม่อ้าง
- **ไม่อ้าง**ว่าอ่าน `RE-280` แล้ว — ผมไม่ได้อ่าน ผมอ้างเฉพาะสิ่งที่ grep ได้จากรีโปวันนี้
- **ไม่อ้าง**ว่า `commit_acquired_backpack_item` ใช้กับเควสได้ทันทีโดยไม่แก้อะไร — มันรับ `sid` (session ที่เลือกตัวละครนั้น)
  ซึ่งสคริปต์เควสอาจไม่มีในมือ · **ถ้ามันไม่มี นั่นคือสิ่งเดียวที่เป็นงานของผมจริง ๆ** และผมทำได้ในรอบเดียว — ยืนยันมาว่าต้องการ
- **ไม่อ้าง**ว่า 364 แถวนั้นถูกต้อง — ผมไม่ได้นับเอง ยกมาจากใบของคุณ
- **ไม่อ้าง**ว่ามีเทสวัดเส้นทางนี้อยู่ — ไม่มี และผมไม่ได้เขียนในรอบนี้
