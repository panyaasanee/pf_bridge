# COO-DECISION — ตัวละครที่ยังไม่เกิด: เขียน vitals ตอน `create_character` (ทาง ข) ไม่ใส่ DEFAULT ในสคีมา (ทาง ก)

## ตัดสินว่าอะไร
1. **ทาง ข** — ค่า `level=1, hp_current=100, hp_max=100` ต้องถูกเขียนลงแถวตอนสร้างตัวละคร ผ่านฟังก์ชันเดียว
   `new_character_vitals()` ใน `persistence_vitals.py` (เขตของคุณ) ที่คืนสามค่านี้พร้อมป้าย TRANSCRIBED เดียวกับ `007`
   จุดเสียบใน `create_character` (`store.py:232` เพิ่มสามคอลัมน์ใน INSERT) เป็นของ **chief** — สั่งแยกใบแล้ว
2. **ห้ามทาง ก** — DEFAULT ในสคีมาต้อง rebuild ตาราง และฝังเลข "OPEN" ไว้ในสคีมาถาวร วันที่ RE พบค่าจริงจะต้อง rebuild อีกรอบ
   ทาง ข แก้ที่เดียวบรรทัดเดียว
3. **อนุมัติสิ่งที่แคบกว่าใบ `0250` ทั้งสองจุด** — คู่ HP ยิงพร้อมกันเท่านั้น และกัน `level = 0` ออกจากคู่ HP
   ไม่ต้องแก้กลับเป็นสามคำสั่ง แถวที่ถูกเว้นไว้ = fail-closed ถูกต้องแล้ว
4. **กฎใหม่ `level = 0` ปฏิเสธ** — `persistence_vitals.require()` ต้องปฏิเสธ `level = 0` เหมือน `hp_max = 0`
   เป็นการปิดให้แน่นขึ้น ไม่ใช่เปลี่ยนพฤติกรรม ⇒ อยู่ในอำนาจสาย ทำพร้อมเทสหนึ่งตัว
5. ประโยค "M4 ปลดล็อกแล้ว" ใช้ได้เฉพาะตัวละครที่มีอยู่ตอน `007` รัน จนกว่าข้อ 1 + จุดเสียบของ chief อยู่บน main
