คำว่า `manifest` ที่เจอในนั้นคือ build manifest ของสะพานเอง (`PF_V4_MANIFEST.md`) ไม่ใช่ `RT_MANIFEST` ของ Windows

## 1. (ก) รัด RT_MANIFEST เป็น id 2 — ลงแล้ว
`gm/plugin_image_check.py` เดินลง subdirectory ของ type entry 24 แล้ว **ต้องเจอ id 2** จึงนับว่ามี manifest
(`ISOLATIONAWARE_MANIFEST_RESOURCE_ID` — id ที่ activation context ของ DLL สร้างจากมันตัวเดียว)
- `PeFacts.manifest_resource_ids` เก็บ id ที่เจอ ⇒ ข้อความบนจอแยกสองรูปได้จริง:
  "ไม่มี manifest เลย → rebuild ด้วย revision 5" กับ "มีที่ id 1 → ฝังใหม่ที่ `;#2`" (ใส่คำสั่งเต็มให้เลย)
- โทเคนคอนโซลเพิ่มเป็น `embedded_manifest=no manifest_ids=1` ⇒ **แยกสองรูปได้จาก log อย่างเดียว**
- **ไม่แตะคำ verdict** — ยังเป็น `manifest_missing` ตัวเดิมที่ใบ `GT-207` อ่านอยู่ คำศัพท์ของใบไม่ขยับสักคำ
- type entry ที่ไม่มีชั้น id (ชี้ตรงไป data) = ไม่นับ · `mt.exe` ผลิตรูปนั้นไม่ได้ และ loader ไม่มีอะไรให้จับคู่

🔴 **ที่ท่านต้องอ่านก่อนเชื่อผม — ทำไมนี่ไม่ใช่ false red ตัวใหม่:**
DLL ตัวเดียวที่ **มีคนวัดว่าโหลดได้จริง** บนเครื่องเจ้าของ (ka1-A, `GT-207` build 1, 18:54) ถูกฝังด้วย
`mt.exe -manifest GameMaster.dll.manifest -outputresource:GameMaster.dll;#2` = **id 2**
และ `build_vs2008.bat` revision 5 ฝังที่ `;#2` อ่านกลับที่ `;#2` ⇒ **ทุกเส้นทางที่มีคนเดินจริงยังเขียวเหมือนเดิม**
ที่กลายเป็นแดงคือ hand-embed ผิด id ซึ่ง **แดงอยู่แล้วตอนโหลด (14001)** เราแค่เลิกรายงานว่ามันเขียว

**nonclaim:** อ่าน resource *tree* ไม่ได้อ่าน *เนื้อ XML* · entry ที่ id 2 แต่ประกาศเวอร์ชัน assembly ผิดยังนับว่า "มี"
ไม่มีใครวัดรูปนั้น จึงไม่มี verdict ไหนอ้างถึง · และโมดูลนี้ยังไม่เคยรันกับ `GameMaster.dll` จริงในโคลนนี้
