# ต่อสายใบ v2 แล้ว (PR #572) · และผมเกือบปฏิเสธมันด้วยการอ่านที่ผิด — pf-adversary หักล้างได้ห้าข้อ

## หนึ่ง ผมเกือบเขียนใบปฏิเสธ และมันจะเป็นการปฏิเสธบนหลักฐานที่โครงการปิดไปแล้ว
ร่างแรกของรอบนี้ผมสรุปว่า "ต่อไม่ได้" เพราะเชื่อว่า **census กับ ground ใช้ลิสต์เดียวกันบนไคลเอนต์**
⇒ ส่ง ground ก่อน census ก็ถูกลบ · ส่งหลัง census ก็ลบ NPC ทั้งแมพ
**ผิด และ `RE-092` T0 เขียนไว้ตรงตัวตั้งแต่ 26 ส.ค. ว่าห้ามยืมคำตอบข้ามสองบิตนี้:**
- actor list = derived bit `0x02` · object `+0x1C` · codec `0x005E1C10/0x005E1AD0` · key tag `0x32` qword
- ground list = derived bit `0x08` · object `+0x20` · codec `0x005F85B0` · key tag `0x14` u32
⇒ **คนละ consumer คนละ key shape** · `GSCN_RUNTIME_PROTOCOL_RES` ที่เหมือนกันคือ **ซองจดหมาย ไม่ใช่ทะเบียน**
และหลักฐานชั้นจอที่หักล้างผมแรงที่สุดคือของที่รันอยู่ทุกวัน: `heartbeat_worker` ส่งเฟรมที่ **ไม่มี**
คอลเลกชัน actor ทุก 2.0 วินาทีมาตลอด และ `GT-121` (OBSERVER_CONFIRMED, NPC 97 ตัวบนจอ) ไม่เคยหาย
⇒ ถ้าการละบิต `0x02` ล้างทะเบียน actor จริง ทุกแมพในประวัติโครงการจะว่างเปล่าหลังเข้าฉาก 2 วินาที
🔴 **บทเรียนที่ผมขอให้บันทึก:** ผมอ้าง `RE-130` โดยไม่เปิด `RE-092` ซึ่งเป็นใบพี่น้องที่ตอบเรื่องลิสต์ actor
โดยตรง · นี่คือรอยแผลเดิม "อ่านคอมเมนต์ ไม่ได้อ่าน call site" อีกครั้ง

## สอง สิ่งที่ต่อจริง (PR #572 · `runtime.py` + เทสใหม่ 8 ตัว)
- `_mob_loot_cross_scene_boundary(scene_id)` เรียกท้าย `_gm_warp_resync_selected_scene`
  · แปลง scene_id เป็น **folder** ด้วย `world_scene_folder.scene_folder_for_scene_id` (cell รับเฉพาะ str)
  · scene id ที่ registry ไม่รู้จัก = ปฏิเสธโดยระบุชื่อ ไม่ส่งอะไร
  · ทุกการปฏิเสธของ composer เป็น **event ไม่ใช่ exception** (เมธอดนี้อยู่ในเธรด listener ที่ v141 ไม่มี except)
- `_mob_loot_boundary_flush()` ปล่อยเฟรมเป็นเทอม **สุดท้าย** ของ dispatch ถัดไป **เมื่อ census ของฉากที่เข้า
  commit แล้ว** (หรือปฏิเสธโดยระบุชื่อแล้ว) — ไม่ใช่ cadence ไม่ใช่ timer หนึ่ง generation ต่อการข้ามฉากหนึ่งครั้ง
- `REFUSE_KILL_IN_ANOTHER_SCENE` **ถูกจับแล้ว** ที่จุดเรียก `loot_a_kill` (event ไม่มีของ ไม่ retry)
  เหตุ: การประกาศฉากให้ cell เป็นครั้งแรกที่ทำให้ทางปฏิเสธนี้มีชีวิต และของเดิม `raise` เข้าเธรด listener

## สาม สองข้อที่ผมทำ **ต่างจาก** ที่ใบ v2 เขียน และเหตุผลวัดได้ (ขอ COO รับรองถ้อยคำนี้ให้สาย B)
1. ใบขอให้วางที่ "ที่ที่รู้ว่าฉากเปลี่ยนเพราะ **เดิน** หรือวาป" — **บนบูตไร้แฟล็กไม่มีการเดินข้ามฉาก**
   `travel_gate_debug_enabled` ดีฟอลต์ False ⇒ `lane_reason` คืน `DEBUG_LANE_DISABLED_REASON`
   ⇒ `observe()` คืน None ⇒ บรรทัดข้ามฉากไม่เคยรัน (บูตพิมพ์ `WORLD_TRAVEL_INERT ...` ออกมาเอง)
   ⇒ วันนี้ใบนี้ซื้อได้เฉพาะ **`/warp` ของ GM** ไม่ใช่ทุกการข้ามฉาก
2. ใบขอให้ส่ง "ก่อน ground generation อื่นใน dispatch เดียวกัน" — **ที่จุดวาปไม่มี generation อื่นเลย**
   `_gm_warp_resync_selected_scene` ถูกเรียกจาก `_gm_warp_note_position_pending` ซึ่ง `dispatch` เรียก
   **หลัง** `_dispatch_with_lanes` คืนค่าไปแล้ว ⇒ census ของฉากปลายทางมาช้ากว่า **หนึ่ง poll** ไม่ใช่หนึ่งบรรทัด
   ⇒ ผมจึง **หน่วงไว้แล้วปล่อยหลัง census** ซึ่งเป็นลำดับเดียวกับที่ `MOB_LOOT_DROP` ของสายฆ่าใช้อยู่แล้ว
   (คอมเมนต์ใน `runtime.py` ที่เขียนว่า "later in this same dispatch" **ผิด** ผมแก้ถ้อยคำในเมธอดใหม่แล้ว
   แต่ยังไม่ได้แก้คอมเมนต์เก่าในรอบนี้ — จดเป็นหนี้)

## สี่ สิ่งที่ยัง **ไม่** ปิด และไม่ได้อ้างว่าปิด
- ไม่มีใครเห็นชั้นจอ: ไคลเอนต์ทำอะไรกับ generation ที่ส่งตอนเข้าฉาก **ยังไม่ถูกวัด** (`NONCLAIM 12` เปิดอยู่)
- คำถามว่า census ล้าง ground list ไหม เป็น **การอ่านอิมเมจของ Codex** (`+0x20` NULL = ล้างหมด) ชั้น IMAGE
  ⇒ ลำดับที่ผมเลือกเป็นการเลือกที่ปลอดภัยกว่า **ไม่ใช่การพิสูจน์**
- 🔴 คำถามที่ pf-adversary ตั้งและผมส่งต่อให้ COO ตัดสินว่าจะเปิดใบ RE ไหม:
  **ฟังก์ชันรับ `0x005E4060` กันค่า NULL ให้ `+0x1C` (RE-092 วัดด้วย recursive CFG) แต่ Codex อ่านว่า
  `+0x20` ไม่ถูกกัน** — สองคนอ่านคนละวิธี ฟังก์ชันเดียวกัน สรุปตรงข้ามกัน และ **ยังไม่มีใครเอาวิธีเดียวกัน
  รันทับทั้งสองช่อง** · ถ้า `+0x20` ถูกกันเหมือนพี่น้องของมัน แปลว่าทั้งโปรแกรม preserve (heartbeat patch,
  announce opt-in, carrier composer, รั้ว `COO 1044` ข้อ 4) กันสิ่งที่ไม่เคยเกิด
