# เจ้าของบรรทัดเขียว "ได้รับ" = **LANE-B** (จุด commit เข้ากระเป๋า) · UI ส่งโคเดกให้ ไม่ต้องยื่น CORE-REQUEST

## ตัดสินอะไร
1. **เจ้าของงาน = LANE-B** · บรรทัดเขียวต้องเกิดที่จุดเดียวกับที่ไอเทมถูก commit เข้ากระเป๋า
   (`store.commit_acquired_backpack_item`) ซึ่งผู้เรียกทุกตัวอยู่ใน `mob_pickup*.py` ของ B
2. **UI ไม่ต้องยื่น `CORE-REQUEST`** สำหรับเรื่องนี้ (คิว CORE-REQUEST ค้าง 6 ใบแล้ว) · สิ่งที่ UI ส่งให้ B คือ
   **โคเดกที่พิสูจน์แล้ว**: `inventory.make_item_move_delta_response` ทรง BAGUPD ถือยอดรวมใหม่ของสล็อต
   ตามโมเดล `$V2` ที่ `GT-063` ปิดไปแล้ว — ส่งเป็นจดหมายถึง B พร้อมชื่อฟังก์ชัน/ทรง/ค่าที่ต้องใส่ ไม่ต้องแตะโค้ด B
3. **`NOW.md` แก้แล้วรอบนี้**: ท่อ promotion เขียนว่า `item_operate_res` = **รอ seam ของ LANE-B** ไม่ใช่ "UI ปลดได้"
4. **ห้ามประดิษฐ์จุดยิงใหม่ใน UI** เช่นยิงบรรทัดเขียวตอนลากของในกระเป๋าตัวเอง — นั่นผิดความหมายของบรรทัดนั้น

## เพราะอะไร

⇒ ปลดแฟล็กเดี่ยว ๆ ผู้เล่นไม่เห็นอะไร · เจ้าของเหตุการณ์คือคนที่ถือเส้นทาง pickup ไม่ใช่คนที่ถือโคเดก
