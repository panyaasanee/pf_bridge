## `CORE-REQUEST-GM-051` — `GM_WARP_POSITION_CONFIRMED` ยิงจากก้าวเดินของผู้เล่นเอง
- **โมดูล**: `runtime.py` (`_gm_warp_note_position_pending` / ตัวพิมพ์ `GM_WARP_POSITION_CONFIRMED`)
- **จุดในรันไทม์**: ตัวที่ arm เมื่อมี action วาปเข้าคิว และตัวที่พิมพ์โทเคนเมื่อมี TargetPos ถัดไป
- **อาการที่วัดได้** (pf-adversary รอบ `07kjfd` ข้อ D3): ล็อกอินสดในฉาก 1 ยืนตรงจุด spawn ที่ pin ไว้พอดี
  (`(-9239.957, -2830.045, 223.292)` ทั้งคู่) → `/warp 1` → ก้าวเดียว 1 หน่วย ⇒ คอนโซลพิมพ์
  `GM_WARP_POSITION_CONFIRMED` **แล้วตามด้วย** `GM_WARP_POSITION_TARGET_MISMATCH` บรรทัดติดกัน
  ⇒ อินพุตที่ทำให้โทเคน "ยืนยัน" ติดทั้งที่ฟีเจอร์ไม่ได้ทำอะไรเลย: วาปที่เป้าหมาย = แถวปัจจุบัน + ก้าวหนึ่งก้าว
- **ทำไมเพิ่งโผล่**: ก่อนรอบนี้ วาปในฉากเดิมแบบไม่มีพิกัดไม่เคยเข้าคิว action ⇒ ตัว arm ไม่เคยติด
- **เกณฑ์ที่ขอ**: โทเคน `CONFIRMED` ต้องแปลว่า "แถวขยับไป**ถึงจุดที่สั่ง**" ไม่ใช่ "แถวเปลี่ยน"
  และสองโทเคนต้องไม่พิมพ์พร้อมกันได้ (ตอนนี้ขัดกันเองบนบรรทัดติดกัน)
- **เทสที่พิสูจน์**: fixture วาปที่ target == ตำแหน่งปัจจุบัน + TargetPos ห่าง 1 หน่วย ⇒ ต้อง**ไม่**ได้ `CONFIRMED`
  · และเคสวาปที่ target ต่างจริง + TargetPos ถึงเป้า ⇒ ต้องได้ `CONFIRMED` (มิวแทนต์ที่คืนของเดิมต้องแดง)

## `CORE-REQUEST-GM-052` — หน้าต่างผ่อนผัน move-authority ซื้อได้ด้วยวาปที่ไม่ขยับใคร
- **โมดูล**: `runtime.py` (`_move_authority_note_server_moves`, ราว `:4085`)
- **จุดในรันไทม์**: กฎที่เปิดหน้าต่างผ่อนผันจาก **สตริงย่อย** `TELEPORT` ใน label ของ action ที่เข้าคิว
  โดยไม่เทียบกับเป้าหมายที่สั่งเลย
- **อาการที่วัดได้** (ข้อ D4): บนซีนาริโอ opt-in `/warp <ฉากของตัวเอง>` เพิ่ม
  `move_authority_hypothesis_grace_reopened_after_server_teleport` แล้วรายงานถัดไปที่กระโดด
  **180,000 หน่วย** กลับมาเป็น `move_authority_hypothesis_teleport_grace_admitted` และ**ถูกเขียนลงแถวจริง**
  รวมกับ D3 (เป้าหมาย = ตำแหน่งปัจจุบัน) ⇒ วาปที่ไม่ขยับอะไรเลยก็ซื้อใบผ่านประตูความเร็วได้
- **ระดับ**: ปานกลาง ไม่ใช่วิกฤต — ต้องเป็นบัญชีใน `gm_accounts` และซีนาริโอเป็น opt-in
  แต่มันคือ **ประตูที่อ่อนลงเพราะรอบของผม** และไม่มีเทสตัวไหนเรียกชื่อมัน
- **เกณฑ์ที่ขอ**: หน้าต่างผ่อนผันต้องผูกกับ**เป้าหมายที่สั่ง** (ระยะจาก `gm_last_warp_target`)
  ไม่ใช่กับสตริงย่อยใน label · วาประยะศูนย์ต้องไม่เปิดหน้าต่าง
- **เทสที่พิสูจน์**: วาประยะศูนย์ + รายงานกระโดดไกล ⇒ ต้องถูกปฏิเสธ · วาปข้ามฉากจริง + รายงานที่ปลายทาง ⇒ ต้องผ่าน
