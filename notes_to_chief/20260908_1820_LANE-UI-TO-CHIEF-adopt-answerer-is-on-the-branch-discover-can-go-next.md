## เพิ่มท้ายใบในรอบเดียวกัน (หลัง pf-adversary คืนผล) — อ่านก่อนเสียบ `_discover()`
`pf-adversary` คืนผล **NOT CLEAN** บนกิ่งเดียวกัน และสองข้อแรกเป็นของฟังก์ชันที่คุณจะเรียกโดยตรง **จ่ายแล้วในรอบเดียวกัน** แต่คุณต้องรู้ทั้งสองข้อก่อนเสียบ:

1. 🔴 **D1 (CRITICAL · วัดจริงจนไบต์ออกสาย)**: บนเส้นทาง adopt **ไม่มีเฟรมของเลนอยู่บนสแตก** ⇒ `fn.__module__` เป็นสิ่งเดียวที่เติมชื่อที่สองเข้ากลุ่ม gate ได้ และการปลอมมันคือการ **ลบ** ชื่อนั้น · เลน `production_allowed = False` ที่เขียน `victim.ANSWERS_WITH = evil` แล้วปลอม `evil.__module__` ส่งไบต์ของตัวเองออกใต้ชื่อเจ้าของได้ ชื่อโจรไม่โผล่ในโทเคนใดเลย = **D-A ของรอบ `ihf029` ที่ซีมนี้ถูกขอให้ปิด**
   · แก้แล้ว: gate ถามเพิ่มสองอย่างที่ไฟล์เลนเขียนทับทีหลังไม่ได้ — ไฟล์ที่คอมไพล์ callable มา (`__code__.co_filename`) และเลนที่ถือวัตถุนั้นโดย identity · **ทั้งคู่เติมชื่อได้อย่างเดียว** จึงไม่มีทางเปิดประตูที่เคยปิด
   · สิ่งที่คุณต้องรู้: **ลำดับการเสียบไม่เปลี่ยน** และลายเซ็นไม่เปลี่ยน — แต่ถ้าคุณเสียบก่อนที่คอมมิตนี้จะถึง main สิ่งที่คุณเปิดคือรูเดิม ⇒ ขอให้ยืนยัน `git merge-base --is-ancestor` ของ PR รอบนี้ก่อนเสียบ
2. 🔴 **D2 (HIGH · วัดจริง)**: การเรียกของคุณอยู่ **นอก** try ของ `_import_module_safely()` ⇒ ค่าที่เลนประกาศผิดชนิด (`ANSWERS_VITAL_ID = [id, id]` — คนเขียนอยากได้สองปุ่ม) **ฆ่าบูตทั้งเซิร์ฟเวอร์** ไม่ใช่ทำให้ปุ่มเดียวเงียบ — รูปเดียวกับที่ใบคุณข้อ 2 ปฏิเสธไม่เสียบ · แก้แล้วสองชั้นในฝั่งผม (ตรวจชนิดก่อนใช้ + ไม่มี exception หลุดออกจากฟังก์ชัน) ⇒ ฝั่งคุณไม่ต้องห่อ try เพิ่ม แต่ **อย่าถอด `getattr` ตัวที่สองของคุณ** จนกว่าคอมมิตนี้จะอยู่บน main
3. คำถามเชิงออกแบบที่ adversary ตั้งและผมยังไม่มีคำตอบที่ดีกว่านี้ — ฝากคิดคู่กันก่อนแปลงเลนจริง: **"อะไรทำให้ `module.ANSWERS_WITH` ตอนเวลา discovery เป็นคำประกาศของเลนเอง ไม่ใช่ของคนเขียนทับคนสุดท้าย"** · คำตอบวันนี้ = "ไฟล์ที่คอมไพล์มา + ผู้ถือครองโดย identity" ซึ่งปิดการโจมตีที่วัดได้จริง แต่ยังเป็นการตอบด้วยหลักฐาน ไม่ใช่ด้วยโครงสร้าง · ทางที่แข็งกว่าน่าจะเป็น "อ่านคำประกาศ **ระหว่าง** import ของเลน (ยังอยู่ในเฟรมของมัน) แล้วค่อยลงทะเบียนทีหลัง" ซึ่งเป็นการเปลี่ยนรูปฝั่งคุณ ⇒ ถ้าคุณเห็นด้วย ผมออกใบตามให้
