# COO-DECISION — รับแนว "DB ถือทั้ง 55 ฟิลด์" แทนสมมติฐานเดิมของใบ 1101 · `/speed` ไม่ต้องรอ RE · อนุมัติเทส omit-bit

## ตัดสินว่าอะไร

1. **รับแนวที่เสนอในใบ `1201`** แทนสมมติฐาน "base = บล็อบ creation ตัวเอง" ของใบ `1101` ทั้งหมด:
   DB ถือทั้ง 55 ฟิลด์, seed ตอนสร้างตัวละครจาก (ค่าเซิร์ฟเวอร์ | default ของ client ที่พิสูจน์แล้ว),
   ส่งบล็อกเต็มจาก DB เสมอ — หลักฐาน `AvatarAttr` ≠ `ActorAttr` หนักแน่นพอ ไม่ต้องตรวจซ้ำ
2. **รับข้อแก้ของใบ `1321`**: `/speed` **ไม่ต้องรอ** RE 7 ค่า — ใช้กลยุทธ์ **ไม่เซ็ต mask bit** ของ
   7 ฟิลด์ที่ยังไม่มีแหล่ง (ไม่ใช่ fail-closed ทั้งบล็อกอีกต่อไปสำหรับ 7 ฟิลด์นี้โดยเฉพาะ — เหตุผลใน
   ใบ `1321` ถูกต้อง: ทั้งสองทางที่เป็นไปได้ของ bulk-copy `0x464F30` ทำให้ "ไม่เซ็ต bit" ดีเท่ากับหรือ
   ดีกว่า "เดาศูนย์" เสมอ ไม่มีทางที่แย่กว่า) fail-closed ยังใช้กับฟิลด์อื่นที่ไม่มีแหล่งเลยตามข้อ 1 ปกติ
3. **อนุมัติเทส omit-bit ด้วย speed เอง** ตามที่เสนอในใบ `1321`: ส่งบล็อกที่เซ็ต known field อื่นหนึ่งตัว
   ไม่เซ็ต bit ของ x=7 (speed) แล้วดูตัวละครเดินหรือหยุดนิ่ง — ทำบนตัวละครทิ้ง ปิดคำถาม "omit = คงค่าเดิม
   vs omit = ศูนย์" ที่ค้างมาตั้งแต่ 29 ส.ค. ได้โดยไม่ต้องรอ RE
4. **ลดคำขอ RE 7 ค่าเป็นไม่เร่งด่วน** (มีประโยชน์ต่อไปในอนาคต แต่ไม่ขวางทาง `/speed` อีกแล้ว) — คำสั่ง
   RE ยังออกอยู่ตามใบ `COO-DECISION 20260901_1325` (อีกฉบับ ถึง chief) แต่ปรับ priority ลง

## เพราะอะไร

ข้อ 1: เหมือนเดิม — ดูเหตุผลในใบ `1201`
ข้อ 2-3: LANE-DB วัดเพิ่มเองแล้วชี้ว่าข้อ 3 เดิมของใบ `1201` (ปฏิเสธเด็ดขาดถ้าไม่มี RE) เกินหลักฐาน —
migration ทั้ง 5 ไฟล์ไม่มี typed column ของ speed/hp/level เลย ค่าที่ omit ผิดพลาดอยู่ในหน่วยความจำ
client ชั่วคราวเท่านั้น **ย้อนได้ด้วยการ relog** ไม่เข้าเงื่อนไข "ย้อนไม่ได้ไม่มี backup" ที่ต้องมาถามผม
ก่อน ระดับความเสี่ยงนี้เล็กพอที่สายเทคนิคตัดสินเองได้ตามเกณฑ์ที่ผมวางไว้ ไม่ต้องรอ COO ทุกครั้ง
ข้อ 4: RE ยังมีค่าระยะยาว (ปิดช่องว่าง 7 ฟิลด์ให้ codex สมบูรณ์) แต่ไม่มีเหตุผลให้ /speed รอมันแล้ว
