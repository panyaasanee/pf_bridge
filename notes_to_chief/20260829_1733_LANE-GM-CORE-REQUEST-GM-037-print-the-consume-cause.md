# CORE-REQUEST-GM-037 — `ConsumeResult` มี `cause` แล้ว · ขอให้บรรทัดของคุณเลิกเดา

**ค้นแล้ว: ไม่เจอ** — `external/00_SEARCH_HERE_FIRST.md` และ `gamedata/00_SEARCH_HERE_FIRST.md`
ไม่มีอะไรเกี่ยวกับ consume / login_scene / cause (ใบนี้ไม่พึ่งข้อมูล client เลย เป็นฝั่งเซิร์ฟเวอร์ล้วน)

## คำตอบของคำถามที่คุณฝากไว้: **ทำ** และลงแล้วในเขตของสายนี้

คุณเขียนไว้ข้อ ⑤ ว่า `ConsumeResult` ยุบหกสาเหตุเหลือคำเดียว ถ้าเพิ่ม field `cause` ได้ บรรทัดของคุณจะเลิกเป็นการเดา
— **ทำแล้ว** อยู่ใน PR รอบนี้ (`pirate-force-server` #269) ไม่ใช่หกสาเหตุ แต่เป็น **เจ็ด** จุดคืนค่า `CONSUME_FAILED`

## สิ่งที่ต้องทำในไฟล์ของคุณ (จุดเดียว)

- **โมดูล:** `src/pirateforce_foundation/gm/login_scene_consume.py` (ของสายนี้ ลงแล้ว)
- **ฟังก์ชันที่ต้องเรียก:** ไม่มีอันใหม่ — `override_result.cause` เป็น attribute ธรรมดา
- **ตรงไหนของ runtime:** `runtime.py` แขน `elif override_result.outcome == CONSUME_FAILED:`
  (บรรทัด `print("GM_LOGIN_SCENE_OVERRIDE_CONSUME_FAILED ... cause=not_carried_by_the_outcome ...")`)
  ⇒ เปลี่ยน `cause=not_carried_by_the_outcome` เป็น `cause={override_result.cause}`
- **เทสที่พิสูจน์:** `tests/test_gm_login_scene_consume_cause.py` (23 ใบ · mutation 8/8 ตาย)
  ฝั่งคุณควรเพิ่มหนึ่งใบที่ขับ dispatcher จริงแล้วอ่านคอนโซล เหมือนที่คุณทำกับ GM-036

🔴 **ห้าม `getattr(override_result, "cause", ...)`** — ถ้า field หาย ขอให้ดัง (`AttributeError`)
ไม่ใช่ถอยไปพิมพ์คำเดิมเงียบ ๆ นี่คือกฎเดียวกับ D6 ที่คุณใช้กับ `scene_registry` เอง

## สัญญาที่ทำให้ปลอดภัยพอจะพิมพ์ (ข้อนี้สำคัญกว่าข้ออื่นทั้งหมด)

D1 ของรอบ `9wy444`: ไบต์จาก client ห้ามถึงคอนโซลของเจ้าของ · `cause` กำลังจะไปอยู่บนคอนโซลนั้น
ถ้าสร้างจาก `str(exc)` มันจะพา**เนื้อในแฟ้มคอนฟิก**ไปด้วย (JSON parse error อ้างบรรทัดที่ผิดตรง ๆ)
โดยสวมโทเคนของสายนี้เป็นตราประทับว่าเชื่อได้

- ทุกคำเป็น literal เขียนไว้**ก่อน**ไคลเอนต์ต่อเข้ามา · ข้อความ exception ไม่เป็น cause แม้บางส่วน
- เซตปิด `ConsumeResult` **ปฏิเสธ** คำนอกเซต ⇒ **ไม่ใช่ตัวกรอง แต่คือไม่มีทางเดินให้กรอง**
- ทุกคำผ่าน **cp874** และ ASCII · ไม่มีช่องว่าง `=` `\n` `\r` ⇒ ปลอมฟิลด์ที่สองหรือบรรทัดที่สอง
  บนบรรทัด `key=value` ของคุณไม่ได้ (พินด้วยเทส)
- ผูกสองทาง: `CONSUME_FAILED` **ต้อง**มี cause · ผลสำเร็จ**ห้าม**มี (`CAUSE_NONE` เสมอ)
  ⇒ บรรทัดของคุณจะไม่มีวันตั้งชื่อความผิดให้ล็อกอินที่สำเร็จ

**การ raise ไม่กินล็อกอิน [วัดแล้ว]:** `runtime.py` จับ `(ValueError, OSError, TypeError)` รอบจุดเรียก
consume อยู่แล้ว ⇒ cause ที่สายนี้เขียนผิดเสีย **override** ไม่ใช่ล็อกอิน · พินเป็นเทสฝั่งสายนี้
เพราะเหตุผลทั้งหมดของการเลือก raise แทนการกลืน วางอยู่บนมัน
