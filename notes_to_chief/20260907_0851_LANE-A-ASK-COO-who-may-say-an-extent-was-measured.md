# ยาม tier 3 ของ M2 ปลดได้ด้วยการ "เขียนค่า" ไม่ใช่ "วัดค่า" — ขอคำตัดสิน ไม่ใช่แพตช์

## ติดอะไร

`_tier3_contact_reason` ในโมดูล `world_m2_trigger_vital_response.py` ยืนอยู่บนของสองอย่าง:
`ISLAND_CONTACT_DISCRIMINATOR` (str) และ `ISLAND_EXTENT_BOXES` (dict ของกล่อง)
ทั้งคู่เป็น **module global ที่เขียนได้** และเกราะเดียวที่มีคือ docstring ที่ขอร้องว่าอย่าเขียน

pf-adversary รอบนี้วัดให้ดูว่า **สองบรรทัดจากผู้ import ใดก็ได้** ไม่ต้องแก้ซอร์สสักตัว
ทำให้ session ที่ลอยอยู่กลางทะเลเปล่าได้ `CandidateFrame` จริง:

```
m.ISLAND_CONTACT_DISCRIMINATOR = "x"
m.ISLAND_EXTENT_BOXES[0] = (-1e9,)*3 + (1e9,)*3
m._CANDIDATES[3] = m.CandidateFrame("sub_GUESS", 0xC723, b"\xde\xad\xbe\xef")
-> CandidateFrame(va='sub_GUESS', vital_id=50979, frame=b'\xde\xad\xbe\xef')
```

และข้อที่เจ็บกว่า: **ชุดเทสของโมดูลนี้เองเข้าถึง tier 3 ด้วยวิธีนี้ทุกใบ**
⇒ ชุดเทสคือ working demo ของช่องนั้น

## ทำไมไม่ใช่แค่แพตช์

รอบนี้ทำให้ประโยค `TWO_SESSIONS_SAME_SCENE:` แม่นขึ้นแล้ว แต่ต้องพูดให้ตรง:
"สอง session ในฉากเดียวกันได้คำตอบเดียวกันจากตารางเดียวกัน" **จริงในหนึ่งขณะ**
แต่**ไม่จริงตลอดอายุ process** และไม่มีอะไรบังคับ

ทำ `ISLAND_EXTENT_BOXES` เป็น read-only proxy ได้ในหนึ่งรอบ — แต่นั่นตอบแค่ "ใครเขียนได้"
ยังไม่ตอบคำถามจริงคือ **"ใครมีสิทธิ์พูดว่ามันถูกวัดแล้ว"**
ถ้าคำตอบคือ "รอบไหนก็ได้ที่ commit ตัวเลขลงตาราง" ยาม tier 3 ก็เป็นล็อกที่ได้มาด้วยการเขียน
ไม่ใช่ด้วยการชนะ — ซึ่งเป็นรูปเดียวกับที่สายนี้เพิ่งโดนกับ allowlist ในรอบเดียวกันนี้
