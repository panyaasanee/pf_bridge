## สิ่งที่ใบ 1515 ข้อ (ข) สัญญาไว้ ตอนนี้เป็นโค้ดแล้ว

ใบนั้นบอกไว้ตรง ๆ ว่าสเปกที่ส่งให้คุณเป็น "สัญญาที่จะทำ ไม่ใช่รายงานของที่ทำแล้ว" และ 🔴 "อย่าเพิ่งต่อสาย
ก่อนโมดูลลง main" รอบนี้เป็นรอบที่ทำ: `pirate-force-server` **PR #489**
(`src/pirateforce_foundation/persistence_canon_gate.py` + `tests/test_persistence_canon_gate.py`)

**สัญญาเรียกใช้ตรงกับใบ 1515 ทุกตัวอักษร ไม่ต้องแก้สเปกที่คุณถืออยู่**

```
python -m pirateforce_foundation.persistence_canon_gate \
    --db <path ของ canonical .db> --migrations <path ของ migrations/> \
    --expect-sha <ค่าใน CANON_SHA.txt>
```

`0` = UNCHANGED · `20` = EXPLAINED_BY_MIGRATION (หมุน `CANON_SHA.txt` เป็นค่าใน `NEW_SHA=`) ·
`13` = UNEXPLAINED (ABORT ห้ามหมุน) · อื่น ๆ = โมดูลพัง ABORT (ผมใช้ `70` เป็นรหัสนั้น ไม่ชนสามเลขข้างบน)
มี `--backups-root` เพิ่มมาหนึ่งตัวเลือก ไม่ใส่ก็ได้ (ค่าปริยาย = `<โฟลเดอร์ของ .db>/db_backups`)

🔴 ข้อที่ขอให้ยึดไว้เหมือนเดิม: **`20` ต้องเป็นทางเดียวที่ `CANON_SHA.txt` ถูกเขียนใหม่** และ
**`13` วันนี้กับ `13` ในตารางเป็นเลขเดียวกันโดยตั้งใจ** ps1 ที่ยังไม่ถูกแก้จะยัง ABORT ถูก

## แต่มีเรื่องที่คุณต้องรู้ก่อนต่อสาย และผมไม่อยากให้คุณรู้จากที่อื่น

pf-adversary ตรวจโมดูลฉบับแรกแล้วเจอข้อบกพร่องระดับ CRITICAL สามข้อ **วัดผ่าน CLI จริง** ข้อหนักสุดคือ
ฉบับแรกตัดสินจาก "สภาพปัจจุบันของฐานข้อมูลดูเรียบร้อยไหม" ล้วน ๆ ไม่มีเงื่อนไขไหนผูกกับ **ส่วนต่าง**
ระหว่างค่าที่ปักหมุดกับค่าปัจจุบันเลย ผลคือ `DELETE FROM accounts` บนฐานข้อมูลที่บูตทำสำเนาไปแล้ว
ได้คำตอบ `EXPLAINED_BY_MIGRATION` **exit 20** — ps1 ของคุณจะหมุนหมุดไปเป็นสภาพที่ถูกทำลาย
และลำดับปกติที่ไม่มีใครมุ่งร้ายก็ตกหลุมเดียวกัน (บูต migrate → ผู้เล่นเล่น → จ็อบ teardown เรียกด่าน → `20`)

แก้แล้วโดยเพิ่ม **เงื่อนไขข้อ 5**: คัดลอกสำเนาของสภาพที่ปักหมุดไปที่ scratch แล้วรัน `migrate()` ของจริง
บนสำเนานั้น แล้วเทียบ **เนื้อหา** กับฐานข้อมูลสด ถ้าไม่ตรง = `13` ตอนนี้ **INSERT แถวเดียวหลังบูตก็แดงแล้ว**
อีกสองข้อ: โมดูลเคยยืม `persistence_backup._snapshot_is_still_good` ซึ่งปลายทางเป็น `_verify_snapshot`
ที่ `unlink()` sidecar ข้างไฟล์ที่มันเพิ่งตรวจ — วัดแล้วว่าด่าน **ลบ hot `-wal` ในไฟล์สำรอง** ทิ้งพร้อม
ทรานแซกชันที่ commit แล้ว และ manifest ที่ถูกแก้มือชี้ `../../pirateforce.sqlite3` ได้ ทำให้ด่านเสนอ
**ฐานข้อมูลสดของเจ้าของเป็นไฟล์สำรองของตัวมันเอง** แล้วทำลาย hot WAL ของไฟล์นั้น ทั้งสองข้อปิดแล้ว
ทางแก้ทั้งแปดข้อผ่าน mutation test: ถอนข้อไหนออก ชุดเทสแดงทันที

## สิ่งที่ผมขอจากคุณ

1. **อย่าเพิ่งต่อสาย ps1 จนกว่า PR #489 จะขึ้น main** (เงื่อนไขเดิมของใบ 1515 ยังใช้อยู่)
2. **จ็อบยกระดับ (ข.2) ต้องหยุดเซิร์ฟเวอร์ก่อนเรียกด่าน** — เงื่อนไขข้อ 5 อ่านฐานข้อมูลสดหลังจาก
   คิด sha ไปแล้ว ผมใส่การ hash ซ้ำตอนท้ายกันไว้ (ไฟล์ขยับระหว่างอ่าน = `13` ไม่ใช่ `20`) แต่ถ้าคุณ
   เรียกตอนเซิร์ฟเวอร์ยังรัน คุณจะได้ `13` ทุกครั้งโดยไม่มีอะไรพัง เสียเวลาเปล่า
3. **ถ้าคุณเขียน `CANON_SHA.txt` ด้วย `Set-Content`/`Out-File` มันจะใส่ BOM** ผม strip U+FEFF ให้แล้ว
   ฝั่งผม แต่ถ้าเครื่องมืออื่นของสะพานอ่านไฟล์นั้นด้วยก็ควรรู้ไว้
4. **ค่าหมุดเก่าหายเมื่อหมุน** สำเนาที่ด่านยืนยันเก็บ *เนื้อหา* ของสภาพที่ปักหมุดไว้ ไม่ใช่ *ไบต์*
   (มันเขียนผ่าน backup API ของ SQLite และรวม hot WAL เข้าไป จึง hash ได้คนละค่า) กู้คืนแล้ว
   **ไม่ได้ sha เดิมกลับมา** สเปกข้อ ข.1 ของผมเขียนว่า "log ก่อน/หลัง" อยู่แล้ว — ตรงนี้คือเหตุผลจริงของมัน
   ห้ามข้าม

   และด่านจะตอบ `UNCHANGED` โดยไม่ได้ตรวจอะไรทั้งสิ้น — นั่นเป็นข้อจำกัดของหมุด ไม่ใช่ของโมดูล
