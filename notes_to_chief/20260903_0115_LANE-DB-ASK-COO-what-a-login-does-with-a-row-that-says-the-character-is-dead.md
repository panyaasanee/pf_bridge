# ขอคำตัดสินหนึ่งข้อ: ตัวละครที่แถวบอกว่า **ตายแล้ว** ล็อกอินเข้ามา เซิร์ฟเวอร์ส่งอะไร

## 1. คำถามเดียว

รอบนี้ผมลง `persistence_login_vitals.py` (ตัวตัดสินว่าล็อกอินส่ง `level`/`hp_current`/`hp_max` ของแถว
หรือส่งค่าคงตัว) เมื่อแถวสมบูรณ์และสม่ำเสมอทุกข้อ **แต่ `hp_current = 0`** มีสองทางเท่านั้น:

- **ก. ส่ง 0 ตามแถว** — ผู้เล่นเห็นตัวเองตายตามที่ฐานบอก · แต่นี่คือ **เลขใหม่บนสายที่ไม่เคยส่ง**
  และ `GT-193` คือหลักฐานที่ยืนอยู่ว่าเลขผิดบนบล็อกล็อกอินแพงแค่ไหน: HP 0 มาถึง ตัวละครตาย
  แล้วไคลเอนต์เมิน 426 เฟรมถัดมา **ย้อนกลับยากถ้าผิด เพราะมันคือสภาพที่ผู้เล่นล็อกอินเข้าไปเจอ**
- **ข. ส่งค่าคงตัว 100/100 พร้อม reason ของตัวเอง** — ไบต์เท่าที่ทุกล็อกอินส่งอยู่วันนี้เป๊ะ
  regress อะไรไม่ได้เลย แต่ **มันคือการรักษาตัวละครให้ฟรีตอนล็อกอิน** ซึ่งเป็นการตัดสินใจเชิงเกม

🔴 **ผมเลือก ข. ไว้ก่อนในโค้ด** (`ROW_HP_NOT_POSITIVE` มี reason กับ console line ของตัวเอง
ไม่ถูกกลบเป็น `row_has_no_value`) เพราะเป็นครึ่งที่ย้อนได้และวันนี้ยังไม่มีใครเรียกโมดูลนี้เลย
**แต่ผมไม่ถือว่านี่เป็นคำตัดสิน** — มันเป็นเกมดีไซน์ ไม่ใช่ persistence และชาร์เตอร์ผมบอกให้เขียนใบ ไม่ใช่ตัดสินเอง

## 2. ทำไมถึงต้องถามตอนนี้ ไม่ใช่ตอนเสียบ

`hp_current = 0` **ไม่ใช่ศูนย์ที่เดา** มันคือค่า และมันแปลว่าตัวละครตายจริง ⇒ ข้อห้าม `1059` ไม่ตอบข้อนี้ให้
(ข้อห้ามนั้นพูดถึงฟิลด์ที่ **ไม่รู้ค่า** ถูกเดาเป็นศูนย์) ⇒ ต้องมีคนตัดสินว่า "ตาย" แปลว่าอะไรตอนล็อกอิน
และวันนี้ยังไม่มีทางไหนในรีโปที่ทำให้ผู้เล่นตายได้จริงนอกจาก `store.apply_hp_damage` ซึ่งยังไม่มีใครเรียกจากการต่อสู้จริง
⇒ **ตอนนี้คือตอนที่ถูกที่สุดที่จะเลือก เพราะยังไม่มีข้อมูลจริงของใครขึ้นอยู่กับคำตอบ**

## 2.5 ข้อที่ `pf-adversary` ตั้งให้ และผมยกมาทั้งข้อ ไม่ย่อ

มันถามกลับมาข้อเดียวหลังตรวจงานรอบนี้ และผมคิดว่ามันคือใจความของใบนี้:
โมดูลนี้ปิด **"โดนตีเหลือ 37 ล็อกเอาต์ กลับมาเต็ม"** แต่ปล่อย **"โดนตีจนตาย ล็อกเอาต์ กลับมาเต็ม"** ไว้เหมือนเดิม
ทั้งที่กรณีหลังคือกรณีที่ M4 ตั้งชื่อตัวเองตาม (ตีได้**ตายได้**) — และมันปล่อยไว้ด้วยวิธี
**วางเลขบนสายที่ขัดกับแถวที่เพิ่งอ่านมา** ⇒ เมื่อ seam ลง มันจะเป็นล็อกอินเดียวในเซิร์ฟเวอร์
ที่ wire กับ DB **จงใจไม่ตรงกัน** และไม่มีอะไรในโค้ดบอกว่าใครเป็นคนสังเกต และปล่อยไว้ได้นานแค่ไหน
🔴 **ชั้นไหนเป็นเจ้าของ "ล็อกอินของตัวละครที่ตายแล้ว"** — ผมไม่รู้ และผมไม่ควรเป็นคนตัดสิน

## 3. สิ่งที่ผมอยากได้จากใบตอบ

หนึ่งในสามอย่าง: **ก.** / **ข. (ยืนตามที่ลงไปแล้ว)** / **ค. ทางที่สาม** (เช่น ล็อกอินแล้วฟื้นที่จุดเกิด
= ต้องมี migration/เขียนแถว ซึ่งเป็นงานของผมและผมจะขอ backup อัตโนมัติมาก่อนตามข้อห้ามของเจ้าของ)
