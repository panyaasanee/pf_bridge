# สร้างประตูของบนพื้นได้เลย · รอบแรกเขียน+อ่านกลับเท่านั้น · คีย์ชนต้องล้มดังที่ตาราง ไม่ใช่เงียบ

## ตัดสินว่าอะไร
1. **รับใบ 1740 ทั้งใบ** — คำตอบ (ก)(ข) ยืน: ของบนพื้นเป็นของเซสชัน ไม่มีตาราง ⇒ ตรงกับ `COO 1048` ว่าเป็นข้อบกพร่องจริง ไม่ใช่ดีไซน์
2. **หนี้ก่อน**: `#664` ถูกปิดไม่ merge (cp1252 บน Windows) · `#666` ที่กู้อยู่ต้องขึ้น `main` ก่อนเริ่มข้อ 3 วัดด้วย `merge-base --is-ancestor` บนโคลน unshallow เท่านั้น
3. **(ค)-1 ใครเขียน = ตามที่เสนอ** LANE-DB สร้าง migration `010` (CREATE TABLE ใหม่เปล่า) + `store.commit_ground_drop` + `store.list_ground_drops_for_scene` · อ่านกลับหลังเขียนทุกครั้ง + บรรทัดคอนโซล · จุดเรียกตอนของตกเป็นของ LANE-B (ชาร์เตอร์ `20260901_1100`) · **ห้ามแตะ `mob_loot.py`** · ธง `GROUND_DROP_DOES_NOT_PERSIST` เป็นของสาย B ห้ามพลิก
4. **(ค)-2 คีย์ชนข้ามเซสชัน**: ตาราง PK = rowid ของตัวเอง · `drop_key` เป็นคอลัมน์ธรรมดาที่มี `UNIQUE(scene_id, drop_key)` ⇒ สองเซสชันออกเลขเดียวกันต้อง**ล้มดังตอนเขียน** (กฎบ้าน: เขียนไม่สำเร็จ = ล้ม ไม่ใช่ทับ) · ตัวออกเลขระดับเซิร์ฟเวอร์เป็นของ LANE-B (ผมสั่งในใบ `1844`) ไม่ใช่ของคุณ
5. **(ค)-3 ขอบเขต = เขียนตอนตก + อ่านกลับ** เท่านั้น · ไม่มี DELETE · ไม่มี expiry (`0253` ยืน) · migration สร้างตารางเปล่าไม่เข้าเงื่อนไข backup ของการ์ด `1112` ข้อ 3 ⇒ **ไม่ต้องเปลี่ยนจุดเรียก `migrate()` ของ chief**
6. รับข้อแก้จาก pf-adversary ทั้งสาม · ไฟล์เทสใหม่ทุกไฟล์ต้องซ้อม `pytest_subset` + `skip_census` แบบไม่มี `pf_bridge` ข้าง ๆ เหมือนรอบนี้
