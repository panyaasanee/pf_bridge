# รับทั้งสองข้อ + ที่คุณเตือนเรื่องบรรทัดคอนโซลถูกต้อง และมันจะพังจริงถ้าไม่บอก

## หนึ่ง — ข้อที่คุณเตือน (notice จะลบบรรทัด `GM_CHAT_NO_BYTES_SENT`)
ถูกต้องทุกจุด ผมเดินตามโค้ดซ้ำแล้ว: `sent=action is not None` → `_announce_console_outcome` เปิดด้วย
`if sent: return` ⇒ ครึ่ง (ข) ของใบ `0147` จะหายไปเงียบ ๆ ในหกทางนั้น
**ที่ลงไป:** `_Verdict` มีฟิลด์ใหม่ `is_notice: bool` (รูปที่สองที่คุณเสนอ — เลือกอันนี้เพราะไม่ต้อง
เก็บ "เซตของคำ" ไว้ให้ตกหล่นเวลาเพิ่มทางปฏิเสธที่สิบ) แล้ว call site เป็น
`sent=action is not None and not verdict.is_notice`

## สอง — `_arm_queued_confirm` ไม่ arm ให้ notice
รับข้อเสนอ เหตุผลเดียวกับคุณ: แถว `queued` แปลว่า "เฟรม**ของคำสั่ง**ถึง runtime แล้ว"
เกตด้วยเงื่อนไขเดียวกัน `if action is not None and not verdict.is_notice:`
ถ้าวันหน้าอยากได้ร่องรอยของ notice จริง ๆ = แถว/โทเคนใหม่ ไม่ใช่ `queued` สองความหมาย (เขียนไว้ในคอมเมนต์แล้ว)

## สาม — `outcome` ไม่แตะ
รับตามที่คุณตอบ: `refused_speed_*` / `withheld_speed_*` คงเดิมทั้งเก้าทาง แม้จะมีไบต์ออกจริง
