## 2. 🔴 แก้ข้อสมมติในหัวใบ — `0x0045C160` **ไม่ได้อ่านฟิลด์ของ `NPCAttr`/`BasicAttr` เลยแม้แต่ฟิลด์เดียว**

**รายชื่อฟิลด์ + offset ที่ predicate อ่าน (ครบ ไม่มีอย่างอื่น):**

| # | ที่อ่าน | ชนิด | ความหมายที่วัดได้ |
|---|---|---|---|
| 1 | `actor + 0x35C` | pointer | เรคคอร์ดนิยามของ actor (ไม่ใช่ attr บนสาย) · null = false |
| 2 | `[actor+0x35C] + 0x44` | u32 | **คีย์แถวของตาราง `AI_WANDER`** · 0 = false |
| 3 | `AI_WANDER[คีย์].n_OFFESIVE` | int (จากตารางข้อมูล) | **≠ 0 ⇒ true** |

⇒ **`0x0045C160` = `IsOffensive()`** · ชื่อที่ตรงกับสิ่งที่มันทำ

## 3. ลำดับสาขาเต็มของตัวเลือกสูตรสีชื่อ `0x00443F50`

`0x0045C160` ถูกเรียกจาก **ที่เดียวทั้งอิมเมจ** = `0x0044422B` ซึ่งอยู่ในฟังก์ชัน **`0x00443F50`** — ตัวเลือก `FontStyleID` ของป้ายชื่อ

### 🔴 คำตอบข้อ "ค่าที่ทำให้ออกจากสูตรผู้เล่น"

**identity 64 บิตที่ `[esi+0x78]` (low) / `[esi+0x7C]` (high) ที่ไม่เป็นบวกแท้**
เงื่อนไขในไบต์: `cmp dword [esi+0x7C],0 / jl [C]` · `jg [B]` · ถ้า hi == 0 แล้ว `test [esi+0x78],[esi+0x78] / jbe [C]`
⇒ **hi < 0 หรือ (hi == 0 และ lo == 0) ⇒ เข้าสาขา NPC ทันที** ไม่มีทางกลับไปสูตรผู้เล่นอีกเลยในฟังก์ชันนี้
นี่คือจุดเดียวกับที่ **`RE-222`** ("NONPOSITIVE-IDENTITY…") เปิดไว้ — ตรงกับที่ COO ระบุที่มาของใบ

## 4. ฟิลด์ attr จริง ๆ ที่ถูกอ่าน อยู่ใน `0x0043C380` ไม่ใช่ใน `0x0045C160`

ถ้าคำถามของหัวใบต้องการ "ฟิลด์ของ NPCAttr/BasicAttr" จริง ๆ **ตัวที่อ่านคือ `0x0043C380`** (ตัวเดียวกับ `relationship_predicate` ที่ `RE-195` เอ่ยถึง) ซึ่งเป็นสาขาแรกของทั้ง [B] และ [C] ⇒ มันตัดสิน **ก่อน** `0x0045C160` เสมอ

อ่านจากอ็อบเจ็กต์นิยามของสองฝ่าย (ได้มาจาก `vfunc[0x74]()` แล้วผ่าน `0x0043B9B0`):

| ที่อ่าน | ชนิด | บทบาทในสาขา |
|---|---|---|
| `+0x98` | byte | ทั้งสองฝั่ง ≠ 0 ⇒ เดินต่อไปทางเทียบ faction · ฝั่งใดฝั่งหนึ่ง = 0 ⇒ ข้ามไปเทียบ `+0x1A0` |
| **`+0x1A0`** | byte | **ค่าฝ่าย/แคมป์** · เท่ากัน ⇒ ไปตารางความสัมพันธ์ · ฝั่งใด `== 3` ⇒ **เป็นศัตรู** · ฝั่งใด `== 2` ⇒ **ไม่เป็นศัตรู** · อื่น ⇒ ถาม `0x0044A500()` |
| `+0x68` | (คู่) | ป้อน `0x0040B560` → `0x004A1D50` = ผลลัพธ์สุดท้ายเมื่อไม่เข้าสาขาข้างบน |
| `other+0x248` → `+0xA8` | byte | `> 0` ⇒ **ไม่เป็นศัตรู** (ตัดก่อนทุกอย่าง) |

และประตูก่อนหน้าทั้งหมด:
- ทะเบียนสถานะ คีย์ **`0x35`** บน `this+0x130` และ `other+0x130` (ทะเบียนตัวเดียวกับที่ `RE-303` ถอดไว้ คีย์ `0x33`/`0x24`/`0x51`) ⇒ แปลงแต่ละฝ่ายเป็น "ตัวจริง" ก่อนเทียบ
- `ebp == ebx` (ตัวเดียวกัน) ⇒ ไม่เป็นศัตรู
- `0x004011A0()` → `[+0xD0] == 0` ⇒ **ไม่เป็นศัตรู** (สวิตช์รวมตัวหนึ่ง)
- กิลด์เดียวกัน (`0x00449B10` + `0x00626DC0`) ⇒ ไม่เป็นศัตรู
- ตารางความสัมพันธ์ฝ่าย: `[0x01093198]→[0x2C0]→[0xC]→ +0x30` (u16) กับ `+0x1A0` ของทั้งสองฝ่าย → `0x00404F80` → `0x004A6EC0`
