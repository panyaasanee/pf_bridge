### ตัวเลข — และมันตอบคำถามของท่านแคบกว่าที่ตั้งไว้มาก

🔴 **ผมไม่มีดาต้าเบสของเจ้าของบนคลาวด์** ตัวเลขข้างล่างวัดจากดาต้าเบสที่ผมสร้างเองในรอบนี้
ผมเขียนไว้ตรงนี้ก่อนตัวเลข ไม่ใช่ใต้มัน

| ดาต้าเบส | แถว | `level` | `hp_current` | `hp_max` | `speed_walk` |
|---|---|---|---|---|---|
| สร้างใหม่ `001`→`009` ไม่มีตัวละคร | 0 | 0 | 0 | 0 | 0 |

**⇒ ข้อสรุปที่ใช้ตัดสินได้: คำถาม backfill หดเหลือคอลัมน์เดียวคือ `speed_walk`**
- `level` / `hp_current` / `hp_max` เป็นศูนย์ในทุกรูปที่ผมสร้างได้ เพราะ `create_character`
  เขียนสามค่านั้นลง `INSERT` ตรง ๆ (`store.py:411`) และ `007` หว่านให้รุ่นที่มีอยู่ก่อนแล้ว
- `speed_walk` **ไม่ถูกเขียนใน `INSERT` เลย** (`store.py:411` ไม่มีชื่อคอลัมน์นี้) ⇒ ก่อน `009`
  แถวใหม่เกิดมาเป็น NULL · หลัง `009` DEFAULT `400.0` รับให้
- `008` หว่านให้แถวที่มีอยู่ **ตอนที่มันรัน** (`migrations/008...sql:123`
  `UPDATE characters SET speed_walk = 400.0 WHERE speed_walk IS NULL;`) และ **`009` ไม่ backfill**
- ⇒ **หน้าต่างคือช่วงระหว่างสองไมเกรชัน เป๊ะ ๆ**: เลขบนเครื่องเจ้าของ =
  **จำนวนตัวละครที่ถูกสร้างหลังวินาทีที่ `008` รัน และก่อนวินาทีที่ `009` รัน บนเครื่องนั้น**
  (ไม่ใช่ "ก่อน `009`" เฉย ๆ — แถวที่เก่ากว่า `008` ถูก `008` หว่านให้แล้ว)
  ถ้า `008` กับ `009` ลงในการบูตเดียวกัน หน้าต่างกว้างศูนย์ ⇒ เลขเป็น **0**
  และเรื่องนี้จบทันทีตามที่ท่านเขียนไว้

คำสั่งที่ผลิตเลขจริงบนเครื่องเจ้าของ (อ่านอย่างเดียว ไม่เขียนอะไร):

```
python -c "import sys;sys.path.insert(0,'src');from pirateforce_foundation.store import SQLiteStore;from pirateforce_foundation import persistence_null_audit as a;print(a.format_report(SQLiteStore(r'<path>.sqlite3','migrations').typed_column_null_audit()))"
```

🔴 **backfill ยังไม่ทำ และผมไม่เสนอให้ทำ** จนกว่าท่านเห็นเลขจากเครื่องนั้น

### 🔴 ข้อจำกัดของเลขนี้ ที่ท่านต้องรู้ก่อนใช้ตัดสิน (ผู้ตรวจหักผมสามข้อ ผมรับหมด)

1. **`0` มีสองความหมาย และรายงานแยกให้ไม่ได้** — ดาต้าเบสที่เจอ `008` กับ `009`
   **ในการบูตเดียวกัน** มีหน้าต่างกว้างศูนย์โดยโครงสร้าง (ไม่มีตัวละครเกิดระหว่างสองไฟล์
   ที่ `migrate()` เดียวรัน) ⇒ ตอบ `0` เพราะ **ไม่เคยมีโอกาส** ไม่ใช่เพราะตรวจแล้วสะอาด
   เฉพาะดาต้าเบสที่ **เปิดเซิร์ฟเวอร์จริงตอนอยู่ที่ `008`** เท่านั้นที่ตอบมากกว่าศูนย์ได้
   ⇒ **ถ้าเลขบนเครื่องเจ้าของออกมา 0 ขอให้ท่านถามต่อว่า `008` กับ `009` ลงพร้อมกันไหม**
   ทั้งสองลำดับเป็นเทสบน main แล้ว
2. **"ถือ NULL" แคบกว่า "ไม่มีค่าที่ถูกเคาะ"** — วัดแล้ว: `/speed 0` ผ่านประตูของสายผมเอง

   ⇒ แถวนั้น **ไม่ถูกเคาะตลอดกาลและตัวนับมองไม่เห็น** เช่นเดียวกับแถว `level 0`
   ที่เซิร์ฟเวอร์ปฏิเสธจะให้ล็อกอิน แต่ทุกคอลัมน์ NOT NULL ⇒ ใบสะอาดสี่บรรทัด
3. **สามไวทัลถูกนับโดยไม่เคยถูกซ้อม** — หน้าต่างที่เทสสร้างจริงคือของ `speed_walk`
   ส่วน `level`/`hp_current`/`hp_max` มีหน้าต่างของตัวเอง (`007` ↔ รอบที่อุดรูตอนเกิด)
   ซึ่งรอบนี้ **ไม่ได้ซ้อม** ⇒ เป็นช่องว่างของ **หลักฐาน** ไม่ใช่ของคิวรี ผมเขียนไว้ในโมดูลแล้ว
