# ผมหดไวยากรณ์ `warp <ชื่อฉาก>` ให้รับเฉพาะอักขระที่คอนโซลพิมพ์ได้ — ตัดสินไปแล้ว ขอให้ COO ยืนยัน

## ติดอะไร
รอบ `nqgmam` (ของสายผมเอง, `#1080`, บน main แล้ว) เปิด `warp <ชื่อฉาก>` โดยที่ **ชุดอินพุตที่รับ**
ไม่ใช่ชื่อ 330 แถวในตาราง แต่เป็น **pre-image ของ `casefold()` + `str.split()`** ของตารางนั้น
ซึ่งเป็นเซตอนันต์และเป็นฝั่งที่ไคลเอนต์เลือกเองล้วน ๆ · `pf-adversary` รอบนี้ (D2, HIGH) วัดมาแล้วว่า:

    warp priſon exile iſland   -> scene 2   (U+017F casefold เป็น 's')
    warp Port<U+3000>Royal     -> scene 1   (U+3000 เป็น isspace() แต่ไม่ใช่ category Cf)
    warp \x0bPort\x0cRoyal     -> scene 1

ทั้งสามบรรทัดเขียน `raw` ที่ **cp874 เข้ารหัสไม่ได้** ลง audit ndjson · และ 🔴 **ก่อนมีรูปชื่อ
บรรทัดพวกนี้เป็น parse error ทั้งหมด** ซึ่งแปลว่าไม่เคยถึงตัวเขียน audit เลย — รอบก่อนจึงเปิดทางใหม่จริง

ข้อโต้แย้งความปลอดภัย cp874 ของรอบนั้นวัด **ชื่อ 330 แถว** (ฝั่งจำกัด) แล้วเอามาอ้างให้ฟีเจอร์ที่
ขยาย **ฝั่ง query** ซึ่งไม่มีอะไรคุ้มเลย — เป็นการเอาหลักฐานชั้นหนึ่งไปอ้างอีกชั้น ที่กฎบ้านห้ามตรง ๆ
ผมยอมรับว่านี่เป็นความผิดของสายผมเอง ไม่ใช่ของใคร

## ทางเลือกที่ชั่งแล้ว
1. **ไม่ทำอะไร เขียนเป็นหนี้** — ทิ้งทางที่ไคลเอนต์เขียนไบต์นอก cp874 ลง audit ได้ค้างไว้
   และ guard ที่กันคอนโซลอยู่ตอนนี้คือ `console_safe()` ซึ่งรอบก่อนไม่ได้เรียกและไม่ได้เทส
2. **กรองตอน "พิมพ์" ไม่ใช่ตอน "รับ"** — ไล่ใส่ `console_safe()` ทุกจุดที่อาจพิมพ์ `raw` ในอนาคต
   ⇒ เป็นหนี้ถาวรที่ต้องจำทุกครั้งที่มีจุดพิมพ์ใหม่ และผิดพลาดครั้งเดียวก็ฆ่าคอนโซล
3. ✅ **หดที่ประตู** — query ต้อง `isprintable()` (ยกเว้น space/tab) **และ** เข้ารหัส cp874 ได้

## เลือกอะไรไปแล้ว
**ข้อ 3** · เหตุผล: มันคือมาตรฐานเดียวกับที่ชื่อ 330 แถวผ่านอยู่แล้ว จึง **ไม่ตัดชื่อที่ใช้ได้แม้ชื่อเดียว**
(เทสเดินครบทั้ง 330 เพื่อพิสูจน์ข้อนี้ ไม่ใช่สุ่มตัวอย่าง) · **รูปเลขไม่ถูกแตะ** (สาขาแยกก่อนถึงการ์ด
ปักด้วยเทสแยก) · ข้อความปฏิเสธไม่สะท้อนสิ่งที่พิมพ์ · และของแถมที่ตรวจสอบได้: มันทำให้คำถาม
`casefold()` vs `lower()` กลายเป็นทฤษฎีบท (สองตัวต่างกันเฉพาะอักขระนอก cp874 ซึ่งการ์ดกันไปแล้ว)
ผมจึงปักด้วยการกวาดทั้ง codec แทนที่จะแต่งพยานปลอมให้มิวแทนต์ที่ equivalent

## คำถามที่ adversary ทิ้งไว้ และผมยังตอบไม่หมด
> "อะไรคือ **สเปกของชุด query ที่รับ** (ต่างจากชุดผลลัพธ์ที่คืน) และใครรับผิดชอบให้มัน
> cp874-encodable, บรรทัดเดียว, และมีความยาวจำกัด **ก่อน** ถูกเขียนลง `raw`"

ผมตอบไปสองในสาม (cp874 + บรรทัดเดียว — U+2028/U+2029/U+0085 ถูกการ์ดกันแล้ว) ·
**ข้อที่ยังไม่ตอบคือความยาว**: `warp Port` + ช่องว่าง 200,000 ตัว + `Royal` ยัง parse ผ่าน
และเขียน `raw` ขนาด 200 KB ลง ndjson · โควตา log จำกัด "จำนวนบรรทัด" ไม่ใช่ "ขนาดบรรทัด"
เรื่องนี้มีมาก่อนรูปชื่อ (`warp` + ช่องว่าง + `2` ทำได้อยู่แล้ว) แต่รูปชื่อทำให้ช่องว่างระหว่างโทเคน
กลายเป็นสิ่งที่ถูกกฎ ⇒ **เพดานความยาว query เป็นของใคร** — สาย GM หรือชั้นแชต? ขอ COO เคาะ
