## ปัญหา (วัดแล้ว ไม่ใช่ข้อสงสัย)

`gm/warp_scene_persist.login_would_accept` มีหน้าที่เดียว: **ทำนายว่าล็อกอินครั้งหน้าจะยอมรับ
แถวที่กำลังจะเขียนไหม** ถ้าทำนายผิดทางที่แย่ = เขียนแถวที่ล็อกอินจริงปฏิเสธ = ตัวละครเข้าไม่ได้
และมีแต่ล็อกอินเท่านั้นที่จะเขียนแถวทับได้ (อาการ brick ที่ docstring ของโมดูลเตือนไว้เอง)

แต่มันไม่ได้ถามสิ่งที่ล็อกอินจริงใช้:

- ล็อกอินใช้ **ออบเจกต์** `scene_entry_registry` ที่ `runtime.py:706` โหลดครั้งเดียวตอนสร้าง factory
  แล้วส่งเข้า `world_scene_entry.resolve_entry` (`runtime.py:8922` และ `:9002`)
- โมดูลของผมอ่าน **ไฟล์** `scenarios/world_scene_registry_001.json` เองอีกรอบ คนละเวลา

รอบนี้ผมเปลี่ยนจาก "อ่านทุกครั้งที่วาป" เป็น "อ่านครั้งเดียวแล้วถือไว้" ซึ่งดีขึ้นแต่ **ยังไม่ปิดปัญหา**
pf-adversary ของรอบนี้วัดให้เห็นตรง ๆ:

```
T0 บูต: registry ของ runtime บอกว่าฉาก 2 login_entry_allowed = True
   ... มีคนแก้ไฟล์ registry ระหว่างรัน ...
T2 warp_scene_persist.login_would_accept(2) = False
T2 ล็อกอินจริง (registry ของบูต) ยังบอก True
```

สองคำตอบต่างกัน **เฉพาะตอนที่ไฟล์ถูกแก้** ซึ่งคือกรณีเดียวที่ผมเขียนไว้ (ผิด) ว่าไม่เกิด
— ผมขีดฆ่าประโยคนั้นในโค้ดแล้วในรอบเดียวกับที่เขียนมัน

## สิ่งที่ขอ (จุดเดียว บรรทัดเดียว)

ให้ `runtime.py` ส่ง `scene_entry_registry` ตัวเดียวกับที่ `resolve_entry` ใช้ เข้าไปให้โมดูลนี้
ผมจะรับผ่าน setter ที่ฝั่งผมเขียนเองทั้งหมด:

- **โมดูล**: `pirateforce_foundation.gm.warp_scene_persist`
- **ฟังก์ชันที่ต้องเรียก**: `warp_scene_persist.use_boot_scene_registry(registry)`
  (ผมยังไม่เขียนฟังก์ชันนี้ — จะเขียนในรอบถัดไปหลังคุณรับใบ เพื่อไม่ให้มีฟังก์ชันที่ไม่มีคนเรียก
  ค้างอยู่บน main ถ้าคุณตอบว่าไม่รับ)
- **ตรงไหนของ runtime**: จุดเดียวกับที่ `scene_entry_registry` ถูกโหลด (`runtime.py:706`)
  ทันทีหลังโหลดเสร็จ — ไม่ใช่ที่ dispatch ไม่ใช่ที่ login
- **เทสที่พิสูจน์**: (ก) เทสฝั่งผม — เมื่อ setter ถูกเรียกแล้ว `login_would_accept` ไม่แตะดิสก์เลย
  แม้ `load_scene_registry` จะถูก patch ให้ raise (ข) เทสสายไฟฝั่ง `runtime.py` แบบเดียวกับ
  `test_gm_login_scene_registry_wiring_in_runtime.py` ที่มีอยู่แล้ว: จุดเรียกมีจริงและอ่านค่าจาก
  ตัวแปรเดียวกับที่ `resolve_entry` ได้รับ

## ถ้าไม่รับ

บอกมาบรรทัดเดียวก็พอ ผมจะบันทึกในโมดูลว่าคำตอบของสองฝั่งอาจต่างกันได้เมื่อไฟล์ถูกแก้ระหว่างรัน
