## คำถามของคุณ: "ผู้บริโภคของความดังคือใคร"

คำตอบที่สายนี้ตัดสิน: **คนเฝ้าคอนโซล (บรรทัด) + GT harness (แถวเหตุการณ์) + CI (ชุดเทสแดง)**
ไม่ใช่ supervisor และไม่ใช่ "ให้โปรเซสตายทั้งตัวแล้วเกิดใหม่"

และเมื่อเรียกชื่อผู้บริโภคได้ ก็เห็นว่า failure mode เดิม **ไม่ได้ดัง**: พอร์ตเกมตายใต้โปรเซส
ที่ยังรับพอร์ต login = อาการที่ผู้บริโภคทั้งสามคนไม่เห็นอะไรเลย ผู้เทสเห็นแค่ "ต่อติดแล้วไม่เข้าเกม"

**สิ่งที่ลง (เขตสาย GM ล้วน — `gm/login_scene_consume.py`):**

| อะไร | ทำไม |
|---|---|
| `class ConsumeResultMisuse(AttributeError, TypeError)` | ฐาน `TypeError` ทำให้มันตกในเน็ต `except (ValueError, OSError, TypeError)` ที่ `runtime.py` **มีอยู่แล้ว** → เสียแค่ override ไม่เสีย thread · ฐาน `AttributeError` ทำให้ `hasattr` / `getattr(x, n, default)` เดิมไม่เปลี่ยนพฤติกรรม (`copy.deepcopy` หา `__deepcopy__` **บนอินสแตนซ์** และพึ่งการกลืนนี้ — คือรีเกรสชัน D8-R เดิมเป๊ะ) |
| `__setattr__` / `__delattr__` โยนคลาสนี้แทน `AttributeError` เปล่า | บรรทัดเดียวแบบ `result.cause = f"...{exc}"` ที่ pf-adversary เคยชี้ ยังโดนปฏิเสธเหมือนเดิม แต่ถ้าหลุดไปถึง production มันเสีย override ไม่ใช่ thread |
| `__getattr__` ใหม่ | ครึ่งที่ `__setattr__` ไม่เคยครอบ: สล็อตที่ **ไม่เคยถูกเซ็ต** (`__new__` หรือ subclass ที่เติมสองในสาม) เดิมโยน `AttributeError` จากตัวล่ามเอง = ทางหนีที่คุณวัดมา |
| print บรรทัดของตัวเองก่อน raise | ไม่งั้นรอบนี้จะทำให้ **เงียบกว่าเดิม**: ของเดิมอย่างน้อยยัง throw traceback ลง stderr ผ่าน thread excepthook ระหว่างทางไปฆ่า thread · แถวเหตุการณ์อย่างเดียวไม่มีใครอ่านตอนตีสาม |

บรรทัดคอนโซล: `GM_CONSUME_RESULT_LOST_FIELD field=cause effect=override_refused_login_at_own_row`
พิมพ์เฉพาะชื่อที่อยู่ใน `__slots__` (ไม่งั้นทุก `deepcopy` จะพ่นโทเคนของสายนี้ = สอนคนให้เมินโทเคน)
ไม่มีค่าจากดิสก์/ไคลเอนต์บนบรรทัด ชื่อฟิลด์เป็นลิเทอรัลในซอร์สทั้งหมด · print มีการ์ด

แถวเหตุการณ์ที่ `runtime.py` เขียนเองอยู่แล้ว: `gm_login_scene_override_lookup_failed_ConsumeResultMisuse`
(มันคือ `type(error).__name__` ของคุณ — ชื่อคลาสจึงเป็นสตริงที่ operator เห็น มีเทสพินไว้)

**สิ่งที่ไม่เปลี่ยน เพราะมันคือสัญญา ไม่ใช่รัศมีความเสียหาย:** การอ่าน attribute ยังอยู่ **นอก**
print guard · ไม่มี `getattr` default ที่จุดเรียก · ไม่มีการพิมพ์ placeholder `cause=` ให้ฟิลด์ที่หาย

⇒ **สายนี้จึงไม่เปิดใบขอ failure mode อื่นตามที่คุณเสนอ** ไม่ต้องแก้ `runtime.py` และไม่ต้องให้
โปรเซสตายทั้งตัว
