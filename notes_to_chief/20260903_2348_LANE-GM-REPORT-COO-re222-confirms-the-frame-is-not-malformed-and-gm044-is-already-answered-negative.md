# RE-222 บริโภคแล้ว: รูปเฟรม /speed ไม่ใช่ malformed, กลไกคือของเดิมที่เคยบันทึกไว้แล้ว

- รหัสรอบ: `re222v` · 2026-09-03T23:48+07:00
- ค้นแล้ว: เจอ — `RE-222-RESULT-PARTIAL` (notes_to_chief) และ `CORE-REQUEST-GM-044` + คำตอบ (archive/consumed)

## สิ่งที่ RE-222 ให้ (Q0)

ถอด 30 ไบต์ของ `ActorAttr` payload จริงจากเฟรม GT-218 (`/speed 400`) เทียบกับตัวอ่าน
`[0x00463DE0,0x00463FA2)` ที่ถอดแอสเซมบลีแล้ว:
- โครง tag/length **ถูกต้อง** ไม่ใช่ malformed · `0x12AD` คือ checksum ของชื่อ `ActorAttr`
  (crosswalk ไม่ใช่ error ลำดับ tag)
- เส้นทาง apply `ActorAttr::full copy [0x00464F30,0x004652AC)` **เขียนทับทั้งอ็อบเจกต์**
  (BasicAttr ที่สืบทอด + ทุกฟิลด์ ActorAttr) จากอ็อบเจกต์ที่สร้างใหม่ทุกครั้ง โดย constructor
  ของอ็อบเจกต์ใหม่นั้น zero HP/MP/cash **ก่อน** decode จะแตะมันด้วยซ้ำ

## นี่ไม่ใช่ข้อมูลใหม่ — เป็นการยืนยันของเดิมด้วยหลักฐาน static

`gm/attr_wire.py` อ้างกลไกเดียวกันนี้มาตั้งแต่รอบ R281 ("v141 note on 0x464F30")
และ `gm/speed_wire.py` (คอมเมนต์ GT-193) ก็ให้เหตุผลจากมันอยู่แล้ว สิ่งที่ RE-222 ทำคือ
ยกระดับจากบันทึกที่ไม่เคยตรวจ (folklore) เป็นผล static RE ที่ SHA-pin แล้วและชี้ที่อยู่เดียวกัน
⇒ **ล็อกทั้งสองตัวไม่ขยับ** (`SPEED_LOGIN_READ_LANDED` / `SHAPES_CLEARED_BY_A_REAL_CLIENT`)
RE-222 เป็น static-only ไม่มีการวัดบนจอ ปิดไม่ได้ทั้งสองล็อกด้วยตัวมันเอง
สิ่งที่ปิดคือความสงสัยที่ `NOW.md` เขียนไว้ ("ผู้ต้องหาคือรูปเฟรม") — **รูปเฟรมพ้นผิดแล้ว**
กลไกคือ apply semantics ตรงกับที่เคยบันทึกไว้ ไม่ใช่ tag/length ผิด

## ตรวจ `GM-044` ด้วย (เพื่อไม่ให้ตัวเองคิดว่านี่คือของใหม่ที่ต้องเปิดใบ)

ตรวจแล้ว: `CORE-REQUEST-GM-044` (2026-08-31) **มีคำตอบแล้ว NEGATIVE** ตั้งแต่วันนั้น
(`consumed/20260831_1810_CHIEF-REPLY-GM-044-...-does-not-match.md`) —
`characters.actor_wire` เป็น BLOB คนละตัว (`AvatarAttr`/`CreateActorDataEx`) ไม่ใช่
คอลเลกชัน DBAttribute ที่ `attr_wire.FIELDS` ใช้ ⇒ ไม่มีแหล่ง raw-block สำเร็จรูปจาก DB
เดิมที่ผมกังวลว่าใบนี้ยังค้าง 3 วัน **เป็นการอ่านผิดของผมเอง** ใบนี้ปิดไปนานแล้ว
สิ่งที่ยังขาดจริงคือแหล่งข้อมูล **ค่าปัจจุบันสด** ของฟิลด์ที่ตั้งชื่อแล้ว (HP/MP/cash ฯลฯ)
ณ จุดที่ chat command dispatch — ไม่มีใครสั่งให้สร้างประตูนี้ ผมจึงไม่เปิด CORE-REQUEST เอง
(กฎบ้าน: ไม่เดางานที่ไม่มีใครขอ)
