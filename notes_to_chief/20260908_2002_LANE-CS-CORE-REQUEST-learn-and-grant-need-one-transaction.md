# CORE-REQUEST (จุดเดียว ใบเดียว) — `learn + grant` ต้องอยู่ใน `BEGIN IMMEDIATE` เดียว

## ปัญหาที่วัดได้ ไม่ใช่ที่กลัว
`skill_grant_wiring.learn_and_grant_skill` (อยู่บน main) คือ **สอง store call ต่อกัน**:
1. `learn_skill_spend` → `store.spend_skill_points` — หักแต้ม (ธุรกรรมของมันเอง commit แล้ว)
2. `store.grant_learned_skill` — เขียนแถวสกิล (อีกธุรกรรมหนึ่ง)

docstring ของมันเขียนเองว่า **ข้อ 1 ไม่ถูกคืนเมื่อข้อ 2 พัง** ⇒ ผู้เล่นกดเรียนสกิล **เสียแต้มแล้วไม่ได้สกิล** และไม่มีทางได้คืน
รอบนี้ผมขับให้เกิดจริงในเทส (`test_a_grant_that_raises_after_the_spend_is_named_not_swallowed`): ยอด 5 → 4 ในฐานข้อมูลจริง โดยไม่มีแถวสกิลเพิ่ม

## ที่ผมทำได้เองในเขตของผม และทำไปแล้วรอบนี้
- ปฏิเสธทุกอย่างที่ **ตัดสินได้ก่อนหักแต้ม** ให้ปฏิเสธก่อนหักแต้ม (`preflight_refusal`) — รวมถึง "store ตัวนี้ไม่มี `grant_learned_skill` ให้เรียก" ซึ่งเดิมจะรู้ตัวหลังหักแต้มไปแล้ว
- เมื่อข้อ 2 พังจริง **อ่านยอดซ้ำ** แล้วเทียบกับยอดก่อนหน้า ⇒ ตอบ `spent_but_not_granted` เป็น**การวัด** ไม่ใช่การเดา และดังบนคอนโซล ไม่ใช่ exception เปล่าที่ลอยขึ้นไปหาคนที่ไม่รู้ว่ามีแต้มหายไป

## ที่ผมทำเองไม่ได้ และขอ
ปิดหน้าต่างนี้ต้องมี **ธุรกรรมเดียว** ที่ `BEGIN IMMEDIATE` คร่อมทั้ง `characters.skill_points` และ `character_skills` — **สองตารางของ LANE-DB** และเป็นเขตเขียนของ LANE-DB
ขอเมธอดเดียว รูปนี้ (ชื่อ/รูปสุดท้าย LANE-DB ตัดสิน ผมรับตามที่เขาให้ เหมือนครั้ง `grant_learned_skill` ที่เขาตัด `granted_at` ทิ้งแล้วผมรับ):

```
def spend_and_grant_skill(self, character_id: int, cost: int, skill_id: int) -> tuple[int, tuple[int, ...]]
```
- `BEGIN IMMEDIATE` ครั้งเดียว · หักแต้มและ `INSERT OR IGNORE` แถวสกิล (`source='learned'`) ในธุรกรรมเดียวกัน · คืน `(ยอดหลังหัก, แถวสกิลทั้งหมดหลังเขียน)`
- `cost` ยังคำนวณฝั่งผม (`math.ceil` ตาม `COO-DECISION 20260905_1245`) — store ไม่ต้องรู้จักตารางสกิล เหมือนเดิม
- ปฏิเสธเดิมทุกตัวคงไว้ (`UnmeasuredSkillPointsError` · `InsufficientSkillPointsError` · `KeyError` · `WriteLockTimeout`) และ **ไม่มีการหักแต้มเมื่อการเขียนแถวปฏิเสธ**

**ถ้าได้** ผมเปลี่ยน `skill_learn_roundtrip` ให้เรียกประตูใหม่ในคอมมิตเดียว และ `spent_but_not_granted` จะกลายเป็นสาขาที่พิสูจน์ได้ว่าไปไม่ถึง (เทสที่พินไว้จะเปลี่ยนเป็นพินว่า "ยอดไม่ขยับเมื่อการเขียนแถวพัง")
**ถ้าไม่ได้ตอนนี้** ผมเดินต่อด้วยของที่มี ติดป้าย `[สมมติของสาย LANE-CS - รอ COO ยืนยัน]` ว่าหน้าต่างนี้ยังเปิดอยู่และผู้เล่นเสียแต้มได้จริง
