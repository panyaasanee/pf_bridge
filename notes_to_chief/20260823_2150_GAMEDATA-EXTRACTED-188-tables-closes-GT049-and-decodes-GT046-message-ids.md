**เหลือค้างข้อเดียว:** ยังไม่รู้ว่า **ใครยิง id 131** (ต้องหาในไบนารี — งาน static ต่อ)

### GT-046 — **message id ทั้งสามที่ "ยังไม่ทราบความหมาย" ถอดได้ครบ**

GT-046 พบว่า handler ของ `PickupTerrainThing` แตกตาม status byte เป็น message id `0x1F`/`0x03`/`0x22`
แต่ระบุว่า *"meanings of 0x03 and 0x22 remain unbound"* — **ตอนนี้ bound แล้วทั้งสาม:**

| status | msg id | ข้อความจริง |
|---|---|---|
| `0xFC` | `0x1F` (31) | **"ระยะทางไกลเกินไป!"** |
| `0xFD` | `0x03` (3) | **"ช่องว่างในกระเป๋าไม่เพียงพอหรือจำนวนไอเทมดังกล่าวมีถึงจำนวนจำกัดแล้ว!"** |
| `0xFE` | `0x22` (34) | **"ไอเทมของผู้อื่น ไม่สามารถเก็บขึ้นมาได้!"** |

*(อ่าน MESSAGE ได้ 907/907 แถว ตรงกับสารบัญพอดี · id ทั้งสามลงบนข้อความเรื่องการเก็บของทั้งหมด)*

### 🔴 สามบรรทัดนี้ปิดคำถามที่ค้างในบันทึกลูทมาทั้งวัน

1. **`0xFE` ⇒ เกมมีระบบสิทธิ์/เจ้าของไอเทมจริง** — ช่อง "สิทธิ์/ล็อกเจ้าของ: ยังไม่รู้" **ปิดได้**
   ⇒ เซิร์ฟเวอร์เราต้องมีเจ้าของของที่ดรอป และต้องปฏิเสธคนอื่น
2. **`0xFD` ⇒ การเก็บล้มเหลวเพราะกระเป๋าเต็ม/ชนเพดานจำนวนได้** ⇒ ต้องเช็คก่อนให้ของ
3. **`0xFC` ⇒ ยืนยันว่ามีการเช็คระยะ** (GT-046 อนุมานจากโค้ด ตอนนี้ข้อความยืนยัน)
