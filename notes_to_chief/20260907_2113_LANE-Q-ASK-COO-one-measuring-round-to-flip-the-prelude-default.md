# ขอทางเดียวในสองทาง เพื่อ "พลิกค่าเริ่มต้น" ของ prelude ให้เป็นของจริง — ตัดสินไปแล้วและเดินต่อแล้ว

## ติดอะไร
รอบนี้ทำให้ prelude ของเกมเอง (`gamedata/lua/utility.lua` ที่ประกาศ `rate`) รันได้ในแซนด์บ็อกซ์ ⇒ สคริปต์ทริกเกอร์ **17 ไฟล์ 34 จุดเรียก** ที่เดิมตายทั้งไฟล์ที่ `attempt to call a nil value (global 'rate')` เดินได้แล้ว
แต่ **seam ยังปิดโดยค่าเริ่มต้น** เพราะเปิดเมื่อไร ตัวเลขที่เป็นเครื่องวัดของสายขยับพร้อมกันสี่ตัว:
`BASELINE_TOTAL_STUB_CALLS` (2597) · `BASELINE_TOTAL_REAL_CALLS` (2852) · `KNOWN_LOAD_FAILURES` · `KNOWN_ENTRY_POINT_CALL_FAILURES`
คอนเทนเนอร์รอบนี้ **ไม่มี `lupa`** (`ModuleNotFoundError` วัดแล้ว) และ COO-DECISION `20260907_1941` ห้าม `pip install` กลางรอบ ⇒ **วัดค่าใหม่ทั้งสี่ไม่ได้** และการปักหมุดที่ไม่มีใครวัดคือสิ่งที่กฎบ้านห้ามตรง ๆ

## grep แล้ว: ไม่ใช่ปัญหาของเกต
`gate-windows.yml:155` ติดตั้ง `lupa==2.8` อยู่แล้ว ⇒ **ไม่ต้องออก CORE-REQUEST ให้ chief** ปัญหาอยู่ที่คอนเทนเนอร์คลาวด์ ไม่ใช่ CI
และเกตก็บอกตัวเลขใหม่ให้เราไม่ได้ด้วย มันบอกได้แค่ "แดง/เขียว" — ถ้าเดาตัวเลขผิด ผลที่ได้คือเกตแดงพร้อมเลขที่ยังไม่รู้อยู่ดี

## ทางเลือกที่มี
- (ก) **รอรอบที่คอนเทนเนอร์บังเอิญมี `lupa`** — ใบ `1941` ของท่านเองบอกว่าเกิดขึ้นได้และไม่ถาวร · ข้อเสีย: รอโดยไม่รู้ว่านานแค่ไหน และเป็นการรอที่ไม่มีใครควบคุม
- (ข) **ขออนุญาตติดตั้ง `lupa` เฉพาะ "รอบวัด" หนึ่งรอบ** โดยผูกเงื่อนไขให้แน่น: บรรทัด `PKG_ENV: lupa=<ver> python=<ver>` ทั้งตอนเริ่มและตอนจบการรัน · ค่าไม่ตรง = การรันเป็นโมฆะ · ผลลัพธ์เดียวที่รอบนั้นส่ง = คอมมิตที่พลิกค่าเริ่มต้น + หมุดสี่ตัวที่วัดมา · ห้ามใช้ผลนั้นอ้างเรื่องอื่น
- (ค) ปล่อยให้ seam ปิดถาวร — **ผมไม่เลือกข้อนี้** เพราะแปลว่า 17 ไฟล์ที่ทำให้เดินได้แล้วจะไม่มีวันเดินในการกวาดจริง

## เลือกอะไรไปแล้ว (ไม่รอคำตอบ)
ส่ง seam แบบ **ปิดโดยค่าเริ่มต้น** ในรอบนี้ พร้อมเทสที่พิสูจน์ความสามารถ **ด้วยส่วนต่าง** (คอร์ปัสเดิม นาฬิกาเดิม เปิด/ปิด prelude: เซตไฟล์ที่ล้มด้วย nil `rate` ต้องไม่ว่างเมื่อปิด และว่างเมื่อเปิด) ซึ่งไม่ต้องใช้ตัวเลขสัมบูรณ์ใหม่แม้แต่ตัวเดียว และ **เกตเป็นคนรันจริง** เพราะเกตมี `lupa`
ติดป้าย `[สมมติของสาย LANE-Q - รอ COO ยืนยัน]` ไว้ที่ข้อเดียว: **ว่าทางที่ถูกคือ (ข)** — ขอรอบวัดหนึ่งรอบ ไม่ใช่รอโชค

## ถ้าผิดต้องย้อนอะไร
ย้อนได้ก้อนเดียวและถูกมาก: `prelude=` เป็นพารามิเตอร์ที่ค่าเริ่มต้นเป็น `None` ทุกจุด ไม่มี migration ไม่มีเฟรม ไม่มีแถว DB · ถ้าท่านสั่งให้ปิดถาวร = ลบโมดูล `lua_api/prelude.py` กับไฟล์เทสของมัน แล้วถอนพารามิเตอร์สี่จุดใน `script_host.py` จบ

## เพิ่มหลังผล adversary คืน (สำคัญกว่าข้อบน — ขอคำตัดสินข้อนี้ก่อน)

**ใครเป็นเจ้าของสตรีมสุ่มของ `rate` และมันถูกคีย์ด้วยอะไร**
adversary วัดแล้ว: `Prelude` ก้อนเดียว seed ทุก host เท่ากันหมด (5 host อิสระตอบ `math.random` ครั้งแรกเป็น `465252` เหมือนกันทุกตัว) และ `time.time` ละเอียดแค่ระดับวินาที การอ่านใหม่ต่อ host จึงไม่ช่วย
`load_corpus`/`run_corpus_entry_points` รับ `Prelude` **ก้อนเดียว** แล้วแจกให้ทั้ง 616 host — ซึ่งเป็นรูปการใช้เดียวที่ API นี้เปิดให้
⇒ dispatcher ที่อ่าน prelude ตอนบูตจะทำให้ **ผู้เล่นทุกคน ที่ทุกทริกเกอร์ ได้ผลทอยเดียวกัน ตลอดอายุโปรเซส** และเดินออกมาทอยใหม่ก็ได้เลขเดิม
เอนจินจริง seed **ครั้งเดียว** ตอน LuaAdapter init เข้าสตรีมร่วมที่เดินหน้าเรื่อย ๆ ⇒ การ seed ต่อ host คือการกลับด้านมัน

**ผมไม่แก้ในรอบที่เจอ** เพราะคำตอบมีสามแบบและแต่ละแบบมีเจ้าของคนละคน:
- (1) **ต่อฉาก** = world state ของ LANE-A ตาม PANYA-DECISION `20260905_1057` (โลกอยู่ในหน่วยความจำเซิร์ฟเวอร์ต่อฉาก) — ถ้าใช่ ผมต้องขอ interface จาก A ไม่ใช่สร้างสมุดที่สอง
- (2) **ต่อตัวละคร** = แถว/คอลัมน์ของ LANE-DB
- (3) **ต่อการเรียกจริง ๆ** = ต้องบอกด้วยว่าอะไรเป็น seed เพื่อให้ผู้เล่นสองคนที่ชนทริกเกอร์คนละอันในวินาทีเดียวกันไม่ได้เลขเดียวกัน
ผมเลือก **ไม่เดา** และปักข้อบกพร่องนี้ไว้เป็นเทส (`test_one_prelude_seeds_every_host_it_is_given_to_identically`) เพื่อให้รอบที่แก้มันแดงตรงจุด · seam ยังปิดโดยค่าเริ่มต้น **จึงไม่มีผู้เล่นคนไหนโดนวันนี้**
ถ้าผิดต้องย้อนอะไร: ไม่มีอะไรต้องย้อน — สิ่งที่ค้างคือ "ยังไม่พลิกค่าเริ่มต้น"
