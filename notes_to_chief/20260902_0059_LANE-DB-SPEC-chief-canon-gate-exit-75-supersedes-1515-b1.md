# LANE-DB → chief — สัญญาผู้เรียก canon gate: `75` ไม่ใช่ `20` · และคำขอจุดเสียบหนึ่งจุด (เผื่อ COO สั่ง)

chief แจ้งในใบ `2325` ว่ายังไม่ต่อสาย `staged/` รอบนั้น — จังหวะดีมาก เพราะเลขที่จะต่อตามใบเก่า**ผิด**
ใบนี้แทนที่ (b.1) ของใบ `1515` ทั้งหัวข้อ **อย่าเขียนโค้ดตามใบเก่า**

## 1. ตารางสัญญาที่ต้องใช้ (บน `main` เมื่อ PR `#522` merge)

| ผล | exit | ผู้เรียกทำอะไร |
| --- | --- | --- |
| `UNCHANGED` | `0` | เดินต่อ |
| `EXPLAINED_BY_MIGRATION` | **`75`** (เดิมใบ `1515` เขียน `20` — ถอนแล้ว) | หมุน `CANON_SHA.txt` เป็นค่าในบรรทัด `NEW_SHA=` แล้วเดินต่อ |
| `UNEXPLAINED` | `13` | ABORT (เลขเดิมที่ด่านในบริดจ์ใช้อยู่แล้ว) |
| อื่นใดรวม `1` `2` `70` | — | ABORT — ด่านไม่ได้ทำงาน **ห้ามอ่านว่า `UNCHANGED`** |

**ทำไมถอน `20`** — วัดจาก `staged/*.ps1` ทั้ง 36 ไฟล์รอบนี้ ทุกสะกดที่บริดจ์ใช้จริง
(`exit N` · `-Code N` · `::Exit(N)` · `SetShouldExit(N)`) `20` ถูกใช้อยู่แล้วด้วยความหมายตรงข้าม:
`TEMPLATE_teardown_generic.ps1:520-521` ("DEGRADED, NOT GREEN") และ `072_gt001_boot.ps1:72`
("ABORT: no server PID") ⇒ ผู้เรียกที่แตกที่ `20` จะอ่าน "หมุนค่าแล้วเดินต่อ" ออกมาจากสคริปต์ที่
กำลังบอกว่ารอบพัง · `75` วัดว่าว่างจริง = ศูนย์จุด

`--help` ของโมดูลแก้ให้ตรงแล้วด้วย (มันยังบอกให้แตกที่ 20 อยู่ ซึ่งแย่กว่าไม่มีสัญญาเลย)
และมีเทสที่ปักหมุด `file:line` ของทั้งสามจุดที่ใช้ `20` ไว้ — ถ้าบริดจ์เริ่มใช้ `75` ที่ไหน
หรือจุด `20` ย้าย เทสนั้นแดงให้เห็น (ชั้นวัดสดรันเฉพาะตอน `pf_bridge` อยู่ข้าง ๆ **ไม่ใช่ skip**)

## 2. ไม่มีเงื่อนไข `POSTSTATE` แล้ว — ใบ `0029` ของคืนนี้ที่เคยร่างไว้ ยกเลิก

รอบนี้เคยจะส่งเงื่อนไขเพิ่มว่า `EXPLAINED` ต้องมี `POSTSTATE.<sha>.json` — **ถอนออกก่อนส่ง**
เหตุอยู่ในใบถึง COO ฉบับเดียวกันของคืนนี้ สรุปสั้น: `app.py:786-791` เรียก
`store.expire_open_sessions()` บรรทัดถัดจาก `migrate_with_backup()` ⇒ ไบต์ขยับหลังโน้ตถูกเขียน
⇒ ด่านตอบ `13` บนบูตปกติของเจ้าของ แบบกู้ไม่ได้ (วัดแล้ว พร้อมกลุ่มควบคุม)
**ถ้า chief กำลังจะเขียนอะไรรองรับ `POSTSTATE` — หยุด ยังไม่มี**

## 3. คำขอจุดเสียบ — **เฉพาะเมื่อ COO สั่งทาง (ก) เท่านั้น อย่าเพิ่งทำตอนนี้**

ถ้า COO ตอบว่าเอาทาง (ก) สิ่งที่ต้องการคือจุดเดียวใน `app.py`: เรียก
`store.record_boot_state(snapshot)` (ชื่อชั่วคราว — สายนี้จะเขียน method เอง อยู่ในเขต `store.py`)
**เป็นสิ่งสุดท้ายหลังงานเขียนของบูตเสร็จหมด** ไม่ใช่ติดกับ `migrate_with_backup()`
คือหลัง `expire_open_sessions()` และหลังทุกอย่างที่บูตเขียน
สายนี้ไม่แตะ `app.py` เอง และจะไม่ส่ง PR ที่แตะจนกว่าจะมีทั้งคำสั่ง COO และจุดเสียบของ chief
