# กฎการรับเข้าของจุด `report-only` คืออะไร — เพราะเพดานอยู่ใน hook ไม่ได้

## ติดอะไร
`lane_hooks.fire()` พิมพ์ `LANE_HOOK_FIRED` **แบบไม่มีเงื่อนไข ก่อน**เรียก hook และอยู่บนเส้นที่วิ่งตั้งแต่
ไบต์แรกของซ็อกเก็ตที่ยังไม่ยืนยันตัวตน ⇒ **ทุก seam report-only เป็นตัวขยายต่อเฟรม** และเพดานฝั่ง hook
(แบบที่ `lane_gm_unknown_vital_counter` มี) ปิดได้แค่ครึ่งเดียว: มันหยุด `session.events` ได้ แต่หยุดบรรทัดคอนโซลไม่ได้

รอบนี้ผมถอด GM-063 ออกเพราะมันพิมพ์ id **ผิด** · แต่ `0x6CEC` (GM-062) พิมพ์ id **ถูก** ตลอดไป **ไม่มีเพดาน**
ลงคอนโซลเดียวกัน และ **ไม่มีใครปฏิเสธมัน** — วัดแล้ว 2000 เฟรมก่อนล็อกอิน = 2000 บรรทัด + 2000 event ค้างถาวร
(≈ 97 MiB ต่อ 1e6 เฟรม/คอนเนกชัน) + 2000 syscall

## ทางเลือกที่ผมเห็น
1. **กฎฝั่งผู้เรียก**: จุด report-only ยิงได้เฉพาะหลังล็อกอิน (ก่อนล็อกอินนับเฟรมอย่างเดียว ไม่ยิง)
2. **กฎฝั่ง `fire()`**: `fire()` เองมีเพดานต่อ (session, point) และ `LANE_HOOK_FIRED` อยู่หลังเพดาน ไม่ใช่ก่อน
3. **กฎฝั่ง sink**: `session.events` มีเพดาน/หน้าต่างเลื่อน แทนที่จะเป็นลิสต์ที่โตไม่จำกัด

## เลือกอะไรไปแล้ว
**ยังไม่เลือก และยังไม่ลงมือ** — เพราะ (2) และ (3) แตะ `runtime.py`/`lane_hooks` ที่กระทบทุกสายพร้อมกัน
และ (1) เปลี่ยนความหมายของทุกใบ P-3 ที่ตั้งใจจะเห็นเฟรมก่อนล็อกอิน · ผมทำได้ทั้งสามแต่ย้อนยาก
[สมมติของสาย LANE-E - รอ COO ยืนยัน]: ถ้าไม่มีคำตอบภายในรอบหน้า ผมจะเดินทาง **(2)** เพราะเป็นที่เดียวที่คุมได้
ทั้งคอนโซลและ event ในการแก้เดียว และไม่เปลี่ยนสัญญาของใบ P-3 ใบไหนเลย
