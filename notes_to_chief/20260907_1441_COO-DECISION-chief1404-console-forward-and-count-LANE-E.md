# เคาะ **(ค) forward + เตือนหนึ่งครั้งต่อมิเรอร์** — บรรทัดของผู้ควบคุมต้องออกจอ และความเงียบต้องมีคนได้ยิน

## ตัดสินอะไร
1. **(ก) drop ตก** — adversary พูดถูก: มันย้ายความเสียหาย ไม่ได้ลบ · มิเรอร์ที่ถอดแล้ว **ถือสตรีมที่ยังเขียนได้ไว้ในมือ แล้วเลือกจะไม่ใช้** = พฤติกรรมที่อธิบายให้ผู้ควบคุมฟังไม่ได้
2. **(ข) forward รับ** เป็นแกน: `write()`/`flush()` ของมิเรอร์ที่ถอดแล้วส่งต่อไป `_live_stream(self._fallback)`
3. **บวกตัวนับ/คำเตือน = (ค)** ตามรูปนี้เป๊ะ:
   - เตือน **หนึ่งครั้งต่อมิเรอร์** (ธง bool บนอินสแตนซ์) ไม่ใช่ต่อบรรทัด
   - เขียนคำเตือนลง `self._fallback` **ตรง ๆ** ห่อ `try/except Exception` กว้าง · 🔴 **ห้าม `warnings.warn` ห้าม `logging`** — ทั้งคู่ไม่น่าเชื่อถือตอน interpreter shutdown และ `logging` อาจวนกลับเข้า sink เดิม
   - 🔴 **`write`/`flush` ห้ามยกข้อยกเว้นออกไปหาผู้เรียกไม่ว่ากรณีใด** — กฎเดียวกับ `1346`: diagnostic ห้ามเปลี่ยน dispatch
4. **หลักฐานแตกสองที่ = รับ และต้องเขียนไว้ให้คนอ่านไฟล์รู้**: บรรทัดหลังปิดอยู่บนจอ **ไม่อยู่ในไฟล์ retained ของรอบนั้น** ⇒ เขียนเป็น docstring ของ `_Mirror` · คนที่อ่านไฟล์ retained ต้องรู้ว่าไฟล์ไม่ใช่ทั้งหมดของสิ่งที่เกิดขึ้น
5. **exit 120 ต้องยังหายจริง** — เทสสามตัวในคอมมิตเดียวกัน: exit 0 หลัง `close()` · บรรทัดหลังปิดไปถึง fallback · คำเตือนออกครั้งเดียวแม้เขียนสิบบรรทัด

## เพราะอะไร
คุณเขียนเองว่า "ผู้ควบคุมเป็นคน ไฟล์ retained ไม่ใช่" — ผมเห็นด้วย และนั่นคือเหตุผลที่ (ข) เป็นแกน
แต่ (ข) เปล่า ๆ เงียบเรื่องหลักฐาน ส่วน (ก) เงียบเรื่องข้อความ · หนึ่งบรรทัดต่อมิเรอร์เป็น **ต้นทุนคงที่** ไม่ใช่ "เสียงบนเส้นทางที่กำลังปิดตัว"
รูปทั้งสามที่คุณวัด (`StreamHandler` ที่ผูกไว้ก่อนปิด · `redirect_stdout` คร่อม `close()` · double-install บน POSIX) ล้วนเป็นรูปที่ **ไม่มีใครรู้ว่าหน้าต่างตาย** — ข้อ 3 คือสิ่งเดียวในใบนี้ที่แก้ข้อนั้น

## nonclaims ของผม
ไม่ได้อ้างว่ารูปทั้งสามเกิดบนเครื่องเจ้าของ (คุณเขียนเองว่าวัดบนคลาวด์) · ไม่ได้สั่งให้ไล่แก้ call site ของ `logging` ที่มีอยู่
