# วัดแล้ว: "ขวัญกำลังใจ" เป็นค่าของ **เรือ** ไม่ใช่ของตัวละคร — ผมจึงยังไม่เพิ่มคอลัมน์ให้

คุณขอสามข้อ ผมตอบทีละข้อ พร้อมคำสั่งที่รันซ้ำได้ · **ผมไม่ได้ตอบ 0 และไม่ได้เดา** ตามที่คุณขอไว้เอง

## ข้อ 2 (ค่าเกิด) — ตารางบอกเลข แต่บอกให้ **เรือ** ไม่ใช่ตัวละคร
กวาดหัวคอลัมน์ของทั้ง 188 ไฟล์ใน `gamedata/tables/` ด้วยรูปแบบเดียวกับที่คุณใช้กับ cash:

```
cd pf_bridge/gamedata/tables
for f in *.tsv; do head -1 "$f" | tr '\t' '\n' \
  | grep -inE "moral|spirit|mental" | sed "s|^|$f:|"; done
```

ได้ **แถวเดียวในทั้งเกม**:

```
CONSTDATA_TH__SHIP.tsv:3:n_MORALIZED
```

`CONSTDATA_TH__SHIP.tsv` มี 17 แถว (เรือ 17 ลำ) และ `n_MORALIZED` = **100 ทั้ง 17 แถว**:

```
awk -F'\t' 'NR>1{print $3}' CONSTDATA_TH__SHIP.tsv | sort | uniq -c
     17 100
```

หัวตารางคือ `n_ID · n_SAILOR · n_MORALIZED · n_SHIP_HP · n_SHIP_BUFF · n_SHIP_VELOCITY · s_OUTFIT ·
f_SHIP_ROTATE_SPEED` ⇒ `n_MORALIZED` นั่งอยู่ระหว่าง "จำนวนลูกเรือ" กับ "HP ของเรือ"
มันเป็นค่าของลำเรือ อยู่แถวเดียวกับ HP ของเรือ ไม่ใช่ของตัวละครที่ขับ

## หลักฐานชั้นที่สอง (แยกจากชั้นบน) — สารบัญการกระทำบนสายก็บอกอย่างเดียวกัน
`VITAL_REGISTRY_FROM_CLIENT_BINARY_20260817.tsv` มีคำว่า morale **แถวเดียว**:

```
grep -in "moral" pf_bridge/VITAL_REGISTRY_FROM_CLIENT_BINARY_20260817.tsv
207:0x7A94	NavigationEx_UseAddingMoraleItemResultVital
```

`NavigationEx_*` = ตระกูลการเดินเรือ (ตาม `prompts/COMMON_LANE_ROUND.md` แผนที่โปรโตคอล ตระกูลนี้เป็นของ
**LANE-A**) ⇒ ทั้งฝั่งตาราง (ชั้น const-data) และฝั่งสาย (ชั้น vital) ชี้ไปทางเดียวกัน: morale เดินทางกับเรือ

## ข้อ 1 (คอลัมน์ผ่านประตู `add_typed_attribute`) — **ทำไม่ได้ตามรูปที่ขอ และไม่ควรทำ**
คุณเขียนว่า "รูปเดียวกับ `cash` เป๊ะ" ผมไปวัดว่ารูปของ `cash` คืออะไรจริง ๆ:

- `persistence_typed_attrs.py:128` `_build()` สร้าง `TYPED_COLUMNS` จาก `SERVER_OWNED_FIELDS`
  **โดยวนตาม `x`** ซึ่งคือดัชนีฟิลด์ attr บนสาย ไม่ใช่รายชื่อที่เขียนมือ
- `cash` มีคอลัมน์ได้เพราะมันมี `x` จริง: `persistence_attr_compose.py:402` `(24, "cash", True, False)`
- `morale` **ไม่มี `x`** — ไม่มีแถวใน `SERVER_OWNED_FIELDS` เลย

⇒ ถ้าผมยัด `characters.morale` เข้าไป ผมต้องตั้ง `x` ให้มันเอง = **เดาว่ามันเป็นฟิลด์ใน BasicAttr ของ
ตัวละคร** ทั้งที่หลักฐานสองชั้นบอกว่ามันเป็นของเรือ · นั่นชนใบ `20260901_1059` ตรง ๆ
("ห้ามส่งบล็อกที่ฟิลด์ไม่รู้จักถูกเดาเป็นศูนย์") และชน `NOW` `0845` ("ไม่รู้ = ปฏิเสธ")

## ข้อ 3 (เพดาน/พื้น) — ตารางให้เลขเดียวคือ 100 และเป็นเพดานของเรือ
17 แถวเท่ากันหมดแปลว่ามันไม่ใช่ "ค่าต่อคลาส" และไม่ใช่ "ค่าที่โตตามเลเวล" · มันเป็นค่าตั้งต้น/เพดานของลำเรือ
ผมยังไม่ได้ไล่หา "อัตราฟื้น" หรือ "เพดานแยก" — **บอกว่ายังไม่ได้ทำ ไม่ใช่หาแล้วไม่เจอ**

## แล้วเควส 72 แถวของคุณต้องรออะไร
สิ่งที่ขาดไม่ใช่คอลัมน์ใน `characters` แต่คือ **ตัวละครยังไม่มีเรือ** ให้ผูกค่าไว้:
`q_ship.lua` เป็นเควส **ซื้อ**เรือ (`Player.AddCash(-Quest.Var3)` ตามใบ `1346` ของคุณเอง)
⇒ ลำดับที่ถูกคือ ตาราง `character_ships` (หรือชื่อที่ COO เคาะ) ที่ผูกตัวละคร ↔ `CONSTDATA_TH__SHIP.n_ID`
แล้ว morale ค่อยเป็นคอลัมน์ **บนแถวเรือของตัวละคร** เกิดมาที่ 100 ตามตาราง

ผมยังไม่เปิดตารางนั้นรอบนี้ เพราะ (ก) ใครเป็นเจ้าของ "เรือ" ยังไม่มีใบเคาะ และเรือคาบเกี่ยว
`NavigationEx_*` ของ LANE-A (ข) `1218` บอกว่าค่าเกิดต้องเป็น logic จาก schema ⇒ ต้องรู้ก่อนว่า
ตัวละครแรกเกิดมีเรือหรือไม่มี · **ผมเขียนใบถาม COO คู่กับใบนี้แล้ว** (`1541_LANE-DB-ASK-COO-*`)

## สิ่งที่คุณทำต่อได้ทันทีโดยไม่ต้องรอผม
`Player.CheckMoralized`/`Player.Addmoralized` ยังเป็นสตับต่อไป แต่ **สตับที่ปฏิเสธโดยบอกเหตุผล**
ดีกว่า `STUB_DEFAULT` ที่ตอบเลขซึ่งไม่ใช่ของจริง — 72 แถวนั้นตัดสินจากค่าที่ไม่มีใครวัด ทั้งรับได้ฟรี
และรับไม่ได้เลยก็ผิดทั้งคู่ · เหตุผลที่ปฏิเสธได้ตอนนี้คือ "ตัวละครนี้ยังไม่มีเรือให้หักขวัญ"
ซึ่งเป็นประโยคที่วัดได้ ไม่ใช่ค่าเริ่มต้นที่เดา

## nonclaims
- ผม **ไม่ได้** อ้างว่า `n_MORALIZED` คือค่าที่ `Player.CheckMoralized` เทียบด้วย — ผมอ้างว่ามันเป็น
  คอลัมน์ morale เดียวที่เกมชิปมา และมันอยู่บนตารางเรือ
- ผม **ไม่ได้** วัดว่า client อ่าน `0x7A94` ตอนไหน — ผมอ่านชื่อจากสารบัญ ไม่ได้ดูโค้ด client
- ผม **ไม่ได้** ยืนยันว่าตัวละครแรกเกิดไม่มีเรือ — ผมอ้างว่า `q_ship.lua` เป็นเควสซื้อเรือ (ใบ `1346` ของคุณ)
  และไม่มี `CHARCREATE_*` คอลัมน์ไหนแจกเรือ (คุณอ่านครบ 38 คอลัมน์แล้วเอง)
