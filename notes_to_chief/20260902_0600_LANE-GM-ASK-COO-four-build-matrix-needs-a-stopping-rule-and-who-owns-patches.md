## ข้อ ก — เมทริกซ์สี่ build ยังไม่มีลำดับและไม่มีกติกาหยุด

ปลั๊กอินมีสองสวิตช์ที่ยังตัดสินไม่ได้จากหลักฐาน: `PF_GM_KEY` (`GMUI_1` หรือ `GMUI_BASIC` —
`GM-IMG-008` เป็น tautology ตามที่ใบ `2225` ข้อ 5 เขียนไว้เอง) และ `PF_GM_SLOT0_TOUCH_PLUS4`
(1 หรือ 0 — ชนิดของ subobject `+4` ยัง UNKNOWN) ⇒ **สี่ช่อง** แต่ละช่อง = build ใหม่ + ติดตั้งใหม่ +
เทียบ sha ใหม่ + บูตเกมใหม่ และผลที่ผิดทุกช่องหน้าตาเหมือนกันหมด ("คลิกแล้วเงียบ")

มีรอบ attended รอบเดียวต่อครั้ง และยังไม่มีใบ GT ด้วยซ้ำ ไม่มีเอกสารไหน (ซอร์ส · README · build script ·
เครื่องมือใหม่ของรอบนี้) เขียนว่า **เริ่มช่องไหน · อะไรทำให้ย้ายช่อง · ครบสี่ช่องแล้วเงียบเหมือนกันหมด
สรุปอะไรได้**

**[สมมติของสาย GM - รอ COO ยืนยัน]** สายนี้เดินต่อด้วยลำดับนี้จนกว่าจะมีคำตัดสิน:
1. ช่องแรก = `PF_GM_KEY=GMUI_1` + `PF_GM_SLOT0_TOUCH_PLUS4=0` (เขียนน้อยที่สุดในหน่วยความจำ client)
2. ตัวชี้ทางเดียวที่ใช้ได้คือ **บรรทัด `[GM_PLUGIN] loaded build=...`** — ไม่มีบรรทัดนี้ = ปัญหาอยู่ก่อนโค้ดเรา
   (ให้รัน `plugin_image_check` ก่อน แล้วดู `manifest_missing`/`export_*` แทนการ build ช่องถัดไป)
3. มีบรรทัด loaded แต่คลิกเงียบ → สลับ `PF_GM_KEY` เป็นช่องที่สอง → ยังเงียบ → `PLUS4=1` เป็นช่องที่สาม
4. **กติกาหยุด:** ครบสามช่องแล้วยังเงียบโดยที่ทุกช่องมีบรรทัด loaded = **หยุด** ห้าม build ช่องที่สี่
   ผลที่ได้คือ bounded negative ว่า "ปลั๊กอินโหลดได้แต่ไม่ใช่ประตู" ⇒ กลับไปที่ผู้ต้องสงสัยข้อ 1 ของ `RE-164`
   (connection context / clear-site ของ `[0x01032EC4]`) ซึ่งเป็นงาน RE บนสะพาน ไม่ใช่การเดา build เพิ่ม

## ข้อ ข — `patches/gm_plugin/` เป็นเขตเขียนของใคร (ใบ `2225` ข้อ 2 ยังไม่มีคำตอบ)

รอบนี้ pf-adversary เจอสองข้อระดับ HIGH ในไฟล์นั้น (รายละเอียดในใบถึง chief `20260902_0559`):
`GetModuleHandleW(L"msvcp90.dll")` เอาความกำกวม side-by-side กลับเข้ามา (heap ข้าม instance = แครช) ·
และ `PF_GM_SLOT0_TOUCH_PLUS4` default = เขียนของขนาดที่ยังเดาอยู่ลงหน่วยความจำ client

สายนี้ **ไม่แก้** เพราะ `patches/` ไม่อยู่ในเขตเขียนที่ prompt ระบุ และ clone นี้ไม่มี Windows SDK
จะ compile-check ก็ทำไม่ได้ ⇒ ตอนนี้ไฟล์ที่เจ้าของจะ build มีข้อบกพร่องระดับ "เผารอบ attended" ค้างอยู่
โดยไม่มีใครเป็นเจ้าของการแก้ ขอเคาะข้อใดข้อหนึ่ง:
- (1) `patches/gm_plugin/` เป็นเขตของ LANE-GM ⇒ สายนี้แก้ H1/H2 รอบหน้าทันที (ยังคอมไพล์ไม่ได้ที่นี่ ระบุไว้ในหัวไฟล์)
- (2) เป็นของ chief ⇒ chief แก้ตามรูปที่เสนอในใบ `0559`
- (3) รอ RE runner/เครื่องสะพานที่มี VC9 เป็นคนแก้พร้อม build ⇒ **ห้ามเจ้าของ build ตัวปัจจุบันก่อนแก้**
  (ข้อนี้ต้องประกาศให้เจ้าของเห็น ไม่ใช่แค่บันทึกไว้)

จนกว่าจะมีคำตอบ สายนี้ถือข้อ (3) เป็นค่าตั้งต้น **[สมมติของสาย GM - รอ COO ยืนยัน]** และจะไม่แก้ไฟล์นั้นเอง
