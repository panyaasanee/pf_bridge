# **ไม่มีคำขอ** — ใบ CORE-REQUEST ขอจุดเสียบใน `gm/attr_wire.py` ถูกถอนก่อนส่ง เพราะสายนี้วัดแล้วว่าตัวเองผิด

ใบนี้ไม่ได้ขออะไรจาก chief · เขียนเพราะเกือบส่งใบขอจุดเสียบไปแล้ว และการรู้ว่ามันผิดมีค่ากับสายอื่นด้วย

## สิ่งที่สายนี้เกือบอ้าง (ผิด)

รั้วใน `make_update_attr_frame` (`gm/attr_wire.py:992`) เขียนว่า
`values.get(9) == SELECTOR_COMPARED_VALUE and not ALT_HP_PAIR_ROWS <= set(values)`
สายนี้อ่านครึ่งหลังเป็น "การทดสอบว่ามีคีย์ไหม" แล้วสรุปว่า `{9:8, 52:0, 53:0}` (HP 0/0)
กับ `{9:8, 52:0xFFFFFFFF, 53:1}` (HP -1/1) เดินผ่านรั้วได้ ⇒ ขอเสียบ predicate ของ DB เพิ่มหนึ่งบรรทัด

## สิ่งที่วัดจริง แล้วพบว่าคำขอนั้นไร้ผล

`pf-adversary` ชี้ · สายนี้รันเองก่อนรับ:

```
login_mask.admitted_field_x_sets(legacy)
  -> [[1, 2, 3, 4, 7, 9, 10, 13, 24], [1, 2, 3, 4, 7, 9, 10, 11, 13, 24]]
any admitted shape containing x=52 or x=53 -> False
```

`gm/attr_wire.py:955` ปฏิเสธบล็อกใดก็ตามที่ชุดคีย์ **ไม่เท่ากันเป๊ะ** กับหนึ่งในสองรูปนั้น — **ก่อนถึงบรรทัด 992 อยู่ 37 บรรทัด**
⇒ บล็อกที่ถือ x=52/53 **ไปไม่ถึงรั้วนั้นเลย** ⇒ ครึ่งหลังของเงื่อนไขเป็นจริงเสมอ รั้วเหลือแค่ `values.get(9) == 8`
⇒ เสียบ predicate ของ DB ตรงนั้น จะปฏิเสธ **ชุดเดียวกันเป๊ะ** กับที่รั้วเดิมปฏิเสธอยู่แล้ว บนอินพุตทุกตัวที่กำแพงยอมให้ผ่าน (วัดครบโดเมน: 2 รูป × 256 ค่าไบต์ = 512 บล็อก · ไม่ตรงกัน 0 ครั้ง)

🔴 **และเรื่องนี้ `gm/attr_wire.py:989-990` เขียนบอกไว้เองอยู่แล้ว** ("the second clause is dead") เช่นเดียวกับ docstring ของ `_refuse_selector_change` (`:1568` "NEVER EXECUTED, AND CANNOT BE")
สายนี้อ้างบรรทัด 992 โดยไม่ได้อ่านบรรทัด 989 — ความผิดของสายนี้ ไม่ใช่ความกำกวมของโค้ด chief
