# ตอบใบ `1806`: ไม่ใช่ "สลับหรือไม่สลับ" — เกตอยู่ในมือคุณแล้ว สองบรรทัด

## คำตอบสั้น

**ใช่ เฟรมตอบคลิกควรอยู่ในรั้วเดียวกัน แต่เฉพาะตอนมีของอยู่บนพื้นจริง**
คุณถามถูกที่ไม่สลับทั้งใบ — เดิมพัน 97 ตัวทุกคลิกด้วยรูปที่ยังไม่มีใครเห็นบนไวร์ ไม่คุ้ม
แต่เฟรมที่ประกอบตอนพื้นว่าง **ไม่มีอะไรให้รักษาอยู่แล้ว** ⇒ ใช้ไบต์ของ v141 ไปตามเดิม ความเสี่ยงเป็นศูนย์
เหลือความเสี่ยงเฉพาะคลิกที่เกิดตอนของกองอยู่ตรงนั้น ซึ่งเป็นคลิกที่ทางเลือกอีกทางคือ "ของหาย" พอดี

## ของที่ลงให้แล้วรอบนี้ (`pirate-force-server` PR #593 · ยังไม่มีอะไรใน `src/` เรียกมัน)

```python
from pirateforce_foundation import mob_loot, mob_combat

pc, frame = mob_combat.remote_actors_preserving_the_ground(
    legacy, entries,
    mob_combat.choose_npc_site(scene_id),          # หนึ่งชื่อต่อฉาก ไม่ใช่ชื่อเดียวสี่ตัวตอบ
    ground_rows_left=mob_loot.ground_rows_live_here(mob_loot_cell, scene_id),
)
```

- 🔴 **ส่ง `scene_id` เข้าไปด้วยทั้งสองที่** — เซลล์มีใบเดียวต่อเซสชันและมันรู้ฉากของตัวเอง
  ถ้าไม่บอกว่าเฟรมนี้เป็นของฉากไหน แถวที่ยืนอยู่ Bg0002 จะไปติดเกตของเฟรมฉาก 1 ได้
  (pf-adversary รอบนี้ D16/D7 · บอกฉากแล้วได้ `another_scenes_cell` แทนตัวเลข = ใช้ไบต์ v141)
- `choose_npc_site(scene_id)` เพราะสายคุณมี **สี่** ตัวตอบ ถ้าใช้ชื่อเดียว ตัวที่ยิงก่อนจะปิดปาก
  อีกสามตัวตลอดอายุโปรเซส (D3) — ใบ `1806` ของคุณเองก็เขียนว่ากระทบทั้งสี่ไฟล์
- `ground_rows_live_here(cell, scene)` **ไม่โยน `Exception` ไม่ว่าจะได้อะไรมา** และค่าติดลบ
  **บอกสาเหตุ**: `no_cell` `cell_refused` `cell_has_no_scene` `another_scenes_cell`
  `caller_scene_unreadable` — คอนโซลพิมพ์สาเหตุจริง ไม่เดา (D4)
- 🔴 **`ground_rows_left=None` = "ไม่ใช่ตัวเลข" ⇒ ไบต์ของ v141** (ไม่ใช่ preserve)
  ค่าตั้งต้นของฟังก์ชันคือ sentinel `PRESERVE_WITHOUT_ASKING` ไม่ใช่ `None` — ร่างแรกใช้ `None`
  เป็นค่าตั้งต้น ซึ่งแปลว่าคุณเขียน `ground_rows_left=None` ตอนยังไม่มีเซลล์แล้วได้รูป preserve
  บน 97 ตัวทุกคลิกแบบเงียบ ๆ พอดี (D2 ของ pf-adversary รอบสอง แก้แล้วก่อน commit)
- นับได้ 0 ⇒ **ค่าที่ `legacy.make_runtime_remote_actors` คืนเอง** (เทสจับด้วย object identity
  ไม่ใช่แค่ `==`) · นับได้ > 0 ⇒ รูป preserve เดียวกับ bar/dying/dead
- `IntEnum` หรือ `int` subclass **นับเป็นตัวเลข** · `True/False` ไม่ใช่

## สิ่งที่ต้องรู้ก่อนใช้ และผมไม่ปิดบัง

- **เกตนี้เปิดหน้าต่างที่ opt-in ไม่มีเงื่อนไขไม่มี**: อ่านค่า → คิลลง → ประกอบเฟรม
  ⇒ เฟรมที่เพิ่งอ่านว่า "ว่าง" จะล้างแถวที่เพิ่งตกลงมา หน้าต่างยาวหนึ่งการประกอบ
  และแถวนั้นถูกประกาศใหม่ในการเผยแพร่ถัดไป แต่มันมีอยู่จริง (D8)
- **การอ่านไม่ใช่การอ่านล้วน**: `publication()` กวาดแถวหมดอายุ ⇒ คลิกกลายเป็นจังหวะหนึ่งที่
  แถวถูกเก็บ และตัวเลขที่ `enter_scene` รายงานว่ากวาดไปกี่แถวจะเป็น 0 หลังจากนั้น (D10)
- โทเคน `GROUND_ACTORS_LIVENESS_UNKNOWN` **ยังไม่มีใบเทสไหนถูกกำหนดให้อ่านมันบนจอ**
  (`GT-204` เป็นใบของ chief และขอบเขตของมันคือของบนพื้น/คลิกซ้าย/เข้ากระเป๋า)

## บรรทัดที่ต้องมีก่อน และมันไม่ใช่ของสายผมทั้งคู่

1. **chief** — จุดเรียก responder ใน `runtime.py` ส่งเซลล์เข้าไปด้วย:
   `mob_loot_cell=getattr(self, "mob_loot_cell", None)` (เซลล์ถูกสร้างที่ `runtime.py:1322`
   และที่ `runtime.py:6892` ก็อ่านด้วย `getattr` แบบเดียวกันอยู่แล้ว)
2. **สาย A** — `respond(...)` รับ `mob_loot_cell: Any = None` (วันนี้มันตกลง `**_ignored`)
   แล้วเรียกตามบล็อกโค้ดข้างบนแทน `legacy.make_runtime_remote_actors`

ถ้าข้อ 1 ยังไม่มา ข้อ 2 ทำไปก่อนได้เลยและ **ไม่เปลี่ยนอะไรบนไวร์** — ได้ไบต์เดิมทุกคลิกพร้อมบรรทัดคอนโซล
`GROUND_ACTORS_LIVENESS_UNKNOWN <ฉาก> no_cell` ที่บอกว่าเซลล์ยังมาไม่ถึง
(ใครก็ตามที่บูตเซิร์ฟเวอร์ grep เจอ — แต่ย้ำตามข้างบนว่ายังไม่มีใบเทสใบไหน "ถูกสั่ง" ให้ดูมัน)
