# ASK-COO — `/speed` จะเป็น **การเขียนค่าที่ยังไม่ถูกตัดสินลงคอลัมน์จริงครั้งแรก และไม่มีทางกลับ**

## เรื่องเดียวที่ถาม
ผู้ตรวจ (pf-adversary) ชี้ข้อที่ผมมองข้ามและผมตัดสินเองไม่ได้ **จึงหยุดและถามก่อนตามกฎ charter**
("เจอทางเลือกที่ย้อนไม่ได้/ไม่มี backup เขียนใบถึง COO ทันที อย่าตัดสินเอง อย่ารอข้ามรอบ")

🔴 **ตัวเลขที่ GM พิมพ์ นับเป็น "ค่าที่ถูกตัดสินแล้ว" หรือยัง — และถ้าเขียนผิด กลับยังไง**

## ข้อเท็จจริงสามข้อที่ชนกันเอง วัดจากรีโปทั้งหมด

1. **`COO-DECISION 20260901_1447` ข้อ 2 ห้าม seed `speed_walk`** ด้วย 150.0 หรือ 400.0 จนกว่า RE จะตอบ
   เพราะ "ทั้งสองเลขเป็นการเดาเท่ากันถ้าไม่มีมัน" — หัวไฟล์ `migrations/006` อ้างข้อนี้เป็นเหตุผลทั้งหมด
   ที่มันเป็น `ADD COLUMN` เปล่า ๆ ไม่มี backfill
2. **method ของผมรอบนี้คือเส้นทางแรกในรีโปที่เขียนตัวเลขลง `speed_walk` ของแถวตัวละครจริง**
   ⇒ RE-193 ยังไม่ตอบ แต่ค่าจะเข้าคอลัมน์ได้แล้วผ่าน `/speed`
3. 🔴 **ไม่มีทางกลับเป็น NULL** — `persistence_typed_attrs.validate` ปฏิเสธ `None` โดยเจตนา
   ("this API does not clear a typed column back to NULL") ⇒ พอ GM พิมพ์ `/speed 400` ครั้งเดียว
   คอลัมน์นั้น **ไม่มี code path ไหนในรีโปพากลับไปเป็น "ไม่มีค่า" ได้อีกเลย**
   กู้ได้ทางเดียวคือ `UPDATE` ด้วยมือ (ซึ่งเจ้าของห้าม) หรือ restore snapshot ทั้งไฟล์

**ทำไมข้อ 3 ถึงสำคัญกว่าที่มันดู**: `persistence_attr_compose` ถือกฎ "ไม่มีค่า = ABSENT ห้ามเดาเป็นศูนย์"
ซึ่งทำงานได้เพราะคอลัมน์ที่ยังไม่มีค่าเป็น NULL ⇒ **การเขียนครั้งแรกเปลี่ยนสถานะของตัวละครนั้นจาก
"เซิร์ฟเวอร์ยังไม่รู้" เป็น "เซิร์ฟเวอร์รู้แล้ว" อย่างถาวร** และค่าที่ทำให้มัน "รู้" คือเลขที่ GM พิมพ์เล่นตอนเทส
ไม่ใช่เลขที่ RE พิสูจน์

## ที่ผมทำไปแล้วรอบนี้ (ไม่ได้หยุดรอ เพราะใบ `0147` สั่งให้ส่ง method รอบนี้)
ส่ง method ตามคำสั่ง แต่ **ไม่ได้ทำอะไรที่ทำให้ข้อ 3 แย่ลง**: ไม่มี migration ใหม่ ไม่มี backfill
ไม่มี seed ไม่มีผู้เรียกในรีโป ⇒ **ณ วินาทีนี้ยังไม่มีตัวละครตัวไหนถูกเขียน** ประตูจะเปิดจริงตอน
LANE-GM ต่อสาย ⇒ **ยังทันตัดสินก่อนที่แถวแรกจะถูกแตะ**

## สามทางที่ผมเห็น — **ไม่เลือกเอง**
- **(ก) ยอมรับ**: เลขที่ GM พิมพ์ = ค่าที่ถูกตัดสินแล้วสำหรับตัวละครนั้น RE-193 ไว้ตัดสิน *ค่าเริ่มต้น*
  ของตัวละครใหม่เท่านั้น ไม่ผูกกับ `/speed` · ถูกที่สุดถ้าเจตนาคือ "GM คือผู้มีอำนาจ"
- **(ข) จำกัดขอบเขต**: `/speed` เขียนได้เฉพาะกับ run-copy DB (ซึ่ง `_speed_db_is_canonical` ของ
  LANE-GM กันไว้อยู่แล้ว) และ **ห้ามแตะ canonical จนกว่า RE-193 จะตอบ** ⇒ ต้องมีคนบังคับจริง
  ไม่ใช่ heuristic ชื่อไฟล์ (ผู้ตรวจชี้ว่าด่านนั้นพิสูจน์ได้แค่ชื่อไฟล์ลงท้าย)
- **(ค) ให้มีทางกลับก่อน**: สายผมสร้าง method `clear_speed_by_identity` (คืนคอลัมน์เป็น NULL)
  ⇒ ต้องผ่อนกฎ "ห้าม clear เป็น NULL" ของ `validate` **ซึ่งเป็นกฎที่มีไว้กันศูนย์ที่เดา**
  ⇒ **ผมไม่แตะกฎนั้นเองเด็ดขาด** ต้องเป็นคำสั่ง

สายนี้เอนไปทาง **(ค) คู่กับ (ก)** — เหตุผล: ถ้ายอมให้เขียน ก็ควรมีทางกลับ ไม่งั้นรอบเทสหนึ่งรอบทำให้
ข้อมูลของตัวละครเปลี่ยนถาวรโดยไม่มี undo ซึ่งเป็นคลาสเดียวกับข้อห้าม "ย้อนไม่ได้ไม่มี backup" ของเจ้าของ
**แต่ผมเอนแล้วบอกว่าเอนเพราะอะไร ไม่ได้ทำ** รอคำสั่ง
