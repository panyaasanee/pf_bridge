# RE-290 บริโภคแล้ว — **ไม่ถอนผู้สมัคร `actor_type 5` ออกจาก `GT-288` ชุด 2** + grep แคบที่ RE ขอ ทำแล้ว

ใบนี้ผมเป็นเจ้าของ (LANE-B เปิด) ⇒ บริโภครอบนี้ตามกฎบ้าน · หัวใบในคิวเป็นของ K ผมจึงส่งข้อความปิดมาแทนการแก้เอง

## 1. เงื่อนไขในใบเป็นจริง
ใบเขียนไว้ว่า: ตอบ `0x45C560` ⇒ ชุด 2 พร้อม · ตอบอย่างอื่น ⇒ ถอนผู้สมัคร `actor_type` ทั้งชุด
RE ตอบ `[0xF0DFF8 + 0x7C] = 0x0045C560` ⇒ **ชุด 2 เดินต่อ ไม่มีการถอน**

## 2. grep แคบที่ RE runner ขอไว้ ทำแล้ว — และเป็นการ **ยืนยันซ้ำ** ไม่ใช่ผลใหม่
RE ชนเส้นเวลา จึงบอกได้แค่ว่า "6 ไฟล์ตรงอย่างน้อยหนึ่งคำ" แล้วขอให้ผม grep คำว่า `45C560` ซ้ำ ผลของผม:

| ไฟล์ (อยู่ที่ `notes_to_chief/reference_codex_attr/` ไม่ใช่ `external/`) | `45C560` | `F0DFF8` |
|---|---|---|
| `PF_ATTR_NAME_COLOR_SELECTOR.tsv` | 12 | 0 |
| `PF_MONSTER_COLOR_GATE.tsv` | 11 | 0 |
| `PF_ATTR_FIELD_SEMANTICS.tsv` · `PF_A2_ATTR_FIELD_DELTA.tsv` · `PF_ATTR_SEMANTIC_DELTA.tsv` | 2 · 2 · 2 | 0 |
| `PF_MONSTER_PRESENTATION.tsv` | ไม่มีไฟล์นี้ในรีโป (RE เขียนชื่อไว้ แต่ `find` ไม่เจอ) | - |

ค่าที่อยู่ในนั้นมาก่อนแล้ว เขียนเป็น
`npc_actor_nameboard_initializer=0x0045C560..0x0045C613@sha256:cdbc017c...f2a432`
และใน `PF_MONSTER_COLOR_GATE.tsv` มี **file offset กำกับด้วย: `0x0005B960..0x0005BA13`**
🔴 นี่คือเลขเดียวกับที่ RE คำนวณสด ๆ จาก PE header รอบนี้ (`VA 0x0045C560 -> file 0x5B960`)
⇒ สองเส้นทางที่ไม่พึ่งกัน ให้ค่าเดียวกัน · **ใช้ค่าเดิมในโคเด็กซ์ และถือ RE-290 เป็นการยืนยันซ้ำ** ตามที่ใบขอ
⇒ `CAvatarNPC` (AT5) และ `CNetNPC` ชี้ initializer ป้ายชื่อตัวเดียวกัน (`NameBoardNPC`, `push 0xC0`)

## 3. ที่ใบนี้ **ไม่** พิสูจน์ (nonclaims — เขียนไว้กันคนอ่านเกิน)
- ไม่ได้พิสูจน์ว่า AT5 **ระบายสีชื่อ** ได้ตามที่ P-2 ต้องการ · พิสูจน์แค่ว่า **มีป้ายชื่อให้ระบาย** (ด่านโครงสร้าง)
- ไม่ได้พิสูจน์ว่า AT5 เรนเดอร์บนจอ (นั่นคือสิ่งที่ `GT-288` ชุด 2 บนเครื่องเจ้าของต้องตอบ)
- ค่าในโคเด็กซ์กับค่าที่ RE อ่าน มาจากไบนารีที่มี sha256 เดียวกัน ⇒ ยืนยันซ้ำ **ภายในไบนารีเดิม** เท่านั้น
