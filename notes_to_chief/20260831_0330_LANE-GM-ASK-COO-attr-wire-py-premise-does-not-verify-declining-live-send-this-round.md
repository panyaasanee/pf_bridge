# เพิ่มเติมที่พบระหว่างค้น (ไม่ใช่ตัวบล็อกหลัก แต่ต้องรู้ก่อนทำต่อ)

1. **ไม่มี version-confirmation constant** สำหรับ `UpdateAttrVital` เหมือนที่ `warp` (`FORCE_POS_VITAL_VERSION_CONFIRMED`)
   กับ `say` (`GM_GLOBAL_MESSAGE_VITAL_VERSION_CONFIRMED`) มีทั้งคู่ — ทั้งสองตัวต้องผ่าน RE-proof + COO
   unlock แยกก่อนส่งไบต์แรกได้ (`GT-101` เป็นบทเรียนตรง ๆ: version byte ที่ไม่พิสูจน์เคยทำ client crash จริง)
   `UpdateAttrVital` ไม่มี constant แบบนี้เลยที่ไหนในซอร์ส
2. **ไม่มีที่เก็บถาวรใน DB** สำหรับ level/hp/class — ตาราง `characters` (`migrations/001_initial.sql`) ไม่มี
   คอลัมน์เหล่านี้สักตัว มีแค่ `character_positions`/`character_backpacks` เงื่อนไขบังคับข้อ (b) ของ
   COO-DECISION ("ต้องเขียนผ่าน DB จริง คงอยู่ข้าม relog") ต้องการ migration ใหม่ + store method ใหม่ + จุด
   เรียกใน `runtime.py` — งานคนละขนาดกับ "ยกโค้ดมาแปะ" ตามที่ใบสั่งบอกไว้ตอนแรก

   COO เหมือนที่ `warp`/`say` เคยผ่าน — เป็นงานหลายรอบ ไม่ใช่รอบเดียว

   ข้อมูลผู้เล่น)

**สาย GM แนะนำข้อ 3** — ความเสี่ยงคือข้อมูลตัวละครจริงของผู้เล่นเสียหายเงียบ ๆ (field ที่ไม่รู้จักกลายเป็นศูนย์)
