## ทำงานหลายไฟล์ต่อใบ
ก่อนทำ batch ระบุ input files และจด SHA-256; ชุดใหญ่ใช้ manifest/fingerprint เดียว ทุก source input read-only ค้น external และ gamedata ก่อนถอด ถ้าหลายใบใช้ผลเดียวกันให้ค้นครั้งเดียวแล้วอ้างพร้อม SHA
ต่อหนึ่งใบ:
1. อ่านใบเต็มล่าสุด บันทึก ticket START/input SHA
2. ผลต้องมี:
   - ค้นใน pf_bridge\external\ แล้ว: เจออะไร/ไม่เจอ พร้อมขอบเขต
   - ค้น gamedata แล้ว: เจออะไร/ไม่เจอ พร้อมขอบเขต
3. ถ้ามีคำตอบเดิม ให้ verify SHA แล้วใช้
4. ปิดและ checkpoint ทีละ job
5. ห้ามเดา/จับคู่เพราะ id เท่ากัน ต้องมี crosswalk field
6. ผลลบต้องบอกขอบเขต ห้ามใช้ linear disassembler เป็นหลักฐานผลลบ
7. แนบ nonclaims และ BUILD_IMPACT ครบ
8. ตรวจ SHA หลังงานเทียบก่อนงาน
เขียนผลทันทีเมื่อใบ DONE/PASS/BLOCKED/PARTIAL ไม่รอทั้ง batch หาก PARTIAL ให้แยก time checkpoint (รอบหน้าทำต่อได้จาก artifact) จาก method ceiling (ห้ามรันซ้ำจน chief แก้ objective)
ก่อนเริ่มใบถัดไป ให้เช็ก elapsed และ queue/NEW_ORDERS mtime; ถ้าเปลี่ยนให้อ่านใหม่ หาก margin ไม่พอให้ closeout
## ผลลัพธ์
หนึ่งจดหมายต่อหนึ่งใบที่ลงมือ:
BRIDGE\notes_to_chief\<YYYYMMDD_HHMM>_<เลขใบ>-RESULT-<สรุป>.md
ห้ามรวมหลายใบในจดหมายเดียวและห้ามเขียนให้ใบที่ไม่ได้ลงมือ
หนึ่ง log ต่อใบ:
<ISO+07>  RE-xxx  DONE|PARTIAL|BLOCKED  jobs=<ช่วง>  letter=<ชื่อไฟล์>
🔴 หนึ่ง log ต่อใบที่เปิดค้างแต่ถูกข้าม (บังคับ ตั้งแต่ 2026-09-02):
<ISO+07>  SKIP  RE-xxx  reason=<other-route|no-route-and-not-static|assigned-<สาย>|already-answered|other:<คำอธิบายสั้น>>
เหตุผล: บรรทัด NO-WORK บอกแค่ว่าไม่มีงาน ไม่ได้บอกว่าทำไมใบที่มีอยู่ถึงไม่ถูกหยิบ — ที่ผ่านมาต้องเสียเวลาหลายชั่วโมงไล่หาเหตุย้อนหลังเพราะ log ไม่ได้บันทึกไว้
ถ้าลงมือหลายใบ เพิ่ม:
<ISO+07>  ROUND  tickets=<เลขคั่นด้วยจุลภาค>  completed=<n>  partial=<n>  elapsed=<นาที>  deadline=OK
อัปเดต MEMORY ก่อนจบ: เวลา, batch, ผล/checkpoint ต่อใบ, SHA สำคัญ และสถานะ lock แบบกระชับ
