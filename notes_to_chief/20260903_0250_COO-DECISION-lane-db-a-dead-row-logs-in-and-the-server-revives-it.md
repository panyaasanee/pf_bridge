# ตัดสิน: **ค.** — แถวบอกว่าตาย ล็อกอินแล้ว **เซิร์ฟเวอร์ฟื้นให้ แล้วส่งค่าที่เพิ่งเขียนจริง**

## ตัดสินว่าอะไร

เมื่อแถวสมบูรณ์และสม่ำเสมอทุกข้อ แต่ `hp_current <= 0`:

1. เขียนแถว `hp_current = hp_max` **ของแถวนั้นเอง** (ค่าที่รู้ ห้ามใช้ค่าคงตัว 100)
2. แล้วส่ง **ค่าที่เพิ่งเขียน** ออกสาย ⇒ wire กับ DB ตรงกันเสมอ ไม่มีการวางเลขที่ขัดกับแถว
3. reason ของตัวเอง `ROW_HP_NOT_POSITIVE_REVIVED_ON_LOGIN` + console line — ห้ามกลบเป็น `row_has_no_value`
4. เขียนไม่สำเร็จ ⇒ **ห้ามล้มล็อกอิน** (D1 ของคุณพิสูจน์แล้วว่าล้ม = ไคลเอนต์ค้างที่ connecting)
   ⇒ ส่งค่าคงตัวเดิมพร้อม reason แยก `REVIVE_WRITE_FAILED` + console line ตัวใหญ่ ⇒ ล้มแบบเห็นได้ ไม่เงียบ

## เพราะอะไร

- **ข. (ที่คุณลงไว้) ผิดตรงเดียว แต่เป็นตรงที่ adversary จับ**: มันคือล็อกอินเดียวในเซิร์ฟเวอร์ที่ wire กับ DB
  **จงใจไม่ตรงกัน** และไม่มีใครเป็นเจ้าของความไม่ตรงนั้น = หนี้เงียบ ซึ่งเป็นรูปที่โปรเจกต์นี้เสียรอบไปแล้วหลายครั้ง
- **ก. แย่กว่า**: วันนี้ยังไม่มีทาง respawn ในรีโปเลย ⇒ ส่ง 0 = ตัวละครติดตายถาวร ล็อกอินเข้ามาแล้วเล่นไม่ได้
  และมันคือสภาพที่ผู้เล่นเจอทันที = ย้อนยากที่สุดในสามทาง
- **ค. คือแบบแผนที่เจ้าของเคาะไว้แล้วโดยชื่อไมล์สโตน**: M4 ชื่อ "ตีได้**ตายได้**" — ตายต้องมีผลจริง
  แต่กลับมาเล่นได้ ไม่ใช่ติดตาย · ฟื้นตอนล็อกอินคือครึ่งที่ทำให้ทั้งสองข้อจริงพร้อมกัน
- ไม่ต้อง migration ไม่ต้องแตะแถวใครหมู่ ⇒ **ไม่เข้าข้อห้าม backup ของเจ้าของ** เขียนเฉพาะแถวที่ล็อกอินเข้ามาเอง

## ใครทำอะไรต่อ

- **LANE-DB**: แก้ `persistence_login_vitals.py` ตามสี่ข้อบน + เทสสองตัว
  (ก) แถว `hp_current = 0` ⇒ แถวถูกเขียนกลับเป็น `hp_max` และไบต์บนสายเท่ากับแถวหลังเขียน
  (ข) เขียนล้มเหลว ⇒ ล็อกอินไม่ล้ม + reason เป็น `REVIVE_WRITE_FAILED` ไม่ใช่ reason ของข้อ (ก)
- 🔴 **ห้ามเสียบ seam เข้าเส้นทางล็อกอินจริงในรอบเดียวกับที่เขียนตัวฟื้น** — สองรอบแยกกัน
  `GT-193` คือราคาที่เราจ่ายไปแล้วสำหรับเลขใหม่บนบล็อกล็อกอิน
- ใบ `0116` ถึง chief (สองบรรทัดที่เหลือ) ไม่ถูกใบนี้บล็อก เดินต่อได้
