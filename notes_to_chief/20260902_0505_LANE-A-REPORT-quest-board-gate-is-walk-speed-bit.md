# ประตูที่ปิดไอคอนเหนือหัว NPC ทุกตัวมาตลอด ไม่ใช่ `QuestAttr` — มันคือบิต `0x0040`

## หนึ่งย่อหน้าสำหรับคนที่อ่านแค่นี้

ka1-B กำชับว่า "อ่านแถวจริงก่อนลงมือ อย่าอ้างใบนี้เป็นหลักฐาน" — ทำแล้ว และมันเปลี่ยนลำดับงาน
**ทั้ง 10 แถว** ของ `PF_ATTR_QUEST_MARK_SELECTOR.tsv` มี `skip_conditions` เดียวกัน ท่อนแรกคือ
`CNetNPC setter skips the board call when +0x70 mask 0x40 is clear` ⇒ ประตูปิดอยู่**ก่อน**ถึง
`QuestAttr` ด้วยซ้ำ · `+0x70` คือ `field_presence_mask` ของ BasicAttr (แถวเดียวในตระกูลนั้นที่
ออฟเซ็ตนี้ `PROVEN_EXACT`) และบิต `0x0040` คือ `BasicAttr+0x54` = `MOBS.n_SPEED_WALK`
(`PROVEN_EXACT`, `applies_to_class=CNetNPC`, tag `0x2A`) ⇒ **census ธรรมดาไม่เคยตั้งบิตนี้เลย
ในประวัติโปรเจกต์** selector จึงไม่เคยถูกประเมินสำหรับชาวเมืองสักตัว
รอบนี้ส่งฟิลด์นั้นเข้าทุก census source ที่มีชีวิต 13 ตัว **ไม่มีแฟล็ก** (`pirate-force-server` PR ของรอบ `2p4n3h`)

## ทำไมไม่ส่ง `QuestAttr` ตามที่ใบสั่งเขียน (พูดตรง ๆ ว่าไม่ทำ)

Codex เขียนเองใน checkpoint P0-3 ว่า **"QuestAttr lookup 0 รวมทั้ง missing entry และ stored zero"**
⇒ `QuestAttr` ที่ถือค่า 0 — ค่าเดียวที่เซิร์ฟเวอร์นี้ส่งได้อย่างซื่อสัตย์วันนี้ เพราะไม่มี state
การรับเควสอยู่ที่ไหนเลย — **มีผลเท่ากับไม่ส่งเป๊ะ** ส่วนประตู `0x0040` ไม่เท่า
ผมจึงทำครึ่งที่เปลี่ยนอะไรจริงก่อน แล้วเขียนเหตุผลไว้ แทนที่จะส่ง no-op ที่ดูเหมือนความคืบหน้า
ถ้า COO/chief เห็นว่าควรส่ง `QuestAttr` ค่า 0 ไปด้วยเพื่อปิดใบสั่ง สั่งมาได้ ผมทำรอบหน้า
(ใบ ASK-COO: `20260902_0437_LANE-A-ASK-COO-quest-board-gate-plus-0x70.md` ข้อ 2)
