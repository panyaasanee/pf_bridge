# COO-DECISION — ต้นทุนเศษของสกิล 111 = ปัดขึ้น (ceil) · กฎบ้านสำหรับต้นทุน SP เศษทุกตัว

## ตัดสินว่าอะไร
1. **ทางเลือก 1 ปัดขึ้น**: `skill_point_cost_to_learn(id)` ที่ไม่ใช่จำนวนเต็ม ⇒ หัก `math.ceil(cost)` แต้ม · สกิล 111 = **1 แต้ม**
2. กฎนี้ใช้กับ**ทุก** skill id ที่ต้นทุนเป็นเศษ ไม่ใช่เฉพาะ 111 (ห้ามเขียนกรณีพิเศษเลข 111) · ต้นทุน ≤ 0 หรือติดลบจากตาราง = ปฏิเสธเหมือนเดิม (`SkillLearnValidatorError`) ไม่ปัดเป็น 0
3. `characters.skill_points` **คง INTEGER** · ห้ามเปลี่ยนชนิดคอลัมน์ (ทางเลือก 3 ปิด) · ทางเลือก 2 (ฟรี) ปิด · ทางเลือก 4 (ปฏิเสธถาวร) ปิด

## เพราะอะไร
- คอลัมน์ INTEGER + wire `SP` offset `0x7C` เป็น u32 = ตัวเลขทั้งระบบเป็นจำนวนเต็มอยู่แล้ว การปัดขึ้นเป็นทางเดียวที่ไม่ให้ของฟรี ไม่ติดลบ ไม่แตะ migration ไม่แตะจุดอ่านของสายอื่น
- ค่า `0.2000000029` คือ float32 ของ `0.2` จากตารางไคลเอนต์ = ตารางตั้งใจให้ "มีต้นทุน" ⇒ ผู้เล่นจ่าย 1 แต้มดีกว่าเรียนไม่ได้เลย
- อยู่ในเขต COO (เกณฑ์/กติกา ไม่ใช่ทิศทางปลายทาง) · ถ้า Panya จะเปลี่ยนภายหลังแก้ที่จุดเดียวใน `skill_learn_validator.py`
