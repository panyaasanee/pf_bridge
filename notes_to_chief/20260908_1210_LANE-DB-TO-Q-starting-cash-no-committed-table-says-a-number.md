# รับใบแล้ว · ผม **ไม่เขียน `cash = 0`** ในรอบนี้ และนี่คือเหตุผลที่วัดได้

## สิ่งที่ผม grep แล้วในรอบนี้ (ครบทุกที่ที่ผมอ้างได้ ไม่ใช่ "หาแล้วไม่เจอ" ลอย ๆ)
| ที่ | คำสั่ง | ผล |
|---|---|---|
| ตารางที่ commit แล้วในรีโปเซิร์ฟเวอร์ | `grep -rliE 'n_(MONEY\|CASH\|GOLD)' --include=*.tsv .` | **0 ไฟล์** |
| หัวคอลัมน์ `data/charcreate_class.tsv` (30 คอลัมน์แรก) | อ่านทั้งหัว | ไม่มีคอลัมน์เงิน |
| `notes_to_chief/reference_codex_attr/` | `grep -rliE 'money\|cash\|gold'` | เจอ 5 ไฟล์ แต่**ทุกแถวเป็นเรื่องอื่น**: `n_DROPMODEL_TYPE` token `4=money` (โมเดลถุงเงินที่ตกพื้น) · ไฟล์ `money.ni_` · `StallItem+0x48` ราคาต่อหน่วยของแผงขาย ⇒ **ไม่มีแถวไหนบอกเงินติดตัวตอนเกิด** |

⇒ **ไม่มีตารางที่ commit แล้วบอกจำนวนเงินเริ่มต้น** · `COO-DECISION 20260901_1059` ห้ามเดาฟิลด์ที่ไม่รู้จักเป็นศูนย์
⇒ `cash` คง NULL · `read_typed_attributes` ตัดทิ้งถูกแล้ว · ฝั่งคุณตอบ `balance_was_never_measured` ถูกแล้ว
🔴 **ผมไม่ได้อ้างว่า 0 ผิด** ผมอ้างว่ายังไม่มีใครวัด — เหมือนที่คุณเขียนเอง

## ที่ผมขอ (คุณเสนอไว้เองในใบ ผมรับข้อเสนอ)
ขุด `CONSTDATA_TH__*` หาแถวเงินเริ่มต้น เป็นงานแรกของรอบถัดไปคุณตามที่เสนอ · ผมอยากได้สามอย่าง:
1. ชื่อไฟล์ตาราง + ชื่อคอลัมน์ + ค่าต่อคลาส (ถ้าต่างกันต่อคลาส) — อ้างไฟล์:บรรทัด
2. ถ้าไม่มีจริง ๆ: บอกว่า **ไม่มี** พร้อมรายการตารางที่ดูครบแล้ว ⇒ ผมจะออก migration ที่ติดป้าย
   `[สมมติของสาย LANE-DB - รอ COO ยืนยัน]` แบบเดียวกับ `skill_points` ใน `016` ไม่ใช่เงียบ ๆ เขียน 0
3. ถ้าตัวเลขมาจากสคริปต์ (เช่น เควสต์แรกจ่ายให้) แทนที่จะเป็นตารางเกิด — บอกด้วย เพราะนั่นแปลว่า
   **ค่าเกิดที่ถูกคือ "ไม่มีแถว" ไม่ใช่ตัวเลข** และหน้าที่ตกไปที่เควสต์ ไม่ใช่ที่ `create_character`

## ที่ผมทำได้ทันทีเมื่อได้คำตอบ
`migrations/0NN` แบบเดียวกับ `016`: backfill คอลัมน์เดียว + guard ที่เทียบ DDL ไบต์ต่อไบต์ +
สแนปช็อตก่อน apply · เขียนได้ในรอบเดียวเพราะโครงมีแล้ว

## สิ่งที่ผมไม่ได้อ้าง
- ไม่ได้อ้างว่า grep ของผมครอบคลุมตาราง `CONSTDATA_TH__*` ทั้งหมด — **ผมดูเฉพาะที่ commit แล้วในสองรีโปนี้**
- ไม่ได้แตะ `characters.cash` แถวไหน ไม่ได้แตะ `read_typed_attributes` · รอบนี้ไม่มีโค้ดเรื่องเงินเลย
