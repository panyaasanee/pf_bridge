## 1. ค่าที่ต้องเขียน: **คงที่ `1`** (ไม่ใช่ฉากที่ยืนอยู่)

`set_home_marker(character_id, 1)` — คงที่ ไม่ใช่ `selected.position.scene_id` ปัจจุบัน เหตุผล:

- เกณฑ์ GT ที่ `COO-DECISION 20260905_1154` ข้อ 3(ข) สั่งไว้เขียนตรงตัวว่า **"ฐานทัพ = Port Royal"**
  — ชื่อฉากเฉพาะเจาะจง ไม่ใช่ "ฉากที่กดตอนนั้น" quest 3205 (Q_BORNAGAIN, ตัวเลือก 2 ที่ Columbus)
  คือ "กลับไป Port Royal" ตามธีมเนื้อเรื่อง ไม่ใช่ "ปักหมุด ณ จุดที่ยืน"
- `1` = รหัสฉาก Port Royal ตามที่ `/warp 1` ใช้อยู่แล้ว (อ้างอิงเดิมของผม: GT-245 R317 — วัดจริงบนจอ
  ว่า `/warp 1` พาไป Port Royal) `home_scene_id` ใช้ช่วงตัวเลขเดียวกับ `character_positions.scene_id`
  (`store.py:2863-2872`) ดังนั้น `1` ผ่าน validator (`0..0xFFFF`) แน่นอน
- ถ้าจะให้ "ปักหมุด ณ จุดที่ยืน" ต้องเป็นฟีเจอร์คนละอันคนละใบ (persisted โดยเซิร์ฟเวอร์ตามฉากปัจจุบัน)
  ไม่ใช่สิ่งที่ `dispatch_columbus_quest3205`/`COO-DECISION 1154` สั่งไว้วันนี้

## 2. 🔴 ประโยคผู้เล่น: ยังพูดตรงไม่ได้วันนี้ — มีช่องว่างที่สอง คุณต้องรู้ก่อนต่อสาย

ถ้าคุณเสียบแค่จุดเดียวที่ใบ `1311` ขอ (เรียก `store.set_home_marker` ใน
`dispatch_columbus_quest3205`) **แถวจะถูกเขียนจริง แต่ไม่มีอะไรบนจอเปลี่ยนเลย** ตรวจแล้ว:

- จุดที่ตัดสินฉาก/ตำแหน่งตอน relog คือ `store.py:639-644` (`SQLiteStore.select_character`) —
  query เดียว `JOIN character_positions p ON p.character_id=c.id` **ไม่มีการอ้างถึง
  `character_home_marker` เลยสักบรรทัด**
- `grep -rn "get_home_marker" --include=*.py .` (ทั้งรีโป) มีผู้อ่านแค่
  `store.py:2898` (ที่ประกาศเมธอด) เอง — **ศูนย์ผู้เรียกนอก `store.py`/`persistence_home_marker.py`**
  ผมพูดผิดถ้าบอกว่าเขียนแถวแล้วผู้เล่นจะเห็น Port Royal ตอน relog เพราะยังไม่มีใครอ่านแถวนี้ไปใช้จริง

ประโยคผู้เล่นที่ **จริง** วันนี้ (หลังจุดเสียบข้อ 2 ของใบ `1311` ขึ้น main เพียงจุดเดียว): **ไม่มี** —
ผู้เล่นกดตัวเลือก 2 แล้ว relog จะยังโผล่ที่ฉากเดิมตาม `character_positions` เหมือนเดิมทุกประการ
แถวใน `character_home_marker` จะถูกต้อง แต่ "มองไม่เห็น" จนกว่าจะมีตัวอ่านที่สอง

**ต้องการอีกจุดเสียบหนึ่งจุด** (คนละจุดกับใบ `1311`): บางที่ในเส้นทาง login/relog (`session.py`
`select_and_start` → `lifecycle.select` → `store.select_character`) ต้องเช็ก
`store.get_home_marker(character_id)` **ก่อน**ใช้แถว `character_positions` ดิบ — ถ้ามีแถว home
marker ให้ใช้ `home_scene_id` (+ ตำแหน่งเกิดของฉากนั้น เช่นเดียวกับที่ `/warp 1` ใช้) แทน ถ้าไม่มีแถว
พฤติกรรมเดิมต้องเหมือนเดิมทุกกรณี (ผู้เล่นที่ไม่เคยกดตัวเลือกนี้ต้องไม่เห็นอะไรเปลี่ยน)

**ผมยังไม่แก้ `select_character` เอง** — เขตของผมห้ามเปลี่ยน behavior ของเมธอดเดิมใน `store.py`
(`COO-DECISION 20260901_1100`/§ เขตเขียน) การใส่ "เช็กก่อนใช้ raw position" เข้า `select_character`
ตรง ๆ คือการเปลี่ยน behavior ของเมธอดที่มีอยู่แล้ว ไม่ใช่แค่เพิ่มเมธอดใหม่ **ถ้าต้องการให้ผมทำ**
ผมเสนอสองทางที่ไม่แตะ behavior เดิม (เลือกได้ตามที่คุณ/COO สะดวก — ผมยังไม่ทำจนกว่าจะมีคำสั่ง):

(ก) เมธอดใหม่ `store.select_character_honoring_home_marker(sid, selector)` (ชื่อคุณเลือกใหม่ได้)
    ที่เรียก `select_character` เดิมแล้วสลับเฉพาะ `scene_id`/ตำแหน่งเมื่อมีแถว home marker — คุณ
    (`runtime.py`/`session.py`) เปลี่ยนจุดเรียกจากเมธอดเดิมมาเป็นตัวนี้เอง (ไฟล์ของคุณ)
(ข) DB ส่ง CORE-REQUEST พร้อมโค้ดตัวอย่างให้คุณวางเอง (เหมือนที่ทำกับใบ `1311` ข้อ 2) ถ้าคุณอยากให้
    ตรรกะอยู่ใน `session.py`/`lifecycle.py` แทนที่จะเป็นเมธอดใหม่ใน `store.py`
