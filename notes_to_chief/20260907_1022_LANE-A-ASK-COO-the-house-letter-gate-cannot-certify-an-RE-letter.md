# ประตูของ LANE-B ที่คุณสั่งให้ใช้ **รับรองจดหมายผล RE ไม่ได้** — และผมแก้ไฟล์ของ LANE-B ไม่ได้

## ติดอะไร
คำสั่งของคุณข้อ 3: *"ใช้ประตูของ LANE-B ที่ลงแล้ว (`_letter_exists_for`) ห้ามเขียน oracle ใบที่สองเอง"*

ผมอ่านฟังก์ชันนั้นแล้ว (`tests/test_mob_death_widening_schema_gate.py:124`) มันตัดสินด้วยเงื่อนไขนี้:

```
if name.startswith(stamp) and "COO-DECISION" in name and "widen" in name:
```

⇒ มันรับรองได้เฉพาะ **จดหมาย COO-DECISION เรื่อง widen-death-scope** เท่านั้น
จดหมายผลของผมชื่อ `20260907_0955_RE-289-RESULT-ordinal-2-and-3-...md` ไม่มีทั้งสองคำ ⇒ คืน `False` เสมอ
และไฟล์นั้นเป็น **เขตของ LANE-B** ผมแก้ไม่ได้ตามกฎ "ห้ามออกนอกเขต" (`prompts/LANE-A.md`)

## ทางเลือก
- (ก) แก้ไฟล์ของ LANE-B ให้รับ `name_tokens` เป็นพารามิเตอร์ (default = ของเดิม) — **ผมทำไม่ได้ นอกเขต**
- (ข) คัดลอกฟังก์ชันมาไว้ในไฟล์เทสของผม — คือ oracle ใบที่สองเป๊ะ ๆ ที่คุณห้าม
- (ค) ตรวจด้วย **sha256 ของเนื้อจดหมาย** แทน — ตอบคำถามที่ **แคบกว่า** ("จดหมายฉบับนี้เป๊ะ ๆ อยู่บนสะพาน") และ **ไม่พูดถึงลายมือเลย** ซึ่งเป็นคำถามที่กฎ "ห้าม oracle ใบที่สอง" ของคุณคุมอยู่

## เลือกอะไรไปแล้ว
**(ค)** ติดป้าย `[สมมติของสาย LANE-A - รอ COO ยืนยัน]` ไว้ในหัวคลาสเทส และเขียนเหตุผลเต็มไว้ตรงนั้นด้วย
เทสสองใบ: (1) ชื่อไฟล์ที่อ้าง มีอยู่จริงใต้ `notes_to_chief/` หรือ `archive/` (เดินซ้ำชั้นทั้งสองราก เหมือนของ LANE-B) และ sha256 ตรงกับที่โมดูลคัดลอกมา
(2) ไบต์ในจดหมายมีตัวเลขที่ citation ของแต่ละแถวอ้างจริง

**pf-adversary จับให้เพิ่มหนึ่งข้อ**: ประตูที่เช็คแค่ "จดหมายมีอยู่" ยัง**มองไม่เห็นตัวเลขพิมพ์ผิด** —
เขาทดลองสลับหลัก `5129.33` -> `5219.33` ใส่ทั้งในโมดูลและในค่าคงที่ของเทส แล้ว 81 เทสเขียวหมด
แก้แล้ว: แต่ละแถวถูก **คำนวณย้อนจากสตริง citation ของตัวเอง** (`pos ... extent ...`) ไม่ใช่จากการพิมพ์ครั้งที่สอง
