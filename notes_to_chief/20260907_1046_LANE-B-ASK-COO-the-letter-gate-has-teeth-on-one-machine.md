# ประตูจดหมายมีเขี้ยวบนเครื่องเดียวในโลก และเครื่องนั้นคือเครื่องคุณ — เคาะให้หน่อยว่าพอไหม

ใบ `0945` ตอบครบสามข้อที่ผมถาม (graft = WARN · ผู้อ่าน WARN = ไฟล์รอบ · จดหมายกุญแจห้ามย้าย) ขอบคุณครับ
เดินตามนั้นทั้งหมดในรอบนี้แล้ว **ใบนี้ไม่ได้ขอทบทวนข้อไหน** แต่เป็นคำถามที่ pf-adversary ทิ้งไว้แล้วผมตอบเองไม่ได้

## สิ่งที่วัดได้ (ไม่ใช่ความเห็น)
`grep -rn "pf_bridge\|PF_BRIDGE_DIR" .github/` ในรีโปเซิร์ฟเวอร์ = **ไม่มี workflow ไหนเช็คเอาต์ `pf_bridge`**
(`fetch-depth: 0` ใน `gate-windows.yml` เป็นประวัติของรีโปเซิร์ฟเวอร์เอง มีไว้ให้ `pf_multiplayer_readiness_audit.py`)
⇒ ไม่มี sibling และไม่มี `PF_BRIDGE_DIR` ⇒ **เทสประตูจดหมาย SKIP บน CI ทุกครั้ง**
⇒ สถานะจริงวันนี้: CI ตรวจลายมือ **0 ใบ** · โคลนคลาวด์ทุกใบ = WARN (shallow) · เครื่องเดียวที่ตัดสินจริง = **เครื่องคุณ**
🔴 รอบก่อน (`av245e`) ผมเขียนคอมเมนต์ในไฟล์เทสว่า "มีสองเครื่องที่ตัดสิน" — **ผิด** รอบนี้แก้คอมเมนต์แล้ว
และแก้จดหมาย `0902` ที่อ้างต่อ ๆ กันมาด้วยใบนี้: ประโยคนั้นในใบ `0902` ให้ถือว่า **ถอน**

## ทำไมถึงเป็นเรื่อง
ประตูนี้คือสิ่งที่กันไม่ให้ "สายมินต์ใบอนุญาตฆ่ามอนให้ตัวเองด้วยการตั้งชื่อไฟล์"
ถ้ามันรันจริงเฉพาะตอนคุณรันชุดเต็มเอง แปลว่าใบอนุญาตปลอมจะเข้า main ได้ และจะถูกจับตอนคุณรัน ไม่ใช่ตอน merge
= เกตที่ทุกคนเชื่อว่ามี แต่ไม่มีใครเห็นมันทำงาน (นี่คือรูปเดียวกับที่ `#996` โดน)

## ทางเลือกที่ผมเห็น (เรียงจากถูกไปแพง)
1. **ปล่อยไว้ตามนี้** เขียนความจริงลงคอมเมนต์ (ทำแล้วรอบนี้) — ราคา: เกตทำงานช้ากว่าที่คิด แต่ยังทำงาน
2. **`gate-windows` เช็คเอาต์ `pf_bridge` เพิ่มหนึ่งขั้น** (`fetch-depth: 0` ด้วย ไม่งั้นได้ WARN ล้วน) —
   เป็นเขต chief และคิว chief ยาว 11 ข้อ ⇒ ต้องผ่านคุณก่อน ผมไม่แทรกเอง
3. ย้ายกฎไปอยู่ในโค้ดโปรดักชัน (`mob_death` ปฏิเสธ ruling key ที่ไม่มีจดหมาย) — **ผมไม่แนะนำ**:
   ทำให้เซิร์ฟเวอร์ต้องมีรีโปที่สองตอนรัน = ผูกโปรดักชันเข้ากับสะพาน
