# `GT-186` / `GT-184` เนื้อใบใหม่ — **ใบเดียวสองปุ่ม** · เลิกเดาเฟรมที่จะทำให้จอเปลี่ยน แล้ววัดว่าไคลเอนต์ทำอะไรเอง

K ขอเนื้อใบใหม่ที่ไม่พึ่ง retry `0x709E` จาก HOME · นี่คือเนื้อใบนั้น K วางคำต่อคำได้เลย
เป็น **ใบเดียว** เพราะสองปุ่มใช้บูตเดียว กดต่อกัน และข้อสังเกตของปุ่มแรกเป็นเบาะแสของปุ่มที่สอง

## ทำไมวัตถุประสงค์เดิมต้องตาย (ข้อเท็จจริง ไม่ใช่ความเห็น)
สามเส้นทางถูกปิดไปแล้ว และทั้งสามเป็นการ **เดาว่าเฟรมไหนทำให้จอเปลี่ยน**:
1. ACK `0x1B40` + ปิด socket ฝั่งเซิร์ฟเวอร์ — **ตกบนจอ** (`R311`, ซ้ำใน `R319`) จอไม่ขยับทั้งสองปุ่ม
2. push `0x709E` ทรงศูนย์ล้วน + string ว่าง ตอน dialog เปิด — **ตกบนจอ** (`R319`) ไคลเอนต์รับแล้วเงียบ แล้วส่ง `0x1B40` ของมันเองต่อ
3. static หาเส้นทางที่ true branch ของ `0x709E` เปิด UI/หน้าเลือกตัวละครตรง ๆ — **ไม่พบ** (`RE-266` BOUNDED-NEGATIVE)
   และ `GetWorldInfoVital 0x3D4B` R-side handler ไม่มี pending-reply/ack flag ⇒ BUILD_IMPACT: ห้าม retry `0x709E` ด้วย payload tweak

🔴 หลังจากเดาสามครั้งแล้วตกสามครั้ง **สิ่งที่ขาดไม่ใช่การเดาครั้งที่สี่** — สิ่งที่ไม่มีใครวัดเลยสักครั้งคือ
**ไคลเอนต์ทำอะไรด้วยตัวเองเมื่อ socket ตายใต้มัน และการปฏิเสธที่ LANE-A ทำไว้ผู้เล่นเห็นไหม**
เนื้อใบนี้จึงเปลี่ยนคำถามจาก "เฟรมไหนทำให้จอเปลี่ยน" เป็น "จอทำอะไรอยู่แล้ว" ซึ่งบูตเดียวตอบได้ และไม่ต้องมีไบต์ใหม่แม้ไบต์เดียว

## เนื้อใบ (วางลง `GAME_TEST_QUEUE.md` ได้ตามนี้)

**ชื่อ**: `GT-186` + `GT-184` (พับเป็นใบเดียว) — ปุ่มออกจากเกม / ปุ่มกลับหน้าเลือกตัวละคร: วัดพฤติกรรมไคลเอนต์ ไม่ใช่ทดสอบเฟรมใหม่

**สิ่งที่เปลี่ยนจากเนื้อใบเดิม**: ไม่มีการส่ง `0x709E` ไม่มี payload tweak ไม่มีธง ไม่มีทรีพิเศษ
เซิร์ฟเวอร์ทำสิ่งที่มันทำอยู่บน main วันนี้เท่านั้น (ACK `0x1B40` subcode 1 + ปิด lease + นัดปิด socket 250 ms · subcode 3 = ตอบใบปฏิเสธของ LANE-A)

**สิ่งที่ต้องตอบ — สามข้อ อิสระจากกัน ทุกข้อตอบได้ในบูตเดียว**

- **O1 (ปุ่มออกจากเกม · เดิม `GT-186`)**: กด "Exit Game" แล้ว **จับเวลา** ว่าไคลเอนต์ทำอะไรต่อ ภายใน 10 วินาที
  เลือกหนึ่ง: (ก) โปรเซสปิดตัวเอง (ข) เด้งไปหน้าล็อกอิน (ค) ขึ้นกล่องข้อความ (เขียนข้อความที่เห็น) (ง) ค้างในโลกเหมือนเดิม (จ) อื่น ๆ
  🔴 **นี่คือค่าที่ไม่มีใครเคยเขียนลงกระดาษ** — `R311`/`R319` บันทึกแค่ว่า "จอไม่เปลี่ยน" ซึ่งตอบ (ง) โดยไม่ได้ตั้งใจตอบ และไม่ได้บอกว่ารอไปนานแค่ไหน
- **O2 (ปุ่มกลับหน้าเลือกตัวละคร · เดิม `GT-184`)**: กด "Back/กลับ" แล้วดูว่า **ใบปฏิเสธของเซิร์ฟเวอร์ผู้เล่นเห็นหรือไม่**
  เซิร์ฟเวอร์ตอบ notice จริง (คอนโซลพิมพ์ `LANE_A_UIA_NOTICE_COMPOSED button=BACK_TO_CHARSELECT subcode=3 vitals=1 pc=56 frame=66`)
  ⇒ บนจอเห็นอะไร: ข้อความ? กล่อง? ไม่มีอะไรเลย? **ถ้าไม่มีอะไรเลย = ชั้นปฏิเสธที่ `GT-205`/`GT-211` วางไว้เป็นจุดเริ่ม ผู้เล่นมองไม่เห็น**
  ซึ่งเป็นข้อเท็จจริงระดับตัดสินใจ ไม่ใช่รายละเอียด — และเป็นเหตุผลว่าทำไมใบนี้ยังคุ้มบูตแม้เส้นทางเดิมตายหมด
- **O3 (เบาะแส ฟรี ไม่ต้องกดเพิ่ม)**: ถ้า O1 ตอบ (ข) "เด้งไปหน้าล็อกอิน" ⇒ ล็อกอินใหม่ในบูตเดียวกัน แล้วดูว่าถึง **หน้าเลือกตัวละคร** ไหม
  ถ้าถึง ⇒ สิ่งที่ปุ่ม `GT-184` สัญญาไว้ **เดินถึงได้โดยไม่ต้องมีเฟรมใหม่เลย** (ล็อกเอาต์ → ล็อกอิน → เลือกตัวละคร)
  และงานของสายนี้เปลี่ยนจาก "หาเฟรมที่เปิดหน้าเลือกตัว" เป็น "ทำให้ปุ่มเดินเส้นทางที่มีอยู่แล้ว" — ราคาต่างกันคนละโลก

**เกณฑ์ผ่าน/ไม่ผ่าน** — ใบนี้ **ผ่านเมื่อ O1/O2/O3 ถูกบันทึกครบ** ไม่ใช่เมื่อจอเปลี่ยน
🔴 จงใจ: จอเปลี่ยนหรือไม่คือ **ผลการวัด** ของใบนี้ ไม่ใช่เงื่อนไขผ่าน ใบที่ผ่านก็ต่อเมื่อจอเปลี่ยนคือใบที่บังคับให้รอบถัดไปเดาเฟรมที่สี่
