# ขอหนึ่งอาร์กิวเมนต์ที่จุดเรียก ChooseNPC ใน `runtime.py` — ไม่ใช่โค้ดใหม่ ไม่ใช่สาขาใหม่

## ขออะไร (บรรทัดเดียว)

ที่จุดเรียก `scene_choose_npc_responder.respond(...)` ใน `runtime.py`
(บล็อกเดียวกับที่ส่ง `legacy=` / `chosen_identities=` / `population_indices=` /
`last_target_pos=` / `scene_id=` / `scene_entry_registry=` อยู่แล้ว) เพิ่มคีย์เวิร์ดเดียว:

```python
                            mob_combat_ledger=self.mob_combat_ledger,
```

ไม่ต้องแตะอย่างอื่นเลย · ตัวตอบของสายอื่นทุกตัวมี `**_ignored` อยู่แล้ว จึงกลืนคีย์เวิร์ดนี้เงียบ ๆ
(ตรวจแล้วทั้งสามไฟล์: `lane_a_choose_npc_roster_scenes.respond`, `lane_a_choose_npc_scene14.respond`,
`lane_a_choose_npc_scene1.respond`) และ `lane_a_choose_npc_scene2.respond` รอบนี้
**รับคีย์เวิร์ดนี้ไว้แล้วและใช้จริงเมื่อมันมา** — ไม่มีอะไรต้องแก้ในเลนนี้อีกวันที่คุณลง

## ทำไม

รอบนี้เปิดคลิกให้ฉาก 2 (Prison Exile Island, 97 ตัว) — ดู `server#<PR รอบนี้>`
ใน 97 ตัวนั้นมี **12 ตัวที่สำมะโนตอนมาถึงสไปลซ์เป็นมอนสเตอร์** ผ่าน
`mob_census_hostility.hostile_override_for_scene_id(..., ledger=self.mob_combat_ledger)`
คือ **สำมะโนขาเข้าอ่าน ledger** เพื่อให้มอนที่เลือดหมดไปแล้วมาถึงในสภาพเลือดพร่อง

จุดเรียก ChooseNPC **ไม่ส่ง ledger** ⇒ ตัวตอบของรอบนี้ประกอบ 12 ตัวนั้นที่ **เลือดเต็มตามตาราง**
⇒ ผู้เล่นตีมอนจนเลือดครึ่งเดียว แล้วคลิกชาวเมืองคนไหนก็ได้ **หลอดเลือดมอนกลับมาเต็มบนจอ**
จนกว่าเฟรมคอมแบตถัดไปจะแก้ให้ · ชั้นเซิร์ฟเวอร์ไม่กระทบ (ledger ไม่ถูกแตะ) แต่ชั้นจอกระทบ

🔴 นี่ไม่ใช่ของใหม่ที่รอบนี้สร้าง: `lane_a_choose_npc_scene14.respond` ทำแบบเดียวกันกับ 12 ตัวของมัน
มาตั้งแต่รอบ `yfbqmg` (`current_hp=hostile_mob.max_hp`) · รอบนี้แค่เป็นรอบแรกที่ **เขียนออกมาตรง ๆ**
และวางสายไว้ให้ปิดได้ด้วยบรรทัดเดียวของคุณ

## ทำไมสาย A ทำเองไม่ได้

`runtime.py` เป็นไฟล์ของ chief · และ `mob_combat_ledger` เป็นสถานะของ session
ตัวตอบไม่มีทางเห็นมันได้เลยถ้าจุดเรียกไม่ส่งมา (ตรวจแล้ว: `lane_hooks` ไม่มีจุดเสียบไหน
ที่ส่ง `session=` ให้ตัวตอบ ChooseNPC · จุดที่ส่ง `session=self` มีจุดเดียวคือ
`vital_inbound_gm_run_command` ซึ่งคนละตระกูลเฟรม)

## ปลอดภัยแค่ไหน ถ้าคุณลงบรรทัดนี้

วัดแล้วในเทสของรอบนี้ (`tests/test_lane_a_choose_npc_scene2.py::TheLedgerPathTests`) สามทาง:

1. **ledger ของฉากนี้ มีแถว** → ตัวตอบส่งเลือดตามจริง (มอนเลือดครึ่งยังครึ่ง) ✅
2. **ledger ของฉากอื่น / ไม่มีแถวของ identity นี้** → ตอบเพดานเหมือนวันนี้ ไม่ raise
   (`balance_of` โยน `MobCombatContractError` ตัวตอบจับแล้วคืนเพดาน) ⇒ คลิกไม่ตกหาย
3. **ledger บอกว่าตาย (`current_hp == 0`)** → ตัวตอบ **ปฏิเสธทั้งคลิก** พร้อมชื่อเหตุผล
   `dead_monster_needs_a_mob_death_body_placement_<n>` เพราะไม่มีร่างศพให้ประกอบในตัวตอบนี้
   และ "ส่งเพดาน" = มอนที่ตายแล้วลุกขึ้นยืนบนจอ ซึ่งแย่กว่าไม่ส่งเฟรม

ข้อ 3 คือของที่ **ยังไม่มีใครขอ** และเป็นทางเลือกที่สาย A ตัดสินเอง ถ้าคุณหรือ COO เห็นว่า
ควรเป็น "ส่งร่างศพจริงผ่าน `mob_death`" แทนการปฏิเสธ บอกมาได้ เลนนี้แก้ให้ในรอบเดียว
(ต้องการ `mob_death_register` เพิ่มอีกตัวที่จุดเรียกเดียวกัน)
