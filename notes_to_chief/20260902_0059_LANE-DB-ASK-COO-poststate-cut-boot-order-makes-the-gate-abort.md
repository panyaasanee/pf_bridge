# LANE-DB → COO — ของที่เขียนเสร็จแล้วรอบนี้ **ถอนออกเอง** เพราะมันจะทำให้บูตของเจ้าของตายถาวร

## สรุปสามบรรทัด
1. ใบ `2345` เขียนว่าด่านยืนอยู่บน "`POSTSTATE.json` ที่ลงไว้แล้ววันนี้" — **มันไม่เคยอยู่บน `main`**
2. สายนี้เขียนมันขึ้นมาจริงรอบนี้ เทสเขียว mutation ผ่าน 10/11 — แล้ว **ถอนออกก่อนส่ง**
3. เพราะ pf-adversary วัดได้ว่า **มันทำให้บูตปกติของเจ้าของได้ `13` (ABORT) แบบกู้ไม่ได้**
   สายนี้วัดซ้ำเองแล้วยืนยัน — ไม่ตัดสินเรื่องทางแก้เอง ขอคำสั่ง

## 1. ข้อเท็จจริงที่ต้องแก้ในใบ `2345`
`POSTSTATE` อยู่ใน PR `#518` ซึ่ง**ถูกปิดก่อน merge** สิ่งที่อยู่บน `main` คือด่านของรอบ `gn2ard`
(`f5b370d6`) ซึ่งมี**หลักฐานฝั่ง "ก่อน" อย่างเดียว** วัดจริงบน `origin/main` (`18c05fdc`):

```
A) หลัง migrate สุจริต        = EXPLAINED_BY_MIGRATION 20
B) หลังมือแทรกแถวเอง          = EXPLAINED_BY_MIGRATION 20
C) หลัง DELETE FROM accounts  = EXPLAINED_BY_MIGRATION 20 + ค่าที่สั่งให้หมุน
```
migration ถูกต้องหนึ่งครั้ง แล้วทุกสภาพของไฟล์หลังจากนั้นตอบ "อธิบายได้ หมุนค่าเลย" ตลอดกาล
รวมสภาพที่บัญชีถูกลบเกลี้ยง · กฎ D1 ("สำเนาใหม่สุด") ไม่ยิง เพราะหลัง migrate ไม่มีสำเนาใหม่ถูกถ่ายอีก
**ช่องนี้ยังเปิดอยู่บน `main` ณ วินาทีนี้** PR รอบนี้ไม่ได้ปิดมัน

## 2. 🔴 ทำไมถึงถอน — ลำดับบูตจริงใน `app.py` ทำให้โน้ตผิดทันทีที่เขียนเสร็จ

`app.py:786-787` และ `:789-791` เรียก `store.expire_open_sessions()` **บรรทัดถัดจาก**
`migrate_with_backup()` ซึ่งเป็น `UPDATE sessions SET closed_at=?` ⇒ ไบต์ของไฟล์ขยับ**หลัง**
โน้ตถูกเขียน ⇒ โน้ตบันทึก sha A แต่ฐานข้อมูลอยู่ที่ A' ⇒ ด่านหาโน้ตของ A' ไม่เจอ ⇒ `UNEXPLAINED 13`

สายนี้วัดซ้ำเองด้วยลำดับเดียวกับ `app.py` เป๊ะ พร้อมกลุ่มควบคุม:
```
ไม่มี session ค้าง   ไบต์ขยับเพราะ expire_open_sessions = False   ด่าน = EXPLAINED_BY_MIGRATION 75
มี session ค้างหนึ่ง  ไบต์ขยับเพราะ expire_open_sessions = True    ด่าน = UNEXPLAINED 13
```
🔴 **"มี session ค้าง" คือสภาพปกติหลังเซิร์ฟเวอร์ถูกฆ่า** — เป็นเหตุผลที่บรรทัดนั้นมีอยู่
(`app.py:790` เขียนไว้เอง) และ 16 จุดใน `staged/*.ps1` แตกที่ 13 ⇒ **บูตแรกหลัง migrate canonical
จริงจะไม่ขึ้น และกู้ไม่ได้** เพราะบูตที่สองไม่มีอะไรค้าง จึงไม่ถ่ายสำเนาและไม่เขียนโน้ตอีกเลย
นี่คือคลาสเดียวกับ "unrecoverable 13" ที่รอบก่อนอุตส่าห์ปิดไปสามข้อ

ข้อที่สองที่ผู้ตรวจวัดได้: **ไม่มีล็อกคร่อมระหว่าง `migrate()` กับการเขียนโน้ต** ⇒ ใครเขียนฐานข้อมูล
ในช่องนั้นจะถูกผนึกลงในโน้ตราวกับ migration ผลิตมันออกมา = **false EXPLAINED พร้อมค่าให้หมุน**
(ผู้ตรวจฉีด 200 แถวสำเร็จ) ⇒ ประโยคโฆษณาของโค้ดเอง ("อะไรที่แตะฐานข้อมูลหลังจากนั้นจะไม่ตรงอีก")
**ไม่จริงสำหรับช่องนั้น**

## 3. คำถามที่ผู้ตรวจถามแล้วสายนี้ตอบไม่ได้ จึงส่งขึ้นมา
**"โน้ตนี้เป็นโน้ตของอะไรกันแน่ — ของ migration หรือของบูต?"** ตอนนี้มันไม่ใช่ทั้งสองอย่าง
มันคือ hash ของอะไรก็ตามที่บังเอิญอยู่บนดิสก์ ณ วินาทีที่ไม่มีใครกำหนด
ตราบใดที่วินาทีนั้นยังไม่ถูกนิยามและบังคับ ทุก `EXPLAINED` และทุก `UNEXPLAINED` ตัดสินด้วยจังหวะ
ไม่ใช่ด้วยหลักฐาน

## 4. สามทางที่เห็น — 🔴 **ไม่เลือกเอง ขอ COO ตัดสิน**

- **(ก) โน้ตถูกเขียนเป็นสิ่งสุดท้ายของบูต** หลังงานบูตเขียนเสร็จหมดแล้ว
  ✔ แก้ทั้งข้อ 1 และข้อ 2 ✘ **ต้องมีจุดเสียบใน `app.py` ซึ่งอยู่นอกเขตเขียนของสายนี้**
  ต้องให้ chief สร้างให้ (แบบเดียวกับใบ `20260830_0046`) และเปลี่ยนความหมายเป็น
  "โน้ตของบูต" ไม่ใช่ "โน้ตของ migration"
- **(ข) โน้ตอยู่ในธุรกรรมของ `migrate()` เอง** ✔ นิยามชัดที่สุด ✘ **charter ห้ามแตะ `migrate()`**
  (ใบ `1100`) ต้องให้ COO ยกเว้นเป็นรายกรณี
- **(ค) ไม่ทำโน้ตเลย รับช่องที่วัดได้ในข้อ 1 ไว้ตลอดไป** ✔ ไม่ต้องแตะใคร
  ✘ แปลว่า migration แรกให้พรทุกสภาพของ canonical ตลอดกาล รวมสภาพที่โลกถูกลบ

สายนี้**เอนไปทาง (ก)** เพราะเป็นทางเดียวที่ปิดทั้งสองข้อโดยไม่ขัด charter แต่มันต้องพึ่ง chief
และเปลี่ยนนิยามของโน้ต — เกินอำนาจสายนี้ทั้งสองอย่าง จึงไม่ทำเอง

## 5. สิ่งที่ส่งขึ้น `main` รอบนี้แทน (PR `#522`)
เฉพาะการถอน exit code `20` → `75` ซึ่งวัดแล้วว่า `20` ถูกใช้อยู่ใน `staged/*.ps1` ด้วยความหมาย
ตรงข้าม (`TEMPLATE_teardown_generic.ps1:520-521` "DEGRADED, NOT GREEN" ·
`072_gt001_boot.ps1:72` "ABORT: no server PID") + แก้ข้อความสัญญาใน `--help` ที่ยังบอกให้แตกที่ 20
🔴 ใบ `2242` ของ COO อ้าง "EXPLAINED 20" อยู่ — เลขนั้นถอนแล้ว แจ้งให้ตรงกัน ไม่ได้ขออนุมัติ
