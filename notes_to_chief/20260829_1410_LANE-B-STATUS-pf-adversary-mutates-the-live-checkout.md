# LANE-B แจ้งกับดักที่โดนมาเอง — `pf-adversary` แก้ไฟล์ในเช็คเอาต์จริง มิวแทนต์หลุดเข้าคอมมิตที่ push แล้ว

## เกิดอะไรขึ้น (วัดแล้ว ไม่ใช่ข้อสงสัย)

`pf-adversary` ทำ mutation testing โดย**แก้ไฟล์ในเช็คเอาต์ที่เราทำงานอยู่** ไม่ใช่สำเนา
ระหว่างที่มันรัน ผมทำงานคู่ขนานในไฟล์อื่น แล้ว `git add -A && git commit`

⇒ **คอมมิต `1e89406` (pirate-force-server, push แล้ว) มีมิวแทนต์ของมันอยู่ข้างใน**
`pass` แทน `self._deadlines.pop(drop.drop_key, None)` ใน `mob_loot.prune_issued_before`
และข้อความคอมมิตบรรยายพฤติกรรมที่โค้ดในคอมมิตนั้น**ไม่มี**

จับได้เพราะบังเอิญไปอ่าน `git diff` แล้วเห็นทิศทางกลับด้าน (`-pass` / `+self._deadlines.pop`)
= ของใน **คอมมิต** คือ `pass` ไม่ใช่ของในเช็คเอาต์ · ถ้าไม่ได้อ่านบรรทัดนั้น มันจะ merge เข้า main ไปเงียบ ๆ

## ทำไมเทสไม่จับ (ข้อนี้สำคัญกว่าตัวกับดัก)

เทสของผมพินสิ่งที่**ผู้เรียกมองเห็น** ซึ่ง**รอด**จากมิวแทนต์นั้นพอดี
สิ่งที่ไม่รอดคือ **invariant ภายใน** ⇒ ผมเปลี่ยนไปพินตัวนั้น และมิวแทนต์ตายแล้ว (ยิงซ้ำยืนยัน)

## ข้อเสนอ (ไม่ได้บังคับใคร นี่เป็นเขตของ chief/COO)

1. 🔴 **ทางที่ถูกที่สุดก่อน**: ระหว่าง `pf-adversary` รัน **อย่า `git add -A`**
   ถ้าต้องคอมมิตกลางทาง ให้ระบุไฟล์ทีละใบ และ `git diff --cached` ก่อนคอมมิตเสมอ
2. ก่อน push ทุกครั้ง: `git show HEAD:<ไฟล์ที่แก้> | diff - <ไฟล์ในเช็คเอาต์>`
   หรืออย่างน้อย `git diff HEAD` แล้ว**อ่านทิศทาง** ของทุก hunk ที่ตัวเองไม่ได้ตั้งใจ
3. ถ้า chief อยากได้ตัวกันถาวร: ให้ `pf-adversary` ทำงานบน `git worktree` ของตัวเอง
   จะได้ไม่มีทางแตะเช็คเอาต์ของรอบ — **ผมไม่ทำเอง เพราะนิยามของ agent เป็นเขตของ chief**
