เพราะถูกกรองออกที่ marker ก่อนแล้ว

## ห่วงโซ่ที่ทำให้กู้ไม่ได้ (deterministic ไม่ใช่ดวง)

1. รอบเปิด draft PR ยึดล็อก — body เป็น "WIP round claim" **ยังไม่มี marker** (สาย GM บันทึกไว้เองในรอบ
   `fftpji`: "ไม่มี draft ไม่มี `PF-AUTOMERGE: v4` จนกว่ารอบนี้จะจบ")
2. รอบทำงาน push ครบ
3. ขั้น "ปลด draft" ล้ม — รอบนี้ไม่ใช่เพราะไม่รู้ท่า แต่เพราะ **เครื่องมือ GitHub MCP ไม่มีอยู่ในเซสชันนั้น**
   (สาย A รายงานเอง: *"the GitHub MCP tool needed to flip draft→ready wasn't available this session"*)
4. ขั้นถัดไป (แก้หัวข้อ/body ที่เป็นจุดใส่ marker) **จึงไม่ได้ทำ**
5. PR ไม่มี marker ตลอดกาล ⇒ reaper ข้าม ⇒ **ไม่มีอะไรในระบบกู้ได้เลย เหลือทางเดียวคือเจ้าของกดเอง**

prompt เดิมทุกสายเขียนว่า marker ใส่ "ทุกครั้งที่เขียน body ใหม่" ซึ่งเป็นขั้นสุดท้าย — ลำดับนี้เองคือบั๊ก

## สิ่งที่ทำไปแล้ว (เจ้าของอนุมัติ กำลังวาง prompt)

สลับลำดับขั้นจบรอบของสาย A/B/GM และ chief: **`1 push → 2 แก้หัวข้อ+body ใส่ marker → 3 ปลด draft`**
(เดิม 2 กับ 3 สลับกัน) ⇒ ปลด draft ล้มเมื่อไหร่ PR ก็ยังมี marker อยู่แล้ว reaper รับช่วงที่ 45 นาที
ปลดให้ด้วยโทเคนของ runner แล้ว merge เอง **เจ้าของไม่ต้องกด**

ตรวจความปลอดภัยก่อนเสนอ: job `decide`/`finish` ข้าม draft ทุกใบอยู่แล้ว (`[ "$DRAFT" = "false" ] || continue`
บรรทัด 301/544 เซิร์ฟเวอร์, 161 บริดจ์) และ reaper แตะ draft เฉพาะอายุ ≥ 45 นาที ⇒ marker ที่ลง body
ตอนขั้นที่ 2 ไม่ทำให้ PR ถูก merge กลางรอบ เพราะถึงขั้นนั้นงาน push ครบแล้ว
