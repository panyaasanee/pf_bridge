# COO-DECISION — GM-049 เลือกทาง (ค): ยกเว้นเงื่อนไข (ค) ชั่วคราว เฉพาะ /speed sparse x=7

## ตัดสินว่าอะไร

เลือก **(ค)** ไม่ใช่ (ก) หรือ (ข): ยกเว้นเงื่อนไข (ค) ของ `gm/attr_wire.py`
(`UPDATE_ATTR_VITAL_VERSION_CONFIRMED`) **ชั่วคราวและแคบ** — ใช้ได้เฉพาะจุดส่ง `/speed`
sparse mask x=7 เท่านั้น **ไม่ใช่บรรทัดฐานทั่วไปของโมดูล** เงื่อนไข (ก)/(ข)/(ค) ของ
`attr_wire.py` ยังยืนสำหรับ full-block และ opcode อื่นทุกตัวเหมือนเดิม

## เพราะอะไร

ความเสี่ยงมีเพดานและย้อนกลับได้: `FINDINGS_R19` ยืนยันแล้วว่าไบต์ผิด = client reject
เฟรม/reconnect ต้อง login ใหม่ ไม่ใช่ข้อมูลเสีย — ไม่เข้าเกณฑ์ "ย้อนไม่ได้" ที่ต้องรอเธอ
sparse x=7 ไม่แตะ unnamed fields จึงเงื่อนไข (ข) เดิม (ออกแบบมาสำหรับ full-block) ไม่เกี่ยวกับ
เคสนี้อยู่แล้ว เหลือแค่ (ค) vital_version byte ซึ่งอยู่ใน header ไม่ใช่ field data — ยอมรับความ
เสี่ยงนี้เฉพาะจุดสอดคล้องกับทิศทางที่ Panya วางไว้ 16:39 ("ส่งให้พอใช้งานได้ก่อน") แม้ใบขอจะ
พูดถูกว่าเป็นคนละคำถามทางเทคนิคจาก RE-194 — เรื่องนี้ไม่ใช่ ก/ข/ค ที่ต้องเก็บไว้ถามเธอ (ทิศทาง
ไม่เปลี่ยน, มี fallback ย้อนกลับได้, ไม่ขัดคำสั่งเธอเรื่องไหนตรงๆ)

## ใครทำอะไรต่อ

   ต้องมีเหตุผลอ้างอิงของตัวเอง (เช่น pattern ของ header อื่นที่พิสูจน์แล้วในตระกูลเดียวกัน)
   บันทึกเหตุผลไว้ในคอมมิต/ใบเปิด GT
2. **LANE-GM**: parser/composer เสร็จแล้ว ไม่ต้องทำเพิ่ม รอ chief ต่อสาย
3. **chief**: ปิด CORE-REQUEST GM-049 แถว 030 ใน `CHIEF_CONTINUATION.md` ทันทีที่ต่อสายเสร็จ

   ตาม pattern เดียวกับ RE-193) เมื่อพิสูจน์ได้จริงแล้วค่อยปิดเป็นเงื่อนไขถาวรของ `attr_wire.py`
