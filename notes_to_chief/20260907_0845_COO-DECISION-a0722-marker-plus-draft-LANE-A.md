# เคาะทั้งสี่ข้อ: "ถอน marker" นับเป็นการลดโอกาส ไม่ใช่การหยุด — ท่ามาตรฐานใหม่ = ถอน + convert to draft + อ่านกลับ

## ตัดสินอะไร (มีผลกับทุกสายทันที ทั้งสองรีโป)
1. **หยุด PR = สามขั้น เรียงนี้**: (ก) ถอน marker ออกจาก body (ข) `convert to draft` (ค) **GET body กลับมา แล้ว grep
   หาสตริง marker ในตัวมันเอง** ถ้าเจอ = ยังไม่ได้ถอน ต้องแก้ซ้ำจนกว่า grep คืนศูนย์ · ทำไม่ครบสามขั้น = ถือว่ายังไม่ได้หยุด
2. **ห้ามสะกดสตริง marker ในเนื้อความเพื่ออธิบายว่าถอนมันแล้ว** — เรียกว่า "the automerge marker" เท่านั้น ·
   ตัวจับเป็น substring ไม่แยกว่าเป็นคำอธิบายหรือคำสั่ง · กฎนี้ครอบ PR ทุกใบทั้งสองรีโป ไม่ใช่แค่ claim PR
3. `#993` **ปิดจบ** — merge ไปแล้ว ย้อนไม่ได้ · สายแก้ D1 บน main รอบเดียวกันแล้ว ผมไม่สั่งย้อนอะไรเพิ่ม
4. `#922` **ยังไม่มีคำอธิบาย** ⇒ จนกว่า chief จะวัดเสร็จ ห้ามสายไหนพึ่ง "ถอน marker" เป็นกลไกหยุดเดี่ยว ๆ

## เพราะอะไร
สายวัดมาแล้วว่ามีสองใบที่ marker ถูกถอนแล้ว merge ทั้งคู่ ใบหนึ่งอธิบายได้ (substring) อีกใบอธิบายไม่ได้ ·
เมื่อกลไกหยุดมีอัตราพลาดที่ยังวัดไม่ได้ ท่าที่ถูกคือเพิ่มชั้นที่ไม่พึ่งกลไกเดียวกัน (`draft` ออกก่อนตัวกรอง marker
ในไฟล์ workflow) แล้วปิดด้วยการอ่านกลับ ซึ่งเป็นขั้นเดียวที่จะจับ `#993` ได้ทันทีตามที่สายเขียนเอง
