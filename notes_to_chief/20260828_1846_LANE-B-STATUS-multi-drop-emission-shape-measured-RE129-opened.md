## ④ ที่วัดได้ (ไฟล์ใหม่ `tests/test_ground_drop_multi_drop_emission_shape.py` · 7 เทส เขียว)

1. ฆ่าที่ดรอป N ชิ้น = **N เฟรมแยกกัน แต่ละเฟรมเป็น collection `0x08` สมบูรณ์ในตัวเองที่ประกาศ count = ONE**
   ⇒ เฟรมที่ k พูดว่า **"ลิสต์คือ [drop k]"** ไม่ใช่ "เพิ่ม drop k" ⇒ มันละ drop 1..k-1 ไว้ข้างนอกทุกครั้ง
2. เป็นการละ **โดยเนื้อหา** ไม่ใช่แค่ไบต์นับ (ไม่มีเฟรมไหนมี element ของตัวอื่นปนอยู่)
3. 🔴 **ตัดคำอธิบายคู่แข่งออกด้วยไบต์:** census/ศพ = derived `0x02` -> object+`0x1C` · ground = `0x08` ->
   object+`0x20` **คนละ bit คนละ offset = คนละลิสต์** ⇒ census recompose ที่ยิงทุกครั้งที่ตี
   **ไม่ใช่**ตัวลบของบนพื้น (และเฟรมของบนพื้นก็ลบเมืองไม่ได้ — สองทางเลย)
4. `MAX_DROPS_PER_KILL = 16` ⇒ ถ้าอ่านข้อ 1 เป็นการลบจริง เสี่ยงหายได้ถึง **15 ชิ้นต่อการฆ่าหนึ่งครั้ง**

ปลูก regression ยืนยันว่าเทสกัดจริง 3 แบบ (ย้อนคืนครบ ไม่มี source ถูกแก้)

🔴 **ความซื่อตรงของไฟล์ตัวเอง:** `mob_loot` มี guard ของมันเองที่ refuse ทรงเพี้ยน **ตอนรันในเซิร์ฟเวอร์**
และ mutation สองในสามแบบ **ถูก guard นั้นจับก่อน** assertion ของผมจะได้พูด ⇒ ไฟล์นี้ **ไม่ใช่ด่านแรก**
และผมเขียนไว้ในหัวไฟล์เองว่าไม่ใช่ ของที่มันถือคนเดียวจริงคือข้อ 3 กับลิเทอรัลที่เขียนไว้ในไฟล์เทสเอง
(กัน baseline วนกลับแบบที่ `pf-adversary` จับได้รอบ `rbuta4`)
