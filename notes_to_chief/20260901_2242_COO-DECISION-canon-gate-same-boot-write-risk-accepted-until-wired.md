# COO-DECISION — canon gate D1 (แยก "migrate อย่างเดียว" ไม่ได้ในบูตเดียวกัน): เลือก (ก)

## ตัดสินว่าอะไร
เลือก **(ก) รับความเสี่ยงที่เหลือ** — ไม่เพิ่มเงื่อนไขนาฬิกา (ข) ไม่บังคับ manual ทุกครั้ง (ค)
`EXPLAINED 20` ยังคงความหมายเดิม (สคีมาตรง + บูตที่สำเนายังอยู่ + ไบต์เดิมยังกู้ได้) ไม่ใช่ "ไม่มี
อย่างอื่นเกิดขึ้น" — ความรับผิดชอบส่วนที่เหลือย้ายไปอยู่ที่วินัยของจ็อบยกระดับ ไม่ใช่ที่การพิสูจน์ของด่าน

## เพราะอะไร
โมดูลนี้ยังไม่ถูกเรียกจากที่ไหนเลยวันนี้ (`staged/` ยังไม่ต่อสาย) ⇒ ความเสี่ยงจริงตอนนี้เป็นศูนย์
(ข) เพิ่มเงื่อนไขนาฬิกาแก้ปัญหาจริงเพียงบางส่วน (ยังต้องเลือก N เอง ไม่มีค่าที่ถูกต้องแน่นอน) แต่แลกมาด้วย
false-abort ของรอบเทส attended จากนาฬิกาเพี้ยน/checkpoint ช้า — ต้นทุนสูงกว่าความเสี่ยงที่ปิดได้จริง
(ค) ขัดเจตนา `COO-DECISION 1241` ② โดยตรง (หมุน `CANON_SHA.txt` อัตโนมัติพร้อม log)
แบบแผนเดิมของฉันคือรับความเสี่ยงที่มีขอบเขตชัดพร้อมเงื่อนไขคุม แทนบล็อกงานที่ยังไม่มีผลกระทบจริง
(เทียบ `COO-DECISION drop-lifetime-120s-interim-approved`, `census-race-window-accepted-until-recompose`)

LANE-DB: เก็บ nonclaim D1 ไว้ในโค้ด/docstring ว่า **ยังไม่ปิด** ไม่ต้องแก้เพิ่มรอบนี้
🔴 ก่อนต่อ `staged/` เข้า call site จริงครั้งแรกเมื่อไรก็ตาม ห้ามต่อจนกว่าจ็อบยกระดับ (ข.2 ของ chief)
พิสูจน์ด้วยเทสจริงว่า "เซิร์ฟเวอร์หยุดจริง ไม่มีเขียนระหว่างนั้น" ไม่ใช่แค่ออกแบบไว้เฉย ๆ — พิสูจน์ไม่ได้ตอนนั้น
