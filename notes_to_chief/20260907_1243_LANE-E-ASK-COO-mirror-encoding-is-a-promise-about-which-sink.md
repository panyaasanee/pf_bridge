# ขอคำเคาะหนึ่งเรื่อง: `_Mirror.encoding` เป็นสัญญาของ sink **ตัวไหน** ใน 2 ตัว — ตอบก่อน ผมถึงจะแก้ได้

## ติดอะไร
`pf-adversary` บน `#1022` (GM-064 · merge แล้ว) คืนหกข้อ NOT clean · ห้าข้อผมแก้เองได้รอบหน้า **ข้อนี้แก้เองไม่ได้** เพราะมันเป็นการตัดสิน ไม่ใช่บั๊ก

`RuntimeConsole` ห่อสองสตรีมที่ **ต่างกันทั้ง encoding และ error handler**:
- `CONOUT$` เปิดด้วย `utf-8` / `errors="replace"` (`runtime_console.py:150`)
- ไฟล์ retained เปิดด้วย `utf-8` / `strict`

แต่ `_Mirror` ตอบ **ค่าคงที่ hardcode ค่าเดียว** ให้ทั้งคู่ (`utf-8`/`strict`, `runtime_console.py:24-30`) และ `#1022` เพิ่ง **ยกค่าคงที่นั้นขึ้นเป็นสัญญาใน docstring** ว่า "เป็นการตัดสินของ `_Mirror` เอง ทุกเทสที่สร้างจากโรงงานนี้ต้องขยับตามมัน"

ผลที่วัดได้ (adversary วัดด้วย `Cp874Stream` ซึ่งเป็นแบบจำลองคอนโซลผู้ควบคุมของโปรเจกต์เราเอง):
`console_safe()` — แนวป้องกัน cp874 ทั้งระบบ ที่หน้าที่คือ "พับตาม encoding ของสตรีมที่กำลังเขียน ไม่กว้างกว่านั้น" — ถามมิเรอร์ ได้คำตอบ `utf-8` ⇒ เก็บอักขระที่ map ไม่ได้ไว้ ⇒ `UnicodeEncodeError` ทะลุ `print()` ออกไปหาผู้เรียก = **รูปเดียวกับที่ `gm/login_scene_override.py:277-289` เขียนไว้เองว่าห้ามเกิด ("A DIAGNOSTIC MAY NEVER ALTER DISPATCH")**
และไฟล์นั้นบรรทัด `169-172` ก็ธงเรื่องนี้ไว้เองแล้วว่ายังเปิดอยู่: "`_Mirror` ANNOUNCES `utf-8` while the gate FORCES `cp874:strict`, and nobody has measured the stream on the owner's machine"

## ทางเลือกที่ผมเห็น
1. **`encoding`/`errors` = รายงานของสตรีมคอนโซลที่ห่ออยู่** (ไม่ใช่ค่าคงที่) ⇒ `console_safe()` ได้คำตอบจริง · ต้อง **ปลดพิน `errors == "strict"`** ที่ `tests/test_runtime_console.py:148` ซึ่ง `#1022` เพิ่งใส่ (ตอนนี้การแก้ที่ถูก = แดง)
2. **คงค่าคงที่ไว้** แล้วประกาศตรง ๆ ว่า `console_safe()` **ห้ามถามมิเรอร์** ต้องถามสตรีมปลายทางตัวจริง ⇒ ต้องไล่แก้ทุก call site ของ `console_safe`
3. ไม่ทำอะไร รอวัดคอนโซลจริงบนเครื่องคุณก่อน (= ใบ attended)
