# CORE-REQUEST (หนึ่งบรรทัดใน runtime.py) — คลิกที่ถูกปฏิเสธต้องไม่ทิ้งเฟรมพื้นที่รอบนี้ประกอบให้แล้ว

## บรรทัดที่ขอ
`runtime.py` สาขา pickup (จุดเรียก `mob_pickup_request.dispatch_inbound_pickup_request`) มีบรรทัด

```
                if outcome.delta is None:
                    return []          # no reply, exactly as an unknown vital
```

ทุก **การปฏิเสธ** มี `delta is None` เสมอ ⇒ สาขานี้ `return []` ก่อนถึงบรรทัด
`out += [("MOB_PICKUP_GROUND_AFTER", gpc, gframe, 0.0) for gpc, gframe in outcome.ground_after]`
ที่อยู่ล่างลงไป

ขอเปลี่ยนเป็น (รูปไหนก็ได้ที่ให้ผลเดียวกัน — บรรทัดล่างนี้คือความหมาย ไม่ใช่ถ้อยคำบังคับ):

```
                if outcome.delta is None:
                    if not outcome.ground_after:
                        return []      # no reply, exactly as an unknown vital
                    return list(self._mob_loot_boundary_flush()) + [
                        ("MOB_PICKUP_GROUND_AFTER", gpc, gframe, 0.0)
                        for gpc, gframe in outcome.ground_after]
```

  `drop_already_taken` 7/7 · ไม่มีเฟรมพื้นออกตอนหมดอายุเลย เพราะเซิร์ฟเวอร์ตีพิมพ์พื้นเฉพาะตอน
  ฆ่า / เก็บสำเร็จ / ข้ามฉาก
- รอบนี้ (`server` PR ของรอบ f4oh9y) ทำครึ่งที่เป็นของสาย B แล้ว: `DropLedgerCell` จำได้ว่าการกวาด
  เก็บแถวไหนไป และ `dispatch_inbound_pickup_request` **ประกอบ** เฟรมพื้น (โรสเตอร์ที่เหลือของฉาก
  รูปเดิม ไม่มี mask ใหม่) ใส่ `outcome.ground_after` มาให้แล้วบนคำปฏิเสธ
- แต่คลิกที่ถูกปฏิเสธไม่เคยเดินไปถึงบรรทัดที่ส่ง ⇒ ตอนนี้คอนโซลพิมพ์
  `MOB_PICKUP_GROUND_EXPIRY_COMPOSED_NOT_SENT_NO_CALL_SITE` ตามจริง ไม่ได้พิมพ์ PUBLISHED
- ค่าคงที่ `mob_pickup_request.EXPIRY_PUBLICATION_CALL_SITE_STATUS` ผูกกับ AST ของ `runtime.py`
  โดยเทส `tests/test_mob_pickup_ground_expiry.py::TheConstantAndTheRuntimeAgree` — **วันที่คุณลง
  บรรทัดนี้ เทสจะแดงจนกว่าจะเปลี่ยนค่าคงที่เป็น `"sent"`** (เปลี่ยนได้ในไฟล์ของผมหรือบอกมา ผมทำรอบถัดไป)
  เทสอ่านจาก AST ไม่ใช่ substring จงใจ เพราะคอมเมนต์ในสาขานั้นพูดคำเดียวกันหมดแล้ว

## สิ่งที่ไม่ได้ขอ
- ไม่ขอให้เปลี่ยนพฤติกรรมของคลิกที่สำเร็จ (เส้นทางนั้นถูกอยู่แล้ว ไม่แตะ)
- ไม่ขอให้ตอบผู้เล่นอะไรใหม่บนคำปฏิเสธ — คำปฏิเสธยังเป็นคำปฏิเสธ ไม่มี delta ไม่มีของเข้ากระเป๋า
  สิ่งเดียวที่เพิ่มคือเฟรม "พื้นตอนนี้มีอะไรบ้าง" ซึ่งลบป้ายผีด้วยการไม่เอ่ยถึงมัน (RE-130)
- ไม่ขอ timer ใด ๆ · ตัวจุดชนวนคือ **เหตุการณ์คลิก** ไม่ใช่นาฬิกา (คำปฏิเสธ `DROP_REFRESH_MS`
  2026-08-26 ยังยืน) · คลิกที่สองบนผีตัวเดิมไม่ประกอบอะไรเลย มีเทสปักไว้

## ผู้เล่นจะเห็นอะไรต่างจากเมื่อวาน (หลังบรรทัดนี้ลง) — พร้อมข้อจำกัดที่ต้องอ่านคู่กัน
คลิกที่ของหมดอายุ **หนึ่งครั้ง** แล้วป้ายผีหายไปจากพื้น **เฉพาะเมื่อฉากนั้นยังมีของยืนอยู่อย่างน้อยหนึ่งแถว**

!! **ฉากของ R307 เองไม่เข้าเงื่อนไขนั้น** (pf-adversary ของรอบนี้ขับผ่าน dispatch จริงแล้วชี้ให้เห็น):
ของสองชิ้นที่เจ้าของคลิก 7 ครั้ง **คือของทั้งหมดของฉากนั้น** ⇒ กวาดแล้วฉากว่าง ⇒ ไม่มีเจเนอเรชันที่ไม่ว่าง
ให้ประกอบ ⇒ **ยังไม่ส่งอะไรอยู่ดี** สิ่งที่ได้เพิ่มในรูปนั้นคือบรรทัดคอนโซลหนึ่งบรรทัด (`..._HELD_SCENE_EMPTY`)
และตัวหนี้ที่การฆ่าครั้งถัดไปในฉากนั้นจ่ายให้ · เขียนเป็น `NONCLAIM 25` ในโค้ดและมีเทสปักไว้ ห้ามใครอ่านว่า "ผีหายแล้ว"

!! **ก่อนลงบรรทัดนี้ ขอให้คุณชั่งข้อนี้ด้วย (pf-adversary D9)**: เฟรมที่ผมประกอบเป็นพื้นของ **ฉากที่ cell คิดว่าตัวเองอยู่**
และ cell ขยับฉากเฉพาะตอนฆ่า/วาป GM เท่านั้น — ผู้เล่นที่ **เดิน** ข้ามฉากไม่ขยับมัน ⇒ คลิกซากป้ายของฉากเก่า
อาจได้พื้นของฉากเก่าตอบกลับไปให้ไคลเอนต์ที่ยืนอยู่ฉากใหม่ · ผมแคบมันแล้วเท่าที่ทำได้ในเขตตัวเอง
(`EXPIRY_PUBLICATION_REASONS` — ปฏิเสธ `drop_is_in_another_scene` ไม่ตอบด้วยพื้นเลย) แต่ปิดไม่ได้จริง
เพราะเซิร์ฟเวอร์ไม่เคยรู้ว่าผู้เล่นเดินข้ามฉาก · ถ้าคุณจะปิดจริงต้องมีจุดที่ cell เรียนรู้ฉากตอนเดิน (คนละใบ คนละรอบ)

## ขั้น attended ที่ควรตามมา (คุณเลือกใบ ผมเขียนขั้นให้ ตามกติกาเดิม)
หลังบรรทัดนี้ลง main: หนึ่งขั้นในใบของบนพื้นที่คุณเปิดอยู่ — ฆ่ามอน ปล่อยของทิ้งไว้ **เกิน 120 วินาที**
โดยยังมีของอีกอย่างน้อยหนึ่งชิ้นบนพื้น แล้วคลิกที่ชิ้นที่หมดอายุ **หนึ่งครั้ง**:
เกณฑ์สองชั้น = (wire) คอนโซลมี `MOB_PICKUP_GROUND_EXPIRY_PUBLISHED expired=N rows_left=M frames=1`
· (client-observable) ป้ายของชิ้นนั้นหายจากพื้นในภาพถัดไป และป้ายของชิ้นที่ยังไม่หมดอายุ **ยังอยู่**
ผมยังไม่เปิดใบใหม่เอง เพราะรันไม่ได้จนกว่าบรรทัดของคุณจะลง (กติกา "ใบที่รันไม่ได้ไม่ลงคิว")
