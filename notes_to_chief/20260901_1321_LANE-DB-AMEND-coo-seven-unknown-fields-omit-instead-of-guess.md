# AMEND — ผมเขียนข้อ 3 เกินหลักฐาน เจ้าของทักถูก · `/speed` ไม่ต้องรอ 7 ค่านั้น

## ผมเขียนอะไรผิด

ใบ `1201` ข้อ 3 ผมเขียนว่า "ถ้า 7 ค่านั้นไม่มา ผมจะไม่ปล่อยของที่เดาเป็นศูนย์เด็ดขาด" ทั้งที่ใน
ย่อหน้าเดียวกันเองก็เขียนว่า "สายนี้จะไม่เลือกเองว่าจะยอมเสี่ยงระดับไหน" — สองประโยคนี้ขัดกันเอง
การประกาศปฏิเสธเด็ดขาด **คือ** การเลือกระดับความเสี่ยงแทนเจ้าของ ซึ่งไม่ใช่อำนาจของสายนี้

เจ้าของ (Panya) ทักรอบนี้ว่า "บางค่าของ client default fall back หากไม่ตั้งมันคืนค่า 0 อยู่แล้ว"
ผมกลับไปวัด ไม่ได้เถียง ผลออกมาว่า**ท่านถูกในข้อเท็จจริงหลัก** และผมประเมินความเสียหายสูงเกินจริง

## สิ่งที่วัดได้รอบนี้ (ทั้งหมดจาก tsv + ซอร์สในรีโป ไม่ใช้ v141 เป็นเกณฑ์)

**1. ค่า default ส่วนใหญ่เป็นศูนย์จริง แต่ไม่ใช่กฎ**
ใน 28 ฟิลด์ที่มี default พิสูจน์แล้ว: **23 เป็นศูนย์ · 5 ไม่ใช่ศูนย์**
ห้าตัวนั้นคือ `BasicAttr@0x54 = 400.0` · `ActorAttr@0x13E = 0x03FC` · `@0x13C = 1` ·
`@0x1AC = 1` · `@0x1A8 = 0xFFFFFFFF` — อัตราพลาดถ้าเดาศูนย์ทุกช่อง ≈ 18% ต่อฟิลด์

🔴 ข้อที่ทำให้ผมยังไม่สบายใจกับการเดาศูนย์แบบเหมารวม: **หนึ่งใน 5 ตัวนั้นคือ speed เอง (400.0)**
ถ้า speed บังเอิญตกอยู่ในกลุ่ม "ไม่รู้" แล้วเราเดาศูนย์ ตัวละครจะหยุดนิ่ง — ฟิลด์ที่งานนี้ทำอยู่พอดี
เป็นตัวอย่างของฟิลด์ที่ศูนย์ผิด ไม่ใช่ตัวอย่างที่หายาก

**2. "ไม่มีแถวใน codex" ไม่เท่ากับ "ไม่มีใครเขียนค่ามัน"** [ข้อสงสัย ยังไม่พิสูจน์]
writer VA ของ constructor `ActorAttr` ที่ระบุตัวได้มี 23 จุด ช่วง `0x464C73..0x464E16`
ระยะห่างมัธยฐาน `0x7` ไบต์ แต่มีช่องว่างสี่ช่วงรวม `0x121` ไบต์ (`0x464C84→0x464CBA`,
`0x464CBA→0x464D2A`, `0x464D75→0x464D91`, `0x464D91→0x464DD0`) = พื้นที่พอสำหรับ writer อีก
หลายสิบจุดที่ยังไม่มีใครไล่ ⇒ ที่ 7 ฟิลด์ "ไม่มีแถว" น่าจะแปลว่า **ยังไม่มีใครไปดู** มากกว่า
"constructor ไม่เขียนมัน" — ยืนยันไม่ได้จากรีโป ต้องดูไบนารี จึงเป็นข้อสงสัย ไม่ใช่ข้ออ้าง
(ช่องว่างอาจเป็น call/branch ไม่ใช่ write ก็ได้)

**3. ความเสียหายเล็กกว่าที่ผมทำให้ดูมาก — จุดที่ผมประเมินผิดที่สุด**
ตรวจ migration ทั้ง 5 ไฟล์แล้ว **ไม่มี typed column ของ speed/hp/level แม้คอลัมน์เดียว** ⇒
ค่าที่ส่งออกไปไม่ถูก persist ที่ไหนเลย มันอยู่ในหน่วยความจำ client ของ session นั้นเท่านั้น
logout/login ใหม่ client ประกอบใหม่จาก constructor ตัวเอง ⇒ **ย้อนได้ด้วยการ relog**
ข้อห้ามของเจ้าของเรื่อง "ย้อนไม่ได้/ไม่มี backup" จึงไม่ตรงกับกรณีนี้ ผมเอาไม้บรรทัดผิดอันมาวัด

## ข้อเสนอที่ดีกว่าทั้งการรอ RE และการเดาศูนย์ — 7 ฟิลด์นั้นไม่ต้องมีค่าเลย

**ไม่ต้องเซ็ต mask bit ของมัน** ผลลัพธ์ถูกล้อมด้วยขอบเขตสองด้าน ไม่ว่าคำตอบเรื่อง bulk-copy
`0x464F30` จะออกทางไหน:

- ถ้า "ละไว้ = คงค่าเดิม" (ยังไม่พิสูจน์) → ละไว้คือ **สมบูรณ์แบบ** ดีกว่าเดาศูนย์ชัด ๆ
- ถ้า "ละไว้ = เป็นศูนย์" (คำอ้าง static ปัจจุบัน) → ละไว้ **เท่ากับ** เดาศูนย์เป๊ะ ๆ ไม่แย่กว่า

⇒ ไม่มีสถานการณ์ไหนเลยที่ "ส่งศูนย์ที่เดาเอา" ดีกว่า "ไม่เซ็ต bit" การรอ 7 ค่าจึงไม่จำเป็นต่อ `/speed`
(หมายเหตุ: x=41 กับ x=42 แชร์ mask bit เดียวกัน `encode_block` บังคับให้มาคู่หรือไม่มาเลย —
ละทั้งคู่ผ่านเงื่อนไขนี้ปกติ)

## และมีเทสหนึ่งครั้งที่ปิดคำถามค้าง 8 วันได้ โดยไม่ต้องขอ RE เลย

คำถาม "ละฟิลด์ไว้แล้ว client เซ็ตเป็นศูนย์หรือคงค่าเดิม" ค้างมาตั้งแต่ `gm/attr_wire.py:67-73`
เขียนไว้เองว่าเป็นคำอ้าง static ที่ไม่เคยวัดกับค่าที่ไม่เป็นศูนย์จริง — เพราะ probe เดิมเริ่มจาก
ตัวละครสร้างใหม่ทุกครั้ง จึงไม่เคยมีค่าเดิมให้เทียบ

**speed เองคือเครื่องมือวัดที่ดีที่สุดที่มี**: มันเป็น default ที่ไม่เป็นศูนย์และพิสูจน์แล้ว (400.0)
และ **มองเห็นด้วยตาโดยตรง** ส่งบล็อกที่เซ็ตฟิลด์ known ตัวอื่นหนึ่งตัว แล้ว **ไม่เซ็ต** bit ของ x=7:

- ตัวละครยังเดินความเร็วปกติ → ละไว้ = คงค่าเดิม → ทาง 2 เดินได้ ปัญหาทั้งหมดจบ
- ตัวละครหยุดนิ่ง/เดินไม่ได้ → ละไว้ = เป็นศูนย์ → คำอ้าง static ถูกต้อง และเรารู้แน่แล้ว

หนึ่งเทส attended ผู้เทสมองด้วยตาเปล่า ไม่ต้อง RE ไม่ต้องอ่านไบนารี และผลลัพธ์ตอบคำถามที่
บล็อกสาย GM มาแปดวัน — ถ้า COO เห็นด้วย ผมจะร่างขอ GT entry ผ่าน chief ในรอบถัดไป
(ทำบนตัวละครทิ้งได้ เพื่อให้ผลเสียกรณีที่สองเป็นศูนย์จริง ๆ)

## แก้ข้อ 3 ของใบ `1201` เป็น

`/speed` **ไม่ต้องรอ** 7 ค่านั้น เดินตามแผน "ไม่เซ็ต bit ของฟิลด์ที่ไม่มีแหล่ง" ได้เลย ·
คำขอ RE 7 ค่ายังมีประโยชน์แต่ลดเป็น **ไม่เร่งด่วน** ไม่ใช่ของขวางทาง · และสายนี้ไม่ประกาศปฏิเสธ
อะไรเด็ดขาดเองอีก — ระดับความเสี่ยงเป็นของเจ้าของกับ COO ผมรายงานตัวเลขให้ครบแล้วข้างบน

## nonclaims

1. ไม่อ้างว่า "ละไว้ = คงค่าเดิม" เป็นจริง — นั่นคือสิ่งที่เทสข้างบนมีไว้วัด ยังไม่รู้คำตอบ
2. ไม่อ้างว่า 7 ฟิลด์นั้น constructor เขียนค่าไม่เป็นศูนย์ — ช่องว่าง VA เป็นข้อสงสัย ไม่ใช่หลักฐาน
3. ไม่อ้างว่าอัตรา 18% ใช้ทำนาย 7 ฟิลด์ที่เหลือได้ — 28 ตัวที่วัดแล้วไม่ใช่ตัวอย่างสุ่ม
   (มันคือชุดที่มีคนไปไล่ก่อน) ตัวเลขนี้บอกได้แค่ว่า "ศูนย์ไม่ใช่กฎ" ไม่ได้บอกความน่าจะเป็นของ 7 ตัวนั้น
4. ข้อ 1 ข้อ 2 และข้อเสนอแนวทาง DB-ถือทั้งบล็อกในใบ `1201` **ไม่ถูกแก้** ยังยืนตามเดิม —
   โดยเฉพาะเรื่องบล็อบ creation เป็น AvatarAttr ซึ่งเป็นคนละเรื่องกับใบนี้
