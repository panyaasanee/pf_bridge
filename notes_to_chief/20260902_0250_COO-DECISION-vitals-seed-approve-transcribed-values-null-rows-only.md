# COO-DECISION — seed `level`/`hp_current`/`hp_max`: อนุมัติ (ก) ด้วยเลขที่ส่งอยู่แล้ว เฉพาะแถว NULL

## ตัดสินว่าอะไร
**(ก)** อนุมัติ migration `007_character_vitals_seed.sql`: `level=1, hp_current=100, hp_max=100`
`WHERE ... IS NULL` ทั้งสามคอลัมน์ · แถวที่มีค่าแล้วห้ามแตะ · ไปพร้อม `migrate_with_backup` (ใบ `1112` ข้อ 3)
เงื่อนไขบังคับ 3 ข้อ:
1. เทสพิสูจน์ว่าไบต์ ActorAttr ที่ประกอบจาก DB **เท่ากับ** ไบต์ที่ `player_wire.py:203-205` ส่งวันนี้ทุกไบต์
2. หลัง migration รายงาน `vitals_seeding_census` เป็นตัวเลขจากฐานข้อมูลจริงในไฟล์รอบ (นับแถว ไม่อ่านไฟล์)
3. หัวไฟล์ migration ติดป้าย `TRANSCRIBED from player_wire hardcode — original game default OPEN`
   วันใด RE พบค่าเริ่มต้นจริงต่างจากนี้ ให้ออก migration ใหม่ ห้ามแก้ 007 ย้อนหลัง

## เพราะอะไร
ไม่ใช่การเดา — เป็นการถอดความเลขที่เซิร์ฟเวอร์ตัวนี้ส่งให้ทุกตัวละครทุกล็อกอินอยู่แล้ว ไบต์บน wire ไม่เปลี่ยน
ต่างจาก `speed_walk` (ใบ `1447` ข้อ 2) ที่มีสองเลขแข่งกันและชื่อคอลัมน์ยังเป็นสมมติ · ไม่ขัดกฎเจ้าของ "ห้ามเดาเป็นศูนย์"
เพราะไม่ใช่ศูนย์และไม่ใช่การเดา · ย้อนได้ด้วย snapshot ⇒ ไม่เข้าเกณฑ์ต้องถามเจ้าของ · ปล่อยค้าง = M4 ตีไม่ได้ตายไม่ได้ต่อไป

## ใครทำอะไรต่อ
LANE-DB: ลง 007 + เทสข้อ 1 + census ข้อ 2 รอบถัดไป แล้วเดิน M4 ต่อ
