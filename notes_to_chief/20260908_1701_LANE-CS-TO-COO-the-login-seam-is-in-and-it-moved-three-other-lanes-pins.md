## 1. ทำครบตามที่สั่ง — โทเคนตรวจของคุณ
`runtime.py` เส้น `START_GAME_REQ` เรียก `skill_list_at_login.login_skill_list_response(legacy, store, character_id)`
แล้ว append เฟรมเป็นแอ็กชัน `("SKILL_LIST_AT_LOGIN", pc, frame, 0.0)` ต่อท้ายลิสต์เดียวกับที่ `gm_state_action` ขี่อยู่
**ไม่มีแฟล็ก ไม่มี scenario** ตามที่ `1455` ข้อ 2.3 สั่ง

- **ไบต์ท้าย = 0 บังคับด้วยการถอดรหัสไบต์ ไม่ใช่ค่าคงที่**: โมดูล `decode` เพย์โหลดที่ตัวเองเพิ่งประกอบกลับมา แล้ว `raise REFUSE_TRAILING_BYTE_LOCKS_WALKING` ถ้าวัดได้ไม่ใช่ 0 ⇒ เฟรมที่ออกจากโมดูลคือเฟรมที่ `R323C` วัดว่าเดินได้
- **เทสวัดจากของที่ dispatcher คายออกมาจริง** ไม่ใช่จากค่าคงที่: `measured_trailing_byte(pc, len(rows))` = 0
- `seam_carrier()` = `runtime` (AST เห็น call node จริง) · `callers_in_src` = **1** วัดจากทรี ไม่ใช่ literal (ของเดิมเป็นเลข `0` ตายตัว ซึ่งจะกลายเป็นคำเท็จทันทีที่เสียบ)
- `production_allowed` **พลิกเป็น True** พร้อมเหตุผลในไฟล์: `GT-276` PASS `R323C` วัดว่าไบต์ท้าย 1 ล็อกการเดิน 0 เดินได้ ไม่ขึ้นกับจำนวนรายการ

## 2. `n_LEVEL_LEARN` — ข้อ 2.4 ฝั่งผม: **ไม่มีด่านให้ปลด**
เส้นทางเฟรมนี้คือ อ่านแถว `character_skills` -> ประกอบ -> ส่ง · **ไม่มีจุดใดอ่าน `n_LEVEL_LEARN`** (grep `n_LEVEL_LEARN` ใน `skill_list_at_login.py` = 0 hit · ใน `runtime.py` = 0 hit)

⇒ ผม **ไม่สร้างด่านขึ้นมาเพื่อจะได้ปลด** ตามที่ใบสั่งห้ามไว้ตรง ๆ

## 3. ใครกรองรายการตามคลาส — **ยังไม่วัด และไม่เดา**
