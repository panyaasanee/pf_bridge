# COO-DECISION — canon gate: เลือก (ก) รับตามที่เป็นอยู่ ห้ามอ้างว่ากันคนตั้งใจโกงได้

## ตัดสินว่าอะไร
เลือก **(ก)** ตามที่สายเสนอ: ด่านนี้ยืนตามที่ลงไว้วันนี้ (`POSTSTATE.json` + อ่าน ledger ในสำเนา)
ไม่ทำ (ข) เซิร์ฟเวอร์เขียน `db_backups/` ฝ่ายเดียว และไม่ทำ (ค) เซ็นลายเซ็นแยกคีย์ ตอนนี้
🔴 **ข้อบังคับที่มากับการเลือกนี้**: ห้ามมีรายงาน/docstring/README ที่ไหนเขียนว่าด่านนี้ "กันการแก้ DB
ด้วยมือ" หรือ "เป็นด่านพิสูจน์ตัวตน" — ต้องเขียนตรงตามที่สายอธิบายไว้เป๊ะ: ด่านนี้แยก "ไฟล์เปลี่ยนเพราะ
อะไรไม่รู้" ออกจาก "migration ที่มีบันทึก" เท่านั้น

## เพราะอะไร
ภัยที่มีจริงวันนี้คือความสับสน/ดริฟต์โดยสุจริต ไม่ใช่ผู้บุกรุกที่เข้าถึงเครื่องได้ — ด่านตอนนี้จับกรณีนั้นได้จริง
(ข) เป็นงานระดับสิทธิ์ไฟล์/OS นอกเขตของ LANE-DB (ค) ต้องมีที่เก็บคีย์และคนหมุนคีย์ ซึ่งเป็นคำถาม
โครงสร้างที่ยังไม่มีความจำเป็นจริงตอนนี้ (ยังไม่มีผู้เรียกโมดูลนี้เลยวันนี้) ทั้งสองทางเลือกเก็บไว้เป็นตัวเลือก
ที่ยกระดับได้ทีหลังถ้าภัยเปลี่ยน ไม่ใช่การปิดประตูถาวร

## ใครทำอะไรต่อ
LANE-DB: เก็บถ้อยคำ nonclaim นี้ไว้ในหัวโมดูลตามที่เขียนไว้แล้ว ไม่ต้องแก้เพิ่มรอบนี้ เดินคิวปกติต่อ
(M4 21 typed column ไม่ผูกกับข้อนี้) เรื่องที่สอง/สาม/สี่ในใบเดิม (wal-race fix, exit code 75,
ขอบเขต 19+12 ไฟล์) รับทราบแล้ว ไม่ต้องรอ COO ตัดสินอะไรเพิ่ม — ทำถูกแล้ว

## กำหนดเมื่อไร
ไม่มีกำหนด — ทบทวนใหม่เฉพาะถ้ามีเหตุผลจริงที่ต้องกันผู้บุกรุกที่เข้าถึงเครื่องได้ (ไม่ใช่แค่ทฤษฎี)
