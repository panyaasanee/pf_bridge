## 1. คำตอบสั้นก่อน เพราะมันเปลี่ยนขนาดของงานทั้งใบ

ka1-A รายงานถูกทุกข้อ และข้อสรุปที่ว่า "ต้องแก้ที่ `parse_outer`" **ไม่จำเป็น** ⇒ ใบนี้ไม่ชนนโยบาย `v141 immutable`

**หลักฐานสองแหล่งอิสระ (G1):**

**(ก) `v141` ไม่เคยทิ้งหางของแพ็กเก็ตเลย มันแค่ไม่ตีความ**
`current/pf_login_game_server_v141.py:2921` — `nested_payload = pc[c.p:]`
คือ **ทุกไบต์ตั้งแต่หลังเฮดเดอร์ของ vital ตัวแรกไปจนจบแพ็กเก็ต** และ `raw_pc` เก็บทั้งเฟรมไว้อยู่แล้ว
⇒ vital ตัวที่ 2..5 ที่ ka1-A บอกว่า "invisible" นั้น **อยู่ในมือเราครบทุกไบต์** สิ่งที่หายไปคือการเดิน ไม่ใช่ข้อมูล

**(ข) โมดูลของเราเดินหางนั้นได้จริงแล้ว วันนี้ บน main**
`src/pirateforce_foundation/action_ack.py:24-52` (`parse_scene006_ea7d`) รับ `vital_count` เป็น **2 หรือ 6**
เปิด `legacy.Cursor(parsed.raw_pc)` เอง แล้วเดินทีละ vital ด้วยตารางความยาวต่อ id:
`ON_LAND_VITAL` = 4×f32 + u16 · `TARGET_POS_VITAL` = 4×f32 + 2×u8 · `ACTION_VITAL` = 64 ไบต์
แล้ว **ประกอบ `ParsedOuter` ปลอมขึ้นหนึ่งใบต่อ vital ที่สนใจ** (`isolated = legacy.ParsedOuter(...)`)
ส่งเข้า parser เดิมของ v141 ตามปกติ · ปิดท้ายด้วย `cursor.remain() != 0 -> return None` (fail-closed แท้)
`damage_model_hypothesis.py:982` ก็ `for _index in range(vital_count)` เช่นกัน

⇒ **รูปทรงของคำตอบมีอยู่ในบ้านแล้ว** งานที่เหลือคือยกมันขึ้นเป็นตัวเดินกลาง แล้วให้ dispatch เรียกเลนต่อ vital
ไม่ใช่การเขียน parser ใหม่ และไม่ใช่การแตะ `v141`
