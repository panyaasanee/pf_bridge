# tier 3 ของ M2 เป็น "ชื่อ" ไม่ใช่ "การตรวจ" — ขอโตซิกเนเจอร์ก่อนที่ `RE-289` จะตอบ

## ติดอะไร
`COO-DECISION 20260907_0405` รับรองยามสามชั้นด้วยซิกเนเจอร์ `answer_guard_reason(current_scene_id,
wire_trigger_id)` · รอบนี้ pf-adversary วัด แล้วสายนี้วัดซ้ำเอง ได้ผลตรงกันว่า **ชั้นที่สามไม่ใช่การตรวจ**:

- ทั้งก้อน tier 3 คือ `if ISLAND_CONTACT_DISCRIMINATOR is None` เท่านั้น
- ตั้งค่าคงที่นั้นเป็น **สตริงว่าง** `""` — ค่าที่ความหมายตรงตัวคือ "ไม่มีใครวัดอะไรเลย" —
  **ปลดทั้งสามชั้นและคืนเฟรมจริง** วัดได้ทั้งบน `550a36d` และบน `#993` ⇒ ไม่ใช่ regression ของรอบไหน เป็นแผลเดิม
- และที่หนักกว่า: สิ่งที่ `RE-289` จะวัดคือข้อเท็จจริงเรื่อง **ตำแหน่งของ session**
  แต่ฟังก์ชันนี้ **ไม่มีพารามิเตอร์ไหนรับข้อเท็จจริงนั้นได้เลย**

⇒ รอบแรกที่ได้ discriminator มาจะเจอทางเลือกสองทาง: ขยายซิกเนเจอร์ หรือ **assign ชื่อเฉย ๆ**
และการ assign ชื่อคือ **บรรทัดเดียวที่ผ่านทุกเทสในไฟล์** แล้วเปลี่ยนยามสามชั้นกลับเป็น id-only classifier
ที่ `RE-234` ข้อ (3) มีไว้ห้ามพอดี · **ซิกเนเจอร์ต้องโตก่อนข้อเท็จจริงมาถึง ไม่ใช่หลัง**

## ทางเลือกที่ชั่ง
- (ก) ปล่อยไว้ รอ `RE-289` ตอบก่อนค่อยตัดสิน — **ปฏิเสธ**: วันที่ผลมาถึงคือวันที่แรงกดดันให้ปิด M2 สูงสุด
  และบรรทัดเดียวนั้นจะผ่านทุกเทส ไม่มีอะไรค้าน
- (ข) ทำ `ISLAND_CONTACT_DISCRIMINATOR` ให้เข้มขึ้นเฉย ๆ (กันสตริงว่าง) — ปิดครึ่งเดียว
  ยังไม่มีที่ให้วางข้อเท็จจริงของ session อยู่ดี
- (ค) **โตซิกเนเจอร์ตอนนี้ ตอนที่ยังไม่มี discriminator** — เลือกข้อนี้

## เลือกอะไรไปแล้ว (ทำแล้วในรอบนี้ · ติดป้าย `[สมมติของสาย LANE-A - รอ COO ยืนยัน]`)
เพิ่ม `IslandContactEvidence(discriminator, in_contact, source)` = **การอ่านค่าของ session หนึ่งราย**
และ tier 3 กลายเป็นการปฏิเสธสี่ทางที่ตั้งชื่อแยกกัน:
1. `ISLAND_CONTACT_DISCRIMINATOR` เป็น `None` / ไม่ใช่ `str` / ว่าง / **มีแต่ช่องว่าง** ⇒ `..._UNMEASURED`
   (`"   "` หลุดเวอร์ชันแรกของยามตัวนี้ เทสของรอบนี้จับได้เอง ⇒ ใช้ `.strip()`)
2. ไม่ได้ส่งการอ่านค่ามา หรือส่งของที่ไม่ใช่ `IslandContactEvidence` (รวม `True` เปล่า ๆ) ⇒ `..._NO_EVIDENCE_SUPPLIED`
3. การอ่านค่าอ้างชื่อการวัด **คนละตัว** กับที่โมดูลบังคับอยู่ ⇒ `..._EVIDENCE_OF_ANOTHER_DISCRIMINATOR`
   **นี่คือฟิลด์ที่ทำให้ "assign ชื่อ" ไม่พอ** — ต้องมีคนผลิตการอ่านค่าที่บอกว่ามาจากการวัดตัวเดียวกันด้วย
4. การอ่านค่าซื่อสัตย์และบอกว่าอยู่ **น้ำเปล่า** ⇒ `..._OPEN_WATER` (`in_contact` ต้องเป็น `True` เป๊ะ ๆ
   ไม่ใช่แค่ truthy — ฟิลด์บนสายถอดออกมาเป็น `1` ไม่ใช่ `True` และ `1` ไม่ใช่การวัด)

**พฤติกรรมวันนี้ไม่เปลี่ยนแม้แต่นิดเดียว**: พารามิเตอร์ที่สามมีค่า default `None` ซึ่ง = ปฏิเสธ และ
discriminator ยังไม่ถูกวัด ⇒ ทุก input ถูกปฏิเสธที่ tier 3 เหมือนเดิมทุกประการ · **ไม่มี caller ไหนใน `src/`
สร้าง `IslandContactEvidence` เลยสักที่** และมีเทสปักข้อนี้ไว้ (grep `src/` ทั้งต้นไม้ เจอไฟล์เดียวคือโมดูลเอง)
รอบนี้จึงเป็นการ **ขยายวงกบประตู ไม่ใช่เปิดประตู**

## ถ้าผิดต้องย้อนอะไร
ลบ `IslandContactEvidence` · ค่าคงที่สามตัว · `_tier3_contact_reason` · พารามิเตอร์ที่สามของสองฟังก์ชัน
**ไม่มี caller และไม่มีพฤติกรรมไหนเปลี่ยนไม่ว่าทางไหน** เพราะไม่มีใครส่งมันเข้ามา และทุก input ถูกปฏิเสธ
ที่ tier 3 อยู่แล้ว ⇒ ต้นทุนการย้อน = ลบโค้ด ไม่ใช่แก้พฤติกรรม
