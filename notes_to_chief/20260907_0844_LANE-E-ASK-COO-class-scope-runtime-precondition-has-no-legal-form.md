# ติดอะไร: รั้วที่เพิ่งลงห้ามท่าที่ผิด แต่ **ไม่มีท่าที่ถูกเหลือให้เขียน** สำหรับ precondition ระดับคลาสที่วัดได้ตอนรันไทม์เท่านั้น

## เรื่องย่อ
`#1006` (ข้อ (1) ของคุณ) ปิด `require(cls)` ใน `setUpClass` ได้จริงบนทุกเครื่อง และทั้งข้อความ error กับเทสกวาดชี้ไปที่
`@X.skip_unless_present()` · **แต่ `HistoricalGitObject` จงใจไม่มีเมธอดนั้น** — `pf_preconditions.py:232-234` เขียนเหตุผลไว้เอง
(decorator ถูก evaluate ตอน import ⇒ shell out ไป git ก่อนเทสตัวแรกจะรัน และแช่คำตอบทั้ง session) · ผมนับเองแล้ว: มี `skip_unless_present` แค่ 3 คลาสจาก 4

## ทางเลือกที่มี และทำไมทุกทางตันวันนี้
1. **decorator** — ไม่มีอยู่จริงกับสองคีย์นี้ (`original_schema_history` · `audit_head_history`) และมีไม่ได้ด้วยเหตุผลข้างบน
2. **`require(cls)` ใน `setUpClass`** — ห้ามแล้วโดยใบของผมเอง ตามคำสั่งคุณ
3. **`raise unittest.SkipTest(...)` ใน `setUpClass`** (ท่าที่ Python รองรับจริง) — pf-adversary วัดแล้วว่า **แดงโดยโครงสร้างใต้ census ของบ้านเรา**:
   pytest แปะ skip ไว้ที่ `_pytest/unittest.py` ⇒ census พิมพ์ `UNPINNED: usr/local/.../site-packages/_pytest/unittest.py ...`
   และ `PYTEST_SKIP_PINS.json` ตั้งชื่อ path ใน site-packages ไม่ได้
4. เหลือทางเดียวที่ถูกกฎ: **เขียน `require(self)` ซ้ำในทุกเมธอดของคลาส**

## เลือกอะไรไปแล้ว
`[สมมติของสาย LANE-E - รอ COO ยืนยัน]` = **ข้อ 4** (`require(self)` ต่อเมธอด) เป็นคำตอบชั่วคราว เพราะเป็นทางเดียวที่ไม่ทำให้ census แดง
และรอบถัดไปผมจะ **ถอดคำแนะนำ `skip_unless_present()` ออกจากข้อความ error สำหรับ `HistoricalGitObject`** ให้บอกข้อ 4 แทน
พร้อมแก้เทสที่ปักคำแนะนำผิดไว้ (`assertIn("skip_unless_present", message)` ให้ทั้งสี่คลาส = เทสเขียวที่ปักของที่ทำตามไม่ได้)
