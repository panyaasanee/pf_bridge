## ตีความสองแบบของ "เสร็จ" ในคำสั่ง -- ขอ COO/เจ้าของเลือก
คำสั่ง `0156` ข้อ 1 นิยาม "เสร็จ" ด้วยขั้นตอนโต้ตอบตามตัวอักษร (เปิดกระเป๋า -> กดสวม -> เห็นช่อง
อุปกรณ์เปลี่ยน -> relog -> ยังสวม) แต่ "ทำไม" ที่ให้ไว้คือเพื่อให้ CS เทสสกิลท่าโจมตีเท่านั้น
สองอย่างนี้เป็นคนละกลไกกัน:
- **(ก) ทางที่ตอบ "ทำไม" ได้ครบ วันนี้**: ห่วงโซ่ข้อ 1-5 ข้างบน -- ไม่มี UI สวมใส่แบบโต้ตอบเลย
  ตัวละครใช้ชนิดอาวุธของคลาสอัตโนมัติทุกครั้งที่ตี ไม่มีอะไรให้กดในกระเป๋า
- **(ข) ทางที่ตอบตัวอักษรของ "เสร็จ" ตรง ๆ**: ต้องมีเฟรม wire จริงสำหรับ "ย้ายไอเทมจากกระเป๋าไปช่อง
  สวมใส่" -- แก้ไขจากที่เดิมคิดว่า "ไม่เจอเลย": สั่ง `pf-static-re` (คลาวด์ ใช้เฉพาะ artifact ที่
  commit แล้ว) ไล่ซ้ำรอบนี้แล้วพบว่า **ฝั่งคำขอ (request) มีการสืบสาย static ไว้แล้วจริง**
  ที่ `current/pf_login_game_server_v141.py:101-113` (คำอธิบาย static producer tracing) +
  `:3869-3903` (โค้ดจำลอง/ตัวรับที่รู้จักคำขอนี้แคบ ๆ): `ItemOperateVitalReq` (`0x4BED`) operation
  byte `5` ที่ `+0x14` = "equip-from-bag", `value32` ที่ `+0x18` = บิตมาสก์ช่องสวม (8/16), item
  identity ที่ `+0x20/+0x24` -- **แต่เป็นแค่ตัวจับภาพการทดสอบเวอร์ชัน V123 ที่จงใจไม่ตอบกลับและไม่
  แก้ DB จริง** ("journals only, no reply, no mutation") ไม่ใช่โค้ดโปรดักชัน · ส่วนที่ยังไม่พิสูจน์จริง
  คือ **ฝั่งตอบกลับ** (เซิร์ฟเวอร์ควรส่งอะไรกลับ, `CollectionBagAttr`/`ItemBagAttr_Equiped+0x34`
  เปลี่ยนยังไง, StartGame ครั้งต่อไปควรส่งอะไรให้ตัวละครที่สวมไปแล้ว) -- ส่วนนี้ต้อง
  `[NEEDS-ATTENDED-CAPTURE]` จริง (จับแพ็กเก็ตก่อน/หลังของการกดสวมจริงหนึ่งครั้งบนจอ) ห้ามเดา
  ทางนี้แคบกว่าที่คิดตอนแรกมาก (schema/offset ของคำขอรู้หมดแล้ว เหลือแค่จับผลตอบจริง) -- DB
