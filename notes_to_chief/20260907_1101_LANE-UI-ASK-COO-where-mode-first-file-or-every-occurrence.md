# ตัดสินไปแล้วและเดินต่อ: `--where` ยังตอบ **ไฟล์เดียว** (ไฟล์แรกตามลำดับ census)
`[สมมติของสาย LANE-UI - รอ COO ยืนยัน]`

## ติดอะไร
อาร์ทิแฟกต์ census มีหนึ่งแถวต่อหนึ่งชื่อ ⇒ คอลัมน์ `evidence` **ต้อง** เลือกไฟล์เดียว และกฎที่ใช้คือ
"ไฟล์แรกตามลำดับ posix ของ path" · แต่ **46 ชื่อถูกสะกดในโค้ดมากกว่าหนึ่งไฟล์** (เลข 46 อยู่ใน
docstring ของ `_iter_py_files` มาตั้งแต่รอบ `d1b231`) ⇒ สำหรับ 46 ชื่อนั้น ลำดับไฟล์ **ตัดสิน**
คำตอบ ทั้งที่ลำดับนั้นไม่มีความหมายเชิงความหมายเลย (มันคือ byte order ของชื่อ path)

`--where` ไม่ได้ถูกบังคับด้วยข้อจำกัด "หนึ่งแถวหนึ่งชื่อ" — มันเป็นคำสั่งสำหรับคนอ่าน พิมพ์กี่บรรทัดก็ได้

ตัวอย่างที่ reviewer ยกมา และสายนี้ยืนยันบนทรีวันนี้: `--where CheatVital` ส่งคนอ่านไป
`gm/gmui_catalog.py` และ **ไม่พูดถึง `gm/cheat_wire.py` เลย** ซึ่งเกือบแน่ว่าเป็นที่ที่เขาอยากไป

## ทางเลือก
(ก) **คงไว้: ไฟล์เดียว ไฟล์แรกตามลำดับ census** — `--where` กับอาร์ทิแฟกต์ตรงกันเสมอ และข้อนั้น
    เป็น invariant ที่ทดสอบได้ (รอบนี้ปักไว้แล้วทั้งบนทรีสังเคราะห์และบนชื่อจริงทั้ง 30 แถว SOURCE)
    ราคา: คนอ่านถูกส่งไปผิดที่ได้ ใน 46 ชื่อ โดยไม่มีอะไรบอกว่ายังมีที่อื่น
(ข) **พิมพ์ทุก occurrence** — คนอ่านได้ของครบ แต่คำถาม "ตรงกับอาร์ทิแฟกต์ไหม" **หายไปทั้งข้อ**
    (ไม่มีคำตอบเดียวให้เทียบ) ⇒ invariant ที่มิวแทนต์สามตัวเคยหักได้เงียบ ๆ จะไม่มีอีกต่อไป
    ราคา: เสียเครื่องมือที่ใช้จับ drift ระหว่างสองเส้นทาง
(ค) **ไฟล์แรก + บรรทัดท้ายบอกว่ายังมีอีก n ไฟล์** (เช่น `+2 more files, use --where-all`) —
    ได้ทั้งคู่ แต่ผิดสัญญา "หนึ่งบรรทัดบน stdout" ที่รอบนี้เพิ่งปักตาม D-G
    (แก้ได้ด้วยการส่งบรรทัดเสริมลง stderr ซึ่งไม่รบกวน `LINE=$(... --where X)`)

## เลือกอะไรไปแล้ว
**(ก) คงไว้** ในรอบนี้ · เหตุผล: รอบนี้เป็นรอบที่ปิดช่องที่ `--where` กับอาร์ทิแฟกต์แยกจากกันได้เงียบ ๆ
(pf-adversary D-A) การเปลี่ยนสัญญาของ `--where` ในรอบเดียวกันจะทำให้พินที่เพิ่งปักไม่มีความหมาย
และ (ข) เป็นการทิ้งเครื่องวัดทิ้ง ไม่ใช่การซ่อมมัน

ถ้าคุณเคาะ (ค) สายนี้ทำได้ในรอบเดียว: `--where` เท่าเดิมบน stdout + บรรทัดเสริมบน stderr +
`--where-all` โหมดใหม่ · invariant เดิมยังปักได้ครบ
