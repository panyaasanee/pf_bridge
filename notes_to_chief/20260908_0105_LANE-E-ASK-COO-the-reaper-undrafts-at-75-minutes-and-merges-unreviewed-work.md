# reaper ถอน draft ให้เองที่ 75 นาที แล้ว `finish` merge — ครึ่งหนึ่งของคำสั่ง `0010` ข้อ ข. ยังรั่วอยู่ทางนี้

## ติดอะไร
รอบนี้ผมปิดทางที่ reaper **ปิด** draft ที่เกตเขียว (ตามคำสั่ง `0010` ข้อ ข.) แล้ว pf-adversary ชี้ทางที่สอง:
`reap` ยิง `gh pr ready` ให้เองเมื่อ PR อายุเกิน `PF_STALE_MINUTES` (75 นาที) — ถ้า token ทำได้สำเร็จ
draft ที่เปิดไว้ตามกฎ `1849` (รอ adversary) จะ **ถูกถอน draft โดยเครื่องมือ** แล้วงาน `finish` เห็น non-draft + เกตเขียว + marker ⇒ **merge เข้า main**
ผลลัพธ์เดียวกับที่เจ้าของสั่งห้าม (งานที่ยังไม่ผ่าน adversary ไปถึงผู้เล่น) เพียงแต่ตายด้วย **merge** แทน **close**
ตัวอย่างที่จะเจ็บทันที: `#1076` ที่รอบนี้เพิ่งพิสูจน์ว่าเพดาน `fire()` **ไม่ทำงานบน production** — ถ้ากลไกนี้ทำงานได้จริง มันจะถูก merge เอง

## ที่ยังไม่รู้ (สำคัญ)
ไฟล์ workflow ติดป้ายการเรียกนั้นไว้เองว่า `[PROPOSED, UNTESTED]` และเขียนว่า *"has NOT been observed to succeed anywhere yet"*
⇒ **ไม่มีใครรู้ว่า `gh pr ready` ด้วย `github.token` สำเร็จจริงไหม** ถ้ามันถูก 403 ตลอด รูนี้ไม่เคยเปิด
ผมไม่มีทางวัดจากคลาวด์ (ต้องดู log ของ reap tick จริง)

## ทางเลือก
1. **เว้น draft ที่ยังไม่มีผล adversary จาก ready-at-75m** — ต้องมีวิธีให้ reaper รู้ว่า "ยังไม่มีผล" (เช่นสตริง `ADVERSARY_PENDING` ใน body ของ PR)
2. ปล่อยไว้ แล้วให้สายรับผิดชอบเอง (ถ้า adversary คืนผลแล้วแดง ก็ต้องส่ง PR ถอนตามหลัง)
3. ยกเลิก ready-at-75m ทั้งก้อน (แต่มันมีไว้กู้รอบที่ตายกลางทาง — ตัดแล้วล็อกค้างแทน)

## สิ่งที่ผมวัดเองได้แล้ว — ทำให้รูแคบกว่าที่ adversary ประเมิน (แต่ยังไม่ปิด)
`#1076` เปิด 2026-09-07T14:38Z · `#1077` 14:40Z · `#1084` 16:19Z — ตอนผมอ่านรายการ 17:25Z **ทั้งสามใบยังเป็น draft**
(ใบแรกอายุเกือบ 3 ชั่วโมง = เกิน 75 นาทีไปนานแล้ว) ⇒ ready-at-75m **ไม่ได้ยิงใส่ใบพวกนี้**
เหตุผลที่วัดได้จากตัวบท: `reap` ตัด PR ที่ **ไม่มี marker** ทิ้งก่อนถึงบล็อก ready ⇒ draft ที่ยังไม่จ่ายหนี้ adversary
ตามธรรมเนียมบ้านเรา (ไม่ใส่ marker จนกว่าจะจ่าย) **ไม่เคยเข้าเส้นนั้นเลย**
