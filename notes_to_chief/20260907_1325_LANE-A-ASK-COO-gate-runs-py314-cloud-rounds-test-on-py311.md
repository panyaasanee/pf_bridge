# เกตรันไพธอน 3.14 · รอบคลาวด์ทุกสายรัน 3.11 — และ closer เขียน "no FAILED line" ทุกครั้งที่มันเกิด

## เรื่องที่เจอ (รอบนี้เสียไปหนึ่งรอบเต็มของสาย A เพราะมัน)

`pirate-force-server#1026` ของรอบ `9r1ang` ถูกปิดเพราะเกตแดงที่ `pytest_subset`
`SYNC-NOTICE 1302` บอกให้ "อ่าน log หาสเต็ปที่ล้ม" — log **ไม่มีชื่อเทสที่ล้มเลย** เขียนว่า
`none - pytest printed no FAILED/ERROR line in this run.`

**[วัดแล้ว]** สาเหตุมีสองชั้น และทั้งสองชั้นไม่ใช่ของสาย A คนเดียว

### ชั้นที่ 1 — เวอร์ชันไพธอนคนละตัว
`.github/workflows/gate-windows.yml:92` ปัก `python-version: '3.14'` (คอมเมนต์บรรทัด 90 อ้างเครื่องคุณ Panya = CPython 3.14.7)
โคลนคลาวด์ที่ทุกสายรันเทสอยู่ = **3.11.15** (`python3 -VV`)
⇒ **ชุดเต็มเขียวบนเครื่องที่รอบเขียนงาน แล้วแดงบนเกต โดยไม่มีใครทำอะไรผิด**

ของสาย A รอบนี้: เทสที่ปักการส่งต่ออาร์กิวเมนต์อ่าน bytecode เก็บ operand ของ `LOAD_FAST`/`LOAD_FAST_BORROW`
CPython 3.14 ยุบการอ่าน local สองตัวติดกันเป็น superinstruction `LOAD_FAST_BORROW_LOAD_FAST_BORROW`
ซึ่ง `argval` เป็น **tuple ของสองชื่อ** ⇒ บน 3.14 ชื่อสองในสามหายไปจากลิสต์ เทสตก 4 ทาง บน 3.11 เขียวสนิท

คำสั่งรันซ้ำได้ (ใช้ `uv` ที่มีในอิมเมจ ไม่ต้องขอเครื่องใคร):
```
uv python install 3.14 && uv venv --python 3.14 v314
VIRTUAL_ENV=$PWD/v314 uv pip install pytest capstone pefile lupa==2.8
git worktree add --detach <ที่ที่พ่อแม่ไม่มี pf_bridge> <กิ่ง>
v314/bin/python -m pytest tests -q -rs -p no:cacheprovider <--ignore 48 โมดูล>
```
ทรีของเกตจริง (3.14 + ไม่มี pf_bridge ข้าง ๆ) รันได้บนคลาวด์ **ก่อน** push แล้ว

**สายอื่นเสี่ยงแค่ไหน — สวีปแล้ว ผลลบ**: `grep -rn LOAD_FAST tests/ tools/ src/` = **1 บรรทัด** คือของสาย A เอง (ลบไปแล้วรอบนี้)
แต่ bytecode ไม่ใช่ทางเดียวที่ 3.11↔3.14 ต่างกัน (ข้อความ error, `NamedTuple` เตือน deprecate ใน 3.14, ลำดับ dict repr ฯลฯ)
⇒ **ข้อนี้ยังเปิดสำหรับทุกสาย**

### ชั้นที่ 2 — closer มองไม่เห็นความล้มเหลวที่มันเพิ่งปิด PR ไปเพราะมัน
`gate-windows.yml:465` grep หา `'^FAILED |^=+ FAILURES =+$|^_+ .+ _+$'`
แต่สเต็ปรัน `pytest -q -rs` · `-q` **ไม่พิมพ์บรรทัด `FAILED `** และ `-rs` รายงานเฉพาะ skip
⇒ else-branch พิมพ์ "200 บรรทัดสุดท้าย" ซึ่งบน suite นี้คือ **บล็อก SKIPPED 184 บรรทัด** ล้วน ๆ
คอมเมนต์ 20 บรรทัดเหนือมันเล่าว่าเคยเสียรอบไปแล้วสองรอบกับเรื่องนี้ (R189 · R350) และแก้ด้วยการขยายหน้าต่าง 40→200
**หน้าต่างไม่ใช่ปัญหา ตัวกรองต่างหาก**

## เลือกอะไรไปแล้ว (ไม่ได้หยุดรอ)
1. เลิกปัก bytecode ย้ายไปปัก `ast` — เสถียรข้ามรีลีส และยัง**แข็งกว่าเดิม**

2. ไม่แตะ `gate-windows.yml` — เป็นเขต chief

## ที่ขอให้เคาะ (สองข้อ หนึ่งเรื่องต่อข้อ)

   ถ้าไม่อยากแตะธง: เปลี่ยน pattern ให้จับ `^SUBFAIL |^ERROR |failed,` ด้วย
