## บรรทัดที่ขอ (ตอนที่ COO ปลด hold แล้ว) — **หนึ่งบรรทัด ไม่ใช่สองอย่างที่เคยร่าง**
```python
if nested_id == mob_pickup_request.PICKUP_REQUEST_VITAL_ID:
    outcome = mob_pickup_request.dispatch_inbound_pickup_request(
        legacy, parsed, store, sid, character_id, bag_cell,
        drop_ledger_cell, identity, x, y, z)
    if outcome.delta is None:
        return []          # ไม่ตอบ เหมือน vital ที่ไม่รู้จักทุกวันนี้
    # แล้วส่ง outcome.delta อย่างเดียว ไม่ประกอบไบต์เอง
```
`PICKUP_REQUEST_VITAL_ID` เป็น **nested id** เท่านั้น (Codex P06 ห้ามใช้เป็น top-level opcode — ผิดชั้น)

**ยาม (guard) อยู่ในฟังก์ชันแล้ว ไม่ใช่ในย่อหน้า:** ยังไม่เลือกตัวละคร (`bag_cell` เป็น None) หรือฉากไม่มี
ground cell = ปฏิเสธโดยชื่อ (`session_has_no_bag_cell` / `session_has_no_ground_cell`) ·
เฟรมพัง = ปฏิเสธโดยชื่อ · การปฏิเสธของ transaction ถูกส่งกลับ **ด้วยชื่อเดิมไม่ห่อ** ·
**ไม่ raise ออกจากฟังก์ชันเลยไม่ว่าไบต์จะเป็นอะไร** (เพราะมันนั่งอยู่ใต้เฟรมของคนแปลกหน้าโดยตรง)

🔴 **ทำไมร่างแรกของใบนี้ผิด และเปลี่ยนไปแล้ว** ร่างแรกส่งให้คุณ "สองบรรทัด + ย่อหน้าอธิบายยาม"
pf-adversary รอบนี้ **กลายพันธุ์ย่อหน้านั้นหกแบบ** (กลับเงื่อนไข ลบยามทิ้ง คีย์ผิดชั้นเป็น outer id ลบทั้งก้อน)
แล้ว **สวีตยังเขียวทุกแบบ** จากนั้นยิงบอดี้ที่ถูกต้อง + ไบต์เกินหนึ่งไบต์เข้าไปตามย่อหน้าที่เขียนไว้
ได้ `AttributeError: 'NoneType' object has no attribute 'object_ref_u32'` **หลุดออกจาก dispatch ขาเข้า**
⇒ ย่อหน้าแบกสัญญา fail-closed ไม่ได้ ตอนนี้สัญญาย้ายเข้าไปอยู่ในฟังก์ชันที่เทสรันจริง
เทสวัดแล้วว่า การลบยาม / กลับเงื่อนไข / ตัดอาร์กิวเมนต์ตัวท้าย **ทำให้เทสของสายผมแดงทุกแบบ**
