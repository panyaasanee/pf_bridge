# 1) โครงของ `0x446F30` ทั้งตัว (ไม่ใช่แค่ลูปที่สอง)

`thiscall` · `ecx` = ตัวจัดการ (เรียกว่า `mgr` ในใบนี้) · อาร์กิวเมนต์เดียวที่ `[esp+0x1C]` = collection ที่เข้ามา

| ที่อยู่ | สิ่งที่ทำ |
|---|---|
| `0x446F37` | **`inc DWORD PTR [mgr+0x04]`** — เพิ่มเลข generation หนึ่งครั้งต่อการเรียกหนึ่งครั้ง |
| `0x446F51..0x446FE0` | **ลูป 1** เดินลิสต์ของ collection ที่เข้ามา |
| `0x446FE1..0x4470DB` | **ลูป 2** เดินลิสต์ของ `mgr` เองที่ `[mgr+0x24]` |

### ลูป 1 — ต่อหนึ่ง entry
1. `ecx=[entry+0x18]` · `eax=[entry+0x1C]` -> `call 0x446170` (ค้นหาด้วยคีย์สองตัว) -> `esi` = อ็อบเจกต์เดิม
2. ถ้าหาไม่เจอ (`esi==0`): `push 1 ; push 1 ; push <ที่อยู่ entry> ; call 0x446990` = **สร้างใหม่**
3. ถ้าเจอ: เรียก virtual slot `+0x20` ของอ็อบเจกต์นั้นพร้อมที่อยู่ entry = **อัปเดต**
4. 🔴 `0x446FBE`: **`[obj+0xD0] = [mgr+0x04]`** — ประทับ generation ปัจจุบันลงบนอ็อบเจกต์ทุกตัวที่แตะในเฟรมนี้

### ลูป 2 — ต่อหนึ่งอ็อบเจกต์ในลิสต์ของ `mgr`
1. `edi = [node+0x18]` = อ็อบเจกต์
2. `0x44702F`: **ถ้า `[edi+0xD0] == [mgr+0x04]` -> ข้าม (เก็บไว้)** = ตัวที่เพิ่งถูกประทับในลูป 1
3. ถ้าไม่เท่า -> เรียก virtual slot `0` ของอ็อบเจกต์ (คืน class descriptor) แล้ว
   `push eax ; push 0x102CB04 ; call 0x88F2B0` = **`IsKindOf`** · ถ้าใช่ -> **ข้าม (เก็บไว้)**
4. ถ้าไม่ใช่ทั้งสองข้อ -> **ถือว่า "ถูกละจากเฟรมนี้"**:
   - ผลักตัวชี้เข้า vector ที่ `[mgr+0x2C]` (มีทางขยาย buffer ที่ `0x5F68D0` เมื่อเต็ม)
   - `ecx=edi ; call 0x441C40`
   - `0x4470B7`: **`[edi+0x70] |= 0x00100000`**

# 3) 🔴 คำตอบของ TENSION — **เฟรม count-1 กวาดจริง**

## กติกาเดียวที่ตัดสิน: อ็อบเจกต์รอดได้สองทางเท่านั้น

1. **ถูกประทับ generation ในลูป 1 ของเฟรมนั้น** (คือมีอยู่ใน entry list ที่ส่งมา)
2. **ผ่าน `IsKindOf` กับคลาสที่ปักไว้ที่ `0x0102CB04`**

⇒ เฟรมที่พา actor-entry collection มาแค่ 1 entry จะประทับได้ตัวเดียว
**ตัวที่เหลือทั้งหมดใน `[mgr+0x24]` เข้าเงื่อนไข "ถูกละ" และถูก `0x441C40` ถอดในการเรียกเดียวกัน**

## แต่ประตูมันแคบกว่าที่กลัว — มี gate ปิดอยู่หนึ่งชั้น

`0x446F30` **ถูกเรียกจากจุดเดียวในทั้งอิมเมจ: `0x5E4085`** (census `E8/E9 rel32` ทุกออฟเซ็ตของ `.text` ทั้ง section)
และจุดนั้นอยู่ใต้เงื่อนไขนี้ใน inbound handler `0x5E4060`:

```
5e4073:  mov  eax, DWORD PTR [esi+0x1c]     ; sub-object ของ derived bit 0x02
5e4076:  test eax, eax
5e4078:  je   0x5e408a                      ; <-- ว่าง = ข้าม reconcile ทั้งก้อน
5e407a:  add  eax, 0x10
5e407d:  push eax
5e407e:  call 0x402a20
5e4083:  mov  ecx, eax
5e4085:  call 0x446f30
```

⇒ **reconcile/removal pass ทำงานเฉพาะเมื่อเฟรมนั้นพา actor-entry collection (bit `0x02`) มาด้วย**
เฟรมที่ไม่มีบิต `0x02` ไม่แตะประชากรเลยแม้แต่ตัวเดียว

## สรุปคำตอบที่เอาไปใช้ได้

**V91 ถูก: actor-entry list เป็น authoritative membership ต่อ generation** — โค้ดยืนยันตรง ๆ
**และเฟรม count-1 ที่พาบิต `0x02` มา จะกวาดประชากรที่เหลือจริง**

ดังนั้นถ้าไม่มีใครเคยรายงานว่าประชากรหายหมด เหลือความเป็นไปได้สามข้อ **และใบนี้ตัดสินไม่ได้ว่าข้อไหน**:

- (ก) เฟรม count-1 ของเลน HYP-PF-023/025 **ไม่ได้พา sub-object บิต `0x02` มาจริง** อย่างที่เราเข้าใจ
- (ข) ประชากรที่เลนเราสร้าง **ไม่ได้อยู่ในลิสต์ `[mgr+0x24]`** (ผมยังไม่ได้พิสูจน์ว่าลิสต์นี้ครอบคลุมอะไรบ้าง — `mgr` มาจาก `0x402A20` ซึ่งเป็นฟังก์ชันจริงมี SEH ไม่ใช่ getter สั้น ๆ)
- (ค) **ไม่เคยมีใครดูผลหลังยิงเฟรม count-1 จริง ๆ** แล้วรายงานกลับมา

🔴 **ตามที่ใบสั่งเขียนไว้เองใน pass criteria: ทางที่เหลือคือ membership-omission GT ที่มีขอบเขต บน identity เดียวที่รู้จัก — นั่นจะเป็นใบใหม่ ไม่ใช่ใบนี้**

## ข้อ 5 ของใบสั่ง: "ของบนพื้นที่โผล่แล้วไม่มีวันหาย ไม่ใช่ฟีเจอร์"

ท่อน A ได้ผลบวก (มีลิสต์ของวัตถุมีพิกัดที่ไม่ใช่ actor จริง ที่ derived bit `0x08`)
🔴 **แต่กลไกอายุ/การถอดที่ decode ในใบนี้ผูกกับ `[mgr+0x24]` ซึ่งเป็นลิสต์ของฝั่ง actor-entry (bit `0x02`) เท่านั้น**
**ไม่มีบรรทัดใดใน `0x446F30` แตะ sub-object `+0x20` หรือ `+0x24`** ⇒ ยังไม่มีหลักฐานว่าลิสต์ของบิต `0x08` มีกลไกอายุ

# 4) คลาสที่ได้รับการยกเว้น — บอกได้แค่ "ตัวไหน" บอกไม่ได้ว่า "ชื่ออะไร"

- ตัวเทียบคือ `0x88F2B0(a, b)`: ไล่โซ่ `b = [b+0x04]` ขึ้นไปเรื่อย ๆ เทียบกับ `a` -> คืน `true` ถ้า `a` เป็นตัวเองหรือบรรพบุรุษ = **`IsKindOf` ตามลำดับชั้นคลาส ไม่ใช่การเทียบชื่อเป็นสตริง**
- `a` = **ที่อยู่ของอ็อบเจกต์ descriptor แบบ static ที่ `0x0102CB04`** (โค้ด `push` ที่อยู่ ไม่ใช่ค่าในนั้น)
- ที่ `0xBCE4D5` ตอนเริ่มโปรแกรม: `mov DWORD PTR ds:0x102CB04, 0xF36384` = ติดตั้ง vtable ให้ descriptor ตัวนี้
  ก่อนหน้านั้น `0xBCE4CB` เรียกคอนสตรัคเตอร์ `0x88F2E0(this=0x102CB04, 0x102CB2C, eax)` โดย `eax` มาจาก
  `push 0x10945D0 ; mov ecx,0x101ABB8 ; call DWORD PTR ds:0xC3B7AC` = **การค้นค่าตอนรันไทม์**
- 🔴 **ชื่อคลาสจึงไม่ได้อยู่ในอิมเมจแบบ literal และผมจะไม่เดา** · `.data` ที่ `0x0102CB04` เป็นศูนย์ทั้งบล็อกในไฟล์ (ตรวจแล้ว) เพราะมันถูกสร้างตอนรัน
- ข้อเท็จจริงที่ช่วยจำกัดขอบเขต: **มี 39 จุดในอิมเมจที่ `push 0x102CB04` เพื่อทำ `IsKindOf` กับคลาสเดียวกันนี้** ⇒ เป็นคลาสที่ใช้บ่อยมาก ไม่ใช่ของหายาก
- **ทางเดียวที่จะได้ชื่อ คือ อ่านค่าตอนรันไทม์** (debugger หรือจ็อบที่อ่านหน่วยความจำของ client ที่บูตแล้ว) — นั่นอยู่นอกขอบเขต STATIC-ON-BRIDGE

# 6) nonclaims (ติดไปกับผลนี้ทุกครั้ง)

- **ไม่ได้พิสูจน์ว่า "ถูกถอดจากทะเบียน" = "หายจากจอและเรดาร์"** — พิสูจน์แค่ว่ามันถูกถอดจากทะเบียนที่ `[0x01093198]+0x180` และถูกตั้งธง `0x100000` · การแปลผลไปถึงจอเป็นชั้น client-observable ซึ่ง **ใบนี้ไม่ผลิตหลักฐานชั้นนั้นเลย**
- **ไม่รู้ว่า `[mgr+0x24]` ครอบคลุมประชากรอะไรบ้าง** — ต้องเปิด `0x402A20` ต่อ (มี SEH ไม่ใช่ getter สั้น) นี่คือชิ้นที่ขาดชิ้นเดียวที่กั้นไม่ให้ปิด TENSION ได้ 100%
- **ไม่รู้ชื่อคลาสที่ยกเว้น** (ดูข้อ 4) และ **ไม่เดา**
- **ไม่ได้ตรวจว่า virtual slot `+0x20` (ทางอัปเดต) ทำอะไร** — นอกขอบเขตข้อ 4 ของใบสั่ง
- **ไม่มีลูกมือมาเดินซ้ำ** — เซสชันผู้ช่วยไม่มี subagent ที่เห็นอิมเมจ ⇒ ทุกข้ออ้างแนบ span + sha256 ให้ re-derive เอง **ถือว่ายังไม่ผ่านการตรวจแบบปฏิปักษ์**
- ผลของท่อน A และ B **เป็นชั้น wire/static ล้วน ห้ามอ้างเป็นหลักฐานของชั้น client-observable ไม่ว่ากรณีใด**
