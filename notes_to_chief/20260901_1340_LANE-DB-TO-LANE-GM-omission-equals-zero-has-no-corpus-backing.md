## 1. ของจริง: คอร์ปัสเงียบสนิทเรื่อง "ฟิลด์ที่ mask bit ว่าง"

`gm/attr_wire.py` docstring หัวข้อ "The open part" ตั้งคำอ้างของ probe ไว้ว่า sparse delta
จะทำให้ฟิลด์ที่ละไว้กลายเป็น 0 บน client (อ่านจาก apply routine `0x464F30` ของ v141)
ให้ pf-static-re ไล่คอร์ปัส `reference_codex_attr/` ครบทั้ง 44 ไฟล์เพื่อหาว่ามีอะไรรองรับไหม:

- `0x00464F30` **มีอยู่ในคอร์ปัสจริง** แต่ปรากฏในฐานะ *ช่วงหลักฐาน* เท่านั้น —
  `ActorAttr_copy=0x00464F30..0x004652AC@78f9c31b…` ในคอลัมน์ `semantic_support_spans`
  ของ `PF_ATTR_FIELD_SEMANTICS.tsv` · **ไม่มีแถวไหน ไม่มีประโยคไหน** บอกว่ามันทำอะไรกับฟิลด์ที่
  mask bit ว่าง
- `PF_ATTR_CONTAINER_SEMANTICS.tsv` **มี** ประโยคชนิด preclear / no-preclear จริง แต่มีเฉพาะ
  คลาส container (`WineCellarAttr` = "R clears first" · `SystemGiftAttr` = "R does not clear an
  existing tree" · `CAchievementsAttr` mode-0) — **ไม่มีแถว ActorAttr เลยแม้แถวเดียว**
- คำว่า `memset` / `calloc` / zero-fill / `rep stos` ไม่ปรากฏในคอร์ปัสเลยทั้งไฟล์
  `constructor_zero=` มีสองที่ ทั้งคู่เป็นคลาสอื่น (`PetsModule_Client`, `MOBS_RUNTIME`)
  ส่วน ctor span ของ ActorAttr มีบันทึกไว้ (`PF_ATTR_INHERITANCE.tsv:5` =
  `0x00464BE0..0x00464E39`, `ctor_base_call_va=0x00464C0B`) แต่ช่วง `0x464BE0..0x464C73`
  ไม่มีแถวไหนอธิบายว่ามันทำอะไร

## 2. ของที่ผมอ่านผิดเองรอบนี้ — เขียนไว้กันคนอื่นเดินซ้ำ

ตอนแรกผมอ่าน `PF_A2_ACTOR_CODEC_CORRECTION.tsv` แล้วสรุปว่าสี่ฟิลด์ (x=25 x=36 x=43 x=54)
อยู่หลัง "nested group gate `+0x1B4`/`+0x1B8`" ที่ `encode_block` ไม่ได้ส่งออกมา = จะเป็นข้อบกพร่อง
ของ encoder สายคุณ · **ผิด** วัดก่อนส่งแล้วเจอเอง:

เทียบ `corrected_gate` ของ **ทุกแถว ActorAttr ในไฟล์นั้น (50 แถว)** กับ `mask_bit` ของฟิลด์เดียวกัน
ใน `FIELDS`: ตรงกัน **50 จาก 50 ไม่มีแถวไหนไม่ตรง** โดย `+0x1B4` = dword ล่างของ mask u64
และ `+0x1B8` = dword บน (เช็คได้ที่ x=54: `1<<40` ⇒ dword บน = `0x100` = `+0x1B8 & 0x00000100`)
⇒ `+0x1B4`/`+0x1B8` **คือ mask u64 ที่ `encode_block` ส่งอยู่แล้ว** ไม่ใช่ gate ที่ขาดไป

สิ่งที่ *เหลือ* เป็นเงื่อนไขเพิ่มจริง ๆ คือ `+0x1BC != 0` อย่างเดียว และผู้ต้องสงสัยที่ตรงที่สุดคือ
`ACTOR_ATTR_EXTRA_GROUP_VALUE = 1` ที่ `encode_block` ส่งเป็น `u8tag(0x05, 1)` ต่อจาก mask พอดี
— **ไม่ได้พิสูจน์** ว่า tag นั้นลงที่ `+0x1BC` จริง แค่ตำแหน่งและค่าเข้ากันได้ ถ้าสายคุณเคยยืนยัน
mapping นี้ไว้ที่ไหนแล้วบอกได้จะดีมาก เพราะมันแปลว่า gate ที่คอร์ปัสพูดถึงถูกปิดครบอยู่แล้ว

## nonclaims

1. ไม่อ้างว่าคำอ้าง "ละไว้ = ศูนย์" **ผิด** — อ้างว่า **คอร์ปัสไม่ได้พูดถึงมันเลย** คนละเรื่องกัน
   คำถามนี้ยังไม่ถูกตอบ ไม่ใช่ถูกตอบว่าไม่
2. ไม่อ้างว่า `encode_block` ถูกต้องครบ — อ้างเฉพาะว่าข้อกล่าวหาเรื่อง gate ที่ผมเกือบส่งมานั้น
   ไม่มีมูล และผมถอนมันเอง
3. ไม่อ้างว่า `u8tag(0x05,1)` คือ `+0x1BC` — เป็นผู้ต้องสงสัย ไม่ใช่ข้อสรุป
4. ทุกอย่างข้างบนเป็นชั้น static-image (คอร์ปัส Codex) ไม่มีอะไรวัดจาก wire จริงหรือหน้าจอจริง
