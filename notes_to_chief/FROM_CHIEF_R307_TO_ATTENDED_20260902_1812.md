# รอบนี้ปะรูที่จะทำให้คุณอ่านผล `GT-204` ผิดทั้งรอบ

## สั้นที่สุด: มันเคยพังยังไง

เก็บของ **ชิ้นสุดท้ายที่เหลือในฉากนั้น** หลังเพิ่งวาปเข้ามา ⇒ ของเข้ากระเป๋าและลง DB เรียบร้อย
แต่อีกไม่กี่วินาทีถัดมา เซิร์ฟเวอร์ส่งภาพพื้น **ของตอนก่อนหยิบ** ออกไป ⇒ **ของโผล่กลับขึ้นมาบนพื้น**
คุณคลิกซ้ำ มันปฏิเสธ ⇒ คุณจะจดว่า "เก็บของไม่สำเร็จ" ทั้งที่ของอยู่ในกระเป๋าแล้ว = ผลผิดทั้งใบ

รอบนี้ปะแล้ว **แต่ยังไม่ขึ้น main จนกว่าเกตจะเขียว** ⇒ ก่อนบูต `GT-204` ให้ทำตาม RECHECK ข้อ 5 ที่เพิ่งเพิ่มในใบ

## ถ้าคุณบูตวันนี้ ให้ทำสามอย่างนี้

1. **เช็คก่อนว่าแผ่นปะลง main แล้วหรือยัง** (คำสั่งเต็มอยู่ใน `GAME_TEST_QUEUE.md` `GT-204` RECHECK ข้อ 5)
   `git grep -n "MOB_LOOT_BOUNDARY_STASH_CLEARED" origin/main -- src/pirateforce_foundation/runtime.py`
   · ได้ >= 1 บรรทัด = ปะแล้ว ใช้ชิ้นสุดท้ายเป็นขั้นตัดสินได้
   · ได้ 0 บรรทัด = **ยังไม่ปะ** ⇒ อย่าใช้ "ของชิ้นสุดท้ายของฉาก" เป็นขั้นตัดสิน (เก็บชิ้นอื่นแทน)
2. **เจอบรรทัดนี้ในคอนโซล ไม่ใช่เรื่องผิดปกติ** — คัดมาลงรายงานเฉย ๆ:
   `MOB_LOOT_BOUNDARY_STASH_CLEARED reason=last_object_pickup ...` = เก็บชิ้นสุดท้าย ฉากว่างแล้ว
   ไคลเอนต์จะ **ไม่ถูกวาดพื้นใหม่** (ปกติ ตามที่ `COO 1345` ตั้งใจ ไม่ใช่ FAIL)
   `MOB_LOOT_BOUNDARY_STASH_CLEARED reason=superseded_by_pickup ...` = มีภาพพื้นใหม่ทับให้แล้วในคลิกเดียวกัน
   ไม่เห็นสองบรรทัดนี้เลย = ปกติเช่นกัน (คลิกนั้นไม่มีของค้างจากการวาปมาเกี่ยว)
3. **ลำดับบูตเดิมไม่เปลี่ยน** `GT-207` -> `GT-193` -> `GT-205` -> `GT-204` ท้ายสุด (`COO 1146`)

  ถ้าคุณเห็น `COLUMBUS_Q3205_BORNAGAIN_REFUSED scene=17 reason=not_home_scene` ในคอนโซล **นั่นคือของที่ถูก**
  ไม่ใช่บั๊ก · ตัวเลือกนี้ยังปฏิเสธทุกครั้งอยู่ดี (ยังไม่มีที่เก็บจุดเกิดใน DB — `RE-112`)
