FROM: LANE-UI (รอบ `719e10`)
เรื่อง: UI-A "กลับหน้าเลือกตัวละคร" — ผมสร้างของที่ **ถูกวัดว่าไม่ทำงานบนจอมาแล้ว 4 ครั้ง** แล้วย้อนออกก่อน push · ขอทิศทาง

## เกิดอะไรขึ้น (เขียนตรง ๆ ไม่แต่ง)
รอบนี้งานหลักติด (`Stall*` 509-512 รอคำตอบ COO จากรอบก่อน) ผมจึงหยิบงานสำรองข้อ 1 = คิวข้อ 2 **UI-A**
พบว่า `runtime.py` เรียก `ui_logout_exit_game` กับทุกเฟรม LogoutVital ของผู้เล่นจริงอยู่แล้ว ⇒ รับ subcode 3 ได้โดย**ไม่ต้องมี CORE-REQUEST ใบใหม่** ทั้งหมดอยู่ในเขตเขียนของสาย
ผม implement แล้ว: ack ที่พินไว้ (`LOGOUT_ACK_PC_SHA256[3]`) → `close_connection()` → ปิดซ็อกเก็ตหน่วง HYP-PF-013 · เทส 16 ใบเขียว · ชุดเต็มรัน · preflight เขียว
**แล้ว pf-adversary คืนผลก่อนปลดล็อก และผลคือ BLOCKING** ผมย้อนออกทั้งหมด ไม่ push โค้ดนั้น

## ทำไมย้อน — หลักฐานที่มีอยู่แล้วในรีโปและผมไม่ได้เปิดก่อนลงมือ
รูปนี้ **ไม่ใช่คำถามเปิด** มันถูกรันต่อหน้าเจ้าของมาแล้วสี่ครั้ง ลบทุกครั้ง:
- `GT-007` (17 ส.ค.) echo ack เปล่า — ไคลเอนต์ไม่กลับหน้าเลือกตัวละคร (03) และไม่ปิดตัวเอง (01)
- `GT-008` (18 ส.ค.) ack+close — **ไคลเอนต์ไม่รับรู้การปิด TCP เลย** ไม่มี transition ไม่มี dialog จอยังสด 40+ วิ
- `R311` (4 ก.ย.) `HYP_PF_013_LOGOUT_SUBCODE03_ACK_THEN_SERVER_SOCKET_CLOSE` 46 B แล้วปิด — จอไม่เปลี่ยน 90 วิ (ภาพ `20260904_192129.png`)
- `R319` (5 ก.ย.) `OBSERVER_CONFIRMED` — ผลเดียวกัน Panya นั่งอยู่หน้าจอเอง
`docs/FUNCTIONAL_COVERAGE.json` สรุปเองว่า **client transitions เป็น protocol-driven ไม่ใช่ transport-driven** — ปิดซ็อกเก็ตไม่ใช่คันโยก

🔴 ความผิดของผมชัด: ผมอ่าน `RE-266` (static, bounded-negative, เรื่อง `0x709E`) แล้วสรุปว่า "ครึ่งบนจอยังไม่มีใครเห็น" ทั้งที่ `FUNCTIONAL_COVERAGE.json` + หัวใบ `GT-184` (ที่ **สายผมเองเป็นคนร่างถ้อยคำ** ว่า "ตัวบล็อกไม่ใช่ 'ยังไม่ได้ต่อสาย' อีกแล้ว มันถูกต่อและวัดแล้วว่าไม่พอ") ตอบไปแล้ว · ผมบันทึกข้อนี้ลง `docs/UI_LANE.md` แถว subcode 3 แล้ว เพื่อให้รอบหน้าไม่เดินซ้ำ — เพราะกับดักนี้ **เทสเขียวทุกใบ** จึงเดินเข้าได้ง่ายมาก

## ของที่จะเสียถ้าผม push ไป (ไม่ใช่แค่ "ไม่ได้อะไรเพิ่ม")
`GT-205` **ยังไม่ปิด** และตัวปิดที่เหลือคือเก็บโทเคน `LANE_A_UIA_NOTICE_COMPOSED` จากคอนโซล · บรรทัด `BACK REFUSED` คือ **สิ่งเดียวในตระกูล logout ที่เคยถูกเห็นบนจอจริง** (R303, 2 ก.ย.)
โค้ดที่ผมย้อนออกจะทำให้บรรทัดนั้นเลิกขึ้นสำหรับ subcode 3 ⇒ แลกใบเสร็จที่ผู้เล่นอ่านได้ กับเซสชันที่ถูกฆ่าโดยไคลเอนต์ที่ (วัดแล้ว) ไม่รู้ตัว 90 วินาที **นั่นคือการถอยหลัง ไม่ใช่การเดินหน้า**

## สองข้อที่ adversary เจอ และเป็นของสายอื่น (แจ้งไว้ ไม่ได้แตะ)
1. `tests/test_world_logout_button_notice_wiring.py` (LANE-A) มี 8 ใบที่อ้างว่าพิสูจน์ว่า `runtime.py` เรียกชั้นปฏิเสธจริงบนเส้น production — แต่มันเขียวเพราะ (ก) เฟรม logout เป็น runtime request **แรก** ของเซสชัน `runtime_ack_sent` จึงยัง False และ (ข) ไม่มีใบไหน `attach_transport_socket_closer` ทั้งที่ production ต่อให้ทุกซ็อกเก็ต ⇒ ไม่มีเทสไหนในรีโปอยู่ในรูปเดียวกับ production เลย · **เขียวเพราะบรรทัดที่ควรตายไม่เคยถูกรัน**
2. คอมเมนต์ `runtime.py:7569` ของ LANE-A อ้างว่าคอนโซลจะไม่พิมพ์ `COMPOSED` บนบูตที่ทิ้งไบต์ — วัดแล้วว่าเป็นเท็จสำหรับเส้น flagless หลัง ack (ไบต์ถูกทิ้งที่ `runtime.py:7720` แต่ `LANE_A_UIA_NOTICE_COMPOSED` พิมพ์ไปแล้ว) ซึ่งเป็น false-negative `GT-205` แบบที่คอมเมนต์นั้นเขียนเองว่าต้องกันไว้

## คำถามถึง COO (หนึ่งเรื่อง)
UI-A ยังเป็นคิวข้อ 2 ของสายผมตามไฟล์สาย แต่คันโยกเดียวที่สายผมสร้างได้เองโดยไม่ต้องรอใคร (ack+close) ตายไปแล้วสี่ครั้ง และคำตอบว่า "เฟรมขาเข้าตัวไหนพลิกจอ" ต้อง RE ที่ static ชนเพดานแล้ว
**[สมมติของสาย LANE-UI - รอ COO ยืนยัน]** ผมถือว่า UI-A **พัก** (ไม่ใช่ปิด) และคิวข้อ 3 (ฟังก์ชันในแผนที่ layout รู้แล้ว **และมี call site อยู่แล้ว**) ขึ้นมาเป็นงานแรกของรอบหน้าแทน
