# ตัดสิน: รหัสผ่านรอง = เก็บค่า MD5 ที่ไคลเอนต์ส่งเป็น opaque ห้ามคำนวณเอง (ครึ่งเก็บไม่ต้อง RE) · ครึ่ง "เฟรมไหนตั้ง/ตรวจ" ค้น V110 ใน `second_password_bypass.py` ก่อน RE · "นามแฝง" = ช่องกรอกบนหน้าสร้างตัวละคร ไม่ใช่ x=1 ไม่ใช่ x=37

## ตัดสินว่าอะไร
1. **ครึ่งเก็บ — การอ่านของคุณถูก ยืนยัน**: คอลัมน์เก็บ upper-hex MD5 ตามที่ไคลเอนต์ส่ง (`PROVEN_EXACT` / `WITHHELD` = preserve raw) · เซิร์ฟเวอร์ห้าม derive/คำนวณ/พิมพ์ · x=30 ห้ามออกตลอดกาล (ขาออก) ไม่ขัดกับการเก็บ (ขาเข้า) · ครึ่งนี้ **ไม่บล็อก RE**
2. **ครึ่ง "เฟรมไหนตั้ง/ตรวจ" ยังไม่ปิด** — คุณ Panya สั่งว่ารหัสผ่านรองต้องใช้เปิดกระเป๋า/คลังจริง ไม่ใช่แค่เก็บ · ก่อนเปิดใบ RE ให้ค้น corpus ที่มีอยู่แล้ว: `second_password_bypass.py` (โหมด `required`/`bypass` · V110 result=OK · HYP-PF-009) + จดหมาย/rounds ที่ตั้ง V110 · ถ้า corpus บอกเฟรม credential ขาเข้าและ layout ครบ = ไม่ต้อง RE ทำ PR เก็บ+ตรวจได้เลย · ถ้าไม่ครบ ใบ RE ตั้งคำถามแคบ: "เฟรมขาเข้าใดพก MD5 ตอนตั้ง และเฟรมใดตอนเปิดกระเป๋า" ≤12,000 อักขระ
3. **"นามแฝง" (คำของคุณ Panya `0328`: "ช่องนามแฝง(นามปากกา) ที่หน้าสร้างตัวละครให้ใส่ค่า")** = ช่องกรอกบน **หน้าสร้างตัวละคร** ที่ไม่ใช่ชื่อตัวละคร · เป้าหมาย RE = สตริง label ของหน้า CharCreate ใน TEXTDATA → ช่องกรอกไหน → ไบต์ไหนใน `CreateActorVital` (คุณมี parser จากชิ้น 1 แล้ว) · **ไม่ใช่** x=1 (ผูก `characters.name` แล้ว) **ไม่ใช่** x=37 กิลด์
4. ถ้าหน้าสร้างตัวละครไม่มีช่องนั้นจริง (label ไม่มี · payload ไม่มีฟิลด์ว่าง) ⇒ ปิดครึ่งนี้เป็น `BOUNDED-NEGATIVE: no such input on CharCreate` พร้อมหลักฐานสตริง ผมรับเป็นคำตอบ ไม่ต้องถามคุณ Panya

## เพราะอะไร
ใบ `0329` ข้อ 4 ผมเขียน "RE ก่อน" หมายถึงครึ่งเฟรม ไม่ใช่ครึ่งเก็บ · เปิดใบ RE โดยไม่ค้น corpus = ผิดวินัยที่ `RE-229` เพิ่งถูกแก้ ถูกต้องที่คุณหยุดถาม
