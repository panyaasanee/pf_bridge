# รายงานตามเงื่อนไขของใบ: ช่อง `+0x164` ถูกป้อน "ชื่อตัวละครจริง" จริง

## ใบสั่งเขียนเงื่อนไขไว้ว่าอะไร

> "**ไม่ต้องแก้พฤติกรรม** เว้นแต่ตรวจแล้วพบว่ามันป้อน *ชื่อตัวละครจริง* ลงช่องนั้น —
> ถ้าพบ นั่นคือของที่หลุด `CORE-REQUEST-027` มา **ให้รายงานก่อนแก้พฤติกรรม**"

**พบครับ** และนี่คือรายงานนั้น **ยังไม่แก้พฤติกรรมแม้แต่บรรทัดเดียว**

## ที่วัดได้

`src/pirateforce_foundation/stats_progression_hypothesis.py:939`
(`stats_progression_baseline_fields`) และตัวสร้าง step ที่ `:1164` กับ `:2529` ป้อน
**`actor.character_name`** — ชื่อของตัวละครที่ผู้เรียกสร้างขึ้น ไม่ใช่โทเคนคงที่ — เข้าฟิลด์
`AttrField("character_name", "actor", 0x01000000, 0x164, tag 0x48)` ⇒ wstring ที่ถูกเข้ารหัสลง
`+0x164` คือชื่อตัวละครจริง

```
stats_progression_baseline_fields(...) -> {... 'character_name': 'Blackbeard'}
encode_actor_attr(...) -> 48 14 00 00 00 <'Blackbeard' utf-16le>  ที่ mask 0x01000000 / +0x164
```

`damage_hp_link_hypothesis.py:319` มีฟิลด์เดียวกัน ป้อนจาก `HP_LINK_BASELINE_CHARACTER_NAME`

## ผมเคยเขียนผิด และขอแก้ตรงนี้

ในไฟล์รอบกับ stub ฉบับแรกของรอบนี้ ผมเขียนว่า "ตรวจแล้วไม่มีการป้อนชื่อตัวละครจริง ค่าที่ป้อนคือ
`STATS_PROBE_CHARACTER_NAME` / `HP_LINK_BASELINE_CHARACTER_NAME` ซึ่งเป็นค่าคงที่ของ probe"
**ผิดครับ** ผมดูแค่ชื่อค่าคงที่ แล้วสรุปเอาเองว่านั่นคือค่าที่ไหลเข้าฟิลด์ ทั้งที่ค่าคงที่พวกนั้นเป็นแค่
**ค่าตั้งต้นของ probe** ส่วนฟิลด์รับมาจาก `actor.character_name` ตรง ๆ
ผู้ที่วัดแล้วชี้ให้เห็นคือ pf-adversary รอบ `ewm6ff` (D7) ผมได้ขีดฆ่าข้อความเดิมในไฟล์รอบและ stub แล้ว
(ขีดฆ่า ไม่ลบ ตามกติกา)

## ขอบเขตที่จำกัดความเสียหาย (ไม่ใช่การปิดคำถาม)

โมดูลทั้งสองเป็น **scenario-gated** — `production_allowed` ไม่ได้เปิด เส้นล็อกอินจริงไม่ประกอบมัน
⇒ **ไม่มีผู้เล่นจริงคนไหนโดนส่งค่านี้วันนี้** นั่นคือขอบเขต ไม่ใช่คำตอบว่าไม่เป็นไร
เพราะสิ่งที่ `CORE-REQUEST-027` ไล่ตามคือ**รูปแบบ**ที่ผู้เขียน V1-V141 ทำไว้ และรูปแบบนั้นยังอยู่ในสองโมดูลนี้
`player_wire.py:80-90` แก้ให้เส้นล็อกอินจริงไปแล้ว (`PANYA-DECISION 20260828_0125` แถว x1/x37)
แต่โมดูล hypothesis สองใบนี้ยังทำแบบเดิมอยู่

## ผมทำอะไรไปแล้ว และไม่ทำอะไร

- **ทำ:** แก้ป้าย/คอมเมนต์ให้ตรงกับ `gm/attr_wire.py:253` (`wstr_164_guild` -> `LABEL_GUILD`)
  และเขียนข้อเท็จจริงที่วัดได้ข้างบนลงในคอมเมนต์ตรงจุดนั้นเอง พร้อมชี้มาที่ใบนี้
- **ไม่ทำ:** ไม่เปลี่ยนสัญลักษณ์ `character_name` (เป็น dict key ที่ชื่อ refusal / probe config /
  เทสของสองโมดูลอ่านอยู่) และ**ไม่ย้ายฟิลด์ไป `BasicAttr` บิต `0x0001` @ `+0x28`**
  ซึ่งเป็นช่องชื่อตัวละครจริง — นั่นคือ "แก้พฤติกรรม" และใบสั่งบอกให้รายงานก่อน

## สิ่งที่ผมขอให้ chief เคาะ

โมดูล hypothesis สองใบนี้ควรถูกแก้ให้ส่งชื่อลง `BasicAttr +0x28` เหมือนที่ `player_wire.py` แก้ไปแล้ว
หรือควรปล่อยไว้ตามเดิมเพราะมันเป็น probe ที่ **ตั้งใจ**ส่งชื่อลงช่องกิลด์เพื่อวัดว่าช่องนั้นทำอะไร
(`gm/attr_wire.py:253` เขียนไว้เองว่า "probe sent a character name here safely")

ผมเดาไม่ได้ว่าอันไหน เพราะคำตอบขึ้นกับว่า probe พวกนั้นยังต้องวัดอะไรอยู่ — ซึ่งเป็นของสาย RE ไม่ใช่ของผม
**ระหว่างนี้ไม่มีอะไรค้างครึ่งทาง**: ป้ายถูกแล้ว พฤติกรรมเดิมไม่ถูกแตะ และข้อเท็จจริงอยู่ในโค้ดตรงจุด
