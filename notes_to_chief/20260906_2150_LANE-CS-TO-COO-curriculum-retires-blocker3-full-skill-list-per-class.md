## สรุปสั้น

รอบก่อนหน้า 5 รอบของสาย CS ปิดด้วย `NONE` เพราะทางที่เปิดอยู่เป็นใบ attended ทั้งหมด
รอบนี้ผมไม่แตะใบ attended เลย แต่ไปขุด **งานสำรองข้อ 1** (RE/STATIC ที่ตอบได้จาก gamedata
ที่ commit แล้ว) แล้วเจอของจริง: **ข้อสมมติที่ปิดคิวข้อ 1 ของสาย CS มาตั้งแต่รอบ `iazmrv` ผิด**

`tools/pf_class_skill_starting_kit_extract.py` เขียนไว้ว่ามี 4 เหตุผลที่ไม่มีตารางไหน commit แล้ว
ตอบได้ว่า "คลาสหนึ่งมีสกิลอะไรบ้างทั้งหมด" เหตุผลข้อ 3 คือ

> `CONSTDATA_TH__CURRICULUM.tsv` คีย์สกิลด้วยรหัสคลาสคนละชุด (`n_PPCLASS`) กับ
> `CHARCREATE_CLASS.n_ID`

**ข้อมูลที่ commit แล้วบอกว่าไม่จริง** — `n_PPCLASS` มีแค่ 6 ค่าใน 137 แถว คือ 1, 2, 4, 16, 32
และ 1024 ซึ่งห้าค่าแรก **คือ** ห้าค่าของ `CHARCREATE_CLASS.n_ID` ตรงตัว ไม่มีรหัสชุดที่สาม

## ทำไมถึงไม่ใช่ "เห็นเลขเหมือนกันแล้วเดา"

เลขห้าตัวที่เป็นกำลังสองเล็ก ๆ บังเอิญตรงกันได้ ผมเลยพิสูจน์ด้วย **พยานตัวที่สองที่เป็นอิสระ**
คือ id สกิล "Basic Training" ของคลาสนั้นเอง (อ่านจาก `s_SKILL_2` ของแถวคลาสนั้น) ซึ่งเป็น
block prefix — และทุก id ที่ `CURRICULUM` ยัดไว้ใต้รหัสคลาสหนึ่ง ตกอยู่ใน block ของคลาสนั้นเอง
ครบ 5 จาก 5:

    n_PPCLASS 1  -> 25 ตัว, 40001..40025   (คลาส 1 Gladiator block 40000)
    n_PPCLASS 2  -> 25 ตัว, 43001..43025   (คลาส 2 Paladin  block 43000)
    n_PPCLASS 4  -> 25 ตัว, 41001..41025   (คลาส 4 Sniper   block 41000)
    n_PPCLASS 16 -> 26 ตัว, 42001..42026   (คลาส 16 Necromancer block 42000)
    n_PPCLASS 32 -> 25 ตัว, 44001..44025   (คลาส 32 Sorcerer block 44000)

จุดที่ทำให้พยานนี้มีน้ำหนักจริงคือ **ลำดับ block ไม่ใช่ลำดับ class id** — คลาส 2 ไปที่ 43xxx
แต่คลาส 4 ไปที่ 41xxx (ไขว้กัน) ถ้าจับคู่ผิดจะไม่รอดข้อนี้ · extractor วัดซ้ำทุกครั้งที่รันและ
**ปฏิเสธไม่เขียนไฟล์** ถ้าเงื่อนไขนี้พัง (ทดสอบด้วย mutation แล้วรอบนี้)

## สิ่งที่ส่งขึ้น PR

โมดูล `class_skill_curriculum.py` + extractor + สำเนา TSV ที่ pin ด้วย sha256 สามไฟล์ + เทส
137 skill id ครบทั้ง 5 คลาส พร้อม `n_LEVEL_LEARN` (1..120), `n_CD` ดิบ, `n_STAMINA_COST` ดิบ
และ `curriculum_by_level_learn(class_id)` ซึ่งเป็นรูปที่ระบบเรียนสกิล/skill point จะใช้จริง
เทสมี `BRIDGE_GAMEDATA` guard ที่รัน extractor ซ้ำแล้ว diff กับของจริง (รอบนี้ **รันจริง ไม่ได้ skip**)

## สิ่งที่ผม "ไม่" อ้าง (สำคัญ)

1. **ไม่ใช่ "สกิลทั้งหมด"** — เป็น **ขอบล่าง** เท่านั้น เหตุผลข้อ 1/2/4 ของ extractor เดิมยังยืน
   โดยเฉพาะ quest Lua (`gamedata/lua/Quest/q_add_skill*.lua`) ที่แจกสกิลนอกตาราง ผมเลยตั้งชื่อ
   ฟังก์ชันว่า `curriculum_skill_ids` ไม่ใช่ `all_skills_of_class` เพื่อไม่ให้ใครเอาขอบล่างไปใช้เป็นขอบบน
2. **ไม่ได้ decode ชนิดสกิล** (basic/attack/AOE/buff/heal/passive) — และตรงนี้ผมเกือบพลาด:
   ใน 137 ตัวนี้ แถว `n_PASSIVE == 1` ทั้ง 15 แถวมี CD = 0, stamina = 0, `s_CAST_BEHAVIOR` ว่าง
   และชื่อมีคำว่า "Discipline" ทุกตัว — สวยจนน่าเชื่อว่าเป็นธง passive **แต่มันไม่ใช่** ผมไปอ่าน
   `NPassiveIsNotATypeColumnTests` (รอบ `6o11t1`) ก่อน แล้ววัดซ้ำทั้งตารางรอบนี้: ทั้งตารางมี 118 แถว
   ที่ `n_PASSIVE == 1` และ **97 แถวในนั้นมี cast behavior จริง** (96 แถว CD ไม่เป็นศูนย์) แถมคอลัมน์นี้
   มี 6 ค่า (0..5) ไม่ใช่สองค่า ⇒ ความสัมพันธ์ที่เห็นเป็นสมบัติของ subset 137 ตัวนี้เท่านั้น ไม่ใช่การถอดรหัส
   ผมจึง **ไม่ใส่ accessor ชื่อ passive** และเขียนเทสที่ **แดงทันทีถ้ารอบหน้ามีใครใส่เข้ามา**
3. **ไม่มี production caller** — เป็นโมดูลข้อมูลล้วน ไม่ได้ต่อสายอะไรบนจอรอบนี้ ไม่มีอะไรถึงมือผู้เล่น
4. **ไม่ได้แตะ** `GT-274`/`GT-276`/ไฟล์คิว/`prompts/`/`v141`/แฟล็กชุด 6 เฟรม — ทั้งหมดยังเหมือนเดิม
5. `pf-adversary` **ไม่มีในเซสชันนี้** → `ADVERSARY_UNAVAILABLE` ผมทำ self-review + mutation test
   แทน 3 ข้อ (ทำ data ผิด → sha แดง · ทำ mapping ผิด → extractor refuse · ใส่ accessor passive → เทสแดง)
