# เกต `PF_SPEED_TRIAL` สร้างแล้วทั้งข้อ — และล็อกทั้งสองตัวยังปิดอยู่ วัดในคอลเดียวกับที่เฟรมออก

**ค้นแล้ว: ไม่เจอ และไม่ต้องใช้** — `external/00_SEARCH_HERE_FIRST.md` และ
`gamedata/00_SEARCH_HERE_FIRST.md` ไม่มีอะไรเกี่ยวกับ `speed` หรือชื่อตัวแปรสภาพแวดล้อมเลย
ซึ่งถูกต้อง: รอบนี้ไม่พึ่งข้อมูลไคลเอนต์แม้แต่ไบต์เดียว มันเป็นเกตในโปรเซสฝั่งเซิร์ฟเวอร์ล้วน ๆ

## ทำครบตามใบทั้งสี่บุลเล็ต
1. **ค่าเริ่มต้น = พฤติกรรมวันนี้เป๊ะ** ตัวแปรไม่ตั้ง = ทุกเฟรมถูกกักเหมือนเดิม
   `SPEED_LOGIN_READ_LANDED` ยังเป็น `False` · `SHAPES_CLEARED_BY_A_REAL_CLIENT` ยังเป็น `frozenset()`
   🔴 เทส `test_both_locks_are_still_shut_while_it_does` วัดค่าทั้งสองตัว **ในคอลเดียวกับที่เฟรมออกจริง**
   ⇒ พิสูจน์ว่าเกต **ข้าม** ล็อก ไม่ได้ **เปิด** ล็อก · รอบไหนไปทำด้วยการพลิกค่าคงตัวแทน เทสตัวนี้แดง
2. **`PF_SPEED_TRIAL=<ค่าเดียว>` ⇒ `/speed <ค่านั้น>` ส่งได้ ค่าอื่นยังถูกกัก** ครบทั้งประโยค
   "ค่าเดียว" นิยามเป็น **f32 หนึ่งค่า ไม่ใช่สตริงหนึ่งสตริง**: `450` `450.0` `4.5e2` arm ตัวเดียวกัน
   และ `400.1` arm `400.1000061035156` ซึ่งเป็นเลขที่แถวจะถือจริงหลัง `validate` ปัดเป็น f32
   ⇒ เกตกับแถวตรงกันโดยโครงสร้าง ไม่ใช่โดยบังเอิญ
3. **fail-closed รูป `PFGM_FORCE`**: ไม่ตั้ง / ว่าง / ช่องว่าง / `fast` / `nan` / `inf` / `1e400` /
   ไม่ใช่สตริง / mapping ที่ `.get` โยน / ค่าเกิน `F32_MAX` — ทุกตัวคือพฤติกรรมวันนี้ + คำหนึ่งคำบนคอนโซล
   ไม่มีทางไหนกลายเป็นประตูที่เปิดให้ค่าที่ไม่มีใครเลือก
   🔴 เทียบด้วย `repr()` ไม่ใช่ `==` เพราะ `-0.0 == 0.0` เป็นจริงใน Python ⇒ `PF_SPEED_TRIAL=0`
   **ไม่** รับ `/speed -0` (สายคุณเพิ่งเจอ `-0.0` จากอีกฝั่งในรอบ `vitdca` ของ LANE-DB)
4. **บรรทัดคอนโซลบอกว่าเปิดให้ค่าไหน** อ่านออกโดยไม่ต้องเปิดซอร์ส:
   `SPEED TRIAL OPEN account='GM_ONE' command=speed env=PF_SPEED_TRIAL trial_opens_for=450.0 sending=450.0 character_id=1 identity=1:0`
   และบรรทัด `SPEED DEFERRED` เดิมได้ฟิลด์ที่สี่ `trial_opens_for=` ⇒ คนที่พิมพ์เลขผิดรู้เลขที่ถูก
   จากคอนโซล ไม่ต้องกลับไปเปิดเชลล์ที่ตั้งค่าไว้ · ทั้งสองบรรทัด ASCII ล้วน (คอนโซล cp874)
   และ **ไม่มีทั้งข้อความดิบของตัวแปรและตัวสะกดที่ GM พิมพ์** ไหลออกมา (`/speed 4.5e2` บนเกตที่ arm `450`
   พิมพ์ `sending=450.0` และสตริง `4.5e2` ไม่โผล่ที่ไหนเลย)

## สองเรื่องที่ผมอยากให้คุณรู้ เพราะมันเปลี่ยนรูปโค้ดจากที่ผมตั้งใจไว้ตอนแรก
**(ก) หมุดของ pf-adversary ดักดราฟต์แรกของผมเอง** ผมเขียน
`if speed_wire.send_deferred() and not trial_admitted:` แล้ว
`test_gm_speed_denied_nine_paths.py::_assert_the_deferral_branch_holds_one_reason` **แดง — ถูกแล้ว**
หมุดนั้นบังคับว่าเงื่อนไขที่คุมสาขา deferral ต้องเป็น "คอลเดียว ไม่มีอะไรอื่น" เพราะ AST
แยกเทอมที่ **ขยาย** การกักออกจากเทอมที่ **หด** การกักไม่ได้ มันจึงปฏิเสธทั้งสองแบบ
⇒ ผมย้ายกุญแจออกมาเป็น **wrapper** `if not trial_admitted:` ครอบทั้งสองล็อก
ล็อกทั้งคู่คงเงื่อนไข คำ audit และบรรทัดคอนโซลเดิม **ทุกตัวอักษร** กุญแจตัดสินแค่ว่า
route จะ *เดินไปถึง* ล็อกหรือไม่ · แล้วผมปักรูปของ wrapper เองเพิ่ม (หนึ่ง `not` เหนือหนึ่งชื่อ)
จากฝั่งเทสของสายผม เพื่อไม่ให้รอบหน้าแก้หมุดของเขาด้วยการลบไฟล์เขาทิ้ง

**(ข) มิวแทนต์ตัวหนึ่งรอดในรอบแรก และมันคือตัวที่สำคัญที่สุด**
`_trial_admits(stored)` -> `_trial_admits(value)` เขียวทั้งไฟล์ เพราะสโตร์ดับเบิลในทุกเทส
สะท้อนเลขที่พิมพ์กลับมาเป็นเลขเดียวกัน ⇒ ผมเพิ่มสโตร์ที่ read-back **เบี่ยง** จากที่พิมพ์
แล้วปักสองทิศ: แถวถือค่าที่ arm ไว้ = ออกได้ **แม้ GM พิมพ์เลขอื่น** · แถวถือเลขอื่น = **กัก**
**แม้ GM พิมพ์ตรงกับที่ arm** เพราะคุณสมบัติที่ต้องคุ้มครองไม่ใช่ "เจ้าของพิมพ์เลขที่ arm ไว้"
แต่คือ "เฟรมที่ออกจากโปรเซสนี้ถือเลขที่ arm ไว้" — สองประโยคนี้เท่ากันเฉพาะตอนไม่มีอะไรคั่นกลาง
