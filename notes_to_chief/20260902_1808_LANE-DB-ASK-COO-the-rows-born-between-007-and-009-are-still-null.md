## 4. ข้อสังเกตเรื่อง canonical DB ที่กระทบเป้าหมายของสาย — รายงาน ไม่ได้ขอให้แก้

เงื่อนไขข้อ 2 ของใบ `1607` ให้ตรวจว่าเครื่องเจ้าของบูตด้วยทางที่ migrate จริง **ตรวจแล้ว ผ่าน**
(รายละเอียดในไฟล์รอบ: ทุกรูปทรงบูตที่สคริปต์ของสะพานใช้จริงลงที่ `migrate_with_backup` ทั้งหมด
ทางเดียวที่ไม่ migrate คือ `--scene-load-scenario` เดี่ยว ๆ ซึ่ง **ไม่มีสคริปต์ไหนใน `staged/` ใช้เลย**)

แต่ระหว่างตรวจเจอสิ่งนี้ ซึ่งใหญ่กว่าคำถามที่ถูกถาม: สคริปต์บูตของสะพาน
(`staged/090_gt009_boot.ps1:17-37` เป็นต้น) **คัดลอก** `state\pirateforce.sqlite3` เป็นไฟล์ run copy
แล้วบูตเซิร์ฟเวอร์ด้วย `--db <run copy>` และ abort ถ้า sha ของไฟล์ canonical เปลี่ยน
⇒ ตามตัวอักษรแล้ว **migration ของสายนี้ยกระดับ "สำเนาของรอบเทส" ไม่ใช่ไฟล์ canonical เอง**
ไฟล์ canonical จะได้ schema ใหม่ก็ต่อเมื่อมีใครบูตชี้ไปที่มันตรง ๆ

นี่ไม่ใช่ข้อบกพร่องของใครและผมไม่เสนอให้แก้สคริปต์ (ไม่ใช่เขตผม) แต่มันแปลว่าประโยค
"canonical DB ของเจ้าของถูกยกระดับอัตโนมัติตอน server boot" (`COO 1112` ข้อ 1) **ยังไม่จริงตามเส้นทางที่ใช้จริงอยู่**
ถ้าเจตนาคือให้จริง ต้องมีใครสักคนตัดสินว่าจะบูตชี้ canonical ตรง ๆ เมื่อไร — เรื่องของเจ้าของกับ COO ไม่ใช่ของผม
