# ข้อมูลจากเจ้าของ: บนเซิร์ฟเวอร์จริง "แล่นเรือชนเกาะ หน้าต่างรายงานกัปตันก็เด้งขึ้นมาเอง ไม่ต้องคลิกที่เกาะ"

## ข้อเท็จจริง (คำของ Panya ตรงตัว)
"แล่นเรือชนเกาะ หน้าต่างก็เด้งขึ้นมารายงานกัปตันแล้ว ไม่ต้องคลิกที่เกาะ"
⇒ กลไกเทียบท่าคือ **เหตุการณ์ชน/เข้าเขตเกาะ** ไม่ใช่การคลิก ไม่ใช่ปุ่ม · ไคลเอนต์ต้องส่งอะไรบางอย่างตอนเรือแตะเขตเกาะ แล้วเซิร์ฟเวอร์ตอบด้วยหน้าต่าง

## ตัดสินว่าอะไร (ปรับ `0343` สองข้อ ที่เหลือยืน)
1. **คำถามในใบ RE ของคุณ (`0343` ข้อ 3) แคบลง**: (ก) ตอนเรือชน/เข้าเขตเกาะ ไคลเอนต์ส่งเฟรมอะไร — เป็น `0x1FB2` ที่มี trigger id ของ**แถวเกาะ**ใน `Bg3001.placements.tsv` (ไม่ใช่ 5 id ของ prop ที่เคยเห็น) หรือเป็น opcode อื่น · (ข) เฟรมตอบที่เปิดหน้า "รายงานกัปตัน เรือเทียบท่า [ชื่อเกาะ]" และเฟรมยืนยันที่ทำให้วาป · **ทางลัดที่ต้องลองก่อน**: ถ้าตาราง TIP/placements ให้ trigger id ของ Prison Exile กับ Spice Paradise ได้ สมมติฐาน "เกาะ = `0x1FB2` id ของเกาะ" ตรวจได้ทันทีด้วย log responder ของข้อ 4
2. **เปิดใบ capture ได้หนึ่งใบ (ไม่ใช่ใบ "เทียบท่า" PASS/FAIL ซึ่งยังปิดตาม `0343` ข้อ 5)**: ผู้เทสแล่นเรือ**ชนเกาะ 2 (Prison Exile) และเกาะ 3 (Spice Paradise) โดยตั้งใจ** บันทึกทุกเฟรมที่ไคลเอนต์ส่งตอนชน (log responder ข้อ 4 พิมพ์ trigger id + ชื่อจากตาราง) · เกณฑ์ผ่านของใบ = "ได้ hex ของเฟรมตอนชนครบสองเกาะ" ไม่ใช่ "หน้าต่างเด้ง" · ใบนี้เข้าหัวข้อ "รอเครื่องคุณ" ใน NOW.md ข้อ 4 · ร่างในรอบ 04:21 พร้อมข้อ 2-4 ของ `0343` · เพดาน 12,000 อักขระ
3. ข้อ 2 (ตารางเกาะ) · ข้อ 4 (log responder ไม่มีไบต์ออก) · กำหนด 05:51 ของ `0343` ยืนทุกตัวอักษร
