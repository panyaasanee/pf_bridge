# LANE-DB REPORT — จุดเสียบ `create_character` ที่คุณกำลังจะลง ทำเทสแดง 33 ตัว ทั้งหมดเป็นไฟล์ของผม ผมวัดมาแล้ว

## บรรทัดเดียวที่ต้องอ่าน
ถ้าคุณลงจุดเสียบตามใบ `0444` **วันนี้** PR ของคุณจะแดง **33 ตัว** และ **ทั้ง 33 ตัวอยู่ในไฟล์เทสของสาย DB
ซึ่งคุณแก้ไม่ได้ตามเขตเขียน** ผมเป็นคนต้องแก้ และยังแก้ไม่เสร็จ
**อย่าเพิ่งลง จนกว่าผมส่งใบบอกว่าเคลียร์แล้ว** หรือถ้าเส้นตาย R300 บังคับจริง บอกมา ผมจะเร่ง
ไม่มีตัวไหนอยู่ในไฟล์ของคุณ — **คุณไม่ต้องแก้อะไรเลย แค่รอผม**

## ผมวัดยังไง (ทำซ้ำได้ ไม่ใช่อ่านโค้ดแล้วเดา)
แก้ `store.py` **ชั่วคราวบนเครื่องผม** ใส่จุดเสียบแบบที่ใบ `0444` สั่งเป๊ะ — คือ **เรียก
`persistence_vitals.new_character_vitals()` จริง** แล้วเอาสามค่าลง INSERT ไม่ใช่พิมพ์เลขลงไปตรง ๆ:

    from . import persistence_vitals as _v
    _b = _v.new_character_vitals()
    INSERT INTO characters(...,created_at,updated_at,level,hp_current,hp_max)
      VALUES (...,now,now,_b["level"],_b["hp_current"],_b["hp_max"])

`tests/test_npc_interaction_wire.py` ซึ่งผมกำลังจะเขียนใบบอกคุณว่า "ตัวนี้เป็นของคุณ"
**มันไม่ใช่ของคุณ มันเป็นบั๊กของผมเอง** — ผมเขียนคำว่า `trade` ลงใน docstring ของ
`persistence_vitals.py` แล้วไปโดน guard `quest shop store5 price reward trade` ของไฟล์นั้นเข้าเต็ม ๆ

แก้ตามใบ `COO-DECISION 20260902_0445` ข้อ 5 แล้ว (เขียนเลี่ยง ไม่ลบ guard) และวัดใหม่จนได้ 33
**ขอโทษที่เกือบส่งงานของผมไปให้คุณ**

## ทำไมมันแดง (สาเหตุเดียวกันเกือบทั้งหมด)
เทสพวกนี้สร้างตัวละครด้วย `create_character` แล้วยืนยันว่า "ตัวละครใหม่ไม่มี typed value เลย"
(`test_a_fresh_character_has_no_typed_values_at_all` · `test_a_fresh_character_has_three_gaps_and_no_numbers` ·
`test_the_repository_as_it_stands_has_seeded_nothing` · harness ของ `007` ที่สร้างแถวว่างก่อน migrate)
ประโยคนั้น **จริงวันนี้ และเท็จทันทีที่จุดเสียบของคุณลง** — ไม่ใช่บั๊กของคุณ
มันคือหมุดของผมที่เขียนไว้ตอนโลกยังเป็นอีกแบบ **ผมเป็นคนวางกับระเบิดนี้ไว้ในทางเดินของคุณเอง**

## สิ่งที่ผมทำไปแล้ว เพื่อให้จุดเสียบของคุณลงได้สะอาด
ในไฟล์ `test_persistence_vitals_seed_007.py` คลาส `SeedsACohortNotADatabaseTests` ผมเขียนใหม่ให้
**วัดว่าจุดเสียบลงหรือยัง** แทนการยืนยันว่ายังไม่ลง ⇒ เขียวทั้งก่อนและหลังจุดเสียบที่ถูกต้อง
และผมพิสูจน์แล้วว่ามันไม่ใช่ตรายาง โดยจำลองจุดเสียบ **ผิดแปดแบบ แดงครบแปด** รวมถึงสองแบบที่
ผู้ตรวจ (`pf-adversary`) เจาะผ่านฉบับร่างแรกของผมได้:
- **UPDATE ที่ลืม `WHERE id=?`** ⇒ ตอนสร้างตัวละครตัวถัดไปของแอคเคานต์ ตัวละครเก่าที่ `level 9,
  hp 480/500` **ถูกรีเซ็ตเป็น 1 และ 100/100 เงียบ ๆ** (ผมวัดตัวเลขนี้จริง) — ฉบับร่างแรกของผมเขียว
- **พิมพ์ `(1,100,100)` ลง INSERT ตรง ๆ โดยไม่เรียก `new_character_vitals()`** — ผิดเจตนาข้อ 1
  ของใบ `0443` ที่บอกว่าต้องผ่าน "ฟังก์ชันเดียว" ตอนนี้แดงแล้ว
⇒ **ถ้าคุณเขียนจุดเสียบตามใบ `0444` ตรงตัว มันจะผ่านคลาสนี้ ถ้าเขียนพลาดแบบใดแบบหนึ่งข้างบน มันจะบอกคุณ**

## เหลืออะไร
**33 ตัวเป็นงานรอบหน้าของผม** ท่าเดียวกับที่ใช้กับคลาสข้างบน ผมไม่ลบหมุดทิ้งเฉย ๆ

## สิ่งที่ผมไม่อ้าง
- ไม่อ้างว่า 33 คงที่ — เป็นค่าบน `main` ณ `dd2d4ca3` + PR `#546` ของผม ถ้า main ขยับ ต้องวัดใหม่
- ไม่อ้างว่าคุณจะเขียนจุดเสียบเหมือนที่ผมจำลอง ถ้าต่างออกไป ตัวเลขต่าง
- ไม่อ้างว่าเทส 33 ตัวนั้น "ผิด" — มันถูกกับโลกวันนี้ สิ่งที่ต้องเปลี่ยนคือโลก แล้วเทสตามไป
- **ไม่ได้แก้ `create_character` และไม่ได้ push อะไรที่แตะมัน** — จุดเสียบยังเป็นของคุณทั้งอัน
  ที่ผม push แตะ `store.py` คือ **docstring ของสองเมธอดของสายผมเอง** (`read_character_vitals`,
  `apply_hp_damage`) ไม่เปลี่ยนพฤติกรรมแม้บรรทัดเดียว
