## 3. ข้อที่ตัดสินต่างจากใบ `0559` — ขอ COO ยืนยัน `[สมมติของสาย GM - รอ COO ยืนยัน]`
ใบ `0559` เสนอ (และ adversary รอบนั้นให้เหตุผลว่า) **"เมื่อ `PLUS4=0` ไม่มีใครใช้ ctor นั้นเลย"**
⇒ ให้ผูก guard กับ macro **เหตุผลนั้นผิด และสายนี้แก้คำของตัวเอง**: slot `+0x08` (`MakeEmptyString`)
เรียก ctor โดยไม่สนใจ macro การผูก guard กับ macro เฉย ๆ จะทำให้ slot `+0x08` คืน buffer ที่ไม่ได้
construct เมื่อ resolve ctor ไม่ได้ = ผู้เรียกทำลายไบต์ขยะ = heap พังแบบเงียบ ๆ

สิ่งที่ทำแทน (สองอย่างพร้อมกัน):
- guard ผูกกับ macro ตามข้อสรุปของใบ (build ที่สัญญาว่าจะ init `+4` เท่านั้นที่ปฏิเสธงานเมื่อ ctor หาย)
- slot `+0x08` **พิมพ์บอกเสียงดัง** เมื่อ ctor หาย (แต่ **คืน pointer เดิม** ไม่ใช่ NULL — ร่างแรกของรอบนี้
  คืน NULL และ adversary หักล้างถูก: `GM-IMG-014` ระบุ `possible_hidden_sret` ⇒ ผู้เรียกทำลาย buffer
  ของตัวเองอยู่แล้วไม่ว่าเราคืนอะไร การคืน NULL จึงไม่กันอะไรเลย แต่เพิ่ม NULL-deref และเบี่ยงจาก
  `required_next_evidence` ของแถวนั้นที่บอกให้คงพฤติกรรม fallback ซึ่งคืน pointer เดิม)

ฐานที่ใช้ตัดสิน: `GM-IMG-014` `semantic_status = PROVEN_EXACT_ABI_NO_PINNED_ROUTE`
blocker `NO_PINNED_CALL_ROUTE_FOR_SLOT8` และ `required_next_evidence` ของแถวนั้นเขียนเองว่า
**"do not claim slot +0x08 is required to open the GM window"** ⇒ ไม่มี route ที่พิสูจน์แล้วว่าเรียก slot นี้
