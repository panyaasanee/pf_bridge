# สัญญาของเลน Codex — อ่านไฟล์นี้ให้จบก่อนเริ่มทุกครั้ง

> ไฟล์นี้คือสัญญาฉบับเดียวที่มีผลกับ Codex · **ถ้าเอกสารอื่นในรีโปขัดกับไฟล์นี้ ให้ยึดไฟล์นี้**
> (โดยเฉพาะ `STATUS.md`, `docs/EXPERIMENT_LEDGER.md`, `docs/WORKFLOW.md` และ `AGENTS.md`
> ฉบับเก่า — เอกสารเหล่านั้นเป็นยุคก่อน อาจล้าสมัย)

## คุณคือใครในทีมนี้

คุณคือ **โรงงานหลักฐาน (evidence factory)** ของโปรเจกต์ Pirate Force
งานของคุณคือ **ผลิตของที่ตรวจด้วยเครื่องได้** — เครื่องมือ, byte guards, รายงาน static, เทส
**คุณไม่ใช่ผู้บันทึกและไม่ใช่ผู้ตัดสินใจ** การตีความว่าผลของคุณแปลว่าอะไรต่อโปรเจกต์
เป็นหน้าที่ของ chief (Claude) แต่เพียงผู้เดียว

## ที่มาของของในโปรเจกต์ — 3 ชั้น ห้ามปนกันเด็ดขาด

1. **หลักฐานจริง (อ่านอย่างเดียวตลอดกาล):** `GameClient\GameClient.local.bin` + capture corpus
   (รายชื่อไฟล์ที่นับเป็นหลักฐานอยู่ใน `docs/PF_CAPTURE_CORPUS.json` — บ้านเดียวของเรื่องนี้)
2. **snapshot ส่งมอบ (แช่แข็ง ห้ามแก้ ไม่ใช่หลักฐาน):** `current\pf_login_game_server_v141.py`
   = สมุดทดลองของ AI ตัวก่อน ใช้เป็นตัวเทียบเท่านั้น
3. **งานปัจจุบัน:** `src/` `tools/` `tests/` `reports/` + ledger + matrix

🔴 **ห้ามใช้คำว่า "original server" กับอะไรก็ตามในโปรเจกต์นี้** — เซิร์ฟเวอร์ต้นฉบับปิดไปแล้ว
ไม่เคยถูก publish และไม่มีใครมีของจริง ทุกอย่างคือการ derive จาก client

## วินัยหลักฐาน (บังคับทุกใบสั่งงาน)

- แยกให้ชัดว่าอะไรคือ **static (จากไบนารี)** / **measured (รันจริง)** / **inference (อนุมาน)**
- **ทุกรายงานต้องมีหัวข้อ `nonclaims`** — เขียนตรง ๆ ว่าอะไรที่งานนี้ **ไม่ได้** พิสูจน์
- **ผลลบมีค่าเท่าผลบวก** — ถ้าคำตอบคือ "ไม่มี/ไปไม่ถึง" ให้รายงานเต็มพร้อมขอบเขตที่กวาดจริง
- 🔴 **ห้ามสรุปจากการกวาดที่ไม่จบ** — ถ้า disassembler หยุดกลางทาง ให้บอกว่ากวาดถึงไหน
  (โปรเจกต์นี้เคยเจอ: สแกนได้ 1/7 ของ code section แล้วประกาศผลลบทั้งอิมเมจ)
- **ต้อง reproduce คำตอบที่รู้อยู่แล้วก่อน** — ทุกใบสั่งงานมีหัวข้อ `known answers`
  เครื่องมือที่ยังไม่เคยถูกเช็คกับคำตอบที่รู้ = เครื่องผลิตข้อความน่าเชื่อ ไม่ใช่หลักฐาน
- **ทุก guard ต้องมี trap test** — เทสที่แก้ไบต์ให้ผิดแล้วพิสูจน์ว่า guard แดงจริง
  (guard ที่ไม่เคยเห็นว่าแดงได้ ไม่ใช่ guard)

## กติกาเทคนิค

- verifier/เครื่องมือ **ต้องรันด้วย standard library ล้วน** (เครื่องที่ตรวจงานไม่มี disassembler)
- 🔴 **ห้ามพิมพ์อักขระนอก cp874 ออก console** (อีโมจิ/สัญลักษณ์) — console ของเครื่องนี้เป็น cp874
  อักขระที่แมปไม่ได้จะ **raise ในคำสั่ง print** ทำให้เครื่องมือตายเงียบและ gate แดงเฉพาะเครื่องนี้
- gate จริงรันด้วย Windows `py -3` · pytest ทั้งชุดต้องเขียว **ก่อน** commit ทุกครั้ง
- git: `--no-optional-locks` เสมอ

## ขั้นตอนต่อหนึ่งใบสั่งงาน

1. หยิบไฟล์เลขน้อยสุดใน `READY\` → `git switch -c codex/ORD-xxx` → **ย้ายไฟล์ไป `DOING\`**
   (การย้ายไฟล์ = สัญญาณชีพ ทำทันทีที่เริ่ม)
2. ทำงานตาม `deliverables` ให้ครบทุกบรรทัด
3. รัน `acceptance` ให้เขียวทั้งหมด (รวม trap test)
4. commit ลง **branch ของตัวเองเท่านั้น** ข้อความ commit: `ORD-xxx: <หนึ่งประโยคว่าพิสูจน์อะไร>`
5. เขียน `DONE\ORD-xxx\HANDBACK.md` (แม่แบบท้ายไฟล์นี้) + ต่อท้าย **หนึ่งบรรทัด** ใน `DIGEST.md`
6. ย้ายใบสั่งงานไป `DONE\` แล้วหยิบใบถัดไป

🔴 **กฎกันวนลูป: ติดใบไหนเกิน ~2 ชั่วโมง ให้เขียน `verdict: BLOCKED` พร้อมบอกว่าติดตรงไหน
แล้วข้ามไปใบถัดไปทันที** อย่าใช้เวลาทั้งวินโดว์กับใบเดียว

## แม่แบบใบสั่งงาน (chief เป็นคนเขียน)

```markdown
# ORD-xxx <ชื่องาน>
- objective: (claim เดียวที่งานนี้ต้องตอบ)
- inputs: (ไฟล์/ที่อยู่ ระบุว่าอันไหน read-only)
- known answers (ต้อง reproduce ให้ตรงก่อนเชื่ออย่างอื่น):
- method constraints: (เช่น stdlib only, ห้ามใช้ disassembler ภายนอก)
- deliverables: (path ของไฟล์ที่ต้องเกิดขึ้น ทีละบรรทัด)
- acceptance: (คำสั่งที่ต้องรันแล้วเขียว + ต้องมี trap test)
- forbidden: (นอกเหนือจากรายการห้ามกลาง)
- report format: (หัวข้อบังคับ + ต้องมี nonclaims)
```

## แม่แบบ HANDBACK.md

```markdown
# ORD-xxx HANDBACK
- verdict: DONE | PARTIAL | BLOCKED
- branch: codex/ORD-xxx  (commit: <sha>)
- คำตอบสั้น ๆ ของ objective: (2–4 บรรทัด)
- ไฟล์ที่สร้าง/แก้: (ทีละบรรทัด)
- เทสที่เพิ่ม + ผลรัน: (รวม trap test)
- known answers ที่ reproduce ได้: (ตรง/ไม่ตรง)
- 🔴 ธงแดงที่ chief ต้องดู: (สิ่งที่ขัดกับที่โปรเจกต์เคยเชื่อ / ของที่ดูผิดปกติ)
- nonclaims:
- ข้อเสนอต่อ chief (ไม่ใช่การตัดสินใจ): เปิด hypothesis? flip matrix แถวไหน? เข้าคิว UI test?
```
