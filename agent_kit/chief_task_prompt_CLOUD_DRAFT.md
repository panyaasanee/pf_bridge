## สิ่งที่ **ต้องเขียนใหม่** — 6 ท่อน

### ① วิธีรันคำสั่ง (แทนท่อน "PF BRIDGE" เดิม)

**เดิม:** ทุกอย่างผ่าน `.ps1` → `inbox\` → อ่านผลจาก `outbox\`
**ใหม่:** งานโค้ด/เอกสาร/วิเคราะห์ **รันในแซนด์บ็อกซ์ของ cloud เองทั้งหมด ไม่ต้องพึ่ง bridge**

**สิ่งที่ยังต้องผ่าน bridge บนเครื่อง Panya (ไม่มีทางอื่น):**
- บูต/ปิด server · แตะ canonical DB `state\pirateforce.sqlite3` และ run copy
- เปิด GameClient · อะไรก็ตามที่ต้องมีหน้าจอจริง
- **gate ตัวเต็ม** — เพราะ 7 check ต้องใช้ `GameClient.local.bin` และอีก 1 ต้องใช้ canonical DB (ดู `.github\workflows\README_GATE_CI.md`)

⇒ **ท่อนนี้ต้องเขียนให้ชัดว่า chief สั่งงานเครื่อง Panya ยังไงเมื่อไม่ได้อยู่เครื่องเดียวกัน**
ทางเดียวที่มีตอนนี้คือ **เขียนใบสั่งลงคิว/กล่องจดหมายแล้ว push** ให้ผู้เทส local `pull` ไปทำ
🔴 **ข้อนี้แปลว่า latency ของงานที่ต้องแตะเครื่องจะเปลี่ยนจาก "วินาที" เป็น "รอบของผู้เทส"** — ต้องเขียนไว้ตรง ๆ

### ② กฎ commit (ท่อนที่เปลี่ยนมากที่สุด)

**เดิม:** *"commit ต้องทำบน Windows bridge เท่านั้น"* — เหตุผลจริงคือ **sandbox git index stale ⇒ ทำ phantom deletions**
**ใหม่ (เมื่อมี remote):** cloud chief `clone` ใหม่ ⇒ **ไม่มี index stale ⇒ commit บน cloud ได้**

🔴 **แต่ห้ามลบเหตุผลเดิมทิ้ง ต้องแทนที่ด้วยเงื่อนไขที่ตรวจได้:**
> commit ได้เมื่อ index มาจาก clone ของรอบนั้นเอง · **ห้าม commit ทับ worktree ที่แชร์กับเครื่อง Panya ผ่าน mount**
> — เงื่อนไข "shared mount" คือสิ่งที่ทำให้กฎเดิมมีอยู่ ไม่ใช่คำว่า "Windows"

**และต้องเพิ่มกฎใหม่ที่ไม่เคยมี:**
- `pull --rebase` ก่อนทำงานเสมอ · ถ้ามี conflict ที่ `GAME_TEST_QUEUE.md` ⇒ **chief ชนะเสมอ** (chief เป็นผู้เขียนแต่ผู้เดียว)
  แต่ถ้า conflict ที่ `notes_to_chief\` ⇒ **ผู้เทสชนะเสมอ** (ผลเทสเป็นหลักฐาน chief ห้ามเขียนทับ)
- **ห้าม force push** ทุกกรณี
- ธง `LOCK_*` และ `inbox/outbox/done/staged` **ต้องไม่อยู่ใน version control** — ถ้าเห็นมันใน `git status` แปลว่า `.gitignore` พัง **ให้หยุดทันที**
  (ถ้าธงที่กำลังถูกถืออยู่โดนเขียนทับด้วย `pull` = กติกา LOCK พังทั้งระบบเงียบ ๆ)

### ③ เกณฑ์ gate

**เดิม:** *"gate จริง = Windows `py -3` · เกณฑ์เขียวล่าสุดอ่านจาก release note ในธง ห้ามใช้ตัวเลขที่จำมา"*
**ใหม่:** กฎ "อ่านจาก release note ห้ามจำ" **ยังอยู่และสำคัญกว่าเดิม** เพิ่มสามข้อ:

- **CI บน `windows-latest` ไม่ใช่ gate ตัวเต็ม** มันคือ *subset* — ตารางว่า check ไหนรันได้/ไม่ได้อยู่ใน `README_GATE_CI.md`
  **ห้ามเขียนคำว่า "เขียว" ในเอกสารส่งกะโดยไม่ระบุว่าเขียวจาก CI หรือจาก gate เต็ม**
- **check ที่รันไม่ได้ต้อง skip อย่างเปิดเผยพร้อมเหตุผลใน log** ห้าม skip เงียบ
- 🔴 **`tools\verify_foundation.ps1` ไม่ใช่ gate อีกต่อไป และผ่านไม่ได้** (พิน 79 สมาชิก แต่ release ออก 105)
  — `README.md:15` และ `AGENTS.md:117` ยังโฆษณาผิดอยู่ **ต้องแก้ก่อนย้าย ไม่งั้น cloud chief จะเชื่อเอกสาร**

### ④ การส่งใบสั่งเทสลง local

เขียนใหม่ว่า chief เขียน `GAME_TEST_QUEUE.md` → `commit` → `push` → ผู้เทส `pull`
**ต้องระบุ:** ผู้เทสจะรู้ได้ยังไงว่ามีของใหม่ · ถ้าผู้เทสกำลังเทสอยู่ตอน chief push จะเกิดอะไร ·
**ผู้เทสต้อง `pull` ตอนไหนถึงจะไม่เปลี่ยนโค้ดที่กำลังเทสอยู่กลางคัน** (ปัญหานี้เกิดเฉพาะทาง (ก) — รีโปเดียว)

### ⑤ อะไรที่ยังต้องผ่าน bridge — ทำเป็นลิสต์สั้นให้จำง่าย

> **บูตเซิร์ฟ · แตะ canonical DB · เปิดเกม · gate ตัวเต็ม · อะไรก็ตามที่ต้องมีหน้าจอ**
> นอกจากห้าอย่างนี้ chief ทำเองบน cloud ได้หมด

### ⑥ 🆕 ท่อนที่ยังไม่มีใน prompt ไหนเลย: **"ถ้าปิดคอมแล้วทำอะไร"**

ต้องเขียนเป็น **ชื่อเลนจริง** ไม่ใช่คำว่า "หางานอื่นทำ" — ลิสต์ 7 เลนอยู่ใน `READINESS_CHECKLIST_CLOUD_20260820.md` ข้อ 9
และต้องเขียนข้อจำกัดตรง ๆ ว่า **เลนที่ต้อง commit จะกองอยู่ใน worktree ถ้าไม่มี remote**
