# COO-DECISION — ห้ามต่อบูตชี้ canonical จนกว่าจะมีกลไกหมุน `CANON_SHA.txt` แยกแยะ "migration ที่คาดหมาย" กับ "corruption"

## ตัดสินว่าอะไร

รับข้อเสนอของ `KA1A-SELFCORRECTION 1205` ส่วนที่ 3 ทั้งสามข้อเป็นเงื่อนไขบังคับก่อน (ไม่ใช่แค่
ข้อเสนอ): ห้ามสร้าง/แก้เส้นทางบูตใดให้ `--db` ชี้ไปที่ canonical DB จนกว่าจะมีของสามอย่างนี้พร้อมกัน
ใน PR เดียว:

1. ด่านตรวจ sha ต้องแยกให้ออกระหว่าง "sha เปลี่ยนเพราะ migration N ที่ apply สำเร็จ (คาดหมายได้ —
   อ่าน `schema_migrations` เทียบ checksum)" กับ "sha เปลี่ยนเพราะอย่างอื่น (abort เหมือนเดิม)"
2. PR ที่ลง migration ที่จะแตะ canonical ต้องมีขั้นหมุนค่าใหม่ลง `CANON_SHA.txt` พร้อม log ชัดเจน
   อยู่ใน PR เดียวกันกับ migration นั้นเสมอ ห้ามแยกสองรอบ
3. ระบุให้ชัดว่าใครเป็นผู้บูตครั้งที่ยกระดับ canonical จริง (จ็อบเฉพาะของ LANE-DB หรือแก้
   `9001_play_boot.ps1` ให้ชี้ canonical) — วันนี้ไม่มีเส้นทางไหนทำเลย ต้องออกแบบขึ้นใหม่ ไม่ปล่อยให้
   เกิดเอง

## เพราะอะไร

ถ้าไม่มีข้อ 1-2 พร้อมกัน: วันที่มีอะไรสักอย่างเริ่มชี้บูตไปที่ canonical จริง รอบเทส attended ถัดไป
จะ abort ที่ด่าน sha ด้วย exit 16 'canonical mismatch' ทันที ข้อความอ่านเหมือน DB พัง คนจะแก้ด้วยการ
ปลดด่านทิ้งเพราะเข้าใจผิด แล้วโปรเจกต์จะเสียตัวจับ corruption ตัวเดียวที่มีอยู่ไปเงียบ ๆ — ตรงกับ
ข้อห้ามของเจ้าของเรื่อง "ปัญหาเงียบ" โดยตรง

## ใครทำอะไรต่อ

  งาน `/speed` (`COO-ORDER 20260901_1101`) ไม่ถูกกระทบ — ยังทำบนสำเนา ไม่ต้องรอเรื่องนี้
