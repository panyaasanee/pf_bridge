## 1. กับดัก: เขียนสตริง marker ในเนื้อความ = ติดอาวุธ automerge โดยไม่ตั้งใจ

เกิดจริงกับรอบนี้ วัดได้ ไม่ใช่การคาดเดา

รอบนี้ตั้งใจ "กัน" ไม่ให้ PR merge ระหว่างแก้ผล pf-adversary จึงถอด marker ออกจาก body
แล้วเขียนอธิบายไว้ว่า *"marker `PF-AUTOMERGE: v4` จะถูกใส่กลับเข้า body นี้ทันทีที่แก้เสร็จ"*

workflow ไม่ได้อ่านความหมายของประโยค มันหาสตริง สตริงอยู่ในประโยคนั้นเอง

ผลลัพธ์: `pirate-force-server#425` merge 19:04Z และ `pf_bridge#648` merge 19:03Z
(ทั้งคู่ merge โดย github-actions[bot]) ทั้งที่ตอนถอด marker ตั้งใจให้ไม่ merge

ประกอบกับ reaper ปลด draft ให้เองที่ ~45 นาทีตามที่บันทึกไว้ในคู่มือ ⇒ **draft ไม่ใช่เครื่องกั้น**
และ **"ถอด marker แล้วแต่ยังพูดถึง marker" ก็ไม่ใช่เครื่องกั้น**

### กฎที่ทุกสายควรถือจากนี้

- ห้ามพิมพ์สตริง marker ลง body ยกเว้นตอนที่ต้องการให้ merge จริง ๆ
  จะอ้างถึงมันให้เขียนว่า "marker automerge" หรือตัดคำ ไม่ต้องพิมพ์เต็ม
- ต้องการกัน PR ไม่ให้ merge ระหว่างแก้: ทางเดียวที่วัดแล้วว่าได้ผลคือ **ไม่มีสตริงนั้นอยู่ใน body เลย**
  (draft ไม่พอ เพราะ reaper ปลดให้ที่ 45 นาที)
- ถ้าจะรีวิว/แก้ก่อนลง main ให้ทำ **ก่อน** เปิด PR หรือก่อนใส่ marker ไม่ใช่หลัง
