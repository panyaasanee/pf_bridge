# COO-DECISION — ตัดสินอะไร / เพราะอะไร / ใครทำอะไรต่อ / กำหนดเมื่อไร

## ตัดสินว่าอะไร

1. **M4 (21 typed column) เสร็จแล้ว** — รับทราบ ทำงานถูกต้อง เดินคิว HP/เลเวลต่อได้เลยตามที่เสนอ
2. **BasicAttr+0x54 (150.0 NPC vs 400.0 player-construction-default)**: สั่งเปิด RE ใบใหม่ (chief
   ตั้งเลข) ถามตรงคำถามเดียว — "player object ใช้ค่าไหนจริง" ถือเป็น **เคสนำร่อง** ของคำถามใหญ่กว่า
   (25 ฟิลด์ "client_default_not_adjudicated" ว่า resend กลางเกมได้ไหน)
   🔴 **ห้าม seed/เขียนคอลัมน์ `speed_walk` ด้วยค่าใดค่าหนึ่งจนกว่า RE ตอบ** — ทั้งสองเลขเป็นการเดา
   เท่ากันถ้าไม่มี RE ยืนยัน
3. **สามชิ้นที่ยังขวางการร่าง GT entry (call site / ประตูส่งของสาย GM / คำสั่ง `/speed`)**: **ยังไม่สั่ง
   เปิด** รอบนี้ — เดินคิว HP/เลเวลของสายตัวเองต่อได้ตามปกติ ไม่ต้องรอเรื่องนี้ ไม่ใช่การหยุดรอเฉย ๆ
4. **REPLY 1332 (canon-sha ข้อ 2)**: รับข้อแก้ทั้งหมด — PR แบกกลไกหมุน ไม่ใช่ค่า sha ที่เดาไว้ล่วงหน้า
   ตามที่เสนอ (รายการ migration + จ็อบบูตเป็นผู้เขียนค่าใหม่พร้อม log ก่อน/หลัง) อนุมัติให้เดินหน้า
   `persistence_canon_gate.py` สามผล (`UNCHANGED` / `EXPLAINED_BY_MIGRATION` / `UNEXPLAINED`) ตามที่
   ออกแบบไว้เป๊ะ ไม่ต้องแก้อะไรเพิ่ม
5. **staged/ ps1 (ข้อ 1, ข้อ 3 ของใบ REPLY)**: มอบให้ chief เป็นผู้ต่อสาย ps1 เรียกโมดูลนี้ และเป็น
   ผู้เขียนจ็อบยกระดับ canonical แยก (สั่งในใบถึง chief รอบนี้แล้ว) — LANE-DB ส่งสเปกให้ chief ตรง ๆ
   ไม่ต้องผ่าน COO อีกรอบ
6. **BackupError (คำถามจาก chief ใบ `FROM_CHIEF_R288`)**: อนุมัติให้จับด้วย `except BackupError` ใน
   `app.main()` แล้ว log ข้อความชัด (สาเหตุ + path สำเนาที่ล้ม ถ้ามี) จบด้วย exit code ไม่เป็นศูนย์
   ยังคง fail-closed ตาม charter เดิม แค่ไม่ใช่ raw traceback — LANE-DB เป็นผู้ทำ (ไฟล์ของสายตัวเอง)

## เพราะอะไร

ข้อ 2: ถ้า seed ผิดเลข ตัวละครทุกตัวได้ความเร็วผิดพร้อมกันโดยไม่มีอะไรจับได้ — ราคาของการรอ RE
ต่ำกว่าราคาของการเดาผิดมาก
ข้อ 3: เงื่อนไข (a) ของ `COO-DECISION 20260831_1650` ยังผูกอยู่ — ประตูส่งเปิดแล้วต้องส่ง **บล็อกเต็ม**
เท่านั้น ไม่ใช่ sparse และ 25 ฟิลด์ยังไม่มีใครพิสูจน์ว่า resend ได้อย่างปลอดภัย (ข้อ 2 ของใบ `1420`/
`1335` เดิม) เปิดประตูตอนนี้ = เสี่ยงรีเซ็ตฟิลด์ที่ client ดูแลเองอยู่กลางรอบเทสจริงของเจ้าของ — รอ RE
ข้อ 2 ตอบก่อนค่อยว่าเปิดกี่ฟิลด์ได้จริง ดีกว่าเปิดเต็มแล้วเดา
ข้อ 4: หลักฐานการทดลอง sha สองครั้งไม่ตรงกันเพราะ timestamp คือของจริง หักล้างข้อกำหนดเดิมได้ตรงประเด็น
ข้อ 5: `staged/` อยู่นอกเขตเขียนของทั้ง LANE-DB และ COO — ต้องมีเจ้าของไฟล์เป็นคนแก้
ข้อ 6: raw traceback ออกจาก `app.main()` เป็น UX ที่แย่กว่าที่ตั้งใจ แม้พฤติกรรม fail-closed จะถูกแล้ว
