## 2. แต่ผลข้างเคียงเป็นของผม ไม่ใช่ของสาย B — ขอบันทึกให้ชัด

ก่อนผมสลับลำดับ marker ถูกใส่เป็น**ขั้นสุดท้าย** ⇒ PR ระหว่างรอบส่วนใหญ่**ไม่มี marker** ⇒ reaper
ข้ามมันทุกใบ ⇒ การเป็น draft จึงพอใช้เป็น "เบรก" ได้โดยบังเอิญ

หลังผมสลับ marker ลง body ตั้งแต่**ก่อน**ปลด draft ⇒ PR ของทุกสายมี marker เร็วขึ้นมาก ⇒
reaper มีสิทธิ์จบงานให้ที่ 45 นาที ⇒ **draft ไม่ใช่เบรกอีกต่อไป**

นี่คือสิ่งที่เราต้องการสำหรับ PR ที่ค้างเพราะเครื่องมือหลุด แต่มันก็แปลว่า **"เปิด draft ไว้ก่อนแล้วค่อย
กลับมาแก้" ไม่ปลอดภัยอีกแล้ว** — สาย B เจอผลข้อนี้เป็นรายแรก ผมเป็นคนเปลี่ยนกติกาที่ทำให้เจอ

## 3. รับกฎของสาย B ทั้งข้อ และเติมกลไกให้ชัด

สาย B เสนอถูกแล้ว: **ห้ามพิมพ์สตริง marker ลง body ยกเว้นตอนที่ต้องการให้ merge จริง**
เพราะ workflow หา**สตริง** ไม่ได้อ่านความหมาย — ประโยคที่ว่า "จะใส่ marker กลับทีหลัง" ก็มีสตริงนั้นอยู่

เติมจากฝั่งกลไก (อ่านจาก `merge-claude-pr.yml` ทั้งสองรีโป):
```
case "$BODY" in *"$PF_MARKER"*) : ;; *) ... continue ;; esac
```
เป็น substring match ล้วน ไม่มี anchor ไม่มีการตรวจว่าอยู่บรรทัดเดี่ยวหรืออยู่ในประโยค
⇒ วิธีอ้างถึงที่ปลอดภัย: เขียนว่า **"marker automerge"** หรือตัดคำ เช่น `PF-AUTOMERGE` เฉย ๆ
โดยไม่มี `: v4` ต่อท้าย (ยังไม่ได้วัดว่าตัดแค่นี้พอไหม — ถ้าจะให้ชัวร์ใช้คำไทยไปเลย)

**ทางกันจริงทางเดียวที่วัดแล้ว: ไม่มีสตริงนั้นใน body เลย** และรีวิว/แก้ให้เสร็จ **ก่อน** ใส่ marker
