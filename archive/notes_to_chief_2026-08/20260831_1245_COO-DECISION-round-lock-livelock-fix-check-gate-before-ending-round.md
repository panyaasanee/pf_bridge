# COO-DECISION -- รับ (ก)+(ข): ล็อกถูกถือ ต้องเช็ค gate ก่อนจบรอบ, chief เป็นตัวกันสำรอง

**ตัดสินว่า:** แก้กฎ "ล็อกถูกถือ -> จบรอบทันที" เป็น "ล็อกถูกถือ -> เช็ค gate ของ PR ที่ถือล็อกอยู่ก่อน ถ้าแดง
และแก้ได้แบบไม่แตะ production/test/allowlist logic (เช่น reword, ชื่อไฟล์ผิด แบบที่ LANE-B เพิ่งทำกับ #363)
ให้แก้แล้ว push เข้า branch เดิมทันทีในรอบนั้น ถ้าแดงจากเหตุที่ใหญ่กว่านั้นให้เขียนใบแจ้ง แล้วค่อยจบรอบ" (ข้อ ก)
เพิ่ม chief ตรวจ gate สถานะของทุก [LANE-x] PR ที่เปิดค้างเป็นส่วนหนึ่งของ mailbox triage ทุกรอบ เป็นตัวกันสำรอง
ชั้นสอง (ข้อ ข) ไม่รับข้อ (ค) ปล่อยตามเดิม

**เพราะ:** livelock ที่เกิดจริง (PR #363 แดง 3.5+ ชม.) มาจากกฎเองตีความว่า "ล็อกถูกถือ" = สัญญาณให้จบรอบ
โดยไม่แยกว่า gate เขียวหรือแดง ทำให้ไม่มีสายไหนกล้าแก้ของอีกสายที่ถือล็อกอยู่ ทั้งที่การแก้ครั้งนี้พิสูจน์แล้วว่า
ทำได้ปลอดภัย (reword บรรทัดเดียว เทสผ่าน 4808/4808) ข้อ (ข) มัดสองชั้นไว้ -- เผื่อสายที่ถือล็อกไม่ทันสังเกตเอง
chief เห็นภาพรวมทุกสายอยู่แล้วในรอบ mailbox triage จึงเป็นจุดตรวจซ้ำที่ไม่เพิ่มงานใหม่มาก

**ใครทำอะไรต่อ:** chief บันทึกกฎใหม่นี้ในเอกสารกระบวนการที่คุมเรื่อง round-lock (จุดเดียวกับที่บันทึก
"claim-before-work" ตาม `COO-DECISION 20260831_0044`) ทุกสาย (A/B/GM) ใช้กฎนี้ตั้งแต่รอบถัดไป
