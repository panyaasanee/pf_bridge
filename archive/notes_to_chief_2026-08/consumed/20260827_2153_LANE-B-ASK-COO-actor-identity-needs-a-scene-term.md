## สิ่งที่พบ (วัดจริง ไม่ใช่ทฤษฎี -- โค้ด+เทสอยู่ใน PR แนบมาพร้อมจดหมายนี้)

`FieldMob.actor_identity = 0x2000 + placement_index + 1` (`field_mobs.py`) ไม่มีพจน์ scene เลย --
`placement_index` เป็นเลขที่แต่ละฉากออกให้เองอิสระจากไฟล์ `.npc` ของฉากนั้น ไม่มีการประสานงานข้ามฉาก
เลย ทำให้สองฉากต่างกันชนกันได้เสมอโดยบังเอิญ รอบนี้เขียนฟังก์ชัน pure
`field_mobs.cross_scene_identity_collisions()` วัดทุกคู่จากตารางที่ mine ไว้จริงทั้งสามฉาก (bg0001
Port Royal / Bg0002 Prison Exile / Bg0015 Hell Volcanic Island) ได้:

```
bg0001 x Bg0002: 4 คู่ชน (placement 58, 59, 60, 95)
bg0001 x Bg0015: 3 คู่ชน (placement 30, 59, 63)
Bg0002 x Bg0015: 3 คู่ชน (placement 59, 61, 78)
รวม 10 คู่ (24 มอนต่างกัน ชนกันเหลือ 10 wire identity)
```

ตัวอย่างที่ชัดที่สุด: placement 59 ชนกัน**ทั้งสามฉาก**พร้อมกัน -- bg0001 ได้ Toxic Vine, Bg0002 ได้
Fighting Fish soldier, Bg0015 ได้ Tornado Eagle มอนสามตัวคนละชื่อคนละสถิติ คำนวณ `actor_identity`
ออกมาเป็น `0x203C` เหมือนกันหมด

## ทำไมถามตอนนี้ ทั้งที่ยังไม่เร่งด่วนวันนี้

ทางเลือกที่แก้ปัญหานี้บางแบบ (ดูข้อ 3) จะย้าย wire identity ของมอนหลายสิบตัวถ้าเลือกผิดตอนนี้ ทั้งที่
เพิ่งมีฉากเดียวขึ้น production (bg0001) -- ยิ่ง Bg0002 ต่อสายจริงเมื่อไหร่ (`CORE-REQUEST-021`) ยิ่งมี
pin/เทส/console line ผูกกับเลขที่คำนวณจากสูตรปัจจุบันมากขึ้นทุกรอบ เคาะตอนมีแค่ฉากเดียวหรือสองฉาก
ถูกกว่าเคาะตอนมีสามฉากขึ้นจอพร้อมกันแล้ว

## ทางเลือก (สำหรับ COO เคาะ -- กระทบ `world_population.py`/เขต chief-สาย A อย่างน้อยหนึ่งจุดเสมอ
ไม่ใช่เขตเขียนของสาย B ล้วน ๆ จึงไม่ตัดสินใจแทน)

1. **เติมพจน์ scene เข้าสูตร wire โดยตรง** (เช่น `0x2000 + scene_ordinal * 0x1000 +
   placement_index + 1`) -- แก้ปัญหาตรงจุดที่สุด แต่เปลี่ยนค่า `actor_identity` ของ **bg0001 เองด้วย**
   ถ้า `scene_ordinal` ของ bg0001 ไม่ใช่ 0 พอดี ทำให้ pin/เทส/console line ที่ผูกกับเลขเดิมของ 13
   มอน bg0001 แดงทั้งชุด (ประสบการณ์ตรงจากรอบที่แก้ `full_roster_override` เคยเจอ 12 pin แดงมาแล้ว
   ครั้งหนึ่ง) -- แพงสุด เสี่ยงสุด ไม่แนะนำ เว้นแต่ COO ต้องการเลขที่ "ถูกต้องตามหลักการ" มากกว่าความ
   เข้ากันได้
2. **คงสูตร bg0001 (scene_ordinal=0) ไว้เหมือนเดิมเป๊ะ ให้พจน์ offset ใช้เฉพาะฉากที่ยังไม่ live** --
   ไม่กระทบ pin เดิมของ bg0001 สักตัว แต่ทุกฉากใหม่ (Bg0002, Bg0015, ...) ต้องตกลง offset ที่ไม่ชนกัน
   เองไปเรื่อย ๆ (ต้องมีตารางกลางกันชน ไม่ใช่แค่สูตรคูณลอย ๆ เพราะพจน์ที่พอมี เช่น
   `0x1000`, ยังไม่พอกันชนกับ `placement_index` ที่มีค่าถึงหลักพัน ต้องคำนวณเผื่อช่วงจริงก่อนเคาะเลข)
3. **ไม่แตะสูตร wire เลย -- ผูก key ที่ชั้นเก็บสถานะแทน** เช่น `DeathRegister`/census override ใช้
   `(scene, actor_identity)` เป็น composite key แทนที่จะเป็น `actor_identity` เดี่ยว ๆ -- ไม่กระทบ
   ไบต์บนสายเลยสักบิต ไม่มี pin ไหนแดง แต่ต้องแก้ทุกจุดที่เก็บ state ข้าม scene (ตอนนี้รู้จุดเดียวคือ
   `DeathRegister`; อาจมีจุดอื่นที่ยังไม่เจอ เพราะ M2 ยังไม่เคยมีจริง ไม่เคยมีใครลองยิงข้าม scene ด้วย
   state เดียวกัน)

## ตัดสินใจเองไปก่อน (ตามกติกา "ตัดสินด้วยคำตอบที่ดีที่สุดแล้วทำต่อ")

รอบนี้ **ไม่เลือกให้เอง** และ **ไม่แก้ทั้งสามทางเลือก** เพราะทุกทางเลือกกระทบ `world_population.py`
(เขตเขียนของ chief/สาย A) อย่างน้อยหนึ่งจุด ไม่ใช่กรณี "ตัดสินใจแทนได้เอง" ตามกติกาเลน (ต่างจากตอน

(`cross_scene_identity_collisions`/`describe_cross_scene_identity_collisions`) ให้พร้อมใช้ทันทีที่
COO เคาะ -- ไม่ว่าจะเลือกทางไหน เครื่องมือนี้ใช้พิสูจน์ผลลัพธ์หลังแก้ได้ทันที (เรียกซ้ำแล้วต้องได้ 0
