# CORE-REQUEST-GM-039: `AttributeError` ในเน็ตของ consume ที่ `runtime.py` — จุดเดียว

**ค้นแล้ว: ไม่เจอ** — `external/00_SEARCH_HERE_FIRST.md` และ `gamedata/00_SEARCH_HERE_FIRST.md`
ค้นแล้วทั้งสองใบ ใบนี้ไม่พึ่งข้อมูล client เลย

## สิ่งที่สายนี้ปิดเองไปแล้ว และสิ่งที่ปิดไม่ได้

รอบนี้สายนี้ทำให้ `ConsumeResult` ที่เสียฟิลด์โยน `ConsumeResultMisuse(AttributeError, TypeError)`
⇒ ตกในเน็ต `except (ValueError, OSError, TypeError)` ที่คุณมีอยู่แล้ว **ไม่ต้องแก้ไฟล์ของคุณ**

pf-adversary ชี้ (D7) ว่านั่นคือการ **หรี่รูให้แคบลงเหลือคลาสเดียว ไม่ใช่ปิดรู** และถูก:
`AttributeError` ตัวอื่นที่เกิดใน `try` ก้อนเดียวกัน — จาก `is_gm_account`, จาก loader ของ override,
หรือจากบรรทัดที่เขียนพรุ่งนี้ — **ยังคลาย game listener thread ทั้งตัวเหมือนเดิม**

## สิ่งที่ขอ (จุดเดียว)

`runtime.py` บล็อก consume ของ login (บรรทัดที่ขึ้นต้นด้วย `override_result = consume_login_scene_override(`)
ตัว `except (ValueError, OSError, TypeError) as error:` ⇒ ขอเพิ่ม `AttributeError`

| หัวข้อ | รายละเอียด |
|---|---|
| โมดูล | `src/pirateforce_foundation/runtime.py` เท่านั้น |
| ฟังก์ชันที่ต้องเรียก | ไม่มี ไม่ต้อง import อะไรจากสาย GM เพิ่ม |
| ตรงไหนของ runtime | เน็ตของบล็อก consume ตอน **login** (จุดเดียว) — **ไม่ใช่** dispatch vital id ใด และ **ไม่ใช่** เน็ตอื่นในไฟล์ |
| เทสที่พิสูจน์ | สายนี้ร่างให้แล้วในเขตตัวเอง (ดูล่าง) — คุณเอาไปวางหรือให้สายนี้เพิ่มในรอบถัดไปก็ได้ |

**เทสที่พิสูจน์ (ร่าง):** ใน `tests/test_gm_login_scene_consume_cause_wiring_in_runtime.py`
มีเทสที่ patch `consume_login_scene_override` ให้คืน stub คลาสแปลกปลอมที่ไม่มี `cause` อยู่แล้ว
(`test_a_result_that_lost_its_cause_raises_out_of_dispatch`) วันนี้มันพิน `assertRaises(AttributeError)`
= พินว่า **ทางหนียังเปิดอยู่** ถ้าใบนี้ลง เทสนั้นกลับด้าน: `dispatch` ต้องคืนปกติ + แถวเหตุการณ์
`gm_login_scene_override_lookup_failed_AttributeError` + ตัวละครยืนที่แถวของตัวเอง
(มิวแทนต์ที่ต้องฆ่าได้: ถอน `AttributeError` ออกจากเน็ต → แดง)

## ราคาที่ต้องชั่ง และสายนี้ไม่ปิดบัง

เน็ตที่กว้างขึ้น **กลืนบั๊กจริงได้**: พิมพ์ชื่อฟิลด์ผิดในบล็อกนั้นจะกลายเป็น "override หาย + หนึ่งแถว
เหตุการณ์" แทนที่จะเป็นเทรซแบ็กบน stderr — ซึ่ง pf-adversary วัดแล้วว่า **เทรซแบ็กมีเนื้อมากกว่า**
(ไฟล์ บรรทัด ชื่อฟิลด์) กว่าที่สายนี้เคยเขียนไว้ในรอบก่อน

สองข้อที่ทำให้สายนี้ยังคิดว่าคุ้ม:
1. ราคาของการปล่อยไว้ไม่ใช่ "ข้อความหาย" แต่คือ **พอร์ตเกมตายถาวรใต้โปรเซสที่ supervisor เห็นว่าแข็งแรง**
   — ผู้เทสเสียทั้งเซสชัน ไม่ใช่เสียบรรทัดเดียว
2. บั๊กแบบพิมพ์ชื่อผิดถูกจับที่ CI ก่อนถึง production อยู่แล้ว: pf-adversary วัดจริงรอบนี้ —
   เปลี่ยน `override_result.cause` เป็น `override_result.casue` ⇒ **แดง 11 เทสใน 5 ไฟล์**

## ทางเลือกถ้าคุณไม่เอาข้อเสนอหลัก (สายนี้ไม่แนะนำ แต่เขียนไว้ให้ครบ)

- (ก) `except Exception` ที่จุดนั้น — **สายนี้คัดค้าน** กว้างเกินและกลืน `KeyboardInterrupt` ไม่ได้ก็จริง
  แต่กลืนทุกอย่างอื่นรวมของที่ควรดัง
- (ข) ไม่ทำอะไร — รับความจริงว่ารูยังเปิด ถ้าเลือกข้อนี้ **ขอให้ตอบว่าเลือก** เพื่อสายนี้จะเขียนไว้ใน
  `docs/GM_LANE.md` ว่าเป็นการตัดสินใจ ไม่ใช่เรื่องที่ลืม (วันนี้เขียนไว้แล้วว่า "ยังไม่ปิด รอ GM-039")
- (ค) จับที่ชั้น listener แทน (`current/pf_login_game_server_v141.py` ครอบ `state.dispatch` ด้วย
  `except Exception` ต่อเฟรม) — ใหญ่กว่าและเป็นไฟล์ v141 ไม่ใช่ `runtime.py` สายนี้ไม่ขอในใบนี้
