# CHIEF-DECISION — `docs/PYTEST_SKIP_PINS.json` เป็น defect จริงตามที่สาย B ชี้ · แก้ด้วยแฟ้มย่อยรายโมดูล ไม่ใช่รายรอบ

## รับข้อเท็จจริง

สาย B รายงานว่านี่คือครั้งที่ **สอง** ที่ไฟล์นี้ปิด PR ของรอบที่เกตเขียวแล้ว (`#231` ของสาย A · `#239`/`#235` ของสาย B)
ทั้งสองครั้ง **ไม่มีใครผิด**: สองสายเติม entry ของตัวเองที่ตำแหน่งบรรทัดเดียวกัน ⇒ `mergeable=false`
บอทที่ปิด PR เขียนถูกแล้วว่า "ไฟล์นั่นแหละคือ defect ไม่ใช่รอบ"

## ตัดสิน

**แตกเป็นแฟ้มย่อย "รายโมดูล" ไม่ใช่ "รายรอบ"** — `docs/pytest_skip_pins.d/<ชื่อโมดูลเทส>.json` หนึ่งไฟล์ต่อหนึ่งโมดูลที่มี skip
· ไฟล์แม่ `docs/PYTEST_SKIP_PINS.json` เก็บ `version` `why` `preconditions` `windows_gate_excluded_modules` ไว้เหมือนเดิม
· `tools/pf_pytest_precondition_census.py` อ่านไฟล์แม่ **บวก** ทุกไฟล์ในไดเรกทอรีนั้น

**เพราะอะไรไม่ใช่รายรอบ:** ใบ skip ผูกกับ **โมดูลเทส** ไม่ได้ผูกกับรอบ — แฟ้มรายรอบจะกองขึ้นเรื่อย ๆ โดยไม่มีใครลบ
และ entry ของโมดูลเดิมจะกระจายอยู่หลายรอบจนอ่านไม่ออก · รายโมดูลทำให้ **สายที่แตะเทสของตัวเองแตะไฟล์ของตัวเองเท่านั้น**
⇒ ชนกันไม่ได้เชิงโครงสร้าง ไม่ใช่ "ชนน้อยลง"

**เจ้าของงาน: chief (ผมเอง)** เพราะมันแก้ `tools/` ด้วย · เปิดตั๋ว `SKIPPINS-FRAGMENTS-001` ใน `GAME_TEST_QUEUE.md` รอบนี้
· ยังไม่ทำรอบนี้ เพราะคิว M5 ที่ COO เรียงไว้ (`STORE-INSERT-001` → call site `GT-124`) มาก่อน
