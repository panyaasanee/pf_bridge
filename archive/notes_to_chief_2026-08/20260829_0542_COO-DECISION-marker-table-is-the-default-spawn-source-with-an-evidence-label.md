# COO-DECISION — รับทางที่ 1 · ตาราง `MARKER` เป็นที่มาของจุดเกิดมาตรฐาน แต่ติดป้ายชั้นหลักฐานว่า "authored ยังไม่มีตายืนยัน"

## ตัดสินว่าอะไร

1. **รับ** ทางที่ 1 เป็นกฎถาวรของโปรเจกต์: ฉากที่ `SCENE_NAME[n].n_MARKER != 0` ⇒ ใช้ `MARKER[n_MARKER]` เป็นจุดเกิด **โดยไม่ต้องขอคำตัดสินรายฉาก** · ฉากที่ `n_MARKER == 0` ⇒ กฎเดิมทุกประการ (หลักฐาน client / คำเคาะเจ้าของ / ปฏิเสธ) — **ห้ามประดิษฐ์พิกัดแทน**
2. **บังคับทางอ้อมเสมอ**: อ่านผ่าน `SCENE_NAME[n].n_MARKER` เท่านั้น · **ห้ามอ่าน `MARKER` ด้วยเลขฉากตรง ๆ** (390 แถว มี 19 แถวที่ `n_ID == n_SCENE` · ฉาก 130 ใช้ marker 1000) — ข้อนี้เป็นข้อห้าม ไม่ใช่คำแนะนำ
3. **ชั้นหลักฐาน = `authored`** ไม่ใช่ `client-observed` · จุดเกิดที่มาจาก marker **ห้ามเลื่อนขั้นเป็น confirmed** จนกว่าจะมีรอบ attended ที่ยืนไคลเอนต์บนจุดนั้นได้จริง (กฎเดิม `COO-DECISION 20260828_2250 who-promotes-a-scene-to-confirmed` ยังบังคับ) · ทะเบียนต้องเขียน provenance ของทุกแถวว่ามาจาก marker ตัวไหน
4. **ไม่ต้องย้อนข้อ ④** · แถวฉาก 14 **คงไว้** — คำว่า "`Bg0015` ยัง dormant" ในกติกาข้อ 11 ผมอ่านว่า **ห้ามส่งโรสเตอร์ออกสาย** ไม่ได้ครอบ "ห้ามฉากมีที่อยู่" · การให้ที่อยู่กับฉากไม่ใช่การ wire
5. ประตูล็อกอินฉาก 14 **ยังปิด** (`login_entry_allowed: false` ที่สาย A ปิดเองรอบนี้ = ถูก และ chief เคาะซ้ำแล้วในใบ 0520) · การรับกฎนี้ **ไม่ใช่** การอนุญาตให้เปิดประตู

## เพราะอะไร

- ทางที่ 2 กินตัวเอง: ต้องเข้าฉากให้ได้ก่อนถึงจะพิสูจน์จุดเข้าได้ ⇒ `GT-134` ค้างทั้งที่ตัวปิดอยู่ในมือ
- ทางที่ 3 เอาผู้เล่นไปยืนทับจุดเกิดมอน และทิ้งของที่ดีกว่าซึ่งมีอยู่จริงในไฟล์
- 13/13 ฉากที่มี marker resolve กลับมาที่ฉากตัวเอง ไม่มีเบี้ยว · ตรวจซ้ำได้ด้วยคำสั่งเดียว ⇒ ปิดการเถียงรายฉากซึ่งเป็นต้นทุนจริงที่เราจ่ายมาแล้วสองรอบ
- ผมรับ **การถอนข้ออ้าง "ยืนยันหนึ่งข้อ"** ของคุณ (ฉาก 2 คือตารางตรงกับตัวเอง) · ข้อที่ยังยืนคือ "ไคลเอนต์รับพิกัด marker แล้วสองครั้ง" ซึ่งพอสำหรับชั้น authored แต่ **ไม่พอ** สำหรับ confirmed — จึงเป็นที่มาของข้อ 3 ข้างบน
- `MARKER[1]` ห่างจากจุดเกิด V135 ราว 2,200 หน่วย ⇒ "marker คือที่ที่เกมวางคุณเสมอ" ยังไม่จริง กฎนี้จึงเป็น **ค่าตั้งต้น** ไม่ใช่ความจริง
