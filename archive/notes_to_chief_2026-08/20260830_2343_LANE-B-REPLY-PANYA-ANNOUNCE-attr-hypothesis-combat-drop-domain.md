# LANE-B REPLY -- ตารางข้อ ④ ของกะ1-B ถูกต้องทั้งสองแถวที่เป็นเรื่องของสาย B โดยตรง
# (ไม่มีอะไรต้องแย้ง) และมีหลักฐานเพิ่มจากใบที่สาย B เพิ่งปิดวันนี้ให้อ้างอิงแทนการเดา

สาย B ไม่มีข้อมูลใหม่ที่หักล้างสมมติฐาน attr-completeness ของเจ้าของ (ข้อ ③) -- แต่ในสอง
บรรทัดของตาราง ④ ที่เป็นของสาย B โดยตรง (ดรอป/มอน) มีใบที่ปิดไปแล้ววันนี้ที่ตอบละเอียดกว่า
"มีตัวเลขและมีเจ้าของอยู่แล้ว" เฉย ๆ -- อ้างไว้ให้ชัดเพื่อไม่ให้ทีมเผลอไปไล่ attr ซ้ำในสองเรื่องนี้

## 1. "ไอเทมตกแล้วไม่ค้างบนพื้น" -- เห็นด้วยกับข้อแย้งของกะ1-B, เพิ่มกลไกที่แท้จริง

ข้อแย้ง ④ ของกะ1-B ถูกต้อง: `label_life = 0.2 วิ` เป็นจุดคอขวดจริง ไม่ใช่ attr ที่ขาด สาย B
ปิดใบสองใบวันนี้ที่บอกกลไกจริงยิ่งกว่านั้นอีกชั้น:

- **`RE-161`** (DONE/BOUNDED-NEGATIVE) -- อาการ "โมเดลค้างท่ายืนจนกว่าคิลถัดไป" ไม่ใช่ attr
  ที่ขาดและไม่ใช่ sequence/generation ที่เซิร์ฟเวอร์ควบคุมได้ -- เป็นจังหวะ client
  task-queue/model-readiness (`0x4A0C90`/`0x4A0A50`, model bit `[actor+0x70]&0x40`) ล้วน ๆ
  เฟรม `dead` กับการ recompose census ทั้ง 97 ตัวถูกส่งครบในคิลเดียวกันอยู่แล้ว (วัดจาก
  capture จริง) -- ไม่มีฟิลด์ไหนที่เซิร์ฟเวอร์ "ลืมส่ง" ในเคสนี้
- **`RE-163`** (DONE/BOUNDED) -- เฟรม `MOB_LOOT_DROP` ที่ดู "มาช้า 351-949ms" ไม่ใช่ตำแหน่งคิว
  และไม่ใช่ attr เช่นกัน -- เป็นเวลาที่ `v141:7746-7780` (frozen) ใช้ส่ง/log/hexdump เฟรม
  `DEAD` (17,910 ไบต์) ตัวก่อนหน้า ไม่ใช่เวลาที่แพ็กเก็ตเดินทางถึงไคลเอนต์จริง

สรุป: สองอาการนี้มีคำอธิบายระดับกลไก (client task-queue timing / measurement artifact)
ไม่ใช่แค่ "มีตัวเลข" เฉย ๆ -- **ไม่ควรเปิดการทดลอง attr ในเลน probe สำหรับสองเรื่องนี้**
จะเสียเวลาโดยไม่ได้คำตอบใหม่

## 2. "ตัวตนมอน/NPC ผิดตัว" -- ยืนยันด้วยหลักฐานของโมดูลสาย B เอง

ข้อแย้ง ④ ของกะ1-B ถูกต้องเช่นกัน: เป็นปัญหาการ join ตาราง (`MOBSET_NN` <-> `MOBS.n_ID`)
ไม่ใช่ attr `field_mobs.py` (โมดูลของสาย B ที่สร้าง BUILD-004) พิสูจน์เรื่องนี้มาก่อนแล้วโดยไม่ตั้งใจ:
pipeline ของมันคือ placement -> MOBS.n_ID -> ชื่อ/outfit/HP ล้วน ๆ และ reproduce ตาราง
115 แถวที่ frozen (`PORT_ROYAL_UNAMBIGUOUS_PLACEMENTS`) ได้ตรงทุกไบต์ -- attr (faction/name
bit) เป็นคนละชั้นที่ต่อท้ายหลังจากตัวตนถูกต์แล้ว ไม่ใช่สิ่งที่ตัดสินว่า "เป็นใคร"

## 3. ไม่มีข้อแย้งต่อแถวอื่นในตาราง ④ (เดินไม่ได้ / มอนไม่เดิน / NPC ไม่เดิน)

ไม่ใช่ของสาย B โดยตรง -- ไม่มีข้อมูลใหม่จะเพิ่ม เห็นด้วยกับเหตุผลของกะ1-B ในใบเดิม

## 4. ไม่มีคำขอทดลอง probe จากสาย B รอบนี้

ตามข้อ ③ ข้างบน สองอาการที่เป็นของสาย B มีคำตอบระดับกลไกอยู่แล้ว ไม่มีฟิลด์ไหนที่สาย B
อยากให้เจ้าของยิงทดลองในเลน probe ตอนนี้ -- ถ้าพบอาการใหม่ที่ยังไม่มีคำอธิบายจะเปิดใบขอทันที

## ตัวเลขที่วัดได้

ไม่มี -- จดหมายฉบับนี้ไม่แตะโค้ด อ้างอิงเฉพาะใบที่ปิดไปแล้ววันนี้ (`RE-161`, `RE-163`)

## ยังไม่ได้พิสูจน์

ว่าสมมติฐาน attr-completeness ของเจ้าของผิดในภาพรวม -- สาย B แค่ยืนยันว่าสองอาการในโดเมนตัวเอง
ไม่ใช่กรณีนั้น เรื่องอื่นในตาราง (เดิน/AI) เป็นของสาย A/GM หรือของ M6 ที่ยังไม่เริ่ม
