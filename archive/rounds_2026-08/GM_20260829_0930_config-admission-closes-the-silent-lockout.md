### `login_scene_override._load_scene_id_map` — จุดที่ปฏิเสธ

หลังด่าน `is_known_scene_id` เดิม เพิ่มด่าน `login_entry_is_pinned` · ผิด ⇒ พิมพ์โทเคนคอนโซลลง stderr

```
GM_LOGIN_SCENE_CONFIG_REFUSED path=<ไฟล์> key=<คีย์> account='<บัญชี>' scene_id=17
    reason=no_pinned_login_entry stageable=(1, 2, 278, 997)
```

**ทำไมล็อกอินไม่ตายเพราะ raise นี้** (วัดผ่าน dispatcher จริง ไม่ใช่อ่านโค้ดเอา):
`consume_login_scene_override` จับ `(OSError, ValueError)` เป็นผล `CONSUME_FAILED` อยู่แล้ว ⇒
ไม่มี override ⇒ ล็อกอินลงที่แถวของตัวเอง (ฉาก 1) · **fail-closed ทั้งแฟ้ม ไม่ใช่ข้ามทีละบรรทัด**
โดยตั้งใจ: แฟ้มที่ข้ามบรรทัดผิดแล้วส่งบัญชีที่เหลือไปตามเดิม คือความเงียบแบบเดียวกับที่รอบนี้กำลังปิด
เลื่อนลงไปหนึ่งบรรทัด · ราคาที่ต้องพูด: บรรทัดเดียวผิด = override ทุกบัญชีในแฟ้มนั้นหยุดทำงานจนกว่าจะแก้
**ไม่มีใครถูกล็อกออกจากเกมด้วยเส้นทางนี้** (เส้นทางที่ยังล็อกได้อยู่คือ D1 ข้างล่าง — คนละเส้น)

### สิ่งที่ adversary โจมตีแล้ว **ไม่แตก**

ไม่มีเหตุปฏิเสธของ `resolve_entry` ข้อไหนขึ้นกับ **แถวของตัวละคร** — ทั้งสี่ข้อขึ้นกับปลายทางล้วน
(`_within_ground` ย้ายตำแหน่ง ไม่เคยปฏิเสธ) ⇒ เพรดิเคตแบบ destination-only เป็นรูปที่ถูกสำหรับ
`resolve_entry` วันนี้ · หา exception ที่หลุดออกนอก `(OSError, ValueError)` ไม่ได้ · ไม่มี import cycle
· `.gitignore` ไม่กลืนไฟล์ใหม่

### ยังไม่ถูกทดสอบ (adversary ประกาศเอง)

"ค่าที่รับเข้าได้ทำให้ล็อกอินพังที่ขั้นถัดไปไม่ได้" — **ยังไม่พิสูจน์** เขาหยุดก่อนขับฉาก 278/997
ผ่าน dispatcher จนจบ ⇒ ถือว่ายังไม่รู้ ไม่ใช่รู้แล้วว่าปลอดภัย

## nonclaim

1. **GM ไม่ใช่หลักฐานว่าฟีเจอร์ทำงาน** — รอบนี้ไม่ได้พิสูจน์ว่าผู้เทสไปถึงฉากไหนได้ พิสูจน์ว่าเซิร์ฟเวอร์
   ไม่รับคำสั่งที่จะพาผู้เทสไปยังที่ที่ล็อกอินจะปฏิเสธ · การไปถึงฉากจริงเป็นของ `GT-141` ตัดสินที่จอ
2. **ยังไม่เคยวัดกับ client จริงเลยสักครั้ง** ทุกบรรทัดในรอบนี้วัดผ่าน dispatcher ในชุดเทส

   ทางถอยเขียนไว้ในหัวโมดูลแล้ว
4. เงื่อนไข spawn ที่เพิ่มเข้าไป **ไม่ได้แก้ของที่พังอยู่วันนี้** ไม่มีฉากไหนในทะเบียนที่ไม่มี spawn
