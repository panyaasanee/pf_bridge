# หน้าต่างสกิลเปิดไม่ได้ (GT-058) — ตั้งสมมติฐานต้นเหตุ (ยังไม่พิสูจน์) และเปิดใบ RE-061 เพื่อทดสอบ

## สรุปก่อน (สำหรับคุณ Panya)

หน้าต่างสกิล (กด K) ที่เปิดไม่ได้ **น่าจะไม่ได้พังที่ตัวเกม** — ไคลเอนต์มีข้อมูลสกิลครบ (2,165 แถว + ไอคอน)
**สมมติฐานต้นเหตุ (ยังไม่พิสูจน์):** เซิร์ฟเวอร์ของเรายังไม่เคยส่ง "สถานะสกิล" ให้ไคลเอนต์ หน้าต่างเลยอาจไม่มีอะไรจะเปิด

🔴 **ย้ำว่านี่เป็นสมมติฐาน ไม่ใช่ข้อสรุป** — ยังไม่มีใครเห็นโค้ดที่ตัดสินใจไม่เปิดหน้าต่าง · ใบ RE-061 คือใบที่จะ **ทดสอบ** ว่าจริงไหม
**ยังไม่ควรสั่งเขียนโค้ดส่งสถานะสกิลจนกว่า RE-061 จะยืนยัน** (ไม่งั้นเสี่ยงเขียน sender ที่ไม่ปลดหน้าต่างจริง)

ถ้าสมมติฐานถูก งานแก้เป็นฝั่งโค้ด (ของ chief) แต่ **เขียนโค้ดตอนนี้ยังไม่ได้** เพราะยังไม่รู้ "รูปไบต์" ที่ถูกต้อง
ของข้อความสถานะสกิล และรูปนั้น **หาได้จากอิมเมจ client บนเครื่องสะพานเท่านั้น** (บนคลาวด์หาไม่ได้ — พิสูจน์แล้วรอบนี้)

**สิ่งที่ต้องทำต่อ (ขั้นเดียว):** ให้คนหน้าเครื่องสะพานหยิบใบ **RE-061** ใน `CLIENT_RE_QUEUE.md` ไปรัน
(เป็นงาน static ไม่ต้องเปิดเกม ไม่ต้องมีคนเฝ้า) — ใบนี้จะตอบว่าสมมติฐานถูกไหม และถ้าถูก chief ค่อยเขียนโค้ดส่งสถานะสกิล แล้วเทสหน้าต่างจริง

## รายละเอียด (ฝั่งเทคนิค)

**สมมติฐานต้นเหตุ (chain · ยังไม่พิสูจน์):**
1. GT-058: กด K → ไม่มี request วิ่งออกเลย · `C`(CHARACTER)/`Quest`/`Reward` เปิดได้ ⇒ อาการอยู่ฝั่ง client ล้วน
2. ไคลเอนต์มีข้อมูลสกิลครบ ⇒ ฟีเจอร์ไม่ได้ถูกปิด (CORRECTION 1147)
3. เซิร์ฟเวอร์เราส่ง skill vital ไปแล้ว 2 ตัว (`0x673C` ขาออก · `0x36AA` ขาเข้า decode-only) แต่ **ไม่เคยส่ง `CSkillModule`/`CSkillAttr` ซึ่งเป็น "สถานะ"** (GT-052: W/R span ว่าง)

**ทำไมเขียนโค้ดบนคลาวด์ยังไม่ได้ (ยืนยันด้วย pf-static-re):**
- `CSkillModule`/`CSkillAttr` **ไม่ใช่ wire vital** ที่มี opcode พิสูจน์แล้ว (id `0x1F7B`/`0x1661` เป็นแค่ name-hash candidate)
- แถว serializer ในชุดส่งมอบ = **EMPTY stub** (`CSkillModule` serializer แค่ตั้ง AL=1 แล้ว ret) ⇒ ประกอบเฟรมไม่ได้
- capture corpus = **NOT_OBSERVED 0 เฟรม** ⇒ ไม่มีเฟรมจริงให้เทียบ
- แต่มีเบาะแส: `CSkillAttr` แขวนใต้ `DBAttribute` เหมือน `ActorAttr` ⇒ สถานะสกิลอาจเดินทางใน ActorAttr collection ไม่ใช่ vital เดี่ยว — RE-061 จะชี้ขาด

**RE-061 ขออะไร (สรุป):** ถอด serializer ของ `CSkillModule` (vtable `0x00F48D88`) + หาตัวพาของ `CSkillAttr`
(vtable `0x00F48B78`, chains DBAttribute), และ **ตอบจากอิมเมจว่าไคลเอนต์มี inbound decoder ของสองคลาสนี้ไหม + โค้ดเปิดหน้าต่าง Skill ขึ้นกับ state นั้นไหม** — ท่าเดียวกับ GT-050
🔴 **สำคัญ:** capture corpus ที่มีเป็น client↔emulator ของเราเอง ไม่ใช่ traffic ของ server ต้นฉบับ (SCENE-013) ⇒ **ใช้ corpus พิสูจน์ว่า server ต้นฉบับส่งอะไรไม่ได้** — หลักฐานตัวจริงคือ decoder/gate ในอิมเมจ · ผลมีสามทาง: บวก (ส่ง state แล้วปลดได้ → เขียน sender ต่อ) · ลบ (ไม่มี decoder/gate → ตัวขวางมีสาเหตุอื่น) · **UNANSWERABLE (ตอบไม่ขาด → ส่งคุณ Panya ตัดสิน ห้ามทิ้งสมมติฐาน)**
