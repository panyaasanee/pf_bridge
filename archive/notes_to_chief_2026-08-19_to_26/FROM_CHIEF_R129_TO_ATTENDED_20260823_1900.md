## สิ่งที่ผมเพิ่งพบจากฝั่ง cloud

**`pf_bridge\external\` ไม่เคยเข้า git เลย** — `.gitignore` ของ repo นี้เป็น deny-all + allowlist
และไม่มีใคร whitelist โฟลเดอร์นี้ ⇒ ชุดส่งมอบ RE 8 ตาราง 17,626 แถวอยู่บนดิสก์เครื่องคุณเท่านั้น
ตัว sync push ไม่ได้ต่อให้รันทุก 5 นาทีตลอดปี

ผลคือรายการค้างข้อ ⑤ ของคำสั่ง Panya 18:22 ("ยังไม่มีโค้ดใน src/tools/tests อ่านชุดส่งมอบเลย")
**บล็อกแน่นกว่าที่เข้าใจกัน**: ฝั่ง cloud/CI เขียนโค้ด/เทสที่อ่านตารางไม่ได้เลยเพราะมองไม่เห็นไฟล์
(คุณกับคนทำใบ static ยังเปิดอ่านจากดิสก์ได้ตามปกติ — ใบใน `CLIENT_RE_QUEUE.md` ไม่เปลี่ยนความหมาย)

## สิ่งที่ผมทำแล้วในรอบนี้ (จดหมายนี้กับ `.gitignore` ฉบับใหม่อยู่ใน commit เดียวกัน — ถ้าคุณอ่านใบนี้ได้ แปลว่า merge แล้ว · แต่ให้ยืนยันตามข้อ 1 ก่อนเสมอ)

แก้ `.gitignore` เปิดช่องแบบ **รายชื่อไฟล์เป๊ะ ๆ** (แพตเทิร์นเดียวกับ `factpack_L1`): ดัชนี + ตาราง 5 ใบที่รู้ชื่อ

```
external/00_SEARCH_HERE_FIRST.md
external/PF_PROTOCOL_REGISTRY.tsv
external/PF_SERIALIZER_FIELDS.tsv
external/PF_RUNTIME_CLASSMAP.tsv
external/PF_INPUT_INVENTORY.tsv
external/PF_FIELD_VALIDATION.tsv
```

เหตุที่ไม่เปิดทั้งโฟลเดอร์: `.gitignore` มีบทเรียนอยู่แล้วว่า TSV บางชนิดคือ byte-extract ของ binary
(`strings_*.tsv` / `pe_*.tsv` ถูกแบน "NEVER ON A REMOTE") — เปิดทั้งโฟลเดอร์เสี่ยงกวาดของต้องห้ามขึ้น remote

## ✅ สิ่งที่ขอให้คุณทำ (ครั้งเดียวจบ ~2 นาที)

1. `git pull` ใน `pf_bridge` แล้ว**ยืนยันว่า `.gitignore` มีบล็อก `!/external/`** (เปิดดูหรือ
   `findstr external .gitignore`) — ถ้ายังไม่มี = PR รอบนี้ยังไม่เข้า อย่าเพิ่งทำขั้นถัดไป
2. **ตรวจตาเปล่า 5 ไฟล์ `.tsv`**: เป็นตาราง analytic (คอลัมน์ VA/span/sha) จริง ไม่ใช่ strings/PE dump —
   ส่วน `00_SEARCH_HERE_FIRST.md` เป็นเอกสารดัชนี ไม่ใช่ตาราง ตรวจแค่ว่าเป็นดัชนีที่ผู้ช่วยเขียนจริง ·
   ถ้าไฟล์ไหนผิดชนิด อย่า add — ตอบกลับมาบอกแทน
3. 🔴 **`git add` ทีละไฟล์ ระบุ path เต็มตามรายชื่อข้างบนเป๊ะ ๆ (6 คำสั่ง)** — ห้ามใช้ `git add external\`
   หรือ `git add -A` เป็นตัวจบงาน เหตุผล: ชื่อในรายการลอกมาจากจดหมาย 1718 ยังไม่เคยเทียบกับดิสก์จริง —
   add รายไฟล์จะ**ฟ้องเสียงดัง**ทันทีถ้าชื่อบนดิสก์สะกดต่าง (รวมถึงต่างแค่ตัวพิมพ์เล็ก-ใหญ่) ·
   ถ้าคำสั่งไหน error ว่าไม่มีไฟล์/ถูก ignore ⇒ จดชื่อจริงบนดิสก์มาตอบ อย่าแก้ `.gitignore` เอง ·
   เสร็จแล้วปล่อย commit/push ไปตามท่อ sync ปกติ
4. **ตอบกลับหนึ่งใบ** (`notes_to_chief/`): ① add สำเร็จกี่ไฟล์ คำสั่งไหน error บ้าง ② **ชื่อไฟล์ของอีก 3 ตารางที่เหลือ
   + จำนวนแถวจริงนับจากหน้าเครื่อง** (จดหมาย 1718 นับรวมเป็น "บรรทัด" 17,626 — ถ้า TSV มี header เลขแถวจริงจะต่างเล็กน้อย ·
   5 ใบที่รู้ = 16,803 ⇒ ที่เหลือ ~823) — ผมจะ whitelist เพิ่มเป็นรายชื่อในรอบถัดไป
   ③ ถ้าในโฟลเดอร์มีไฟล์อื่นนอกเหนือจาก 8+ดัชนี บอกมาด้วยว่ามีอะไร (ไม่ต้อง add)
