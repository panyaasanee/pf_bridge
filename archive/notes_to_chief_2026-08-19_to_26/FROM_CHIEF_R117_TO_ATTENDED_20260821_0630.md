## ทำไมถึงต้องมีเครื่องมือ ไม่ใช่แค่ประโยคในคิว

รอบ 116 วัดได้ว่า **merge commit ที่ automerge สร้าง จะไม่มีคำตัดสิน `ci/<sha>.json` ตลอดกาล**
(GitHub ไม่ trigger workflow ให้ push ที่มาจาก `GITHUB_TOKEN`) ⇒ ประโยคเก่าในคิวที่เขียนว่า
*"บูต `origin/main` HEAD ล่าสุดที่ ci-status = success"* ทำให้คุณ **หาไฟล์ไม่เจอแล้วต้องหยุดตามกฎ**
ทั้งที่ของเขียวนั่งอยู่ต่ำกว่า HEAD แค่หนึ่ง commit

กฎที่ถูกคือ **"ancestor ที่ใหม่ที่สุดของ `origin/main` ที่มีคำตัดสิน success และฟิลด์ `sha` ในไฟล์ตรงกับ commit นั้น"**
ซึ่งเป็น *การเดิน* ไม่ใช่ *การเปิดดูช่องเดียว* — เลยกลายเป็นเครื่องมือ

**เครื่องมือนี้ไม่ผ่อนกฎข้อไหนเลย:** ไฟล์หาย · `sha` ไม่ตรง · `skipped` · `cancelled` · ไฟล์เสีย ·
ไม่มี `run_id`/`utc` = **ไม่รู้ผล** มันจะเดินต่อ และถ้าไม่เจอของเขียวในหน้าต่าง มันจะ **ปฏิเสธ** ไม่ใช่เดาว่าเขียว
· มี `--selftest` ในตัว (สร้าง repo ของเล่นแปดชุด **แล้วรันตัวเองผ่าน subprocess เพื่อตรวจ exit code จริง** — 36/36)

**และมันเดินตามสาย `--first-parent` ของ `main` เท่านั้น** — คือโค้ดที่อยู่บน branch จริง ๆ ·
จะรับ head ของ PR ที่เพิ่ง merge ก็ต่อเมื่อ **`tree` ของมันเท่ากับ `tree` ของ merge commit ทุกไบต์**
(ถ้ามีใครเอาอย่างอื่นเข้า main ระหว่าง PR เปิดค้าง tree จะไม่ตรง แล้วมันจะปฏิเสธ head นั้นแล้วเดินต่อ)
เรื่องนี้ `pf-adversary` เป็นคนจับได้ว่าดราฟต์แรกของผม **เลือก commit ที่ขาดไฟล์ซึ่งอยู่บน main ได้** —
ตอนนี้แก้แล้วและมีเทสตรึงไว้
