## 🔒 ข้อกำหนดของการ์ด — และมันต้องยืนบนหลักการที่ **คุณเขียนเอง**

`DESIGN_R107_WINDOWS_SYNC.md` ข้อ 3 ตัดสินไว้ว่า:
> *"**git เองคือ lock ข้ามเครื่อง** — `push` ที่ไม่ fast-forward **ถูกปฏิเสธฝั่งเซิร์ฟเวอร์แบบ atomic**
> นี่คือ mutual exclusion ตัวจริงตัวเดียวที่มีอยู่ในระบบนี้"*

🔴 **ให้ใช้หลักการนั้นเป๊ะ ๆ กับการ์ดนี้ — อย่าไปคิดกลไกใหม่**
**การ์ดต้องได้มาด้วยการ `push` สำเร็จ ไม่ใช่ด้วยการ "เขียนไฟล์แล้วเชื่อว่าตัวเองได้"**

### ลำดับที่ต้องเป็น (ทุกรอบ ก่อนทำงานใด ๆ ทั้งสิ้น)
1. `git pull --ff-only` ที่ `pf_bridge`
2. อ่านไฟล์ล็อก (ชื่อที่เสนอ: **`CLOUD_ROUND_LOCK.json`** — คุณตั้งชื่อเองได้ แต่ต้อง **tracked**)
   - ถ้า `HELD` และ heartbeat **ใหม่กว่าเพดาน** ⇒ 🔴 **จบรอบทันที** เขียนบรรทัดเดียวว่าข้ามเพราะรอบไหนถืออยู่
     **ห้ามทำงานใด ๆ ห้าม clone repo โค้ด ห้ามอ่านซอร์ส ห้ามคิดงานต่อ** — ยิ่งถูกยิ่งดี
3. ถ้าว่าง ⇒ เขียน `HELD` + เวลา + เลขรอบ + session id → **commit → push**
4. 🔴 **ถ้า push ถูกปฏิเสธ (non-fast-forward) ⇒ แปลว่าอีกรอบชิงไปได้ ⇒ จบรอบทันที**
   **ห้าม retry ห้าม force ห้าม rebase แล้วลองใหม่** — การแพ้คือคำตอบที่ถูก
5. push สำเร็จ ⇒ **คุณถือล็อก** ค่อยเริ่มทำงาน
6. ระหว่างรอบยาว **เคาะ heartbeat + push เป็นระยะ** (เสนอทุก ~20 นาที) เพื่อให้ takeover ปลอดภัย
7. จบรอบ ⇒ เขียน `RELEASED` → commit → push **ทุกกรณี รวมถึงกรณีรอบล้มเหลว**

### กติกา takeover (เซสชัน cloud ตายกลางคันได้ ไม่มีใครเก็บกวาดให้)
- heartbeat เก่ากว่าเพดาน (เสนอ **3 ชั่วโมง**) ⇒ ยึดล็อกได้ **แต่ต้องบันทึกว่าเป็น takeover พร้อมเลขรอบที่ทิ้งไว้**
- 🔴 **ห้ามยึดเพราะ "น่าจะตายแล้ว"** — ต้องเกินเพดานจริงเท่านั้น

### สิ่งที่ต้องแก้พ่วง
- `.gitignore` ของ `pf_bridge` เป็น **deny-all** ⇒ ต้องเติม `!` ให้ไฟล์ล็อกใหม่ ไม่งั้นมัน **ไม่ถูก track และการ์ดไร้ผลเงียบ ๆ**
  ⚠️ อย่าตั้งชื่อขึ้นต้นด้วย `LOCK_` และอย่าเป็น `.txt` — จะไปโดน `/LOCK_*.txt` ที่กันไว้
- ตัว sync ฝั่ง Windows จะ `pull` ไฟล์นี้ลงมาด้วย **ไม่เป็นไร** เป็นสถานะของฝั่ง cloud ล้วน ผู้เทสไม่ต้องสนใจ
