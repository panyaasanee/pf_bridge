# 📬 คำสั่งจาก Panya: แกะสูตรความเสียหายจาก client (static RE) — `combat/damage_and_hit_result`

- **เวลา:** 2026-08-19 ~02:2x ICT (เวลาโดยประมาณ)
- **ช่องทาง:** Panya ถามว่าทำไมแถว "ความเสียหายจริง" ถึง blocked → เซสชันหลักอธิบายว่า
  *blocked on evidence not code* (corpus ตอบไม่ได้ · hash-guarded audit ยืนยันแล้ว) → เสนอ 3 ทาง
  → **Panya สั่ง "แกะเลย" = เลือกทางที่ 2 (แกะจาก client binary ก่อน)**
- **มือเขียน:** Claude เซสชันหลัก · **สถานะ:** อนุมัติแล้ว เป็น milestone ลำดับต้น ๆ

## สิ่งที่อนุมัติ

**`DAMAGE-MODEL-001` (ชื่อชั่วคราว — chief ตั้งใหม่ได้) — static RE จาก `GameClient.local.bin` เท่านั้น**

เป้าหมาย: ตอบให้ได้ว่า **client คาดหวังอะไรจาก server เรื่องผลการโจมตี** — โครงเฟรม, ฟิลด์,
และถ้าโชคดี **สูตร/ตารางค่าที่ฝังอยู่ใน client เอง** (แบบเดียวกับที่ HP-DEATH-001 เจอว่า
"ตาย" = client derive เองจาก HP==0 ไม่ต้องมีเฟรมตาย)

**คำถามที่อยากได้คำตอบ (เรียงตามคุณค่า):**
1. **ตัวรับผลการตี** — `ChitResult`/hit-result consumer ที่ SCENE-009 เคยชี้ไว้: vtable, serializer,
   ฟิลด์ทั้งหมด + ความหมายเชิงโครงสร้าง (ใครโดน ใครตี เท่าไหร่ ชนิดอะไร คริติคอลไหม พลาดไหม)
2. **client คำนวณเองบ้างไหม** — มีสูตร/ตาราง/ค่าคงที่ในอิมเมจที่บ่งบอกว่า client ทำ prediction
   หรือ derive อะไรเองหรือไม่ (ถ้ามี = ได้ของจริงฟรี เหมือนเคส HP==0)
3. **ค่าที่ผูกกับ attribute** — ATK/DEF/หรือ field ใน BasicAttr ที่ถูกอ่านตอนแสดงผลความเสียหาย
   (เชื่อมกับงาน HP-DEATH-001/002 ที่ pin ฟิลด์ HP ไว้แล้ว)
4. **ตัวเลขบนจอ** — damage number / floating text / HUD ที่ผูกกับผลการตี = จุดที่รอบใหญ่จะเห็นด้วยตา

**เงื่อนไขบังคับ (Panya ย้ำหลักเดิม):**
- **report-only** — ห้ามแตะ `src/` ห้ามเปิด encoder ห้าม flip matrix ในรอบนี้
- **ห้ามเดาแล้วเขียนเป็นของจริง** — สิ่งที่แกะไม่ออกให้เขียนเป็น bounded unknown ตามธรรมเนียม
- แถว `combat/damage_and_hit_result` **ยังคง blocked จนกว่าจะมีคำเคาะรอบใหม่** — งานนี้มีไว้
  *ตอบว่าปลดบล็อกได้ไหมและด้วยอะไร* ไม่ใช่ปลดเอง
- ทุกตัวเลขต้องมี verifier รันซ้ำได้ + เทสบังคับ ตามมาตรฐานที่ใช้มาแล้ว 6+ รอบ

## บริบทการตัดสินใจ (Panya เข้าใจและยอมรับแล้ว)

เซสชันหลักเสนอ 3 ทาง — Panya เลือกทาง 2 **ก่อน** ทาง 1:
- **ทาง 1 ออกแบบสูตรเอง** (opt-in + client acceptance เหมือน PF-012/014/015) — เร็วสุด
  แต่ได้ "เกมของเรา" ไม่ใช่ตัวเลขของเกมจริง
- **ทาง 2 แกะจาก client ← เลือกอันนี้** — ถ้าเจอ = ได้ของจริง ตรงหลัก *"เหมือนจริงใช้จริง ทำครั้งเดียวจบ"*
- **ทาง 3 หาหลักฐานใหม่** — แทบเป็นไปไม่ได้ (server ต้นฉบับตายแล้ว ไม่มี publish)

**ถ้าแกะแล้วไม่เจอ (negative result) = ผลที่มีค่า** — ให้เขียนรายงานเชิงลบให้ชัดว่าปิดทางไหนไปแล้วบ้าง
แล้ว**กลับมาเสนอ Panya ว่าจะไปทาง 1 ไหม** พร้อมขอบเขตที่จะออกแบบเอง (อย่าเริ่มเอง)

## ทำไมจังหวะนี้เหมาะ (ข้อสังเกตจากผู้เทส ไม่ใช่คำสั่ง)

- HP-DEATH-001/002 เพิ่ง pin ฟิลด์ HP + กลไก "ตาย" เสร็จหมาดๆ — **ระยะห่างจากการฆ่าตัวละครได้
  เหลือ 1 mask bit + 1 float** → ถ้า DAMAGE-MODEL-001 สำเร็จ จะได้ **ความเสียหาย + ความตาย ครบชุด**
  ในเวลาไล่เลี่ยกัน = หมวด combat ขยับได้หลายแถวรวด
- แถวนี้เป็น **ช่องว่างใหญ่ที่สุดที่เหลือของ combat** (chief เขียนไว้เองใน next ของรอบ 81 ข้อ 3)
- งานนี้ static ล้วน = ทำกลางคืนได้เอง ไม่ต้องรอรอบใหญ่ ไม่ต้องมี Panya
