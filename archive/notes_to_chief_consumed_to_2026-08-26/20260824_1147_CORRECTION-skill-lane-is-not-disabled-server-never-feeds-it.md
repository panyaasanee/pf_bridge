# แก้ข้อ ① ของจดหมายตรวจกวาด 1119 — **เลนสกิลไม่ได้ถูกปิด เซิร์ฟเวอร์เราไม่เคยป้อนข้อมูลให้มันต่างหาก**

**ผู้เขียน:** ผู้ช่วย (cloud) · **ถึง:** chief (cc) และ Panya · เวลา 2026-08-24 ~11:4x
**แทนที่:** ข้อ ① ของ `20260824_1119_AUDIT-4-findings-*` — ข้อ ②③④ ของจดหมายนั้นยังใช้ได้ตามเดิม

## สิ่งที่ผมเขียนผิด

จดหมาย 1119 เสนอว่า *"เลนสกิลอาจถูกปิดใน client build นี้"* และเตือนว่าอาจเสียเวลาเทสวันที่ 26
**กรอบนั้นน่าจะผิด** และคำเตือนก็ผิดตาม

## หลักฐานที่ขัดกับ "build ถูกปิด"

| หลักฐาน | ค่า |
|---|---|
| `CONSTDATA_TH__FUNCTION_CONTROL` แถว `Skilllearn` | **`1;60;0` → `1;130;0` เปิดครบทั้ง 6 สเตจ** (เทียบ `Itemmall_Main` ที่เป็น `0;0;0` ในสองสเตจแรก = รูปแบบของ "ปิด") |
| ข้อมูลสกิลที่ไคลเอนต์ขนมา | `SKILL_CONTEXT` **2,165 แถว** · `SKILL_TEXT` 940 แถว · ไอคอนสกิล 14 ไฟล์ |
| สตริงชื่อหน้าต่าง/ทูลทิปในอิมเมจ | **0 hit** — UI ขับด้วยข้อมูลใน `Data\GUI\` ไม่ได้ฝังในโค้ด ⇒ ไล่ hotkey ผ่านสตริงในอิมเมจทำไม่ได้ |

build ที่ถูกปิดฟีเจอร์จริงจะไม่ขนข้อมูล 2,165 แถวกับไอคอนมาด้วย

## คำอธิบายที่เข้ากับหลักฐานทั้งหมดมากกว่า

**ฝั่งเซิร์ฟเวอร์ของเรายังไม่เคยส่งสถานะสกิลให้ไคลเอนต์เลย**

- ทะเบียน RE มีข้อความตระกูลสกิล **10 ตัว** (`CSkillModule` · `CSkillAttr` · `CLearnSkillVital` ·
  `CLearnSkillResultVital` · `CRevertSkilltVital` · `TriggerCastSkillVital` · ตระกูล Pets อีก 4)
- เซิร์ฟเวอร์เรา implement แล้ว **2 ตัว** (`0x673C` ขาออก · `0x36AA` ขาเข้า) ทั้งคู่อยู่หลัง flag opt-in
  และเพิ่งเกิดใน R138/R140 เมื่อไม่กี่ชั่วโมงก่อน
- **`CSkillModule` / `CSkillAttr` ไม่เคยถูกส่งเลย** (GT-052 จดไว้เองว่า W/R span ว่าง)

⇒ ไคลเอนต์ไม่มีสถานะสกิลอยู่ในมือ **หน้าต่างจึงไม่มีอะไรจะเปิด** — และสอดคล้องกับสิ่งที่ GT-058 วัดได้พอดี:
กด `K` แล้ว **ไม่มี request วิ่งออกเลย** เพราะไคลเอนต์ไม่ได้คิดว่าต้องไป "ขอ" ข้อมูล มันคาดว่าได้รับมาตั้งแต่ต้นแล้ว
ส่วน `C` / `Quest` / `Reward` เปิดได้ เพราะข้อมูลของหน้าต่างเหล่านั้นมาจากสิ่งที่เซิร์ฟเวอร์เราส่งจริงอยู่แล้ว

## เรื่อง Lua stub — คนละเรื่องกัน อย่าปนกัน

`CastSkill*` เป็น `STUB_NOOP` ใน binding ของ Lua **เป็นเรื่องปกติของไคลเอนต์** — การร่ายสกิลเป็นอำนาจของเซิร์ฟเวอร์
สคริปต์ฝั่งไคลเอนต์จึงมี binding เปล่าไว้เฉย ๆ · **ไม่ใช่หลักฐานว่า build ถูกปิด** และไม่เกี่ยวกับ hotkey `K`
ซึ่งเป็นทาง UI native คนละทางกับ Lua · จดหมาย 1119 เอาสองเรื่องนี้มาปนกัน

## ผลต่อแผน

- ❌ **ยกเลิกคำเตือนเดิม** ที่ว่าเทสสกิลวันที่ 26 จะเสียเวลาเปล่า — เหตุผลที่ให้ไว้ไม่ถูก
- 🔴 **แต่ข้อสรุปเชิงปฏิบัติคล้ายเดิม ด้วยเหตุผลที่ถูกกว่า:** ตราบใดที่เซิร์ฟเวอร์ยังไม่ส่ง `CSkillModule`/`CSkillAttr`
  **หน้าต่างสกิลก็จะยังเปิดไม่ได้ ไม่ว่าจะเทสกี่รอบ** ⇒ ลำดับที่ถูกคือ **เขียนฝั่งเซิร์ฟเวอร์ให้ส่งสถานะสกิลก่อน แล้วค่อยเทส**
- ⇒ นี่เป็นงานของ **เลนโค้ด (cc)** ไม่ใช่เลนเทส และไม่ใช่เลน static

## nonclaims

- **ยังไม่พิสูจน์** ว่าไคลเอนต์ต้องการ `CSkillModule` ก่อนเปิดหน้าต่าง — เป็นคำอธิบายที่เข้ากับหลักฐานที่มี ไม่ใช่ข้อพิสูจน์
- ไม่ได้ไล่ handler ของ `K` ในอิมเมจสำเร็จ (สตริง 0 hit) ⇒ **ยังไม่มีใครเห็นโค้ดที่ตัดสินใจไม่เปิดหน้าต่างจริง ๆ**
- `FUNCTION_CONTROL` แถว `Skilllearn` เกี่ยวกับ **เพดานเลเวลสกิล** อาจไม่ใช่สวิตช์ของหน้าต่าง — ใช้เป็นหลักฐาน
  ว่า "ไม่มีร่องรอยการปิดฟีเจอร์" เท่านั้น ไม่ใช่ว่า "หน้าต่างถูกเปิดใช้งาน"
- ไม่ claim อะไรเกี่ยวกับเซิร์ฟเวอร์ต้นฉบับ ซึ่งปิดไปแล้ว กู้ไม่ได้ตลอดกาล
