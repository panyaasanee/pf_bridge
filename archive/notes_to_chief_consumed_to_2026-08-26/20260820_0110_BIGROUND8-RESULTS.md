- **ไม่ได้พิสูจน์ว่าเซิร์ฟเวอร์ต้นฉบับใช้ท่อเหล่านี้** — พิสูจน์ได้แค่ว่า client รับและเรนเดอร์
- **GT-025:** ไม่ได้ตรวจ DB (เลนประกาศ `database_write: none`) · ไม่ได้พิสูจน์ respawn หรือทางออกจากสถานะ
- **GT-025 เรื่องวงนับถอยหลัง:** **Panya เห็นชัดว่าเป็นการนับถอยหลัง 20 วินาที ผมไม่ได้** —
  ผมจับได้เฟรมเดียวและ **อ่านตัวเลขในวงไม่ออก** ⇒ บันทึกเป็น **พยานตาเปล่าของ Panya + ภาพประกอบหนึ่งเฟรม**
  **ห้ามเขียนใน ledger ว่า "client นับถอยหลังตาม `hp_death_timer`"** จนกว่าจะถ่ายไล่ทีละวินาทีได้
  (ถ้าจริงจะเป็นหลักฐานตรงว่า client อ่านค่า timer จริง — คุ้มที่จะทำ scenario เฉพาะกิจ)
- **GT-023:** ผลลบของ GT-021 (สามเฟรมแล้วไม่มี `Common_Death`) **มาจากรอบก่อนหน้า ไม่ได้รันซ้ำคืนนี้**
  ⇒ การอ้างว่า "เฟรมที่สี่คือสาเหตุ" อาศัยผลเก่าหนึ่งชั้น · **ไม่ได้กดปุ่มในหน้าต่างคืนชีพ**
  ⇒ **ไม่รู้ว่าปุ่มทำงานไหม** · ไม่ได้พิสูจน์ระบบ rescue/คืนชีพโดยผู้เล่นอื่น
- **GT-023 timing:** ผมอ่านลำดับจาก **ภาพของตัวเอง** ซึ่งมี latency ไม่ได้ instrument
  ⇒ ข้อที่แข็งคือ **ลำดับ** (`Main_Dead` มาก่อน `Common_Death`) **ไม่ใช่วินาทีที่แน่นอน**
- **GT-024:** ทุกอย่างในข้อ 3 · โดยเฉพาะ **"ไม่เห็นเลข" ของจ็อบ 924/931 ต้องไม่ถูกนับเป็นผลลบ**
  (เป็นการเล็งกรอบผิดที่ — ดูข้อ 3.2)
- **GT-024 ชั้นพยาน:** ข้อ ①③⑤ และ "เลขอยู่บนผู้เล่นไม่ใช่ NPC" มาจาก **ตาเปล่าของ Panya**
  ไม่ใช่ภาพที่ผมจับได้ ⇒ **ยังไม่มีไฟล์ภาพของ `63`, ของคำว่า `MISS`, และของอาการกระตุก**
  · สิ่งที่มีไฟล์ภาพจริงคือ **`379` หนึ่งเฟรม** และ **HP 100/100 ก่อน/หลัง**
  ⇒ ถ้า chief จะเขียนลง ledger ให้ระบุชั้นพยานให้ตรง อย่ากลืนเป็น "ผู้เทสถ่ายได้"
- ✅ **HP ไม่ลดจริง — ยืนยันสองปาก:** ภาพของผม (100/100 ก่อนและหลังครบ sweep)
  **และ Panya ยืนยันด้วยตาเองว่า HP ไม่ลด** ทั้งที่มีเลขความเสียหายขึ้น 3–4 ครั้ง
  ⇒ ตรงกับ `database_write: none` ของเลนนี้ และตรงกับ DAMAGE-MODEL-001 ที่ว่า client เป็นแค่ตัวแสดงผล
- **`MISS` ที่ขึ้นบนจอ:** เห็นด้วยตาเปล่า **1 ครั้ง** · ยังไม่รู้ว่าเป็นสตริงจาก client เองหรือมาจาก flag
  ⇒ **ห้ามเขียนว่า "flag bit 0 สั่งให้แสดง MISS"** จนกว่าจะมี static ยืนยัน
- **สูตรความเสียหายเป็นของเราเอง ไม่ใช่ของเซิร์ฟเวอร์ต้นฉบับ** (nonclaim บังคับของเลนนี้)
- **ไม่ได้เทสปุ่ม logout ในเกม** ทั้งรอบ

## 5) 🛠️ บทเรียนเครื่องมือ / บั๊กที่เจอ (chief เอาไปซ่อม template ได้เลย)

1. ⭐ **เปิด client ด้วย `Invoke-CimMethod Win32_Process Create` แทน `Start-Process -Redirect*`**
   ⇒ ลูกไม่สืบทอด handle ของจ็อบ **สะพานกลับ `idle` ทันที** — **วงจรอุดตันของรอบ #7 หายถาวร**
   (ใช้จริงในจ็อบ 913/915/917/918/922/924/928/930/931 ทุกใบไม่บล็อกเลย)
   🔴 **แต่ห้ามแค่ลบ `-Redirect*` ทิ้ง** — `Start-Process 'xxx.bin'` ที่ไม่มี redirect ใช้ ShellExecute
   และ `.bin` ไม่มี file association ⇒ **ล้มเงียบ `-PassThru` คืน `$null`** (จ็อบ 912 พิสูจน์)
   redirect ในจ็อบเก่ามีไว้บังคับ `UseShellExecute=false` **ไม่ใช่แค่เก็บ log**
2. 🔴 **`TEMPLATE_teardown_generic` + จ็อบ relaunch = กับดัก exit 15**
   จ็อบ relaunch client ต้องเขียน **`stamp` ของรอบบูต** ไม่ใช่เวลาของตัวเอง มิฉะนั้น guard window
   (stamp-1 .. stamp+5 นาที) จะไม่ครอบ console ที่บูตไปก่อนหน้า (จ็อบ 918 → 919 fail · แก้ด้วย 920)
   **ข้อเสนอ:** ใส่คอมเมนต์ในหัว template ว่า `stamp` = boot stamp เสมอ
3. 🔴🔴 **ผมทำผิดกฎที่ตัวเองเขียนไว้: เปิด client ตัวใหม่โดยดูแค่ `Get-Process = 0`**
   (จ็อบ 925) ทั้งที่ตัวเก่าไม่ได้ปิดสวย ⇒ **ค้าง "กำลังเชื่อมต่อ..." ตามที่ PLAYBOOK ข้อ 2 ทำนายเป๊ะ**
   · **Panya จับได้เองและตำหนิ** · เสียเวลา ~15 นาที + ต้องรีบูตเซิร์ฟ
   **ทางแก้ที่ลงมือแล้ว:** จ็อบ 931 ใส่ **การ์ดในโค้ด** — ถ้า
   `Get-NetTCPConnection -State Established` บนพอร์ต 10188/10189 **> 0 ให้ ABORT**
   ⇒ **ขอให้ chief ยกการ์ดนี้เข้าไปในทุก template ที่เปิด client** จะได้ข้ามด้วยดุลพินิจไม่ได้อีก
4. **แชตในเกม: ถ้าไม่ได้โฟกัสช่อง input จริง ตัวอักษรจะกลายเป็น hotkey** — คืนนี้เปิดหน้าต่าง
   OPTIONS / คีย์บอร์ด / ความละเอียด / SOCIAL โดยไม่ได้ตั้งใจอย่างละครั้ง (กด ESC ปิดหมด ไม่ได้แก้ค่าใด ๆ)
   **ท่าที่ปลอดภัย:** `mouse_move` ไปเหนือแผงแชตก่อน → คลิกแถบ input → **ถ่ายยืนยันว่าข้อความอยู่ในช่องแล้ว**
   → ค่อยกด Enter **ในการเรียกครั้งเดียวกัน** (ถ้าคั่นด้วย action อื่น focus หลุด)
5. **ทริกเกอร์ต้องเป็น ascii 12 ตัวอักษรจริง ๆ** — ลองส่ง `PFPROBE2` (8 ตัว) เฟรมถึงเซิร์ฟ (`0xAC52` 46 ไบต์)
   แต่ **ไม่เข้าเงื่อนไข ไม่มี sweep ออกมา** ⇒ ความยาวเป็นส่วนหนึ่งของ predicate
6. **เปิด client โดยไม่บูต server ⇒ dialog "ถูกตัดออกจากเซิร์ฟเวอร์" แล้วปิดตัวเองใน ~3.5 นาที**
7. **`request_access` ของ computer use timeout ที่ 180 วิ** ถ้าไม่มีคนกด Allow — ต้องบอก Panya ล่วงหน้า
8. **หน้าต่างเซิร์ฟเวอร์ (py.exe) เปิดทับหน้าต่างเกมเสมอหลังบูต** — ผู้เทส local ต้องขอสิทธิ์ `py.exe`
   ไว้ด้วยเพื่อจะสลับหน้าต่างได้ · และ **File Explorer/PowerShell ที่เด้งมาบัง = คลิกไม่ได้จนกว่าจะขอสิทธิ์**
   (ได้ tier `click` พอสำหรับกดสลับหน้าต่าง)
