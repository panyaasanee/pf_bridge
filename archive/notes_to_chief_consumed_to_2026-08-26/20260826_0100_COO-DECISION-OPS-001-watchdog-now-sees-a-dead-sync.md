## ③ สิ่งที่แก้ — `pf_bridge_watchdog.ps1` รู้จัก sync แล้ว

แทรกก่อนบรรทัด `if ($alive.Count -gt 0 -and -not $frozen) { exit 0 }` (เดิม `exit` ก่อนถึงส่วนใหม่)

| ทำอะไร | ขอบเขต |
|---|---|
| อ่าน `sync_last_check.txt` · เก่ากว่า **12 นาที** = sync ตาย (task เต้นทุก 2 นาที) | ตรวจ |
| **ซ่อมได้อย่างเดียว:** `.git\index.lock` ที่เก่ากว่า 3 นาที **และไม่มี process `git` มีชีวิต** ⇒ ย้ายไป `_to_delete\` | ซ่อม |
| เขียน `SYNC_ATTENTION.txt` บอกว่าเกิดอะไร และสาเหตุที่พบบ่อยสองแบบคืออะไร | ส่งเสียง |
| sync กลับมาดี ⇒ ลบ alert **เฉพาะใบที่ watchdog เขียนเอง** (ตรวจบรรทัดแรก) | คืนสภาพ |

🔴 **เจตนาที่ต้องเข้าใจ: มันซ่อมแค่ *หนึ่ง* อาการ ที่เกิดมาแล้วสองครั้งและมีวิธีแก้เชิงกล**
อะไรที่ต้องใช้วิจารณญาณ — ไฟล์ tracked ที่หายไป · conflict จริง — **ปล่อยให้คนทำ**
**watchdog ที่เดาเรื่อง git แย่กว่า sync ที่หยุด**

🔴 และอีกข้อที่เกือบพลาด: ตอนแรกผมเขียนให้มันลบ `SYNC_ATTENTION.txt` ทุกครั้งที่ sync ดูดี
แต่ **`pf_git_sync` เขียนและลบไฟล์เดียวกันนี้ด้วยเหตุผลของมันเอง** ⇒ ผมจะไปลบคำเตือนของคนอื่นทิ้ง
⇒ แก้เป็น **ลบเฉพาะใบที่ขึ้นต้นด้วย `SYNC STALE as of`** ซึ่งเป็นของ watchdog เท่านั้น

## ④ ทดสอบแล้ว สามรอบ ทั้งทางบวกและทางลบ

```
parse errors = 0
run 1  sync ปกติ (อายุ 0.5 นาที)      SYNC_ATTENTION = False   ถูก
run 2  ย้อนเวลา sync_last_check 40 นาที SYNC_ATTENTION = True    ถูก
       watchdog.log: "SYNC STALE: sync_last_check.txt is 40 min old (> 12)"
run 3  คืนค่าเดิม                      SYNC_ATTENTION = False   ถูก (ลบตัวเองแล้ว)
bridge processes หลังรัน watchdog สามครั้ง = 1  ถูก (ไม่ได้ฆ่าหรือปลุกอะไรเกิน)
WATCHDOG_SYNC_VERDICT=PASS
```

🔴 **การ์ดที่ไม่มีใครเคยเห็นมันปฏิเสธอะไร ไม่ใช่การ์ด** — `run 2` คือรอบที่ทำให้ใบนี้นับได้
